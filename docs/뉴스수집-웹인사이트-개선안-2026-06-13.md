## 0. 한눈에 보기 (Executive Summary)

David 요청은 크게 두 덩어리다.

1. **뉴스 수집 정교화** — 소스 점검, 불필요 기사 필터, 어드민 사용성, **해시태그를 의미있게 → signal-insight 로 연결**, 개인화 추천(관심사 기반 추천·연관기사·상단 추천).
2. **웹 인사이트 수집 신설** — Substack/Medium/기술블로그를 뉴스와 **별도 수집 방식**으로, 소스 관리를 **뉴스/리포트/웹인사이트/유튜브 4분류**로 재편, **뉴스레터 카테고리 삭제**.

현재 코드 분석 결과 **이미 깔려 있는 인프라**가 많다(중복 3단계, cluster_id, content_keywords/content_services, 번역 폴백+한도, opinion_channel 소스 12개). 따라서 신규 구축보다 **"있는 걸 의미있게 연결·정리"** 가 핵심이고, 진짜 신규는 ① 태그 체계(signal) ② 개인화 추천 ③ 웹인사이트 분리 수집 세 가지다.

기반 구조 우선 순서로 본 **권장 실행 순서**:

```
P0 정리(소스·카테고리·태그 의미화·필터)  ← 빠른 기반 정돈
   └─ P1 태그→Signal 체계 (signal-insight 의 토대)
        └─ P2 개인화 추천 (태그·signal 위에서만 의미)
   └─ P1' 웹인사이트 분리 수집 (소스 4분류 위에서)
        └─ P3 어드민 통계 대시보드 (모든 사용량 데이터 누적 후)
```

## 1. 현재 구조 진단 (사실 기반)

### 1.1 수집 파이프라인
- 진입점 `src/lib/crawler/orchestrator.ts` `runCrawl()`.
- 어댑터 3종: `news-site`(RSS), `youtube`(채널 RSS), `opinion_channel`도 news-site 어댑터로 처리(별도 어댑터 없음).
- 흐름: fetch → 중복 3단계(URL→bodyHash→titleHash) → 품질필터(`isAdLike` + `effectiveLength<30` reject) → near-dup `cluster_id` 그룹핑 → 관련도 게이팅(**현재 OFF**) → 번역(EN만, 크롤당 20건) → `contents` insert → `tagContent`.
- 본문은 **RSS 스니펫만**(풀본문 추출은 미구현, 백로그).

### 1.2 태깅(현재의 "해시태그")
- `tagContent()`: `keywords` 테이블의 name 을 **본문에 `includes` (대소문자 무시)** 단순 포함 매칭 → `content_keywords` + (키워드의 service_id 로) `content_services` 적재.
- **문제 3가지**:
  1. **단순 부분일치** → "GPU" 가 "GPU레이싱게임" 같은 무관 문맥에도 매칭. 한국어는 띄어쓰기 경계가 약해 오탐 많음.
  2. **키워드 = 서비스 태그로 혼용** → "이게 무슨 주제냐(토픽)" 와 "어느 사업부 소관이냐(서비스)" 가 한 테이블에 섞임. **signal(시그널/이슈) 개념 부재.**
  3. 적재 텍스트가 **스니펫**이라 매칭 근거가 빈약 → 태그가 적게/엉뚱하게 붙음 = "의미없는 해시태그" 체감의 원인.

### 1.3 번역
- `src/lib/translate/index.ts`: DeepL→Papago→Google 폴백. `translation_usage`(월 사용량) + `translation_settings`(provider on/off) 로 **월 한도 초과 시 자동 skip** = 사실상 lock 동작 **이미 구현**. 다만 "한도 도달 시 명시적 lock 상태 노출/알림" UI 는 약함.

### 1.4 소스 모델
- `source_type` enum: `news_site / report_publisher / opinion_channel / newsletter / youtube_channel` (5종).
- `content_category` enum: `뉴스 / 가트너 / KRG / 웹인사이트 / 오피니언 / 뉴스레터 / AI보고서 / 유튜브` (8종).
- `sources.group_name` 으로 과세분 RSS 묶음 그룹핑 이미 도입(지시서 43).
- 즉 **"웹인사이트" 카테고리와 opinion_channel 타입은 이미 존재** → 요청은 "신설"보다 **분류 체계 재정의 + 별도 수집 경로**.

### 1.5 어드민
- 메뉴 분리됨: 콘텐츠/소스/키워드/크롤로그/업로드(리포트)/번역/뉴스레터/모닝브리핑.
- 통계는 어드민 홈 4개 카운트(총/오늘/활성소스/검토대기)뿐. **접속자·조회수·번역량·TTS 사용량 통합 대시보드 없음**(데이터는 `translation_usage`, `tts_usage`, `contents.view_count` 에 일부 존재).

### 1.6 추천·개인화
- **전무.** `cluster_id`(연관기사 인프라), `content_services`(서비스 매칭), `user_services`(관심 서비스) 는 있으나 이를 활용한 추천 쿼리/UI 없음.

## 2. 개선안 — 기반 구조 우선 순서

각 항목: **문제 → 개선안 → 구현 포인트(테이블/파일) → 난이도**.

### P0. 기반 정돈 (Quick foundation — 의존성 적고 즉시 효과)

#### P0-1. 소스 점검 & 4분류 재편 + 뉴스레터 카테고리 삭제
**문제**: 카테고리/타입이 8+5 로 과다하고 "뉴스레터"는 요청상 폐기 대상. 요청 분류는 **뉴스 / 리포트 / 웹인사이트 / 유튜브**.

**개선안 — 매핑 재정의**:

| 신규 소스 그룹(UI) | source_type | content_category | 수집 방식 |
|---|---|---|---|
| 뉴스 | `news_site` | `뉴스` | RSS 일일 |
| 리포트 | `report_publisher` | `가트너`/`KRG` | 수동 업로드(파일) |
| 웹 인사이트 | `opinion_channel`(→ 의미상 web_insight) | `웹인사이트` | RSS, **개별 주기** |
| 유튜브 | `youtube_channel` | `유튜브` | 채널 RSS |

- **뉴스레터 폐기**: `newsletter` source_type 과 `뉴스레터` content_category 사용 중단. enum 값은 Postgres 특성상 즉시 삭제 어려우니 **(a) UI/필터에서 제거 + (b) 신규 적재 차단**로 1차 처리, enum 물리 삭제는 별도(데이터 마이그레이션 후).
  - 단, **뉴스레터 *발송* 기능(Phase 3-A)** 은 별개다. 폐기 대상은 "수집 *소스/카테고리*로서의 뉴스레터"임을 지시서에 명확히 못박을 것. (혼동 시 발송 시스템 깨짐)
- **소스 점검**: 현재 active 소스 dump → 30일 `crawl_logs` 조인해 **fetched=0 / 연속 failed / inserted 거의 0** 소스 식별 → 삭제·교체 후보 리스트화(어드민에서 보이게, P0-3).
- **신규 소스 후보**: `docs/오피니언-소스-후보.md` 에 이미 후보 있음 → 검증 후 web_insight 로 편입.

**구현 포인트**: `src/lib/types.ts`(라벨 맵), 필터 UI, `sources` 시드, enum 정리 SQL.
**난이도**: 중 (enum 이 까다로움 — 점진 폐기 권장).

#### P0-2. 불필요 기사 필터 강화 (관련도 게이팅 ON)
**문제**: `RELATEDNESS_GATING_ENABLED=false` → 모든 기사 무조건 published. 불필요 기사 유입의 직접 원인.

**개선안 (단계적)**:
1. **관련도 점수 정교화**: 현재 binary(키워드 1개라도 포함→1.0). → **가중 점수**로:
   - 제목 매칭 가중 ↑, 본문 매칭 ↓, 매칭 키워드 수, 부정 키워드(블랙리스트) 차감.
   - `relatednessScore()` 를 `0~1` 연속값으로.
2. **블랙리스트 필터 신설**: 광고 외에 "연예/스포츠/부동산/사건사고" 등 도메인 무관 키워드 패턴 → reject. 현재 `AD_PATTERNS` 옆에 `EXCLUDE_PATTERNS` 추가(어드민 관리화는 P0-3).
3. **게이팅 ON + 승인 큐**: `RELATEDNESS_GATING_ENABLED=true`, threshold 미만은 `pending` → 어드민 콘텐츠 관리의 "검토 대기"로. (어드민 승인 UI 는 이미 존재 — `/admin/contents`)
4. **소스 신뢰도 등급**: 신뢰 소스는 게이팅 면제, 광역 소스(Google News 등)는 엄격 적용. `sources` 에 `trust_tier` 컬럼.

**구현 포인트**: `src/lib/crawler/quality.ts`, `orchestrator.ts`(게이팅 분기), `sources` 컬럼 추가.
**난이도**: 중 — **불필요기사 문제의 핵심 해결책**.

#### P0-3. 어드민 소스/콘텐츠 관리 사용성 개선
**문제**: 소스 관리·콘텐츠 관리가 불편(David 명시). 통계 산재.

**개선안**:
- **소스 관리 재설계**: 탭/필터를 **뉴스 / 리포트 / 웹인사이트 / 유튜브** 4탭으로. 각 소스 행에 **최근 수집 상태**(마지막 수집일, 최근 7일 inserted, 연속 실패 배지)를 `crawl_logs` 조인해 인라인 표시 → "죽은 소스" 즉시 식별.
- **인라인 토글/편집**: is_active, crawl_interval, group_name, trust_tier 를 목록에서 바로 수정.
- **콘텐츠 관리**: 검토대기(pending) 우선 노출 + 일괄 승인/반려, 카테고리·소스·기간 필터, 잘못 태깅된 기사 태그 수정.
- **블랙리스트/광고패턴 DB화**: `quality.ts` 상수를 `filter_patterns` 테이블로 빼고 어드민에서 편집.

**구현 포인트**: `src/app/admin/sources`, `src/components/admin/SourceManager.tsx`, `/admin/contents`.
**난이도**: 중 (UI 작업량).

### P1. 태그 → Signal 체계 (signal-insight 의 토대) ★기반 핵심

> David: "해시태그가 의미없게 붙어있는데 의미있게 붙어야 하고, 이게 나중에 **signal-insight 로 이어져야 한다**."

#### P1-1. 3축 태그 모델 정립
현재 "키워드" 한 축에 뒤섞인 것을 **3개 축**으로 분리:

| 축 | 의미 | 저장 | 용도 |
|---|---|---|---|
| **서비스 태그** | 어느 사업부/서비스 소관 | `content_services` (기존) | 담당자 큐레이션·필터 |
| **토픽 태그(해시태그)** | 무슨 주제 (AI, 보안, 5G, 클라우드…) | `content_keywords`→토픽 분리 | 사용자 노출 해시태그·연관기사 |
| **시그널 태그** | 비즈니스 시그널 유형 | **신규** `signal_type` | signal-insight 집계 |

**시그널 타입 enum(초안)**: `경쟁사동향`, `규제·정부발표`, `신제품·출시`, `투자·M&A`, `기술트렌드`, `시장지표`, `파트너십`, `인사·조직`. → 이게 나중에 "이번 주 경쟁사 동향 시그널 N건" 같은 **signal-insight 리포트**의 단위가 된다.

#### P1-2. 키워드 카탈로그 확장 (경쟁사·빅테크·정부)
**문제**: 현재 키워드 seed 는 7개 서비스의 자사 제품 용어 위주. **경쟁사·빅테크·정부 발표** 키워드 부재 → David 명시 요청.

**개선안 — keywords 테이블에 축 컬럼 추가**:
- `keywords.kind` enum: `service`(자사) / `competitor`(경쟁사) / `bigtech` / `gov` / `topic`. (`is_competitor` bool 은 이걸로 흡수)
- 시드 추가:
  - **경쟁사**: KT, SKT, SK브로드밴드, 세종텔레콤, 드림라인 등 + 글로벌(Verizon, AT&T, NTT…).
  - **빅테크**: AWS, Azure, Google Cloud, NVIDIA, OpenAI, Anthropic, Microsoft, Meta…
  - **정부·규제**: 과기정통부, 방통위, 개인정보보호위, 전파법, 망 이용대가, AI 기본법…
- 각 키워드에 **연결 시그널 타입** 매핑(예: "M&A"→투자·M&A, "과기정통부"→규제·정부발표).

#### P1-3. 태깅 정확도 개선 (오탐 제거)
- **단어 경계 매칭**: 영문은 `\b` 경계, 한글은 형태소 약식(조사 앞뒤 경계) 적용해 부분일치 오탐 감소.
- **별칭(alias) 지원**: `keyword_aliases` (예: "엔비디아"=="NVIDIA"=="GPU 1위") → 표기 흔들림 흡수.
- **풀본문 보강 연계**: 스니펫만으로는 태깅 빈약 → 풀본문 enrichment(백로그)와 묶어 태깅 품질 ↑.
- **신뢰 임계**: 매칭 점수 낮은 태그는 "후보 태그"로만 저장, 노출 안 함.

#### P1-4. Signal 집계 기반 마련
- `content_signals` (content_id, signal_type, score) 적재.
- 일/주 단위 **signal rollup 뷰**: 시그널 타입 × 서비스 × 기간 카운트 → 후속 "signal-insight" 화면/리포트의 데이터 소스.
- **이것이 P2 추천과 AI보고서(경쟁사분석 등)의 공통 토대.**

**구현 포인트**: `keywords` 컬럼·시드 SQL, 신규 `signal_type` enum, `content_signals`/`keyword_aliases` 테이블, `tagContent()` 재작성, 집계 뷰.
**난이도**: 높음 — 하지만 **signal-insight·추천·AI보고서 전부의 기반**이라 최우선 투자처.

### P1'. 웹 인사이트 분리 수집 (소스 4분류 위에서)

> 뉴스와 **별도 수집 방식**, **개별 수집 가능**하도록.

#### P1'-1. 전용 어댑터 분리
**문제**: 현재 opinion_channel 이 news-site 어댑터 재사용 → 뉴스와 동일 정책(당일 발행만, 12h 주기)에 묶임. 블로그·Substack 은 발행 빈도가 낮아(주 1회 등) 당일 정책에 걸려 거의 안 잡힘.

**개선안**:
- `web-insight` 어댑터 신설(또는 opinion 어댑터 명시 분리). 차이점:
  - **lookback 길게**(기본 7~14일, 소스별 설정) — 이미 `OPINION_LOOKBACK_DAYS=7` 존재, 이를 소스별 컬럼 `lookback_days` 로 일반화.
  - **풀본문 추출 우선**(블로그는 RSS 에 본문 전체 오는 경우 많음 → 태깅·요약 품질 ↑).
  - **저자(author)·블로그명** 메타 강조.
- **개별 수집 버튼**: 어드민 소스 행마다 "지금 이 소스만 수집" (`/api/admin/crawl-now` 에 source_id 파라미터 추가).

#### P1'-2. 대상 소스군
- Substack/Medium: RSS 표준(`{블로그}/feed`). 
- 기술블로그: **AWS, Azure, Google Cloud, Cloudflare, Cisco** 는 이미 opinion 시드에 존재 → web_insight 로 재분류.
- **국내 통신사 기술블로그 추가**: **LG U+(자사), KT, SKT** 테크 블로그 + 네이버 D2, 카카오 tech, 토스 등.
- 검증: 각 RSS live + 파싱 확인(rss-parser) 후 등록(기존 오피니언 시드 방식 답습).

#### P1'-3. 카테고리·표시 정합
- content_category `웹인사이트` 사용(기존). 뉴스 피드와 섞이지 않게 대시보드 카테고리 그리드/필터에서 별도 노출.

**구현 포인트**: `src/lib/crawler/adapters/` 신규 어댑터, `sources.lookback_days`, `crawl-now` 라우트, 시드 SQL, 카테고리 라벨/필터.
**난이도**: 중.

### P2. 개인화 추천 (태그·signal 위에서만 의미)

> 세 가지 요청: ① 관심사 기반 추천 ② 기사 하단 연관기사 ③ 뉴스&미디어 상단 추천.

전제: P1 태그/시그널이 있어야 추천 품질이 나온다. 그래서 **P1 뒤**.

#### P2-1. 기사 하단 연관기사 (난이도 ↓ — 먼저)
- **1차(즉시 가능)**: `cluster_id` 같은 그룹 + **공유 토픽 태그 수** 기준 정렬. 인프라 이미 있음.
- **2차**: FTS(`search_vector` 존재) 기반 "more like this" + 같은 서비스 태그.
- **3차(선택)**: pgvector 임베딩 유사도(신규 의존성 — ADR 필요).
- 표시: 상세페이지 `dashboard/contents/[id]` 하단 "연관 기사" 섹션.

#### P2-2. 관심사 기반 추천 피드
- 입력 신호: `user_services`(관심 서비스, 기존) + **열람 이력**(신규 `content_views` 또는 view 로그) + 북마크(`bookmarks`, 기존).
- 추천 점수 = 사용자 관심 서비스/토픽 매칭 + 최신성 + 인기(view_count/bookmark_count) 가중.
- **개인화의 핵심 신규 데이터 = 열람 이력**. 지금은 `view_count`(전역)만 있고 **누가 무엇을 봤는지 없음** → `content_views(user_id, content_id, viewed_at)` 신설 필요(P2 선결).

#### P2-3. 뉴스&미디어 상단 추천 캐러셀
- 사용자 부서(`department`)·관심 서비스 기준 상위 N건을 카테고리 페이지 상단에 "추천" 섹션.
- 비로그인/신규(이력 없음) 대비: **부서 기본 추천**(같은 부서 인기) → cold-start 처리.

**구현 포인트**: `content_views` 테이블+RLS, 추천 쿼리(서버 컴포넌트/RPC), 대시보드 UI 3곳.
**난이도**: 중~높음. **P2-1 먼저(저비용), P2-2/3 는 열람이력 누적 후 품질 상승.**

### P3. 어드민 통합 통계 대시보드

> David: 접속자수·조회수·번역량·TTS 사용량을 통계에서.

데이터가 누적돼야 의미 있으므로 **후순위**(단, 수집 시작은 빠를수록 좋음).

| 지표 | 데이터 소스 | 상태 |
|---|---|---|
| 번역량(월) | `translation_usage` | **있음** — 바로 차트화 가능 |
| TTS 사용량 | `tts_usage` | **있음** |
| 조회수 | `contents.view_count` | 전역 합계 있음 / 일별 추이는 `content_views`(P2-2) 필요 |
| 접속자수(DAU/WAU) | **없음** — 신규 `access_logs` 또는 미들웨어 로깅 필요 | 신규 |

**개선안**: `/admin/stats` 단일 대시보드 — 기간 선택 + 4개 지표 카드 + 추이 차트. 차트 라이브러리 결정 필요(ADR: Recharts 권장 — 기존 React 19 호환·경량).
**난이도**: 중 (접속자 로깅만 신규, 나머지는 시각화).

## 3. 의존성 그래프 & 권장 로드맵

```
[P0-1 소스 4분류·뉴스레터 폐기] ──┐
[P0-2 관련도 게이팅 ON]           ├─ 독립, 병렬 가능 (빠른 정돈)
[P0-3 어드민 소스/콘텐츠 UX]    ──┘
            │
            ▼
[P1 태그→Signal 3축 체계] ★기반 핵심
   ├─ P1-1 3축 모델
   ├─ P1-2 키워드 확장(경쟁사/빅테크/정부)
   ├─ P1-3 태깅 정확도
   └─ P1-4 signal 집계  ──────────────┐
            │                          │
[P1' 웹인사이트 분리수집] (P0-1 후)     │
            │                          ▼
            └────────────► [P2 개인화 추천]
                              ├─ P2-1 연관기사(저비용·선행)
                              ├─ P2-2 관심사 추천(+content_views)
                              └─ P2-3 상단 추천 캐러셀
[P3 어드민 통계] — 데이터 누적과 병행, 시각화는 언제든
```

**제안 묶음(지시서 단위)**:
1. **묶음 A (P0)**: 소스 4분류+뉴스레터 폐기 / 관련도 게이팅 ON+블랙리스트 / 어드민 소스·콘텐츠 UX. *(빠른 체감, 불필요기사 즉시 감소)*
2. **묶음 B (P1)**: 3축 태그+시그널 enum+키워드 확장+태깅 재작성+집계 뷰. *(signal-insight 토대)*
3. **묶음 C (P1')**: 웹인사이트 전용 어댑터+개별 수집+국내 통신사 블로그 시드.
4. **묶음 D (P2)**: 연관기사(선) → content_views → 관심사 추천 → 상단 캐러셀.
5. **묶음 E (P3)**: access 로깅 + /admin/stats 대시보드.
