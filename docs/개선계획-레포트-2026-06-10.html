1. 종합 요약

Insight Out은 핵심 데이터 파이프라인(크롤링→중복제거→번역→피드)과 뉴스레터 발송이 실제 운영 가능한 수준으로 구현되어 있고, DB 보안(18개 테이블 전체 RLS 적용)과 기술 부채 관리(잔여 TODO 0건, 타입-스키마 동기화) 상태가 우수합니다. 반면 대시보드 첫 화면에 노출되는 일부 위젯(AI 보고서, 경쟁사 동향, 모닝 브리핑)이 목업 데이터로 동작하는 채 운영 환경에 노출되어 있어, "차분하고 신뢰감 있는 비즈니스 도구"라는 제품 톤과 가장 크게 충돌하는 지점입니다.

구조적으로는 대시보드 셸 전체가 클라이언트 컴포넌트로 작성되어(AGENTS.md 규칙 12 위반) 초기 렌더 성능과 SEO에 손해를 보고 있으며, loading.tsx/error.tsx 부재, 일부 페이지 metadata 누락, 브랜드 컬러 하드코딩(규칙 9 위반) 등 빠르게 고칠 수 있는 규칙 위반이 산재합니다. 테스트 코드는 0건입니다.

3. UI/UX 분석

3.1 잘 되어 있는 것

  • Tailwind v4 @theme 기반 디자인 토큰 + OKLch 색상 체계, 다크모드 변수까지 정의. ThemeToggle이 헤더에 실제 연결되어 있음 (AGENTS.md의 "토글 UI 미구현" 기술은 오히려 문서가 낡음)
  • 한국어 UI 텍스트 100%, lang="ko" 적용 — 핵심 하드룰 1·2 준수
  • 모바일 드로어에 ESC 닫기 처리, 상세·검색 페이지의 Suspense 사용, 콘텐츠 상세의 동적 metadata 등 기본기가 있음
  • 빈 상태(empty state) 처리와 반응형 레이아웃이 대체로 일관됨

4. 기능 구현 품질

보안 — 18개 테이블 전체에 RLS 적용, auth.uid()/is_admin() 패턴 일관 사용, service_role 키 서버 한정. 우수합니다. 다만 API 라우트에 rate limit과 요청 타임아웃이 없어 크론·어드민 엔드포인트가 남용에 노출될 수 있습니다.

크롤러·번역 — 중복제거 3단계(URL 정규화→제목 유사도→해시), 품질 필터, 번역 3사 폴백 체인까지 설계 문서(phase2a)와 구현이 일치. 운영 재시험 항목이 할일 목록에서 관리되고 있는 점도 건강한 신호입니다.

기술 부채 — TODO/FIXME 0건, types.ts와 스키마 동기화 양호. 그러나 테스트가 단 한 개도 없습니다. 특히 크롤러 dedup·quality·유사도 로직은 순수 함수라 테스트 비용이 낮고 회귀 위험은 높은, 테스트 도입 1순위 영역입니다.
