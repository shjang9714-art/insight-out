## 4. ⚠️ 다음 세션이 반드시 알아야 할 것

### 4-1. 이 코드베이스의 실패 모양은 **하나**다
**graceful인데 silent다.** 에러가 안 나고, 로그도 없고, 그냥 **아무 일도 안 일어난다.**

**→ 새 코드를 짤 때 "실패가 보이는가"를 반드시 묻는다.**

### 4-2. **"없다"고 단정하기 전에 찾아라**
오늘 반복된 패턴: **새로 만들라고 지시했는데 이미 있었다.**
- `content_views` API · `toExcerpt` 본문 폴백 · `/admin/source-quality` 진단 화면 · `lgu_impact` 컬럼 · `capPerGroup` · `looseJsonParse`

**플래너가 부분 grep으로 단정해 4번 틀렸다**(생성기 3→**11** · `validateSourceRows`가 fetch 안 한다 → **하고 있었다** · 마이페이지가 네비에 섞여 있다 → **없었다** · 검수 모달에 키워드가 있다 → **0회**).

### 4-3. 병렬 레인이 **세 번** 사고를 냈다
`cc59a1d`(요약 분리 → SQL·감시목록·어드민버튼 구멍 3개) · `9e10230`(key_insights 폐기 ↔ MCP가 그 테이블에 기록) · `PR #40`(309를 말없이 구현 → 계획서가 낡음)

**→ ⓪ 최신화 때 `git log --oneline --stat origin/main -5`를 반드시 읽는다.** `merge`는 충돌만 막지 **의미 충돌**은 못 막는다.

### 4-4. **규칙은 코드로 강제한다**
주석으로 부탁하면 깨진다(293의 생성기 목록, 292의 `EXPECTED_CRONS`가 **하루에 두 번** 어긋났다).
**292 후속은 `vercel.json`을 단일 진실로 삼고 빌드가 실패하게 만들었다. 그게 정답이다.**

### 4-5. 플래너는 **git을 만지지 않는다**
플래너 샌드박스는 `unlink`가 막혀 있어 `.git/*.lock`이 남고, **그게 구현자의 병합을 막았다**(두 번).
**재현검증은 워킹트리 파일을 직접 읽는다.** `git log`(읽기)는 안전하나 `fetch`/`merge`는 쓰지 않는다.
