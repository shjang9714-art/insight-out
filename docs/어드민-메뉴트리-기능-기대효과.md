# Insight Out 어드민 — 메뉴트리 · 기능 · 기대효과

> 작성: 2026-07-01 · 목적: 어드민 개선 검토를 위한 현황 정리(as-is)
> 범위: `/admin` 전체(8개 그룹 · 16개 페이지). 사용자 대시보드(`/dashboard`)는 별도.

## 0. 한눈에 — 메뉴트리

```
개요
 └ 대시보드                (/admin)                수집·검토·참여 현황 한눈에

분류 엔진
 ├ 카테고리 분류기준       (/admin/keywords)       콘텐츠→서비스·카테고리 분류 키워드
 ├ 수집 키워드            (/admin/keyword-groups) 수집 관련도·검색어·시그널 기준

 ├ 번역                  (/admin/translation)    번역 연결·월간 사용량
```

**파이프라인 관점**: 수집(소스·크롤링) → 정제/분류(분류 엔진·콘텐츠 관리) → 지식화(엔티티·이슈) → 산출(AI 인사이트·브리핑·뉴스레터) → 운영(대시보드·LLM·번역·사용자). 어드민은 이 **데이터 파이프라인의 관제탑**이다.

## 1. 개요 그룹

### 대시보드 (`/admin`)
**기능**: 오늘 할 일(검토 대기·오늘 수집·크롤 실패 건수) · "지금 AI 갱신" 수동 트리거(인사이트/후보/타임라인/브리핑) · 운영 신호등(LLM 토큰·번역·TTS 사용량, 이슈/엔티티/카드/시그널 점등) · 콘텐츠 건강(발행 비율·본문 길이 분포·논조 미분석·미태깅·깨진 링크) · KPI(총·오늘·검토대기·북마크·활성 소스) · 차트(카테고리·상태·14일 추이·소스 Top10).
**기대효과**: 운영자가 **한 화면에서 파이프라인 건강·병목·할 일**을 즉시 파악 → 이상 조기 발견, 수동 개입 지점 판단.

---

## 2. 콘텐츠 그룹

### 콘텐츠 관리 (`/admin/contents`)
**기능**: 다중 필터(상태·카테고리·소스·본문상태·검색·오늘·북마크) · 행 편집(제목/요약/카테고리/소스/저자/발행일/원문) · 상태 토글(published↔pending↔rejected) · 일괄 상태변경·삭제 · 배경작업(수집기사 비우기·유튜브 비우기·풀본문 채우기·신호 분류 실행·선택 풀본문).
**기대효과**: 수집된 원재료의 **품질 게이트키핑**(노출/숨김) + 본문·시그널 **보강 배치**로 산출물(인사이트·브리핑) 품질의 토대 확보.

### 콘텐츠 추가 (`/admin/upload`)
**기능**: CSV/Excel 일괄 업로드(제목·소스·발행일 필수) · 텍스트/JSON 붙여넣기 수동 등록.
**기대효과**: 자동 수집이 못 잡는 **오프라인·비정형 자료(리포트·내부 문서)를 파이프라인에 편입** → 커버리지 보강.

### 모닝브리핑 (`/admin/briefings`)
**기능**: 날짜별 브리핑 목록·상태 배지 · TTS 월간 사용량 · 스크립트 확인 · TTS 오디오 생성(LLM+TTS) · 재생 · 상태 전환(초안→공개→보관)·발행 승인.
**기대효과**: 매일 자동 생성되는 **오디오 브리핑의 검수·발행 통제** → 잘못된 요약의 사용자 노출 방지.

---

## 3. 수집 그룹

### 소스 관리 (`/admin/sources`)
**기능**: 소스 목록(이름·타입·활성·최근크롤·방법) · 추가/편집(URL·RSS·크롤 간격·방법·활성 토글) · 삭제 · 소스별 즉시 크롤 · RSS 자동 감지 임포트 · 실시간 크롤 진행률.
**기대효과**: **수집 범위·주기의 직접 제어** → 신규 출처 편입, 저품질 출처 정리, 파이프라인 입구 관리.

### 크롤링 현황 (`/admin/crawl-logs`)
**기능**: 요약(마지막 실행·성공/부분/실패) · 로그 테이블(소스별 최근 100건: 상태·수집/삽입/중복/보류·소요·오류).
**기대효과**: **수집 실패·중복의 가시화** → 소스 설정 오류·차단·구조 변경을 신속 진단.

---

## 4. 분류 엔진 그룹

### 카테고리 분류기준 (`/admin/keywords`)
**기능**: 분류 키워드 목록(서비스 매핑·경쟁사 여부) · CRUD.
**기대효과**: 콘텐츠를 **서비스·카테고리로 자동 라벨링하는 규칙 관리** → 개인화(담당/관심)·필터의 정확도 기반.

### 수집 키워드 (`/admin/keyword-groups`)
**기능**: 태그타입별(산업/기업/기술/시장/정책/콘텐츠유형) 그룹 · 포함/제외 패턴 · 검색어(seed) · 가중치 · 시그널 힌트 · CRUD(다음 수집부터 반영).
**기대효과**: **무엇을 얼마나 중요하게 수집·태깅할지의 정책 엔진** → 관련도·시그널·버킷색·검색어의 단일 소스.

### 엔티티 사전 (`/admin/entities`)
**기능**: 엔티티 목록(정규명·타입·설명·경쟁사·언급수) · 추가/편집(동의어 칩) · 중복 병합(진행률) · AI 정규화 제안.
**기대효과**: 기업·기술·인물의 **표기 흔들림을 하나로 정규화** → 경쟁사 동향·관계지도·관심기업 정확도의 토대.

## 5. 이슈·인사이트 그룹

### 이슈 관리 (`/admin/issues`)
**기능**: 이슈 목록(상태·자동배정 콘텐츠 수) · 추가/편집(match_keywords 칩으로 자동 매칭) · 콘텐츠 수동 추가/제거 · 상태(초안→발행/보관/삭제) · 관련 콘텐츠 추천.
**기대효과**: 흩어진 기사를 **테마(이슈)로 묶는 지식 구조화** → 이슈 탭·타임라인·"왜 중요한가"의 원천.

### AI 인사이트 (`/admin/insights`)
**기능**: 인사이트 카드 생성(7/14일, LLM) · 관심업체 동향 생성(워치리스트, LLM) · 논조 분석(최대 40건, LLM) · 카드 목록(주제·범위·상태·기간·헤드라인·시사점·인용) · 상태 토글(초안/발행/보관)·삭제·필터.
**기대효과**: 파이프라인의 **최종 산출물(인사이트 카드) 생성·검수·발행 통제** → 사용자 브리핑·카드의 품질·정확성 관문. (LLM 의존)

## 6. 연동·사용량 그룹

### 번역 (`/admin/translation`)
**기능**: 공급자별(DeepL/Papago/Google) 연결 상태·활성 토글·월간 사용량.
**기대효과**: **번역 비용·한도 가시화 + 공급자 전환** → 외신 본문 번역의 안정성·비용 통제.

### LLM 관리 (`/admin/llm`)
**기능**: 제공자별 상태·월 토큰·비용 추정 · 작업유형별(분류/요약/보고서) 우선 제공자·모델 라우팅 · 활성 토글 · 연결 테스트(응답시간·모델·응답).
**기대효과**: **AI 산출의 엔진 관제**(비용·한도·품질·장애) → 인사이트/브리핑/논조의 안정 공급. (전사 LLM 키 블로커의 관리 지점)

## 7. 발행 그룹

### 뉴스레터 (`/admin/newsletter`)
**기능**: 발송 설정(활성·시간·요일·카드수·제목 템플릿) · 미리보기 · 지금 발송(수동) · 발송 이력(최근 20건: 수신자·상태·트리거).
**기대효과**: 산출물을 **정기 푸시 채널로 배포·이력 추적** → 능동적 도달, 발송 사고 방지.

## 8. 시스템 그룹

### 사용자 관리 (`/admin/users`)
**기능**: 사용자 목록(이메일·이름·부서·팀·직급·권한·승인·가입일) · admin↔user 토글 · 이메일로 admin 추가 · 가입 승인/거절.
**기대효과**: **접근 통제·온보딩 게이트** → 내부 도구 보안·조직 매핑(부서/팀은 개인화의 근거).

## 9. 개선 검토를 위한 관찰 (seed)

현황 정리에서 눈에 띄는 검토 관점(판단은 열어둠):

1. **수동 트리거 편중** — 풀본문·신호분류·인사이트 생성·논조·TTS가 대부분 "버튼 수동". 자동 cron이 있는 것과 없는 것이 섞여 있어, **어떤 걸 자동화/스케줄로 올릴지** 검토 여지.
2. **메뉴 성격 혼재** — "분류 엔진"의 카테고리 분류기준 vs 수집 키워드가 사용자에겐 구분이 모호할 수 있음(둘 다 키워드). **명칭·통합/분리** 검토.
3. **건강·사용량 지표의 분산** — 대시보드·번역·LLM·브리핑에 사용량/건강 지표가 흩어짐. **운영 관제 통합 뷰** 검토.
4. **LLM 의존 산출물의 폴백** — 인사이트·논조·브리핑은 LLM 필수(키 블로커 시 정지). 규칙 기반 폴백·큐잉 상태 노출 검토(사용자 화면은 이미 162/166 폴백 적용, 어드민은?).
5. **"준비 중" 잔재** — 리서치 반영·(브리핑 스크립트 일부) 등 미완 항목의 노출/정리.
6. **콘텐츠 관리 과부하** — 필터·행편집·일괄·배경작업이 한 화면에 집중. **작업 흐름(검수 vs 보강 배치) 분리** 검토.
7. **일관성** — 사용자 화면은 최근 IA·색·카드 재설계(159~173)를 거쳤으나, 어드민 UI는 그 정합(색 토큰·용어)에서 벗어나 있을 수 있음.

> 다음 단계: 위 관찰 중 우선순위를 정해, 사용자 화면처럼 **슬라이스 단위 개선 지시서**로 전환.
