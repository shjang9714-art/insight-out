## 0. 원칙
- **상태의 source = git `docs/작업계획서.md` 의 신호등.** Notion 을 git 에 맞춘다(양쪽 충돌 시 git 기준).
- **모호하면 추측 금지 → David 에게 질문.** 작업 DB 에만 있고 git 에 없는 작업은 **임의 생성·변경하지 말고 목록으로 보고**.
- 각 Notion DB·페이지는 **먼저 fetch 해 현재값·속성명을 확인**한 뒤 갱신. 이미 맞는 항목은 건드리지 않음.
- 순수 문서·기록 작업(코드·스키마 변경 없음).

## 1. 입력 파악 (Sonnet 스스로)
1. `docs/작업계획서.md` 끝의 `*마지막 sync: YYYY-MM-DD*` 확인 → **그 이후 신규 커밋**을 `git log --oneline --since=<날짜>` (또는 직전 sync 커밋 이후)로 수집. David 가 범위를 지정했으면 그걸 우선.
2. 그 커밋들이 **어떤 작업(작업계획서 행)을 완료/진행시켰는지** 매핑.
3. 각 Notion DB(아래 §4 id) fetch.

## 2. 실행 단계 (A→E)
**A. git `docs/작업계획서.md` 최신화**
- 신규 커밋으로 완료된 작업 행 신호등 갱신(예: ⚪/🟡/🔵 → 🟢).
- 진행 현황 메모에 핵심 변경 1~2줄 추가, 필요 시 백로그 갱신.
- 끝의 `*마지막 sync:*` 를 오늘 날짜로.

**B. Notion 작업계획서 페이지 신호등 ← git 일치**
- 페이지 `3702f2c9-f358-80bf-8bf5-fb7aac0a4d22`. **갱신된 git 신호등을 그대로** 동일 작업 행에 반영(모든 Phase·David/수희 트랙).
- 셀 교체: `update_content` 로 `<td>STATUS</td>\n<td>작업명</td>` 단위(작업명 고유 → 안전). 작업명 표기가 git↔Notion 다르면 Notion 실제 텍스트에 맞춤.

**C. Notion 작업 DB 상태 ← git 신호등 매핑**
- DB `14c892b8-1475-4637-b80a-3446d307c06d`. 각 작업 페이지 `상태` 를 git 신호등에 맞춰 갱신(§5 매핑). 메모에 완료 컨텍스트(예: `완료 2026-MM-DD, PR #N, 핵심 변경`).
- git 에 없는 작업 DB 항목 → 보고만(임의 변경 금지).

**D. 개발 일지 DB — 신규 push 별 1줄(필수)**
- DB `4c3f5301-363e-4ec3-844f-5c098a790110`. §1 에서 수집한 커밋/PR 각각(또는 묶음 단위)으로 항목 추가. 속성 §4 참조. 커밋 링크 `https://github.com/shjang9714-art/insight-out/commit/<sha>`.

**E. 이슈 & 공유 DB — 마일스톤일 때만(선택)**
- DB `5e5f7e0b-c883-4589-b0fa-c1f993f4895c`. 기능 완료·중요 결정 등 공유 가치가 있을 때 `유형=공유`(또는 `결정사항`) 글 1건.

**F. git 변경 커밋·푸시 (필수 — 빠뜨리면 git↔Notion 어긋남)**
- A 에서 편집한 `docs/작업계획서.md` 를 **반드시 commit + push** 한다(Sonnet 이 직접 수행). Notion 은 커넥터로 즉시 반영되지만 git 파일 편집은 push 해야 origin/main 에 반영됨 → **둘을 같은 루틴 안에서 동시에 마무리.**
- 커밋 예: `docs: 작업계획서 신호등 동기화(<대상>)` → `git pull --rebase && git push`.
- `.git/index.lock` 있으면 `rm -f .git/index.lock` 후 재시도.
