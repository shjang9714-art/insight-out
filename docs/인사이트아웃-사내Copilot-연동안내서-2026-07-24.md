# 인사이트 아웃 ↔ 사내 Copilot Studio 연동 안내서

> 대상: 사내 Copilot Studio·Power Automate·Teams 봇 구축 담당
> 목적: 인사이트 아웃 데이터를 사내 에이전트가 이해·활용하도록 연결 규격·데이터 규격·MCP 도구를 정리
> 판: 2026-07-24 (갱신 — 읽기·아카이브 도구 421·422·423 배포 반영) · 작성: 인사이트 아웃팀

---

## 1. 목적과 방향

**인사이트 아웃**은 LG U+ 기업사업의 사내 시장 인텔리전스 플랫폼입니다. 뉴스·유튜브 수집, 본문 보강, AI 전략 리포트, 경쟁사 주간 분석, 데일리 인사이트, 모닝브리핑, 뉴스레터, 키워드·기업 분석을 하나의 흐름으로 제공합니다.

**이번 연동의 목표**는 사내 VDI 환경의 **MS Teams / M365 Copilot 봇**이 인사이트 아웃의 데이터를 직접 질의·요약·활용하게 만드는 것입니다. 예: "오늘 주요 동향 알려줘", "AICC 최근 뉴스 요약", "경쟁사 이번 주 동향", "이번 주 전략 시사점 5개".

**방향(핵심 원칙):**
- 연결은 **MCP(Model Context Protocol) 표준**으로 합니다. 인사이트 아웃이 **MCP 서버**를 제공하고, 사내 Copilot Studio 에이전트가 이를 **도구로 소비**합니다.
- **읽기 중심 + 발행분만.** 에이전트는 서비스에 발행된 데이터만 읽습니다(초안·내부 데이터 비노출).
- **사내 데이터는 밖으로 나가지 않습니다.** 인터넷 접근(인사이트 아웃 호출)은 전부 MS 클라우드(Copilot Studio·Power Automate)가 대행하고, 결과는 M365에 착지합니다.

---

## 2. 연동 아키텍처 (VDI 제약 반영)

VDI는 외부 인터넷에 직접 나가지 않습니다. 따라서 인터넷을 향한 호출은 전부 **MS 클라우드**가 수행하고, VDI는 M365 앱으로 결과만 소비합니다.

```
[사내 VDI]                         [MS 클라우드]                    [공개 인터넷]
 Teams / M365 Copilot  ◀──M365──  Copilot Studio 에이전트  ──MCP──▶  인사이트 아웃
 (봇 소비)                          Power Automate (스케줄·게시·메일)   /api/mcp
                                    │                                (Bearer 토큰)
                                    └─▶ SharePoint / Teams 채널 (결과 착지)
```

- 확인된 전제: VDI 안에서 **Teams·SharePoint·Outlook·Copilot·Power Automework 사용 가능**, VDI Copilot이 외부 콘텐츠 수집 가능(= MS 클라우드측 검색이 VDI 외부차단과 무관하게 작동).
- 따라서 인사이트 아웃 측이 VDI egress를 위해 준비할 것은 없습니다. **온프레미스 게이트웨이 불필요.**

## 3. 연결 규격 (사내에서 붙일 때)

| 항목 | 값 |
|---|---|
| MCP 서버 URL | `https://insight-out-app.vercel.app/api/mcp` |
| 전송(Transport) | **Streamable HTTP** (SSE 아님 — Copilot Studio는 2025-08 이후 SSE 미지원) |
| 인증 방식 | **API 키 (헤더)** |
| 헤더 이름 | `Authorization` |
| 헤더 값 | `Bearer <인사이트아웃 발급 토큰>` (Bearer + 공백 + 토큰) |
| 토큰 종류 | 인사이트 아웃 MCP 토큰, **read 스코프**(읽기 전용), 만료 설정 |

### Copilot Studio "MCP 서버 추가" 설정값
- **서버 이름**: `Insight Out`
- **서버 설명**: `인사이트 아웃 시장 인텔리전스. 뉴스·이슈·기업·리포트·경쟁사 분석을 검색·조회한다.`
- **서버 URL**: `https://insight-out-app.vercel.app/api/mcp`
- **인증**: API 키 / **유형**: 헤더 / **헤더 이름**: `Authorization` / **값**: `Bearer <토큰>`
- **코드 세부정보**: 사용 안 함

> 토큰은 인사이트 아웃팀이 발급해 전달합니다. **Azure Key Vault 또는 Power Platform 환경변수**에 보관하고, 플로·에이전트 정의에 평문으로 넣지 마세요.

## 4. 데이터 규격 (핵심 엔티티)

모든 응답은 **발행분만**, **PII·내부 필드 제외**입니다.

| 엔티티 | 테이블 | 주요 필드 | 발행 조건 |
|---|---|---|---|
| 콘텐츠(기사/영상) | contents | id, title, summary_ko, body(번역/원문), category(news·youtube·report·opinion), published_at, original_url, source, matched_groups·matched_keywords, **sentiment(논조)**, **lgu_impact(위기/기회/관망)** | status=published |
| 이슈 | issues | id, title, summary, status, created_at | published |
| 기업·기관 | entities | id, canonical_name, aliases, type | — |
| AI 전략 리포트 | ai_reports | id, title, summary, type, publisher, published_at, topic, 본문, keywords(근거) | published_at IS NOT NULL |
| 경쟁사 주간 브리핑 | competitor_weekly_reports | week_start/end, summary, overall_impact(위기/기회/관망), emerging_topics, sections(moves·impact·implication·citations…) | status=published |
| 데일리 인사이트 | daily_insights | day_of, category, headline, summary_ko, market_trend, competitor_trend, implication, why_it_matters, implication_lenses(기회/위기/액션), source_articles | status=published, needs_review=false |
| 모닝브리핑 | briefings | briefing_date, title, script, audio_url, highlights({content_id, insight}) | status in (published, archived) |
| 엔티티 이벤트 | entity_events | event_date, signal_type, headline, detail, **biz_impact(위기/기회/중립)**, biz_impact_reason, citations | entity_id 지정 조회 |
| 기업 문서/DART | company_documents | title, summary_ko, original_url, published_on, entityName, doc_type(IR·전략·ESG·기술 등), is_official, dart_rcept_no | review_status=none, public |
| 뉴스레터 | newsletter_issues | id, sent_on, subject, content_ids(수록 기사), recipient_cnt, payload(카드·티저 본문) | status in (sent, partial) · **수신자 PII 미조회** |
| 아카이브(개인) | archives · archive_items | 아카이브명, 항목(content_id·note·기사 제목·URL) | **토큰 계정(actor.userId) 것만** |

**공통 제외 필드**(에이전트에 노출 안 됨): 작성자 user_id, 내부 LLM 프롬프트, 원천 근거 id 배열, 모델명, 내부 심사 메모·해시·파이프라인 타임스탬프.

## 5. MCP 도구 명세

에이전트가 호출할 수 있는 도구입니다. **[현재]** = 사용 가능. (2026-07-24 배포 완료: 421 분석 산출물 · 422 뉴스레터 · 423 아카이브)

### 읽기 도구 (read 스코프)
| 도구명 | 목적 | 주요 입력 | 출력(요약) | 상태 |
|---|---|---|---|---|
| `content_search` | 콘텐츠 검색 | query, group, category, days(기본30), limit(≤50) | 기사/영상 목록(제목·요약·날짜·분류·태그) | [현재] |
| `content_get` | 콘텐츠 본문 조회 | id(uuid), max_chars(기본6000) | 본문 전문 + 메타(논조·LGU임팩트·키워드) | [현재] |
| `issue_list` | 이슈 목록 | query, status, limit | 이슈 목록 | [현재] |
| `entity_list` | 기업·기관 조회 | query, limit | 기업/기관 목록 | [현재] |
| `ai_report_list` / `ai_report_get` | 발행 AI 전략 리포트 | (list) type·limit / (get) id | 리포트 요약·본문·근거 | [현재] |
| `competitor_weekly_list` / `_get` | 경쟁사 주간 브리핑 | (get) week | 주간 요약·영향·섹션 | [현재] |
| `daily_insight_list` / `_get` | 데일리 인사이트 | day·limit / id | 헤드라인·시사점·렌즈 | [현재] |
| `briefing_list` / `_get` | 모닝브리핑 | date·limit / id | 스크립트·하이라이트·오디오 URL | [현재] |
| `entity_events` | 엔티티 이벤트(위기/기회) | entity_id | 이벤트 타임라인 + biz_impact | [현재] |
| `company_document_list` / `_get` | 기업 문서·DART | entityId·docType | 문서 목록·요약·원문 | [현재] |
| `newsletter_list` / `newsletter_get` | 발송 뉴스레터 | (list) limit / (get) id | 제목·발송일·수록 기사·본문 카드 | [현재] |

### 아카이브 도구 (archive 스코프 — 별도 토큰)
| 도구명 | 목적 | 주요 입력 | 비고 | 상태 |
|---|---|---|---|---|
| `content_archive` | 발행 기사를 토큰 계정 아카이브에 담기 | content_id, note?, archive_name? | 중복 방지. 토큰 계정(1개) 단위 | [현재] |
| `archive_list` | 내 아카이브 조회 | archive_name?, limit? | 본인 계정만. content_id→content_get 연결 | [현재] |

### 쓰기 도구 (reports/ops 스코프 — 필요 시)
| 도구명 | 목적 | 비고 |
|---|---|---|
| `report_create` / `report_update` | 전략보고서 초안 작성·수정 | reports 스코프. **에이전트가 보고서를 작성·저장하는 경로**. 초안 default 비공개(publish 스코프 없으면 노출 불가) |
| `report_list` | 작성 워크플로용 리포트 목록 | reports 스코프 |
| `ops_list`·`ops_get`·`ops_create`·`ops_update` | 작업·요청·공지 기록 | ops 스코프 |
| (후속) 정식 보고서 생성 파이프라인 트리거 | 서비스 정식 AI 리포트 자동 생성 | **Supabase 비동기 워커 도입 후 제공.** 그전까지 보고서 생성은 위 `report_create`(에이전트 작성)로 대체 |

> **읽기용 봇은 read 토큰 하나면 충분**합니다. **아카이브(archive)·리포트 작성(reports)·작업기록(ops)** 등 쓰기 동작은 read 토큰과 **분리된 별도 스코프 토큰**으로만 가능합니다(봇이 실수로 발행·오염하지 못하게). 스코프는 인사이트 아웃 토큰 발급 화면에서 선택합니다.

## 7. 보안·거버넌스
- **읽기 전용·발행분만**: 토큰은 read 스코프, 각 도구가 발행 조건을 직접 적용. 초안·내부 데이터·PII 비노출.
- **최소 권한**: 봇 용도에 필요한 스코프만. 쓰기(아카이브·보고서 생성)는 별도 토큰.
- **토큰 관리**: 만료 설정, 클라우드 시크릿 보관, 유출 시 즉시 폐기. 인사이트 아웃은 토큰→사용자 매핑으로 호출 감사 추적.
- **한 방향(Pull-only)**: 사내 데이터는 인사이트 아웃으로 전송되지 않음.
