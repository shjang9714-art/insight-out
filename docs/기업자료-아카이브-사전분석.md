## 0. 확정 범위 (David)
MVP를 아래 순서로 **얇은 수직 슬라이스**부터:
1. **DART 공시 API** 자동수집(저작권 안전·구조 명확)
2. 기존 **리포트 PDF 파이프라인에 `기업자료` category 얹기** — **단, 어드민에서 별도 관리**(리포트와 분리된 관리 화면).
3. **entity 연결 + 상세**(문서↔기업 양방향)
4. **IR 자료실 감시**(HTML watch)
5. **사용자·어드민 수동 업로드 "통"** — 소개서/백서/피치덱, 그리고 헤드리스·버전비교로 자동수집이 어려운 자료를 **사람이 수집해 올릴 수 있는 상시 경로**를 처음부터 마련.

소개서/백서/피치덱 **자동수집**·헤드리스 브라우저·버전 자동비교·통합 질의(RAG)는 MVP 밖(수동 업로드 통으로 우선 수용).

## 2. 아키텍처 결정 (확정)

**결정 1 — contents 재사용 + 1:1 확장 테이블.**
문서는 `contents`의 **새 category `기업자료`** 행으로 저장(검색·중복·PDF·북마크·entity연결 인프라 공유). 문서 전용 필드는 **신규 `company_documents`**(content_id 1:1)로 분리 — contents 오염 방지.
- `company_documents(content_id PK/FK, entity_id, doc_type, doc_group, is_official, source_kind, page_count, published_on, official_status, version_group_id, prev_content_id, ingest_status, review_status …)`
- category enum에 `기업자료` 추가(마이그레이션).

**결정 2 — `entities`가 캐논 기업키.**
문서↔기업은 `content_entities`(→entities)로 연결. `curated_companies`(주요기업/경쟁사/스타트업)는 **분류 레이어**로만 사용(entities에 매핑; entity_id FK 유무는 253 스키마 확인해 없으면 name/alias 매핑). 기업정보·기업자료 **이중관리 금지**(제안서 10장).

**결정 3 — 수동 업로드 통을 1급 경로로.**
자동수집(DART/IR)과 **동일한 문서 파이프라인**에 들어오는 업로드 엔드포인트. 업로더는 `source_kind='MANUAL'`·`review_status='검토대기'` 기본. 사용자 업로드는 **조직 전용/검토 후 공개**, 어드민 업로드는 즉시 공개 가능. 저작권 게이트(아래) 적용.

**결정 4 — 어드민 별도 관리(David).**
`기업자료`는 리포트 어드민과 **분리된 관리 화면**(`/admin/company-documents`): 소스 레지스트리·수집 검토함·업로드 검토·상태 관리. 리포트 업로드 폼은 재사용하되 라우트·목록·검토는 별개.

**결정 5 — 저작권 기본값(리스크 최우선).**
기본은 **메타+AI요약+원문링크**. **원문 파일 저장은 (a)DART 공시 (b)사전승인 공식도메인 자료**로 한정. 소개서/백서/피치덱·재업로드는 링크·메타만(원문 저장은 명시 승인 시). `official_status`·`공개범위`로 관리, takedown/비공개전환 경로 처음부터.

## 3. MVP 슬라이스 → 지시서 분할(안)

- **355-A (SQL+수집)** — DART OpenAPI 커넥터: 기업별 공시(사업/분기/주요사항보고서) 목록·문서 수집 → `contents(category='기업자료')`+`company_documents` 적재, entity 매칭, 자동공개(공시 한정). `sources`/`crawl_logs` 재사용 + 기업별 DART corp_code 매핑. **신규 SQL**(category enum·company_documents·document_sources).
- **355-B (화면+category)** — `기업동향`에 `기업·기술 자료` 탭 신설(뉴스와 주간브리핑 사이). 기업별/최신/유형별 보기·기업구분/유형 필터·상단 지표·이번주 신규. 상세 2패널(좌 분석·우 PdfViewer 재사용).
- **355-C (어드민+업로드 통)** — `/admin/company-documents`: 소스 레지스트리·수집 검토함·**수동 업로드 통(어드민)** + **사용자 업로드 경로**(조직전용·검토대기). 저작권 게이트·상태 관리.
- **355-D (entity 연결·상호링크)** — 주요기업 상세에 `자료` 영역, 뉴스 상세↔기업자료 양방향, 주간브리핑 "활용된 자료" 출처. `content_entities`·`ai_report_sources` 재사용.
- **355-E (IR 자료실 감시)** — 기업별 HTML 자료실 watch + PDF 링크 탐지 → 문서 파이프라인. 실패 시 검토대기.

버전비교·헤드리스·RAG·소개서 자동수집은 **356+**(별도).

## 4. 리스크 / 미결정
- **저작권**(최우선): 원문 저장 범위·takedown·공개범위 정책 확정 필요. 결정 5가 기본선.
- **DART corp_code 매핑**: entities↔DART 고유번호 매핑표 필요(초기 수동 시드).
- **curated_companies의 entity_id FK 유무**(253 스키마): 있으면 직결, 없으면 name/alias 매핑 — 355-A 착수 시 확인.
- **Storage 용량·비용**: 원문 PDF 저장 대상이 늘면 비용↑ → 링크우선 원칙이 비용도 억제.
- **사용자 업로드 악용·유해파일**: 업로드 통에 파일검사·검토대기 필수(제안서 18·24장).

### 해외 공시(EDGAR) 판단 — 보류
사용자가 LG U+ B2B 담당자라 실제 경쟁세트는 KT·SKT(DART 커버). NVIDIA·MS·AWS는 경쟁사보다 파트너·생태계에 가깝고, 10-K/10-Q는 영문·글로벌 전반이라 한국 B2B 신호 밀도가 낮다. 커넥터는 저마찰이나 downstream(영→한 요약·추출) 비용이 큼 → **MVP 제외**. 넣더라도 소수 타깃(3~4곳)만, 영문 요약 파이프라인 준비 후.

### 거버넌스(발견 API 공통)
- 발견 결과는 **원천이 아니다** → `review_status='검토대기'`, `is_official=false`, **원문 저장 금지(링크·메타만)**. 어드민 승인 시에만 승격, 원문 저장은 공식도메인 한정(결정 5).
- **쿼터 가드 필수**: 네이버 일 25k·Tavily 월 1k를 넘지 않게 호출 카운터/캐시. Tavily는 어드민 수동 트리거 전용(자동 크론 금지).
- 모든 키는 **팀이 Vercel 환경변수 등록**(코드·문서에 비밀키 금지).
- 발견 대상 문서 클래스: 네이버/Tavily = 기업 공식·준공식 자료 후보(doc_group 회사및사업/투자및경영). arXiv/SS/GitHub = **기술·연구 자료**(doc_type='기술·연구', 링크전용) — 기업 아카이브와 같은 파이프라인이되 별 doc_type로 구분.
