## 0. 왜 GDELT
- **무료.** DOC API는 키 불필요, BigQuery는 무료 티어(1TB/월) 안에서 파티션·컬럼 프루닝으로 처리 가능.
- **원문 URL 제공** → 우리 보강이 원문에서 본문을 가져와 425/426 게이트 그대로 탐(빅카인즈처럼 원문URL 불확실·유료 문제 없음).
- **날짜·언어·매체 필터** → 한국 기사 + 기간 지정 가능.
- **풍부한 메타**(테마·톤·인물·조직) → "질적 데이터" 축적 여지(선택적으로 신호로 저장).

## 1. 세 경로 (역할 분담)

### (A) GDELT DOC 2.0 API — 앞으로/최근(≤3개월), 키 불필요 ★ 즉시
- `https://api.gdeltproject.org/api/v2/doc/doc?query=...&mode=ArtList&format=json&timespan=...&sourcelang:korean`
- 반환: url, title, domain, seendate, language, sourcecountry. 쿼리당 ≤100.
- **네이버(430)와 같은 검색 백엔드로 병행** — 키워드 시드로 조회 → RawItem → processCrawlItem.
- 무료·키 없음 → **바로 붙일 수 있음**(431).

### (B) GDELT BigQuery gkg_partitioned — 과거 6개월 소급 ★ (GCP 키 필요)
- 테이블 `gdelt-bq.gdeltv2.gkg_partitioned`(날짜 파티션). **비용 관리 필수**:
  - `_PARTITIONTIME` 로 **월 단위 청크**(2026-01, 02, …) — 6개월을 한 번에 안 긁고 월별로.
  - **컬럼 프루닝**: `DocumentIdentifier`(URL), `DATE`, `SourceCommonName`(매체)만.
  - **한국 필터**: `SourceCommonName` 이 한국 매체 도메인(.kr·조선·동아·매경 등 리스트) or V2Locations 한국.
  - **키워드/테마 필터**: `V2Themes`·`AllNames`·`DocumentIdentifier` 가 관심 키워드 매칭(시장·경쟁사·통신 등) — 전량 아닌 관련분만.
- → 월별 쿼리로 한국 관련 기사 **URL 목록** 확보 → processCrawlItem(stub) → 보강 → 게시.
- **SQL-free**: 커서 테이블 불필요 — 6개월 창을 주기적으로 재쿼리하고 **dedup(canonical/hash)이 기존분 스킵**. 재실행 멱등.
- 필요: **GCP 프로젝트 + BigQuery + 서비스계정 키**(env). 무료 티어 내(월별·프루닝).

### (C) Google Custom Search — 보조(선택, 저우선)
- 무료 100/일이라 대량 백필엔 부적합. 특정 공백 보완용 정도. **이번엔 보류**(A·B로 충분).

## 2. 파이프라인 재사용 (공통)
- A·B 모두 **URL 발견 → RawItem → `processCrawlItem`** (isSearchSourced=true) → 425 flip(pending) → 보강(원문 본문) → **425/426 관련도 게이트 통과분 게시**.
- 중복은 canonical/hash 자동 흡수(네이버·Google·RSS·GDELT 겹쳐도 1건).
- **질적 데이터(선택 확장)**: GDELT V2Tone·V2Themes 를 신호로 저장하고 싶으면 별도 컬럼/후속(지금은 발견만).

## 4. 리스크·관리
- **BigQuery 비용**: 파티션+컬럼프루닝+월청크로 무료 티어 유지. 쿼리마다 스캔 바이트 로깅. 한국·키워드 필터로 스캔량↓.
- **GDELT 한국 커버리지**: 글로벌 DB라 한국 매체 커버가 고르지 않을 수 있음 — 매체 도메인 리스트로 보정, 네이버가 보완.
- **관련도**: 모든 GDELT 발견분도 425/426 게이트 통과분만 게시(off-topic 유입 없음).
- **레이트·타임아웃**: DOC 쿼리 소량·바운드, BigQuery 월청크 바운드.
