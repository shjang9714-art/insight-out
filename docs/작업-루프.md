## 2. 루프 (1 사이클)

```
① Opus  →  지시서 작성        docs/sonnet-지시서/NN-제목.md  (로컬, 커밋 X)
② David →  Sonnet 에 위임      Claude Code 가 로컬 지시서를 직접 읽음 (한 줄 붙여넣기)
③ Sonnet→  구현 + 완료 보고     "무엇을 했는지 + 결과 보고" (§4 양식)
④ David →  보고를 Opus 에 전달   Cowork 로 복붙
⑤ Opus  →  검증 + 판정         ✅통과 / 🔧수정요청(다음 지시서)
⑥ ✅ 시 David "커밋해" 트리거 → Sonnet 이 지시서+코드 커밋·푸시 → /api/version 배포확인
─────────────── (여러 사이클 반복) ───────────────
⑦ 묶음 종료 시 1회 → David "기록 동기화 루틴대로" → Sonnet 이 작업계획서·Notion·개발일지 반영+푸시
```

핵심 (중복·혼란 방지):
- **git(커밋·푸시·머지)은 Sonnet 전담.** David 는 위임·전달·"커밋해" 트리거만. Opus 는 git 안 함.
- **기록 동기화는 작업 묶음 끝에 ⑦에서 1회만.** 매 작업마다 X (루틴이 지난 sync 이후 커밋 전부 수집). Opus 도 매 작업 끝에 반복 언급 금지.
- **지시서는 위임 전 커밋 안 함(①).** Sonnet 이 로컬 파일을 직접 읽음 → 코드와 함께 ⑥에서 커밋.
- **③ 보고·⑤ 검증은 매 사이클 필수. 검증 통과 전 푸시 금지.**
- 예외: **수희가 Supabase 에서 실행할 SQL 핸드오프**는 미리 커밋·푸시해 수희가 받게 한다.

## 3. David 가 쓰는 복붙 명령

### 3.1 Sonnet 에 위임 (Claude Code 에 붙여넣기)


### 3.2 Sonnet 보고를 Opus 에 전달 (Cowork 에 붙여넣기)
```
Sonnet 작업 완료 보고다. 검증해줘:
[Sonnet 보고 내용 붙여넣기]
```

### 3.3 git — **Sonnet 전담** (⑤ 검증 통과 후, 지시서+코드 묶어서)
David 는 커밋하지 않고 "검증 통과 — 커밋·푸시해" 한 줄만 준다. Sonnet 이 실행:
```bash
rm -f .git/index.lock          # 스테일 락 있으면
git add -A                     # 지시서 + 코드 함께
git commit -m "<type>: <한국어 요약>"
git pull --rebase && git push
```
> 위임 전에는 커밋하지 않는다(Sonnet 이 로컬 지시서를 읽음). 배포 확인은 `/api/version`(상세: [`배포-검증-프로세스.md`](./배포-검증-프로세스.md)). 기록 동기화는 묶음 끝에 1회(⑦).

## 4. Sonnet 완료 보고 양식 (지시서마다 동일)

```
## 완료 보고 — [지시서 번호·제목]
- 변경 파일: <경로 목록>
- 한 일: <3~5줄 요약>
- 완료 조건 충족: [x] 항목별 체크
- 검증 결과: tsc / lint / build 통과 여부 + 로그 핵심
- 미해결·판단보류: <있으면. 없으면 "없음">
```

## 5. Opus 검증 기준 (매 사이클)

1. **완료 조건** 항목 전부 충족했는가 (지시서의 체크리스트 대조)
2. **설계 의도**대로인가 (스키마/타입/네이밍 일치)
3. **실제 검증** — Opus 가 직접 `tsc`/파싱/diff 재확인 (보고를 믿지 않고 재현)
4. 판정: ✅ 통과 → 머지 OK / 🔧 수정 → 다음 지시서로 차이만 지시
