# 설계 — 관심기업 "기업 동향" 상세 재구상

David 피드백(2026-07-09): 관심기업 카드는 핵심·시사점·근거를 보여주는데, **"자세히 보기"를 누르면 기사 1건으로 점프** → "기업 동향"이 아니라 "단순 최신 뉴스"가 됨. 심각. 카드 내용을 기반으로 **풍성한 상세 + 근거 자료**를 보여줘야 함. 단, 모든 관심기업을 매주 생성 가능한지 스케일 고민 필요.

---

## 1. 현행 진단 (검증된 코드 사실)
- **AI 기업 요약은 이미 생성됨** — `generateCompanyInsightCards`(`lib/insight/generate.ts`)가 워치리스트 회사별 최근 기사를 LLM에 넣어 `insight_cards`(scope='company', topic=회사)로 저장. 필드: `headline`(부제)·`card_headline`(핵심)·`implication`(시사점)·`citations[{content_id,quote}]`(근거)·`source_content_ids`. **cron `ai-refresh`에서 배치 생성.** minArticles 미만 회사는 스킵.
- **문제의 핵심**: `getCardDetailHref`(card-meta.ts)가 카드 제목·"자세히 보기" 클릭 시 **`/dashboard/contents/{첫 source 기사}`** 로 보냄 → 기사 1건. **인사이트 카드 전용 상세 페이지가 없음**(현재 라우트 미존재).
- 즉 **데이터(요약·시사점·근거)는 다 있는데, 그걸 풍부하게 펼칠 상세 화면이 없어서** 기사로 떨어지는 구조적 갭.

## 2. 설계 제안

### A0. 관심기업 요약 뷰 재구성 (David 결정 2026-07-09)
- **기간 그룹핑 폐지** → **회사별 카드 그리드**로. 관심기업은 "사용자가 고른 회사"가 주인공이므로 회사 단위로 재구성.
  - **회사당 최신 동향 카드 1개**(가장 최근 기간의 company 카드)를 그리드에 노출. 회사가 여럿이면 반응형 그리드(`grid-cols-2 lg:grid-cols-3`), 정렬 = 내 관련도 → 최신순.
  - 기간은 그룹 헤더가 아니라 **카드 내 작은 날짜 라벨**(예: "7.3~7.9" 또는 "3일 전") → sparse period(카드 1개) 문제 근본 해소.
  - 카드 = **압축 요약**(회사명 + 핵심 card_headline + 시사점 1~2줄 clamp + 날짜 + 중요도/내관련도 배지). 상세한 근거·전문은 상세 페이지로.
- **"자세히 보기" 버튼 제거** → **카드 전체 클릭**으로 상세 이동.

### A. 기업 동향 상세 페이지 신설 (핵심)
카드 클릭·"자세히 보기" → **`/dashboard/insights/[cardId]`**(신규). 구성:
- **헤더**: 회사명(topic) + 기간 + 중요도/내 관련도 배지.
- **핵심**(card_headline) 크게 + **부제/맥락**(headline).
- **시사점**(implication) — LG U+ 관점 함의, 전문(카드에선 3줄 clamp였던 것 풀어서).
- **근거 자료 섹션(핵심 요구)**: `citations` 전부를 **인용문 + 출처 기사 제목·매체·링크**로 나열 → "왜 이렇게 분석했나"를 근거로 제시. `source_content_ids` 중 인용 안 된 기사도 "참고 기사" 목록으로.
- **관련 키워드**(computeRelatedKeywords) → 토픽 페이지.
- (선택) **최근 기사 타임라인**: 그 회사 관련 최근 N건(날짜순) — 동향의 시간 흐름.
- 하단 "관심기업으로 돌아가기".

### B. 라우팅 교정
- `getCardDetailHref` → **카드 상세(`/dashboard/insights/[id]`)** 로 변경. (근거 섹션 안의 개별 기사는 여전히 `/dashboard/contents/{id}`.)
- ⚠️ `getCardDetailHref`는 **관심기업·AI인사이트 헤드라인·경쟁사 동향분석 등 공유** → 카드 상세 페이지가 그 카드들(scope industry/company) 모두를 렌더하면 전 사용처가 함께 개선됨(일석이조). 회귀: 상세 페이지가 없는 카드가 없도록 폴백(근거 기사로).

### C. 요약 풍부화 (선택 · 2단계)
- 현재 1카드 = 1 헤드라인+시사점. "동향"답게 **2~3개 주요 전개(움직임) + 종합 시사점** 구조로 확장하려면 생성 프롬프트·스키마 변경 필요(예: `developments[]`). 
- **1단계는 A/B(상세페이지+라우팅)만으로도 "기사 점프" 문제 해결** — 기존 카드가 근거와 함께 풍부하게 보임. C는 그 다음 고도화.

## 3. 생성 카뎐스 · 스케일 (David 고민 반영)
- **카드는 회사 단위 공유**(scope=company, topic=회사) — 유저×회사가 아니라 **distinct 회사 수**만 생성. 워치리스트 dedup + 인기순 이미 적용.
- **minArticles 게이트**로 기사 적은 회사는 자동 스킵(낭비 방지).
- **238(sambanova/mistral 편입)로 무료 LLM 용량 크게 늘어남** → 배치 부담↓.
- **권장 전략**:
  1. **주 1회 배치**(현 cron을 주간 기업카드 갱신으로): 기사 충분한 회사만, 인기순 **top-N 캡**(예: 상위 40~60개사).
  2. **신규 관심기업 추가 시 온디맨드 생성**(WatchlistManager 추가 직후 그 회사 1건 생성 트리거) — 사용자가 방금 넣은 회사가 비어보이지 않게.
  3. 오래된 카드(기간 지난)는 다음 배치에서 갱신(upsert onConflict period,scope,topic).
- **비용 감각**: 회사당 주 1 LLM 호출. 회사 수십~백이면 주당 수십~백 호출 → 238 무료 용량으로 충분. (분류·요약과 라우팅 분산)

## 4. 결정 (2026-07-09 David 확정 / 잔여)
- ✅ **요약 뷰 = 회사별 카드 그리드**(기간 그룹핑 폐지, 회사당 최신 카드 1개, 날짜 라벨).
- ✅ **"자세히 보기" 버튼 제거 → 카드 전체 클릭**.
- ✅ **상세 스코프 = 카드 1건 상세**(그 회사 최신 카드 + 근거). (회사 종합 뷰·타임라인은 후속 고도화.)
- 잔여 결정:
  1. **요약 풍부화(C)**: 1단계는 상세 페이지만(기존 카드 재사용), 다중 전개 생성은 후속? (추천: 후속)
  2. **생성 카뎐스**: 주 1회 top-N 배치 + 신규 관심기업 온디맨드 — top-N 값(예: 40~60)?

## 5. 추천 (내 의견)
- **1단계 = A(카드 1건 상세 `/dashboard/insights/[id]`) + B(라우팅 교정)** — 데이터 이미 있으니 **가장 빠르게 "기사 점프" 문제 해결**, 전 카드 사용처 동시 개선.
- **2단계 = C(다중 전개 요약)** + 회사 종합 뷰 — 고도화.
- **생성**: 주 1회 top-N 배치 + 신규 관심기업 온디맨드.

이 방향(1단계 먼저) 확정되면 구현 지시서(상세 페이지 + 라우팅 + 온디맨드 생성)로 뽑겠습니다.
