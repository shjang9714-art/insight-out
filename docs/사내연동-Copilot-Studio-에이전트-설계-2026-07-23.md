# 인사이트 아웃 ↔ 사내 Copilot Studio 에이전트 연동 설계 노트

> 작성: 플래너(Opus) · 2026-07-23 · 디렉터 구상("인사이트 아웃 데이터를 사내 전용 데이터와 결합해 사내 특화 에이전트 구현")
> 확정 방향: **M365 / Copilot Studio** 런타임
> 성격: 아키텍처·통합 설계(코드 지시서 아님). 인사이트 아웃 측 변경은 최소.

---

## 0. 목표와 원칙

**목표.** 인사이트 아웃의 시장 인텔리전스(콘텐츠·이슈·기업·전략보고서)를 **사내에서만 볼 수 있는 데이터**와 결합해, 사내망 안에서 도는 **사내 특화 에이전트**가 두 소스를 함께 활용한다.

**축이 되는 보안 원칙 — 한 방향(Pull-only).**
- 사내 에이전트가 인사이트 아웃을 **읽기 전용으로 당겨온다.**
- **사내 데이터는 Vercel(외부)로 절대 나가지 않는다.** 결합·추론은 전부 사내(M365 테넌트) 안에서.
- 인사이트 아웃 토큰은 **`read` 스코프만**(쓰기·발행 불가) → 통합이 뚫려도 사내 데이터 유출·서비스 오염 둘 다 구조적으로 불가.

## 1. 아키텍처 (4계층)

```
[사내망 / M365 테넌트]                              [공개 인터넷 / Vercel]

┌─ 에이전트 계층 ────────────────┐
│  Copilot Studio 에이전트        │
│   · 지시문(사내 특화 페르소나)   │
│   · 지식: 사내 데이터            │
│   · 액션(툴): MCP               │──(A) MCP streamable HTTP ──▶  인사이트 아웃
└───────────┬────────────────────┘     Bearer(read 토큰)           /api/mcp
            │                                                    (콘텐츠·이슈·기업 조회)
┌─ 데이터 계층 ──────────────────┐
│  Dataverse / SharePoint /      │
│  내부 SQL  (사내 전용 데이터)    │◀─(B) 선택: Power Automate ETL ─ 인사이트 아웃
└───────────┬────────────────────┘     (배치로 당겨와 결합/RAG)     /api/mcp or read
            │
┌─ 오케스트레이션 계층 ───────────┐
│  Power Automate 플로            │
│   · 트리거·스케줄·승인          │
│   · Teams/메일 배포            │
└───────────┬────────────────────┘
            │
┌─ 표현 계층 ────────────────────┐
│  Teams / M365 Copilot / 웹챗    │  ← 사용자는 여기서 에이전트와 대화
└────────────────────────────────┘
```

**두 결합 경로 (A/B — 병행 가능):**
- **(A) 라이브 MCP** — 에이전트가 질의 시점에 인사이트 아웃 MCP 툴을 호출. 최신·오케스트레이션형. 대화형 에이전트 기본.
- **(B) 배치 동기화** — Power Automate가 인사이트 아웃 데이터를 사내 저장소로 당겨와 사내 데이터와 물리 결합(RAG·오프라인·대량 조인). 실시간 인터넷 접근 제약이나 조인 성능이 필요할 때.

권장: **(A)로 시작**(구현량 최소, 이미 MCP 완비), 필요가 확인되면 (B) 추가.

## 2. 인사이트 아웃 측 — 변경 최소(사실상 0 코드)

이미 있는 것(확인함):
- `/api/mcp` — 운영 중 MCP 서버(`mcp-handler ^1.1.0`, streamable HTTP). read 툴: **콘텐츠 검색·본문 조회·이슈 목록·기업/기관 조회**.
- 토큰 인증 — `mcp_tokens` 테이블, **1토큰=1user_id + 스코프**, 만료(`expires_at`)·폐기(`revoked_at`) 지원. 토큰→user_id라 **감사 추적** 가능.
- 스코프 — `read` / `ops` / `reports` / `publish`.
- 토큰 발급 엔드포인트 — `/api/admin/mcp-tokens`(어드민 전용).

**해야 할 일 딱 하나:**
1. `/api/admin/mcp-tokens`에서 **통합 전용 토큰을 `read` 스코프만** 부여해 발급(ops/reports/publish 제외).
2. **만료 기간 설정**(예: 90일) + 갱신 절차 정하기.
3. 발급 토큰은 **사내 시크릿 저장소**(Azure Key Vault / Power Platform 환경 변수)에 보관. 플로·에이전트 정의에 평문으로 넣지 않기.

**붙이기 전 점검 1개(전송 호환):**
- Copilot Studio는 2025-08 이후 **SSE 전송을 지원 안 함 → streamable HTTP만.** `mcp-handler`가 streamable HTTP(POST)를 노출하므로 호환되나, 연결 시 Copilot Studio가 정상 handshake 하는지 **PoC에서 실측**. 문제 시 `mcp-handler` 전송 옵션 확인.

## 3. Copilot Studio 측 — MCP를 툴로 연결

1. **MCP 서버 추가**: Copilot Studio에서 인사이트 아웃 `/api/mcp`를 MCP 도구로 등록. 각 MCP 툴(콘텐츠 검색 등)이 **에이전트 액션으로 자동 등록**되고, 서버가 바뀌면 자동 반영(GA 기능).
2. **인증**: 커넥션에 **API 키(헤더) 방식**으로 `Authorization: Bearer <read 토큰>` 주입. (인사이트 아웃이 Bearer 헤더를 받으므로 OAuth 없이 API key 헤더로 충분.)
3. **에이전트 지시문**: "너는 LG U+ 기업사업 사내 인텔리전스 에이전트다. 시장 동향·경쟁사·이슈 근거는 인사이트 아웃 툴에서, 사내 맥락은 사내 지식에서 가져와 결합한다" 식의 페르소나·근거 규칙.
4. **지식(사내 데이터)**: Dataverse 테이블 / SharePoint 문서 라이브러리 / 내부 SQL을 에이전트 **지식 소스**로 연결. 결합은 에이전트가 질의 때 양쪽을 함께 참조.

---

## 4. 사내 데이터 계층

- **Dataverse**: 정형 사내 데이터(고객·파이프라인·조직도 등)를 테이블로. 에이전트 지식·플로가 직접 조회.
- **SharePoint/OneDrive**: 비정형 문서(내부 보고서·자료)를 지식으로.
- **내부 SQL/DW**: 대량 정형 데이터가 이미 있으면 온프레미스 데이터 게이트웨이로 연결.
- (B) 경로 채택 시: Power Automate가 인사이트 아웃 데이터를 이 계층으로 당겨와 사내 키(고객사·엔티티)로 조인.

---

## 5. Power Automate의 역할 (에이전트 두뇌 아님)

- **트리거·스케줄**: "매일 아침 경쟁사 이슈 요약을 담당팀 Teams에", "특정 기업 신호 발생 시 알림" 등.
- **승인 흐름**: 에이전트 초안 → 담당자 승인 → 배포.
- **M365 접착제**: Teams 메시지·메일·SharePoint 기록.
- **(선택) 배치 ETL**: (B) 경로에서 인사이트 아웃 → 사내 저장소 동기화.
- ⚠️ Power Automate에서 임의 URL 호출/HTTP·에이전트 워크플로 MCP 호출은 **프리미엄 커넥터**(라이선스 확인).

## 6. 보안·거버넌스

| 항목 | 조치 |
|---|---|
| 데이터 방향 | Pull-only. 사내 데이터 외부 반출 금지. |
| 토큰 범위 | **`read` 스코프만.** ops/reports/publish 미부여. |
| 토큰 수명 | `expires_at` 설정 + 갱신 절차. 유출 시 `revoked_at`로 즉시 폐기. |
| 토큰 보관 | 사내 시크릿 저장소(Key Vault/환경 변수). 정의에 평문 금지. |
| 감사 | 토큰→user_id 매핑으로 호출자 추적(인사이트 아웃 측). |
| 네트워크 | **사내망 → `insight-out-app.vercel.app` 아웃바운드 허용**(프록시 allowlist) — 유일한 IT 선결. Copilot Studio 클라우드가 호출하므로 온프레미스 게이트웨이는 불필요. |
| DLP | Power Platform DLP 정책에서 이 커넥터·MCP 사용 범위 검토. |

## 7. 단계별 롤아웃

**Phase 0 — PoC (며칠).** read 토큰 발급 → Copilot Studio에 `/api/mcp` 연결 → 전송 handshake 실측 → "경쟁사 X의 최근 이슈" 같은 질의로 툴 호출 확인. 사내 데이터 없이 인사이트 아웃 단독.

**Phase 1 — 사내 결합 파일럿.** Dataverse/SharePoint에 사내 데이터 1종 연결 → 에이전트가 두 소스 결합 답변 → 한 팀(예: 기업사업 기획) 대상 Teams 배포.

**Phase 2 — 오케스트레이션.** Power Automate로 스케줄 브리핑·알림·승인 흐름 추가.

**Phase 3 — 확장/거버넌스.** (필요 시) (B) 배치 동기화, 토큰 갱신 자동화, DLP·감사 정례화.

## 8. 열린 질문 · 리스크

1. **전송 호환(중)** — Copilot Studio ↔ `mcp-handler` streamable HTTP handshake. Phase 0에서 실측, 안 되면 전송 옵션·프록시 점검.
2. **라이선스(중)** — Copilot Studio 메시지 용량·Power Automate 프리미엄 커넥터 비용.
3. **네트워크 승인(사내 IT)** — Vercel 도메인 아웃바운드 allowlist. Copilot Studio 클라우드 IP가 인사이트 아웃에 접근(공개 URL이라 기본 가능)하되, 회사 정책상 인사이트 아웃 측에 IP allowlist를 걸 거면 Copilot Studio egress IP 확인 필요.
4. **read 툴 커버리지** — 현재 노출: 콘텐츠·이슈·기업. 브리핑·경쟁사 주간 등 **다른 데이터가 에이전트에 필요하면 read 툴 추가**(인사이트 아웃 측 소폭 개발 — 별도 지시서).
5. **인사이트 스코프 보류** — `insights` 스코프는 190에서 보류 중(지면 미정). 필요 시 재설계.

---

## 9. 요약

- 연결 다리(MCP)·인증(토큰)·발급(어드민 API)이 **이미 다 있다.** 인사이트 아웃 측 즉시 할 일은 **read 토큰 1개 발급**뿐.
- Copilot Studio는 MCP를 GA로 소비 → **몇 클릭으로 인사이트 아웃 툴이 에이전트 액션이 된다.**
- 사내 데이터는 M365 테넌트 안에 두고, 에이전트가 질의 때 결합. **한 방향 pull로 사내 데이터는 불출.**
- Power Automate는 오케스트레이션·M365 접착·(선택)배치 ETL.
- 첫걸음: **Phase 0 PoC** — 토큰 발급 + Copilot Studio 연결 + handshake 실측.
