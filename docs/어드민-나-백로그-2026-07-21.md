## 1. 주간브리핑 생성 — 전역 진행 표시 🔴 우선

### 1.1 확인된 사실 — 만들 필요가 없다

`src/app/admin/layout.tsx` 가 **이미 전역으로** 다음을 감싼다.
```tsx
<EnrichJobsProvider>
  … <AdminSidebar /> <main>{children}</main>
  <EnrichJobsDock />        // fixed bottom-4 right-4 z-50
</EnrichJobsProvider>
```
- Provider 가 **layout 에 있으므로 페이지를 옮겨도 상태가 유지된다.**
- `localStorage` 에 저장하고(139행), 새로고침 시 `running` 을 **`interrupted` — "탭 종료 또는 새로고침으로 중단됨"** 으로 복원한다(88행).
- `EnrichJobsDock` 은 실행 중인 작업이 없으면 `return null`(29행), 있으면 우하단에 뜬다.
- 모닝브리핑 오디오·AI 콘텐츠 보강·데이터 보강이 **이미 이 체계를 쓴다.**

### 1.2 문제는 하나다

`AdminCompetitorWeeklyGenerate.tsx:38` 이 **생짜 `fetch`** 를 쓴다.
```ts
const res = await fetch('/api/admin/competitor-weekly', { … })
```
`useEnrichJobs` 를 쓰지 않으므로 **그 화면을 떠나면 진행 상황이 사라지고, 돌아와도 복원되지 않는다.**

### 1.3 조치
- `enrich-jobs` 레지스트리에 주간브리핑 생성을 **등록**하고, `useEnrichJobs` 로 실행하도록 바꾼다.
- ⚠️ **레지스트리 그룹 주의.** 현재 `getEnrichJobs('ai')` / `('data')` 두 그룹이 각각 `/admin/ai-jobs` · `/admin/enrich` 화면을 채운다. 주간브리핑을 `'ai'` 에 넣으면 **`/admin/ai-jobs` 목록에 주간브리핑이 나타난다** — 의도한 것인지 판단이 필요하다. 실행 버튼은 주간리포트 화면에 두고 싶다면 **Dock 에는 뜨되 잡 목록에는 안 뜨는 제3 그룹**이 필요할 수 있다.
- **디렉터 요청의 "모든 AI 생성 시 동일하게"** 는 이미 충족돼 있다. 예외가 이것 하나였다. **다른 예외가 더 없는지 전수 확인할 것** — `admin` 하위에서 `useEnrichJobs` 없이 장시간 `fetch` 를 거는 곳.

## 2. 지식보고서 표지

### 2.1 확인된 사실 — 자동 생성은 이미 돈다

`KnowledgeReportUploadForm.tsx:120~126`
```ts
if (extension === 'pdf') {
  try {
    const cover = await renderPdfCover(file)
    if (cover) await uploadCover(supabase, metadata.report.id, cover, 'webp')
  } catch (coverError) {
    console.error('[knowledge-reports] PDF 표지 생성 실패:', coverError)   // ← 화면엔 아무 말도 없다
  }
}
```

### 2.2 실제 결함
1. **실패가 조용하다.** `console.error` 뿐이라 운영자는 표지가 왜 없는지 모른다.
2. **PPTX 는 아예 시도하지 않는다**(`extension === 'pdf'` 조건). 업로드는 pptx 를 받는데 표지는 안 만든다.
3. **수동 등록 경로가 없다.**
4. **사후 재시도 경로가 없다.** 등록 후 표지만 다시 만들 수 없다.

### 2.3 조치 방향
- 실패 시 **폼에 사유를 표시**한다. `coverReasonLabel()`(`AdminContentManager.tsx:367`)에 이미 사유 라벨 매핑이 있다 — 재사용.
- 수동 업로드 + **1페이지 다시 가져오기** 버튼. 후자는 `/api/admin/contents/[id]/pdf-cover` 와 `handleRefetchPdfCover`(`AdminContentManager.tsx:975`)에 **구현이 이미 있다.** 지식보고서용 엔드포인트가 없다면 그 라우트를 참고해 만든다.
- ⚠️ **덮어쓰기 확인 문구를 빠뜨리지 말 것.** 기존 구현은 *"수동 등록분 포함 교체됩니다"* 를 `confirm` 으로 묻는다. 수동 등록을 추가하면 이 경고가 **더 중요해진다.**

## 3. 외부리포트 — 목록·발행 탭

**401 의 셸 위에 올린다. 401 에 넣지 않는다** — 발행 탭은 신규 기능이라 (나)다(396 §1 원칙).

- 탭 구성이 **카테고리마다 달라진다.** 뉴스·유튜브·웹인사이트는 `목록 | 소스`, 외부리포트는 `목록 | 발행 | 소스`, 지식보고서는 `목록 | 등록`.
  → 401 `ContentHub` 의 탭 배열을 **카테고리 함수로** 바꾸는 작업이 선행된다.
- 발행 탭: 파일 첨부 → 표지 자동(1p) → 수동 교체. **§2 와 같은 코드**를 쓴다. 두 화면이 갈라지지 않게 **공용 컴포넌트로 뽑을 것.**
- 테이블 통일: 디렉터 요청. 현재 외부리포트는 `AdminContentManager` 의 공용 테이블을 이미 쓴다 — **무엇이 다르게 보이는지 화면에서 먼저 특정할 것.** 추정 금지.

## 4. AI 리포트 주제 자동 — **디렉터 결정: 이슈에서 제안**

- `리포트 생성` 탭에 **이슈 선택 목록이 이미 있다**(라이브 확인). 이슈를 고르면 **그 제목을 `주제` 에 자동으로 채운다.**
- **채운 뒤에도 수정 가능해야 한다.** 잠그지 않는다.
- 이슈를 **여러 개** 고른 경우: 첫 번째를 쓸지, 합칠지 결정 필요. **단순하게 첫 번째 + 운영자 수정**을 기본으로 제안한다.
- 이미 주제를 입력한 상태에서 이슈를 고르면 **덮어쓰지 않는다.** 비어 있을 때만 채운다.
- **LLM 호출 0.** 비용·지연 없음.

## 5. 주간브리핑 3단계 흐름 — **디렉터 결정: 패스② 자동화 검토**

### 5.1 현재 흐름이 어려운 이유

`생성 실행`(패스①) → `분석`(패스② 수동 복사·붙여넣기) → `생성 설정`(크론) 이 **탭으로 나란히** 있다. 탭은 **동등한 선택지**를 뜻하는데 실제로는 **순서가 있는 단계**다. 그래서 어디부터 눌러야 하는지가 화면에 없다.

398 로 표시 버그는 고쳤지만 **구조는 그대로다.**

### 5.2 조사부터 — 지시서를 바로 쓰지 않는다

디렉터가 **패스② 자동화**를 택했다. 이건 348 설계의 핵심 전제를 바꾸는 일이다.

> 348: *"패스② 는 사람이 Claude 에 붙여넣어 분석한다. 분석 없이는 발행하지 않는다."*

**왜 수동이었는지부터 확인해야 한다.** 후보:
- 비용 — 주 1회 대량 컨텍스트라 API 호출이 비쌌나?
- 품질 — 대화형 Claude 의 결과가 API 보다 나았나?
- 검수 — 사람이 한 번 보게 하려는 **의도적 게이트**였나?

**세 번째라면 자동화는 설계 후퇴다.** 이 경우 자동화 대신 *생성 → 자동 분석 → **사람이 검토·발행*** 으로 게이트를 뒤로 옮기는 게 맞다.

### 5.3 조사 항목
1. `docs/` 에서 348 의 패스② 수동 결정 근거를 찾는다.
2. 패스② 컨텍스트의 **실제 토큰 규모**를 잰다(비용 추정의 근거).
3. 현재 프로젝트에 LLM API 호출 경로가 있는지(패스① 이 쓰는 것) 확인 — 있다면 재사용 가능한지.
4. Vercel 함수 **실행 시간 제한**에 걸리는지. 걸리면 백그라운드 잡 구조가 필요하다(§1 의 EnrichJobs 와 이어진다).

**조사 결과를 디렉터에게 보고한 뒤 지시서를 쓴다.** 지금 쓰면 또 실물과 어긋난다.

### 5.4 병행 — 프롬프트 동봉 (작고 즉시 가치)

자동화 여부와 무관하게, **패스② 복사 버튼이 프롬프트까지 함께 복사**하면 지금 당장 쉬워진다. 디렉터 원문: *"프롬프트까지 같이 만들어서, 사용자가 어느 llm에 붙여도 구현가능하게."*

- 현재는 데이터만 복사되어 **운영자가 지시문을 직접 써야 한다.**
- 패스① 이 쓰는 시스템 프롬프트(`FACTS_SYSTEM_FALLBACK` 계열)와 같은 자리에 **패스② 프롬프트를 상수로** 두고, 복사 시 `프롬프트 + 데이터` 한 덩이로 만든다.
- 자동화가 되면 **같은 상수를 API 호출이 쓴다.** 버리는 작업이 아니다.

→ **§5.4 를 먼저 하고 §5.2 조사를 병행한다.**
