# BigKinds 과거기사 수집 — 도입 준비 메모 (2026-07-25)

> 목적: 과거 기사 소급 수집을 위한 BigKinds Open API 도입. 단 **신청·승인·법무가 선행**이라 어댑터는 스펙 확보 후 작성.

---

## 0. 핵심 사실 (조사됨)
- **BIGKINDS-LAB(공개 GitHub) = 뉴스 "분석" API**(분류·요약·키워드·개체명·형태소) — 텍스트를 넣어 분석. **뉴스 검색/조회 API 아님.** 우리 용도(날짜로 과거 기사 발견)와 다름.
- **뉴스 검색 Open API = 별도**, bigkinds.or.kr 의 "OPEN API 서비스". **로그인·신청·승인 뒤**라 공개 문서로 스펙 확인 불가.
- **저작권**: 무료 제공은 메타 + 본문 앞 **200자**. 전문은 **유료(뉴스토어)**. 기사 재배포·복제 제한.
- **1990~현재·104매체·약 1억 건** — 확보만 되면 과거 커버리지는 최고.

## 1. 도입 전 확인해야 할 것 (승인 후 실제 API 스펙에서)
어댑터를 정확히 쓰려면 아래가 필요합니다:
1. **엔드포인트·인증** — 검색 API URL, API 키/토큰 방식.
2. **날짜 범위 파라미터** — from/to(기간) 지원 형식.
3. **🔴 원문 URL 제공 여부** — 응답에 **원 기사 URL(provider link)** 이 있는지. **있어야** 우리 보강이 원문에서 본문을 가져와 기존 파이프라인(425 flip → 게시)에 태울 수 있음. 없으면 200자 스니펫만 → 본문 확보 불가(활용 제한).
4. **응답 필드** — title, media(매체), published date, url, snippet 등.
5. **쿼터·요율** — 무료 티어 일/월 콜 한도, 전문 유료 여부.

## 2. David/팀 진행 (병렬)
1. **BigKinds 회원가입 → OPEN API 사용 신청**(bigkinds.or.kr). 사내(상용) 목적 명시 — 승인 조건·상용 가능 여부 확인.
2. 승인 후 **API 스펙 문서 + 키**를 확보해 플래너에 전달.
3. **사내 법무 확인**(병렬): BigKinds 이용약관 + 원문 본문 저장·사내 활용의 저작권 적합성. (현 RSS 수집에도 해당되나 규모↑, 명시적 검토 권장.)

## 3. 플래너/Sonnet (스펙 확보 후)
- 실제 API 스펙 받으면 **BigKinds 발견 어댑터** 설계·지시서 작성:
  - 날짜창을 거슬러(주/월 단위) 검색 → 메타+URL 발견 → **원문 URL 있으면** 기존 `processCrawlItem`(stub → 보강 → 관련도 게시)로. 425/426 그대로 재사용.
  - 커서 테이블(쿼리별 진행)·저빈도 스케줄러는 앞서 준비한 백필 설계(`Phase2-과거기사-백필-설계`) 패턴 재사용.
- **원문 URL 미제공이면**: 스니펫만으로는 본문 파이프라인에 못 태움 → 전문 유료 검토 or BigKinds 검색은 "무엇이 언제 있었는지" 인덱스로만 활용(별도 설계).
