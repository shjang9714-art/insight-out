## 2. 🔴 David 확정 필요 — 대체 구조

L2 탭을 없앤 자리를 **무엇으로 채우는가.** 세 방향의 트레이드오프가 갈린다.

### 안 A — 세로 스택 (탭화 이전으로)
탭을 걷고 섹션을 **한 화면에 세로로** 쌓는다. (396 이전 상태)
- ✅ 가장 직관적. 한눈에 다 보임. 되돌리기 = 기존 코드 복원.
- ❌ **긴 스크롤.** 콘텐츠 목록(2,198줄) + 소스가 한 화면에 쌓이면 과하다.
- 적합: 섹션이 2~3개고 짧은 화면(뉴스레터·지식보고서·AI리포트).

### 안 B — 사이드바 L1 분리
각 탭을 **사이드바 하위 메뉴**로 올린다. `경쟁사 주간 > 발행`, `경쟁사 주간 > 생성`…
- ✅ 탭 없음. 각 기능이 독립 페이지. URL 명확.
- ❌ **사이드바 비대화** — 최종안이 "사이드바 대상 중심"으로 피하려던 것. 메뉴가 2~3배로 늘어난다.
- 적합: 기능이 뚜렷이 갈리고 자주 오가지 않는 것.

### 안 C — 페이지 분리 (탭 → 라우트, 사이드바 유지)
탭을 **별도 라우트**로 쪼개되 사이드바엔 대표 하나만. 화면 안에서 링크/버튼으로 이동.
- ✅ 탭 바 없음. 사이드바 안 늘어남.
- ❌ 화면 간 이동 동선을 새로 설계해야. "돌아가기"가 필요.

### 안 D — 혼합 (화면 성격별)
**한 원칙을 전부에 강요하지 않는다.**
- 순서형(경쟁사 프로세스)·개념모호형(핵심인사이트) → 재설계(안 C 또는 단계 UI)
- 기능분리 명확(콘텐츠+소스, 뉴스레터 이력·설정) → 세로 스택 또는 유지
- David 불만이 실제로 이 둘(프로세스·개념모호)에 집중됐다.

## 3. 되돌릴 때 풀어야 할 것 (탭별 내용의 행선지)

| 탭 내용 | 지금(탭) | 되돌리면 |
|---|---|---|
| 콘텐츠 **소스**(401) | `발행 콘텐츠 | 소스` | 소스가 어디로? 세로 스택이면 목록 아래, 사이드바면 `소스 관리` 부활 |
| 뉴스레터 **설정·이력** | 3탭 | 세로 스택이면 한 화면 3섹션(원래 그랬음) |
| 경쟁사 **생성·분석·설정** | 4탭 | 프로세스라 **단계 UI**가 맞을 수도(③ 피드백) |
| 핵심인사이트 **카드·이슈·일일** | 3탭 | 개념이 다른 셋 → 사이드바 분리가 자연스러울 수도 |

→ **일률적으로 못 되돌린다.** 화면마다 탭 내용의 성격이 달라 행선지가 다르다. **안 D(혼합)가 현실적**일 가능성이 크다.

## 4. 권고 (플래너 의견)

1. **전면 일괄 되돌리기는 위험하다.** 방금 큰 노력으로 만든 걸 뒤집는 데다, 화면마다 탭 성격이 달라 한 방법으로 안 된다.
2. David 불만이 **집중된 두 화면부터** 고치는 게 실효적이다:
   - **핵심인사이트**(개념 모호한 3탭) — 사이드바 분리 or 재구성
   - **경쟁사 주간**(순서형 프로세스) — 단계 UI(설명·폰트↑) — ③ 피드백과 합침
3. 나머지(뉴스레터·지식보고서·AI리포트·콘텐츠)는 **탭이 기능분리로 자연스러운지** 각각 재판단. 기능분리 명확한 건 유지 가치 있음.
4. **최종안 §2.2 를 개정**한다 — "L2 탭 대신 X" 원칙을 문서로 확정해야 앞으로 안 흔들린다.

## 5. David 결정 (2026-07-22 확정)

**대체 구조 = 사이드바 분리를 기본으로, 단 "탭을 유지해야 하는 것은 지금처럼 내부 탭으로."**
→ 안 B(사이드바) + 안 D(혼합)의 결합. **기본은 사이드바 분리, 기능 분리가 자연스러운 곳만 탭 예외.**
→ 최종안 §2.2("내부 탭은 기능 중심")는 **"L2 탭은 지양하되, 한 대상의 부속 면은 내부 탭 허용"** 으로 개정.

## 6. 화면별 판정안 (플래너 제안 — David 확인 요청)

**판정 기준:** 탭 내용이 **서로 다른 관리 대상/개념**이면 → 사이드바 분리. 탭 내용이 **한 대상의 부속 면(보기·설정·부속 액션)**이면 → 탭 유지.

| 화면 | 현재 L2 탭 | 판정 | 근거 |
|---|---|---|---|
| **핵심인사이트** | 인사이트 카드 · 이슈 관리 · 일일 핵심 | 🔴 **사이드바 분리** | 셋이 **개념상 다른 관리 대상.** David 직접 지적. 각각 독립 메뉴로. |
| **경쟁사 주간** | 발행 · 생성 · 분석 · 설정 | 🔴 **사이드바 분리 + 프로세스 재설계** | 발행(목록)은 독립 메뉴, `생성→분석→설정`은 **순서형이라 단계 UI**로(육안 피드백 ③: 설명·폰트↑). |
| 지식보고서 | 발행 콘텐츠 · 등록 | 🟢 **탭 유지** | 등록은 발행 목록의 **부속 액션.** |
| AI 리포트 | 발행 콘텐츠 · 생성 | 🟢 **탭 유지** | 생성은 발행 목록의 부속. |
| 뉴스레터 | 이력 · 발송 · 설정 | 🟢 **탭 유지** | 한 뉴스레터의 **운영 면들.** |
| 콘텐츠 | 발행 콘텐츠 · 소스 | 🟢 **탭 유지** | 소스는 그 콘텐츠 타입의 부속(401). |
| 콘텐츠 추가 | 업로드 · 붙여넣기 · URL | 🟢 **탭 유지** | 같은 등록의 **입력 방식 차이.** |

→ **실질: 문제 화면 2개(핵심인사이트·경쟁사)만 사이드바 분리/재설계. 기능 분리가 명확한 5개는 탭 유지.**
→ 이것이 David 결정("사이드바 분리 기본 + 탭 유지 예외")과 육안 피드백(핵심인사이트·경쟁사 탭이 안 직관적)에 정합한다.
