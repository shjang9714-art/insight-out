## 1. 개선의 핵심 방향

현재 어드민의 문제는 기능 수가 많아서가 아니라, **사용자에게 제공되는 하나의 콘텐츠를 관리하려면 수집·AI·프롬프트·콘텐츠·발행 메뉴를 각각 찾아다녀야 한다는 것**이다.

개편 방향:

> **사용자 서비스 메뉴와 어드민의 서비스 관리 메뉴를 거의 1:1로 매핑하고, 해당 콘텐츠의 수집·생성·검수·발행 기능을 한 화면의 탭으로 통합한다.**

예: 사용자가 보는 `리포트 > AI 리포트`를 운영하려면 어드민에서도 `리포트 > AI 리포트`로 들어간다. 그 안에서 발행 콘텐츠·프롬프트·모델·실행 이력·사용량을 모두 관리한다.

## 2. 어드민 설계 원칙

### 2.1 사용자 메뉴와 같은 용어를 사용한다

사용자 서비스와 어드민에서 동일 명칭 유지: 핵심인사이트 · 키워드분석 · 관계지도 · 주요기업 · 경쟁사동향 · 경쟁사 주간리포트 · 뉴스 · 웹인사이트 · 유튜브 · AI 리포트 · 외부리포트 · 지식보고서 · 모닝브리핑.

운영자가 사용자 화면을 보고 해당 콘텐츠의 어드민 위치를 바로 찾을 수 있어야 한다.

### 2.2 사이드바는 대상 중심, 내부 탭은 기능 중심

사이드바에서 기능을 모두 펼치지 않는다. 사이드바에는 `AI 리포트`까지만 표시하고, 진입 화면에서 탭으로 제공한다.

```
리포트 > AI 리포트
  현황 | 발행 콘텐츠 | 리포트 유형 | 프롬프트 | 모델·생성 설정 | 실행 이력 | 사용량·비용
```

이 원칙을 뉴스·웹인사이트·모닝브리핑·경쟁사 주간리포트 등에 동일 적용한다.

### 2.3 동일한 메뉴명은 반복해도 된다

`뉴스 > 콘텐츠 관리`, `웹인사이트 > 콘텐츠 관리`, `유튜브 > 콘텐츠 관리`, `AI 리포트 > 발행 콘텐츠`, `외부리포트 > 발행 콘텐츠` 같은 반복은 비효율이 아니라 **콘텐츠별 운영 맥락을 명확히 하는 구조**다.

다만 실제 개발에서는 공통 컴포넌트·API를 재사용한다. 메뉴 진입점은 여러 개지만 시스템 로직은 중복 구현하지 않는다.

```
/admin/content?type=news
/admin/content?type=web-insight
/admin/content?type=youtube
/admin/content?type=ai-report
```

### 2.4 콘텐츠별 설정과 전역 설정을 구분한다

| 각 콘텐츠 내부에서 관리 | 시스템 설정에서 관리 |
|---|---|
| 실제 사용하는 프롬프트 | 사용할 수 있는 AI 제공자 |
| 생성 단계별 모델 | 모델 목록 |
| 생성 일정 | API 연결 |
| 번역·TTS 여부 | 모델별 단가 |
| 실행 결과 | 호출 한도 |
| 콘텐츠별 사용량 | 공통 장애 상태 |
| 발행 설정 | TTS·번역 서비스 등록 |

전역 설정은 **자원을 등록**하고, 각 콘텐츠 메뉴에서는 **그 자원을 어떻게 사용할지** 설정한다.

## 4. 운영센터

**목적:** 운영자가 로그인 직후 현재 서비스 상태와 오늘 처리할 일을 확인하는 관제 영역.

**운영 대시보드** — 오늘 수집·생성·발행 현황, 검수 대기, 승인 대기, 수집/AI 생성/발행 실패, 실행 중 작업, AI 리포트별 상태, LLM·번역·TTS 사용 현황, 오늘 예정 예약 작업.
AI 리포트 카드 최소 표시: 리포트 유형 · 운영 상태 · 현재 프롬프트 버전 · 주 모델 · 번역·TTS 여부 · 최근 실행 결과 · 다음 실행 시각 · 이번 달 사용량·비용 · 생성 성공률.

**작업·오류 센터** — 수집/본문추출/AI생성/번역·TTS/발행 실패. 실패 단계부터 재실행, 전체 재실행, 담당자 지정, 오류 상태 변경.

**작업 이력** — 예약/수동 실행, 재처리, 백필, AI 생성, 발행, 관리자 변경 작업.
※ 작업 이력 = 운영 작업 흐름, 로그 분석 = 기술 로그 검색·분석 으로 구분.

**운영 게시판** — 운영 공지, 장애 공유, 검수 요청, 담당자 메모, 변경사항 기록.

## 5. 홈

**홈 화면 구성** — 사용자 홈 화면의 콘텐츠 배치·노출 순서 운영. 홈 섹션 활성/비활성, 노출 순서, 대표 콘텐츠 고정, 자동 노출 규칙, 배너·공지, 주요기업 노출, 핵심인사이트 노출, 추천 리포트, 미리보기, 예약 반영.
단순 설정 목록이 아니라 **실제 홈 화면과 유사한 미리보기 기반 편집 화면**으로 구성.

## 6. 인사이트

### 6.1 핵심인사이트
탭: 현황 · 콘텐츠 관리 · 이슈 관리 · 생성 설정 · 프롬프트 · 실행 이력 · 발행 관리.
핵심 이슈 후보 관리, 인사이트 카드 생성, 카드 제목·요약·근거 편집, 우선순위·노출 기간, 관련 키워드·기업·인물 연결, AI 프롬프트 관리, 자동/수동 작성, 검수·승인·발행, 생성 근거 조회.
→ 기존 **이슈 관리 · 인사이트 카드 · 일일 핵심 Insight**를 이 영역으로 통합.

### 6.2 키워드분석
탭: 분석 현황 · 키워드 관리 · 분석 기준 · 시그널 설정 · 결과 검수 · 화면 구성.
분석 대상 키워드, 키워드 그룹, 기간별 언급량, 상승·하락 시그널 기준, 연관 키워드, 감성·논조 기준, 주요 콘텐츠 연결, 비정상 데이터 제외, 결과 검수, 노출 설정.
→ 공통 키워드 원장은 기준정보에서, 여기서는 **적용 설정·결과** 관리.

### 6.3 관계지도
탭: 관계 현황 · 엔티티 · 관계 관리 · 근거 콘텐츠 · 검수 대기 · 화면 설정.
관계 생성·수정·삭제, 관계 유형·강도·신뢰도, AI/운영자 생성 구분, 근거 기사·리포트 연결, 원·선 클릭 시 노출 콘텐츠, 중복 엔티티 병합, 관계 검수, 표시 범위.

## 8. 콘텐츠

외부 원문 수집·검수 중심. 공통 운영 패턴: 현황 · 콘텐츠 관리 · 소스 관리 · 수집 실행 · 본문 수집 · 수집 이력 · 통계. (같은 명칭 반복 허용)

**8.1 뉴스** — 뉴스 소스 관리(RSS·API·크롤링), 수집 주기, 과거 기사 백필, 본문 추출, 중복 판정, 키워드·기업·인물 분류, AI 요약·번역·보강, 검수·제외·발행, 성공률.

**8.2 웹인사이트** — 전문기관·기업 블로그·기술 사이트 등 고부가 콘텐츠. 목록/본문 페이지 설정, 본문 수집, 원문 보존, 작성기관·저자 관리, 분류, 경쟁사동향 연계, 수집량·실패율, 중요 콘텐츠 선별, 발행.
뉴스와 유사 구조이되 **장문 원문·출처 신뢰도 관리 강화**.

**8.3 유튜브** — 탭: 콘텐츠 관리 · 채널 관리 · 영상 수집 · 자막·요약 · 수집 이력 · 통계.
채널 등록, 재생목록 수집, 영상 메타데이터, 자막 수집, AI 요약, 관련 기업·키워드 연결, 썸네일, 노출, 비공개·삭제 영상 처리.

## 9. 리포트

### 9.1 AI 리포트
> AI 리포트를 단순 목록이 아니라 **생성 워크플로·프롬프트·모델·검수·발행·비용이 결합된 생산 단위**로 관리.

탭: 현황 · 발행 콘텐츠 · 리포트 유형 · 프롬프트 · 모델·생성 설정 · 실행 이력 · 사용량·비용.

- **현황** — 유형별 카드: 운영 상태, 생성 주기, 현재 프롬프트·버전, 주/대체 모델, 번역·TTS 여부, 최근/다음 실행, 성공률, 검수 대기, 이번 달 사용량·비용.
- **발행 콘텐츠** — 생성 리포트 목록, 초안·검수·승인·발행 상태, 본문 수정, 커버 이미지, 관련 콘텐츠·기업 연결, 예약 발행, 미리보기.
- **리포트 유형** — 리포트명, 목적·설명, 출력 형식, 노출 위치, 입력 데이터, 생성 주기, 자동 발행 여부, 검수 방식, 번역·TTS, 담당자, 운영/테스트/중지 상태.
- **프롬프트** — 리포트 유형·생성 단계에 연결(자료 선별 / 핵심 사실 추출 / 목차 / 본문 작성 / 사실 검증 / 최종 편집 / 요약 / 번역 / TTS 스크립트). 기능: 목록·조회·신규·수정·복제·테스트·버전 비교·승인·운영 반영·복원·비활성/보관. **운영 중 프롬프트를 직접 덮어쓰지 않고 새 버전으로 생성.**
- **모델·생성 설정** — 단계별: 주/대체 모델, Temperature, 최대 토큰, Timeout, 재시도, 출력 스키마, 비용 상한, 실패 처리, 수동·예약 실행.
- **실행 이력** — 실행마다: 방식, 프롬프트 버전, 모델, 단계별 시간, 입출력 토큰, 번역·TTS 사용량, 비용, 결과, 오류, 발행 콘텐츠 연결. 단계별 입출력·프롬프트 조회 + **실패 단계부터 재실행.**
- **사용량·비용** — LLM 입출력 토큰, 번역 문자·호출, TTS 문자·음성 길이, 이미지 생성량, 모델별/리포트별/프롬프트 버전별 비용, 월 예산·경고.

## 11. 기준정보

여러 콘텐츠·분석에서 공통 사용하는 데이터를 한곳에서 관리. **원장을 관리하고, 실제 적용은 각 서비스 메뉴에서 설정.**

- **키워드** — 원장, 동의어, 금칙어, 활성 상태, 관련 엔티티.
- **키워드 그룹·시그널 기준** — 키워드 그룹, 산업·기술 분류, 상승·하락 기준, 중요도 기준, 분석 임계치.
- **엔티티 사전** — 기업·인물·기관·기술·제품·국가/지역, 별칭, 중복 병합.
- **분류·카테고리** — 콘텐츠 유형, 산업, 기술, 주제, 보고서 유형, 노출 카테고리.
- **제외 규칙** — 제외 도메인·URL·키워드, 중복 기준, 저품질 콘텐츠 기준.
- ~~**공통 태그**~~ — ⛔ **폐기(2026-07-19, 지시서 389).**
  **사유**: 이 시스템에 "태그"의 실체는 이미 존재하며 별도 원장이 필요 없다. 콘텐츠 태그는 `contents.matched_keywords`(text[], GIN 인덱스, 코드 121곳 참조)이고 그 원장은 `keywords` 테이블(→ 기준정보 > 키워드), 태그의 분류 축은 `keyword_groups.tag_type` enum(industry/company/tech/market/policy/content_type)(→ 기준정보 > 키워드 그룹·시그널 기준)이다. `tags`·`content_tags` 테이블은 존재하지 않는다.
  별도 태그 원장을 신설하면 **쓰는 화면이 0개인 원장**이 되어, `key_insights` 폐기 때와 같은 사고(기록은 되는데 읽는 화면이 없음)가 반복된다.
  **되살리려면**: 먼저 "키워드로는 표현할 수 없는 태그"의 구체적 용도와 그것을 소비할 화면을 정의할 것. 그 정의 없이 다시 만들지 말 것.

## 16. 공통 UI·UX 지침

**사이드바** — 최대 2계층, 사용자 서비스와 같은 명칭, 서비스 관리 영역과 관리자 공통 영역 시각 분리, 메뉴 검색 유지, 현재 위치 명확 표시.

**페이지 구조** — 브레드크럼 · 페이지 제목·설명 · 현재 상태 컨텍스트 바 · 상단 탭 · 필터·검색 · 목록/작업 화면.
AI 콘텐츠 컨텍스트 바: 콘텐츠/리포트 유형 · 운영 환경 · 상태 · 현재 프롬프트 버전 · 주 모델 · 최근 실행 결과.

**편집 화면** — 복잡한 편집은 작은 팝업 금지, 전체 화면/대형 워크스페이스 사용. 콘텐츠 편집은 미리보기·편집 2패널, 프롬프트 편집은 설정·편집기·테스트 3영역. 미저장 이탈 경고.

**테이블** — 불필요한 가로 스크롤 제거, 제목·요약·썸네일은 하나의 콘텐츠 셀로 통합, 관리 기능은 상세·핵심 액션·⋯로 정리, 관리 컬럼을 별도 박스처럼 분리하지 않음.
