# 어드민 UI/UX 통일 — 스펙 & 슬라이스 계획

> 작성: Opus(Cowork) · 2026-07-01 · 근거: 어드민 UI 감사 + David 방향(2026-07-01)
> David 방향: ①메뉴는 **레벨1(그룹)–레벨2(페이지)로 끝**, L3(인페이지 탭)은 상위로 승격/제거 ②색·버튼 위치·계위 **통일**(인지 부조화 제거) — "아주 중요". ③기능 초점 = **양질 콘텐츠 수집 체계**(RSS→불량률→반복방지→엔티티).

---

## 0. 진단 요약 (감사)

- **메뉴 깊이**: 사이드바 L1(그룹)→L2(페이지)로 이미 구성. **진짜 L3 인페이지 탭은 `ContentAddTabs`(업로드: 파일/텍스트) 하나뿐.** 나머지(콘텐츠 상태필터·이슈 상태·insights 기간드롭다운 등)는 "필터/토글"이지 내비게이션 탭이 아님. newsletter·llm·dashboard의 다중 섹션은 세로 스크롤(탭 아님).
- **불일치 핵심 3가지**:
  1. **페이지 헤더 제각각** — 15개 페이지가 각자 `<h1>+<p>` 작성, `space-y-6` 래퍼 유무·아이콘 유무·인라인 드롭다운 혼재. 공용 `AdminSectionHeader`는 3곳만 사용.
  2. **상태 배지 색 하드코딩·불일치** — 같은 "성공"이 `text-green-700`·`bg-green-50`·`#57cc99` 등 제각각(6개 파일). 25%가 하드코딩 색.
  3. **엔티티/차트 색 하드코딩** — 엔티티 타입 배지·차트 바 색이 hex/임의 클래스.
- **이미 양호**: 버튼 위치(생성=헤더우측/폼하단, 삭제=행우측)·테이블/폼 스타일·컨테이너 폭(max-w-7xl)은 대체로 일관.

> 결론: **"메뉴 재편"보다 "디자인 토큰·공용 컴포넌트 통일"이 본질.** 그리고 통일의 기준색은 **신규 hex가 아니라 163/167에서 만든 앱 토큰을 재사용**한다.

## 1. 통일 원칙

1. **계위: L1(그룹) – L2(페이지)로 끝.** 페이지 안에서 "탭으로 다른 화면 전환" 금지. 새 기능은 L2 메뉴로 추가하지, 페이지 속 탭으로 숨기지 않는다.
2. **한 개의 색 체계.** 어드민 전용 색을 새로 만들지 않고 **163 시맨틱 토큰**(positive/risk/negative ±soft)·**167 버킷/카테고리 팔레트**를 재사용.
3. **공용 컴포넌트 우선.** 페이지마다 재작성하지 않고 `components/admin/ui/` 프리미티브로 수렴.
4. **같은 의미 = 같은 모양·같은 위치.** 상태=배지 규칙 하나, 주요 액션=헤더 우측, 위험 작업=danger+확인.

## 2. 통일 스펙 (무엇을 하나로)

### 2-1. 페이지 헤더 — `AdminPageHeader` 공용
모든 어드민 페이지가 동일한 헤더 사용:
- `title`(h1) · `description`(선택) · `icon`(선택) · `actions`(우측 슬롯).
- 래퍼·간격 표준(`space-y-6`)을 헤더가 소유 → 페이지별 래퍼 편차 제거.
- 페이지 우측 주요 액션(생성·실행·미리보기 등)은 **항상 헤더 `actions` 슬롯**에 배치(위치 통일).
- `insights`의 인라인 상태 드롭다운, `llm`의 아이콘 등 특례를 헤더 규격으로 흡수.

### 2-2. 상태 배지 — 163 토큰 공용 헬퍼
`components/admin/ui/StatusBadge.tsx` + `lib/admin/status-style.ts`:
- 의미 3단계 → 163 토큰 매핑: **성공/정상 = positive, 주의/부분 = risk, 실패/숨김 = negative, 중립 = muted.**
- 콘텐츠 상태(노출/검토/숨김), 크롤 상태(성공/부분/실패), 브리핑/이슈/인사이트 상태 모두 이 헬퍼로. 하드코딩 green/yellow/red/#hex 제거.

### 2-3. 범주 색(엔티티 타입·카테고리·차트) — 팔레트 토큰
- 엔티티 타입(기업/기술/제품/인물/정책/산업)·콘텐츠 카테고리·차트 시리즈 색을 **167 방식의 팔레트 상수**(토큰/저채도 클래스)로 단일 정의(`lib/admin/palette.ts`) 후 배지·차트 공용 사용. 파일마다 hex 반복 제거.

### 2-4. 버튼 variant — `Button` 확장
- `variant`: `brand`(주요) · `secondary`(보조) · `danger`(위험) · `ghost`. 현행 `bg-brand-600 text-white` 반복을 variant로.
- **위험 작업(삭제·대량 배경작업)은 `danger` + 확인 다이얼로그 필수**(현재 삭제 확인 없음 = UX 위험).

### 2-5. 필터 칩·배지 — `AdminFilterChip` 일원화
- 인라인 `<span>` 필터/라벨을 공용 칩/배지로. 활성/비활성 스타일 하나로.

### 2-6. 테이블·폼 — 템플릿 확정(이미 양호)
- 테이블 컨테이너/헤더(`rounded-xl border bg-card` + `thead bg-muted`)·폼(Card+Label+Input) 패턴을 표준으로 문서화. `TableHeader`·`FormField` 경량 래퍼는 선택(중복 크면 도입).

### 2-7. ContentAddTabs(유일 L3) 처리 — 결정 필요
- (a) **유지**: 단일 페이지 내 폼 전환(내비게이션 아님)이라 L1-L2 규칙 위반 아님 — 그대로 둠.
- (b) **평탄화**: 두 폼을 한 화면에 좌우/세로로 나란히(탭 제거).
- 권고: **(a) 유지**(탭이 아니라 "입력 방식 선택"으로 명확히 라벨). 단 새 L3는 금지 원칙 확정.

## 3. 슬라이스 계획

> 순서 원칙: **기반(공용 컴포넌트·토큰) 먼저 → 페이지 그룹별 적용.** 페이지 적용은 **콘텐츠·수집 그룹 먼저**(트랙 B 콘텐츠 품질과 겹침 → 두 번 안 건드림).

- **174 어드민 디자인 기반**: `AdminPageHeader` · `StatusBadge`+status-style(163 토큰) · `Button` variant(+danger 확인) · palette 상수. (공용만, 페이지 미적용)
- **175 적용 ①: 콘텐츠·수집 그룹** — contents·upload·briefings·sources·crawl-logs 헤더/배지/버튼 교체. (트랙 B 착지점)
- **176 적용 ②: 분류·이슈·인사이트 그룹** — keywords·keyword-groups·entities·issues·insights.
- **177 적용 ③: 연동·발행·시스템 + 차트 색** — translation·llm·newsletter·users + DashboardCharts/LlmManager 색 팔레트화.
- (각 적용 슬라이스는 순수 프레젠테이션 — 기능 변화 0, 회귀 가드 명확.)

## 4. 트랙 B(양질 콘텐츠 수집)와의 관계

UI 통일이 끝난(또는 병행하는) 화면 위에 **기능 강화**를 얹는다. David 지정 초점 순서:
1. **RSS 수집 관리**(소스) — 소스별 품질 지표(성공률·중복률·본문확보율·반려율) 노출.
2. **수집 불량률**(크롤 로그·콘텐츠 건강) — 불량 유형 가시화.
3. **반복 방지(학습)** — 제외 규칙(도메인·본문최소·중복 임계) + 반려 사유 축적 → 자동 보류.
4. **엔티티 관리** — 정규화·병합 UX 강화.
→ 이 트랙은 174~177(UI 통일)과 별개 슬라이스로, **175(콘텐츠·수집)와 자연히 연결**된다. 상세는 별도 계획.
