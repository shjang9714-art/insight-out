- ⚠️ 단 모바일이 **다크모드 신규 토큰·모바일 전용 변수**를 추가하면 겹친다. 그때는 **모바일 토큰을 별도 `@layer` 나 별도 파일**로 분리해 어드민 변경과 안 겹치게.

## P-3. 안전한 병렬 조합

**동시 진행해도 안전(파일 안 겹침):**
- 어드민 T1-3(AI 리포트 주제 — `admin/reports`) · T3-1·T3-2 · T4 조사 ↔ 모바일 M-1 프로토타입·로그인·홈·검색 오버레이·미니플레이어
- 이유: admin 레인 vs login/신규 모바일 컴포넌트 — 파일 교집합 0.

**순서 조율 필요(충돌 A):**
- 어드민 T2-3(북마크·아카이빙) ↔ 모바일 콘텐츠 상세·마이. **T2-3 를 먼저**(북마크 데이터 모델·훅 확립) → 모바일이 그 위에 리더 UI. 또는 한 슬라이스.

## P-4. 권고 (M-0 = PWA 확정 반영)

**PWA 방향이 병렬성을 오히려 좋게 만든다.** M-1~M-5 가 **대부분 신규 파일**(manifest·SW·`components/mobile/*`·모바일 provider)이라 어드민 (나)와 파일 교집합이 거의 0이다. 유일한 실질 충돌은 **M-6(미구현 화면) ↔ T2-3**뿐.

1. **즉시 병렬 가능**: 어드민 (나) T1-3 → T3/T4 조사 ↔ 모바일 **M-1(PWA 셋업)·M-2(앱 셸)·M-3(미니플레이어)·M-4·M-5**. 파일이 안 겹친다. 각자 `agent/*` 브랜치 → 재현검증 → ff 머지.
2. **M-3 는 어드민 자산 재사용**: 미니플레이어 전역 Context = `EnrichJobsProvider/Dock` 패턴. 어드민 레인이 이미 검증했으니 모바일이 그 구조를 가져온다.
3. **충돌은 M-6 ↔ T2-3 하나**: 둘 다 `dashboard/contents/[id]`·`mypage`. **T2-3(북마크·아카이빙 데이터 모델)을 먼저** 세우고 → M-6 모바일 리더가 그 위에 UI. 스키마가 얽히면 수희 SQL 조율. 순서만 지키면 된다.
4. **선행 결정**: 탭 구성(기업 1급) 실기기 리뷰 확정 — 이건 설계라 병렬 진행과 무관하게 David가 언제든.
5. 안전장치는 이미 작동 — **브랜치 격리 + 재현검증 + ff 머지.** 두 레인이 다른 `agent/*` 를 쓰면 물리적으로 안 섞인다.
