# Phase 2 — 과거기사 백필 설계 (2026-07-25)

> 목적: 신규 수집과 별개로 과거 기사를 소급 축적(검색 품질·소스 균형·데이터 두께).
> 담당: **[수희]** 커서 테이블·스케줄러 · **[Sonnet]** 백필 엔드포인트 · **[Opus]** 이 설계.

---

## 0. 🔴 핵심 제약 (설계를 좌우) — RSS 는 과거를 못 준다
- 크롤러는 **RSS/피드 기반**(`adapters/news-site.ts`). `adapter.fetch(source, since)` 의 `since` 는 **pubDate 하한 필터일 뿐**, 피드가 반환하는 항목 자체는 **최근분**이다.
- 기존 `?days=N`(≤30) 백필도 `since` 창만 넓힐 뿐, RSS 에 옛 기사가 없으면 안 걸린다. → **RSS 소스는 과거기사 소급이 원천적으로 불가.**
- **가능한 경로**: (a) **검색 날짜창** — Google News RSS 검색 `q=...&when:`/`after:YYYY-MM-DD before:YYYY-MM-DD` 로 과거 구간을 조회, (b) 사이트맵(미지원), (c) 소스별 아카이브 페이지네이션(미지원).
- → **본 설계는 (a) 검색 날짜창 백필**로 한정한다. 대상은 **키워드 시드(search_seeds)/쿼리** 기반. 임의 RSS 소스 아카이브는 범위 밖(별도 어댑터 필요).

## 1. 접근 — 검색 날짜창을 거슬러 페이징
- 각 **백필 쿼리**(키워드 시드/그룹 쿼리)에 대해, **최근 → 과거로 주(week) 단위 창**을 walk-back:
  - 창 예: `[2026-06-15, 2026-06-22)` → 다음 실행에서 `[2026-06-08, 2026-06-15)` …
  - 각 창마다 Google News 검색 URL(날짜 연산자 포함) fetch → **기존 ingest 경로로 stub 저장**(425 flip: pending → 보강 → 관련도 통과분 게시). 백필 기사도 동일 품질 게이트.
- **커서** = 그 쿼리가 어디까지 거슬러 갔는지(다음 창 시작). 목표 하한(예: 12개월 전)까지 내려가면 완료.

## 2. 분담

### A. 스키마 [수희] — 백필 커서 테이블 `article_backfill_state`
```
query_key       text  (시드/쿼리 식별)     -- PK
label           text  (사람용 라벨)
window_end      date  (현재 창의 끝 = 다음에 조회할 구간 상단)
backfill_floor  date  (여기까지 내려가면 완료, 예: 12개월 전)
last_run_at     timestamptz
articles_found  int
articles_stub   int
status          text  ('active' | 'done' | 'paused' | 'error')
error           text
updated_at      timestamptz
```
- 신규·재시도·백필 큐를 분리(§통합개선안 7.4) — 백필은 이 테이블 기반, 신규 enrich 와 별개.

### B. 백필 엔드포인트 [Sonnet] `/api/cron/backfill`
- GET, `Bearer CRON_SECRET`. 1회 호출당 **소량**(예: 시드 1~3개 × 창 1개)만 처리(신규 수집 자원 잠식 금지 §7.1).
- 처리: `article_backfill_state` 에서 `status='active'` 이고 오래 안 돈 쿼리 N개 선택 → 각 `window_end` 기준 **직전 주 창**의 검색 URL 구성 → 기존 news-site 어댑터로 fetch → **`processCrawlItem` 경로로 stub 저장**(중복은 canonical/hash 로 자동 스킵) → `window_end` 를 한 주 뒤로 당김(과거로) → `backfill_floor` 도달 시 `status='done'`.
- 실패 시 status='error'+error, 다음 실행 재시도(§7.5 백오프는 후속).
- ⚠️ 착수 확인: search_seeds fetch 시 **Google News 검색 URL·날짜 연산자 주입 지점**(orchestrator 의 synthetic source URL 구성) 정독 후, 날짜창을 URL 에 실을 수 있는지 검증. 안 되면 어댑터에 날짜창 파라미터 소폭 추가.

### C. 스케줄러 [수희] — 백필 드레인
- C 보강 워커와 **동일 패턴**(pg_cron `net.http_get` 또는 GitHub Actions)으로 `/api/cron/backfill` 을 **저빈도**(예: 30~60분)로 호출. 신규 수집(일1회)·보강(10분)보다 느슨하게 — 백필은 급하지 않음.

## 3. 스코프·비스코프
- ✅ 검색 가능한 키워드/쿼리의 과거기사(Google News 날짜창).
- ❌ 임의 RSS 소스의 아카이브(피드에 없음) — 필요하면 소스별 사이트맵/아카이브 어댑터(별도 대형 작업).
- ❌ 유튜브 과거(video_id 유니크·검색 한계) — 범위 밖.

## 4. 착지 순서·의존
1. **A(커서 테이블)** — SQL 선행.
2. **B(엔드포인트)** — A 후 반영(테이블 참조). 425 flip 위에서 동작(이미 배포됨).
3. **C(스케줄러)** — 보강 워커(C) 세팅되면 같은 방식으로 추가.
- 신규 수집·보강 파이프라인과 **독립**(백필이 자원 잠식 X).

## 5. 리스크
- **검색 품질**: Google News 날짜창 검색의 커버리지·중복. 중복은 canonical/hash 로 흡수(기존).
- **레이트 리밋**: 저빈도·소량 처리로 완화. 창 크기(주)·시드 수 튜닝.
- **함수 시간**: 1회 소량 바운드(신규처럼 softDeadline).
- **관련도**: 백필 기사도 425/426 관련도 게이트 통과분만 게시(off-topic 유입 없음).
