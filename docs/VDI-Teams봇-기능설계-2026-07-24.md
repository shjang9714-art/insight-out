## 기능별 매핑 (구성 · 인사이트 아웃 측 필요)

### A. 추천 질문 봇 (5개 대화 스타터)
Copilot Studio "대화 스타터"에 5개 고정, 사용자가 선택 → 에이전트가 MCP로 데이터 모아 답변.

| 스타터 | 쓰는 MCP 도구 | 상태 |
|---|---|---|
| 오늘 주요 동향 | daily_insight_list(오늘)·briefing(오늘)·content_search | **421** |
| AICC 관련 최근 뉴스 요약 | content_search(query="AICC", days=N) → 에이전트 요약 | 기존 |
| (특정) 기업/경쟁사 동향 | entity_list·entity_events·competitor_weekly | **421** |
| 이번 주 전략 시사점 5개 | competitor_weekly·daily_insight(implication_lenses) → 에이전트 종합 | **421** |
| 이 내용을 팀즈 채널에 브리핑으로 게시 | (읽기 아님) **Power Automate → Teams 채널 게시** | David |

→ **인사이트 아웃 측: 421 read 도구면 1~4 커버.** 5번(채널 게시)은 PA/Teams.

### B. 뉴스레터·리포트 정기 푸시 봇
Power Automate 스케줄 플로 → 최신 뉴스레터/리포트 조회 → Teams 채널/메일 전달.
- **필요(신규 소)**: `newsletter_list`/`newsletter_get` MCP read 도구(발행 이슈). 421엔 미포함 → 추가.
- report_list는 421에 포함. 뉴스레터 발송(Brevo)은 이미 있음. Teams 푸시 = PA.

### C. 아카이브 명령 + 아카이브 기사 수신
- **"이 기사 아카이브해줘"** → **신규 write 도구 `content_archive`**(토큰→user_id 이므로 그 사용자 아카이브에 저장). 테이블 `archives`/`archive_items` 존재.
- **"아카이브된 기사 메일로 받기"** → **이미 있음**: `src/app/api/email/send-archive/route.ts` + `archive-template.ts`. 재사용.
- **"팀즈로 URL/원문 받기"** → **신규 read 도구 `archive_list`**(내 아카이브 목록) + PA가 Teams로 전달.
- ⚠️ **write(아카이브)라 read-only 토큰과 분리** — ops 스코프(또는 신규 archive 스코프) 토큰 필요.

### D. 팀즈에서 보고서 생성 → 팀즈로 전달
두 방식:
- **(a) 에이전트 작성**: Copilot Studio가 MCP read(421)로 데이터 모아 **스스로 보고서 텍스트 작성** → PA가 Teams 게시. 인사이트 아웃 생성 파이프라인 안 씀. **가장 빠름.**
- **(b) 인사이트 아웃 파이프라인 트리거**: `generate-strategy`(`api/reports/generate-strategy`) 를 **신규 도구/엔드포인트로 트리거** → 정식 전략보고서 생성 → 반환. 무거운 LLM 작업(비동기·maxDuration 고려). 발행 게이트(초안 default 비공개) 유지.
- 권장: **짧은 브리핑형은 (a), 정식 전략보고서는 (b).** (b)는 신규 트리거 도구 + 비동기 처리 설계 필요.

## 인사이트 아웃 측 신규 작업 (→ 지시서 큐)
| # | 작업 | 규모 | 스코프 | 상태 |
|---|---|---|---|---|
| 421 | 분석 산출물 read(리포트·경쟁사·데일리·브리핑·이벤트·기업문서) | 중 | read | **진행 중** |
| 422 | 뉴스레터 read 도구(`newsletter_list`/`get`) | 소 | read | 대기 |

| 424 | 보고서 생성 트리거(`generate-strategy` 도구, 비동기) | 대 | reports(write) | 대기(설계 필요) |

- 422·423은 A~C를 완성. 424는 D(b)용(무거워 후순위).
- 메일 아카이브 발송은 **재사용**(신규 없음).

## 스코프·보안
- **read 도구(421·422·archive_list)** = `read` 스코프.
- **write 액션(아카이브·보고서 생성)** = read-only 토큰과 **분리**. `ops`/`reports`(또는 신규 `archive`) 스코프 토큰 별도 발급. 봇이 실수로 발행/오염 못 하게 **스코프 최소**, 리포트는 초안 default 비공개(publish 스코프 미부여).
- 토큰은 클라우드 시크릿(Key Vault/PA 환경변수). VDI에서 다루지 않음.
