## 🧭 권장 검증 순서 (채우기 먼저 → 보기 검증)

화면 대부분은 "생성/채우기"를 먼저 해야 내용이 보입니다. 이 순서로:

1. **수희: `137-signals-classified-marker.sql` 적용** (마지막 SQL)
2. **마이페이지**: 담당 서비스 + 관심 기업 설정 → "보기"(렌즈) 동작 전제
3. **`/admin/contents`**: "기사 풀본문 채우기" 드레인 → "신호 분류" 드레인 (137 SQL 후)
4. **`/admin/entities` → "정규화 제안"**: MS류 중복 병합 **먼저** (깨끗한 엔티티 위에서 타임라인 생성되게)
5. **`/admin/entities` 엔티티 상세 → "사건 타임라인 생성"** (경쟁사 1~2개)
6. **이슈 관리 → "AI 이슈 후보 생성"** → 승인 → 이슈별 **"AI 브리핑 생성"**
7. 이제 사용자 화면 검증: 이슈 · 기업(사건 타임라인·관계 그래프) · AI인사이트(카드뉴스·보기 전환) · 검색(RAG 질문)

> 4를 5보다 먼저: 정규화로 합쳐진 엔티티 위에서 타임라인을 만들어야 사건이 안 쪼개짐.

## 1. 기사 풀본문 채우기 (지시서 129) — `/admin/contents`

- [ ] "본문 보강" 버튼이 **"기사 풀본문 채우기"** 라벨로 보임 (강력 새로고침 Cmd+Shift+R)

- [ ] (야간) 새벽 4시 cron(`/api/cron/body-backfill`) 후 remaining 감소 — 다음 날 확인

## 4. 렌즈 개인화 (지시서 132) — 이슈 / 기업 / AI인사이트

- [ ] **마이페이지**에서 담당 서비스 + 관심 기업(워치리스트) 설정
- [ ] 이슈/기업/AI인사이트 상단 **렌즈 스위처**(내 담당 / 경쟁사 워치 / 전체) 표시

- [ ] **`전체` 렌즈 = 기존과 동일**(회귀 0), 담당/워치 미설정 시 해당 칩 **비활성**
