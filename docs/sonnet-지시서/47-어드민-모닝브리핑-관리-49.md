## 배경·목표
- 데이터 계약상 **어드민(#49)** = draft 미리보기·오디오 재생성·승인(`status='published'`). 합성 API(#50)와 플레이어(#51)는 이미 머지됐고, 그 사이를 잇는 **운영 화면**이 비어 있다.
- 목표: 어드민이 한 화면에서 (1) 브리핑 목록을 보고, (2) 스크립트를 확인하고, (3) **오디오를 생성/재생성**하고(기존 `POST /api/admin/briefings/[id]/tts`), (4) 들어보고, (5) **승인(공개)** 하면 사용자 플레이어에 뜬다.

## 파트 A — 목록 조회 API `GET /api/admin/briefings/route.ts`
- `crawl-now` 의 `verifyAdmin()` 패턴 동일(비관리자 401/403). `runtime='nodejs'`·`dynamic='force-dynamic'`.
- `createAdminClient()`(service_role)로 **모든 상태** 최근순 조회(어드민은 draft 포함 전체를 봐야 함):
  ```ts
  admin.from('briefings')
    .select('id, briefing_date, title, script, audio_url, audio_duration_seconds, voice, status, generated_at, published_at, updated_at')
    .order('briefing_date', { ascending: false })
    .limit(60)
  ```
- 응답에 **이번 달 TTS 사용량**도 포함(translation-status 처럼 한 번에): `tts_usage` 에서 `provider='google'`·현재 KST period `chars` 조회 + `cap = Number(process.env.TTS_MONTHLY_CHAR_CAP ?? 3_500_000)`.
- 응답 형태(예):
  ```json
  { "period": "2026-06", "tts": { "used": 0, "cap": 3500000 }, "briefings": [ ... ] }
  ```
- KST period 헬퍼는 `synthesize-briefing.ts` 의 `getKstPeriod()` 와 동일 로직(작은 중복 허용 또는 공용 유틸로 추출).

## 파트 B — 상태 변경 API `PATCH /api/admin/briefings/[id]/route.ts`
- `[id]/tts/route.ts` 와 **같은 폴더**에 `route.ts` 추가(`PATCH` 핸들러). `verifyAdmin()` 재사용(공용 함수로 빼서 두 라우트가 import 하면 중복 제거에 좋음 — 과하면 각자 복붙도 허용).
- body: `{ status: 'published' | 'archived' | 'draft' }`. **허용 전이만**:
  - `draft → published`(승인), `published → archived`(보관), `published → draft`(공개 취소, 옵션), `archived → published`(재공개, 옵션).
  - 그 외 전이는 400 `'허용되지 않는 상태 전이입니다.'`.
- `published` 로 전이 시 `published_at = now()`(아직 없으면). 그 외는 건드리지 않음.
- 화이트리스트 검증 후 `admin.from('briefings').update({ status, published_at? }).eq('id', id)`. 응답 `{ ok:true, status }`. 미존재 404.
- ⚠️ `audio_url` 없는 draft 를 published 로 올리는 것 자체는 **막지 않음**(스키마상 audio 없는 published 도 플레이어가 스크립트만으로 표시). 단 UI(파트 C)에서 "오디오 없이 공개" 시 확인 문구로 안내.

## 파트 C — 어드민 UI
### C-1 네비 + 페이지(서버)
- `src/app/admin/layout.tsx` 의 `NAV_ITEMS` 에 추가: `{ href: '/admin/briefings', label: '모닝브리핑' }`(`크롤링 현황` 뒤 권장).
- `src/app/admin/briefings/page.tsx`(서버 컴포넌트): `metadata`(title `'모닝브리핑 | 어드민 | Insight Out'`) + 제목/설명 + `<BriefingManager />`. translation/page.tsx 구조 그대로.

### C-2 Manager `src/components/admin/BriefingManager.tsx` (`'use client'`)
TranslationStatusManager 의 골격(useEffect GET 로드·`isActive` 가드·`Loader2` 로딩·에러 배너·`Button`)을 따른다.
- **로드**: `fetch('/api/admin/briefings', { cache:'no-store' })` → period·tts·briefings 세팅.
- **상단 사용량 카드**: `이번 달 TTS — {used}/{cap}자 (잔여)`, `Progress` 바(번역 화면과 동일 룩). 색·토큰 동일.
- **목록**: 각 briefing 카드(`rounded-xl border border-border bg-card`)에:
  - 헤더: `briefing_date`(ko-KR) + `title` + **상태 뱃지**(draft=회색/`secondary`, published=`brand`, archived=muted, failed=red). 뱃지는 시맨틱/브랜드 토큰만.
  - 스크립트 **미리보기 접힘/펼침**(버튼 토글, `max-h` 스크롤). 빈 스크립트면 "스크립트 없음".
  - 오디오: `audio_url` 있으면 `<audio controls src={audio_url} className="w-full">` 미리듣기. 없으면 "오디오 없음".
  - **액션 버튼**(상태/오디오에 따라):
    - **오디오 생성/재생성**: `POST /api/admin/briefings/${id}/tts` → 처리 중 `Loader2`·버튼 disable. 성공 시 해당 행만 갱신(반환 audioUrl 반영) 또는 목록 refetch. 실패 시 reason 을 행 단위 에러로 표시(409 한도초과 메시지 그대로). 라벨: audio 없으면 "오디오 생성", 있으면 "재생성".
    - **승인(공개)**: status==='draft' 일 때 노출. `PATCH {status:'published'}`. `audio_url` 없으면 클릭 시 `confirm('오디오 없이 공개하면 스크립트만 재생됩니다. 공개할까요?')` 후 진행. 성공 시 뱃지 published 로.
    - **보관**: status==='published' 일 때 노출. `PATCH {status:'archived'}`.
    - (옵션) **공개 취소**: published→draft.
  - 액션 진행 상태는 행별 `pendingId`/`pendingAction` 으로 관리(번역 화면의 `pendingProvider` 미러).
- **빈 상태**: briefings 0건이면 "관리할 브리핑이 없습니다. (#47 스크립트 생성 후 표시됩니다)".
- 모든 텍스트 한국어. 아이콘은 lucide-react(`Loader2`·`AlertCircle`·`CheckCircle2`·`Play`/`Volume2` 등 기존 설치분).

## 검증 메모(Opus 재현용)
- 상태 전이 화이트리스트: 비허용 전이(예 archived→draft 막았는지/허용했는지 명세대로)·draft→published `published_at` 채워지는지.
- 오디오 없는 draft 공개 시 confirm 경로, 공개 후 사용자 플레이어가 그 행을 집어오는지(published).
- TTS 사용량 카드 수치가 `tts_usage` 실값과 일치, cap 환경변수 반영.
- 행별 액션 동시성: 한 행 처리 중 다른 행 버튼 정상.
