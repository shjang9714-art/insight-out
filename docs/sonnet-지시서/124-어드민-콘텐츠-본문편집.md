## 배경 (마스터플랜 §3⑤)

운영자가 어드민에서 콘텐츠 메타(제목·요약·카테고리·출처·저자·발행일)는 편집 가능하나 **본문(`body_original`)은 편집 불가**. 깨진 인코딩·잘린 본문·노이즈를 손볼 수 없다. 편집 모달에 본문 textarea를 추가한다.

> 컴포넌트 표준화(목록행·필터칩·빈상태·섹션헤더 공통화)는 **성격이 리팩터**라 본 지시서와 분리(→ 125). 124는 본문 편집 기능만.

## 설계 결정 (Opus)

1. 기존 편집 모달 패턴 그대로 확장 — `openEdit` 로드 select에 `body_original` 추가, `edit` 상태에 필드 추가, 모달에 textarea, `handleEditSave` update payload에 포함.
2. 본문은 길 수 있으므로 textarea(rows 큰 값·`resize-y`·`font-mono`는 선택). 빈 값은 `null`로 저장(`.trim() || null`).
3. **표시 일관성**: `body_original` 편집 후 상세/카드 표시는 기존 `clean-body`(htmlToPlainText/&nbsp; 처리)가 표시 시점에 처리하므로 추가 작업 불필요. 단 편집 textarea에는 **원문 그대로** 로드(가공 금지).
4. 목록 행에는 본문을 안 보여주므로 `setContents` 낙관적 반영은 기존 필드(제목·카테고리·소스)만 유지 — 변경 없음.

## 작업 — `src/components/admin/AdminContentManager.tsx`

### A. 로드 (`openEdit`, L256)
- select 컬럼에 `body_original` 추가: `'id, title, summary_ko, category, source_id, author, published_at, body_original'`.
- `setEdit({ ... , bodyOriginal: data.body_original ?? '' })`.

### B. 편집 상태 타입
- `edit` 상태 인터페이스(파일 상단 정의)에 `bodyOriginal: string` 추가.

### C. 모달 JSX (요약 필드 근처, L940 부근)
- "요약" 아래에 **"본문(원문)"** 필드 추가:
  ```tsx
  <div>
    <Label htmlFor="edit-body">본문 (원문)</Label>
    <textarea
      id="edit-body"
      value={edit.bodyOriginal}
      onChange={(e) => setEdit((p) => p && { ...p, bodyOriginal: e.target.value })}
      rows={12}
      className="w-full rounded-lg border border-border bg-background px-3 py-2 text-sm text-foreground leading-relaxed focus:outline-none focus:ring-2 focus:ring-brand-600/30 resize-y"
      placeholder="본문 원문(HTML·텍스트). 표시 시 자동 정리됩니다."
    />
    <p className="mt-1 text-xs text-muted-foreground">표시 화면에서 HTML·&amp;nbsp; 는 자동 정리됩니다. 여기서는 원문을 그대로 편집하세요.</p>
  </div>
  ```
  (기존 모달의 Label/textarea 스타일과 동일 토큰 사용. 하드코딩 hex 금지.)

### D. 저장 (`handleEditSave`, L292 update payload)
- payload에 `body_original: edit.bodyOriginal.trim() || null` 추가.

## 디자인 준수 (§4)
- 기존 모달 필드와 동일 밀도·간격·토큰. 본문 textarea는 충분한 높이(rows≥12). 안내 문구로 "표시 시 자동 정리" 명시(혼란 방지). 다크모드 토큰 양립.
