라이브 건수: issues 42, issue_contents 639, content_signals 1,812, **evidence_pairs(issue↔signal join) 849**

**확정 분기:**
1. content↔signal 연결: **이미 완료**(content_id FK)
2. sentiment: contents 단에 존재하나 **거의 비어 있음** → 논조 위젯은 이번 차수 **제외**(별도 백필 후)
3. signal_type 분류 컬럼: 존재(사업기회는 Phase E에서 enum 추가)
4. 이슈↔콘텐츠: issue_contents로 **이미 존재**

**결론: 신규 테이블(issue_signals) 불필요. 마이그레이션 없이 읽기 뷰만 추가.** (원본 설계의 Case A는 폐기)

## 1. 사슬 (논리)

```
issues ─< issue_contents >─ contents ─< content_signals
                              │              (content_id)
                              ├─ source_id → sources.name
```

이슈 근거 = `issue_contents`로 이슈에 연결된 콘텐츠 중 **시그널을 가진 것**.

## 2. 뷰 생성 (supabase/ SQL)

파일: `supabase/2026-06-29-issue-evidence-view.sql`

```sql
-- 이슈 근거 콘텐츠 드릴다운 뷰: (issue_id, content_id) 그레인, 시그널 보유 콘텐츠만
create or replace view public.issue_evidence as
select
  ic.issue_id,
  c.id                                       as content_id,
  c.title,
  c.summary_ko,
  c.original_url,
  c.thumbnail_url,
  c.category::text                           as category,
  c.published_at,
  s.name                                     as source_name,
  array_agg(distinct cs.signal_type::text)   as signal_types,
  max(cs.score)                              as max_signal_score,
  count(cs.id)                               as signal_count
from public.issue_contents ic
join public.contents c          on c.id = ic.content_id
left join public.sources s      on s.id = c.source_id
join public.content_signals cs  on cs.content_id = c.id
group by ic.issue_id, c.id, s.name;

-- ★ GRANT 필수 (Data API 노출)
grant select on public.issue_evidence to anon, authenticated;
```

> 검증: 생성 후 `select * from issue_evidence limit 5;` 로 행이 나오는지, GRANT 후 PostgREST(`/rest/v1/issue_evidence?issue_id=eq.<uuid>`)에서 노출되는지 확인.
> 참고: 뷰는 기본 security definer. 만약 RLS로 빈 결과가 나오면 `alter view public.issue_evidence set (security_invoker = on);` 또는 정책 점검.

## 3. 데이터 조회 (API)

앱이 Supabase 클라이언트를 직접 쓰므로 **신규 API 라우트 없이 클라이언트 쿼리 권장**(표면 최소화):

```ts
const { data } = await supabase
  .from('issue_evidence')
  .select('*')
  .eq('issue_id', issueId)
  .order('max_signal_score', { ascending: false })
  .order('published_at', { ascending: false });
```

(서버 컴포넌트/RSC에서 동일. 별도 엔드포인트가 패턴상 필요하면 `GET /api/issues/[id]/evidence`로 위 쿼리 래핑 — 그 경우 라우트 등록 빌드매니페스트 검증.)

## 4. UI — "근거 콘텐츠" 섹션

위치: 이슈 상세. **먼저 라우트 존재 확인** — `/dashboard/issues/[id]` 상세 페이지가 있으면 그 하단에, 없으면 AI인사이트 카드의 펼침/모달 영역에 추가.

요구사항:
- 섹션 제목 "근거 콘텐츠" + 건수
- 콘텐츠 카드 리스트(max_signal_score desc, published_at desc):
  - thumbnail_url(없으면 플레이스홀더), title, source_name, published_at
  - `signal_types` 배열을 **분류 배지**로 표시(예: `경쟁사동향` `기술트렌드`)
  - 클릭 → original_url 새 탭
- 0건일 때 빈 상태 문구
- 유튜브 카테고리면 기존 `YoutubeVideoCard` 스타일 재사용 가능(선택)

> 논조 배지는 **이번 차수 제외**(sentiment 미채움). 백필 완료 후 후속 차수에서 추가.
