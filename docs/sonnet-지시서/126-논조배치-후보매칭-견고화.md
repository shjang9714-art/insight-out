## 배경 (운영 진단 2026-06-21)

`/admin/insights` "논조 분석" 1회 실행 결과 = **candidates 40 / analyzed 0**. 즉 후보(경쟁사 기사)는 40건 잘 잡혔고, **40건 전부 `classifySentiment` 가 null** 을 반환.

근본 원인 추적:
- classify 라우팅(55): ①cerebras(미등록 skip) → **②groq llama-4-scout(등록)** → ④openrouter(등록). 즉 `llmComplete('classify')` 는 **텍스트를 정상 반환**한다(둘 다 실패해 null 날 확률 낮음).
- `classifySentiment`/`classifyRelevance` 는 출력을 **엄격 JSON**(`JSON.parse(cleaned)`)으로만 받음. 무료/소형 모델(llama-4-scout 등)은 잡담·앞말·코드펜스 변형·여분 텍스트를 섞기 쉬워 → **parse 실패 → null** → 전건 실패.
- 대조: `summarizeKo` 는 자유텍스트(JSON 불요)라 정상 → LLM 인프라 자체는 동작. 문제는 **classify 계열의 엄격 JSON 파싱**.

## 설계 결정 (Opus)

1. **관용 파서** 도입: 코드펜스 제거 → JSON.parse 시도 → 실패 시 **출력에서 첫 `{...}` 부분문자열 추출** 후 재시도. (앞말/뒷말 섞인 JSON 구제.)
2. **sentiment 키워드 폴백**: 그래도 JSON 못 얻으면 출력 텍스트에서 `긍정|부정|중립`(및 positive/negative/neutral) 스캔 → 매핑. 논조는 값이 3종뿐이라 안전.
3. **classifyRelevance** 도 관용 파서 적용(게이트가 조용히 결정적 폴백 중이었을 가능성 해소). relevant 불리언 누락 시 null 유지(결정적 폴백 안전).
4. **진단성**: 파싱 실패 시 원문 일부를 `console.warn`(truncate 200자). sentiment 라우트 반환 `reason` 에 분석 결과 분포(예: `analyzed/nullCount`) 노출(다음 실행에서 null인지 parse인지 구분).

## 작업

### A. 공통 파서 — `src/lib/llm/parse.ts` (신규)
```ts
/** 코드펜스/잡담 섞인 LLM 출력에서 JSON 객체를 관용적으로 추출. */
export function looseJsonParse(raw: string): unknown | null { /* 아래 로직 */ }
```
- 로직:
  1. `const s = raw.trim().replace(/^```(?:json)?\s*/i,'').replace(/\s*```\s*$/,'').trim()`
  2. `try { return JSON.parse(s) } catch {}`
  3. 첫 객체 추출: `const m = s.match(/\{[\s\S]*\}/); if (m) { try { return JSON.parse(m[0]) } catch {} }`
  4. `return null`

### B. sentiment 파싱 견고화 — `src/lib/insight/sentiment.ts`
- `const out = await llmComplete('classify', SYSTEM_PROMPT, user); if (!out) return null`
- `looseJsonParse(out)` → 객체.sentiment 가 `긍정|중립|부정` 이면 반환.
- 실패 시 **키워드 폴백**: `out` 내 `부정` 우선, 그다음 `긍정`, 그다음 `중립`(또는 negative/positive/neutral) 탐색 → 매핑. (우선순위는 부정>긍정>중립 권장 — 악재 누락 방지.)
- 둘 다 실패 시 `console.warn('[sentiment] parse fail:', out.slice(0,200))` 후 null.

### C. relevance 파싱 견고화 — `src/lib/crawler/classify.ts`
- `JSON.parse(cleaned)` 블록을 `looseJsonParse(out)` 로 교체. 이후 `relevant` 불리언 검증·tags 로직 그대로. parse 실패 시 `console.warn` 후 null(결정적 폴백 유지).

### D. 라우트 진단 — `src/app/api/admin/sentiment/route.ts`
- 루프에서 `result === null` 카운트(`let nullCount=0`). 반환 `{ analyzed, candidates: rows.length, nullCount }`. (UI는 기존 표시 유지, 후속에서 nullCount 노출해도 됨.)
