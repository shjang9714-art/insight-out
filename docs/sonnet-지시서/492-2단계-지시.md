## 판단 ① — 어드민 RLS 경로도 범위에 포함한다

인벤토리 §3의 지적이 맞다. `admin/page.tsx`(14곳)·`AdminContentManager.tsx`(12곳) 등은 service_role이 아니라 **관리자 세션 RLS**로 돌지만, `contents: admin 전체 조회` 정책에 `deleted_at` 조건이 없으므로 **삭제분이 그대로 보인다.**

**규칙을 이렇게 정한다 — 클라이언트 종류(service_role / RLS / 브라우저)와 무관하게, "정상 목록·집계"를 그리는 모든 `contents` 조회는 `.is('deleted_at', null)`을 붙인다.** 삭제분을 보는 곳은 휴지통 화면·복원·영구삭제뿐이다.

**RLS 정책은 바꾸지 않는다.** 어드민이 휴지통을 봐야 하므로 `admin 전체 조회`는 그대로 둔다. 필터는 애플리케이션 코드에 두는 편이 grep으로 확인 가능해 안전하다.

→ 1단계에서 제외했던 **어드민 RLS 경로를 다시 훑어 A/B/C로 분류하고, A에 필터를 넣는다.**

## 판단 ② — `dedup.ts` 분류를 정정한다 (인벤토리와 다름)

인벤토리는 5곳 전부 A(살아있는 것만)로 분류했다. **3곳은 B로 바꾼다.**

| 위치 | 판정 | 근거 |
|---|---|---|
| `dedup.ts` URL 중복(`original_url`) | **B — 삭제분 포함** | |
| `dedup.ts` 제목 해시(`title_hash`) | **B — 삭제분 포함** | |
| `dedup.ts` 본문 해시(`body_hash`) | **B — 삭제분 포함** | |
| `dedup.ts` near-dup 클러스터 (2곳) | **A — 살아있는 것만** | 삭제된 행이 클러스터 대표가 되면 안 된다 |

**이유.** 앞의 셋을 A로 두면, 관리자가 스팸 기사를 지워도 **다음 수집에서 같은 기사가 다시 들어오고, 지워도 또 들어온다.** 무한 재생이다. 삭제된 것을 "이미 있었다"로 판정해야 되살아나지 않는다.

**잘못 지운 것의 복구 경로는 재수집이 아니라 휴지통 복원이다.** 30일이 지나 영구 삭제되면 그때부터는 자연스럽게 재수집된다. 이 판단을 `dedup.ts`에 **주석으로 남길 것.**
