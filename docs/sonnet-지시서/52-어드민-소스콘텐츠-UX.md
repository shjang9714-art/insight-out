## 배경
게이트 ON(지시서 51) 이후 `pending`(보류) 콘텐츠가 쌓일 예정이라 **검토 대기 큐 UX**가 시급. 또 소스 관리에 "어느 소스가 죽었나"가 안 보여(David 명시 불편). 둘 다 순수 UI/조회로 개선한다. (filter_patterns DB화 등 SQL 필요한 항목은 이번 범위 제외.)

## Part A. 콘텐츠 관리 — 검토 대기 우선 + 일괄 승인/반려
대상: `src/components/admin/AdminContentManager.tsx`

현재: 최근 100건을 collected_at desc 로 한 번 로드 → 클라이언트 필터. **pending 이 100건 밖이면 누락**, 일괄 작업 없음, per-row 승인/반려만.

### A-1. 검토 대기 우선 + 상태 서버필터
- **mount 시 pending 카운트** 조회(가벼운 head count):
  ```ts
  const { count } = await supabase.from('contents')
    .select('id', { count: 'exact', head: true }).eq('status', 'pending')
  ```
  상단에 **"검토 대기 N건"** 칩/버튼 표시 → 클릭 시 `status='pending'` 필터.
- **상태 필터를 서버 쿼리로**: `status` 가 'all' 이 아니면 로드 쿼리에 `.eq('status', status)` 적용하고 `status` 변경 시 재조회(useEffect 의존성에 status 추가). 그래야 pending 전량(최근순 100)이 보임. (category·search 는 기존대로 클라이언트 필터 유지.)
- status='all' 일 때는 **pending 을 상단 정렬**(클라이언트 sort: pending→published→rejected, 그 안에서 collected_at desc).

### A-2. 일괄 선택 + 일괄 승인/반려
- 행 체크박스 + 헤더 전체선택(현재 필터된 목록 기준). 상태 `selectedIds: Set<string>`.
- 선택이 1건 이상이면 목록 상단에 **일괄 바**: "N건 선택 · [일괄 승인] [일괄 반려] [선택 해제]".
- 일괄 처리: `supabase.from('contents').update({ status }).in('id', [...selectedIds])` → 성공 시 로컬 상태 갱신 + 선택 해제. 실패 시 기존 error 배너.
- 기존 per-row 승인/반려/삭제 버튼은 유지.
- 처리 중 로딩 표시(기존 workingId 패턴 확장 or 별도 isBulkWorking).

## Part B. 소스 관리 — 인라인 수집 상태 + 죽은 소스 식별
대상: `src/components/admin/SourceManager.tsx` + 신규 라우트.

현재: 소스 목록에 마지막 수집일(last_crawled_at)만. 최근 성과·실패 여부 안 보임.

### B-1. 신규 API: `src/app/api/admin/source-status/route.ts` (GET)
- `crawl_logs` 는 클라이언트(브라우저 anon)에서 RLS 로 못 읽을 수 있으니 **서버 라우트(admin 클라이언트)** 로 제공.
- `verifyAdmin()` 은 `crawl-now/route.ts` 의 패턴을 그대로 복제(또는 `src/lib/admin/auth.ts` 로 추출 후 양쪽 사용 — 택1, 보고에 명시).
- `createAdminClient()` 로 최근 7일 `crawl_logs` 조회 후 **source_id 별 집계**:
  ```ts
  // 반환: { [source_id]: { inserted7d, lastStatus, lastFinishedAt, consecutiveFailures } }
  ```
  - `inserted7d`: 최근 7일 inserted_count 합.
  - `lastStatus`/`lastFinishedAt`: 가장 최근 로그.
  - `consecutiveFailures`: 최신부터 연속 'failed' 개수.
- `export const runtime='nodejs'`, `dynamic='force-dynamic'`.

### B-2. SourceManager 인라인 배지
- 목록 로드 후 `/api/admin/source-status` fetch → `Map<source_id, status>` 병합.
- 테이블에 **"수집 상태" 열** 추가:
  - `inserted7d` 숫자(최근 7일 신규).
  - 배지: `consecutiveFailures >= 2` → 🔴 "연속실패 N", `is_active && inserted7d === 0`(7일째 0건) → ⚠️ "점검 필요(죽은 소스 후보)", 그 외 정상은 배지 없음/✅.
- 상태 조회 실패해도 목록 자체는 정상 렌더(상태 열만 '—'). 비차단.

## 회귀 / 주의
- contents/sources 스키마·RLS 무변경. 기존 per-row 승인/반려/삭제·소스 추가/수정/토글·크롤 트리거 모두 정상.
- 서버필터 전환 시 무한 재조회 주의(useEffect 의존성 status 만, category/search 는 클라이언트).
- source-status 라우트는 admin 인증 필수(비admin 403). crawl_logs 양이 많을 수 있으니 7일·필요 컬럼만 select.
- 큰 목록에서 전체선택 후 일괄 업데이트 시 `.in()` id 수 과다 주의(현재 최대 100건이라 안전).
