# 지시서 221 — 본문 최소 길이 미수집 + 어드민 설정

목표: 크롤 수집 시 **본문이 너무 짧은 기사(기본 250자 미만)를 완전 미수집(reject)** 한다. 임계값은 어드민이 `/admin/settings`에서 조정할 수 있게 DB에 저장하고, 크롤러가 서버에서 읽는다.

범위(David): 본문 250자 미만 완전 미수집 + 어드민 설정. **SQL 핸드오프 있음**(단일행 설정 테이블).

---

## 1. 현행 진단 (검증된 코드 사실)

- 길이 게이트: `src/lib/crawler/orchestrator.ts:328` — `effectiveLength(item.title, item.body) < MIN_EFFECTIVE_LENGTH` 면 `counts.rejected++; return {}`.
- `src/lib/crawler/quality.ts:27` `export const MIN_EFFECTIVE_LENGTH = 30` — **제목+본문 합산 30자**(매우 낮음, 제목만 길어도 통과). `effectiveLength`(55–58)는 `제목 + 본문` 공백정규화 길이.
- **크롤러는 상수만 읽고 DB 설정 없음.** 게이트는 `item.body`(수집 시점 = RSS 스니펫) 기준.
- 설정 저장 DB 패턴 존재: `homepage_sections`(202, 단일 도메인 설정 테이블 + RLS + `set_updated_at` 트리거) / `llm_settings`(524). API 패턴 `src/app/api/admin/llm/route.ts`(GET+PATCH, `verifyAdmin`→`createAdminClient`→upsert). 어드민 UI는 `/admin/settings` 페이지 + 매니저 컴포넌트.
- **주의(스니펫)**: 수집 시점 `item.body`는 RSS 스니펫이라 짧을 수 있음. 본문 강화(enrich-body, 나중)는 게이트 이후 → 짧은 스니펫은 강화 전에 걸러짐. David 의도(수집 단계에서 얇은 기사 제거)에 부합.

## 2. 구현

### 2-0. SQL 핸드오프(선푸시·수희) — `docs/sql-handoff/221-crawl-settings.sql`
단일행 설정 테이블:
```sql
create table if not exists public.crawl_settings (
  id boolean primary key default true check (id),   -- 단일행 강제
  min_body_length integer not null default 250,
  updated_at timestamptz not null default now()
);
insert into public.crawl_settings (id) values (true) on conflict (id) do nothing;
alter table public.crawl_settings enable row level security;
create policy "crawl_settings read all" on public.crawl_settings for select using (true);
create policy "crawl_settings admin write" on public.crawl_settings for all using (public.is_admin()) with check (public.is_admin());
```
(202 `set_updated_at` 트리거 있으면 재사용.)

### 2-1. 본문 길이 기준 게이트(크롤러)
- `quality.ts`: `export const DEFAULT_MIN_BODY_LENGTH = 250` 추가. 순수 본문 길이 헬퍼 `bodyLength(body): number`(공백정규화 후 길이; `effectiveLength`와 달리 **본문만**).
- `orchestrator.ts` 처리 함수가 `minBodyLength`(런 시작 시 DB에서 1회 조회한 값)를 받아, 게이트에 추가:
  ```ts
  bodyLength(item.body ?? '') < minBodyLength  // → rejected
  ```
  기존 `effectiveLength < MIN_EFFECTIVE_LENGTH`(30) 게이트는 유지(하위 안전망).
- 크롤 런 진입점(orchestrator의 크롤 시작부/`runCrawl` 류)에서 **1회** `crawl_settings.min_body_length` 조회 → 각 아이템 처리에 전달. 조회 실패/컬럼·테이블 없음(42P01/42703) → `DEFAULT_MIN_BODY_LENGTH`(250) 폴백(graceful).

### 2-2. 설정 API
`src/app/api/admin/crawl-settings/route.ts`(llm route 미러): `GET`(현재값, 없으면 기본 250 반환) / `PATCH`({ min_body_length }) → `verifyAdmin`→`createAdminClient`→`upsert(onConflict id)`. 입력 검증(예: 50~5000 범위).

### 2-3. 어드민 UI (`/admin/settings`)
시스템 설정 페이지에 "수집 필터" 카드 신설 `src/components/admin/CrawlSettings.tsx`(214 박스 규격 `p-5`·`admin-card-title`):
- 라벨 "본문 최소 길이(자)", number input, 저장 버튼. 설명 "이 글자수 미만 본문의 기사는 수집하지 않습니다."
- GET로 초기값 로드, PATCH로 저장. 저장 성공/실패 안내(AdminErrorBox 재사용 가능).

## 3. 회귀 가드
- 기존 30자 합산 게이트 유지(안전망) + 본문 250자 게이트 추가.
- DB 미적용(42P01/42703) 시 크롤러는 250 기본값으로 정상 동작(graceful).
- 설정 변경은 **다음 크롤 런부터** 적용(런 시작 시 1회 조회).
- reject 카운트(`counts.rejected`)에 반영 — 크롤 현황/로그에서 확인 가능.
- 상세/표시/기존 데이터 불변.
