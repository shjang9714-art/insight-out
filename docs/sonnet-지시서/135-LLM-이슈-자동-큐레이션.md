## 배경

이슈가 12개·전부 수동 → 이슈 상세(131)·렌즈(132)가 굶음. 자동 큐레이션으로 이슈층을 채운다. **재사용 자산**: `matched_groups`/`matched_keywords`(크롤러가 모든 콘텐츠에 자동 적재) · `cluster_id`(near-dup) · `insight/generate.ts`의 테마 그룹핑(빈도순 그룹→그룹당 대표 8건→LLM→환각검증→멱등 upsert) · `feed-dedup.ts` 유사도 · `/admin/insights` draft→published 검토 UX. **스키마 무변경.**

**원칙(브레이크)**: v1은 **matched_groups(테마) 기준 군집** 한 가지로(검증된 신호). 사람 검토 필수(draft). 신호/엔티티 기반 정밀 군집·자동 발행은 v2.

## A. 후보 생성 엔진 — `src/lib/issues/generate-candidates.ts` (신규)

`insight/generate.ts`의 `generateIndustryInsightCards` 구조 미러(이슈로 재해석).
```ts
export interface IssueCandidate {
  title: string            // 지속되는 테마형 이슈명(헤드라인 아님)
  summary: string          // 한 줄
  match_keywords: string[] // 미래 자동매칭용 5~8
  content_ids: string[]    // 핵심 근거(검증 통과분)
  theme: string            // 출처 matched_group
}
export async function generateIssueCandidates(admin, opts?: {
  days?: number; maxCandidates?: number; minGroupSize?: number
}): Promise<IssueCandidate[]>
```
- 입력: 최근 `days`(기본 7) published 콘텐츠 중 `matched_groups` 있는 것. **matched_groups 빈도 집계 → 상위 `maxCandidates`(기본 8) 그룹**(그룹 건수 ≥ `minGroupSize`=3).
- 그룹당 대표 콘텐츠 ~8건(`cluster_id` null 우선 = 중복 사건 압축, importance/recency 정렬) → `{content_id, title, summary_ko, published_at}`.
- LLM(`llmComplete('report')`): "이 기사들이 이루는 **지속적 이슈(테마/내러티브)** 하나를 정의: {이슈명, 한 줄 요약, 향후 자동매칭 키워드 5~8, 핵심 근거 content_id}. 단발 헤드라인 아님. 제공 사실만. JSON." → `looseJsonParse`.
- **환각 가드**: content_ids ⊂ 제공 집합(미존재 제거). title/summary 빈 후보 제거.
- 키 없음/실패 → 해당 그룹 skip(부분 graceful), 전체 throw 금지.

## B. 중복 제거 — `feed-dedup.ts` 재사용

1. **후보 간**: `dedupSimilarItems`(title Jaccard ≥ 0.35 또는 keywords Jaccard ≥ 0.5) → 유사 후보 병합/제거.
2. **기존 이슈 대비**: 비-archived 이슈의 `title`+`match_keywords` 조회 → 후보가 **title 유사도 ≥ 0.4** 또는 **match_keywords Jaccard ≥ 0.5**면 **skip**(이미 있는 이슈). (경계값은 보수적으로 skip.)
- 결과: 신규 후보만 남김 + skip 카운트.

## C. 영속 (draft 후보 insert)

- 살아남은 후보마다: `issues` insert `{ title, summary, status:'draft', match_keywords, source:'claude' }` → id → `issue_contents` batch insert `{ issue_id, content_id, source:'claude' }`(content_ids).
- 재실행 멱등: B의 기존-이슈 대비 skip이 중복 생성 차단(이미 만든 draft도 기존 이슈로 잡힘). 기존 draft 삭제 안 함.

## D. API — `POST /api/admin/issues/candidates/generate` (신규)

- 어드민 게이트(기존 verifyAdmin), `runtime nodejs`, `maxDuration 120`(그룹 N개 × LLM 1콜 순차).
- body opts(days·maxCandidates·minGroupSize, 기본값). → 생성→dedup→insert. → `{ created, skipped, candidates: [{title, theme, contentCount}] }`. LLM 키 없음 503.

## E. 어드민 UI — `IssueManager.tsx` 확장

- 상단에 **"AI 이슈 후보 생성"** 버튼(기간 Select 7/14일 + 생성 → D API, 스피너·결과 문구 `N개 생성·M개 중복 skip`). `/admin/insights` 생성 패널 톤 미러.
- 목록에 **"AI 후보(draft)" 필터/섹션**: `source='claude' & status='draft'` 이슈. 각 후보에 **근거 콘텐츠 건수**(있으면 제목 몇 개 미리보기) + **승인(→published)** / **거절(→archived)** / **편집**(기존 handleSave 재사용). 상태전이는 기존 로직 재사용.
- (승인 후 기존 `handleRematch`로 match_keywords 추가 배정 가능 — 안내만.)
