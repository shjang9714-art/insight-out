## 배경 (David)

경쟁사 동향(96)·키워드맵(94)이 `keywords.is_competitor` 를 읽는데 **그 플래그를 켜는 UI가 없음**(KeywordManager는 서비스·카테고리 태깅만). 반면 `entities.is_competitor` 는 **엔티티 사전(100)에서 체크박스로 편집 가능.** → 두 필드가 따로 놀고, 정작 96이 쓰는 쪽은 등록 창구가 없는 빈 구멍. **경쟁사 등록 창구를 엔티티 사전 하나로 통일**한다.

## 설계 결정 (Opus, David 승인)

- 경쟁사 식별 = **`entities.is_competitor = true` 의 `canonical_name`**. 등록 = 어드민 **엔티티 사전(100) 경쟁사 체크박스**(기존). `keywords.is_competitor` 는 레거시(미사용, 컬럼 유지).
- 매칭 메커니즘 동일(이름 ↔ `matched_keywords` overlap/포함). 엔티티 canonical_name 은 키워드그룹 패턴에서 시드돼 matched_keywords 와 정합.

## 작업

### 1. 경쟁사 동향 names — `src/components/analysis/AiInsightsView.tsx` (L146 부근)
- `supabase.from('keywords').select('name').eq('is_competitor', true)` →
  **`supabase.from('entities').select('canonical_name').eq('is_competitor', true)`** → `competitorNames = rows.map(canonical_name)`. 이후 overlap 로직 동일.

### 2. 키워드맵 competitorSet — `src/components/analysis/AiInsightsView.tsx` (L243~246)
- topKeyword 이름들에 대해 경쟁사 여부 판정 시 `keywords` 대신 **`entities`**: `.from('entities').select('canonical_name, is_competitor').in('canonical_name', names)` → `is_competitor` 면 `competitorSet.add(canonical_name)`.
- (또는 1에서 받은 competitorNames 집합을 재사용해 쿼리 1회로 통합 — 권장.)

### 3. 논조 백필 후보 — `src/app/api/admin/sentiment/route.ts` (L69 부근)
- `from('keywords')...eq('is_competitor', true)` → **`from('entities').select('canonical_name').eq('is_competitor', true)`** → names 로 `overlaps('matched_keywords', names)`. 동일.

### 4. (확인) 등록 창구
- 엔티티 사전(100)에 경쟁사 체크박스 이미 존재 → 추가 작업 없음. KeywordManager 는 변경 없음(레거시 keywords.is_competitor 토글 추가하지 않음 — 통일 취지).

## 회귀 / 주의
- **신규 SQL 없음.** entities 미적용/빈이면 경쟁사 0(빈 상태 graceful) — 운영상 엔티티 사전에서 KT/SKT/삼성SDS 등 경쟁사 체크 필요(엔티티가 없으면 먼저 추가).
- canonical_name ↔ matched_keywords 매칭이라, 경쟁사 엔티티의 canonical_name 이 실제 기사 matched_keywords 에 나타나야 잡힘(키워드그룹 패턴 시드분은 정합).
- `keywords.is_competitor` 읽는 곳이 위 3곳뿐인지 재확인(grep `is_competitor`) — 누락 없이 전부 entities 로.
- 동작·UI 동일, 데이터 소스만 변경. 색·overlap·논조 백필 로직 그대로.
- UI 한국어(#1)·`any` 금지.
