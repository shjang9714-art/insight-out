## 0. 한 줄

163의 **positive/positive-soft 토큰을 민트(그린) → 블루로 전역 교체**해, 제품 전체에서 성공·긍정·증가 표시가 파란 톤이 되게 한다(그린 계열 제거). 토큰만 바꾸면 사용자·어드민 배지·칩이 자동 반영된다.

- 소비처(토큰 사용 → 자동 반영): 사용자 화면 163/166/167(긍정 sentiment·증가율·키워드 방향 ▲), 어드민 175 `StatusBadge`(성공/발행 tone=positive), 이슈 tone 등. **전부 토큰 경유** → 값만 바꾸면 일괄 변경.
- `--risk`(앰버 hue 50)·`--negative`(레드 hue 25)는 유지.

## 3. 구현 (`globals.css`)

`--positive`/`--positive-soft`의 hue를 **블루(≈ hue 255~262)** 로 교체(라이트+다크). 목표 색감:
- 라이트: `--positive` ≈ blue-600 `#2563EB` → `oklch(0.55 0.20 262)` · `--positive-soft` ≈ blue-50 `#EFF6FF` → `oklch(0.97 0.02 255)`
- 다크: `--positive` ≈ blue-400 `#60A5FA` → `oklch(0.72 0.13 253)` · `--positive-soft` ≈ `oklch(0.18 0.06 255)`
- 채도·명도는 기존 risk/negative와 균형 맞춰 미세조정 허용(대비 확보). **hue만 그린(155)→블루(255±)로 확실히 이동**이 핵심.
- (선택) info 토큰 신설이 필요하면 **슬레이트**(hue ~250, 저채도)로 별도 정의 — 단 현재 미사용이면 이번엔 생략(후속 v2에서).

**그린 잔재 점검**: 토큰 외에 컴포넌트에 하드코딩된 `emerald-*`/`green-*`(성공·긍정 의미)이 있으면 positive 토큰/블루로 교체. (175에서 어드민 상태배지는 토큰화됨. 사용자 화면·잔여 emerald 확인.)

## 4. 회귀 가드 / 비기능 요건

- 의미 불변: positive = 성공/긍정/증가(색만 블루). risk/negative/neutral 무변경.
- 라이트·다크 양쪽 대비 확보(블루 soft 배경 위 텍스트 가독).
- 토큰 경유 소비처 전부 자동 반영 — 개별 컴포넌트 수정 최소(하드코딩 그린만 정리).
- 블루가 브랜드 마젠타·정보와 혼동되지 않게(성공=블루는 라벨 동반이라 OK). 신규 hex 0(globals 토큰 정의부 제외).

## 5. 검증 (Sonnet 자체)

1. `npx tsc --noEmit` 0 / `npx eslint` 0
2. 긍정/증가/성공 배지·칩이 **블루**로 표시(사용자 이슈·인사이트 증가율, 어드민 성공/발행 상태)
3. `grep -rnE "emerald-|green-[0-9]" src/components src/app` → 성공·긍정 의미 잔재 0(의도적 잔여는 사유)
4. 라이트·다크 대비 OK, risk(앰버)·negative(레드)와 명확히 구분
