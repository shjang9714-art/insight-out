> 문제: `/dashboard/contents/[id]` 가 **풀본문 추출(`ensureFullBody`, 최대 6초)을 await 한 뒤 렌더** → 캐시 안 된 기사 클릭 시 최대 6초 빈 화면. 체감 최대 지연 지점.
> ⚠️ 작업 전 `AGENTS.md`(Next.js 16, 서버컴포넌트/Suspense) + 현재 `src/app/dashboard/contents/[id]/page.tsx`·`src/lib/contents/full-body.ts` 를 읽을 것.

## 0. 목표 (한 줄)
상세 페이지의 **제목·메타·태그·스니펫을 즉시** 보여주고, **풀본문은 `<Suspense>` 로 스트리밍**해서 추출이 끝나면 본문이 채워지게 한다. (초기 페인트가 추출을 기다리지 않음)

## 1. 핵심 변경
현재: 페이지 상단에서 `body = await ensureFullBody(...)` → 렌더 차단.
변경: **본문만 별도 async 서버 컴포넌트로 분리**하고 `<Suspense fallback={스니펫}>` 로 감싼다. 페이지의 나머지(제목/메타/태그/리포트 뷰어)는 즉시 렌더.

## 2. 할 일

### 2.1 `ArticleBody` async 서버 컴포넌트 (같은 파일 하단 또는 `src/app/dashboard/contents/[id]/ArticleBody.tsx` 신규)
- props: 상세 페이지가 조회한 콘텐츠 행(최소 `id, body_original, body_fetched_at, original_url, summary_ko` 등 `ensureFullBody` 에 필요한 필드).
- 내부에서 `const body = await ensureFullBody({...})` (지금 페이지가 만들던 Content 객체 구성 그대로 이동).
- 렌더: 본문 전문(`whitespace-pre-wrap` 등 기존 본문 스타일 그대로) + 하단 "원문 보기" 링크(`original_url`, target=_blank rel=noopener). **즉, 지금 뉴스 분기에서 본문+원문링크를 그리던 JSX를 이 컴포넌트로 이동.**
- 서버 전용(‘use client’ 없음). `ensureFullBody`/admin 은 서버에서만.

### 2.2 `page.tsx` 수정
- 상단의 `body = await ensureFullBody(...)` **제거**(뉴스 분기에서 await 안 함). 리포트 분기(`getReportSignedUrl`)는 **그대로 유지**(빠름).
- 뉴스 분기 본문 자리에:
  ```tsx
  <Suspense fallback={<ArticleBodyFallback snippet={content.summary_ko ?? content.body_original ?? ''} />}>
    <ArticleBody content={content} />
  </Suspense>
  ```
  - `ArticleBodyFallback`: 스니펫을 같은 본문 스타일로 즉시 표시 + 작게 "본문 불러오는 중…" 정도의 표시(차분하게, `text-gray-400`). 스니펫이 비면 "본문을 불러오는 중입니다…"만.
- `import { Suspense } from 'react'` 추가. 페이지는 `dynamic='force-dynamic'` 유지(스트리밍과 호환).

### 2.3 중복 쿼리 축소(가벼운 개선)
- `generateMetadata` 가 콘텐츠를 조회한다면 **`select('title')` 만**(메타는 제목만 필요) → 페이지 본 쿼리와의 중복 부담 감소.

### 2.4 건드리지 말 것
- `ensureFullBody` 내부 로직(타임아웃·캐시·폴백)·리포트 분기·태깅·크롤러 변경 금지.
- 데스크톱/모바일 시각 결과(레이아웃) 동일하게 — 본문이 "나중에 채워질" 뿐.
