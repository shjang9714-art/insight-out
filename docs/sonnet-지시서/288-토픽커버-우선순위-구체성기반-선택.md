## 0. 한 줄

토픽 커버를 **매칭된 첫 태그**가 아니라 **가장 구체적인 태그** 기준으로 고른다. `AI 기술`·`IT 동향` 같은 우산 태그가 모든 기사의 커버를 독점하는 걸 막는다.

## 1. 현행 진단 (검증된 코드 사실)

`src/lib/contents/topic-cover.ts`의 `pickTopicCover`:

```ts
const candidates = [
  ...(matchedGroups ?? []),
  ...(matchedKeywords ?? []),
  ...(category ? [category] : []),
]
for (const candidate of candidates) {
  if (!candidate) continue
  const urls = NORMALIZED_POOL[normalize(candidate)]
  if (urls && urls.length > 0) {
    return urls[hashIndex(id, urls.length)]   // ← 첫 매칭에서 즉시 return
  }
}
```

**문제**: 후보 순서에 **우선순위 개념이 없다.** `matchedGroups`/`matchedKeywords`에 담긴 순서(= 매칭된 순서)를 그대로 따르고 첫 매칭에서 멈춘다.

**실제 증상**(David 스크린샷):
- `자이스, 용인 반도체 센터 개소` — 태그 `#AI 기술` `#반도체` → **AI 기술 커버**가 붙음. 기사 핵심은 **반도체**인데.
- `메타 자체 칩 아이리스` — `#AI 기술` `#AIDC` `#IT 동향` `#데이터센터` → **AI 기술 커버**.
- `레티널 AI 글라스 광학 모듈` — `#AI 기술` `#IT 동향` → AI 기술 커버.

**구조적 원인**: `AI 기술`·`IT 동향`은 요즘 **거의 모든 기술 기사에 붙는 우산 태그**다. 이게 먼저 걸리면 구체 토픽(반도체·AIDC·모빌리티…)이 있어도 무시된다. 결과:
1. **의미 불일치** — 반도체 기사에 AI 일반 이미지.
2. **커버 독점** — 대부분의 기사가 AI 기술 풀로 몰려 같은 그림이 도배된다. (풀 장수를 늘려도 이 쏠림은 안 없어진다.)

**현재 토픽 키 22개**(매니페스트 기준):
`AI기술` `AICC` `AIDC` `AI보고서` `CCTV·영상보안` `ESG` `IT동향` `SME솔루션` `뉴스` `도요타` `리포트` `모빌리티` `반도체` `에너지` `웹인사이트` `전략보고서` `정부규제` `제조DX` `클라우드` `통신B2B` `피지컬AI` `현대자동차`

## 3. 구현 — `src/lib/contents/topic-cover.ts` 한 파일

### 3-1. 토픽 우선순위(구체성) 테이블 추가
숫자가 **작을수록 먼저** 선택된다.

```ts
/**
 * 토픽 선택 우선순위 — 작을수록 먼저(더 구체적 = 기사 주제를 잘 대표).
 * 'AI 기술'·'IT 동향'은 거의 모든 기술 기사에 붙는 우산 태그라, 구체 토픽이 있으면 양보시킨다.
 * 미등재 키는 DEFAULT_PRIORITY(구체 토픽으로 간주).
 */
const TOPIC_PRIORITY: Record<string, number> = {
  // 1) 엔티티 — 가장 구체적
  '도요타': 1,
  '현대자동차': 1,

  // 2) 구체 도메인 — 기사 주제를 잘 대표
  '반도체': 2,
  'AIDC': 2,
  'AICC': 2,
  '모빌리티': 2,
  '통신 B2B': 2,
  '제조 DX': 2,
  'CCTV·영상보안': 2,
  'SME 솔루션': 2,
  '피지컬 AI': 2,
  '클라우드': 2,
  '에너지': 2,
  'ESG': 2,
  '정부 규제': 2,

  // 3) 우산 토픽 — 구체 토픽이 없을 때만
  'AI 기술': 8,
  'IT 동향': 8,

  // 4) 카테고리·문서종류 — 최후
  '뉴스': 9,
  '웹인사이트': 9,
  '리포트': 9,
  'AI보고서': 9,
  '전략보고서': 9,
}

const DEFAULT_PRIORITY = 3   // 미등재 = 구체 토픽 취급(우산 토픽만 명시적으로 낮춘다)
```

### 3-2. `pickTopicCover` — 후보를 우선순위로 정렬 후 선택
```ts
export function pickTopicCover({ id, matchedGroups, matchedKeywords, category }: PickTopicCoverInput): string | null {
  const candidates = [
    ...(matchedGroups ?? []),
    ...(matchedKeywords ?? []),
    ...(category ? [category] : []),
  ].filter(Boolean) as string[]

  // 풀이 있는 후보만 남기고, (우선순위 → 원래 순서)로 안정 정렬
  const matched = candidates
    .map((c, i) => ({ c, i, urls: NORMALIZED_POOL[normalize(c)] }))
    .filter((x) => x.urls && x.urls.length > 0)
    .sort((a, b) => {
      const pa = TOPIC_PRIORITY[canonicalOf(a.c)] ?? DEFAULT_PRIORITY
      const pb = TOPIC_PRIORITY[canonicalOf(b.c)] ?? DEFAULT_PRIORITY
      return pa - pb || a.i - b.i          // 동순위면 원래 순서(안정)
    })

  const best = matched[0]
  if (!best) return null
  return best.urls[hashIndex(id, best.urls.length)]
}
```

- **`canonicalOf(c)`**: 후보 문자열(예: `'AI기술'`, `'ai 기술'`)을 `TOPIC_PRIORITY`의 키(canonical 토픽명)로 맞추는 헬퍼가 필요하다.
  - `NORMALIZED_POOL`은 `normalize()`된 키로 저장돼 있으므로, **`TOPIC_PRIORITY`도 같은 `normalize()`를 적용한 맵으로 미리 만들어 두는 게 안전하다**(모듈 로드 시 1회):
    ```ts
    const NORMALIZED_PRIORITY: Record<string, number> = {}
    for (const [k, v] of Object.entries(TOPIC_PRIORITY)) NORMALIZED_PRIORITY[normalize(k)] = v
    ```
    그리고 조회는 `NORMALIZED_PRIORITY[normalize(candidate)] ?? DEFAULT_PRIORITY`.
  - 이렇게 하면 `canonicalOf` 헬퍼 없이 `normalize()` 하나로 통일된다. **이 방식을 쓸 것.**

- **`hashIndex`는 그대로 유지** — 같은 기사엔 항상 같은 이미지(깜빡임 방지).

## 4. 회귀 가드

- **`hashIndex`의 결정성 유지** — 같은 콘텐츠 id는 항상 같은 이미지여야 한다(새로고침마다 바뀌면 안 됨).
- **매칭이 하나도 없으면 `null`** 반환(기존과 동일 — 카드가 `BrandedCover`로 폴백).
- **`normalize()`를 우선순위 조회에도 동일하게 적용** — `AI기술`/`AI 기술`/`ai기술`이 전부 같은 키로 잡혀야 한다. 안 그러면 우선순위가 조용히 무시되고 기존 동작으로 돌아간다(가장 실수하기 쉬운 지점).
- **미등재 토픽은 `DEFAULT_PRIORITY`(구체 취급)** — 새 토픽이 생겨도 우산 토픽에 밀리지 않는다. 우산 토픽만 명시적으로 8~9로 내린다.
- `TOPIC_COVER_POOL`·매니페스트 생성기·파일명 규약은 **건드리지 말 것**.
- 실사 썸네일(`thumbnail_url`)이 있으면 애초에 이 함수가 안 불린다 — `coverUrlFor`의 우선순위(실사 > 생성 풀)는 불변.
