# 지시서 365 — 키워드 상승요인 분석: 클립보드 폴백 + 키워드 대소문자 무시 매칭

> 대상: 구현 에이전트 · 관리자 전용 · **원칙적으로 신규 SQL 없음**(대소문자 처리에 최소 RPC가 필요하면 sql-handoff로 분리·수희)
> ⚠️ 읽을 것: `src/components/admin/AdminKeywordRiseAnalyze.tsx`(handleCopyContext) · `src/app/api/admin/keywords/rise/route.ts`(checkEligibility) · `src/lib/keywords/detail.ts`(L164 loadKeywordContents·L172 `.contains`·L190 resolveKeywordEntity) · `src/lib/keywords/rise.ts`(normalizeKeyword) · `AGENTS.md`

## 배경 (David, 재현됨)
1. **클립보드 실패**: 관리자 상승요인 패스② 화면에서 `[① 분석 컨텍스트 복사]`가 `navigator.clipboard.writeText`만 호출 → 브라우저가 클립보드를 막으면("The request is not allowed by the user agent") 프롬프트를 아예 못 얻어 API URL을 직접 열어야 했다.
2. **대소문자 오판**: 키워드 `ai`(소문자)로는 "최근 7일 기준 상승 또는 신규 키워드만 분석할 수 있습니다."로 거부되고 `AI`(대문자)만 통과. 원인 = `detail.ts` L172 `.contains('matched_keywords', [name])`가 배열 **정확일치**라 저장된 표기(예: "AI")와 대소문자가 다르면 0건 → 스냅샷 부적격. (`resolveKeywordEntity`는 이미 `ilike`라 무관.)

## 작업

### 1. 클립보드 폴백 (AdminKeywordRiseAnalyze.tsx)
- `handleCopyContext`에서 받아온 `data.prompt`를 **컴포넌트 state에 항상 보관**한다(`copiedPrompt` 등).
- `navigator.clipboard`가 없거나 `writeText`가 throw하면(권한 차단 등) 에러로 끝내지 말고, **프롬프트 원문을 읽기전용 textarea(또는 접힌 `<details>`)로 화면에 노출**해 관리자가 드래그로 수동복사할 수 있게 한다. 안내문구(예: `자동 복사가 차단됐습니다 — 아래 내용을 직접 복사하세요`).
- 자동복사 성공 시엔 기존 "복사됨" 토스트 유지(폴백 영역은 접힘/비노출이어도 됨). **성공/실패 어느 경우든 프롬프트는 확보**되게.
- `factCount`(근거 사건 N건) 표기는 유지.

### 2. 키워드 대소문자 무시 매칭
- **목표**: `ai`·`AI`·`Ai` 어떤 표기로 입력해도 동일 키워드로 취급돼 적격성·근거·저장이 일관되게 동작.
- 정타 지점 = `detail.ts`의 콘텐츠 매칭(`loadKeywordContents`의 `.contains('matched_keywords', [name])`). 배열 정확일치라 대소문자를 못 흡수한다.
- 권장 접근(무-SQL 우선):
  - **입력 키워드의 저장표기(canonical casing)를 먼저 해석**한 뒤 그 표기로 `.contains`를 태운다. 해석 순서: (a) `resolveKeywordEntity`(이미 `ilike`)로 매칭되면 그 `canonical_name` 사용 → (b) 없으면 `keywords`/최근 `matched_keywords`에서 **대소문자 무시로 실제 저장표기 1건을 조회**해 사용 → (c) 그래도 없으면 입력값 그대로.
  - 위 해석으로도 못 잡는 경우가 있으면 **최소 RPC**(`unnest(matched_keywords) k WHERE lower(k)=lower($1)` 기반 매칭/카운트)를 `sql-handoff/365-*.sql`로 분리해 수희 핸드오프(문서만, 코드에서 호출부는 준비). **RLS·grant 확인**.
- `rise.ts`의 `normalizeKeyword`(저장키는 이미 `toLocaleLowerCase('ko-KR')`)와 **표기 해석을 혼동하지 말 것**: 저장키(소문자 정규화)는 유지하되, **콘텐츠·스냅샷 매칭은 저장된 실제 표기**로 하도록 분리한다.
- 적격성 거부 메시지는 유지하되, 이제 대소문자 차이만으로는 거부되지 않아야 한다.

## 회귀 / 주의
- 관리자 전용(`verifyAdmin`) 게이트 유지. 색 토큰·한글 문구·`prefetch={false}`.
- 클립보드 폴백은 **HTTPS/비HTTPS·권한차단 모두에서 프롬프트 확보**가 핵심(자동복사는 best-effort).
- 대소문자 처리로 **한글 키워드·기존 대문자 키워드가 회귀하지 않게**(기존 통과하던 `AI`는 계속 통과).
- 검증: `tsc`·ESLint·`check-prefetch`·`build` + (dev)관리자에서 `ai`·`AI` 둘 다 적격 통과·근거 동일 + 클립보드 차단 시 폴백 textarea 노출. 완료보고에 커밋 해시.
