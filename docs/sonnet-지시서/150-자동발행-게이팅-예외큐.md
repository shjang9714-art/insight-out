## 0. 한 줄

AI 생성물(인사이트 카드·이슈)이 전부 `draft`로 떨어져 **관리자가 일일이 승인해야** 사용자에게 보인다 → 신선도 부채·운영 병목. **객관적 신뢰 임계 이상은 생성 즉시 `published`(자동발행), 미만만 `draft`(예외 큐)**로 바꾼다. 보수적 임계 + 언제든 회수(unpublish) 가능. 관리자는 "전부 승인"이 아니라 "경계선만 검토".

## 1. 현행 진단 (검증된 코드 사실)

- 인사이트 카드: `src/lib/insight/generate.ts` 산업/회사 upsert 모두 `status: 'draft'`. 사용자뷰(`AiInsightsView`)·카드뉴스는 `status='published'`만 노출.
- 이슈: `generate-candidates.ts` 후보 → admin route(`candidates/generate`)·cron(`ai-refresh`) 둘 다 `status: 'draft'` insert.
- 승인: 어드민 PATCH(`/api/admin/insights/[id]`, 이슈는 IssueManager)로 수동 draft→published. **회수도 같은 경로**(published→draft).
- 즉 생성은 자동화(145/149)됐는데 **발행만 사람 게이트**.

## 2. DB / SQL

**스키마 변경 없음.** `status` 컬럼 기존. 자동발행 = 생성 시 status 값 분기. 회수는 기존 PATCH 재사용.

## 3. 구현

### 3-1. `src/lib/insight/auto-publish.ts` (신규, server-only) — 신뢰 판정 단일 출처

튜닝 가능한 임계 상수 + 순수 판정 함수. (ML 아님, 객관적 규칙.)

```ts
import 'server-only'

// 자동발행 임계 — 보수적. 미달은 draft(사람 검토).
export const AUTO_PUBLISH = {
  insight: { minCitations: 2, minSources: 3 },
  issue:   { minContents: 4 },
}

export function insightAutoPublish(validCitations: number, sourceCount: number): boolean {
  return validCitations >= AUTO_PUBLISH.insight.minCitations
      && sourceCount   >= AUTO_PUBLISH.insight.minSources
}

export function issueAutoPublish(contentCount: number): boolean {
  return contentCount >= AUTO_PUBLISH.issue.minContents
}
```

근거: 인용 검증(환각가드)을 이미 통과한 카드 중 **인용 2+·출처 3+** 면 사실 근거가 충분. 이슈는 LLM이 고른(환각가드 통과) **콘텐츠 4건+** 이면 테마 실체가 있음. 미달은 빈약 → 사람 판단.

### 3-2. 인사이트 카드 — `generate.ts` 두 upsert

산업·회사 upsert payload의 `status: 'draft'` → 조건부:
```ts
import { insightAutoPublish } from '@/lib/insight/auto-publish'
// ...
const autoPub = insightAutoPublish(validCitations.length, sourceIds.length)
// payload:
status: autoPub ? 'published' : 'draft',
...(autoPub ? { published_at: new Date().toISOString() } : {}),
```
- **`published_at` 세팅은 수동 PATCH 발행이 세팅하는 필드와 동일하게** 맞출 것(PATCH route 확인 → 같은 필드/값). insight_cards에 published_at 컬럼 없으면 status만, upsert 헬퍼(148 `upsertInsightCard`)가 42703 폴백하므로 안전하게 포함 가능하나 **불명 컬럼 추가 금지** — PATCH가 실제로 쓰는 필드만 미러.

### 3-3. 이슈 — admin route + cron 두 insert

`candidates/generate/route.ts`·`ai-refresh/route.ts`의 이슈 insert `status: 'draft'`:
```ts
import { issueAutoPublish } from '@/lib/insight/auto-publish'
// ...
status: issueAutoPublish(candidate.content_ids.length) ? 'published' : 'draft',
```
(이슈도 PATCH 발행이 published_at 등 세팅하면 동일 미러.)

### 3-4. 예외 큐 가시화 (가벼운 터치)

자동발행으로 draft에 남는 건 "경계선"뿐 → 관리자가 거기만 보게. 기존 화면 최소 보강:
- `/admin/insights`·이슈 관리: 상단에 **"검토 대기 N"** 카운트(draft 수) + draft 필터 칩. (122 AdminTodoBlock에 이미 검토대기 집계 있으면 거기에 인사이트/이슈 draft 합류만.)
- 큰 재설계 금지 — 카운트+필터 수준. 자동발행이 본질이고 이건 보조.

### 3-5. 회수 안전망 (확인만)

- 자동발행물 오류 시 회수 = 기존 PATCH(published→draft/archived) 그대로 동작하는지 확인. 신규 작업 없음.

## 4. 회귀 가드 / 비기능 요건

- 임계 미달 → 기존과 동일(draft, 사람 승인). **회귀 0**, 단지 고신뢰분만 자동 노출.
- 자동발행은 **인용 검증(환각가드) 통과분에 한정** → 무근거 노출 차단.
- 회수(unpublish) 경로 유지 = 사후 교정 가능.
- 임계는 `AUTO_PUBLISH` 상수 한 곳 → 튜닝 쉬움.
- SQL·신규 의존성 0. 하드코딩 hex 0(UI는 카운트/칩, 기존 토큰).

## 6. 후속 (범위 밖)

- 자동 vs 수동 발행 구분 마커(감사/롤백용) — 필요 시 `auto_published` 플래그.
- 품질점수 정교화(소스 tier·신선도 가중, E2 연계) → 임계 동적화.
- 사건 타임라인·브리핑 등 다른 생성물 자동발행 확장.
