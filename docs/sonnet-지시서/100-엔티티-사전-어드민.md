## 배경 (David)

엔티티 토대(99)는 룰 시드라 "MS"와 "Microsoft"가 별개로 들어온다. **정규화(병합)·큐레이션 도구**가 지식그래프의 실질 가치. 어드민이 엔티티를 추가/수정하고, 동의어를 묶고, 중복을 **병합**하는 화면이 이번 슬라이스. (인물 엔티티 수동 추가도 여기서 — NER 전까지.)

## 설계 결정 (Opus, 확정)

1. **CRUD = 클라이언트 supabase + is_admin RLS**(KeywordGroupManager 동일 방식, 엔드포인트 불필요). 99의 "admin 전체" 정책으로 insert/update/delete 가능.
2. **병합 = RPC `merge_entities(source, target)`**(원자적·다중 테이블 → SECURITY DEFINER, is_admin 내부검사). 클라에서 `supabase.rpc('merge_entities', { p_source, p_target })`.
3. **alias 는 글로벌 unique** — 한 동의어는 한 엔티티. 병합 시 소스 canonical 이 타깃 alias 로 보존.
4. **노출 위치 = 관리 › 분류 엔진 그룹**(키워드 그룹 인근). 신규 1차 메뉴/계위 변경 없음(IA 진화는 후속).

## 작업

### A. (선행) SQL — `docs/sql-handoff/100-merge-entities.sql` (수희 선적용·먼저 푸시)
- 내용(작성됨): `merge_entities(p_source, p_target)` — content_entities 충돌제거 후 이전 → alias 이전 → 소스 canonical→타깃 alias → 소스 삭제(cascade) → mention_count 재계산. `grant execute ... to authenticated`.
- `supabase/schema.sql` SSOT 에 함수 정의 반영(#6).

### B. EntityManager 컴포넌트 — `src/components/admin/EntityManager.tsx` (신규, `'use client'`)
KeywordGroupManager 구조 미러(클라 supabase, 폼 state, 목록, 칩 입력, 로딩/에러 한국어).

- **목록·필터**: `entities` select(id·canonical_name·entity_type·description·is_competitor·service_id·mention_count) `order mention_count desc`. 상단 컨트롤: 타입 필터(전체 + EntityType 6종, `ENTITY_TYPE_LABEL`), 검색창(이름·동의어). 행: 타입 배지(색)·canonical_name·mention_count·is_competitor 표시·(액션: 수정·동의어·병합·삭제).
  - 검색은 canonical_name `ilike` + `entity_aliases.alias ilike` 조회해 entity_id 합집합(중복 발견 핵심).
- **생성/수정 폼**: canonical_name, entity_type(셀렉트 6종), description, is_competitor(체크), service_id(서비스 셀렉트, nullable — `services` select id·name). 저장:
  - 생성: `entities.insert(...)` → 성공 시 `entity_aliases.insert({entity_id, alias: canonical_name})`(on conflict 무시 위해 사전 존재 체크 또는 try).
  - 수정: `entities.update(...).eq('id', ...)`.
- **동의어 관리**(엔티티별): 선택 엔티티의 `entity_aliases` 목록(칩) — 추가(insert, 중복/타엔티티 점유 시 에러 안내), 삭제(delete). canonical_name alias 는 삭제 비권장(안내).
- **병합**: 한 엔티티에서 "다른 엔티티로 병합" → 대상 엔티티 검색·선택 → `window.confirm`(파괴적: "이 엔티티를 X로 병합합니다. 되돌릴 수 없습니다.") → `supabase.rpc('merge_entities', { p_source: thisId, p_target: targetId })` → 목록 새로고침. 에러 한국어.
- **삭제**: `entities.delete().eq('id', ...)`(cascade) + confirm.

## 회귀 / 주의
- **SQL 선적용**: `merge_entities` 없으면 병합 버튼 rpc 실패(에러 안내) — CRUD 는 99 적용 시 동작. 99 미적용이면 목록 빈상태.
- 병합은 **되돌릴 수 없음** — confirm 필수. RPC 원자적(부분 병합 없음).
- alias **글로벌 unique** — 다른 엔티티가 점유한 동의어 추가 시 23505 → "이미 다른 엔티티에 등록된 동의어입니다" 안내.
- CRUD 는 클라+RLS(서버 엔드포인트·service_role 금지, #8). 어드민 세션만(미들웨어가 /admin 가드).
- `any` 금지·UI 한국어(#1)·색 토큰(#9)·`cn()`·shadcn(Select/Input/Button/Badge) 재사용·lucide만.
- mention_count 는 병합 시 RPC가 재계산. 일반 CRUD 는 갱신 안 함(백필/후속 트리거 영역) — 정렬 보조값일 뿐.
