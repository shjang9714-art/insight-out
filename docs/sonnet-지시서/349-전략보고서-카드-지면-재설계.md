## 배경 (David)

레퍼런스(첨부 리포트 카드 그리드)와 비교했을 때 문제가 셋이었다.

1. **카드에 제목이 두 번 나온다.** 커버 이미지 안에 한 번, 그 아래 본문에 또 한 번. 같은 문장이 두 번 나오면 그 공간의 정보량은 0이다.
2. **본문 폭이 좁고(768px) 폰트가 작다.** 임원 보고용 문서인데 14px 본문이라 임팩트가 없다.
3. **제목·개요가 본문 HTML과 분리돼 있다.** 인쇄·PDF에서 두 문서처럼 보인다.

## 설계 결정 (Opus·David)

1. **커버에 제목을 쓰지 않는다.** 커버는 유형을 색으로 구분하는 표지 블록(아이콘 + `INSIGHT REPORT` 워드마크). 제목은 본문 영역에서 한 번만.
2. **표지 + 본문을 하나의 지면으로 합친다.** 인쇄해도 한 문서다.
3. **본문 폭 `max-w-5xl`(1024px)** — 표·인용이 있는 지면에 맞다. 목록은 `max-w-6xl`(1152px) 그대로. (768/896/1024/1152 중 David 선택)
4. **이모지 금지, 포멀한 표식만.** 시선을 잡되 장식이 되지 않는 것: 유형 아이콘(lucide 라인), 섹션 마커(브랜드 사각), 불릿(브랜드 원), 번호 배지.
   - **체크(✓)는 쓰지 않는다.** "AIDC — 정면 충돌" 같은 분석 항목에 체크가 붙으면 완료된 할 일 목록처럼 읽힌다. 체크는 실행 항목 목록에서만 의미가 있다.
5. **본문 스타일은 전부 요소 선택자로.** `sanitizeReportHtml`이 `class` 속성을 제거하므로 body_html에 클래스를 심을 수 없다. → `globals.css`의 `.io-report-body` 하위 선택자로 처리.

## 작업

### A. 카드 — `src/components/reports/ReportCard.tsx`

- 커버(폴백): 유형별 그라데이션 + **lucide 라인 아이콘** + 우상단 `INSIGHT REPORT`(10px, tracking 0.18em). **제목 렌더 금지.**
  | 유형 | 아이콘 | 커버 |
  |---|---|---|
  | 시장동향 | `LineChart` | `from-blue-700 to-blue-900` |
  | 경쟁사분석 | `Radar` | `from-rose-800 to-slate-900` |
  | 키워드분석 | `Tags` | `from-violet-700 to-violet-950` |
  | 서비스리포트 | `Layers` | `from-emerald-700 to-teal-900` |
  | 자유주제 | `FileText` | `from-slate-600 to-slate-800` |
- `cover_image_url`이 있으면 이미지(alt=""; 제목은 아래에 있으므로 중복 낭독 방지).
- 본문: 유형 칩 → **제목 `text-[17px] font-bold` 2줄** → 요약 2줄 → 푸터(`발행일 · 발행자` / `보고서 열기 →`).

### B. 상세 지면 — `src/app/dashboard/reports/[id]/page.tsx`

- `PageContainer variant="reading"`(max-w-3xl) → `PageContainer` + `div.io-report.mx-auto.max-w-5xl`
- **표지 + 본문을 하나의 카드(`rounded-2xl border p-8 sm:p-12`)** 안에. 표지는 `border-b-2 border-foreground pb-6`.
  - 메타: 유형 칩 + `CalendarDays` 발행일 + `Building2` 발행자 (13px)
  - 제목 `text-[30px] sm:text-[34px] font-bold`
  - 리드(summary) `text-[17px] leading-[1.8]`
- **근거 섹션도 같은 지면 안으로** (`border-t-2` + `Link2` 아이콘).
- 타이포 스케일 상향:

| 요소 | 전 | 후 |
|---|---|---|
| h2 | 16 | **24 / bold** |
| h3 | 14 | **19 / bold** |
| p·li | 14 | **16 / leading 1.85** |
| table | 14 | **15 / 패딩 확대** |
| 리드 | 14 | **17** |
| 제목 | 20 | **30~34** |

### C. 본문 표식 — `src/app/globals.css` (`.io-report-body`)

```css
/* 섹션 마커 — h2 앞 브랜드 사각(4×0.72em) */
.io-report-body h2::before { … }
/* 불릿 — 브랜드 원, 중첩은 빈 원 */
.io-report-body ul > li::before { … }
/* 번호 — 연한 브랜드 원형 배지(counter) */
.io-report-body ol > li::before { content: counter(io-ol); … }
/* 항목 앞머리 굵은 어구는 브랜드 컬러(스캔 시 눈이 걸리는 지점) */
.io-report-body li > strong:first-child { color: var(--color-brand-700); }
```
- 프로즈 클래스에서 `list-disc` / `list-decimal` / `pl-*` 제거(위 CSS와 충돌).
- 인쇄 규칙(`@media print`, `.io-report`)은 348에서 추가한 것 유지.

### D. 주간 리포트 정합 — `CompetitorWeeklyReport.tsx`

`지켜볼 지표`의 `·` 문자 불릿 → 동일한 브랜드 원 표식으로 통일.

## 회귀 / 주의

- `sanitizeReportHtml`의 `allowedAttributes`는 **건드리지 않는다.** class 허용은 XSS 표면을 넓힌다 — 스타일은 요소 선택자로 충분하다.
- `[&_li]:pl-1` 같은 Tailwind 유틸리티를 다시 넣지 말 것. `.io-report-body`의 `padding-left`와 충돌한다.
- 커버 이미지의 `alt`는 빈 문자열이어야 한다(제목이 바로 아래에 있어 중복 낭독).
- 다크모드: 유형 칩·커버 그라데이션 `dark:` 변형 확인.
- 검증: `npx tsc --noEmit` · ESLint · `check-prefetch` · `npm run build` · 육안(`/dashboard/reports` 카드, 상세, 인쇄 미리보기).
