## 0. 한 줄
크론(`/api/cron/briefing`)이 **스크립트만 자동 생성**하고 TTS 는 어드민 수동 전용이라, 매일 오디오가 비어 미니플레이어가 재생 불가다. **크론에 `synthesizeBriefingAudio` 를 best-effort 로 붙인다.**

---

## 1. 착수 전 확인 (직접 확인 2026-07-23)

- **크론**(`/api/cron/briefing`, 35줄): `generateBriefing({ force, date, autoPublish: true })` **만** 호출. `maxDuration = 60`.
- `generateBriefing`(`generate-briefing.ts`): **스크립트 생성·발행까지.** TTS(`synthesize`) 호출 없음.
- **TTS 호출처는 어드민 2곳뿐**: `/api/admin/briefings/route.ts`·`/api/admin/briefings/[id]/tts/route.ts` → `synthesizeBriefingAudio(id)`.
- `synthesizeBriefingAudio(briefingId)`(283행): 스크립트 조회 → Gemini TTS → PCM→WAV → Storage 업로드 → `briefings.audio_url` 갱신. **자체 예산·cap 체크**(`TTS_MONTHLY_CHAR_CAP`·`TOTAL_BUDGET_SECONDS`) + **rate limit 재시도**(429 백오프).
- **결과**: 매일 스크립트는 나오지만 `audio_url = null` → `FloatingBriefingMini` 의 `hasAudio` false → 재생 버튼 비활성(🚫). David 가 겪은 그 화면.

---

## 2. 구현 — 크론에 TTS best-effort 추가

### 2.1 `/api/cron/briefing/route.ts`
`generateBriefing` 성공 후, **생성된 브리핑 id 로 `synthesizeBriefingAudio` 를 호출**한다.
```ts
const result = await generateBriefing({ force, date, autoPublish: true })
// 스크립트 생성/발행이 끝났으면, 오디오도 이어서 생성(best-effort).
if (result?.ok && result.briefingId) {          // ← generateBriefing 반환에 id 가 있는지 §2.2 확인
  try {
    const tts = await synthesizeBriefingAudio(result.briefingId)
    if (!tts.ok) console.warn('[cron/briefing] TTS 스킵:', tts.reason)
  } catch (e) {
    console.error('[cron/briefing] TTS 실패(무시):', e)   // 스크립트 발행은 유지
  }
}
```
- ⚠️ **`generateBriefing` 반환 형태 확인**(§2.2). `briefingId` 를 안 주면, `date` 로 방금 만든 브리핑을 조회해 id 를 얻는다(어드민 `/api/admin/briefings/route.ts` 가 하는 방식 참고).

### 2.2 반환·조회 확인
- `generateBriefing` 이 `{ ok, briefingId? }` 를 주는지 코드로 확인. 없으면 크론에서 `briefings` 를 `briefing_date = 오늘` 로 조회해 id 취득(단건).
- **이미 오디오가 있으면(재실행) 재생성하지 않는다** — `synthesizeBriefingAudio` 내부에 멱등 가드가 있는지 확인. 없으면 `audio_url` 존재 시 스킵을 크론에서 건다(TTS 예산 낭비 방지).

### 2.3 🔴 best-effort 원칙 (실패 격리)
- **TTS 실패가 브리핑 생성/발행을 깨면 안 된다.** try/catch 로 감싸 실패는 로그만, 크론 응답은 스크립트 성공으로.
- rate limit(`tts.ok === false`, reason 에 rate limit)·예산 초과는 **정상 스킵** — 다음 실행/다음날 재시도. 크론 실패로 처리하지 않는다.

### 2.4 maxDuration 여유 확인
- 현재 `maxDuration = 60`. `generateBriefing`(LLM 스크립트) + `synthesizeBriefingAudio`(Gemini TTS + WAV + 업로드)가 **60초 안**에 드는지 확인.
- 빠듯하면 **maxDuration 을 상향**(예: 120·300 — Hobby 상한 확인). Vercel 함수 시간제한 초과 시 오디오가 잘려 실패하므로, TTS 소요를 고려해 넉넉히.
- ⚠️ Hobby 플랜 함수 실행 시간 상한을 초과하지 않는 선에서.

### 2.5 하지 말 것
- `synthesizeBriefingAudio`·`generateBriefing` **내부 로직 무수정.** 크론이 순서대로 부르기만.
- 어드민 수동 TTS 버튼 **유지**(재생성·특정 브리핑용).
- `vercel.json` briefing 크론 **스케줄 무변경**(402 의 하루 1회 원칙).
- `FloatingBriefingMini` 는 이 지시서에서 안 건드린다(별건 §4).

## 3. 회귀 가드
1. **크론 실행 → 스크립트 생성 + 오디오 자동 생성**(`audio_url` 채워짐).
2. 다음날 사용자 홈에서 **미니플레이어 재생 버튼 활성**(🚫 아님), 재생됨.
3. **TTS 실패해도 스크립트는 발행**된다(크론이 실패로 안 죽음).
4. rate limit·예산 초과 시 **정상 스킵**, 로그만.
5. 재실행 시 **이미 있는 오디오 재생성 안 함**(예산 절약).
6. 어드민 수동 TTS 버튼 그대로 동작.
7. maxDuration 안에서 완료(타임아웃 없음).
