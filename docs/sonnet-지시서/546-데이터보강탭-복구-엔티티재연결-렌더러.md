## 1. 실측 사실 — 재조사 금지

### 1-1. 증상

어드민 > 소스 관리 > **`데이터 보강 재처리`** 탭을 누르면 화면 전체가
error boundary(`콘텐츠 준비중...`)로 떨어진다. 탭 안의 작업 **9개 전부** 못 쓴다.

### 1-2. 원인 — 렌더러 목록에 키가 하나 빠졌다

`src/components/admin/AdminContentProcessing.tsx:82-86`

```ts
export default function AdminContentProcessing({ jobs }: Props) {
  for (const job of jobs) {
    if (!DATA_JOB_RENDERERS.includes(job.key)) {
      throw new Error(`[enrich-jobs] data 화면에 ${job.key} 렌더러가 없습니다.`)
    }
  }
```

- `getEnrichJobs('data')` 가 반환하는 **9개**(itemScoped 제외):
  `body-backfill` · `canonical-backfill` · `thumbnail-backfill` · `youtube-transcript` ·
  `pdf-cover-backfill` · `cluster-backfill` · **`entity-relink`** · `youtube-tagging` ·
  `translate-backfill`
- `DATA_JOB_RENDERERS`(`:41-50`) 에 있는 것은 **8개** — **`admin:entity-relink` 가 없다.**

⇒ 렌더 시작 즉시 throw.

### 1-3. 언제부터인가

커밋 **`4385eb0`** "feat: 엔티티 소급 재매칭 백필 추가" (2026-08-21 23:34 KST) 가
`enrich-jobs.ts` 에 `admin:entity-relink` 를 추가하면서
**`AdminContentProcessing.tsx` 는 건드리지 않았다.** 그 커밋의 변경 파일 4개에 없다.

⇒ **그때부터 이 탭은 계속 죽어 있었다.**

### 1-4. 🔴 이 가드는 없애면 안 된다

`:82-86` 의 throw 가 바로 이 누락을 드러낸 장치다.
**가드를 지워서 "에러를 없애는" 방식으로 고치지 말 것.** 그러면 다음에 잡을 추가할 때
카드가 조용히 안 그려지고 아무도 모른다. **가드는 그대로 두고 렌더러를 추가한다.**

### 1-5. 작업 메타 (이미 있다 — 건드리지 말 것)

## 2. 작업

`src/components/admin/AdminContentProcessing.tsx` **한 파일만** 고친다.

### 2-1. `DATA_JOB_RENDERERS` 에 키 추가

`'admin:cluster-backfill'` 과 `'admin:youtube-tagging'` 사이에
`'admin:entity-relink'` 를 넣는다 (`ENRICH_JOBS` 정의 순서와 맞춘다).

### 2-2. 잡 참조 추가

`clusterJob` 아래에:

```ts
const entityRelinkJob = requireEnrichJob(jobs, 'admin:entity-relink', 'data')
```

### 2-3. 카드 렌더 추가

`clusterJob` 카드 다음 자리에, **`canonicalJob` 카드와 같은 단순 패턴**으로 넣는다.

```tsx
<JobCard
  job={entityRelinkJob}
  isRunning={isRunning(entityRelinkJob.key)}
  pending={pendingFor(entityRelinkJob.key)}
  description={<>매칭 키워드는 있는데 엔티티 링크가 없는 기사를 규칙 기반으로 다시 잇습니다.<br />전체 범위로 실행하며 남은 대상이 0이 될 때까지 자동 반복합니다.</>}
>
  <Button
    type="button"
    size="sm"
    variant="outline"
    disabled={isRunning(entityRelinkJob.key)}
    onClick={() => startJob(entityRelinkJob.key)}
  >
    엔티티 다시 연결
  </Button>
</JobCard>
```

⚠️ **`startJob` 에 인자를 주지 않는다** — `from`/`to` 없이 전체 범위가 기본이고,
지금 필요한 것도 전체 범위다.

## 4. 검증 — 브라우저 없이 할 수 있는 것

⚠️ 최종 화면 확인은 머지 후 David 담당이다. 여기서는 아래만 한다.

### 4-1. 🔴 목록과 렌더러가 1:1 인지 (핵심)

`getEnrichJobs('data')` 가 주는 키 집합과 `DATA_JOB_RENDERERS` 가
**정확히 같은지** 스크립트로 대조하고 **양쪽 목록을 보고에 적는다.**

```
getEnrichJobs('data') 키:  [...]   ← 9개
DATA_JOB_RENDERERS:        [...]   ← 9개여야 한다
차집합(양방향):             없음
```

**차집합이 하나라도 있으면 실패다.** 스크립트는 커밋하지 않는다.

### 4-2. `requireEnrichJob` 호출 개수

`requireEnrichJob(...)` 호출이 **9개**여야 한다(기존 8 + `entityRelinkJob`).
