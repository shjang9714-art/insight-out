## 0. 한 줄

**"뉴스 요약"은 어디에나 있다. "이게 우리한테 무슨 의미인가"가 Insight Out이 있는 이유다.**
그걸 **LLM이 지어낸 한 줄이 아니라, 이미 가진 사실 두 가지**로 보여준다:
① **위기/기회 신호**(`lgu_impact`) · ② **이 기사가 실제로 어디에 쓰였는지**(역참조).

---

## 1. ⚠️ 초안 폐기 — "시사점 서술문"은 만들지 않는다

> **초안(2026-07-12 오전)은 요약 LLM 호출에 "LG U+ 관점 시사점 1~2문장"을 얹으려 했다. 폐기한다.**
> 폐기 사유를 남기는 이유: 다음에 또 같은 아이디어가 나온다.

1. **개별 기사에 시사점은 대부분 뻔하다.** 진짜 시사점은 **여러 기사를 묶어야** 나온다(*"경쟁사 3곳이 3주 연속 AIDC 투자를 발표했다"*). 기사 한 건에서는 나올 수 없다.
2. **그 일은 이미 하고 있다.** 인사이트 카드·주간리포트·전략보고서가 정확히 그 층위다. 313은 그걸 기사 단위로 흉내 내는 것이고, **흉내는 뻔해진다.**
3. **LLM은 null을 안 낸다.** *"이 기사의 LG U+ 시사점은?"* 이라고 물으면 프롬프트에 순응해 억지로 만든다. 그러면 모든 카드에 *"AI 시장 성장은 LG U+의 AI 사업에도 시사점을 줍니다"* 급 문장이 붙는다.
4. **뻔한 문장은 없느니만 못하다.** 화면의 좋은 자리를 차지한 채 **신뢰만 깎는다.** 사용자는 한 주 만에 그 영역을 안 읽게 된다.
5. **증거**: `lgu_impact`(241)는 만들어진 뒤 **사용자 화면에 한 번도 안 올라갔다.** 붙일 만큼 유용하지 않았다는 신호다 — **라벨조차 그랬는데 서술문은 더하다.**

**→ `contents.lgu_implication` 컬럼을 만들지 않는다. `313-lgu-implication.sql`은 폐기.**

## 4. 구현

### 4-1. 위기/기회 배지 — **LLM 0**

**콘텐츠 상세**(`dashboard/contents/[id]/page.tsx`) **+ 카드**(`ContentCard.tsx`)
- `lgu_impact === '위기'` → **위기**
- `lgu_impact === '기회'` → **기회**
- `lgu_impact === '관망'` 또는 `null` → **아무것도 안 띄운다** ⛔

⚠️ **색·모양을 새로 정하지 말 것 — 이미 경쟁사 화면에 같은 배지가 있다.**
```tsx
// src/components/entities/CompetitorNewsGroups.tsx:40,43  (기존)
위기: className="rounded-full px-2 py-0.5 text-[11px] font-semibold bg-negative-soft text-negative"
기회: className="rounded-full px-2 py-0.5 text-[11px] font-semibold bg-blue-50 text-blue-700 dark:bg-blue-950/40 dark:text-blue-300"
```
→ **기회는 초록이 아니라 파랑이다.** 같은 개념이 화면마다 다른 색이면 그게 인지부조화다.
**공용 배지 컴포넌트로 추출**하고 경쟁사 화면도 그것을 쓰게 할 것. 색을 새로 짓지 말 것.

> **`관망`에 배지를 띄우지 말 것.** 대부분이 관망이라 배지가 의미를 잃는다. **신호는 드물어야 신호다.**

- `.select`에 `lgu_impact` 추가(목록·상세 둘 다). 컬럼 미적용(42703) graceful.

### 4-2. **"위기/기회만 보기" 필터** — 이게 실제 워크플로다

콘텐츠 목록 상단 필터에 추가:
```
[전체] [🔴 위기] [🟢 기회]
```
*"이번 주 우리한테 나쁜 소식만 훑자"* 가 실제 사용 시나리오다. 배지만 있고 필터가 없으면 반쪽이다.

### 4-3. ⭐ 역참조 — "이 기사를 인용한 리포트·인사이트"

**콘텐츠 상세 하단**(관련 콘텐츠 위):

```
이 기사를 인용한 리포트·인사이트

  📄 전략보고서     2026 AIDC 경쟁 구도            →
  💡 AI 인사이트    SKT, 데이터센터 투자 확대       →
  🏢 기업 인사이트   SK텔레콤                       →
  🎙 모닝브리핑     7월 12일                       →
```

**문구 (David 확정)**
- 제목: **`이 기사를 인용한 리포트·인사이트`**
- ⛔ **부제문을 붙이지 말 것.** *"아래 자료의 근거로 활용되었습니다"* 같은 설명 줄은 **화면만 차지하고 안 읽힌다.** 제목 하나로 뜻이 다 전달된다.
- ⛔ *"분석"* · *"활용"* 이라는 단어를 쓰지 말 것 — 전자는 헷갈리고(David), 후자는 관공서 톤이다.
- **톤: 사실적·담백.** 이 블록은 설득하는 곳이 아니라 **사실을 보여주는 곳**이다.

**요건**
- 각 항목은 **해당 산출물로 이동하는 링크**여야 한다. 클릭 유도가 이 블록의 목적이다.
- **하나도 없으면 블록 자체를 렌더하지 말 것.** *"인용된 곳 없음"* 같은 빈 껍데기 금지.
- **발행된 것만**(`status = 'published'` 등) 보여줄 것. 초안·미발행을 노출하면 안 된다.
- 조회는 **한 번에 병렬로**(`Promise.all`). 상세 페이지가 느려지면 안 된다.
- 항목이 많으면 **종류별 최대 3건 + "더 보기"**.

**⚠️ 조회 실패 graceful**: 4개 중 하나가 실패해도 **나머지는 보여줄 것.** 전부 날리지 말 것.

### 4-4. 왜 이게 "시사점"보다 강한가 (구현자 참고)

- **사실이다.** LLM이 지어낸 게 아니라 *"우리 분석이 실제로 이 기사를 근거로 삼았다"* 는 기록이다.
- **뻔해질 수가 없다.** 없으면 안 보여주면 그만이다.
- **탐색을 유도한다.** 기사 → 리포트 → 다른 기사로 이어진다. 제품 안에 머물게 한다.
- **LLM 0원.**

## 5. 회귀 가드

- ⛔ **`lgu_implication` 컬럼·시사점 서술문을 만들지 말 것**(§1). 초안은 폐기됐다.
- ⛔ **`관망`에 배지를 띄우지 말 것.** 신호가 흔해지면 신호가 아니다.
- ⛔ **역참조가 비면 블록을 렌더하지 말 것.** 빈 껍데기 금지.
- **미발행 산출물을 노출하지 말 것.**
- **역참조 조회 하나가 실패해도 나머지는 보여줄 것.** 상세 페이지가 통째로 죽으면 안 된다.
- **`lgu_impact` 컬럼 미적용(42703) graceful.**
- **LLM을 새로 호출하지 말 것.** 이 슬라이스는 **LLM 0**이다. `classifyLguImpact`·`backfillLguImpact`는 그대로 둔다(기존 백필용).
- 상세 페이지의 기존 섹션(요약·본문·관련 콘텐츠·관련 기업·북마크) **불변**.
- 목록의 기존 필터·정렬·페이지네이션과 충돌하지 말 것.
- **`insight_cards.citations`(jsonb)를 쓰지 말 것** — `source_content_ids`(uuid[])가 정본이다.

## 7. 후속 (범위 밖)

- **경쟁사 주간 리포트 역참조** — 근거가 `sections jsonb`에 묻혀 있다. **근거를 별도 테이블/컬럼으로 빼는 게 먼저**다. 별도 슬라이스.
- 카드에도 역참조 요약(*"리포트 2건에 인용됨"*) — 카드 밀도 정리 후.
- `lgu_impact` 정확도 개선 — 데이터가 화면에 올라가야 틀린 걸 발견할 수 있다. **먼저 보여주고 나서 고친다.**
- `llmCompleteDetailed`가 `hardLimit`을 반환하게 — 지금은 `errorReason.includes('한도소진')` 문자열 매칭이라 취약(310 후속 잔여).
