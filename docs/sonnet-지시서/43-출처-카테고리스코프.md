## 배경 (버그)
콘텐츠/검색 페이지가 출처를 **전부**(`from('sources').select('id, name')`) 불러와 `SourcePopover` 에 넘김. 그래서 **가트너·KRG 등 파일업로드 카테고리 페이지에서도 뉴스 RSS 출처 ~50개가 전부 노출**됨 — 해당 카테고리와 무관한 출처라 맞지 않음.

소스 타입↔카테고리가 1:1이 아니므로(`report_publisher` 하나가 가트너·KRG·웹인사이트 3개 공유) **타입 기반 필터로는 부정확**. → **"현재 카테고리에 실제 published 콘텐츠가 있는 출처만" 노출**한다.

## 작업 (contents·search 양쪽 동일)

### 1. 카테고리별 출처 ID 집합 조회
- 기존 전체 소스 로드(`from('sources').select('id,name').order('name')`)는 **유지**(전체 목록 보유용).
- `category` 가 있을 때, 해당 카테고리의 출처 ID 집합을 별도 조회:
  ```ts
  // category 변경 시 재실행되는 effect
  if (!category) { setScopedSourceIds(null); return }     // 전체 콘텐츠 = 스코프 없음
  const { data } = await supabase
    .from('contents')
    .select('source_id')
    .eq('status', 'published')
    .eq('category', category)
    .not('source_id', 'is', null)
  setScopedSourceIds(new Set((data ?? []).map((r) => r.source_id)))
  ```
- 상태 `scopedSourceIds: Set<string> | null`(null = 전체).

### 2. SourcePopover 에 넘기는 목록을 스코프
```ts
const visibleSources = scopedSourceIds
  ? sources.filter((s) => scopedSourceIds.has(s.id))
  : sources
```
- `<SourcePopover sources={visibleSources} … />` 로 교체.
- 카테고리에 출처가 0개면 팝오버 버튼 비활성/숨김(취향) — `SourcePopover` 가 이미 `sources.length === 0` 처리하면 그대로.

### 3. (권장) 카테고리 전환 시 범위 밖 출처 선택 정리
- `category` 변경으로 현재 선택된 `srcIds` 중 `scopedSourceIds` 에 없는 값이 생기면 결과가 빈 채로 헷갈릴 수 있음.
- 해당 effect 에서 교집합만 남기도록 URL 정리: `srcIds.filter(id => scopedSourceIds.has(id))` 가 기존과 다르면 `updateParam('src', 교집합.join(','))`. (무한루프 주의 — 값이 실제로 줄 때만 갱신.)
- 과하면 생략 가능(보고에 명시).

## 성능 메모
- `contents.select('source_id').eq('category',…)` 는 단일 컬럼이라 비교적 가벼우나, 대량 시 부하 가능. 느려지면 **추후 RPC/뷰(`sources_in_category`)로 전환**(별도 SQL 핸드오프). 지금은 클라이언트 distinct 로 충분.
