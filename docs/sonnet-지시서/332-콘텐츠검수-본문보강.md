## 1. 현행 진단 (2026-07-13 워킹트리 확인)

### 1.1 ⭐ API는 **이미 있다. 부르는 UI가 0곳이다.**

`src/app/api/admin/body-backfill/by-ids/route.ts`
```
POST /api/admin/body-backfill/by-ids
body:     { ids: string[] }
반환:      { processed, improved, skipped, truncated }   ← EnrichByIdsResult
```

`grep -rn "body-backfill/by-ids" src/` → **route 파일 1곳뿐. 호출하는 컴포넌트 0개.**
지시서 130이 "선택 채우기" UI를 규정했으나 **구현되지 않은 채 남았다.**

> 이게 이 코드베이스의 대표 패턴이다 — 인수인계 §4-2: *"없다고 단정하기 전에 찾아라. 실제 패턴은 '있는데 안 쓰인다'였다."*

### 1.2 행 액션은 5개뿐 (`AdminContentManager.tsx:1466-1514`)
`노출`(→published) · `숨김`(→rejected) · `보기`(상세 링크) · `수정`(편집 모달) · `삭제`
→ **본문 보강·재수집·요약 재생성·라벨 재분류·썸네일 재생성은 행 단위에 전혀 없다.**

### 1.3 벌크 바도 3개뿐 (`:1263-1299`)
`selectedIds: Set<string>`(`:301`) 기반. `노출` · `숨김` · `삭제`.

### 1.4 본문 상태는 **이미 표시되고 있다** (`:1446-1458`)
`getBodyState(content)`(`:116`) → `'full' | 'snippet' | 'none'`
라벨: `none`→**"미시도"** · `snippet`→**"스니펫"** · `full`→**"풀본문"**(`bodyLenAvailable`가 false면 "처리됨")
→ **보강 대상을 판별할 근거가 이미 화면에 있다.** 새 상태를 만들지 말 것.

### 1.5 필터도 이미 있다 (`:1172-1173`)
본문 상태 Select에 `풀본문` / `스니펫` 옵션 존재 (`bodyLenAvailable` false면 disabled).

### 1.6 편집 모달의 유일한 재수집 버튼은 **PDF 표지 전용**(`:948-959`)
`POST /api/admin/contents/{id}/pdf-cover` — **본문이 아니다.** 혼동하지 말 것.

## 3. 구현

### 3-1. 행 액션에 **"본문 보강"** 추가 (`AdminContentManager.tsx:1466`)

- **조건부 노출**: `getBodyState(content) !== 'full'` 일 때만 보인다. 이미 풀본문인 행에 버튼을 띄우지 말 것.
- 클릭 → `POST /api/admin/body-backfill/by-ids` with `{ ids: [content.id] }`
- 진행 중: 해당 행만 스피너(`Loader2`, 이미 import돼 있다). **행 단위 working 상태**를 둘 것(전체 테이블을 잠그지 말 것).
- 완료 후 **그 행의 본문 상태를 갱신**한다:
  - `improved > 0` → 낙관적으로 `'full'` 표시 + **해당 행만 재조회**(권장). 목록 전체 리로드는 하지 말 것.
  - `improved === 0` → **"본문을 가져오지 못했습니다"** 를 행에 표시. **조용히 성공한 척하지 말 것.**

> 🔴 **인수인계 §4-1**: 이 코드베이스의 실패는 *graceful인데 silent*다. `improved === 0`은 **정상 응답**이다(원문에서 본문을 못 뽑은 경우). **반드시 사용자에게 보이게 할 것.**

### 3-2. 벌크 바에 **"본문 보강"** 추가 (`:1263`)

- 선택된 `selectedIds` 중 **`getBodyState !== 'full'` 인 것만** 추린다. 0건이면 버튼 비활성 + 이유 표시.
- **50건 상한**(`MAX_IDS_PER_CALL`)을 UI가 알아야 한다:
  - 50건 초과 선택 시 → **"50건까지만 처리됩니다"** 를 버튼 옆에 미리 표시.
  - 응답의 `truncated === true` 면 → **"N건 중 50건만 처리했습니다. 다시 실행하세요."**
- 결과 요약: **`처리 N · 보강 N · 실패 N`** 을 벌크 바에 남긴다. (`processed` / `improved` / `skipped`)
- 기존 `isBulkWorking` 패턴(`:1268`)을 따를 것.

### 3-3. 응답 해석 규칙 (혼동 방지)

| 필드 | 뜻 |
|---|---|
| `processed` | 시도한 건수 |
| `improved` | **실제로 풀본문이 채워진 건수** ← 성공 |
| `skipped` | 원문 URL 없음 / 추출 실패 / 스니펫이 더 김 → **재시도해도 안 됨** |
| `truncated` | 50건 초과라 잘림 |

**`processed`를 성공으로 표시하지 말 것.** 사용자가 봐야 할 숫자는 **`improved`** 다.

## 4. 회귀 가드

- ⛔ **`nav.ts`를 건드리지 말 것** (330이 단독 소유).
- ⛔ **`/api/admin/body-backfill/by-ids` 라우트를 수정하지 말 것.** 이미 동작한다. **UI만 붙인다.**
- ⛔ **`/api/admin/body-backfill`(일괄, `?limit=&from=&to=`)과 혼동하지 말 것.** 별개 라우트다.
- **기존 행 액션 5개(노출·숨김·보기·수정·삭제)를 건드리지 말 것.**
- **관리 컬럼 폭 `MANAGE_COL_WIDTH = 340`**(`:92`) — 버튼이 하나 늘면 **넘친다.**
  → **아이콘 버튼**으로 넣거나 폭을 조정할 것. **테이블 레이아웃이 깨지면 안 된다.**
  → ⚠️ 관리 컬럼 톤앤매너·2줄형 전환은 **별도 슬라이스**다(David 지시: 어드민 16개 테이블 전수 점검). **이번에 테이블 구조를 갈아엎지 말 것.**
- **`getBodyState`·`BODY_STATE_CLASS`·`bodyLenAvailable`를 그대로 쓸 것.** 본문 상태 판정을 새로 만들지 말 것(§1.4).
- **`bodyLenAvailable === false`**(`body_len` 컬럼 미적용) 상황에서도 **안 깨질 것.** 이때 상태는 "처리됨"으로 뭉뚱그려진다 — 버튼 노출 조건이 오작동하지 않는지 확인.
- 선택 상태(`selectedIds`)는 보강 후에도 **유지**한다(사용자가 다시 누를 수 있어야 한다).

## 5. 검증

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build` **통과 (반드시 네가 돌릴 것 — 플래너는 못 돌린다)**

- 보강 중에도 **다른 행의 노출/숨김이 동작하는지** (전체 잠금 금지)
- 관리 컬럼이 **넘치거나 줄바꿈되지 않는지** (340px)
