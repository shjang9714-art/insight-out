## 2. 구현

### 2.1 (#1) "이번 달 기준" 표기 — 표시만
- `admin/page.tsx`: `getKstPeriod()` 값을 `period` prop 으로 `AdminOpsSignals` 에 전달(이미 lib 에 있음, import).
- `AdminOpsSignals.tsx`: 패널 헤더(또는 "사용량 / 한도" 줄 옆)에 **`{period} 기준 · 매월 1일 자동 초기화`** 캡션(작게, `text-xs text-muted-foreground`).
- ⚠️ **데이터·집계·리셋 로직 무변경.** 이미 월 관리라 문구만. 번역·TTS 수치도 같은 달 기준이므로 캡션이 패널 전체를 커버.

### 2.2 (#2) 한도 = 키 개수 × 키당 한도 — 표시 + 강제
**핵심: 표시(page.tsx)와 강제(lib/llm/index.ts)가 같은 keyCount 로직을 공유해야 한다.** 어긋나면 "보이는 한도"와 "실제 막히는 지점"이 달라진다.

**2.2.1 공용 헬퍼 신규** — `src/lib/llm/` 에 `getProviderKeyCount(provider): number`.
- provider→env 매핑은 **기존 `providers/*.ts` 의 `keysEnv` 정의를 재사용**한다(하드코딩 새 맵 만들지 말 것 — 이미 각 provider 가 자기 env 를 안다). providers 레지스트리에서 keysEnv 를 끌어와 `process.env[keysEnv]?.split(',').map(t=>t.trim()).filter(Boolean).length ?? 0`.
- 착수 시 providers 레지스트리 구조를 확인해, keysEnv 를 한 곳에서 순회할 수 있는지 파악(안 되면 최소한의 provider→keysEnv 맵을 `providers/` 근처에 두고 gemini 포함 6종 공용).

**2.2.2 표시(page.tsx)**: 각 provider 의 `limit` 을 **`monthly_token_limit(=키당 한도) × getProviderKeyCount(provider)`** 로 계산해 전달. 추가로 `keyCount` 도 prop 으로 넘겨 배지 표시.
- ⚠️ **의미 재정의**: 이제 `monthly_token_limit` 을 **"키당 월 한도"**로 해석한다. 기본 1,000,000 = 키 1개당 100만.

**2.2.3 강제(lib/llm/index.ts L178·L201)**: 스킵 판정을 **`>= (s?.limit ?? 1_000_000) × getProviderKeyCount(provider)`** 로 바꾼다. 표시와 동일 공식.
- 🔴 **이게 이 슬라이스의 유일한 런타임 hot-path 변경.** keyCount 가 `NaN`/`undefined` 로 새지 않게 헬퍼가 항상 정수 반환. keyCount 0(키 미등록)이면 cap 0 → 항상 스킵(키 없으면 어차피 호출 불가라 정합). 단 **`llm_settings.enabled=true` 인데 keyCount=0** 이면 설정 오류이므로 패널에 경고 배지(§2.2.4).

**2.2.4 배지**: `AdminOpsSignals` 각 provider 줄에 **"키 N개"** 배지. `N=0` 이면 경고 톤(예: `text-amber-500` "키 미등록").

### 2.3 (#3) provider별 활용처 정보 아이콘
**2.3.1 조회(page.tsx)**: `llm_task_routing` 에서 `is_active=true` 행을 읽어 **provider→task_type[] 역매핑**(Map). `AdminOpsSignals` 에 `providerTasks` prop 으로 전달.

**2.3.2 task→활용처 라벨(정적 맵)** — `AdminOpsSignals`(또는 근처 상수)에 한국어 라벨. 조사 근거 그대로:
```
classify:      '분류·감성·시그널·LGU임팩트·이슈매칭'
summarize:     '요약·경쟁사주간·기업인사이트·브리핑하이라이트'
report:        '전략보고서·이슈브리프·이슈후보·엔티티이벤트·엔티티정규화'
briefing:      '모닝브리핑 스크립트'
key_insight:   '키워드 인사이트'
daily_insight: '데일리 인사이트'
```

**2.3.3 UI**: 각 provider 이름 옆 **정보 아이콘**(lucide `Info`). hover/click 툴팁에 그 provider 가 라우팅된 task 들의 활용처 라벨 나열.
- 라우팅된 task 가 없으면 **"폴백 대기"**(명시 할당 없이 폴백 풀로만 쓰임 — `lib/llm/index.ts` 폴백 순서 gemini→…→openrouter).
- 툴팁은 기존 UI 라이브러리 재사용(있으면). 없으면 `title` 속성 + 작은 팝오버 최소 구현. **접근성**: 아이콘에 `aria-label`.

## 3. 하지 말 것
- **스키마·집계·리셋 로직 변경 금지**(#1 은 표기만). `llm_usage`·`increment_*` RPC 무수정.
- keyCount 표시(page.tsx)와 강제(lib/llm)가 **다른 로직 쓰지 않기** — 반드시 `getProviderKeyCount` 하나 공유.
- `llm_task_routing` **쓰기 금지**(읽기만).
- 폴백 순서·라우팅 알고리즘(`lib/llm/index.ts` L141–214) **로직 무변경** — 한도 비교식의 `limit` 만 keyCount 배수로.
- env 키 값 자체를 화면·로그에 **노출 금지**(개수만).
- 번역·TTS 강제/집계 무변경(#2 는 LLM provider 한도만).

## 4. 회귀 가드
1. 패널에 **"2026-07 기준 · 매월 1일 자동 초기화"** 캡션.
2. 각 provider 한도가 **키당 한도 × 키 개수**로 표시(예: 키 2개면 2,000,000). "키 N개" 배지.
3. 키 미등록(N=0) provider 는 cap 0 + 경고 배지, 실제 호출도 스킵.
4. **강제 로직이 표시와 일치** — 키 추가 시 한도·실제 막히는 지점이 함께 커진다.
5. provider 이름 옆 **정보 아이콘** → 그 provider 활용처(라우팅 task 라벨) 표시. 라우팅 없으면 "폴백 대기".
6. 기존 사용량 수치·번역·TTS 표시 그대로.
7. LLM 라우팅·폴백 동작 회귀 없음(한도식만 변경).
8. env 키 값 비노출(개수만).
