## 0. 한 줄

최근 N일 **검토대기·반려가 반복된 도메인**을 집계(RPC)해 어드민 제외 규칙 화면 상단에 **"제외 후보(자동 제안)"** 패널로 띄운다. 각 후보는 **[제외 규칙 추가](원클릭)** 또는 **[무시](학습)**. 이미 활성 도메인 규칙이 있거나 무시한 도메인은 다시 제안하지 않는다.

## 1. 현행 진단 (검증된 코드 사실)

- 크롤 단계 즉시 reject(광고·짧은 글·`exclusion reject`)는 `counts.rejected++; return {}` → **contents 미저장**(orchestrator 327). 따라서 DB에 남는 저품질 신호 = **status='pending'(게이트/hold 보류)·status='rejected'(관리자 반려)·저품질 본문**. → 최악(이미 자동 차단)은 집계 대상 아님(무방), 학습 목표 = **"들어온 뒤 걸러진 반복 junk"**.
- `contents.original_url`(호스트 추출 가능)·`status`·`collected_at`·`review_reason` 존재. 소스 수십 × 콘텐츠 수천 → **DB RPC로 GROUP BY**(186 패턴).
- 190 제외 규칙 = 도메인/URL/제목 부분일치, `matchExclusion`→`ruleHit` 도메인은 `host === value || host.endsWith('.'+value)`. 후보 값은 `www.` 제거한 호스트로 제안(www/bare 병합 커버리지↑).
- 190 POST `/api/admin/exclusion-rules` = `{ rule_type, value, action?, note?, created_by? }`(기본 action 'reject') — **원클릭 규칙 생성에 재사용**.

## 2. DB / SQL (수희 핸드오프)

`docs/sql-handoff/195-exclusion-candidates.sql` — 이미 작성·**먼저 커밋·푸시**.
- `exclusion_candidate_ignores(domain pk, created_by, created_at)` — 무시(학습) 목록.
- `exclusion_candidates(p_days int=30, p_min_count int=3)` RPC → 도메인별 total·junk_count·pending·rejected·junk_ratio·last_collected·sample_title. junk=status in ('pending','rejected'). **제외**: 빈 host·`news.google.com`·이미 활성 도메인 규칙 있음·무시 목록. junk_count 내림차순(limit 100).
- 미적용(RPC 42883·테이블 42P01) → 195 코드 graceful(후보 [] → 패널 "집계 준비 전").

## 3. 구현 (크롤러 무변경 — API + 어드민 UI만)

### 3-1. API — `/api/admin/exclusion-candidates`(신규, service_role)
- **GET** `?days=30&min=3` → `supabase.rpc('exclusion_candidates', { p_days, p_min_count })`.
  - RPC 미존재/오류(42883·42P01 등) → `{ candidates: [] }` graceful(에러 아님, 콘솔 warn).
  - days 기본 30(7/14/30 허용), min 기본 3(clamp 1~50).
- **POST** `{ domain }` = **무시 등록** → `exclusion_candidate_ignores` upsert(`onConflict: domain`), created_by=현재 관리자 식별(가능하면). 테이블 미존재 graceful(200 + noop 또는 503 안내 — graceful 우선).
- 규칙 추가는 **기존 POST `/api/admin/exclusion-rules` 재사용**(신규 아님).

### 3-2. 타입 (`src/lib/admin/exclusion-rules.ts` 또는 신규 파일)
```ts
export interface ExclusionCandidate {
  domain: string
  total: number
  junk_count: number
  pending: number
  rejected: number
  junk_ratio: number      // 0~1
  last_collected: string | null
  sample_title: string | null
}
```

### 3-3. UI — `ExclusionRulesManager.tsx` 상단에 "제외 후보(자동 제안)" 패널
> 규칙 테이블과 **같은 컴포넌트에 포함**해 규칙 추가 시 `load()`(규칙)와 `loadCandidates()`를 함께 갱신(후보→규칙 즉시 반영).

- 마운트 시 `loadCandidates()`(GET). 로딩/빈/에러 상태.
- **패널 헤더**: "제외 후보 (자동 제안)" + 설명 1줄 "최근 30일 검토대기·반려가 반복된 도메인입니다. 규칙으로 추가하면 다음 수집부터 자동 처리됩니다." (기간 셀렉트 7/14/30 — 선택, 기본 30).
- **후보 행**(카드/행):
  - `domain` (font-medium) · **불량 배지**: `junk_count건 / 전체 total` + `junk_ratio` (≥0.5 risk 톤, 그 외 중립 — 175/180 토큰, 그린 없음).
  - 최근 사례 `sample_title`(truncate, title 툴팁) · `last_collected` 상대표기(194 `formatRelativeHit` 재사용 가능).
  - **[제외 규칙 추가]**: 확인 후 POST `/api/admin/exclusion-rules` `{ rule_type:'domain', value:domain, action:'hold', note:'자동 후보(불량 N건)', created_by }` → 성공 시 후보에서 제거 + 규칙 목록 `load()` 갱신. (기본 **hold**=검토 대기, 안전·되돌리기 쉬움. reject 로 강화는 규칙 표에서.)
  - **[무시]**: POST `/api/admin/exclusion-candidates` `{ domain }` → 후보에서 제거(다시 제안 안 함).
- **빈 상태**: 후보 0 → "제외할 만한 반복 도메인이 없습니다". RPC 미적용/집계 전 → "집계 준비 전(195 SQL 적용·수집 후 반영)".
- `.admin-scope` v2 타이포·StatusBadge 톤 재사용. 신규 hex 0.

## 4. 회귀 가드 / 비기능 요건

- **크롤러 완전 무변경**(집계는 사후 읽기). 수집 파이프라인 회귀 0.
- RPC/테이블 미적용 → 후보 [] · 패널 "집계 준비 전" · 규칙 관리 정상(graceful).
- 후보 집계 RPC 1콜(도메인 전체 GROUP BY) — N+1 금지.
- 이미 활성 도메인 규칙·무시 도메인은 SQL 단계에서 anti-join(중복 제안 없음).
- 원클릭 규칙 생성은 기존 POST 재사용(신규 write 경로 없음). 어드민 한정·service_role.
- 상태색 175/180 토큰(그린 없음). 신규 hex 0. LLM·신규 npm 의존 0.
