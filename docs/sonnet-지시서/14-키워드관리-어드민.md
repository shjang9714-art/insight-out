## 0. 목표 (한 줄)
`/admin/keywords` 에서 `keywords` 테이블을 CRUD — 서비스별 키워드 추가/수정/삭제. (크롤러가 이 키워드로 콘텐츠↔서비스 태깅)

## 1. 데이터 (이미 존재)
- `keywords` 컬럼: `id, name, service_id(→services, nullable), is_competitor(default false), created_at`. **`lower(name)` 유니크** → 키워드명 전역 고유(중복 시 23505).
- RLS: `keywords: admin 관리`(is_admin) → 로그인 admin 브라우저 client(`createClient()`) CRUD 통과(service_role 불필요). `/admin/*` 는 proxy.ts 가드.
- 서비스 목록은 `services`(7개) 에서 조회해 select 에 사용.

## 2. 할 일 (소스 관리 패턴 그대로)

### 2.1 `src/app/admin/keywords/page.tsx` (신규, 서버 컴포넌트)
- `metadata`("키워드 관리 | 어드민 | Insight Out") + 헤더(h1 "키워드 관리" + 설명: "크롤러가 이 키워드로 콘텐츠를 서비스에 자동 태깅합니다.") + `<KeywordManager />`.

### 2.2 `src/components/admin/KeywordManager.tsx` (신규, `'use client'`)
- `createClient()`로:
  - **서비스 로드**: `services` `order`·`name` 정렬 → select 옵션.
  - **키워드 로드**: `keywords` + `services(name)` 조인, 서비스별 정렬. 표/그룹: 키워드명·서비스(라벨, 미지정 "—")·경쟁사 여부·작업(수정/삭제).
  - **서비스별 개수 요약**(선택, 권장): 서비스별 키워드 수를 작게 표시 → David 가 **빈 서비스(0개)** 를 바로 알아봄.
  - **추가**: 폼(키워드명*·서비스 select(미지정 허용)·경쟁사 토글) → `insert`. **중복(23505) 시 "이미 등록된 키워드입니다." 안내.**
  - **수정**: 인라인/모달(서비스·경쟁사 변경) → `update eq('id')`.
  - **삭제**: 확인 후 `delete eq('id')`. (키워드 삭제는 기존 `content_keywords` 매핑도 정리됨 — FK cascade. 안내 문구.)
- 한국어 에러/로딩, shadcn/ui(Button/Input/Select/Label). mutation 후 목록 갱신.

### 2.3 어드민 내비
