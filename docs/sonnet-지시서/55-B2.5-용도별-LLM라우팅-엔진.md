## 배경 / 목표
지시서 54 의 키 풀(고정 순서 폴백)을 **용도(task)별 모델 라우팅**으로 확장. 작업 가치에 맞춰 모델 배정 + 한도 소진/장애 시 폴백. 라우팅·모델 카탈로그는 **DB 기반**(어드민 편집 대비, UI 는 56). 키는 계속 **Vercel env** 전용.

## A절. SQL 핸드오프 (`docs/sql-handoff/55-llm-routing.sql`) — 먼저 커밋·푸시

```sql
-- 모델 카탈로그: 발급처별 제공 모델
create table public.llm_models (
  id             uuid primary key default gen_random_uuid(),
  provider       text not null,
  model_id       text not null,                 -- API 모델 식별자
  label          text,
  strengths      text[] not null default '{}',  -- ['speed','korean','reasoning','volume','fallback']
  context_tokens integer,
  is_active      boolean not null default true,
  created_at     timestamptz not null default now(),
  unique (provider, model_id)
);

-- 용도별 라우팅: task → 우선순위별 provider/model
create table public.llm_task_routing (
  id         uuid primary key default gen_random_uuid(),
  task_type  text not null,        -- 'classify' | 'summarize' | 'report'
  priority   integer not null,     -- 낮을수록 먼저
  provider   text not null,
  model_id   text not null,
  is_active  boolean not null default true,
  unique (task_type, priority)
);

alter table public.llm_models       enable row level security;
alter table public.llm_task_routing enable row level security;
create policy "llm_models admin"   on public.llm_models       for all using (public.is_admin()) with check (public.is_admin());
create policy "llm_routing admin"  on public.llm_task_routing for all using (public.is_admin()) with check (public.is_admin());

-- ── 시드 (2026-06 기준 무료 모델. ⚠️ 정확한 model_id 는 각 provider 문서로 확인 후 조정) ──
insert into public.llm_models (provider, model_id, label, strengths) values
 ('gemini','gemini-2.5-flash','Gemini 2.5 Flash', array['korean','balanced']),
 ('groq','llama-4-scout-17b-16e-instruct','Llama 4 Scout (Groq)', array['speed']),
 ('groq','qwen-3-32b','Qwen3 32B (Groq)', array['speed','korean']),
 ('cerebras','llama-4-scout','Llama 4 Scout (Cerebras)', array['speed','volume']),
 ('cerebras','qwen-3-235b','Qwen3 235B (Cerebras)', array['reasoning']),
 ('openrouter','meta-llama/llama-3.3-70b-instruct:free','Llama 3.3 70B (OpenRouter)', array['fallback'])
on conflict do nothing;

insert into public.llm_task_routing (task_type, priority, provider, model_id) values
 ('classify', 1, 'cerebras', 'llama-4-scout'),
 ('classify', 2, 'groq', 'llama-4-scout-17b-16e-instruct'),
 ('classify', 3, 'gemini', 'gemini-2.5-flash'),
 ('classify', 4, 'openrouter', 'meta-llama/llama-3.3-70b-instruct:free'),
 ('summarize',1, 'gemini', 'gemini-2.5-flash'),
 ('summarize',2, 'cerebras', 'qwen-3-235b'),
 ('report',   1, 'cerebras', 'qwen-3-235b'),
 ('report',   2, 'gemini', 'gemini-2.5-flash')
on conflict do nothing;
```
> ⚠️ 구현 시 각 provider 문서에서 **현재 유효한 model_id** 확인 후 시드/기본값 보정(특히 Groq/Cerebras 의 Llama4/Qwen3 정확 ID). 변동돼도 추후 어드민(56)·`*_MODEL` env 로 교체 가능.

## B절. 코드 (검증 통과 후 커밋)

### 1. 모델 ID 현행화 (즉효)
- `src/lib/llm/providers/gemini.ts` 기본값 `gemini-2.0-flash` → **`gemini-2.5-flash`**.
- groq/cerebras provider 기본 모델도 현행 무료 ID 로(위 시드와 일치). 모두 `*_MODEL` env override 유지.

### 2. provider 시그니처에 model 주입
- `LlmProvider.complete(system, user, model?)` 로 확장(model 미지정 시 기존 기본값).
- `openai-compat.ts` `complete(system,user,model)` → 전달 model 우선, 없으면 config.defaultModel.
- `gemini.ts` 동일.

### 3. `src/lib/llm/index.ts` — 용도별 라우팅
- `llmComplete(task: LlmTask, system: string, user: string): Promise<string|null>` 로 변경. `LlmTask = 'classify'|'summarize'|'report'`.
- 동작:
  1. `llm_task_routing`(task_type=task, is_active, **priority asc**) + `llm_settings` + `llm_usage`(period) 로드.
  2. 라우팅 행 순회: 해당 `provider` 모듈 찾기(이름 매핑 맵) → `isConfigured()` && enabled(기본 true) && `used < limit` 이면 `provider.complete(system, user, model_id)` 호출.
  3. 성공 → `increment_llm_usage(provider, period, tokens, 1)` → text 반환. 실패/skip → 다음 행.
  4. 라우팅 비어있거나 전부 실패 → **기존 고정 폴백 풀**(54)로 한 번 더 시도(안전망) 후 null.
- provider 이름→모듈 맵: `{ gemini, groq, cerebras, openrouter }`(추가 provider 는 키 확보 후 별도). `'server-only'` 유지.

### 4. `src/app/api/admin/llm-test/route.ts` 갱신
- `llmComplete` 시그니처 변경 반영 → `llmComplete('classify', 'You reply with JSON only.', 'Return {"ok":true}.')`.
- 응답에 어떤 task·provider·model 이 응답했는지 포함(디버깅용).

### 5. `supabase/schema.sql`
- `llm_models`, `llm_task_routing` + RLS 반영.

### (이번 범위 아님)
- `/admin/llm` 관리 UI = **지시서 56**.
- Mistral·GitHub Models·Cloudflare provider 추가 = 키 확보 후(코드 only, 팩토리 baseURL). 56 또는 별도.
- 실제 분류/요약 호출부(태깅·시그널) = **B3**.

## 회귀 / 주의
- 키 미설정/라우팅 미적용이어도 빌드·기존 기능 정상(llmComplete=null, 호출부 없음). 프로덕션 동작 영향 없음(테스트 라우트 제외).
- **키 값은 DB 에 절대 저장하지 않음** — env 전용. 어드민(56)은 isConfigured()/usage 만 노출.
- 모델 ID 가 provider 에서 유효하지 않으면 그 row 실패 → 다음 폴백. (그래도 최소 1개는 유효하도록 시드 확인.)
- 번역 시스템·크롤러·게이트 무변경.
