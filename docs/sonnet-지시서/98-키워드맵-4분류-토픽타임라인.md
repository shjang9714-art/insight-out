## 배경 (David)

AI 분석 키워드 맵(94)·뜨는토픽(91)의 후속 보강:
- **4분류 완성**: 키워드를 카테고리(기술/시장·정책/업체/일반)로 분류해 필터. (94 메모: 기술=`keyword_groups.tag_type`, 인물=엔티티 추출 필요.)
- **클릭 → 토픽 타임라인**: 토픽/키워드 클릭 시 검색(`?q=`)이 아니라 그 토픽의 **시간순 기사 타임라인**.

## 설계 결정 (Opus, 확정 — 임의 변경 금지)

1. **4분류 = `keyword_groups.tag_type` 기반 4버킷**: **기술**(tech) / **시장·정책**(market+policy) / **업체**(company, 기존 경쟁사·관심업체 강조 유지) / **일반**(industry·content_type·미매핑). `matched_keywords`(패턴)는 keyword_groups.include_patterns→tag_type 로 역매핑.
2. **인물(person)은 이번 범위 제외.** 데이터에 엔티티(인물) 없음 → NER/LLM 추출 인프라 필요(별도 SQL·크롤 변경). **후속 슬라이스**로 분리(미해결 명시). 이번 v1 = 기술/시장·정책/업체/일반 4버킷.
3. **타임라인 = 신규 서버 페이지** `/dashboard/topics/[topic]`. 검색 페이지 재사용 X(검색은 텍스트 매칭, 타임라인은 `matched_groups`/`matched_keywords` 배열 contains·시간순). matched_groups/keywords 둘 다 매칭(2쿼리 머지 — `.or` 따옴표 이슈 회피).
4. **신규 SQL 없음.** 키워드 맵 필터는 클라이언트 leaf 컴포넌트로 분리(현 페이지는 서버 유지).

## 작업

### 1. tag_type → 4버킷 헬퍼 — `src/lib/categories.ts`(기존 파일에 추가) 또는 신규 `src/lib/tag-buckets.ts`
```ts
export type TagBucket = '기술' | '시장·정책' | '업체' | '일반'
export function tagTypeToBucket(t: string | null | undefined): TagBucket {
  if (t === 'tech') return '기술'
  if (t === 'market' || t === 'policy') return '시장·정책'
  if (t === 'company') return '업체'
  return '일반' // industry, content_type, null, 미매핑
}
export const TAG_BUCKETS: TagBucket[] = ['기술', '시장·정책', '업체', '일반']
```

### 2. 키워드 분류(서버) — `src/app/dashboard/ai-analysis/page.tsx`
- 기존 병렬 페치에 **keyword_groups 조회 추가**: `keyword_groups` `is_active=true` select `name, tag_type, include_patterns`.
- **패턴→tag_type 맵** 구성: 각 그룹의 `include_patterns` 각 패턴(lower) → 그룹 `tag_type`. 충돌 시 비-`industry` 우선(더 구체적). 그룹명(lower)도 같은 맵에 추가(토픽=그룹명 대비).
- 기존 `topKeywords` 각 항목에 **bucket** 부여: `tagTypeToBucket(map.get(lower(name)))`. (watched/competitor 는 기존대로 별도 강조 플래그로 유지 — bucket 은 '업체'로 강제하지 말고 색 강조는 그대로.)
- 분류 결과 배열(`{ name, count, bucket, watched, isCompetitor }`)을 **클라이언트 컴포넌트로 전달**.

### 3. 키워드 맵 클라이언트 컴포넌트 — `src/components/dashboard/KeywordMap.tsx`(신규, `'use client'`)
- props: 분류된 키워드 배열 + (필요 시) 폰트 크기 계산용 min/max 또는 미리 계산된 size.
- **카테고리 필터 칩**: `전체` + `TAG_BUCKETS`(기술/시장·정책/업체/일반). `useState` 로 선택 버킷, 클릭 시 클라우드 필터. 각 칩에 해당 버킷 개수 뱃지(0이면 칩 비활성/흐림).
- 클라우드: 기존 94 스타일(폰트=빈도, 색=관심업체 brand / 경쟁사 red / 일반 muted) 유지. 각 키워드 `Link href={/dashboard/topics/${encodeURIComponent(name)}}`(검색 아님 — 작업 4).
- 범례(관심업체/경쟁사/일반) 기존 유지. 서버 페이지에서 이 컴포넌트를 키워드 맵 섹션 자리에 렌더.

### 4. 토픽 타임라인 페이지 — `src/app/dashboard/topics/[topic]/page.tsx`(신규, 서버)
- `params: Promise<{ topic: string }>` → `const { topic } = await params; const decoded = decodeURIComponent(topic)`. ([id] 페이지 패턴 미러.)
- metadata: `${decoded} 타임라인 | Insight Out`.
- 조회(서버 supabase, published): **2쿼리 머지**(`.or` 따옴표 회피)
  - A: `contents` `.contains('matched_groups', [decoded])`
  - B: `contents` `.contains('matched_keywords', [decoded])`
  - 각 select `id,title,summary_ko,category,published_at,collected_at,sentiment,sources(name)`, `order collected_at desc`, `limit 60`. id 기준 dedup 머지 후 정렬(published_at desc nulls last → collected_at desc).
- 렌더: 상단 헤더(토픽명 + 총 N건). **KST 일자별 그룹 헤더** + 그 아래 기사 리스트(제목 Link `/dashboard/contents/{id}`, 출처·날짜, summary 1~2줄 발췌, 논조 배지(96, 있으면)). 경량 인라인 리스트 또는 ContentRow/ContentListCard 재사용(props 맞으면). 0건이면 빈 상태("이 토픽의 최근 기사가 없습니다").
- 뒤로/상단에 "AI 분석으로" 링크(선택).

### 5. 뜨는토픽 → 타임라인 링크 — `src/app/dashboard/ai-analysis/page.tsx`
- 뜨는토픽 위젯 각 항목(현 `t.group` span)을 `Link href={/dashboard/topics/${encodeURIComponent(t.group)}}` 로. (그룹명=토픽=타임라인 매칭 정확.)

## 회귀 / 주의
- **신규 SQL 없음.** `matched_groups`/`matched_keywords` GIN(393·394)로 `.contains` 효율적.
- **기술 버킷은 `keyword_groups.tag_type='tech'` 등록분에 의존**(어드민 키워드그룹 관리 63). 미등록이면 기술 칩 0(흐림, graceful) — 운영상 tag_type 지정이 채움 조건.
- 패턴→tag_type 역매핑은 근사(한 패턴이 여러 그룹에 있으면 비-industry 우선). 완벽 분류 아님 — v1 허용.
- 타임라인 2쿼리 머지: 같은 기사 양쪽 매칭 시 dedup 필수(id Set). 토픽 문자열은 `decodeURIComponent` 후 그대로 배열 매칭(따옴표/콤마 escape 불필요 — `.contains([value])` 가 안전 처리).
- 키워드 맵을 client 컴포넌트로 분리하되 **AI 분석 페이지 본체는 서버 유지**(다른 섹션 서버 렌더 보존). 필터는 client leaf 안에서만.
- UI 한국어(#1)·색 토큰(#9)·lucide·`cn()`·`@/` alias·`any` 금지.
- 인물 분류 제외(NER 후속) — 칩에 '인물' 넣지 말 것(빈 칩 혼란 방지).
