## 0. 한 줄

AI 인사이트 상단에 **범위 필터 `[전체][내 업무][내 관심사]`** 를 추가하고, 이게 기존 렌즈 상태(`useActiveLens`: all/mine/watch)를 구동한다. **2차 탭은 `[브리핑][이슈]` 로 축소**하고 **"내 관점" 탭은 제거**(그 기능 = 범위 필터로 흡수). 산재한 렌즈 스위처는 상단 필터로 통일하고, 렌즈 라벨을 사용자 친화 명칭으로 바꾼다.

## 1. 현행 진단 (검증된 코드 사실)

- 렌즈 상태: `src/lib/lens.ts` — `LensKey='mine'|'watch'|'all'`, `LENS_PRESETS`(라벨: mine='내 담당', watch='관심 기업', all='전체'), `useActiveLens()`(localStorage `io:lens` + 이벤트 브로드캐스트, 전 소비자 동기화).
- 2차 탭(160): `AiInsightTabs` = [브리핑][이슈][내 관점], `issues/page.tsx` `VALID_VIEWS=['briefing','issues','mine']`.
- "내 관점" 탭(`AiInsightsView` `view==='mine'`): 내 업무 시사점(`brief.myImplication`) + **`<LensSwitcher/>` 임베드** + 내 관심사 키워드 동향(`watchedKwStrip`) + 내 관심사 매칭 인사이트(`mineInsightGroups`) + 미설정 빈상태.
- 렌즈 소비자: `InsightCardsSectionClient`(브리핑 카드 — activeLens로 필터/정렬·매칭 배지) · `IssueBoardClient`(이슈 탭 — `showLensSwitcher={false}`로 이미 자체 스위처 숨김, activeLens 읽음) · `LensSwitcher`(컴포넌트) · `EntitiesPageClient`·`KnowledgeGraph`(기업동향 — **본 지시서 범위 밖**).
- 즉 브리핑·이슈는 이미 `activeLens` 를 읽으므로, **상단 필터가 `setActiveLens` 만 호출하면 즉시 반영**된다.

## 3. 구현

### 3-1. 렌즈 라벨 재명명 (`lib/lens.ts`)
`LENS_PRESETS` 라벨을 설계안 §9 명칭으로:
- mine: '내 담당' → **'내 업무'**
- watch: '관심 기업' → **'내 관심사'**
- all: '전체'(유지)
- desc도 자연스럽게 보정(예: mine='담당 서비스 관련만', watch='관심 기업·토픽만'). **"렌즈" 단어는 사용자 노출 문구에 쓰지 않음**(메모리: 일반 사용자 우선).
- `LensKey` 식별자(mine/watch/all)는 그대로(코드 영향 최소).

### 3-2. 상단 범위 필터 — `ScopeFilter.tsx` (신규, 클라)
`[전체][내 업무][내 관심사]` pill 바. `useActiveLens()` 의 `[active, setActive]` 사용. `AiInsightTabs`(2차 탭)와 시각적으로 구분되는 1차 필터 톤(선택=brand, 비선택=muted). 순서: 전체 → 내 업무 → 내 관심사.
```tsx
'use client'
import { useActiveLens } from '@/lib/lens'
import { cn } from '@/lib/utils'
const OPTS: { key: 'all'|'mine'|'watch'; label: string }[] = [
  { key: 'all', label: '전체' }, { key: 'mine', label: '내 업무' }, { key: 'watch', label: '내 관심사' },
]
export default function ScopeFilter() {
  const [active, setActive] = useActiveLens()
  return (
    <div className="inline-flex items-center gap-0.5 rounded-lg border border-border p-0.5">
      {OPTS.map(o => (
        <button key={o.key} type="button" onClick={() => setActive(o.key)}
          className={cn('rounded-md px-3 py-1 text-[13px] font-medium transition-colors',
            active === o.key ? 'bg-brand-600/10 text-brand-600' : 'text-muted-foreground hover:text-foreground')}>
          {o.label}
        </button>
      ))}
    </div>
  )
}
```

### 3-3. 페이지 배선 (`issues/page.tsx`)
- `VALID_VIEWS = ['briefing', 'issues']` (mine 제거, 잘못된 값→briefing).
- 헤더 아래 레이아웃: **상단 `<ScopeFilter />`(범위) + 그 아래 `<AiInsightTabs />`(브리핑/이슈)**. 둘의 위계가 보이게(필터가 위, 탭이 아래 또는 한 줄에 좌우 분리). 설계안 §10 순서 = 필터 → 탭.

### 3-4. 2차 탭 축소 (`AiInsightTabs.tsx`)
`TABS = [{briefing,'브리핑'},{issues,'이슈'}]`. 'mine' 제거.

### 3-5. "내 관점" 탭 제거 + 콘텐츠 흡수 (`AiInsightsView.tsx`)
- `view` 타입에서 'mine' 제거, `view==='mine'` 블록 삭제.
- 흡수: **범위 필터로 자연 반영** — 브리핑의 `InsightCardsSectionClient` 는 activeLens=mine/watch 일 때 이미 매칭 카드로 필터/정렬(=옛 "매칭 인사이트"). 이슈의 `IssueBoardClient` 도 activeLens 반영. 업무 시사점은 `InsightBriefCard`(162)에 이미 `myImplication` 포함 → 브리핑에서 노출.
- 정리: mine 전용 계산(`watchedKwStrip`, `mineInsightGroups`, mine 분기에서만 쓰던 변수) 제거(미사용 0). 단 `risingKws`/`kwStrip`(브리핑 ④)·`brief`(InsightBriefCard용)는 유지.
- (선택) 브리핑 ④ 키워드 동향을 activeLens=watch 일 때 관심 키워드 우선 정렬 — 과설계 말고 여력 시만.
- AI 인사이트 내 잔여 `<LensSwitcher/>` 임베드 제거(상단 필터로 대체). `LensSwitcher` 컴포넌트 자체는 기업동향에서 아직 쓰므로 삭제하지 않음.

### 3-6. 범위 밖 (건드리지 않음)
- 기업동향(`EntitiesPageClient`·`KnowledgeGraph`)의 렌즈 사용 — 라벨 재명명(3-1)만 자동 반영, 상단 필터는 추가 안 함(후속).

## 4. 회귀 가드 / 비기능 요건

- 범위 필터 선택이 브리핑·이슈 양쪽에 즉시 반영(localStorage 이벤트 — 새로고침·탭이동에도 유지).
- 미설정 사용자가 '내 업무'/'내 관심사' 선택 시: 빈 결과가 아니라 **설정 유도 안내**(기존 `InsightCardsSectionClient` 빈상태 카피 재사용 — "마이페이지에서 설정" ).
- "내 관점" 탭 URL(`?view=mine`) 진입 → briefing 폴백(깨짐 없음).
- 기업동향 렌즈 동작 회귀 0(라벨만 변경).
- 하드코딩 hex 0. SQL/LLM 0. 미사용 코드 0.
