## 1. 착수 전 확인 결과 (현황대조 §5 규율)

**두 화면을 직접 열어 렌더 구조를 확인했다.**

| 화면 | 컴포넌트 | 실제 렌더 구획 |
|---|---|---|
| 뉴스레터 | `NewsletterManager` 360줄 | `발송 설정`(152행~) · `미리보기 / 수동 발송`(256행~) · `발송 이력`(302행~) — **`<section>` 3개** |
| 모닝브리핑 | `BriefingManager` 434줄 | **TTS 사용량 카드**(217행~) + **브리핑 목록**(245행~) — 그게 전부 |

### 1.1 ⚠️ 모닝브리핑은 탭화 대상이 아니다 — 확인으로 판단이 바뀜

현황대조는 `BriefingManager` 를 **434줄**이라는 크기만 보고 탭화 대기열에 넣었다. **열어보니 구획이 둘인데, 그중 하나(TTS 사용량)는 탭이 아니라 컨텍스트 지표다.**

TTS 사용량을 탭으로 만들면 안 되는 이유: **목록 작업 중에 항상 보여야 하는 값**이다. 오디오 생성 버튼을 누르기 전에 잔여량을 보는 것이 이 화면의 동선인데, 탭으로 감추면 그 동선이 끊긴다.

→ **탭 없이 `AdminTabShell` 의 `contextBar` 로 올린다.** `AdminTabShell` 은 `{tabs.length > 0 && ...}` 가드가 있어 **`tabs={[]}` 이면 탭 바를 렌더하지 않는다**(코드 확인함, 45행). 브레드크럼·헤더·컨텍스트바 표준만 취한다.

> 399 §1.1 에 이어 **두 번째로 실물 확인이 계획을 바꿨다.** 줄 수는 탭 개수를 예측하지 못한다.

### 1.2 ⚠️ 뉴스레터 — 지금도 발송 후 이력이 갱신되지 않는다 (기존 결함)

```ts
const [issues] = useState<Issue[]>(initialIssues)   // 62행 — setter 가 없다
```
**수동 발송에 성공해도 `발송 이력` 이 그대로다.** 새로고침해야 보인다. 탭이 아니라 지금도 그렇다.

→ **이번에 고치지 않는다.** 탭화와 무관한 기존 동작이고, 함께 고치면 회귀 원인이 탭화인지 이 변경인지 가려낼 수 없다. **§7 에 기록만 한다.**
→ 다만 탭으로 나누면 **"발송했는데 이력 탭에 없다"가 훨씬 눈에 띈다.** 후속 슬라이스에서 처리한다.

## 2. 구현 — A. 뉴스레터

### 2.1 신규 `src/components/admin/NewsletterHub.tsx`

`'use client'`. 396 `CompetitorWeeklyHub` 와 같은 모양.

| 탭 value | 라벨 | 내용 |
|---|---|---|
| `history` | **발송 이력** | 이력 테이블 + 수신자 상세 (기본 탭) |
| `send` | **미리보기·발송** | 미리보기 iframe + 수동 발송 |
| `settings` | **발송 설정** | 요일·시각·카드 수·제목 템플릿 |

- `defaultTab = 'history'` — 396·399 와 같은 원칙. **들어오면 결과부터 보인다.**
- `aria-label="뉴스레터 관리"`

### 2.2 ⚠️ 상태 배치 — 이 슬라이스의 유일한 기술 위험

현재 상태 7덩이가 한 컴포넌트에 있다. **탭 경계를 넘는 것과 넘지 않는 것을 나눈다.**

| 상태 | 위치 | 이유 |
|---|---|---|
| `settings` · `settingsStatus` · `settingsError` | `settings` 탭 내부 | 그 탭에서만 쓴다 |
| `previewHtml` · `previewLoading` · `sendStatus` · `sendResult` | `send` 탭 내부 | 그 탭에서만 쓴다 |
| `issues` · `selectedIssueId` · `recipients` · `recipientsLoading` | `history` 탭 내부 | 그 탭에서만 쓴다 |

**셋 다 서로를 참조하지 않는다**(확인함 — `sendResult` 는 279행에서만, `selectedIssueId` 는 127·144·346행에서만 쓰인다). **따라서 상태를 Hub 로 끌어올릴 필요가 없다.** 399 와 다른 점이다.

⚠️ **단, 탭 전환 시 언마운트되면 상태가 날아간다.** `renderContent` 가 활성 탭만 렌더하므로:
- `미리보기` 를 띄운 뒤 다른 탭에 갔다 오면 미리보기가 사라진다 — **허용한다**(재생성 버튼 1회).
- **`발송 설정` 의 편집 중 내용이 날아가는 것은 허용하지 않는다.** 저장 안 한 상태로 탭을 옮기면 입력이 사라진다. → `settings` 상태는 **Hub 로 올린다.** 나머지 둘은 탭 내부에 둔다.

### 2.3 컴포넌트 분리
`NewsletterManager` 를 3개로 쪼갠다. **로직·마크업은 그대로 옮기고 새로 쓰지 않는다.**
```
NewsletterSettingsForm.tsx   ← 발송 설정 (settings 상태는 Hub 에서 prop 으로)
NewsletterSendPanel.tsx      ← 미리보기 / 수동 발송
NewsletterHistory.tsx        ← 발송 이력 + 수신자
```
각 `<section className="rounded-2xl border …">` 래퍼와 `<h2>` 제목은 **제거한다** — 탭 라벨이 그 역할을 한다(396 §3.3 과 동일).

### 2.4 `page.tsx`
- 서버 조회(`newsletter_settings`·`newsletter_issues`) **무변경**. `initialSettings`·`initialIssues` 를 Hub 에 prop 으로 전달.
- `AdminPageHeader` **제거**(Shell 이 렌더).
- **`renderContent` 를 page 에서 만들지 않는다**(396 §3.2 — 서버→클라 함수 전달 실패).

## 3. 구현 — B. 모닝브리핑

### 3.1 신규 `src/components/admin/BriefingHub.tsx`

```tsx
'use client'
export default function BriefingHub() {
  return (
    <AdminTabShell
      tabs={[]}                          // ← 탭 없음 (§1.1)
      defaultTab=""
      contextBar={<BriefingTtsBar />}    // TTS 사용량 카드
      renderContent={() => <BriefingManager />}
    />
  )
}
```

- ⚠️ **`tabs={[]}` 로 `useTabParam` 이 깨지지 않는지 확인할 것.** `values` 가 빈 배열이 되므로 `defaultTab` 처리에서 예외가 날 수 있다. 나면 `AdminTabShell` 을 고치지 말고 **`BriefingHub` 에서 `AdminPageHeader` + 브레드크럼을 직접 조립**하는 쪽으로 우회한다. Shell 은 9개 화면이 쓰는 공용이라 이 슬라이스에서 손대면 안 된다.
- TTS 사용량은 `BriefingManager` 가 `/api/…` 로 받아오는 값이라 **Hub 로 올리려면 조회도 함께 올라간다.** 조회를 옮기기 싫으면 **이번엔 `contextBar` 를 쓰지 말고 `BriefingManager` 안에 그대로 두고**, 브레드크럼·헤더 표준만 적용한다. **둘 중 쉬운 쪽을 택하고 §7 에 어느 쪽인지 기록할 것.**

### 3.2 모닝브리핑에서 하지 말 것
- `BriefingManager` **내부 로직 무수정.** 오디오 생성·하이라이트 생성·상태 변경은 실제로 돌아가는 파이프라인이다.
- `EnrichJobsProvider` 연동(`useEnrichJobs`·`buildEnrichRunId`)을 **건드리지 않는다.** 실행 중 상태 추적이 여기에 걸려 있다.
- 탭을 **억지로 만들지 않는다.** 최종안의 미구현 탭(스케줄·음성 설정 등)은 (나) 범위다.

## 5. 회귀 가드
1. **뉴스레터 설정 저장**이 동작하고, 저장 후 상태 배지(`saved`)가 뜬다.
2. **설정 편집 중 탭을 옮겼다 돌아와도 입력이 남아 있다**(§2.2).
3. **미리보기 생성** → iframe 에 HTML 이 뜬다.
4. **수동 발송**이 동작하고 성공·오류 문구가 각각 맞는 톤으로 뜬다.
5. **발송 이력 20건**이 뜨고, 행 클릭 시 수신자 목록·오픈율이 조회된다.
6. 같은 행을 다시 클릭하면 접힌다(127행 토글).
7. **모닝브리핑 목록**이 뜨고 오디오 생성·하이라이트 생성·상태 변경(발행/보관/초안)이 동작한다.
8. **TTS 사용량 게이지**가 정상 표시된다.
9. 실행 중 작업의 진행 표시(`EnrichJobsProvider`)가 유지된다.
10. URL `?tab=send` / `?tab=settings` 직접 진입이 동작한다(뉴스레터).
11. 브레드크럼이 `발행·구독 / 뉴스레터`, `AI 인사이트 / 모닝브리핑` 으로 뜬다.
12. 헤더가 두 번 나오지 않는다.

## 7. 기록란 (구현자가 채울 것)

| 항목 | 결과 |
|---|---|
| 모닝브리핑 `tabs={[]}` 방식 채택 여부 (§3.1) | **채택함.** `AdminTabShell` 무수정으로 정상 동작(코드 확인·`npm run build` 통과 둘 다 확인). |
| `useTabParam` 이 빈 배열에서 정상 동작했는가 | **정상.** `values=[]`이면 `includes` 가 항상 false라 `active`가 `defaultValue`(`''`)로 고정될 뿐, 예외 없음. `tabs.length > 0` 가드로 탭 바도 렌더되지 않음. 빌드 통과로 재확인. |
| TTS 를 `contextBar` 로 올렸는가, `BriefingManager` 에 남겼는가 | **`BriefingManager` 에 그대로 남김(쉬운 쪽).** TTS 사용량이 `BriefingManager` 자체 조회(`BriefingsResponse.tts`)에 묶여 있어, 분리하려면 조회 로직까지 옮겨야 해 "내부 로직 무수정" 원칙과 충돌한다. `BriefingHub`는 `contextBar` 없이 `tabs=[]` + `renderContent={() => <BriefingManager />}`만 적용. |
| 뉴스레터 `settings` 상태를 Hub 로 올렸는가 | **올림.** `settings`·`settingsStatus`·`settingsError` 3개만 `NewsletterHub`가 들고 `NewsletterSettingsForm`에 prop으로 전달. `send`(`NewsletterSendPanel`)·`history`(`NewsletterHistory`) 상태는 각 탭 컴포넌트 내부에 둠(§2.2 표대로, 서로 미참조 확인됨). |

**별건 — 고치지 말고 기록만**
- §1.2 **발송 이력이 발송 후 갱신되지 않는다**(`const [issues] = useState(...)`, setter 없음). 탭화로 더 눈에 띄게 된다. 후속 슬라이스 필요.
