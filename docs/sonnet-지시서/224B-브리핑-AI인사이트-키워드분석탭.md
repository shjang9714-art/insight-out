# 지시서 224B — 브리핑을 AI인사이트 "키워드 분석" 탭으로 이동

목표: 224에서 기업동향에서 제거한 **브리핑(entity_signal_summary)** 콘텐츠를 **AI인사이트 L2 탭**으로 옮긴다. 탭 이름은 **"키워드 분석"**, 위치는 **L2 탭 맨 끝**(관계지도 뒤).

David 결정: 브리핑 → AI인사이트 이동, 이름 "키워드 분석", AI인사이트 L2 마지막에 배치(일단).

범위: `AiInsightsView.tsx`(서버, 데이터 패치 추가) + `AiInsightBoard.tsx`(탭·뷰 추가) + AiInsightsView를 렌더하는 페이지의 view 검증. **SQL 없음**(entity_signal_summary 기존 존재). 프론트 온리.

전제: 224가 먼저(또는 함께) 적용 — 기업동향에서 briefing 뷰가 제거된 상태.

---

## 1. 현행 진단 (검증된 코드 사실)
- **AI인사이트** `AiInsightBoard.tsx`: L2 탭 `TABS = [brief(핵심 Insight), headline(헤드라인 분석), trending(뜨는 토픽), issues(이슈 타임라인), graph(관계지도)]`. `AiInsightViewId = 'brief'|'headline'|'trending'|'issues'|'graph'`. `view` state + `history.replaceState('?view=')`.
- **AiInsightsView.tsx**(서버): 여러 소스 병렬 패치 후 AiInsightBoard에 props 위임. 시그니처 `view?: 'brief'|'headline'|'trending'|'issues'|'graph'`.
- 이동할 원본: **구 기업동향 briefing 블록**(224에서 삭제) — `entity_signal_summary`(`entity_id, signal_count, content_count, signal_types, last_seen`, order signal_count desc limit 30) + `entities`(id, canonical_name, entity_type, is_competitor) 조인 → 카드 그리드(엔티티명·타입 배지·시그널 칩·건수·날짜, 링크 `/dashboard/entities/{id}`).

## 2. 구현

### 2-1. `AiInsightsView.tsx` — entity_signal 패치 추가
- 기존 `Promise.all([...])`에 항목 2개 추가(또는 별도 병렬):
  ```ts
  supabase.from('entity_signal_summary')
    .select('entity_id, signal_count, content_count, signal_types, last_seen')
    .order('signal_count', { ascending: false }).limit(30),
  // 결과의 entity_id 로 entities 메타 조회(이어서)
  ```
- entity 메타 조회: `entities.select('id, canonical_name, entity_type, is_competitor').in('id', eids)`.
- **직렬화 가능한 배열**로 합쳐 AiInsightBoard에 전달:
  ```ts
  interface SignalItem {
    entityId: string; name: string; entityType: EntityType; isCompetitor: boolean
    signalCount: number; contentCount: number; signalTypes: string[]; lastSeen: string | null
  }
  ```
  (row + 메타 조인해 `signalItems: SignalItem[]` 구성. 메타 없는 entity_id 는 제외.)
- 시그니처 확장: `view?: ... | 'keyword'`. `<AiInsightBoard ... signalItems={signalItems} />` 추가.

### 2-2. AiInsightsView 를 렌더하는 페이지 — view 검증에 'keyword' 추가
- 해당 페이지(예: `dashboard/analysis` 또는 AI인사이트 라우트)의 `searchParams.view` 유효값 목록에 **'keyword' 추가**(없으면 기본값으로 튕겨 마지막 탭 접근 불가).

### 2-3. `AiInsightBoard.tsx` — 탭·뷰 추가(맨 끝)
- 타입: `AiInsightViewId = ... | 'keyword'`.
- `TABS` **맨 끝에** 추가: `{ id: 'keyword', label: '키워드 분석' }`.
- props에 `signalItems: SignalItem[]`(위 타입 인라인 정의).
- 렌더 블록 추가(관계지도 뒤):
  ```tsx
  {view === 'keyword' && (
    <section>
      <p className="mb-4 text-xs text-muted-foreground">엔티티별 시그널 요약 — 신호가 많은 순</p>
      {signalItems.length === 0 ? (
        <div className="rounded-xl border border-dashed p-8 text-center text-sm text-muted-foreground">
          시그널 데이터가 있는 엔티티가 없습니다.
        </div>
      ) : (
        <div className="grid gap-3 sm:grid-cols-2 lg:grid-cols-3">
          {/* 구 기업동향 briefing 카드 그리드 마크업 그대로 이식:
              엔티티명 + 타입 배지(경쟁사면 red 톤) + signal_types 칩(최대3) + 시그널/콘텐츠 건수 + last_seen,
              Link href={`/dashboard/entities/${entityId}`} */}
        </div>
      )}
    </section>
  )}
  ```
  마크업은 구 `entities/page.tsx` briefing 블록(356~419행)을 `SignalItem` 필드명에 맞춰 이식(`ent.canonical_name`→`name`, `row.signal_count`→`signalCount` 등). `ENTITY_TYPE_LABEL` import 유지.

## 3. 회귀 가드
- 기존 5개 뷰(brief/headline/trending/issues/graph) **불변** — 'keyword'만 추가.
- `signalItems`는 서버에서 직렬화된 배열 → 클라이언트 컴포넌트 경계 안전.
- 초기 진입 `?view=keyword` 지원(2-2 view 검증 추가). 미추가 시 마지막 탭 딥링크가 기본값으로 튕김 — 반드시 반영.
- entity_signal_summary가 뷰/집계라도 select만 하므로 안전. 데이터 없으면 빈 상태.
- 기업동향(224)에서 briefing 제거와 **중복 노출 없음**(옮긴 것이라 한 곳에만).

## 4. 검증 (Sonnet)
- `npx tsc --noEmit` 0, `npx eslint`(수정 파일) 0, `npm run build`.
- 육안: AI인사이트 L2 마지막 탭 "키워드 분석" 노출, 엔티티 시그널 카드 그리드 정상, `?view=keyword` 딥링크 동작.
- 기존 탭 회귀 없음.
