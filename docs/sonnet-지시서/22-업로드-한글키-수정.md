# 지시서 22 — 리포트 업로드 한글 Storage 키 오류 수정

> 작성: Opus(Cowork) · 대상: 구현 에이전트(Codex) · 검증: Opus · 커밋: 구현 에이전트
> ⚠️ 작업 전 `src/app/api/admin/upload/route.ts`(storagePath 생성)·`src/components/admin/ReportUploadForm.tsx`(category 전달) 를 읽을 것.

## 증상
`/admin/upload` 에서 발행처 "가트너"로 PDF 업로드 시:
`파일 업로드 실패: Invalid key: 가트너/2026/<uuid>.pdf`

## 원인
`upload/route.ts` 의 `storagePath = ${category}/${year}/${uuid}.${ext}` 에 **발행처 한글명(가트너/웹인사이트 등)이 폴더 세그먼트로 들어감**. Supabase Storage 객체 키는 **ASCII-safe 문자(`A-Za-z0-9._-` + `/`)만 허용** → 한글 포함 시 `Invalid key`. (KRG처럼 영문 발행처는 통과)

## 수정
**Storage 키의 발행처 세그먼트만 ASCII로 정규화.** DB에 저장되는 발행처 라벨·표시값은 변경 금지(한글 유지).
- `route.ts` 에서 `category` 를 그대로 쓰지 말고 `safeSegment(category)` 로 변환:
  - 소문자화, 공백→`-`, **허용셋(`a-z0-9-_.`) 외 문자 제거**.
  - 결과가 빈 문자열이면(한글 전용 등) **원본 category의 안정 해시**로 폴백 → 같은 발행처가 항상 같은 폴더. 예: `pub-${sha256(category).slice(0,8)}`(기존 `src/lib/crawler/normalize.ts` 의 `sha256` 재사용 가능).
  - 최종 세그먼트도 안전 보장(빈 값 금지).
- `storagePath = ${safeCategory}/${year}/${uuid}.${ext}`. `year`·`uuid`·`ext` 로직 불변. `ext` 도 영숫자만 남기도록 가볍게 정리(안전).
- `contents` insert 의 발행처/제목 등 **표시 데이터는 한글 그대로**. `file_path` 는 새 안전 경로 저장.

## 건드리지 말 것
- 업로드 동작(서명 URL 발급·Storage 업로드·insert)·버킷·RLS·서명 URL 조회(`getReportSignedUrl`) 로직 불변. 한글은 키에서만 제거, 그 외 전부 유지.

## 점검
- 발행처 "가트너"·"웹인사이트"(한글) 업로드 성공(키가 ASCII, 예 `pub-xxxxxxxx/2026/<uuid>.pdf`).
- 영문 발행처(KRG) 회귀 없음.
- 업로드 후 상세에서 서명 URL로 PDF 정상 열림(키 바뀌어도 `file_path` 일관).
