## A. 요약 카드 — 5개를 한 줄로

**`수집 · 게시 · 검토대기 · 발행 · 실패작업` 5개를 한 행(row)에 나란히 배치한다.**

- 전체 상태는 헤더 배지로 이미 있으므로 **카드에서 뺀다.**
- **최고 매체 비중 카드도 뺀다** — C 의 신규 섹션으로 이동한다.
- 각 카드 `width="20%"`, 값은 크게, 비교값은 작게. 5칸이 640px 안에 들어가야 하므로 폰트·패딩을 줄인다(값 18~19px, 라벨 11px, 비교값 10px 수준).
- `[긴급]`/`[주의]` 배지는 **아이콘성 짧은 표기**로 줄이거나 카드 배경·글자색으로만 구분한다. 5칸에 긴 배지 텍스트가 들어가면 줄바꿈으로 높이가 들쭉날쭉해진다.
- 5칸 모두 **같은 높이**로 보이게 `valign="top"` + 고정 패딩.

### 모바일 스택
320px 에서 5칸은 불가능하다. `<head>` 에 **`<style>` 블록 하나**를 두고 미디어 쿼리로 `max-width:480px` 일 때 카드가 `display:block;width:100%` 로 쌓이게 한다.
- 인라인 스타일을 **기본값으로 유지**하고 미디어 쿼리는 덮어쓰기 용도로만 쓴다(미디어 쿼리 미지원 클라이언트는 인라인 그대로 렌더).
- 483 지시서의 "외부 CSS 금지"는 **외부 파일 링크 금지**를 뜻한다. `<head>` 내 `<style>` 은 허용한다.

## B. 사용자 섹션 — 가입 현황을 함께

⑤ 사용자 섹션 맨 위에 **가입 현황 한 줄**을 둔다.

```
가입 현황   누적 26명 · 신규 1명 (전일 +0% · 7일평균 0%)
```

- `users.total`(누적)과 `users.newUsers`(신규)를 **한 줄에 나란히** 본다. 지금은 따로 떨어져 있어 "26명 중 오늘 1명"이라는 관계가 안 읽힌다.
- 그 아래 기존 `승인 대기` · `7일 미접속` 유지.
- 신규 가입 비교값은 기존 `TrendMetric` 을 그대로 쓴다.

## C. 신규 섹션 — 소스별 수집 현황 (발행 현황 **다음**)

섹션 순서를 이렇게 바꾼다.
```
① 오늘 반드시 확인
② 요약 카드 (A)
③ 발행 현황
④ 소스별 수집 현황   ← 신규
⑤ 수집·콘텐츠 건강
⑥ 사용자 (B)
⑦ AI·외부 사용량
⑧ cron 상태
⑨ 조치 필요 항목
```

### C-1. 무엇을 보여주나
**어떤 콘텐츠가 어디서 수집됐는지**를 본다. 전일(KST) 기준.

**(1) 카테고리별 수집 건수** — `뉴스 · 리포트 · 웹인사이트 · 유튜브 · AI보고서` 각 건수와 비중. 막대(`trendBars` 와 같은 테이블 셀 방식) 재사용.

**(2) 소스 Top 5** — 이름 · **카테고리** · 건수 · 비중.
```
동아일보 경제      뉴스        212건   32%
연합뉴스           뉴스        118건   18%
...
```

**(3) ⚠️ 소스 미지정 건수를 반드시 별도 표기한다.**
`contents.source_id` 가 없는 수집분이 상당수다 — 483 검증에서 30일 매체 집계 분모가 **4,538건**이었는데 수집은 하루 668건 규모다. 즉 **소스가 등록된 수집분은 전체의 일부**다.
→ `소스 미지정 N건 (M%)` 을 목록 아래에 반드시 표기한다. 없으면 "Top 5 합이 전체와 안 맞는다"는 오해가 생긴다.
→ 비중(%)의 **분모는 전일 전체 수집 건수**로 통일한다(소스 있는 것만이 아니라).

### C-2. 데이터 — 신규 SQL 없이
전일 범위만 조회하면 수백~수천 행이므로 앱 집계로 충분하다.
```
contents: select category, source_id, sources(name, type)
          where collected_at >= 전일시작(KST) and < 전일종료(KST)
```
- `source_quality_stats` RPC 는 **30일 창이고 카테고리가 없다** — 이 섹션에는 쓰지 마라.
- ⚠️ 483 이 없앤 `limit(10000)` 패턴을 다시 만들지 말 것. 전일 범위라 상한이 필요 없지만, 방어적으로 상한을 두려면 **상한에 걸렸을 때 그 사실을 표기**해야 한다(조용히 자르지 말 것).
- 조회 실패 시 이 섹션만 `unavailable` 로 표기하고 메일은 그대로 발송한다.

### C-3. 요약 카드의 최고 매체 비중
A 에서 뺀 대신, 이 섹션의 Top 1 이 그 역할을 한다. **경고 판정(70% 이상)은 유지**하되 판정 대상을 **전일 기준 Top 1 비중**으로 바꾼다(기존 30일 기준은 일일 리포트와 시간축이 어긋난다).

## D. 483 잔여 (같이 처리)

`<head>` 에 다음 두 줄 추가 — 다크모드 강제 반전 방지.
```html
<meta name="color-scheme" content="light dark">
<meta name="supported-color-schemes" content="light dark">
```

메일 제목에 **날짜를 항상 포함**한다. 현재 `severity`가 `critical`/`warning` 이면 날짜가 빠져 받은편지함에서 어느 날짜 건인지 구분되지 않는다.
```
[위험][인사이트 아웃 운영리포트] 7월 30일 · gemini 한도 초과 · cron 1건 미실행
```
- 알림 문장을 그대로 넣지 말고 **짧은 구(句)로 축약**한다. 제목 전체가 **70자를 넘지 않게** 한다(Gmail 목록에서 잘린다).
