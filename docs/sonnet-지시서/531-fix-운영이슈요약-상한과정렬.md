# 지시서 531-fix — 운영 이슈 요약 상한과 정렬 방어

- 브랜치: `agent/531-ops-group` (`8dbafa9` 후속)
- 대상: `src/app/admin/page.tsx` 의 `fetchOpsIssueSummary`

## 문제

1. DB에서 `last_seen_at` 기준으로 조회한 뒤 JavaScript에서 `severity`로 재정렬한다. 명시적 상한이 없으면 PostgREST 기본 1,000행 상한에 의해 오래된 `critical` 이슈가 조용히 누락될 수 있다.
2. `severityRank` 정의 밖 값이 들어오면 비교 결과가 `NaN`이 되어 정렬이 붕괴한다.

## 수정

1. `status <> 'resolved'`, `last_seen_at desc` 조회 체인에 `.limit(200)`을 추가한다.
2. 심각도 순위 조회를 함수로 감싸고, 정의되지 않은 값은 `9`로 뒤로 보낸다.

```ts
const rank = (severity: OpsIssueSummaryRow['severity']) => severityRank[severity] ?? 9
```
