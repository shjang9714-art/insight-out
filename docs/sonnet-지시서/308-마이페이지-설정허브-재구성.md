## 0. 한 줄

마이페이지를 **"설정 편집기"가 아니라 "설정 허브"** 로 바꾼다. 실제 편집은 **각 화면이 이미 쓰는 모달을 재사용**하고, 마이페이지는 **무엇이 설정돼 있고 어디서 쓰이는지**만 보여준다. 그리고 **죽은 설정을 걷어낸다.**

## 1. 현행 진단 (재검증됨 — 2026-07-12, 293·294·305 배포 후)

### 1.1 ⭐ 인지부조화의 원인 — 관심업체 편집 UI가 여러 곳에 흩어져 있다
`user_watchlist`를 편집하는 UI:
```
src/components/watchlist/WatchlistSettingsModal.tsx   ← "주요 기업 설정" 모달 (기업동향 화면)
src/components/watchlist/WatchlistManager.tsx
src/components/analysis/AiInsightsView.tsx
src/components/dashboard/PersonalizationNudge.tsx
src/app/dashboard/mypage/page.tsx                     ← 마이페이지에도 별도 UI
```
→ **같은 설정을 여러 화면이 각자의 UI로 편집한다.** "어디서 바꾸는 게 맞지?"가 매번 생긴다.

**해결의 핵심**: `WatchlistSettingsModal`이 **이미 존재한다**(확인됨). 마이페이지가 **자기 UI를 버리고 이 모달을 재사용**하면 편집 UI가 하나가 되고, 어디서 열든 같은 화면이 된다.

### 1.2 ⛔ `content_filter_mode`는 **제거하지 않는다** — 309에서 살아난다 (초안 정정)
> **초안(295)은 이걸 "죽은 설정"으로 보고 제거하라고 했다. David 결정(304)으로 뒤집혔다.**

`content_filter_mode`는 **309에서 `default_lens`(`mine`/`watch`/`all`)로 승격**되어 **실제로 동작하는 설정**이 된다.
→ **308에서는 제거하지 말고, "살아 있는 설정"으로 §3-2의 관심 설정 영역에 배치한다.**

**309가 먼저다.** 309가 배선을 끝낸 뒤 308이 UI를 재구성한다. **순서를 바꾸지 말 것.**

### 1.3 `직책`(position)도 죽어 있다 — **제거 확정**(David 지시)
`types.ts`와 **어드민 사용자 목록 select**(`src/app/admin/users/actions.ts:62`)에만 있다. 추천·권한·개인화 어디에도 안 쓰인다.

### 1.4 살아 있는 설정 (건드리지 말 것)
- **담당 서비스**(`user_services`) — `lens.ts` · `dashboard/contents/page.tsx`가 **실제로 읽는다.**
- **관심업체**(`user_watchlist`) — `lens.ts` · `insight/generate.ts` · `entities/major-companies.ts`가 **실제로 읽는다.**

### 1.5 ✅ 진입 경로는 **이미 올바르다** — 고칠 것 없다 (초안의 오진을 정정)
> **초안(295)은 *"상단 네비에 마이페이지가 서비스 메뉴와 같은 위계로 섞여 있다"* 고 썼다. 사실이 아니다.**

- 마이페이지 진입점은 **우측 상단 사용자 영역**(이름·팀·아바타) **전체를 감싼 `<Link href="/dashboard/mypage">`**(`:293-296`)다. **이미 설정 자리에 있다.**
- **드롭다운 메뉴가 코드베이스에 아예 없다**(`DropdownMenu` 0회, shadcn `dropdown-menu` 컴포넌트 없음).

→ **네비에서 뺄 것도 없고, 유저 드롭다운을 새로 만들지도 않는다.** 초안 §3-5는 **폐기한다.**

## 3. 구현

### 3-1. 죽은 설정 제거 — **`직책`(position) 하나뿐이다**
- **`직책`(position)** — 마이페이지·온보딩 폼에서 **제거**. 어드민 사용자 목록의 표시는 그대로(값 없으면 빈칸).
- ⛔ **`기본 보기`(default_lens)는 제거하지 말 것.** 309에서 살아난 설정이다(§1.2). §3-2에 배치한다.

### 3-2. ⭐ 관심 설정 = "허브 + 모달 재사용" (이 지시서의 본체)

마이페이지는 **편집기를 갖지 않는다.** **현재 설정 요약 + 어디서 쓰이는지 + 편집 버튼**만 둔다.
버튼을 누르면 **각 화면이 이미 쓰는 모달**이 그대로 열린다.

```
관심 설정

┌────────────────────────────────────────────────────────┐
│ 관심 기업 · 7개 선택됨                                  │
│ 안랩 · OpenAI · Microsoft · SK AX · 현대오토에버 …     │
│                                                        │
│ 📍 기업동향 · AI 인사이트에서 이 기업들의 소식을        │
│    모아 보여줍니다.                                     │
│                                       [기업 설정 →]    │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│ 담당 서비스 · 5개 선택됨                                │
│ 보안/클라우드 · M2M · AICC · AIDC · 모빌리티            │
│                                                        │
│ 📍 콘텐츠 · 홈에서 내 서비스 관련 소식을 우선           │
│    보여줍니다.                                          │
│                                     [서비스 설정 →]    │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│ 기본 보기                        ( ) 내 업무           │   ← 309에서 살아난 설정
│                                  (•) 내 관심사          │
│                                  ( ) 전체              │
│ 📍 콘텐츠 · AI 인사이트 · 기업동향을 열 때 이 기준으로  │
│    시작합니다. 화면에서 언제든 바꿀 수 있습니다.        │
└────────────────────────────────────────────────────────┘
```
> **기본 보기(`default_lens`)만은 마이페이지에서 직접 편집한다** — 모달이 따로 없고, 라디오 3개면 끝난다.
> 라벨·설명은 **`LENS_PRESETS`를 그대로 쓸 것**(문구를 새로 짓지 말 것 — 화면의 렌즈 전환 UI와 글자가 달라지면 그게 또 인지부조화다).
> 값을 바꾸면 **`localStorage` 갱신 + `'lens:changed'` dispatch** (309 §3-4). 안 그러면 "바꿨는데 화면이 그대로"가 된다.

**요건**
- **[기업 설정]** → **`WatchlistSettingsModal`을 그대로 재사용.** 마이페이지 전용 편집 UI는 **삭제**한다.
- **[서비스 설정]** → 담당 서비스 선택 모달. 없으면 만들되, **온보딩(`Step1Profile`)의 선택 UI를 모달로 추출해 공용화**할 것. **온보딩·마이페이지가 같은 컴포넌트를 쓰게 한다.**
- **"📍 어디서 쓰이는지" 문구는 필수다.** David 지시의 핵심 — 이 설정이 무엇에 영향을 주는지 알아야 한다.
- 선택 결과(칩)는 **읽기 전용 요약**. 마이페이지에서 직접 편집하지 않는다.

> **이게 인지부조화를 없애는 방식이다.** 편집 UI가 하나뿐이니 *"여기서 바꾸면 저기도 바뀌나?"* 라는 의문 자체가 생기지 않는다.

### 3-3. 마이페이지를 **탭**으로 나눈다 (885줄 → 분리)

진입 경로는 **그대로 두고**(§1.5), 페이지 안을 나눈다:

```
[설정]  [북마크]  [아카이브]
```

- **설정 탭** = 3영역
  ```
  1. 기본 정보  — 이름 · 이메일(읽기 전용) · 부문 · 팀        [저장]
  2. 관심 설정  — 관심 기업(허브+모달) · 담당 서비스(허브+모달)
  3. 알림 설정  — 뉴스레터 수신 · 수신 이메일                 [저장]
  ```
  저장 버튼은 **섹션당 1개**. 관심 설정은 모달에서 저장하므로 **저장 버튼이 없다**.
- **북마크 / 아카이브 탭** — **기능·데이터는 그대로.** 현재 코드를 탭 안으로 옮기기만 한다.
- **새 라우트를 만들지 말 것**(`/dashboard/bookmarks` 등). `/dashboard/mypage` 하나를 유지한다.
- 885줄 한 파일이므로 **탭별 컴포넌트로 파일을 쪼갤 것.**

> **왜 별도 라우트·드롭다운이 아닌가**: 코드베이스에 드롭다운 컴포넌트가 없고(§1.5), 진입점은 이미 아바타로 분리돼 있다. **새 라우트 2개 + 새 드롭다운은 이 슬라이스의 목적(인지부조화 제거)과 무관한 비용이다.**

### 3-4. 밀도 압축
- **담당 서비스 카드**: 설명문 제거(툴팁으로) · 아이콘 축소 · 높이 축소. 선택 상태만 확실히.
- **관심업체 모달**: 선택 결과(칩)를 **위**, 검색·그룹 선택을 **아래**. 그룹 목록은 **접기/펼치기**.
- 뉴스레터 설명 문구 축소.

## 4. 회귀 가드

- **살아 있는 설정을 깨지 말 것** — `user_services`·`user_watchlist`는 `lens.ts`·`insight/generate.ts`가 실제로 읽는다. **저장 경로·데이터 형식 불변.**
- **`WatchlistSettingsModal`을 새로 만들지 말 것.** 기존 것을 재사용한다. **그게 이 지시서의 핵심이다.**
- **온보딩과 마이페이지가 같은 서비스 선택 컴포넌트를 쓰게 할 것.** 따로 만들면 또 갈라진다 — **지금 문제의 원인이 그것이다.**
- ⚠️ **온보딩이 깨지지 않을 것** — **서비스 선택이 항상 보여야 한다.** (원래 `content_filter_mode` 토글이 이걸 조건부로 감췄다. 309에서 풀렸는지 확인하고, 안 풀렸으면 여기서 푼다.)
- **`position` 컬럼을 DB에서 지우지 말 것**(§2) — `admin/users/actions.ts:62`가 select 한다. **UI에서만** 뺀다.
- ⛔ **`기본 보기`(default_lens)를 제거하지 말 것.** 309에서 살아난 설정이다. 초안(295)의 "제거" 지시는 **폐기됐다.**
- **북마크·아카이브의 데이터·기능은 유지.** 탭으로 옮기기만 한다.
- **상단 네비를 건드리지 말 것**(§1.5) — 마이페이지는 이미 네비 탭에 없다. **드롭다운을 새로 만들지 말 것.**
- `/dashboard/mypage` 경로 유지.
