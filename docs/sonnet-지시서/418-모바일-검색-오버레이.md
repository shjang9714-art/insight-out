## 0. 한 줄
모바일 검색 FAB 를 누르면 **페이지 이동 대신 풀스크린 오버레이**가 뜬다 — 렌즈별 추천 질문 칩 + **결과 인라인**. 검색 페이지의 fetch·결과 렌더를 **공용화**해 오버레이와 검색 페이지가 같은 로직을 쓴다. (AI 답변 카드·"보고서로"는 미구현 기능이라 이번 범위 제외.)

---

## 1. 착수 전 확인 (실측 2026-07-23, origin/main)

- **검색 FAB**: `src/components/dashboard/MobileBottomNav.tsx` — `<Link href="/dashboard/search">`(411, 순수 라우트 이동). `md:hidden`(모바일 전용).
- **검색 페이지**: `src/app/dashboard/search/page.tsx` `SearchContent` — `'use client'`, `useSearchParams()`로 `q`/`filter`, `useEffect`(L102~)가 Supabase **ILIKE** 3테이블(`contents`·`daily_insights`·`issues`) 병렬 → `results` state. **fetch 로직이 페이지에 인라인**(공용 훅 없음). 결과 렌더는 `ContentRow`·`SearchResultCard` map. `q` 없으면 `<SuggestedQuestions>`.
- **재사용 가능(그대로)**: `SearchBar`(입력·필터, **이미 `onClose` prop 있음** — 오버레이 상정), `SuggestedQuestions`(렌즈별 질문 칩, 클릭 시 `router.push(/dashboard/search?q=)`), `SearchResultCard`, `ContentRow`, `search-filters.ts`.
- **`DetailSheet`(M-4) 재사용 안 함**: 인터셉트 라우트·85vh 바텀시트·상세 전용. 문서 L44 "상세는 시트 / **전역 진입은 오버레이**"로 명시 구분. 신규 오버레이가 맞다.

## 2. 구현

### 2.1 검색 로직 공용화 (검색 페이지 리팩터 — "잘라 옮기기", 동작 동일)
**신규 훅** `src/lib/search/use-unified-search.ts`(클라이언트):
- 시그니처 `useUnifiedSearch(q: string, filter: SearchFilterKey | ''): { results: UnifiedResult[] | null; isLoading: boolean; error: string | null }`.
- `SearchContent`의 `useEffect`(ILIKE 3테이블·회사 별칭 정규화·60건 병합 정렬) **로직을 그대로 이 훅으로 이동**. `UnifiedResult`·헬퍼 타입도 공용 위치로.

**신규 컴포넌트** `src/components/search/SearchResultsList.tsx`:
- props `{ results: UnifiedResult[] }`. `SearchContent`의 **결과 map(ContentRow/SearchResultCard 분기)을 그대로 이동**.

**검색 페이지**: `SearchContent`가 위 훅 + `SearchResultsList`를 쓰도록 교체. ⚠️ **화면·동작 픽셀 동일**(회귀 금지). 로딩/빈/에러 문구도 그대로.

### 2.2 신규 `src/components/mobile/SearchOverlay.tsx` (클라이언트, 모바일 풀스크린)
- radix `Dialog` **primitive** 기반(래퍼 `ui/dialog`는 중앙 모달이라 부적합 — primitive 재사용). **풀스크린**: `fixed inset-0 z-50 bg-background`, 위→아래 슬라이드/페이드, `env(safe-area-inset)` 반영. **`md:hidden`** (모바일 전용; 데스크톱은 기존 헤더 검색 유지).
- 내부 상태: **로컬 `q`·`filter`**(URL 아님). 오버레이는 페이지 이동 없이 그 자리에서 검색.
- 구성:
  - 상단: 닫기(×) + **`SearchBar`**(입력·필터). 제출을 **오버레이 로컬 상태로** 받도록 `SearchBar`에 **선택 prop `onSubmit?(q, filter)`** 추가 — 있으면 `router.push` 대신 `onSubmit` 호출(없으면 기존 네비 동작 그대로, 데스크톱 회귀 0). 오버레이는 `onSubmit`으로 로컬 `q`·`filter` set.
  - `q` 없을 때: **`SuggestedQuestions`** — 칩 클릭이 네비 대신 로컬 `q`를 set 하도록 **선택 prop `onSelect?(q)`** 추가(있으면 그걸, 없으면 기존 `router.push`). 오버레이는 `onSelect`로 로컬 set.
  - `q` 있을 때: `useUnifiedSearch(q, filter)` → 로딩/빈/에러/`SearchResultsList` 인라인(2.1 공용 사용).
- 결과 클릭(ContentRow/카드는 `<Link>`)로 상세 이동 시 **오버레이 자동 닫힘**: `usePathname()` 변화 감지 effect 로 open=false(전역 셸 지속이라 안 닫으면 새 페이지 위에 남는다).

### 2.3 오버레이 열림 상태 + FAB 연결
- 열림 상태를 **`DashboardShell`**에 두고 `MobileBottomNav`에 전달(가벼운 context 또는 state lift). 예: `SearchOverlayProvider`로 `openSearch()` 노출, `<SearchOverlay>`를 셸에 마운트.
- `MobileBottomNav` 검색 FAB: `<Link href="/dashboard/search">` → **`onClick={openSearch}` 버튼**으로. (여전히 `md:hidden`이라 모바일 전용, 데스크톱 무관.)
- ⚠️ `/dashboard/search` 라우트·페이지는 **유지**(딥링크·데스크톱·오버레이 결과 클릭 외 경로). 없애지 않는다.

### 2.4 하지 말 것
- **검색 fetch·필터·별칭 정규화 로직 재작성 금지** — 훅으로 잘라 옮기기만.
- `SearchBar`·`SuggestedQuestions` 기존 동작(네비) **회귀 금지** — 새 prop은 **선택적**, 없으면 종전 그대로.
- `DetailSheet`·M-4 인터셉트 라우트 **무관·무수정**.
- 데스크톱 헤더 검색·`/dashboard/search` 페이지 **무변경**(2.1 리팩터는 내부 구조만, 화면 동일).
- AI 답변 카드·출처 pill·"보고서로 보내기"는 **이번 범위 아님**(미구현 기능, 후속).
- 인증·라우트·데이터 로직 무수정.

## 3. 회귀 가드
1. **모바일**: 검색 FAB → 풀스크린 오버레이(페이지 이동 없음). ×·뒤로가기·ESC 로 닫힘.
2. 오버레이에 렌즈별 추천 질문 칩 → 칩 탭 시 **오버레이 안에서** 결과가 뜬다(이동 없음).
3. 입력·필터 제출 → 오버레이 안 인라인 결과.
4. 결과 클릭 → 상세로 이동하며 **오버레이 자동 닫힘**.
5. **검색 페이지(`/dashboard/search`)가 이전과 픽셀 동일**하게 동작(리팩터 회귀 없음) — q/filter URL, 결과, 빈/로딩/에러.
6. **데스크톱**: 헤더 검색·검색 페이지 그대로, 오버레이 안 뜸, FAB(하단탭바) 자체가 `md:hidden`.
7. `SearchBar`·`SuggestedQuestions`를 쓰는 기존 위치(헤더·검색페이지) 동작 회귀 없음(새 prop 미전달 시 종전).
8. 하단 탭바·미니플레이어와 z-index 안 충돌(오버레이 최상단 z-50+).
