# 지시서 540 — 프롬프트 DB 이관 3종 (533 선행 과제)

> 플래너(Opus) · 2026-08-20 · 기준 `origin/main = 97b033d` · 브랜치 `agent/540-prompt-migration`
> **SQL·DDL 없음.** 아래 §0 을 먼저 읽을 것 — 이전 검토서의 전제가 틀렸다.

## 0. 전제 정정 — 이관 기반은 이미 다 있다

`검토-어드민IA-2차통합안-2026-08-16` 은 "프롬프트를 DB로 옮기는 작업이 선행되어야 한다"고 썼다.
실사 결과 **옮길 기반이 이미 전부 존재한다.**

- `llm_prompts(key, label, prompt_text, updated_at)` 테이블이 **이미 있다.** 스키마 변경 불필요.
- `loadPrompt(admin, key, fallback)` 헬퍼가 있다(`src/lib/prompts/load-prompt.ts`).
  DB 우선, 없으면 코드 상수 폴백. 테이블이 없어도 안 깨진다.
- `/api/admin/prompts` GET 이 **카탈로그 + DB 를 병합**한다. DB 행이 없으면 코드 상수를
  그대로 보여 주고 `saved: false` 로 표시한다. → **시드 SQL 도 필요 없다.**
  카탈로그에 등록하는 순간 콘솔에 뜨고, 저장하면 그때 행이 생긴다.
- 카탈로그가 절차를 이미 문서화해 두었다(`catalog.ts` 상단 주석):
  ① `loadPrompt` 로 DB 우선 로드 ② 상수를 export ③ 카탈로그에 등록. **세 곳을 함께 갱신.**

즉 이 작업은 **키 3개를 그 절차대로 등록하는 것**이 전부다.

(참고 — `llm_prompts` 에 `competitor_weekly_area` · `competitor_weekly_summary` 두 행이 있는데
코드 참조가 0건이고 카탈로그에도 없다. GET 이 카탈로그 밖 key 를 숨기므로 화면에도 안 뜬다.
**죽은 행이다. 이번에 건드리지 말 것** — 삭제는 별도 판단.)

## 1. 대상 3종

| 새 key | 현재 위치 | 치환 토큰 |
|---|---|---|
| `briefing_script` | `src/lib/briefing/generate-briefing.ts` `buildSystemPrompt(hostName)` | `{host_name}` |
| `newsletter_card_insight` | `src/lib/newsletter/card-insights.ts` `SYSTEM_PROMPT` | 없음 |
| `daily_insight` | `src/lib/insight/generate.ts:61` `SYSTEM_PROMPT` | 없음 |

## 2. 작업

### 2-1) `briefing_script`

- `buildSystemPrompt(hostName)` 를 **템플릿 상수**로 바꾼다.
  `export const BRIEFING_SYSTEM_FALLBACK` — 본문의 `${hostName}` 자리에 **`{host_name}`** 리터럴을 넣는다.
  (치환 토큰 방식은 `competitor_weekly_facts` 의 `{area_label}` 전례를 따른다.)
- 사용 지점(현재 `llmCompleteDetailed('briefing', buildSystemPrompt(hostName), …)`, 약 405행)
  **앞에서** `loadPrompt(admin, 'briefing_script', BRIEFING_SYSTEM_FALLBACK)` 로 한 번 읽고
  `.replaceAll('{host_name}', hostName)` 한 결과를 넘긴다. `admin` 은 같은 함수(약 323행)에 이미 있다.
- ⚠️ **치환을 빠뜨리면 진행자가 자기 이름을 `{host_name}` 이라고 읽는다.** TTS 로 나가는 글이다.

### 2-2) `newsletter_card_insight`

- `SYSTEM_PROMPT` 를 `export const NEWSLETTER_CARD_INSIGHT_FALLBACK` 로 바꾼다.
- `generateCardInsights()` 안에서 `createAdminClient()` 로 클라이언트를 만들고
  `loadPrompt(admin, 'newsletter_card_insight', …)` 를 **함수당 1회** 호출한다.

### 2-3) `daily_insight`

- `src/lib/insight/generate.ts:61` 의 `SYSTEM_PROMPT` 를
  `export const DAILY_INSIGHT_SYSTEM_FALLBACK` 로 바꾼다.
- ⚠️ **그룹 루프 안에서 읽지 말 것.** 루프 진입 **전에** 한 번 읽어 변수에 담고 루프에서 재사용한다.
  루프 안에 넣으면 그룹 수만큼 DB 조회가 늘어난다.
- 같은 파일의 `COMPANY_SYSTEM_PROMPT`(약 289행)와 그 전용 로더(약 351~363행)는 **건드리지 않는다.**

### 2-4) 카탈로그 등록

`src/lib/prompts/catalog.ts` 에 세 항목을 추가한다. `group` 은 어드민 콘솔의 묶음 라벨이다.

| key | label | group |
|---|---|---|
| `briefing_script` | 모닝브리핑 — 진행 스크립트 | 모닝브리핑 |
| `newsletter_card_insight` | 뉴스레터 — 카드 인사이트 | 뉴스레터 |
| `daily_insight` | 핵심 인사이트 — 주간 생성 | 핵심 인사이트 |

`description` 에는 **치환 토큰이 있으면 반드시 명시**한다
(`briefing_script` → "`{host_name}` 치환됨").

## 3. 하지 않을 것

- DDL·SQL·시드 (§0 참고 — 전부 불필요하다)
- `PromptConsole` · `/api/admin/prompts` 수정
- 프롬프트 **문구 자체**의 변경 — 이관이지 개편이 아니다. 공백·줄바꿈까지 그대로 옮긴다
- `competitor_weekly_area` · `competitor_weekly_summary` 죽은 행 삭제
- `COMPANY_SYSTEM_PROMPT` 경로 통합
- 발행 그룹 nav 재편 — 533 에서 한다

   (= 코드 상수 사용 중) 로 현재 문구가 그대로 보이는지
