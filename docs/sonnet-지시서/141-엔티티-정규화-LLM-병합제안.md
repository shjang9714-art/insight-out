## 배경 (A2 — 로드맵의 "진짜 난제")

엔티티 스키마·`merge_entities` RPC·수동 병합 UI(EntityManager)·alias 글로벌 유일성·크롤 alias 매칭은 **이미 있음.** 빠진 건 **정규화 자동화**: 같은 실체가 'MS'·'Microsoft'·'마이크로소프트' **여러 행으로 쪼개져도 감지·병합을 사람이 수동으로** 찾아야 함. 특히 **영문↔국문↔약칭은 문자열 유사도로 못 잡음 → LLM 필수.** 이 정규화가 134 사건 타임라인·136 관계 탐색기·워치리스트 매칭 품질의 **공통 토대.**

**해법**: LLM이 엔티티 목록을 읽어 **동의어 그룹(같은 실체의 다른 표기)을 제안** → 어드민이 검토 후 **기존 merge_entities로 병합 + 동의어 보강.** 자동 병합 아님(사람 확인 필수).

**원칙(브레이크)**: v1은 **제안 + 어드민 검토 병합**(파괴적 자동 병합 금지). 크롤 인라인 NER·자동 적용은 v2.

## A. LLM 정규화 제안 — `src/lib/entities/suggest-normalization.ts` (신규)
`generate-events.ts` 패턴 미러.
```ts
export interface NormalizationGroup {
  canonicalId: string      // 대표(목록 중 mention 최다 등)
  canonicalName: string
  mergeIds: string[]        // 대표로 병합할 기존 엔티티 id(검증 통과)
  newAliases: string[]      // 추가 동의어(약칭·표기 변형)
  reason: string            // 왜 같은 실체인지 한 줄
  confidence: number        // 0~1
}
export async function suggestEntityNormalization(
  admin, opts?: { entityType?: string; limit?: number }
): Promise<NormalizationGroup[]>
```
- 입력: `entities`(+각 `entity_aliases`) mention_count 상위 `limit`(기본 150), **entity_type 단위로**(회사는 회사끼리 — 교차 타입 병합 금지). 각 `{id, canonical_name, type, aliases[]}`.
- 프롬프트: "다음 엔티티 목록에서 **같은 실체의 다른 표기**(영문/국문/약칭, 예 MS=Microsoft=마이크로소프트)를 묶어라. 각 그룹: 대표 1개(목록 내)·병합할 나머지 id·추가 동의어. **확실한 것만, 추측 금지.** 다른 회사를 합치지 말 것. JSON: {\"groups\":[{\"canonical_id\":\"\",\"merge_ids\":[],\"new_aliases\":[],\"reason\":\"\",\"confidence\":0~1}]}." → `looseJsonParse`.
- **환각 가드**: canonical_id·merge_ids가 **입력 집합에 존재**하고 **동일 entity_type**인 것만. 자기 자신 merge 제거, 빈 그룹 제거. confidence < 0.6 제외(보수적).
- 키 없음/실패 → `[]`(throw 금지).

## B. API
- `POST /api/admin/entities/suggest-normalization` — 어드민 게이트, `maxDuration 120`. opts(entityType·limit) → 제안 반환(**적용 안 함**). 키 없음 503.
- 적용은 기존 경로 재사용: **각 merge_id에 `rpc('merge_entities', { p_source: merge_id, p_target: canonical_id })`** 순차 + `new_aliases`를 `entity_aliases` insert(`on conflict (lower(alias)) do nothing`). 클라이언트에서 호출하거나 `POST /api/admin/entities/apply-normalization`(그룹 1개 받아 처리) 신설 중 택1.

## C. 어드민 UI — `EntityManager.tsx` "정규화 제안" 패널
- 상단/탭에 **"정규화 제안"**: 타입 Select(회사/기술/…) + **"제안 생성"** 버튼(→ A API, 스피너).
- 결과: 그룹 카드 목록 — **대표명** + [병합될 엔티티 칩들] + **추가 동의어** + 이유·신뢰도 배지. 각 그룹에 **"병합 적용"**(확인 후 merge_entities 루프 + alias insert → 목록 새로고침) / **"무시"**.
- 비전문 사용자 안내: "같은 회사가 여러 이름으로 쪼개진 걸 합칩니다. 적용하면 되돌릴 수 없어요." (기존 병합 confirm 톤 재사용.)

## D. (보너스) 동의어 보강 — 선택
- 단일 엔티티 선택 시 "동의어 추천"(LLM이 약칭·표기 변형 제안) → 어드민이 골라 추가. (A 프롬프트 재사용, 단일 엔티티 모드.) v1 포함 여부는 가벼우면 포함, 무거우면 v2.
