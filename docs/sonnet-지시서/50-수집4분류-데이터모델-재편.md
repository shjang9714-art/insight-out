# 지시서 50 — 수집 4분류 데이터 모델 재편 (source_type 정리 + collection_method + content_category 마이그레이션)

> 작성: Opus(Cowork) · 대상: 구현 에이전트(Claude Code) · 검증: Opus · 커밋: 구현 에이전트
> ⚠️ 작업 전 `AGENTS.md` + 아래 파일들을 읽을 것. `npm install` 먼저.
> **DB 변경 있음 → 수희 SQL 핸드오프 동반.** 워크플로우(§20.5)대로 **SQL 핸드오프(아래 A절)는 예외적으로 먼저 커밋·푸시**해 수희가 적용하게 하고, 코드(B절)는 검증 통과 후 커밋. SQL 적용 전 코드 배포 시 새 enum 값('web_insight','리포트') 적재가 런타임 실패하므로 **순서 주의**(SQL 먼저 적용 → 코드 배포).

읽을 파일: `src/lib/types.ts`, `src/lib/categories.ts`, `src/components/admin/SourceManager.tsx`, `src/components/admin/ReportUploadForm.tsx`, `src/lib/crawler/orchestrator.ts`(L169~182), `src/lib/crawler/adapters/index.ts`, 카테고리 색상맵 3곳(`src/components/dashboard/ContentCard.tsx`, `ContentRow.tsx`, `src/app/dashboard/contents/[id]/page.tsx`), `supabase/schema.sql`.

## 배경 / 원칙

근거: `docs/뉴스수집-웹인사이트-개선안-2026-06-13.md` + David 확정 설계.

**수집 콘텐츠는 4분류로 단순화**: 뉴스 / 리포트 / 웹인사이트 / 유튜브.
- `오피니언` → **웹인사이트**로 통합(별도 카테고리 폐기).
- `가트너`·`KRG` → **리포트**로 통합(발행처는 source로 관리 — 발행처 일원화는 지시서 51).
- `뉴스레터` *수집* 카테고리·소스타입 → **폐기**(UI 제거 + 신규 선택 차단). **뉴스레터 *발송* 기능(`/admin/newsletter`, `newsletter_subscriptions`, `dispatch.ts`)은 절대 건드리지 말 것** — 별개 시스템.
- `AI분석`·`전략보고서`는 **"생성" 콘텐츠**라 수집 content_category가 아니다 → **이번 지시서에서 content_category enum에 추가하지 않음**(각자 기능/라우트가 처리. 전략보고서=기존 AI보고서 기능).

**핵심 아키텍처 결정**:
1. **content_category를 source_type에서 파생**한다. 지금 `categoryForSourceType()`가 source_type↔category를 따로 들고 있어 어긋남(오피니언↔웹인사이트 불일치의 원인). 파생으로 일원화.
2. **source_type 과 collection_method 분리**. 예: AWS 블로그(웹인사이트, RSS) vs 과기정통부(뉴스, RSS) — 같은 방법, 다른 타입. 그래서 수집 방법은 별도 컬럼.
3. **enum 은 비파괴**: 값 삭제 금지. `ALTER TYPE ... RENAME VALUE`(rename, 무손실)와 `ADD VALUE`만 사용(AGENTS enum 규칙).

## A절. SQL 핸드오프 (수희가 Supabase 에서 실행) — **먼저 커밋·푸시**

`docs/sql-handoff/50-수집4분류.sql`(신규)로 작성하고, **순서·트랜잭션 주의**를 주석으로 명시.

```sql
-- ⚠️ Postgres 제약: 새 enum 값(ADD VALUE)은 "추가한 트랜잭션 안에서는 사용 불가".
--    따라서 STEP 1(스키마 변경)을 먼저 실행·커밋한 뒤, STEP 2(데이터 UPDATE)를 별도로 실행한다.

-- ===== STEP 1: 스키마 (먼저 실행·커밋) =====
-- 1) source_type: opinion_channel → web_insight (무손실 rename)
alter type source_type rename value 'opinion_channel' to 'web_insight';

-- 2) collection_method enum + sources 컬럼
create type collection_method as enum ('rss','api','html','manual','youtube');
alter table public.sources
  add column collection_method collection_method not null default 'rss';

-- 3) content_category 에 '리포트' 추가 (오피니언은 이미 '웹인사이트' 값 존재 → 추가 불필요)
alter type content_category add value if not exists '리포트';

-- (여기서 커밋. 새 enum 값 사용은 다음 단계에서.)

-- ===== STEP 2: 데이터 (STEP 1 커밋 후 별도 실행) =====
-- 4) collection_method 백필
update public.sources set collection_method='youtube' where type='youtube_channel';
update public.sources set collection_method='manual'  where type='report_publisher';
-- news_site / web_insight 는 default 'rss' 유지

-- 5) 카테고리 마이그레이션
update public.contents set category='웹인사이트' where category='오피니언';
update public.contents set category='리포트'     where category in ('가트너','KRG');
-- 뉴스레터 category 콘텐츠: 크롤러는 생성하지 않으므로 거의 없음.
--   있으면 수희·David 확인 후 개별 처리(기본은 그대로 두고 UI 에서만 제외).
```

- enum 값 물리 삭제(오피니언/가트너/KRG/뉴스레터, newsletter source_type)는 **하지 않는다**(논리 폐기). 코드/UI에서만 제외.
- 수희에게: STEP 1 실행→커밋 확인 후 STEP 2 실행. (한 번에 붙여넣으면 enum 오류 가능.)

## B절. 코드 (검증 통과 후 커밋)

### 1. `supabase/schema.sql` (SSOT — AGENTS #6)
- `source_type` enum: `opinion_channel` → `web_insight` 로 갱신(주석도).
- `collection_method` enum + `sources.collection_method` 컬럼 반영.
- `content_category` enum에 `'리포트'` 추가.
- (기존 파일이 단일 생성 스크립트면, 마이그레이션이 아니라 **최종 상태**로 반영.)

### 2. `src/lib/types.ts`
- `SourceType`: `'opinion_channel'` → `'web_insight'`. (`newsletter`, `youtube_channel` 유지)
- `ContentCategory`: `'리포트'` 추가. 기존 `'가트너'|'KRG'|'오피니언'|'뉴스레터'` 는 **DB enum에 남아있으므로 union에 유지**하되 `// deprecated(수집 미사용, 50에서 마이그레이션)` 주석.
- `CONTENT_CATEGORY_LABEL`: `'리포트': '리포트'` 추가(나머지 키는 Record 완전성 위해 유지). `'웹인사이트': '웹 인사이트'` 확인.
- `CollectionMethod` 타입 추가: `'rss'|'api'|'html'|'manual'|'youtube'`. `Source` 인터페이스에 `collection_method: CollectionMethod` 추가.

### 3. `src/lib/categories.ts` — `CATEGORY_DEFS`
- 수집 카드만 일관되게: **가트너·KRG·오피니언·뉴스레터 항목 제거**, `리포트` 추가. 결과 순서:
  `뉴스`, `리포트`(💼 또는 📊), `웹인사이트`, `유튜브`, `AI보고서`(기존 유지).
- ⚠️ 홈/AI분석/전략보고서 카드 풀개편은 **지시서 51**. 이번엔 위 최소 정합만(마이그레이션된 데이터와 카드가 어긋나지 않게).
- `CATEGORY_DEFS` 소비처(`CategoryGrid`, `SearchBar`, search page)는 자동 반영되므로 추가 수정 불필요 — 단 빌드/육안 확인.

### 4. `src/components/admin/SourceManager.tsx`
- `SOURCE_TYPE_LABELS`: `{ news_site:'뉴스', report_publisher:'리포트', web_insight:'웹인사이트', youtube_channel:'유튜브' }`. 기존 행 렌더 안전을 위해 `newsletter:'뉴스레터(미사용)'` 는 **라벨 맵에는 남기되**,
- `SOURCE_TYPES`(추가 폼 드롭다운 + 필터 칩): `['news_site','report_publisher','web_insight','youtube_channel']` — **newsletter 제외**(신규 선택 차단).
- `collection_method` 지원: `SourceRow`/`SourceForm`에 필드 추가, 폼에 Select(rss/api/html/manual/youtube), 목록 테이블에 열 1개 추가, 저장 payload 포함. 기본값은 유형에 맞게(youtube_channel→youtube, report_publisher→manual, 그 외 rss) 폼 초기화.
- `needsRssUrl` 등 기존 로직은 collection_method 기준으로 바꿔도 되나, 과하면 type 기준 유지(보고에 명시).

### 5. `src/lib/crawler/orchestrator.ts`
- `categoryForSourceType()`(L169~171) **파생 방식으로 재작성**:
  ```ts
  function categoryForSourceType(type: SourceType): ContentCategory {
    switch (type) {
      case 'web_insight': return '웹인사이트'
      case 'report_publisher': return '리포트'
      case 'youtube_channel': return '유튜브' // 실제 유튜브는 별도 경로지만 완전성 위해
      default: return '뉴스' // news_site, (legacy)newsletter
    }
  }
  ```
- `sinceForSource()`(L178) 의 `source.type === 'opinion_channel'` → `'web_insight'`.
- `OPINION_LOOKBACK_DAYS` 상수명은 그대로 둬도 무방(웹인사이트 lookback 일반화는 지시서 C). 바꾸면 주석만.

### 6. `src/lib/crawler/adapters/index.ts`
- `getAdapter()` `case 'opinion_channel':` → `case 'web_insight':` (동일 news-site 어댑터 매핑 유지).

### 7. `src/components/admin/ReportUploadForm.tsx` (최소 변경)
- `REPORT_CATEGORIES` → `[{ value:'리포트', label:'리포트' }]` 하나로. `form.category` 기본값 `'리포트'`, 카테고리 Select 는 단일 고정(또는 숨김+고정값).
- **발행처(source) 필수화·자료유형 축은 지시서 51**(여기선 손대지 않음). 기존 출처/저자 필드 그대로.

### 8. 카테고리 색상맵 3곳 (`ContentCard.tsx`, `ContentRow.tsx`, `contents/[id]/page.tsx`)
- `'리포트'` 키 색상 추가(가트너/KRG 팔레트 재사용 — 예: purple 계열). `'웹인사이트'` 키 색상 없으면 추가(오피니언 green 계열 재사용). 기존 legacy 키(가트너/KRG/오피니언/뉴스레터)는 남겨도 무해 — 제거는 선택.

### 9. (선택) mock-data 정리
- `mock-data/{reports,taxonomy,articles}.ts` 의 `'뉴스레터'` 참조는 mock이라 런타임 영향 적음. 시간 남으면 정리, 아니면 생략(보고에 명시).
