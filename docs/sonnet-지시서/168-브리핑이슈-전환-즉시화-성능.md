## 0. 한 줄

## 3. 구현

### 3-1. 전환 경로에서 LLM 제거 (가장 큰 효과)
- `AiInsightsView` 310행: 브리핑도 **`buildRuleBrief` 결과(ruleBrief)를 즉시 렌더**. `await enhanceBriefWithLlm(...)` 를 **동기 렌더 경로에서 제거**.
- LLM 고도화는 후속(범위 밖): 별도 클라이언트 비동기 로드(`/api/insight/brief-enhance` 호출 후 카드 텍스트 교체) 또는 캐시. 168에서는 **규칙 기반 즉시**로 통일 — 전환이 LLM을 절대 기다리지 않게.
- `InsightBriefCard` 는 `source:'rule'` 로 렌더(162 폴백 문구 그대로). 회귀 아님(LLM 미연결 시 기존과 동일).

### 3-2. 탭 전환 클라이언트 토글 (네비게이션 제거)
서버는 **데이터만 1회 패칭**, 뷰 전환은 클라이언트 state.
- `AiInsightsView`(서버)에서 **브리핑·이슈 데이터를 모두** 산출(현재 briefing/issue 조건부 await → 둘 다 패칭). 직렬화 가능 형태로 새 클라이언트 컴포넌트 `AiInsightBoard.tsx` 에 props 전달.
- `AiInsightBoard.tsx`(신규, 클라): `view` 를 **useState** 로 토글. 내부에 기존 브리핑 섹션(InsightBriefCard·InsightCardsSectionClient·뜨는 토픽)·이슈 섹션(IssueBoardClient) 렌더 분기. 탭 전환 = state 변경(네비게이션·재패칭 0).
- `AiInsightTabs` → `<Link>` 대신 **버튼**(onClick=setView). 활성 스타일 유지.
- URL 동기화(공유·새로고침용)는 가볍게: 탭 변경 시 `history.replaceState` 또는 `router.replace(scroll:false)` 로 `?view=` 만 갱신(풀 네비게이션 아님). 초기 `view` 는 서버가 searchParams 로 결정해 props.
- "뜨는 토픽"·키워드 strip 등 **서버 JSX 였던 부분은 데이터를 props 로 받아 클라이언트에서 렌더**(Link 는 next/link 그대로 사용 가능). 직렬화 불가 요소 없게.

### 3-3. 로딩 스켈레톤
- `src/app/dashboard/issues/loading.tsx` 신규 — 탭/카드 골격 스켈레톤(초기 진입·force-dynamic 첫 로드 대비). 전환은 클라이언트라 즉시지만, 최초 로드 체감 개선.

### 3-4. (선택) 데이터량 가드
- 브리핑·이슈 둘 다 초기 패칭하므로, 각 쿼리 `limit` 합리적 유지(현행 유지). 과하면 이슈 활동은 상위 N개만.

## 4. 회귀 가드 / 비기능 요건

- 기능 동일: 브리핑/이슈 내용·범위 필터·카드 구조(164)·색(163·167)·이슈 깊이(166) 모두 유지.
