## 0. 전제 — 491이 깔아둔 것

- `crawl-now`는 이미 `runJob`으로 감싸져 있다(`key: 'admin:crawl-now'`, `rejectIfRunning: true`).
- `AdminTable`에 `selection` props가 있다. 현재 사용처는 `AdminContentManager` **한 곳뿐**.
- 따라서 **새 락도 새 선택 로직도 만들지 않는다.** 있는 것을 연결한다.

---

## A. ⚠️ 선행 수정 — `crawl-now`의 job key를 소스별로 분리

현재 `crawl-now`는 `sourceId` 유무와 무관하게 **`key: 'admin:crawl-now'` 하나**를 쓴다.
여기에 `rejectIfRunning: true`가 걸려 있으므로, **소스 A를 재수집하는 동안 소스 B 버튼이 전부 409로 막힌다.** 소스별 재수집 버튼을 붙이는 순간 이 화면은 쓸 수 없게 된다.

```
key: sourceId ? `admin:crawl-now:${sourceId}` : 'admin:crawl-now'
```

- 전체 수집(=`sourceId` 없음)은 기존 키를 유지한다.
- ⚠️ **전체 수집이 도는 중에도 개별 소스 재수집이 통과하게 된다.** 이건 의도된 트레이드오프다 — 개별 버튼이 서로를 막지 않는 쪽이 운영상 중요하다. 이 판단을 주석으로 남길 것.

## B. `G-10` — `SourceManager` 행에 재수집

`SourceManager`에는 현재 `crawl-now` 참조가 **0건**이다. 관리자는 재수집하려면 `/admin/source-quality`로 나가야 한다.

행마다 다음을 붙인다.

1. **재수집 버튼** — `POST /api/admin/crawl-now { sourceId }`. 새 API 만들지 마라.
2. **최근 수집 시각** — `sources.last_crawled_at`. 이미 `SourceManager`가 select하고 있다.
3. **최근 실패 사유** — 기존 `/api/admin/source-status`(또는 `crawl_logs`)를 재사용한다. **새 집계 API를 만들지 마라.** 조회가 실패하면 `null`로 두고 "확인 실패"로 표시한다(0이나 빈칸으로 위장 금지).
4. **실행 중 상태** — `job_runs`에서 `job_key = 'admin:crawl-now:<id>'` 이면서 `status='running'`인 행을 조회해 버튼을 스피너·비활성으로. **폴링은 5초 이상 간격**으로, 화면을 벗어나면 중단할 것.
5. **완료 결과** — 성공은 토스트(488 규칙), 실패는 `AdminErrorBox` 인라인. 409(이미 실행 중)는 오류가 아니라 안내 문구로 처리한다.

확인창은 필요 없다(파괴적이지 않다). `AdminConfirm`을 붙이지 마라.

## C. `G-15` — 일괄 처리

`AdminTable`의 `selection`을 아래 화면에 연결하고 **선택바**를 붙인다.

| 화면 | 일괄 동작 |
|---|---|
| `SourceManager` | 활성화 / 비활성화 · **선택 소스 재수집** |
| `EntityManager` | 상태 변경 |
| `KeywordGroupManager` | 활성/비활성 |
| `IssueManager` | 상태 변경 |

- 선택바는 `AdminContentManager`의 것을 **공용 컴포넌트로 추출**해 재사용한다. 화면마다 새로 만들지 마라.
- **파괴적 일괄 동작(삭제)은 이번에 넣지 않는다.** 상태 변경·활성 토글·재수집만. 일괄 삭제는 492의 소프트 삭제가 들어간 뒤에 검토한다.
- 일괄 동작에는 `AdminConfirm`을 쓰고 `targets`에 대상 이름을 넣는다.
- 실행 중에는 선택바를 잠근다(`AdminContentManager`의 `isBulkWorking` 패턴).
- ⚠️ **`UserManager`의 일괄 승인은 이번 범위가 아니다.** 현행이 자동 승인이라 대기 큐가 항상 비어 있고, `F-01`(자동 승인 유지 vs 수동 전환) 결정 후에 다시 본다.

## 검증

1. 소스 A 재수집 중에 **소스 B 재수집이 정상 동작**한다(409가 아니다).
2. 같은 소스를 연속 두 번 누르면 두 번째가 **409 안내**로 처리된다(오류 배너가 아니다).
3. 실행 중 버튼이 스피너·비활성이고, 완료 후 토스트가 뜬다.
4. 최근 실패 사유 조회를 강제 실패시키면 **"확인 실패"**로 표시된다(빈칸·0이 아니다).
5. 소스 3개를 선택해 일괄 비활성화하면 확인창에 **대상 이름 3개**가 보이고, 실행 중 선택바가 잠긴다.
6. 페이지·정렬·필터를 바꾸면 선택이 초기화된다(487 `useAdminTable` 동작 유지).
7. 일괄 동작이 `admin_audit_log`에 기록된다.
8. `npm run lint` · `npx tsc --noEmit` · `npm run check:admin-auth` 통과.
