# 지시서 224 — 기업동향 3탭 재구성 + 경쟁사(동향)

목표: 기업동향(L2) 탭을 **관심기업 / 경쟁사(뉴스) / 경쟁사(동향)**으로 재구성한다. **경쟁사(동향)**은 헤드라인분석의 **insight_cards 소스·카드 UI를 그대로 재사용**하되, 기간이 아니라 **`competitor_group`(통신 / 클라우드·플랫폼 / 빅테크)**으로 재그룹핑한다. 기존 **브리핑 탭은 제거**(entity_signal의 AI인사이트 이동은 224B 후속).

David 결정: 그룹 = 통신·클라우드·플랫폼·빅테크(어드민 편집 가능, 추후 변경 가정). 경쟁사(동향) = 헤드라인분석 카드 재배치(새 AI 생성 없음).

범위: `EntityTabs.tsx`·`entities/page.tsx`·`InsightCardsSectionClient.tsx`(라벨 그룹 지원) + 어드민 `EntityManager`(그룹 선택). DB는 `224-경쟁사-competitor-group.sql`(수희). 

---

## 1. 현행 진단 (검증된 코드 사실)
- **기업동향** `entities/page.tsx`: `VALID_VIEWS=['watchlist','competitor','briefing']`.
  - `watchlist`: user_watchlist → `insight_cards`(scope='company') 매칭(`isWatched(topic)`) → `InsightCardsSectionClient`.
  - `competitor`: `entities.is_competitor=true` → 최근 14일 기사(감성분포) 리스트.
  - `briefing`: `entity_signal_summary` → 엔티티 시그널 카드 그리드.
- **헤드라인분석**은 `AiInsightsView`(AI인사이트, `view='headline'`)에서 `insight_cards`(scope='industry')를 `InsightCardsSectionClient`로 렌더 — **경쟁사(동향)이 재사용할 소스·컴포넌트**.
- `InsightCardsSectionClient`는 `InsightGroup{key,start,end,cards}`로 그룹핑, 헤더는 `formatPeriod(start,end)` + 최신/이전 배지. → **라벨 그룹 지원만 추가하면 그룹명 헤더로 재사용 가능.**
- `EntityTabs.tsx`: `InsightViewTabs`에 3항목 전달(watchlist/competitor/briefing).

## 2. 구현

### 2-1. `InsightCardsSectionClient.tsx` — 라벨 그룹 지원(최소 확장)
- `InsightGroup`에 옵셔널 필드 추가: `label?: string`(있으면 기간 대신 이 라벨을 섹션 헤더로).
- 헤더 렌더(228~244행 영역): `label ? <span>{label}</span> : formatPeriod(start,end)`. `label` 있을 때는 **최신/이전 배지·opacity 처리 생략**(그룹은 시간축이 아님), 대신 그룹 카드 수 `{displayedCards.length}건` 표시(선택).
- 나머지 카드 렌더·렌즈·뷰토글 로직 **불변**. `start/end`는 label 그룹에서 빈 문자열 허용.

### 2-2. `entities/page.tsx` — 뷰 재구성
- `VALID_VIEWS = ['watchlist','competitor','trend'] as const` (**'briefing' 제거, 'trend' 추가**).
- **watchlist**: 기존 로직 그대로.
- **competitor**(=경쟁사(뉴스)): 기존 경쟁사 로직 그대로(라벨만 탭에서 "경쟁사(뉴스)").
- **briefing 블록 삭제**(entity_signal_summary 관련 fetch·렌더 제거). ※ entity_signal의 AI인사이트 이동은 224B.
- **trend**(=경쟁사(동향)) 신규:
  1. `insight_cards` 조회: `status='published'` AND `scope in ('industry','company')`, `order period_start desc, generated_at desc`, limit 80.
  2. 경쟁사 매핑 소스: `entities`에서 `competitor_group is not null`(또는 `is_competitor=true`) 행 + `entity_aliases` 조회 → **이름/별칭(lower) → competitor_group** 맵 구성.
  3. 각 카드의 `topic`(lower)이 맵의 이름/별칭과 일치(정확/부분 포함)하면 해당 `competitor_group`에 버킷팅. (다중 매칭 시 첫 그룹.) 매칭 없는 카드는 제외.
  4. 그룹 순서 고정: **통신 → 클라우드·플랫폼 → 빅테크**(맵에 없는 그룹명은 뒤에). 각 그룹을 `InsightGroup{key:group, start:'', end:'', label:group, cards}`로.
  5. `contentMap`·`card_headline` 보강·`bucketByTopic`은 watchlist/headline과 동일 방식 재사용(근거·키워드 렌더 위해).
  6. 렌더: `<InsightCardsSectionClient groups={trendGroups} contentMap={...} bucketByTopic={...} />`.
  - 빈 상태: "경쟁사 동향 인사이트가 아직 없습니다."(경쟁사 미등록/매칭 카드 없음 구분 메시지).

### 2-3. `EntityTabs.tsx` — 3탭
```ts
const TABS = [
  { id: 'watchlist',  label: '관심기업',     href: '/dashboard/entities?view=watchlist' },
  { id: 'competitor', label: '경쟁사(뉴스)', href: '/dashboard/entities?view=competitor' },
  { id: 'trend',      label: '경쟁사(동향)', href: '/dashboard/entities?view=trend' },
]
```
- 활성 판정 `view` 기존 방식. 폭·스타일(233/235)·컴포넌트 그대로.

### 2-4. 어드민 `EntityManager` — competitor_group 편집
- 엔티티 편집 행/모달에 **`competitor_group` 선택**(빈값/통신/클라우드·플랫폼/빅테크; 자유 텍스트 허용해 후속 확장). 저장 시 `entities.competitor_group` upsert.
- `is_competitor`와 독립이나, 그룹 지정 시 `is_competitor=true` 자동 체크 권장(경쟁사 동향 노출 일관).

## 3. 회귀 가드
- watchlist·competitor(뉴스) 동작·데이터 **불변**(라벨만 변경).
- `InsightCardsSectionClient`는 `label` 옵셔널 → **기존 호출부(기간 그룹) 영향 없음**(label 미전달 시 기존 formatPeriod 경로).
- briefing 제거로 `entity_signal_summary` 조회 사라짐 → 그 데이터는 224B에서 AI인사이트로. (※ David 확인: 임시로 UI 비노출 허용?)
- trend 매칭은 대소문자·부분 포함이라 오매칭 주의 — 짧은 별칭(예: 'KT') 부분포함 오탐 가능 → **정확일치 우선, 부분포함은 길이 3+ 별칭만** 적용 권장.
- 링크·상세 라우팅(223) 불변.
