## 배경 (David)

전략보고서 = IA 종착점. 114(뷰어+샘플)에 이어 **2단계 = 생성 워크벤치.** 단 무료 LLM이 약하므로 **"생성기"가 아니라 "조립기"**: 이슈/콘텐츠를 고르면 **기존 데이터로 구조 초안을 자동 조립**하고, 판단 섹션(시사점·대응)만 사람/Claude가 채운다. → LLM 없이도 즉시 쓸 만한 초안.

## 설계 결정 (Opus)

1. **조립기(LLM-light)**: 선택 이슈/콘텐츠 → 서버가 DB에서 사실(이슈 요약·관련 콘텐츠·논조·엔티티)을 끌어와 **markdown 골격**을 만들고 `ai_reports`(status='draft')로 저장. 판단 섹션은 placeholder(`> 작성 필요`).
2. **편집**: 보고서 상세에 `body_md` 편집(textarea) + 저장. (Claude/사용자가 placeholder 채움. 추후 "AI로 다듬기"는 옵션.)
3. **per-user**: 본인 user_id 로 생성(RLS). 근거 콘텐츠 = ai_report_sources.

## 작업

### A. 초안 조립 — `src/app/api/reports/generate/route.ts` (신규, POST)
- 세션 사용자 확인(로그인). body: `{ type: AiReportType, title?: string, issueIds?: string[], contentIds?: string[] }`(최소 1개 소스).
- 서버 조립(authed supabase, RLS 내 조회):
  - **선택 이슈별**: `issues`(title·summary) + `issue_contents`→`contents`(category·sentiment) 집계(관련 N건·카테고리 분포·논조 긍/중/부) + 상위 엔티티(issue 콘텐츠의 content_entities→entities 빈도 top 5).
  - **선택 콘텐츠**: title·요약·논조.
  - **근거 content_id 집합** = 선택 콘텐츠 + 이슈 콘텐츠 상위 일부.
- `body_md` 템플릿 조립:
  ```
  # {title 또는 자동: "<유형> 보고서 — <오늘>"}
  ## 1. 개요
  대상: <선택 이슈/콘텐츠 요약 한 줄>
  ## 2. 이슈별 동향
  ### <이슈.title>
  <이슈.summary>
  - 관련 콘텐츠 N건(뉴스 x·리서치 y·웹인사이트 z)
  - 논조: 긍 a / 중 b / 부 c
  - 관련 엔티티: e1, e2, e3
  (이슈 반복)
  ## 3. 시사점 (LG U+ 관점)
  > 작성 필요 — 위 동향에서 사업 시사점 1~3개
  ## 4. 기회 / 리스크
  > 작성 필요
  ## 5. 대응 방향
  > 작성 필요
  ## 근거 콘텐츠
  (선택/이슈 콘텐츠 제목 목록)
  ```
- `ai_reports` insert(user_id, type, status='draft', title, prompt=요청 요약, body_md) → returning id. `ai_report_sources` insert(근거 content_id들, on conflict do nothing).
- 반환 `{ id }`. 환각 방지: 사실은 DB 값만(추론 금지), 판단은 placeholder.

### B. 워크벤치 UI — `src/app/dashboard/reports/new/page.tsx` (신규, client)
- 단계: ① 유형 선택(ai_report_type 5종 셀렉트) ② **이슈 다중 선택**(`issues` published 목록 체크) + (선택) **콘텐츠 검색·선택**(title ilike) ③ 제목(선택, 비우면 자동) ④ "초안 생성" → `POST /api/reports/generate` → 성공 시 `/dashboard/reports/{id}` 이동.
- 소스 0이면 버튼 비활성. 로딩·에러 한국어.
- query param `?issue={id}` 또는 `?topic=` 있으면 해당 이슈 사전 선택(보고서로 만들기 연계).

### C. 보고서 편집 — `src/app/dashboard/reports/[id]/page.tsx` (114) 보강
- 본인 보고서면 **"편집" 토글** → `body_md` textarea(큰 영역) + 제목·상태(draft/completed) + 저장(`ai_reports.update`, RLS 본인). 저장 후 마크다운 렌더로 복귀.
- (선택, 후속) "AI로 다듬기" 버튼 = gateway LLM best-effort(키 없으면 비활성).

### D. 진입점 연결 — `src/components/analysis/AiInsightsView.tsx`
- "보고서로 만들기"(111/113) 링크 → `/dashboard/reports/new`(가능하면 해당 인사이트/이슈 사전선택 `?issue=` 또는 `?topic=`). 경쟁사 "배틀카드"도 `/dashboard/reports/new?type=경쟁사분석&...`로(선택).
- 보고서 목록(114)에 **"새 보고서" 버튼** → `/dashboard/reports/new`.

## 회귀 / 주의
- **신규 SQL 없음**(ai_reports/sources 기존). per-user RLS — 본인 생성/편집만.
- **LLM 미사용**(조립만) — 키 부족 무관. "AI로 다듬기"는 옵션(graceful).
- 환각 방지: 사실 섹션은 DB 값만, 판단은 명시적 placeholder(§12).
- 이슈/콘텐츠 없으면 워크벤치 빈 안내(이슈 시드 후 풍부).
- body_md textarea 편집은 단순(리치 에디터 후속). 저장 시 trim·길이 상한 고려.
- UI 한국어(#1)·색 토큰(#9)·`any` 금지. 조립은 서버, 선택 UI는 client.
