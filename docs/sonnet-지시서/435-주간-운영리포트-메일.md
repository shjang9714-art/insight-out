## 2. 구현

### 2.1 `src/lib/ops/weekly-report.ts` (신규)
일일과 같은 스타일(단일 파일, `Promise.all` 병렬 집계, HTML 빌더 동봉). 창(window)은 **롤링 7일**.

```ts
import type { SupabaseClient } from '@supabase/supabase-js'

export interface WeeklyReport {
  periodStart: string   // 7일 전 00:00 KST 기준 ISO
  periodEnd: string     // now ISO
  collection: {
    total: number; published: number; rejected: number
    dailyAvg: number            // total / 7 반올림
    prevTotal: number           // 직전 7일 수집(전주)
    deltaPct: number            // (total-prevTotal)/prevTotal*100 반올림, prev 0이면 null 취급→0
    topSourceShare: number      // 최근 7일 최고 매체 비중 %
  }
  system: {
    crawlFailed: number; crawlPartial: number; failedJobs: number
    backlog: number             // 현재 본문 보강 대기(스냅샷)
  }
  issues: {
    openedThisWeek: number      // first_seen_at >= periodStart
    resolvedThisWeek: number    // resolved_at >= periodStart
    stillOpen: number           // status in (open,acknowledged,in_progress)
    topOpen: { title: string; severity: 'critical'|'warning'|'notice'; occurrence_count: number; recommended_action: string | null }[] // 최대 5
  }
  users: { total: number; newThisWeek: number; pending: number; inactive7d: number }
  usage: { llm: { provider: string; used: number; limit: number; percent: number }[] } // 월 누적(일일과 동일 계산 재사용 가능)
}

export async function gatherWeeklyReport(admin: SupabaseClient): Promise<WeeklyReport>
export function buildWeeklyReportHtml(r: WeeklyReport): string
```

구현 지침:
- `weekStart` = `new Date(Date.now() - 7*86400000)`(자정 정렬은 선택, 롤링이면 그대로), `prevStart` = `-14d`, `prevEnd` = `weekStart`.
- **수집 7일 합계**: `contents` `collected_at >= weekStart` count(총/게시/거절). **전주**: `collected_at >= prevStart AND < weekStart` count → `deltaPct`.
- **일평균** = `Math.round(total/7)`.
- **crawl_logs** 7일 `status='failed'|'partial'` count, **job_runs** 7일 `status != 'success'` count — 일일의 쿼리에서 `gte(start)` 를 `weekStart` 로 바꾼 것.
- **backlog·topSourceshare·llm usage**: 일일의 로직 재사용(backlog·usage 는 스냅샷/월누적이라 동일). 중복 구현 대신 **필요하면 daily-brief 의 계산 헬퍼를 export 해 공유**(과한 리팩터는 지양 — 쿼리 몇 줄 복제 허용).
- **이슈 처리 현황(핵심 주간 가치)**: `ops_issues` 에서
  - `openedThisWeek` = `first_seen_at >= weekStart` count
  - `resolvedThisWeek` = `resolved_at >= weekStart` count
  - `stillOpen` = `status in ('open','acknowledged','in_progress')` count
  - `topOpen` = 위 미해결 중 severity·last_seen_at 정렬 상위 5(title·severity·occurrence_count·recommended_action).
- `buildWeeklyReportHtml`: 428 HTML 톤 그대로. 섹션 = ①이번 주 한눈에(수집 total·일평균·전주대비 ▲/▼deltaPct) ②이슈 처리(신규 N·해결 N·미해결 N + topOpen 목록) ③시스템(실패 합계·backlog) ④사용자(신규 이번 주·승인 대기·미접속) ⑤AI·외부 사용량 ⑥하단 어드민 링크. `esc()` 재사용(daily-brief 에서 export 하거나 동일 함수 복제).

### 2.2 `src/app/api/cron/ops-weekly/route.ts` (신규)
`ops-brief/route.ts` 복제 후 교체:
```ts
import { gatherWeeklyReport, buildWeeklyReportHtml } from '@/lib/ops/weekly-report'
// ... 동일 인증 + runJob
const result = await runJob(admin, { key: 'cron:ops-weekly', trigger: 'cron' }, async () => {
  const report = await gatherWeeklyReport(admin)          // detectOpsIssues 호출하지 않음
  const override = (process.env.OPS_BRIEF_RECIPIENTS ?? '').split(',').map(v=>v.trim()).filter(Boolean)
  let recipients = override
  if (!recipients.length) {
    const { data, error } = await admin.from('users').select('email').eq('role','admin').not('email','is',null)
    if (error) throw error
    recipients = (data ?? []).map(r=>r.email).filter(Boolean)
  }
  if (!recipients.length) return { ok:true, skipped:true, reason:'수신 관리자 없음' }
  const fmt = (s:string)=> new Date(s).toLocaleDateString('ko-KR',{timeZone:'Asia/Seoul',month:'long',day:'numeric'})
  const subject = `[인사이트 아웃 주간 운영 리포트] ${fmt(report.periodStart)}~${fmt(report.periodEnd)} · 미해결 ${report.issues.stillOpen}`
  const messageId = await sendBrevoEmail({ to: recipients, subject, html: buildWeeklyReportHtml(report) })
  return { ok:true, sent: recipients.length, messageId, subject, stillOpen: report.issues.stillOpen }
})
```
- `runtime='nodejs'`·`dynamic='force-dynamic'`·`maxDuration=60` 동일. 수신자는 **일일과 동일 정책**(`OPS_BRIEF_RECIPIENTS` 재사용 — 별도 env 만들지 말 것).

### 2.3 `vercel.json` — 크론 추가
`crons` 배열에 추가(월요일 08:00 KST = 일요일 23:00 UTC):
```json
{ "path": "/api/cron/ops-weekly", "schedule": "0 23 * * 0" }
```
- 일일 ops-brief(08:00 KST)와 요일만 겹치므로 무해. Vercel 요일 크론은 배포시 고정 — competitor-weekly 식 "매시+게이트" 불필요(주간은 고정 스케줄로 충분).

### 2.4 `src/lib/jobs/expected-crons.ts` — CRON_META 추가 (필수·빌드가드)
```ts
// 주간(168h 주기) — 여유 두어 200h
'cron:ops-weekly':          { label: '주간 운영 리포트',  maxAgeHours: 200 },
```
- ⚠️ **maxAgeHours 는 반드시 168 초과**(주간 주기). 안 그러면 정상인데도 "지연" 오탐. 200 권장.
- 이 항목을 빼면 `vercel.json` 에 크론 추가 시 `expected-crons.ts` 가 **기동 즉시 throw** — 반드시 함께 커밋.

- **전주 0 division**: `prevTotal===0` 이면 `deltaPct=0`(또는 '신규'), NaN/Infinity 금지.
