## 0. 한 줄

## 1. 현행 진단 (확인된 코드 사실)

**(a) 카운트는 이미 존재한다 — export만 안 돼 있다.** 아래 5개 모듈 모두 동일 이름의 비공개 헬퍼를 갖는다:

| 모듈 | 함수 | 미처리 판정 조건 |
|---|---|---|
| `src/lib/contents/enrich-body.ts` | `pendingCount()` (162행) | `body_fetched_at is null` + `original_url not null` |
| `src/lib/contents/thumbnail-backfill.ts` | `pendingCount()` (36행) | `thumbnail_url is null` + `original_url not null` + mode별 `thumbnail_fetched_at` |
| `src/lib/contents/pdf-cover-backfill.ts` | `pendingCount(admin, mode)` (36행) | `thumbnail_url is null` + `file_path not null` |
| `src/lib/crawler/cluster-backfill.ts` | `pendingCount()` (62행) | `category='뉴스'` + `cluster_checked_at is null` + `body_fetched_at not null` |
| `src/lib/contents/youtube-transcript-backfill.ts` | `pendingCount(admin, mode)` (45행) | (모듈 내 조건) |

- 이 조건들은 **같은 파일의 `drain*` 함수와 동일**하다(예: `enrich-body.ts` 카운트 169행 ↔ `drainBackfill` 195행). → **별도 집계 쿼리를 새로 짜면 안 된다.** 백필 로직과 갈라져 거짓 숫자가 된다.
- 각 모듈 export 현황: `drain*`만 export. `pendingCount`는 **비공개**.

**(b) `remaining` 계약이 이미 있다.** `EnrichJobResult`(`src/lib/admin/enrich-jobs.ts`)에 `remaining: number | null` 필드가 있고 백필이 채워 반환한다. 다만 **실행해야만** 볼 수 있다 — 실행 전 조회 경로가 없다.

**(c) `translate-backfill`은 고아다.** `src/app/api/admin/translate-backfill/route.ts` 안에서만 등장하고 호출처 0 — `ENRICH_JOBS` 레지스트리(키 14개)에 없고, 크론에도 없고, UI 버튼도 없다. 번역 누락이 쌓여도 채울 경로가 없다. (라우트 내부 조건: `category='유튜브'` + `original_language='en'` + `body_translated_ko is null`)

**(d) 화면 구조.** `/admin/enrich/page.tsx` → `getEnrichJobs('data')` 로 잡 목록을 뽑아 `<AdminContentProcessing jobs={DATA_JOBS} />` 에 넘긴다. 레지스트리는 `key·label·endpoint·usesLlm·surface·kind·method·limit·modes…` 를 갖는다.

**(e) 가시성 공백.** `AdminContentHealth` 는 **태깅 누락만** 표시한다(154행). 다른 백필의 밀린 양은 어디에도 안 보인다.

## 3. 구현

### 3.1 `pendingCount` 5개를 export 로 공개 (조건은 손대지 않는다)
아래 5개 파일에서 `async function pendingCount(` → **`export async function pendingCount(`** 로만 변경. **쿼리 조건·시그니처·본문은 절대 수정 금지.**
- `src/lib/contents/enrich-body.ts`
- `src/lib/contents/thumbnail-backfill.ts`
- `src/lib/contents/pdf-cover-backfill.ts`
- `src/lib/crawler/cluster-backfill.ts`
- `src/lib/contents/youtube-transcript-backfill.ts`

### 3.2 신규 `src/app/api/admin/backfill-status/route.ts` — 실행 없이 건수만
- `verifyAdmin()` 은 **기존 백필 라우트(예: `body-backfill/route.ts`)의 것을 그대로 복제**해 동일 인증을 적용한다(401/403 문구 동일).
- `export const runtime = 'nodejs'`, `export const dynamic = 'force-dynamic'`. `maxDuration` 은 불필요(카운트만).
- 5개 `pendingCount` 를 **별칭 import** 후 `Promise.allSettled` 로 병렬 호출. 실패한 항목은 `null` 로 두고 나머지는 정상 반환(하나가 죽어도 화면 전체가 죽지 않게).
```ts
import { pendingCount as pendingBody } from '@/lib/contents/enrich-body'
import { pendingCount as pendingThumbnail } from '@/lib/contents/thumbnail-backfill'
import { pendingCount as pendingPdfCover } from '@/lib/contents/pdf-cover-backfill'
import { pendingCount as pendingCluster } from '@/lib/crawler/cluster-backfill'
import { pendingCount as pendingYoutubeTranscript } from '@/lib/contents/youtube-transcript-backfill'
```
- `mode` 인자를 받는 함수는 **`'fresh'`** 로 호출한다(화면 기본 동작과 일치).
- 응답: `{ counts: { 'admin:body-backfill': 123, 'admin:thumbnail-backfill': 0, ... } }` — **키는 `EnrichJobKey` 와 정확히 일치**시킨다(UI 매칭용). 실패 항목은 값 `null`.

### 3.3 `src/lib/admin/enrich-jobs.ts` — translate 등록 (고아 해소)
- `EnrichJobKey` 유니온에 `| 'admin:translate-backfill'` 추가.
- `ENRICH_JOBS` 에 항목 추가(다른 data 잡과 동일 형태):
```ts
{
  key: 'admin:translate-backfill',
  label: '유튜브 영문 본문 번역',
  endpoint: '/api/admin/translate-backfill',
  usesLlm: false,
  surface: 'data',
  kind: 'loop',
  method: 'POST',
  limit: 20,
},
```
> `usesLlm`·`kind`·`limit` 은 라우트 실제 동작(`?limit=20`, 반복 처리)에 맞춘 값이다. 라우트는 **수정하지 않는다.**

### 3.4 `src/components/admin/AdminContentProcessing.tsx` — 건수 배지
- 마운트 시 `GET /api/admin/backfill-status` 1회 호출(비차단 — 실패해도 실행 버튼은 정상 동작해야 한다).
- 각 잡 행에 해당 `counts[job.key]` 를 **"미처리 N건"** 으로 표시. 값이 `null`/`undefined` 면 배지를 **숨긴다**(0으로 표시하지 말 것 — "모름"과 "없음"은 다르다).
- `0` 이면 "미처리 없음" 으로 표시(회색), `>0` 이면 강조(`text-amber-600` 계열 등 기존 토큰 사용).
- 잡 실행이 끝나면 응답의 `remaining` 으로 해당 배지를 **갱신**한다(이미 반환되는 값이라 추가 요청 불필요).

## 4. 회귀 가드
1. **`pendingCount` 의 쿼리 조건·시그니처를 바꾸지 말 것.** `export` 키워드만 붙인다. 조건이 바뀌면 실제 백필 동작이 바뀐다.
2. **`drain*` 함수·백필 라우트 로직 무변경.** `translate-backfill/route.ts` 도 손대지 않는다(레지스트리 등록만).
3. **건수 조회 실패가 화면을 막으면 안 된다.** `backfill-status` 가 500이어도 잡 목록·실행 버튼은 그대로 동작해야 한다.
4. 카운트 응답 키는 `EnrichJobKey` 문자열과 **정확히 일치**해야 한다(오타 시 배지가 조용히 안 뜬다).
5. `AdminContentHealth`(태깅 누락)는 **건드리지 않는다** — 별개 지표.
6. 이번 슬라이스는 **카운트가 이미 있는 5개 + translate 등록**까지다. 카운트가 없는 잡(sentiment·lgu-impact·youtube-summary·youtube-tagging·summary·canonical·signals)은 **후속**(§6).
7. `getEnrichJobs('data')` 결과에 translate 가 새로 들어오므로, **AI 화면(`surface:'ai'`)에는 나타나지 않아야** 한다(`surface: 'data'` 확인).

## 6. 후속 (범위 밖)
- 카운트가 없는 잡에 `pendingCount` 추가: `sentiment`·`lgu-impact`·`youtube-summary`·`youtube-tagging`·`summary`·`canonical`·`signals`. **반드시 각 백필의 선별 조건과 같은 파일에 붙여** 갈라지지 않게 할 것.
- 수동 의존 백필(canonical·thumbnail·pdf-cover·cluster·translate) 중 자동화할 것 선별 → 크론 추가. 단 **크론 3종 세트**(vercel.json + `CRON_META` + 수동 실행 버튼)를 반드시 함께.
- 최종안 `통계분석 > 수집 분석` 구축 시 이 건수를 추이 그래프로 승격.
