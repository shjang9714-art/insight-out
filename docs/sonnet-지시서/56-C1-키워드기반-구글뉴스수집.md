## 배경 / 목표
현재 수집은 **소스 중심**(등록된 RSS 피드만 통째로 당겨와 거름). 등록 안 한 매체의 관련 기사는 못 잡음. **키워드(검색) 중심 수집**을 추가: keyword_groups 의 `search_seeds` 로 **Google News RSS 검색**을 질의해 관련 기사를 능동 수집하고, **기존 파이프라인(중복제거·품질·게이트·태깅)에 그대로 태운다**.

핵심: 새 수집 경로지만 **아이템 처리 로직은 재사용**(중복 코드 금지). dedup/게이트가 RSS 소스와의 중복·노이즈를 자동 처리.

## A절. SQL 핸드오프 (`docs/sql-handoff/56-search-seeds.sql`) — 먼저 커밋·푸시
```sql
-- keyword_groups 에 검색 시드 추가 (Google News 질의어)
alter table public.keyword_groups
  add column search_seeds text[] not null default '{}';

-- (선택) 일부 그룹 시드 예시 — 운영하며 어드민/SQL 로 확장
update public.keyword_groups set search_seeds = array['AICC','AI 컨택센터','콜센터 AI'] where kind = 'aicc';
update public.keyword_groups set search_seeds = array['AI 데이터센터','GPU 클라우드','코로케이션'] where kind = 'aidc';
update public.keyword_groups set search_seeds = array['Private 5G','5G 특화망','네트워크 슬라이싱'] where kind = 'telecom_b2b';
update public.keyword_groups set search_seeds = array['스마트팩토리','산업 AI','OT 보안'] where kind = 'manufacturing_dx';
update public.keyword_groups set search_seeds = array['피지컬 AI','휴머노이드 로봇'] where kind = 'physical_ai';
```
- search_seeds 가 빈 그룹은 키워드 검색 대상 아님(= 기능 off 단위). 운영하며 채움.

## B절. 코드 (검증 통과 후 커밋)

### 1. 아이템 처리 로직 추출 (리팩토링, 동작 불변)
- `crawlOne` 의 **for-루프 본문(아이템 1건 처리: dedup→품질/EXCLUDE→near-dup cluster→게이트/importance→번역→insert→tagContent→counts 갱신)** 을 함수로 추출:
  ```ts
  interface ItemSourceCtx { id: string | null; type: SourceType; trust_tier: number }
  async function processCrawlItem(
    admin: SupabaseClient, item: <RawItem>, src: ItemSourceCtx,
    keywords: CrawlKeyword[], groups: ScoringGroup[],
    translationBudget: TranslationBudget, counts: CrawlCounts
  ): Promise<{ partial?: boolean; errorMessage?: string }>
  ```
  - `row.source_id = src.id`(null 허용), `category = categoryForSourceType(src.type)`, `exempt = src.trust_tier >= 2 || groups.length === 0`. 나머지 로직·집계 **그대로**.
  - `crawlOne` 은 이 함수를 호출하도록 교체(동작 동일해야 함 — 회귀 주의).

### 2. 키워드 검색 수집 함수 `crawlKeywordSearch`
```ts
const KEYWORD_LOOKBACK_DAYS = 2
const MAX_SEARCH_SEEDS = 30
const GOOGLE_NEWS_RSS = (q: string) =>
  `https://news.google.com/rss/search?q=${encodeURIComponent(q)}&hl=ko&gl=KR&ceid=KR:ko`
```
- 입력: admin, keywords, groups(ScoringGroup), translationBudget.
- 활성 keyword_groups 중 `search_seeds` 비지 않은 것들의 **시드 합집합**(중복 제거) → 최대 `MAX_SEARCH_SEEDS` 개로 제한.
- since = `getDaysAgoStartKst(KEYWORD_LOOKBACK_DAYS)`.
- 각 시드:
  - news-site 어댑터 재사용해 RSS 파싱: `getAdapter('news_site')!.fetch({ ...syntheticSource, rss_url: GOOGLE_NEWS_RSS(seed) }, since)`.
    (syntheticSource: 어댑터가 요구하는 최소 필드만. rss_url 만 실제 의미.)
  - 받은 각 item → `processCrawlItem(admin, item, { id: null, type: 'news_site', trust_tier: 1 }, keywords, groups, translationBudget, counts)`.
  - **시드 간 dedup 은 기존 URL/제목/본문 해시가 자동 처리**(같은 기사 여러 시드에 잡혀도 1건).
- 시드별 try/catch(1개 실패가 전체 안 막음), 지수백오프는 어댑터/withRetry 재사용.
- 결과를 CrawlSummary details 에 `source:'Google News 키워드'` 로 1줄 합산(별도 source 행 없음).

### 3. `runCrawl` 통합
- 기존 소스 수집(`Promise.allSettled(dueSources…)`) **뒤에** `crawlKeywordSearch` 1회 실행(force/일반 모두). 활성 그룹에 search_seeds 가 하나도 없으면 skip(no-op).
- 전체 합계(fetched/inserted/duplicate/held/rejected)에 키워드 검색 결과 합산.
- 개별 소스 수집(Part1 §1-2의 sourceId 단일 수집, 지시서 53)일 때는 키워드 검색 **skip**(특정 소스만 돌리는 의도이므로).

### 4. (선택·소폭) 출처 표시 라벨
- 대시보드/어드민에서 `source_id` 가 null 인 콘텐츠는 출처가 '—' 로 보임 → "Google News 검색" 으로 라벨 표기(콘텐츠 카드/행/상세에서 source 없을 때 fallback). 과하면 생략(보고에 명시).

## 회귀 / 주의
- **리팩토링 동작 불변**: crawlOne 이 processCrawlItem 사용 후에도 기존 수집/게이트/태깅/집계 결과가 동일해야 함(가장 중요한 회귀 포인트).
- Google News RSS 의 링크는 **google 리다이렉트 URL**(원문 직링크 아님) → original_url 에 그대로 저장. URL 기준 교차중복은 RSS 소스와 못 잡지만 **제목/본문 해시 dedup 이 잡음**. (canonical_url 해석은 후속 과제.)
- 본문은 스니펫 수준(기존과 동일) → 게이트는 제목+스니펫으로 동작. 정상.
- 게이트 적용됨(trust_tier=1, 비면제) → 검색 결과 중 관련도 낮은 건 pending. 검색이 이미 키워드 타겟이라 대부분 통과 예상.
- 볼륨: 시드 30 × 쿼리당 수십 건이라 dedup/게이트 후에도 양이 늘 수 있음 → 첫 수집 후 보류/적재량 점검(검증).
- 크롤러 외(번역·dedup 헬퍼) 무변경.
