## 2. 구현

### 2.1 집계 라이브러리 `src/lib/admin/analytics.ts` (신규)
서버 전용. 두 gather 함수 + 타입.

```ts
import type { SupabaseClient } from '@supabase/supabase-js'

// ── 콘텐츠 분석 ──
export interface ContentAnalytics {
  windowDays: number
  daily: { date: string; count: number }[]              // 일별 수집량
  byCategory: { category: string; count: number }[]
  byStatus: { status: string; count: number }[]         // published/pending/rejected
  topSources: { name: string; count: number }[]         // 상위 10
  topBookmarked: { id: string; title: string; bookmark_count: number }[] // 상위 10
  totalInWindow: number
  truncated: boolean                                    // 표본 상한 초과 시
}
export async function gatherContentAnalytics(admin: SupabaseClient, windowDays: number): Promise<ContentAnalytics>

// ── AI 사용량·비용 ──
export interface AiCostAnalytics {
  months: string[]                                      // 최근 N개월 'YYYY-MM'
  llmByMonth: { period: string; provider: string; tokens: number }[]
  currentUsage: { provider: string; used: number; limit: number; percent: number }[] // 이번달 한도대비
  translationByMonth: { period: string; chars: number }[]
  ttsByMonth: { period: string; chars: number }[]
}
export async function gatherAiCostAnalytics(admin: SupabaseClient, months: number): Promise<AiCostAnalytics>
```

구현 지침:
- **daily**: `contents.select('collected_at').gte('collected_at', windowStart).limit(50000)` → JS에서 날짜(KST) 버킷팅. 50000 초과면 `truncated=true`(상한 표기, 침묵 금지). 기간 옵션 7/30/90, 기본 30.
- **byCategory / byStatus**: 기간 내 카테고리·status별 — 카테고리 목록(위 5종)마다 `count:'exact', head:true` 병렬, 또는 daily용 select에 `category,status` 포함해 JS 집계(쿼리 수 절약, 권장).
- **topSources**: `contents.select('source_id, sources(name)').gte(windowStart).not('source_id','is',null).limit(20000)` → 소스별 카운트 상위 10(대시보드 30일 분포 로직 복제).
- **topBookmarked**: `contents.select('id, title, bookmark_count').gt('bookmark_count', 0).order('bookmark_count', {ascending:false}).limit(10)`.
- **AI**: 최근 N(기본 6)개월 period 문자열 생성 → `llm_usage.select('provider, tokens, period').in('period', months)`; provider×month 합산. `currentUsage` = 이번달 provider별 tokens vs `llm_settings.monthly_token_limit`(×키수는 대시보드/일일브리핑의 `getProviderKeyCount` 재사용 가능하면 재사용, 아니면 단순 limit). translation/tts 동일하게 월별 chars.
- ⚠️ 조회수·클릭 등 **이벤트 기반 지표는 넣지 않는다**(인프라 없음). 북마크(bookmark_count)만 성과 지표로.
