## 설계 결정 (Opus, David 승인)

1. **이슈 = Claude가 큐레이션한 상위 주제** = `issues`(title·summary·match_keywords). **판단(어떤 이슈가 있는가·매칭규칙·서사)은 Claude 루틴**(고품질, 주기적, 무료 티어 미사용), **반복 매칭(신규 콘텐츠 자동 배정)은 앱**(무료). keyword_groups 가 패턴→자동매칭 하는 방식과 동일 구조.

## 작업

### A. (선행) SQL — `docs/sql-handoff/101-issues.sql` (수희 선적용·먼저 푸시)
- issue_status enum + issues + issue_contents + 인덱스 + RLS(인증 published 조회·admin 전체). `supabase/schema.sql` SSOT 반영(#6). 시드 없음.

### B. 타입 — `src/lib/types.ts`
- `IssueStatus = 'draft'|'published'|'archived'`.
- `Issue { id; title; summary: string|null; status: IssueStatus; match_keywords: string[]; source: string; created_at; updated_at }`.
- `IssueContent { id; issue_id; content_id; source: string; created_at }`.

### C. 자동배정(룰) — `src/lib/crawler/orchestrator.ts` + `src/lib/crawler/quality.ts`
- `quality.ts` 에 헬퍼 `matchIssues(title, body, issues): string[]`(매칭된 issue_id 배열) — `matchKeywordGroups` 미러: `text = (title+' '+body).toLowerCase()`, 각 이슈의 `match_keywords` 중 하나라도 `text.includes(kw.toLowerCase())` 면 그 issue.id.
- 크롤 시작부: `issues` published 조회 → `IssueMatch[] = {id, match_keywords}[]`(빈/실패 시 링킹 skip, try/catch). groups/aliasMap 로드 인근.
- processCrawlItem post-insert(content_entities upsert 인근, 같은 `if (newId)` 블록): `matchIssues(item.title, item.body ?? '', issueList)` → issue_id 집합 → `issue_contents` upsert `{ issue_id, content_id: newId, source: 'rule' }` onConflict `issue_id,content_id` ignoreDuplicates. **try/catch 격리**. 빈 집합 skip.
- 시그니처 전파(다른 링킹들과 동일하게 issueList 인자 추가).

### D. 이슈 보드 — `src/app/dashboard/issues/page.tsx` (신규, 서버)
- metadata("이슈 | Insight Out"). 헤더(아이콘 `Radar`/`Flame` 적절히, "이슈").
- 데이터: `issues` published 조회 + 각 이슈 활동 집계. 효율 위해:
  - 최근 14일 `issue_contents` join `contents`(collected_at·sentiment·category) 바운디드 조회 → JS 집계: 이슈별 **최근 7일 건수**, **직전 7일 대비 급상승**(91 computeTrendingTopics 방식), **논조 분포(긍/중/부)**, 총 콘텐츠 수.
- 카드 그리드: 이슈명 + summary(있으면 1~2줄) + 최근 건수·▲급상승 배지(91 스타일)·논조 미니 분포. 카드 클릭 → `/dashboard/issues/{id}`.
- 빈 상태("아직 등록된 이슈가 없습니다"). 정렬: 급상승→최근건수.

### E. 이슈 상세 — `src/app/dashboard/issues/[id]/page.tsx` (신규, 서버)
- `params: Promise<{ id: string }>`([id] 패턴). 이슈 조회(없으면 notFound 또는 빈 안내).
- 집계(issue_contents → contents):
  1. **헤더**: title + summary(AI 인사이트). status.
  2. **관련 콘텐츠 by 카테고리**: 이슈 콘텐츠를 `category`별 카운트(CONTENT_CATEGORY_LABEL: 뉴스/리서치/웹인사이트/유튜브) + 각 카테고리 최근 몇 건 목록(제목 링크 `/dashboard/contents/{id}`).
  3. **타임라인**: 이슈 콘텐츠 시간순(98 패턴 — KST 일자 그룹, 제목·출처·날짜·논조 배지). 상위 N(예: 40).
  4. **관련 엔티티**: 이슈 콘텐츠의 `content_entities` join `entities` → 빈도순 상위 엔티티 칩(타입색·ENTITY_TYPE_LABEL·클릭→`/dashboard/topics/{canonical}`). (99 재사용.)
  5. **논조 분포**: 이슈 콘텐츠 sentiment 집계(긍/중/부 막대 또는 배지).
- 전부 서버 집계. 데이터 0이면 각 섹션 graceful.

## 회귀 / 주의
- **SQL 선적용(수희).** 미적용 시: 크롤 자동배정 upsert 실패→격리(크롤 정상), 보드/상세 빈 상태. 적용 후 Claude 루틴이 이슈를 넣어야 내용이 채워짐(시드 없음 — 정상).
- **이슈 내용은 Claude 큐레이션 루틴이 채움**(Opus 담당). 이 지시서는 빈 집을 짓는 것 — 빈 상태가 기본값.
- 자동배정 텍스트매칭은 근사(부분문자열) — 짧은 match_keyword 오탐 가능. Claude가 변별력 있는 키워드를 고르는 것으로 완화(큐레이션 책임).
- 크롤 1회 issues 로드 = 이슈 수 바운디드(큐레이션)라 부담 적음. 매우 커지면 후속 최적화.
- 보드/상세는 서버 컴포넌트 유지. RLS(#7)·service_role 적재(크롤러)·UI 한국어(#1)·색 토큰(#9)·`any` 금지.
- 91 급상승 KST 주 경계 헬퍼와 일치시킬 것(불일치 금지).
