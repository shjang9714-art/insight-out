# 지시서 379 — TTS 청크 크기·per-chunk 타임아웃 재튜닝 (여전히 504/abort)

> ⚠️ 읽을 것: `src/lib/tts/synthesize-briefing.ts`(378 — `MAX_CHUNK_CHARS = 1600`·`synthesizeChunk`의 `AbortSignal.timeout(60_000)`·청크 순회·maxDuration 300) · `AGENTS.md`

## 증상 (David, 배포 후)
"**청크 1/1: TTS 합성 중 오류(The operation was aborted due to timeout)**". 378 배포됐으나 여전히 실패. 콘솔 500/504.

## 원인 (실측 기반)
- 378 dev 실측: **981자 청크 = 약 52초**(Gemini TTS는 대략 **~18~19자/초**로 느림).
- `MAX_CHUNK_CHARS = 1600` → 1600자 청크는 **~85초** 소요인데, **per-chunk `AbortSignal.timeout(60_000)`(60초)** 에 걸려 abort.
- 즉 **청크가 60초 타임아웃 대비 너무 크다.** (maxDuration 300은 늘었지만 청크 단위 fetch에서 먼저 죽음.)

## 작업 (`synthesize-briefing.ts`)

### 1. 청크 크기 축소 + per-chunk 타임아웃 상향(정합)
- `MAX_CHUNK_CHARS` **1600 → 약 700~800**(≈40~45초/청크로 60초 여유 확보).
- per-chunk `AbortSignal.timeout`을 **60초 → 약 120초**로 상향(문장 하나가 커서 청크가 커지는 예외에도 여유). 단 **총합이 maxDuration(300초) 안**에 들도록: 청크 크기·타임아웃을 잡을 때 `대략 총_문자수 × 0.055초`가 예산.

### 2. 총 예산 가드(긴 브리핑 방어)
- 합성 시작 전 **예상 소요 = script.length × ≈0.055초**를 계산해, **maxDuration 예산(예: 280초)을 초과할 것으로 보이면** 시작 전에 명확한 사유로 중단(`스크립트가 너무 길어 한 번에 합성할 수 없습니다(약 N초 예상). 스크립트를 줄이거나 분할 발행하세요.`). 무한정 시도하다 504 나는 것보다 사전 안내가 낫다.
- (참고: Vercel 함수 상한이 300초라, 아주 긴 브리핑은 근본적으로 단일 호출로 불가 — 이 경우는 후속에서 백그라운드 큐/분할 저장 검토. 이번은 튜닝 + 사전가드까지.)

### 3. 로그
- 각 청크 실제 소요(ms)를 `console.log`로 남겨(튜닝 근거). 완료 시 총 소요·청크수 로그.
