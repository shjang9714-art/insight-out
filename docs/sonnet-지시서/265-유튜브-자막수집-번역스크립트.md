# 지시서 265 — 유튜브 자막 수집 + 번역 스크립트

목표: 유튜브 영상의 **자막(transcript)을 수집**해 **한글로 번역**하고, 상세(264 분석 패널)에 **번역 스크립트**를 표시한다. 이걸로 요약/분석 품질도 올라간다(제목+설명 → 자막 기반).

David 요청: 자막을 별도 수집.

범위: 자막 수집(크롤러/enrich) + 번역 파이프라인 재사용 + `265-youtube-transcript.sql`(컬럼) + 264 패널에 스크립트. 전제: 252(유튜브 태깅)·번역 파이프라인.

> ⚠️ **현실 3가지(명시)**: (1) YouTube **공식 자막 다운로드 API는 소유자 OAuth 필요** → 제3자 영상엔 부적합. 실무는 **timedtext/라이브러리(youtube-transcript 등) — 비공식**. (2) **자막 없는 영상 많음**(자동자막도 미생성 케이스) → graceful. (3) 비공식 엔드포인트는 **ToS 회색·rate limit·변동** 가능. → 실패/없음을 정상 흐름으로 처리, 무리한 대량 병렬 금지.

---

## 1. 데이터 모델 (`docs/sql-handoff/265-youtube-transcript.sql` — 작성 완료, 수희 핸드오프)

> **증보(Opus)**: 원안의 컬럼 3개에 **`transcript_fetched_at`을 추가**했다. 3개만으로는 백필 대상을
> `transcript is null`로 잡을 수밖에 없어, **자막이 아예 없는 영상을 매 회차 영원히 재시도**하게 된다
> (§3이 경고한 rate limit·ToS 위험을 자초). 219(썸네일)·282(fresh/retry)의 `*_fetched_at` 마커 패턴을 따른다.

```sql
alter table public.contents
  add column if not exists transcript            text,        -- 원문 자막(언어 원본)
  add column if not exists transcript_ko         text,        -- 번역 스크립트(한글)
  add column if not exists transcript_lang       text,        -- 자막 언어(ko/en/…)
  add column if not exists transcript_fetched_at timestamptz; -- 시도 시각(null=미시도, 값=시도완료)

-- 미시도 유튜브 영상 백필 스캔용 부분 인덱스
create index if not exists contents_youtube_transcript_pending_idx
  on public.contents (collected_at desc)
  where category = '유튜브' and transcript_fetched_at is null;
```

- 유튜브 정본은 **`contents`(`category='유튜브'`)** — `src/lib/crawler/orchestrator.ts:801`에서 그렇게 적재됨(확인 완료).
- **`supabase/schema.sql`도 함께 갱신**할 것(드리프트 방지 — 276이 같은 방식으로 처리).

## 2. 구현

### 2-1. 자막 수집 (`lib/crawler` 또는 `lib/youtube`)
- video_id로 **자막 트랙 조회·추출**: `youtube-transcript`(npm) 또는 timedtext 엔드포인트. 우선 **한국어 자막 → 없으면 영어/자동자막**.
- 세그먼트 합쳐 `transcript`(원문) + `transcript_lang` 저장. **길이 상한**(예: 20k자)로 컷.
- **graceful**: 자막 없음/조회 실패 → `transcript` null, 로그만. 크래시 금지.
- **⚠️ 시도 마커 필수**: 성공·실패·자막없음 **어느 경우든 `transcript_fetched_at = now()`로 마킹**한다.
  이걸 빼면 자막 없는 영상을 매 회차 다시 긁어 rate limit에 걸린다(원안의 구멍).
- **백필은 282의 fresh/retry 모드를 그대로 복제**(`src/lib/contents/thumbnail-backfill.ts` 참조):
  - `mode=fresh`(기본): `category='유튜브' AND transcript_fetched_at IS NULL` (아직 시도 안 함)
  - `mode=retry`: `transcript_fetched_at IS NOT NULL AND transcript IS NULL` (과거 실패행만 재시도)
  - 배치 + `remaining` 카운트 + 중단 버튼 — 282 `drainThumbnailBackfill` 구조 재사용.
- **트리거**: 신규 유튜브 수집 시(252 tagYoutubeContent 인접) 자동 + 기존은 **어드민 백필 버튼**("유튜브 자막 수집", `/api/admin/youtube-transcript?mode=fresh|retry`). 어드민 UI는 282가 만든 "아직 시도 안 함 / 실패행 재시도" 2버튼 패턴을 따른다.
- **레이트 리밋**: 순차 처리 + 배치 간 짧은 딜레이. 대량 병렬 금지(§0 경고).

### 2-2. 번역 (기존 파이프라인 재사용)
- `transcript_lang !== 'ko'`면 **기존 번역 로직**으로 → `transcript_ko`. 번역 **budget** 준수(초과 시 스킵, 다음 회차). 이미 한국어면 transcript_ko=transcript.

### 2-3. 요약 강화 (선택)
- 264 분석 패널의 "주요 내용" 생성 입력에 **transcript_ko(있으면)**를 포함 → 제목·설명만일 때보다 훨씬 정확한 요약. (llmComplete('summarize'), 한글, 길이 컷.)

### 2-4. 표시 (264 패널)
- 264 분석 패널에 **"스크립트" 접힘 섹션**: `transcript_ko` 있으면 표시(원문 토글 선택). 없으면 섹션 생략.
- 긴 스크립트는 스크롤·펼치기.

## 3. 회귀 가드
- 컬럼 미적용(42703) graceful: 수집·표시 스킵, 기존 동작 무변.
- 자막 없는 영상: transcript null → 패널 스크립트 섹션 생략(요약은 제목/설명 기반).
- **자막 없는 영상도 `transcript_fetched_at`을 반드시 마킹** → fresh 백필이 같은 영상을 재차 긁지 않을 것(rate limit 방지). 이 가드가 깨지면 백필이 매번 전체를 재시도한다.
- 비공식 엔드포인트 실패: 격리(크롤 무중단), 백오프.
- 번역 budget 공유 — 초과 시 스킵.
- 비유튜브 콘텐츠 무관.
