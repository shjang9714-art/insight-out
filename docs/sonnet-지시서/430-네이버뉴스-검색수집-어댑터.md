## 0. 한 줄
네이버 뉴스 검색 API 를 **검색 수집 백엔드로 병행 추가**한다. 기존 키워드 시드로 네이버도 조회 → 기사 **발견(URL·메타)** → 기존 파이프라인(stub → 보강 → 관련도 게시). 본문은 원문에서 추출(현행 그대로). 소스 다양성↑·편향↓.

---

## 1. 착수 전 확인
- 어댑터 인터페이스(`adapters/index.ts`·`types.ts`): `SourceAdapter.fetch(source, since): Promise<RawItem[]>`. `RawItem = { original_url, title, body?, published_at?(ISO), thumbnail_url?, language? }`.
- 검색 시드 수집(orchestrator): 각 `keyword_groups.search_seeds` 시드로 **합성 소스(`isSearchSourced: true`)** 만들어 `adapter.fetch` → `processCrawlItem`. isSearchSourced 는 425 에서 bodyTooShort 게이트를 원래 면제(짧아도 stub 적재).
- **네이버 API**: `GET https://openapi.naver.com/v1/search/news.json`
  - 헤더: `X-Naver-Client-Id`, `X-Naver-Client-Secret` (env).
  - 파라미터: `query`(검색어), `display`(≤100), `start`(≤1000), `sort=date`.
  - 응답 `items[]`: `title`, `originallink`(원문 URL), `link`(네이버 URL), `description`, `pubDate`(RFC822).
  - 제약: `start+display-1 ≤ 1000`(쿼리당 최대 1000건), 하루 25,000콜.

## 2. 구현

### 2.1 어댑터 `src/lib/crawler/adapters/naver-news.ts`
- `export async function fetchNaverNews(query: string, since: string, opts?: { maxItems?: number }): Promise<RawItem[]>`
- **env 가드**: `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` 없으면 **`[]` 반환**(graceful — 미설정 시 조용히 스킵).
- 페이지네이션: `display=100, sort=date`, `start` 1→101→…(`start+display-1 ≤ 1000` 준수, 기본 상한 예: 300건). **`pubDate < since` 나오면 중단**(최근순이라 그 이후는 볼 필요 없음).
- **매핑(발견용)**:
  - `original_url = item.originallink || item.link` — **originallink(원문) 우선**(보강·dedup·저작권상 원문 지향).
  - `title` = HTML 태그·엔티티 제거(`<b>` 등).
  - `body` = `description` 태그 제거(짧은 스니펫 — 발견용, 본문은 이후 보강이 원문에서 채움).
  - `published_at` = `pubDate`(RFC822 → ISO).
  - `language = 'ko'`.
- 오류·레이트리밋: try/catch, 로그 + 부분 반환(전체 크롤 무중단).

### 2.2 검색 수집에 네이버 병행 (orchestrator)
- 키워드 시드 루프에서 **기존 Google News RSS fetch 에 더해 `fetchNaverNews(seed, since)` 도 호출** → RawItems 를 합쳐 `processCrawlItem`.
- env 없으면 네이버분은 빈 배열 → 기존과 동일(무영향).
- 합성 소스 `isSearchSourced: true` 유지 → 짧은 스니펫도 stub(pending) 적재 → 보강 → **425/426 관련도 게이트 통과분만 게시**.
- **중복**: 같은 기사가 Google·네이버·RSS 로 겹쳐도 canonical/hash dedup 이 흡수(originallink 사용으로 dedup 정확도↑).
- 콜 예산: 시드 수 × 페이지 상한이 25k/일 안에 들도록(시드 많으면 시드당 1~2페이지로 제한). 로그로 콜 수 관찰.

## 3. 하지 말 것
- **네이버 `link`(네이버 내부 URL) 말고 `originallink`(원문) 우선** — 본문 보강·중복제거·저작권상 원문 지향.
- description(스니펫)을 **본문으로 확정하지 않기** — 발견용이고 본문은 원문 보강이 채운다(425 경로).
- env 없을 때 **에러/중단 금지**(graceful skip).
- 기존 Google News RSS·RSS 소스 수집 **무변경**(네이버는 병행 추가).
- 하루 25k콜 초과 주의(시드×페이지 상한).
- 새 스키마·SQL 금지.

## 4. 회귀 가드
1. env(네이버 키) 있으면 **네이버 출처 기사도 수집**(소스 다양성↑), 없으면 기존과 완전 동일(스킵).
2. 네이버 발견 기사가 `pending` stub → 보강 → **관련도 통과분만 게시**(425/426).
3. Google/RSS 와 중복되는 기사는 자동 흡수(중복 게시 없음).
4. `originallink`(원문 URL) 로 적재(네이버 URL 아님).
5. 기존 수집(Google RSS·RSS 소스) 회귀 없음.
6. 레이트리밋·오류 시 크롤 전체 무중단(부분 반환).
