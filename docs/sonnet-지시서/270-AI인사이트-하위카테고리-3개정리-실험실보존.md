## 배경 / 목표

현재 AI 인사이트(`/dashboard/issues`)의 하위 카테고리 탭은 **6개**다:
`핵심 Insight(brief) · 헤드라인 분석(headline) · 뜨는 토픽(trending) · 이슈 타임라인(issues) · 관계지도(graph) · 키워드 분석(keyword)`.

6개가 탭 컨테이너 폭(`--nav-group-w` = 500px)을 넘겨 **라벨이 두 줄로 접혀** 보인다. 이를 다음과 같이 정리한다.

1. **일반 사용자에게 노출되는 하위 카테고리는 3개**, 순서 고정:
   `핵심 인사이트(brief) → 키워드 분석(keyword) → 관계지도(graph)`
2. **나머지 3개**(`헤드라인 분석 · 뜨는 토픽 · 이슈 타임라인`)는 일반 사용자에게 **숨김**. 단 **관리자(role='admin') 계정에서는 '실험실' 그룹으로 계속 접근 가능**하게 보존(추후 다른 서비스 구상 시 재활용).
3. `핵심 Insight` 탭 라벨을 **`핵심 인사이트`** 로 변경.
4. 라벨이 **한 줄에 다 들어오도록**(두 줄 접힘 제거). 3개로 줄면 500px 안에 여유 있게 들어오고, 라벨 자체의 줄바꿈도 `whitespace-nowrap`으로 막는다.

> **데이터 fetch는 건드리지 않는다.** `AiInsightsView.tsx`의 `Promise.all`은 6개 뷰 데이터를 view 값과 무관하게 항상 전부 받아온다. 숨긴 탭도 관리자 실험실에서 그대로 렌더되어야 하므로 기존 fetch를 유지한다(쿼리 개수 변화 없음, role 조회 1개만 추가).

> **관리자 판별은 기존 패턴 재사용.** `src/app/dashboard/entities/[id]/page.tsx`가 이미 쓰는
> `supabase.from('users').select('role').eq('id', user.id).single()` → `role === 'admin'` 방식을 그대로 따른다.

4. 탭 렌더를 (a) 항상 보이는 `PRIMARY_TABS` 한 줄 + (b) 관리자에게만 보이는 `실험실` 라벨 + `LAB_TABS` 줄로 재구성.
5. 각 뷰별 렌더 블록은 그대로 유지(관리자 실험실에서 렌더되어야 함).
