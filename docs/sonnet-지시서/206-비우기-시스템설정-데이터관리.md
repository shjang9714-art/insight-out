## 0. 한 줄

`AdminContentManager` 상단의 "수집 기사 비우기 / 유튜브 비우기" 버튼·핸들러·2단계 확인을 떼어, `/admin/settings` 하단 **"데이터 관리"** 섹션의 신규 컴포넌트로 옮긴다. 기존 API(`/api/admin/contents/purge`, `/api/admin/youtube/purge`)는 그대로.

## 1. 현행 진단 (검증된 코드 사실)

- `AdminContentManager.tsx`: 비우기 UI(:766~791, outline 빨강 버튼 2개) + 핸들러 `handlePurge`(:~478)·`handleYoutubePurge`(:~513) + 상태(`isPurging`/`purgeResult`/`isYtPurging`/`ytPurgeResult`, :~178~181) + 결과 칩(:734~761 중 purge 관련).
- API: `GET /api/admin/contents/purge`(건수) · `POST`(삭제, original_url 있는 크롤분만·업로드 리포트 보존). `GET/POST /api/admin/youtube/purge`(youtube_videos 전량). **변경 없음.**
- 설정 페이지: `src/app/admin/settings/page.tsx`(201·202) — AdminAppearanceSettings + "공개 홈 구성" 섹션. 여기에 "데이터 관리" 섹션 추가.

## 2. 구현 (프런트 이동)

### 2-1. 신규 `src/components/admin/AdminDataReset.tsx` (`'use client'`)
- 비우기 2종 이동: `handlePurge`·`handleYoutubePurge` 로직(건수 GET → 2단계 확인 → POST → 결과)을 그대로 옮김. 상태(isPurging/purgeResult 등)도 이 컴포넌트로.
- UI: 각 항목을 카드/행으로 — 제목("수집 기사 삭제", "유튜브 영상 삭제") + 설명(무엇이 지워지고 무엇이 보존되는지: 예 "크롤링 수집 기사만 삭제, 업로드한 리포트는 보존") + **삭제 건수 미리보기**(GET) + 실행 버튼.
- **파괴적 작업 경고 강화**: 2단계 확인(1차 클릭=건수와 함께 "정말 N건 삭제?" 확인 상태 → 2차 클릭=실행). 버튼은 204에서 톤다운된 destructive 토큰 사용(`border-destructive/40 text-destructive hover:bg-destructive/10`), 실행 직전 확인 문구.
- 결과·오류 메시지 한국어, 로딩 표시.

### 2-2. `settings/page.tsx` 에 "데이터 관리" 섹션 추가
- 기존 "공개 홈 구성" 섹션 아래에:
  ```
  <AdminSectionHeader icon={Database} title="데이터 관리" hint="수집 데이터 초기화. 되돌릴 수 없으니 주의하세요." />
  <AdminDataReset />
  ```
  (아이콘은 lucide `Database`/`Trash2` 등 적절히.)

### 2-3. `AdminContentManager.tsx` 에서 제거
- 비우기 버튼 2개(:766~791)·purge 결과 칩·핸들러(`handlePurge`,`handleYoutubePurge`)·상태(isPurging/purgeResult/isYtPurging/ytPurgeResult) 삭제.
- **주의**: 이 블록(`flex flex-col items-end`)에는 풀본문/신호/URL/기간select 도 함께 있음 — **206에선 비우기만 제거**하고 나머지는 그대로 둔다(205가 재편). import 정리(Trash2 등 미사용 시).
