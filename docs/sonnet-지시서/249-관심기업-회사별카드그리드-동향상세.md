# 지시서 249 — 관심기업: 회사별 카드 그리드 + 기업 동향 상세 페이지

목표: 관심기업 탭을 **"내 회사들의 최신 동향 대시보드"**로 재구성한다. (1) 기간 그룹핑 폐지 → **회사별 카드 그리드**(회사당 최신 동향 카드 1개), (2) **"자세히 보기" 버튼 제거 → 카드 전체 클릭**, (3) 카드 클릭 시 **기업 동향 상세 페이지**(핵심·시사점 전문 + **근거 자료**)로. AI 요약·근거 데이터는 이미 생성됨(`insight_cards` scope='company') — **생성 로직 변경 없음, 프론트만.**

David 결정(2026-07-09): 회사별 카드 그리드 · 자세히버튼 제거 · 카드1건 상세 · 1단계는 상세페이지만(다중전개 요약·온디맨드 생성은 후속) · top-N 캡 없음(기존 생성 유지).

범위: `entities/page.tsx`(watchlist 뷰) + **신규 상세 페이지** + `card-meta.ts`(getCardDetailHref) + (공유 카드 컴포넌트). SQL 없음. 설계: `docs/설계-관심기업-동향상세-재구상.md`.

---

## 1. 현행 진단 (검증된 코드 사실)
- 관심기업 뷰(`entities/page.tsx` view='watchlist'): 워치리스트 회사에 매칭되는 `insight_cards`(scope='company')를 **기간(period_start|period_end)으로 그룹핑** → `InsightCardsSectionClient`(핵심/시사점/근거/키워드 + "자세히 보기"). 
- **문제**: 기간 그룹핑이라 sparse period(카드 1개) 발생. **`getCardDetailHref`(card-meta.ts)가 "자세히 보기"·제목 클릭 → `/dashboard/contents/{첫 기사}`(단일 기사)** → 기업동향이 아닌 기사 점프.
- 카드 데이터: `id, topic(회사), card_headline(핵심), headline(부제), implication(시사점), citations[{content_id,quote}], source_content_ids, period_start/end, generated_at`. **상세에 필요한 건 다 있음.**
- `getCardDetailHref`는 관심기업·AI인사이트 헤드라인·경쟁사 동향분석이 **공유** → 여기 고치면 전 사용처가 카드 상세로 개선(의도된 일석이조).

## 2. 구현

### 2-1. 관심기업 뷰 재구성 (`entities/page.tsx` watchlist)
- **회사별 재구성**: 워치리스트 회사별로 매칭 company 카드 중 **최신 1개**(period_start desc, generated_at desc)만 선택 → 회사당 카드 1개.
- **카드 그리드**: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4`. 정렬 = 내 관련도(computeRelevance) → 최신순.
- **컴팩트 카드**(신규 `CompanyTrendCard` 또는 인라인): 
  - 상단 배지: 회사명(topic) + 중요도 + 내 관련도.
  - **핵심**(card_headline ?? headline) — 2줄 clamp, 굵게.
  - **시사점**(implication) — 2줄 clamp, muted.
  - 하단: **날짜 라벨**(period `M.D~M.D` 또는 "N일 전") + 근거 건수(`근거 N건`).
  - **카드 전체가 `<Link href={cardDetailHref}>`** → 상세. **"자세히 보기" 버튼·인라인 근거 리스트 제거**(상세로 이동).
- 빈 상태: 기존 "마이페이지에서 관심기업 설정"(+225 인탭 모달) 유지.
- **기간 그룹 헤더·InsightCardsSectionClient 사용 제거**(이 뷰 한정). 다른 뷰(AI인사이트 등)의 InsightCardsSectionClient는 불변.

### 2-2. 기업 동향 상세 페이지 (신규 `dashboard/insights/[id]/page.tsx`)
- `insight_cards` 를 id로 조회(published). 없으면 notFound 또는 안내.
- 근거 콘텐츠 메타: `source_content_ids` + `citations[].content_id` 모아 `contents`(id,title,category,sources(name),published_at) 배치 조회.
- 렌더:
  - **헤더**: 회사명(topic) + 기간 + 중요도/내관련도 배지 + "← 관심기업" 뒤로.
  - **핵심**(card_headline) 크게 → **부제/맥락**(headline).
  - **시사점**(implication) 전문(clamp 없이).
  - **근거 자료(핵심 섹션)**: `citations` 각각 **인용문("...") + 출처 기사 제목·매체 링크**(`/dashboard/contents/{content_id}`). 인용 없는 `source_content_ids`는 "참고 기사" 목록으로. → "왜 이렇게 분석했나"를 근거로 제시.
  - **관련 키워드**(computeRelatedKeywords) → 토픽.
  - (선택·후속) 그 회사 최근 기사 타임라인.
- 인증 게이트 안(dashboard 하위 자동).

### 2-3. 라우팅 교정 (`card-meta.ts`)
- `getCardDetailHref(card)` → **`/dashboard/insights/${card.id}`**(카드 상세). 근거 섹션 내 개별 기사만 `/dashboard/contents/{id}`.
- `card.id` 인자 필요 → 시그니처에 `id` 추가, 호출부(카드 렌더)에서 id 전달 확인.
- 폴백: 상세 페이지가 어떤 published 카드든 렌더하므로 콘텐츠 폴백 불필요(단 카드 id 없으면 기존 콘텐츠 링크 유지 방어).

## 3. 회귀 가드
- **생성·SQL 변경 없음**(기존 company 카드 재사용).
- `getCardDetailHref` 변경은 **AI인사이트 헤드라인·경쟁사 동향분석에도 적용** → 이들도 카드 상세로(개선). 상세 페이지가 scope industry/company 모두 렌더하는지 확인(회사명 대신 topic 표시로 일반화).
- 관심기업 외 뷰(InsightCardsSectionClient)는 그대로 — watchlist 뷰만 그리드로 교체.
- 카드 id 항상 존재(insight_cards PK) → 링크 안전.
- 근거 콘텐츠 없는 카드도 상세 렌더(근거 섹션 빈 상태 처리).
