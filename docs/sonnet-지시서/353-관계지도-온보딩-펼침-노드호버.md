## 작업

### 1. 유형 필터 제거 → 색상 범례로 격하
- 현 "유형 필터 (누르면 숨김)" 칩(토글로 타입 숨김)은 의미가 약하다(David). **hide 토글 폐지** — `hiddenTypes` state·`toggleType`·`visibleNodes/visibleLinks`의 hidden 분기 제거(전 노드 표시).
- 대신 **비인터랙티브 색상 범례** 한 줄만 남긴다: 유형별 색 점 + 라벨(+선택적 count). 클릭 동작 없음. "색 = 유형"만 설명.

### 2. 처음부터 버블이 펼쳐져 보이게 (디폴트)
- 지금은 열면 버블이 중앙에 뭉쳐 보임. force 튜닝으로 **초기 상태에서 퍼지게**:
  - charge 반발력 강화: `-280` → **약 -600**.
  - **collide force 추가**(겹침 방지): `d3Force('collide', d3.forceCollide(r))`, r = 노드 시각 반지름 + 여유(예: `n.val*2.5 + 6`). `react-force-graph`는 d3-force 내장 — `fg.d3Force('collide', forceCollide(...))`.
  - force 적용을 **로드 직후 즉시**(현재 150ms setTimeout에만 의존하지 말고, 최초 1회는 바로) + `warmupTicks` 40→**약 120**, `cooldownTicks` 상향.
  - **`onEngineStop`에서 `graphRef.current?.zoomToFit(400, 40)`** 호출 — 퍼진 그래프가 뷰포트에 맞게. 확장(expandNode) 후에도 재적합.
- 목표: 최초 페인트~안정화까지 뭉침 없이 방사형으로 펼쳐짐.

### 3. 온보딩 — 라벨칩 우선, 검색은 (+)로 격하 + 탈(脫)전문용어
- 초기 사용자는 "엔티티"가 어렵고 뭘 검색할지 모름(David).
  - **빠른 중심 칩을 최상단 1차 액션으로** 승격, 헤더 문구를 쉬운 말로(예: `이런 걸 볼 수 있어요` / `관심 기업·기술`). 현재 `빠른 중심:` 라벨 교체.
  - **검색 입력창을 상시노출에서 (+) 버튼 뒤로 숨김**: 기본은 `＋ 직접 검색`(또는 돋보기) 버튼만, 클릭 시 입력창 인라인 확장. `showSearchDrop`/`searchQuery` 로직은 유지, 컨테이너만 토글.
  - de-jargon: placeholder `엔티티 검색해 중심으로 설정…` → **`회사·기술 이름으로 찾기`**. 상단 안내문의 "엔티티" 표현도 `기업·기술·인물` 중심으로 순화(용어는 필요 최소만).

### 4. LG유플러스를 빠른 중심 맨 앞 + 디폴트 중심
- 현 `initialCenter = entities[0]`(최다 언급 = "AI" 같은 일반어일 수 있음). **LG유플러스를 기본 중심으로.**
  - LG유플러스 엔티티 해석: `entities`에서 `canonical_name` ∈ (`LG유플러스`,`LGU+`,`LG U+`) 매칭(별칭 있으면 포함). `src/components/analysis/AiInsightsView.tsx` L183 `initialCenter`를 **LG유플러스 우선, 없으면 기존 entities[0] 폴백**으로.
  - `KnowledgeGraph`의 `presets`: `[LG유플러스, ...competitors, ...topNonCompetitors]` 순서로 **맨 앞에 pin + 중복 제거**. 활성(디폴트) 칩 표시는 기존 `rootId === e.id` 강조 재사용.

### 5. 노드 호버 → 우측 인스펙터에 관련기사 미리보기 + 클릭 히트영역 개선
- **노드 호버**: 지금은 호버 시 캔버스 라벨(`클릭 → 관련 기사 보기`)뿐. **`onNodeHover` 추가** — 디바운스(약 200ms) + 캐시(`nodeContentCacheRef: Map<id, ContentItem[]>`)로 `content_entities` 조회 후, **우측 인스펙터에 "미리보기" 상태로** 관련기사 표시(엣지 호버 툴팁 패턴 재사용).
  - 호버=미리보기(가벼움), **클릭=잠금(기존 유지)**. 잠금(selected/lockedEdge) 상태가 있으면 호버가 그것을 덮어쓰지 않게(잠금 우선). 호버 해제 시 미리보기만 사라지고 잠금은 유지.
- **클릭 히트영역**: 작은 노드(val 작음)가 잘 안눌림. **`nodePointerAreaPaint` 추가** — 포인터 판정 원 반지름을 `Math.max(시각반지름, 12)`로 키워 작은 노드도 쉽게 클릭. `nodeRelSize`/`linkHoverPrecision` 점검. (시각 크기는 그대로, 히트영역만 확대.)

### 6. 기사 "전체보기" 연동 — **검토만**(코드 변경 없음, 지시서에 결과만 기록)
- 현 상태: 노드 패널 `content_entities … .limit(8)`(전체보기 링크 없음, 단 `상세 보기 →` = `entities/[id]`) · 엣지 패널 `entity_pair_contents … p_limit 8`(전체보기 없음) · 호버 툴팁 3건.
- 검토 결론(직접 판단해 문서화): **노드 = `entities/[id]`가 사실상 전체보기** 역할(그 페이지가 해당 엔티티 전체 기사 나열하는지 확인해 기록). **엣지(두 엔티티 공동기사) = 전용 전체보기 없음** → 후속(354+)에서 필터 검색/페어 페이지로 확장 여지. **이번엔 구현하지 말 것.**

## 회귀 / 주의
- 이 파일은 canvas라 **hex 색상 예외 유지**(AGENTS.md §1-9). 신규 색도 토큰 아닌 hex 사용 OK, 단 기존 팔레트와 일관.
- `react-force-graph-2d`의 d3-force 접근은 `(fg as any).d3Force(...)` 기존 패턴 재사용. `d3.forceCollide` import 필요(있는 d3 버전 확인 — 없으면 `react-force-graph`가 내장한 d3 이용).
- 호버 조회는 **디바운스+캐시 필수**(노드마다 무분별 요청 금지). 잠금>미리보기 우선순위 명확히.
- `initialCenter` 변경은 서버(AiInsightsView) 한 곳 — EntitiesPageClient는 prop만 받으므로 별도 수정 불필요(확인).
- `prefetch={false}`, 한글 URL 인코딩 유지.
- 검증: `tsc` · ESLint · `check-prefetch` · `npm run build` · 육안(열자마자 펼침 · LG유플러스 디폴트 중심 · 칩 우선/검색 (+) · 노드 호버 미리보기 · 작은 노드 클릭 · 유형필터 없음).
