## 0. 한 줄 · 스코프
`/admin/relations`에 **엔티티 관계 탐색기**를 신설한다 — 엔티티(기업/기술/인물/정책/산업)를 고르면 **같은 콘텐츠에 함께 등장(동시출현)한 엔티티들**과 그 **근거 콘텐츠**를 보여준다. "미팅 전 이 기업과 엮인 것들"을 근거와 함께.
- **v1 = 탐색기(목록·근거 중심)**, 그래프 라이브러리 미도입. 시각 포스그래프는 **v2(별건, 의존성 도입 필요)**.

## 1. 착수 전 확인 (컬럼·패턴 — origin/main 확인됨)
- **entities**: `id, canonical_name, entity_type('company'|'tech'|'product'|'person'|'policy'|'industry'), description, is_competitor, service_id, mention_count`. 라벨 맵 `ENTITY_TYPE_LABEL`(기업/기술/제품/인물/정책/산업) — `@/lib/types`.
- **content_entities**: `id, content_id, entity_id, source, score`. → **동시출현 = 같은 content_id를 공유하는 엔티티 쌍.**
- **entities 조회 패턴**(`src/app/api/council/route.ts` 참고): `select('id, canonical_name, entity_type, description, is_competitor, mention_count').order('mention_count',desc).ilike('canonical_name', %q%).eq('is_competitor', true).limit(≤50)`.
- **content_entities 바운드 패턴**(`src/lib/entities/generate-events.ts`): "content_entities → 콘텐츠 최근 days·최대 N건". 동일하게 상한.
- **nav**: `src/lib/admin/nav.ts` 인사이트 그룹에 `{ href: '/admin/relations', label: '관계지도', ..., disabled: true, badge: '준비중' }` 존재 → **disabled·badge 제거**.
- 어드민에 relations/entities 페이지 없음(신규). 페이지 셸은 `AdminPageHeader`(source-quality 미러), 데이터 `createAdminClient()`.
- 콘텐츠 상세 링크: `/admin/contents/[id]`(어드민) 사용.

## 2. 구현

### 2.1 집계 라이브러리 `src/lib/admin/relations.ts` (신규, server-only)
```ts
import 'server-only'
import type { SupabaseClient } from '@supabase/supabase-js'
import type { EntityType } from '@/lib/types'

export interface EntityBrief { id: string; name: string; type: EntityType; isCompetitor: boolean; mentionCount: number }
export interface ConnectedEntity { entity: EntityBrief; sharedCount: number }   // 공유 콘텐츠 수 = 관계 강도
export interface EvidenceContent { id: string; title: string; category: string | null; published_at: string | null }

const CONTENT_SAMPLE_LIMIT = 500      // 선택 엔티티의 콘텐츠 상한
const CONNECTED_LIMIT = 20            // 연결 엔티티 상위
const EVIDENCE_LIMIT = 20

// 엔티티 피커 목록(검색·타입·경쟁사 필터, mention_count desc)
export async function listEntities(admin: SupabaseClient, opts: { q?: string; type?: EntityType | null; competitorOnly?: boolean; limit?: number }): Promise<EntityBrief[]>

// 선택 엔티티의 동시출현 연결 엔티티(공유 콘텐츠 수 desc, 상위 N)
export async function getEntityRelations(admin: SupabaseClient, entityId: string): Promise<{ focus: EntityBrief | null; connected: ConnectedEntity[]; contentSampled: number; truncated: boolean }>

// 두 엔티티가 함께 등장한 근거 콘텐츠
export async function getRelationEvidence(admin: SupabaseClient, aId: string, bId: string): Promise<EvidenceContent[]>
```
구현 지침:
- **getEntityRelations**(바운드·확장성):
  1. 선택 엔티티 조회(`entities ... eq('id', entityId).single()`). 없으면 focus=null.
  2. 그 엔티티의 콘텐츠: `content_entities.select('content_id').eq('entity_id', entityId).order('created_at',desc).limit(CONTENT_SAMPLE_LIMIT)` → contentIds. `truncated = length>=limit`.
  3. 그 콘텐츠에 함께 있는 다른 엔티티: `content_entities.select('entity_id, content_id').in('content_id', contentIds).neq('entity_id', entityId)` → entity_id별 **distinct content 수** 집계(같은 쌍이 여러 content 공유 → 강도).
  4. 상위 CONNECTED_LIMIT entity_id → `entities.select(brief cols).in('id', ids)`로 해소 → `ConnectedEntity[]`(sharedCount desc).
- **getRelationEvidence**: `content_entities.select('content_id').eq('entity_id', aId)` ∩ `eq('entity_id', bId)` 교집합 content_ids(각 limit 500) → `contents.select('id, title, category, published_at').in('id', shared).order('published_at',desc).limit(EVIDENCE_LIMIT)`.
- **listEntities**: council 패턴 복제. 기본 mention_count desc, limit 30.
- 모든 쿼리 `.limit()` 상한. 결과 없거나 에러 시 빈 배열(graceful).

### 2.2 페이지 `src/app/admin/relations/page.tsx` (신규, 서버 렌더)
- `searchParams`: `q`(검색), `type`(엔티티 타입 필터), `entity`(선택 id), `with`(근거 볼 상대 id).
- 서버에서: `listEntities`(피커) + `entity` 있으면 `getEntityRelations` + `entity&with` 있으면 `getRelationEvidence`.
- `AdminPageHeader` + `RelationsExplorer`에 데이터 전달. `dynamic='force-dynamic'`, metadata '관계지도 | 어드민 | Insight Out'.

### 2.3 `src/components/admin/RelationsExplorer.tsx` (신규)
- 그래프 라이브러리 없이 3열/패널 구성(반응형):
  - **① 엔티티 피커**: 검색창(GET form, `?q=`) + 타입 필터 칩(`?type=`) + 경쟁사 토글. 목록은 `<Link href="?entity=id">`(mention_count·type 배지). 선택 강조.
  - **② 연결 엔티티**: focus 엔티티 헤더(이름·타입·경쟁사·mention_count) + 연결 목록(이름·타입 배지·**공유 N건** 막대/숫자, sharedCount desc). 각 행 `<Link href="?entity=focus&with=thatId">`로 근거 열기. `truncated`면 "표본 상위 500 콘텐츠 기준" 안내.
  - **③ 근거 콘텐츠**: `with` 선택 시 두 엔티티 공유 콘텐츠 목록(제목·카테고리·발행일 → `/admin/contents/[id]` 링크).
- 데이터 0/미선택 시 안내 문구. `ENTITY_TYPE_LABEL`로 타입 표기. 순수 `<Link>` 네비게이션(클라이언트 상태 불필요 — 'use client'는 검색 폼 정도만 필요 시).

## 3. 회귀 가드 / 검증
- **바운드**: 선택 엔티티 콘텐츠 ≤500, 연결 ≤20, 근거 ≤20 — 무제한 조인/select 금지. `truncated` 노출.

- **v1 범위**: 시각 포스그래프 미포함(의도) — 목록·근거 중심.
