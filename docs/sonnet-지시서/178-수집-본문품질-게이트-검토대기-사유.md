## 0. 한 줄

수집 시 **본문이 없거나·추출 실패·잘림 의심**이면 자동 발행하지 않고 **검토 대기(pending)** 로 보내고, **왜 대기됐는지(review_reason)를 기록**해 어드민 콘텐츠 관리에서 보이게 한다. 기존 관련도 게이트(150)의 대기 사유도 함께 기록.

## 1. 현행 진단 (검증된 코드 사실)

- 게이팅: `src/lib/crawler/orchestrator.ts:361` `contentStatus: 'pending' | 'published'` — **관련도 점수(`relatednessScore`)와 LLM 재판정**으로만 결정(150). `exempt`(trust_tier≥2·그룹없음·web_insight)는 게이트 면제.
- 본문 상수: `SUMMARY_MIN_BODY_LEN=200`, `ENRICH_MIN_BODY_LEN=400`. 풀본문 추출(enrichment)은 신규 적재 후 best-effort tail.
- **본문 품질 게이트 없음**(짧음/누락/추출실패로는 pending 안 됨). **사유 필드 없음**(`review_reason`/`hold_reason` 미존재).
- 어드민 `AdminContentManager` 는 status 배지(검토 대기)만 표시, 사유 없음.

## 2. DB / SQL (수희 핸드오프)

```sql
-- 178: 검토 대기 사유. nullable(발행 콘텐츠는 null). 후방호환.
ALTER TABLE contents ADD COLUMN IF NOT EXISTS review_reason text;
```
파일: `docs/sql-handoff/178-review_reason.sql`. **먼저 커밋·푸시해 수희가 적용**(코드는 컬럼 없어도 graceful).

## 3. 구현

### 3-1. 본문 품질 판정 — `src/lib/crawler/quality.ts` (규칙 함수 추가)
```ts
export type ReviewReason =
  | 'body_missing'    // 본문 없음/못 불러옴
  | 'body_short'      // 본문 과소(잘림 의심)
  | 'extract_failed'  // 풀본문 추출 실패
  | 'body_truncated'  // 말줄임·더보기 등 잘림 마커
  | 'low_relevance'   // 관련도 낮음(기존 게이트)
  | 'llm_irrelevant'  // LLM 재판정 무관

// 본문 품질 사유(없으면 null). 신뢰 소스 면제는 호출부에서.
export function assessBodyQuality(body: string | null | undefined, opts?: { minLen?: number }): ReviewReason | null {
  const text = (body ?? '').trim()
  if (!text) return 'body_missing'
  const min = opts?.minLen ?? 200
  // 잘림 마커: 끝이 …/[…]/더보기/read more/... 등
  if (/(…|\.\.\.|\[…\]|더보기|read more)\s*$/i.test(text)) return 'body_truncated'
  if (text.length < min) return 'body_short'
  return null
}
```
- 임계값·마커는 가이드(라이브 분포 보고 튜닝). 보수적으로 — 명백한 누락/잘림 위주.

### 3-2. 게이팅 배선 — `orchestrator.ts`
`contentStatus`(361) 결정부에 **본문 품질 게이트 + 사유** 추가:
```ts
let reviewReason: ReviewReason | null = null

// 관련도 게이트(기존)
if (관련도로 pending) reviewReason = 'low_relevance'
// LLM 재판정 pending 시 reviewReason = 'llm_irrelevant'

// 본문 품질 게이트(신규) — 면제 소스도 본문 누락/추출실패는 잡되, 단순 짧음은 비면제 소스만
const bodyReason = assessBodyQuality(item.body, { minLen: SUMMARY_MIN_BODY_LEN })
if (bodyReason && !(exempt && bodyReason === 'body_short')) {
  contentStatus = 'pending'
  reviewReason = reviewReason ?? bodyReason  // 이미 관련도 사유 있으면 우선순위 정책대로
}
// published 로 확정되면 reviewReason = null
if (contentStatus === 'published') reviewReason = null
```
- 풀본문 추출(enrichment) 단계에서 **추출 성공으로 본문이 충분해지면**, 그 콘텐츠의 status를 pending→published 승격 + `review_reason=null` 정리(선택, enrichment tail에서). 반대로 추출 실패로 여전히 부실하면 `extract_failed`로 사유 보정.
- insert/upsert payload에 `review_reason` 포함(컬럼 없을 때 42703 graceful — 기존 148/155 패턴 재사용).

### 3-3. 어드민 표시 — `AdminContentManager`
- 검토 대기(pending) 행/카드에 **사유 배지·툴팁**: `REVIEW_REASON_LABEL`(예: body_missing="본문 없음", body_short="본문 짧음(잘림 의심)", extract_failed="본문 추출 실패", body_truncated="본문 잘림", low_relevance="관련도 낮음", llm_irrelevant="AI 무관 판정").
- 사유별 색은 175 status-style tone(주의=risk/neutral) 재사용. 필터에 "사유별" 추가(선택, 후속 가능).
- `review_reason` 컬럼 select 추가(없으면 graceful null).

## 4. 회귀 가드 / 비기능 요건

- **컬럼 미적용(수희 전)**: review_reason 저장/조회 42703 graceful → 게이팅(status)은 정상 동작, 사유만 미표시.
- 과잉 게이팅 방지: 신뢰 소스(trust_tier≥2)의 단순 짧음은 면제(스니펫 홍수 방지). 누락·추출실패는 사유 기록.
- 발행 콘텐츠는 review_reason=null 유지(사유는 대기 콘텐츠 전용).
- 기존 관련도 게이트·풀본문·요약 흐름 무변경(사유 태깅만 추가).
- SQL 외 신규 의존성 0. 하드코딩 hex 0.

## 5. 검증 (Sonnet 자체)

1. `npx tsc --noEmit` 0 / `npx eslint` 0
2. 본문 없음/추출실패/잘림 마커 아이템 → status=pending + 해당 review_reason
3. 관련도 낮음 → pending + low_relevance / LLM 무관 → llm_irrelevant
4. 발행 콘텐츠 → review_reason null
5. 신뢰 소스 단순 짧음 → 과잉 대기 안 됨(면제)
6. 어드민 검토 대기 목록에 사유 배지 표시, 컬럼 없을 때 graceful
