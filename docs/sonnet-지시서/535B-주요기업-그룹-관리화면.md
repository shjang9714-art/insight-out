# 지시서 535-B — 주요기업·그룹 관리 화면 신설

> 플래너(Opus) · 2026-08-20 · 기준 `origin/main = 06fda0c` · 브랜치 `agent/535b-curated-admin`
> 근거: `검토-어드민IA-2차통합안-2026-08-16` §① — "`curated_companies`·`curated_groups` 에
> 어드민 쓰기 경로가 아예 없다(SQL 핸드오프로만 관리)".
> **DDL·SQL 없음.** 두 테이블 모두 이미 있다.

## 실측 사실 (재조사 금지)

- 데이터: `curated_companies` **40행**, `curated_groups` **12행**
  (`kind='watchlist'` 7 / `kind='competitor'` 5, `display_mode` 는 `always` 9 · `on_issue` 3).
- 스키마 (그대로 쓴다)
  - `curated_companies(id uuid, name text NOT NULL, aliases text[], groups text[], is_competitor bool, entity_id uuid, role text, sort_order int, is_active bool, created_at)`
  - `curated_groups(key text NOT NULL, label text NOT NULL, kind text NOT NULL, display_mode text NOT NULL default 'always', sort_order int, is_active bool, created_at)`
- **`/admin/companies` 는 nav 에 `disabled` 자리만 있고 라우트 파일이 없다.** 여기에 만든다.
- 읽는 곳 5군데: `entities/major-companies.ts`(서비스 기업동향) ·
  `competitor-weekly/generate.ts` · `crawler/orchestrator.ts`(회사 seed) ·
  `insight/generate.ts`(카드 생성 대상) · `company-documents/dart-corpcode/resolve`.

### ⚠️ 이 화면이 만들 수 있는 사고 두 가지

**① `name` 을 바꾸면 과거 카드가 서비스에서 사라진다.**
`major-companies.ts` 가 `insight_cards.topic`(문자열)을 `curated_companies.name` 과
**소문자 완전일치**로 조인한다. FK 가 아니다. 이름을 고치는 순간 그 회사의 과거 주간 시사점이
전부 고아가 된다. 게다가 `name`·`aliases` 는 **크롤 검색 시드**라 수집 대상도 바뀐다.

**② `curated_groups.key` 를 바꾸면 소속 기업이 그룹에서 빠진다.**
`curated_companies.groups` 는 `key` 문자열 배열이고 **FK 가 없다.**

→ 아래 3)·4) 의 가드는 선택이 아니다.

## 작업

### 1) 화면

- `src/app/admin/companies/page.tsx` 신설. `AdminTabShell` 2탭:
  `{ value: 'companies', label: '기업' }` · `{ value: 'groups', label: '그룹' }`
- `nav.ts`: **실험실 그룹의 `disabled` `/admin/companies` 항목을 제거**하고,
  **기업동향 그룹**에 활성 항목으로 넣는다. 위치는 `기업 주간 시사점` **다음**.
  description 에 "서비스 기업동향에 노출되는 주요기업·그룹을 관리합니다" 를 쓴다.

### 2) API

- `src/app/api/admin/curated/companies/route.ts` — GET(목록) / POST(생성)
- `src/app/api/admin/curated/companies/[id]/route.ts` — PATCH / DELETE
- `src/app/api/admin/curated/groups/route.ts` — GET / POST
- `src/app/api/admin/curated/groups/[key]/route.ts` — PATCH / DELETE
- 전부 `verifyAdminRequest({ capability: 'manage_sources' })` 로 시작한다.
- 입력 검증
  - `name`·`label`·`key`: trim 후 빈 문자열이면 400.
  - `kind` 는 `watchlist | competitor`, `display_mode` 는 `always | on_issue` 만 허용(그 외 400).
  - `aliases`·`groups` 는 문자열 배열. trim + 빈 값 제거 + 중복 제거.
  - `groups` 의 각 값이 **실재하는 `curated_groups.key` 인지 서버에서 확인**한다.
    없는 key 면 400. 자유 입력을 그대로 저장하지 말 것.
  - 그 외 필드는 버린다. 요청 본문 패스스루 금지.
  - `entity_id`·`role` 은 이번 범위에서 **읽기 전용**(표시만, 편집 없음).
- 목록 조회에 `.limit()` 을 넣는다(40행·12행이지만 체크리스트 항목).

### 3) `name` 변경 가드 (사고 ①)

- 기업 PATCH 에서 `name` 이 바뀌면, 서버가 **옛 이름으로 된 `insight_cards`(scope='company',
  topic=옛이름) 건수를 `count:'exact', head:true` 로 세어** 응답에 담는다.
- 화면은 저장 **전에** `useAdminConfirm()` 으로 확인을 받고, 문구에 그 건수를 넣는다:
  "이름을 바꾸면 옛 이름으로 생성된 주간 시사점 N건이 서비스 기업동향에서 보이지 않게 됩니다."
  → **건수를 먼저 받아야 하므로**, 화면에서 `?probeName=<새이름>` 같은 조회를 따로 하거나
  PATCH 를 2단계(확인용 count 조회 → 실제 저장)로 나눈다. 구현 방식은 자유지만
  **확인창에 실제 숫자가 떠야 한다.** 추정치·고정 문구 금지.
- ⚠️ **과거 카드의 `topic` 을 자동으로 일괄 수정하지 말 것.** `contents` 가 아닌 다른 테이블이지만
  일괄 UPDATE 는 별도 판단이 필요하다. 이번엔 **경고만** 한다.

### 4) `curated_groups.key` (사고 ②)

- **`key` 는 생성 시에만 정할 수 있고, 수정은 불가**로 막는다(입력 필드 disabled).
  바꾸려면 새로 만들고 기업의 `groups` 를 옮기게 한다.
- 그룹 DELETE 는 **그 key 를 참조하는 기업 수를 먼저 세어** 0이 아니면 400 으로 거부하고
  건수를 메시지에 담는다.

### 5) 삭제보다 비활성

- 기업·그룹 모두 목록의 기본 동작은 **`is_active` 토글**이다.
- 하드 DELETE 는 별도 버튼 + `useAdminConfirm({ destructive: true })`.
  기업 삭제 확인 문구에 **그 이름의 `insight_cards` 건수**를 넣는다.

### 6) 목록 UI

- `AdminTable` 사용. 기업: 이름 · 별칭 · 그룹(label 로 표시) · 경쟁사 · 정렬 · 활성 · 관리.
  그룹: key · label · kind · display_mode · 정렬 · 활성 · 관리.
- `groups` 편집은 **`curated_groups` 에서 불러온 목록의 다중 선택**으로 한다(자유 입력 금지).
- `sort_order` 는 숫자 입력으로 충분하다. 드래그 정렬은 이번 범위 밖.

## 하지 않을 것

- DDL·SQL, FK 추가, `insight_cards.topic` 일괄 수정
- `entity_id`·`role` 편집
- 서비스(사용자) 화면 수정
- 생성 로직(`generateCompanyInsightCards`)·크롤러 변경
- 드래그 정렬, 일괄 가져오기(CSV)

## 검증

1. `npx tsc --noEmit` / `npx eslint`(경고 0건) / `npm run build`
2. 사이드바 기업동향 그룹에 "주요기업"이 활성으로 뜨고, **실험실의 준비중 항목은 사라졌는지**
3. 기업 40건 · 그룹 12건이 목록에 다 나오는지
4. **이름 변경 확인창에 실제 카드 건수가 뜨는지** — 실제 `insight_cards` 건수와 대조할 것
5. 그룹 `key` 입력이 수정 모드에서 잠기는지
6. 소속 기업이 있는 그룹을 삭제하면 400 과 건수가 뜨는지
7. `groups` 에 없는 key 를 API 로 직접 보내면 400 인지(화면 우회 가드)
8. `is_active=false` 로 바꾼 기업이 **서비스 기업동향에서 사라지는지**(`major-companies.ts` 가
   `is_active` 로 필터한다 — 회귀 가드)
