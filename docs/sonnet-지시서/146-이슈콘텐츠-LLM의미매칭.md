## 0. 한 줄

이슈-콘텐츠 자동배정이 지금은 **순수 substring/ILIKE 매칭**(키워드가 본문에 글자 그대로 있으면 무조건 배정)이라 오탐이 많다. 키워드 매칭은 **싼 후보 추림(recall)** 으로 그대로 두고, 그 위에 **LLM 의미 검증(precision) 레이어**를 한 겹 얹어 "키워드는 걸렸지만 주제가 다른" 콘텐츠를 걸러낸다. 키 없으면 기존 동작 그대로(회귀 0).

## 1. 현행 진단 (검증된 코드 사실)

자동배정 경로 2곳, 둘 다 글자 단위 매칭:

1. **크롤 시점** — `src/lib/crawler/orchestrator.ts:519~538` → `matchIssues(title, body, issueList)` (`src/lib/crawler/quality.ts:139~144`): `\`${title} ${body}\`.toLowerCase().includes(kw.toLowerCase())`. 매칭된 issue_id → `issue_contents` upsert(source `'rule'`).
2. **어드민 재배정** — `src/components/admin/IssueManager.tsx:325~380` `handleRematch`: match_keywords 각각 `title.ilike.%kw%,summary_ko.ilike.%kw%`(클라이언트 직접 supabase) → 후보 합집합 → `issue_contents` upsert(source `'rule'`).

문제: "AI"·"통신" 같은 광역 키워드가 무관 기사까지 끌어옴. 글자가 안 겹치지만 같은 테마인 기사는 놓침. 의미 판단 부재.

**이번 슬라이스 범위 = 어드민 재배정 경로(2)를 서버 라우트로 옮기고 LLM 검증을 추가**한다. 크롤 시점(1)은 per-item LLM이 비싸므로 **이번엔 손대지 않음**(현행 substring = 싼 1차 recall로 유지). cron/크롤 배선은 §6 v2.

## 2. DB / SQL

**스키마 변경 없음. SQL 핸드오프 없음.** `issue_contents.source` 는 text이고 `'claude'` 값은 이미 후보생성(135)에서 쓰임. onConflict 키 `'issue_id,content_id'` 그대로.

## 3. 구현

### 3-1. `src/lib/issues/semantic-match.ts` (신규, server-only)

재사용 가능한 의미 필터. 패턴은 `generate-candidates.ts`(llmComplete('classify')·looseJsonParse·환각가드·graceful) 미러.

```ts
import 'server-only'
import { llmComplete } from '@/lib/llm'
import { looseJsonParse } from '@/lib/llm/parse'

export interface SemanticCandidate {
  id: string
  title: string
  summary_ko: string | null
}

export interface SemanticFilterResult {
  matchedIds: string[]
  mode: 'llm' | 'keyword-fallback'   // 호출부 메시지·source 표기용
}

const BATCH_SIZE = 20          // 프롬프트당 후보 수
const MAX_BATCHES = 6          // 예산 캡 (최대 120건 검증)

const SYSTEM_PROMPT = `당신은 LG U+ B2B 시장 인텔리전스 분석가다.
하나의 "이슈(테마)"와 기사 목록이 주어진다. 각 기사가 이 이슈 테마에
**실제로 속하는지** 의미로 판단하라. 키워드가 글자만 겹치고 주제가 다르면 제외.

규칙:
1. 제공된 id만 출력. 새 id 지어내기 금지.
2. 애매하면 제외(정밀도 우선).
3. JSON 객체 1개만 출력. 설명 금지.

출력 스키마:
{ "matched_ids": ["속하는 기사 id만"] }`

function buildUserPrompt(
  issue: { title: string; summary: string | null },
  batch: SemanticCandidate[],
): string {
  const lines = batch
    .map(c => `[${c.id}] ${c.title}` + (c.summary_ko ? `\n요약: ${c.summary_ko}` : ''))
    .join('\n\n')
  return `이슈: ${issue.title}` +
    (issue.summary ? `\n이슈 요약: ${issue.summary}` : '') +
    `\n\n기사 목록:\n${lines}`
}

function parseMatchedIds(raw: string, validIds: Set<string>): string[] | null {
  const parsed = looseJsonParse(raw)
  if (!parsed || typeof parsed !== 'object' || Array.isArray(parsed)) return null
  const arr = (parsed as Record<string, unknown>).matched_ids
  if (!Array.isArray(arr)) return null
  return arr.filter((x): x is string => typeof x === 'string' && validIds.has(x))
}

/**
 * 키워드로 추린 후보를 LLM으로 의미 검증.
 * - LLM 키 없음/전 배치 실패 → 후보 전체 통과(키워드 폴백, 회귀 0).
 * - 일부 배치만 실패 → 성공 배치는 LLM 결과, 실패 배치는 후보 통과(보수적 recall 유지).
 */
export async function semanticFilterIssueContents(
  issue: { title: string; summary: string | null },
  candidates: SemanticCandidate[],
): Promise<SemanticFilterResult> {
  if (candidates.length === 0) return { matchedIds: [], mode: 'keyword-fallback' }

  const batches: SemanticCandidate[][] = []
  for (let i = 0; i < candidates.length && batches.length < MAX_BATCHES; i += BATCH_SIZE) {
    batches.push(candidates.slice(i, i + BATCH_SIZE))
  }
  // 예산 초과분(MAX_BATCHES*BATCH_SIZE 이후)은 검증 없이 후보 통과
  const overflow = candidates.slice(MAX_BATCHES * BATCH_SIZE).map(c => c.id)

  const matched = new Set<string>(overflow)
  let anyLlmOk = false

  for (const batch of batches) {
    const validIds = new Set(batch.map(c => c.id))
    try {
      const raw = await llmComplete('classify', SYSTEM_PROMPT, buildUserPrompt(issue, batch))
      const ids = raw ? parseMatchedIds(raw, validIds) : null
      if (ids) {
        anyLlmOk = true
        ids.forEach(id => matched.add(id))
      } else {
        // 이 배치 LLM 실패 → 보수적으로 후보 통과
        batch.forEach(c => matched.add(c.id))
      }
    } catch {
      batch.forEach(c => matched.add(c.id))
    }
  }

  return {
    matchedIds: [...matched],
    mode: anyLlmOk ? 'llm' : 'keyword-fallback',
  }
}
```

설계 노트:
- **graceful 원칙**: LLM이 통째로 죽으면 결과 = 후보 전체 = 현행 키워드 동작과 동일(회귀 0). 부분 실패도 recall 손실 없게 후보 통과.
- **환각 가드**: `validIds.has(x)` 로 배치 밖 id 차단.
- **예산 캡**: 후보 300건이어도 LLM 호출 ≤ 6회.

### 3-2. `src/app/api/admin/issues/[id]/rematch/route.ts` (신규)

어드민 재배정을 서버화 + LLM 검증. verifyAdmin은 `candidates/generate/route.ts` 의 것을 그대로 복제(같은 패턴).

```ts
import { NextRequest, NextResponse } from 'next/server'
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'
import { createAdminClient } from '@/lib/supabase/admin'
import { semanticFilterIssueContents, type SemanticCandidate } from '@/lib/issues/semantic-match'

export const runtime = 'nodejs'
export const dynamic = 'force-dynamic'
export const maxDuration = 120

// verifyAdmin: candidates/generate/route.ts 와 동일 구현 복제
// ... (생략: 그 파일 11~44행 그대로)

export async function POST(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> },
) {
  const { error: authError } = await verifyAdmin()
  if (authError) return authError

  const { id } = await params
  const admin = createAdminClient()

  // 이슈 로드
  const { data: issueRow } = await admin
    .from('issues')
    .select('id, title, summary, match_keywords')
    .eq('id', id)
    .single()
  if (!issueRow) return NextResponse.json({ error: '이슈 없음' }, { status: 404 })

  const issue = issueRow as { id: string; title: string; summary: string | null; match_keywords: string[] }
  const keywords = (issue.match_keywords ?? []).filter(Boolean)
  if (keywords.length === 0) {
    return NextResponse.json({ error: 'match_keywords 가 없습니다.' }, { status: 400 })
  }

  // 1) 키워드 ILIKE 후보 추림 (published 만)
  const candMap = new Map<string, SemanticCandidate>()
  for (const kw of keywords) {
    const safe = kw.replace(/[%,]/g, ' ').trim()
    if (!safe) continue
    const { data } = await admin
      .from('contents')
      .select('id, title, summary_ko')
      .eq('status', 'published')
      .or(`title.ilike.%${safe}%,summary_ko.ilike.%${safe}%`)
      .limit(300)
    for (const row of (data ?? []) as SemanticCandidate[]) {
      if (!candMap.has(row.id)) candMap.set(row.id, row)
    }
  }
  const candidates = [...candMap.values()].slice(0, 300)
  if (candidates.length === 0) {
    return NextResponse.json({ candidateCount: 0, matchedCount: 0, mode: 'keyword-fallback' })
  }

  // 2) LLM 의미 검증
  const { matchedIds, mode } = await semanticFilterIssueContents(
    { title: issue.title, summary: issue.summary },
    candidates,
  )

  // 3) issue_contents upsert (LLM 확정분은 source 'claude', 폴백은 'rule')
  if (matchedIds.length > 0) {
    const rows = matchedIds.map(content_id => ({
      issue_id: id,
      content_id,
      source: mode === 'llm' ? 'claude' : 'rule',
    }))
    const { error: upErr } = await admin
      .from('issue_contents')
      .upsert(rows, { onConflict: 'issue_id,content_id', ignoreDuplicates: true })
    if (upErr) {
      console.error('[issues/rematch] upsert 실패:', upErr.message)
      return NextResponse.json({ error: '배정 저장 실패' }, { status: 500 })
    }
  }

  return NextResponse.json({
    candidateCount: candidates.length,
    matchedCount: matchedIds.length,
    mode,
  })
}
```

주의:
- `.or()` 인젝션 가드: 키워드에서 `%`·`,` 제거(`safe`). PostgREST `or` 문법 깨짐 방지.
- 후보 300 캡은 기존 클라이언트 로직과 동일.

### 3-3. `src/components/admin/IssueManager.tsx` — `handleRematch` 서버라우트 호출로 교체

기존 클라이언트 직접 supabase 블록(후보 ILIKE + upsert, 대략 334~380행)을 새 라우트 fetch로 대체. 시그니처·상태(rematchingId·rematchMsg)·버튼은 유지.

```ts
const handleRematch = async (issue: IssueRow) => {
  if (issue.match_keywords.length === 0) {
    setRematchMsg({ id: issue.id, text: 'match_keywords 가 없습니다. 수정에서 키워드를 등록하세요.', ok: false })
    return
  }
  setRematchingId(issue.id)
  setRematchMsg(null)
  try {
    const res = await fetch(`/api/admin/issues/${issue.id}/rematch`, { method: 'POST' })
    const json = await res.json()
    if (!res.ok) {
      setRematchMsg({ id: issue.id, text: json.error ?? '재배정 실패', ok: false })
      return
    }
    if (json.candidateCount === 0) {
      setRematchMsg({ id: issue.id, text: '키워드에 매칭되는 콘텐츠가 없습니다.', ok: false })
      return
    }
    const modeLabel = json.mode === 'llm' ? '의미 검증' : '키워드'
    setRematchMsg({
      id: issue.id,
      text: `후보 ${json.candidateCount}건 중 ${json.matchedCount}건 배정 (${modeLabel})`,
      ok: true,
    })
  } catch (e) {
    setRematchMsg({ id: issue.id, text: e instanceof Error ? e.message : '재배정 실패', ok: false })
  } finally {
    setRematchingId(null)
  }
}
```

- 기존 `supabase`·`Promise.all` 후보 로직 제거. 다른 곳에서 `supabase` import가 계속 쓰이면 import는 유지(미사용 시 lint 에러 → 제거).
- 버튼 라벨/툴팁(`키워드로 재배정` 등)·"match_keywords 없음" 비활성 분기는 그대로.

## 4. 회귀 가드 / 비기능 요건

- LLM 키 없음 → `mode: 'keyword-fallback'`, 후보 전체 배정 = 현행과 동일. UI 메시지에 "(키워드)" 표기.
- 크롤 시점 자동배정(orchestrator `matchIssues`)·후보생성(135)·이슈 상세·activity 집계 **무변경**.
- 하드코딩 hex 색 0 (이 슬라이스는 UI 색 추가 없음).
- 새 의존성 없음.
