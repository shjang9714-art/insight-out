## 0. 목표 (한 줄)
해시 완전일치로 못 잡는 **제목 90% 이상 유사한 near-duplicate**(같은 사건 다른 보도)를 찾아, 버리지 않고 **`cluster_id`로 묶어 "대표 1건 + 관련 N건"** 구조로 적재한다.

## 1. 배경·경계 (#4와의 역할 구분)
- **#4(완료)**: 정규화 URL **존재확인(`findByUrl`)** + `body_hash`/`title_hash` **완전일치** 중복 → 스킵. 적재는 `insert`(부분 유니크 인덱스 때문에 upsert 아님), URL 중복(23505)도 멱등 스킵. (진짜 중복 제거)
- **#12(이번)**: 완전일치는 아니지만 **제목 토큰 유사도 ≥ 0.9** → near-dup. **스킵하지 않고** `cluster_id`를 부여해 그룹으로 적재. (PRD 4.4 "관련 기사 N건")
- 의존성 추가 금지(외부 라이브러리 없이 토큰 기반 자가 구현 — 설계 §3.1 A안).
- 임베딩/pgvector/TF-IDF는 범위 밖(Phase 4 트렌드보드).

## 2. cluster_id 규칙 (스키마는 이미 존재)
`contents.cluster_id uuid → contents.id` (self-ref, nullable). 의미:
- `null` = 단독 기사(아직 그룹 없음).
- 값 = **그룹 대표 content의 id**. 대표 자신도 `cluster_id = 자기 id`로 설정(그래야 "그룹"으로 쿼리 가능).
- **대표 선정**: 그룹 내 **가장 이른 `published_at`** (동률이면 먼저 적재된 것 = 기존 행). 새 기사가 기존 대표보다 더 이르면 대표를 새 기사로 승계하지 말 것(이번 범위에선 단순화 — 기존 대표 유지, 새 기사는 관련 N건으로 편입).

## 3. 할 일

### 3.1 `src/lib/crawler/similarity.ts` (신규)
- `tokenize(title: string): string[]` — 소문자화 후 공백 분리, 1글자 토큰·불용 기호 제거. 한국어는 형태소 분석 없이 공백 기준(설계 §3.1 A: 단순 토큰화).
- `jaccard(a: string[], b: string[]): number` — 토큰 집합 교집합/합집합.
- `titleSimilarity(t1: string, t2: string): number` — Jaccard 기반 0~1 점수. (옵션: 토큰 길이 짧을 때 보정 위해 정규화 편집거리와 `max` 결합 가능하나, 1차는 Jaccard 단독으로 충분.)
- `SIMILARITY_THRESHOLD = 0.9` 상수 export.

### 3.2 `src/lib/crawler/dedup.ts` (수정 — 후보 조회 추가)
- `findSimilarCandidates(admin, publishedAt, sinceDays=2)`: `contents`에서 **최근 N일**(`published_at` 또는 `collected_at` 기준, 기본 2일) + `category='뉴스'` 행의 `{ id, title, published_at, cluster_id }`만 조회. 전수비교 회피용 1차 좁히기. (날짜 인덱스 `contents_published_at_idx` 활용.)

### 3.3 `src/lib/crawler/orchestrator.ts` (수정 — 한 단계 삽입)
> ⚠️ 현재 `crawlOne` 의 dedup 순서(오늘 기준): **`findByUrl` → `findByBodyHash` → `findByTitleHash`(전부 miss면) → `row` 구성 → `admin.from('contents').insert(row)`**. (upsert 아님 — `row` 객체에 필드 추가가 곧 적재값)

이 3개 완전일치 체크를 **모두 통과한 직후, `const row = {...}` 구성 전에** near-dup 그룹핑을 삽입하고, 그 결과 `clusterId` 를 **`row` 객체에 `cluster_id: clusterId` 로 포함**한다(insert 라 그대로 적재됨):
```
// (findByUrl/findByBodyHash/findByTitleHash 통과 = 완전중복 아님)

// 추가: near-dup 그룹핑
const candidates = await findSimilarCandidates(admin, item.published_at)
const match = candidates.find(c => titleSimilarity(c.title, item.title) >= SIMILARITY_THRESHOLD)
let clusterId: string | null = null
if (match) {
  const repId = match.cluster_id ?? match.id      // 그룹이면 그 대표, 아니면 match 자신
  if (!match.cluster_id) {                          // match가 단독이면 대표로 승격(자기참조)
    await admin.from('contents').update({ cluster_id: repId }).eq('id', match.id)
  }
  clusterId = repId
  console.log(`[크롤러] 관련기사 그룹 편입: "${item.title}" → cluster ${repId}`)
}

const row = {
  category: '뉴스' as const,
  // …기존 필드 그대로…
  cluster_id: clusterId,   // ← 신규: null이면 단독, 값이면 그룹 편입
  // published_at, collected_at …
}
const { error: insertError } = await admin.from('contents').insert(row)
// 이하 23505/에러 처리는 기존 그대로
```
- `cluster_id` 는 이제 `insert` 의 `row` 에 **직접 포함**(과거 upsert 제외 로직은 폐기됨 — 신규 행에만 들어가므로 안전).
- near-dup 도 `inserted` 로 카운트(별도 카운트 신설 금지 — API 계약 유지).
- 기존 `row` 주석("status·cluster_id·… payload 제외")에서 **`cluster_id` 는 빼서** 갱신.

### 3.4 건드리지 말 것
