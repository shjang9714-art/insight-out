## 1. 현행 진단 (검증된 코드 사실)
- `src/app/login/page.tsx`(client): `signInWithOAuth({provider:'google'})` + `signInWithPassword({email,password})` 병행. 로고 `/brand/logo-hero.png`(846×1392, 실존). 배경 `bg-gray-50`, 카드 `bg-white`. **문제: 전부 옅은 회색 — 대비·시인성 약함, Google 버튼 회색이라 비활성처럼 보임.**

## 2. 구현 — `src/app/login/page.tsx` 전면 재작성

### 2-1. 인증 로직 (2단계 OTP)
- **1단계(이메일 제출)**: 
  ```ts
  const { error } = await supabase.auth.signInWithOtp({
    email,
    options: { shouldCreateUser: true },   // 최초 임직원 가입 허용(도메인 Hook이 게이팅)
  })
  ```
  성공 → `step='otp'`로 전환. 실패 메시지 처리(아래 3). `shouldCreateUser:true`라 신규는 생성 시 Hook이 도메인 검사 → 비도메인은 여기서 거부 메시지.
- **2단계(코드 확인)**:
  ```ts
  const { error } = await supabase.auth.verifyOtp({
    email, token: code, type: 'email',
  })
  if (!error) { router.push('/dashboard'); router.refresh() }
  ```
- **보조 액션**: `코드 재전송`(1단계 재호출, 쿨다운 30~60s 버튼 비활성), `이메일 변경`(step='email' 복귀, code 초기화).
- 코드 입력은 6자리 숫자(`inputMode="numeric"`, `maxLength={6}`, 붙여넣기 허용, 6자리 채워지면 자동 제출 선택).

### 2-2. 도메인 UX(소프트 힌트 — 하드블록 금지)
- 이메일 인풋 placeholder `name@lguplus.co.kr`, 하단 소캡션 `사내 이메일(@lguplus.co.kr)로 로그인하세요`.
- **클라이언트에서 도메인 하드검증 금지**(기존 예외계정/allowlist가 막힘). 도메인 판정은 서버 Hook이 담당. 단, 완전 빈/형식오류만 클라이언트 가드.

### 2-3. 프리미엄 애니메이션 디자인 (라이트 기준, 다크 호환)
목업 `docs/mockups/login-premium-mockup.html`의 톤을 Tailwind로 이식:
- **배경**: 은은한 오로라(앰버 #F5B301 / 마젠타 #E0338A / 라일락) 블롭 3개가 `blur-3xl`로 느리게 드리프트 + 위로 떠오르는 미세 입자(canvas 또는 CSS). `prefers-reduced-motion` 시 정지.
- **로고**: 실제 `/brand/logo-hero.png` 유지 + 은은한 글로우/부유(`animate` float, halo). 스플래시 전환 대비 중앙 정렬·여백 넉넉히.
- **헤드라인**: `흩어진 인텔리전스를 하나의 흐름으로` — **짙은 잉크(text-foreground)로 대비 강화**(현행 회색 탈피). 서브 `Intelligence in. Insight out.` italic 뮤트.
- **카드**: `bg-white`, `rounded-[22px]`, 부드러운 큰 그림자(마젠타 tint 은은), 진입 시 순차 fade-up.
- **CTA**: 이메일 단계 `인증 코드 받기`, OTP 단계 `확인` — **프리미엄 다크 버튼**(잉크 그라디언트, hover lift, 로딩 스피너). 회색 비활성처럼 보이지 않게 대비 확보.
- 키프레임은 `styled-jsx`(`<style jsx>`) 또는 파일 스코프 `<style>`로. Tailwind 유틸+최소 CSS 혼용 가능.

### 2-4. 상태·구조

- 로딩 중 버튼 비활성·스피너. 에러 배너는 카드 상단(현행 red-* 대신 `--destructive` 토큰, 218 톤).
- 기존 `Suspense`/`useSearchParams`(callback error) 구조 유지 가능.

## 3. 에러 처리 (사용자 친화 한국어)
- 도메인 거부(Hook, http 403 메시지 전파): `사내 이메일(@lguplus.co.kr) 계정만 로그인할 수 있습니다.` (Hook message를 그대로 노출하거나, 코드/상태로 매핑).
- 코드 불일치/만료: `인증 코드가 올바르지 않거나 만료되었습니다. 다시 시도해 주세요.`
- 레이트리밋(429): `요청이 많습니다. 잠시 후 다시 시도해 주세요.`
- 전송 실패/네트워크: 일반 메시지 + 재시도 안내.

## 4. 회귀 가드
- `signInWithOtp`/`verifyOtp`는 Supabase JS 표준 — 기존 `createClient()`(client) 그대로 사용.
- **OTP는 콜백 미사용** → `/auth/callback`·미들웨어 publicPaths 변경 불필요.
- 로그인 성공 후 `router.push('/dashboard')`+`refresh()` → 미들웨어가 온보딩/승인 게이팅(신규는 SQL 239로 자동승인 → 바로 온보딩→대시보드).
- 기존 사용자(비번/구글로 만들어진 계정) 동일 이메일로 OTP 로그인 가능(신원 동일). 비번/구글 백엔드는 남지만 UI 제거로 미노출.
- 로고·헤드라인 텍스트·라우팅 불변. 다크모드에서 오로라·도트·버튼 대비 확인.
- `prefers-reduced-motion`: 애니메이션 정지(접근성).
