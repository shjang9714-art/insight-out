## 배경 (Explore 매핑 2026-06-22)

이슈 상세는 이미 70% 구현: 타임라인(일자별)·논조 분포(정적 막대)·관련 엔티티(상위30)·유사이슈(105)·카테고리 샘플. **빠진 4가지**:
1. **content_signals 미연결** — 1,159 신호(`signal_type`: 경쟁사동향/규제·정부/신제품·출시/투자·M&A/기술트렌드/시장지표/파트너십/인사·조직)가 이슈 상세에서 안 쓰임.
2. **논조 시계열 추세 없음** — 정적 비율만, 악화/개선 흐름 안 보임.
3. **근거 드릴다운 없음** — 섹션 클릭 → 필터된 원본 목록 없음.
4. **AI 종합 없음** — `issues.summary`가 수동 한 줄. 모인 수십 건을 LLM이 종합한 브리핑 부재.

이슈 상세를 **증거(A: 데이터 스캐폴드) + 종합(B: AI 브리핑)** 산출물로 완성. (이슈 12개·수동 생성 상태 → 다음 thread = LLM 이슈 자동 큐레이션. 본 지시서는 상세 완성에 한정.)

데이터: `issues`(id·title·summary·status·match_keywords) · `issue_contents`(issue_id·content_id) · `contents`(sentiment·category·published_at·summary_ko·sources) · `content_signals`(content_id·signal_type·score) · `content_entities`(content_id·entity_id).

## A. 증거 스캐폴드 (서버 쿼리 + UI)

### A-1. content_signals 통합 — `issues/[id]/page.tsx`
- 기존 `contentIds`(issue_contents에서 추출) 확보 후, 신호 조회 추가:
  ```ts
  const { data: signals } = await admin
    .from('content_signals')
    .select('content_id, signal_type, score')
    .in('content_id', contentIds)
  ```
- **집계**: `signal_type`별 건수·합산 score → 상위순. **"신호 구성" 섹션** 신규(논조 분포 옆): 각 signal_type 배지 + 건수 막대(예: `경쟁사동향 12 · 규제·정부 5 · 투자·M&A 3`). 기존 `AdminFilterChip`/배지 톤 재사용, 하드코딩 hex 금지.
- **타임라인 행 배지**: content_id→대표 signal_type(score 최대) 맵 구성 → 타임라인 각 콘텐츠에 작은 signal 배지 추가(라인 438~503 영역).

### A-2. 논조 시계열 추세
- 이미 가진 issue_contents+contents(sentiment·published_at/collected_at)에서 **일자(KST)별 긍/중/부 집계** 산출(서버). 날짜 부족 시 collected_at 폴백.
- **클라이언트 미니 차트** `src/components/issues/IssueSentimentTrend.tsx` 신규(서버 페이지가 집계 배열 prop 주입). Recharts(기존 의존성) **stacked bar 또는 line**(일자 x축, 긍/부 누적). 데이터 ≤1일이면 차트 생략하고 정적 분포만.
- **추세 방향 라벨**: 최근 절반 vs 이전 절반 부정비율 비교 → `개선/악화/유지`(IssueBoardView `changeFlag` 개념 재사용). 섹션 헤더에 표기.

### A-3. 근거 드릴다운 — `src/components/issues/IssueEvidenceExplorer.tsx` (신규, 클라이언트)
- 서버가 이슈 콘텐츠 배열(id·title·category·sentiment·signal_type·published_at·source·summary_ko·entityIds)을 prop 주입.
- **facet 칩 행**: 카테고리 / 논조(긍·중·부) / 신호유형 / (선택)엔티티. 칩 클릭 → 목록 클라이언트 필터(복수 조건 AND). 빈 결과 시 `AdminEmptyState` 톤 안내.
- 각 행 = 제목 링크(`/dashboard/contents/{id}`) + 메타(논조·신호·출처·일자). 기존 타임라인을 이 explorer로 대체하거나 하단 "근거 탐색" 섹션으로 병치(둘 중 택1, 타임라인 정보 손실 없게).

## B. AI 이슈 브리핑 (LLM) — 헤드라인

### B-1. 생성 로직 — `src/lib/issues/brief.ts` (신규)
`insights/generate.ts` 패턴 미러(citation 검증·환각가드·graceful·멱등).
```ts
export interface IssueBrief {
  situation: string      // 현황 2~3문장
  drivers: string[]      // 핵심 동인 2~4
  sentiment_read: string // 논조 해석 1~2문장
  implications: string[] // 시사점 2~3
  citations: string[]    // 근거 content_id (검증 통과분만)
}
export async function generateIssueBrief(admin, issueId): Promise<IssueBrief | null>
```
- 입력 수집: 이슈 + issue_contents→contents **상위 ~40건**(published_at desc), 각 `{content_id, title, summary_ko, sentiment, signal_type}`만(본문 미전송=토큰 절약). 신호 구성·논조 분포 요약도 프롬프트에 동봉.
- 프롬프트: "아래 콘텐츠들을 근거로 이 이슈의 **현황·핵심 동인·논조 해석·시사점**을 한국어로 종합. 추측 금지, 제공된 사실만. 각 주장에 근거 content_id 명시. JSON으로만 출력." 스키마 명시.
- 호출: `llmComplete('report', prompt)` (종합 품질). 출력 `looseJsonParse`(126).
- **환각 가드**: `citations`의 각 content_id가 이슈 콘텐츠 집합에 존재하는지 검증, 미존재 제거. drivers/implications가 비면 null 반환(부분 실패 graceful).
- 키 없음/실패 → null(throw 금지).

### B-2. 저장 — SQL 핸드오프 `docs/sql-handoff/131-issue-brief-컬럼.sql` (신규)
```sql
-- 131: issues AI 브리핑 캐시 컬럼. 멱등.
alter table public.issues
  add column if not exists brief jsonb,
  add column if not exists brief_generated_at timestamptz,
  add column if not exists brief_model text;
```
- `generateIssueBrief` 성공 시 `update issues set brief=<json>, brief_generated_at=now(), brief_model=<model>`.
- **graceful degrade(130 패턴)**: 상세 페이지/어드민 select에서 brief 컬럼이 없으면(42703) brief 없이 재조회 → AI 섹션은 "브리핑 미생성" 폴백.

### B-3. 어드민 트리거 — `POST /api/admin/issues/[id]/brief`
- 어드민 게이트(기존 verifyAdmin 패턴), `runtime nodejs`, `maxDuration 60`(LLM 1콜).
- `generateIssueBrief(admin, id)` → 저장 → `{ brief }` 반환. 키 없음/실패 시 503 + 사유.
- `IssueManager.tsx` 각 이슈 행/편집부에 **"AI 브리핑 생성"** 버튼(생성 중 스피너·결과 표시·재생성 가능). (인사이트 카드 생성 UX와 통일.)

### B-4. 사용자 표시 — `issues/[id]/page.tsx` 상단 "AI 브리핑" 섹션
- brief 있으면: 현황 → 핵심 동인(목록) → 논조 해석 → 시사점(목록) 렌더. citations는 근거 칩(제목 링크). `brief_generated_at` 표기.
- brief 없으면: 기존 `summary` 폴백 또는 "브리핑이 아직 생성되지 않았습니다"(관리자 안내). 하드코딩 색 금지.
