## 3. 구현

### 3-1. 탭 라우팅 — `?view=` 쿼리
`/dashboard/issues?view=briefing|issues|mine`. 기본값 `briefing`.
- `issues/page.tsx`: `searchParams`에서 `view` 읽어 `<AiInsightsView view={view} />`로 전달. 잘못된 값은 `briefing`으로 폴백.

### 3-2. 2차 탭 바 — `AiInsightTabs.tsx` (신규, 클라)
`AnalysisTabs` 스타일 재사용. 탭 정의:
```tsx
const TABS = [
  { id: 'briefing', label: '브리핑' },
  { id: 'issues',   label: '이슈' },
  { id: 'mine',     label: '내 관점' },
]
```
- `href={`/dashboard/issues?view=${t.id}`}`, 활성 스타일은 `AnalysisTabs`와 동일(`bg-background … shadow-sm`).
- 활성 판정은 현재 `view`(클라에서 `useSearchParams`) 기준.

### 3-3. `AiInsightsView.tsx` — `view` prop 분기
시그니처: `async function AiInsightsView({ view = 'briefing' }: { view?: 'briefing' | 'issues' | 'mine' })`.
공통 데이터(현재 Promise.all)는 필요한 것만 유지하고, **탭별로 렌더 분기**:

- **브리핑** (`view==='briefing'`): ② AI 인사이트 카드(`InsightCardsSectionClient`) + ④ 뜨는 토픽/키워드. (※ 상단 브리핑 요약 카드는 지시서 162에서 추가 — 160에서는 자리만 비워둠.)
- **이슈** (`view==='issues'`): ⑤ 시장 주요 이슈(`IssueBoardClient cards={issueCards}`).
- **내 관점** (`view==='mine'`): 개인화 뷰(아래 3-4).

**제거**(이 파일에서 삭제 — 기업동향이 담당): ⑥ 경쟁사 동향 섹션, ⑦ 지식그래프 섹션, ③ 관심 기업 인사이트 섹션 및 관련 쿼리(`competitorNamesRes`/`competitorResults`, `entityTeaserRes`, `companyCardsRes`/`companyCards`/`companyInsightGroups`). → 미사용 import/변수 0 정리.

상단: 페이지 제목 아래 `<AiInsightTabs />` 렌더. `LensSwitcher`는 "내 관점" 탭 안으로 이동(개인화 성격) 또는 유지 — 메모리상 "렌즈" 용어 지양이므로 **표면 라벨에 '렌즈' 노출 금지**, 내부 컴포넌트 재사용은 가능.

### 3-4. "내 관점" 탭 초기 구성
설계안 §5 표 "내 관점 = 사용자 담당 업무 기준 해석". 160에서는 **기존 재료로 가능한 범위**만:
- 내 관심 키워드 트렌드: `classifiedKeywords` 중 `watched` 또는 담당 서비스 매칭만 필터(이미 `isWatched`·키워드 방향 ▲▽ 계산 있음).
- 내 관심 토픽 매칭 인사이트/이슈: 산업 인사이트 카드·이슈 중 사용자 관심 키워드와 겹치는 것 우선 노출.
- 미설정 사용자: 빈 상태 안내 + 마이페이지 링크(기존 147/158 넛지 톤과 일치, "렌즈" 용어 금지).
- 업무 시사점 문장 생성(자연어)은 **지시서 162 범위**(LLM/규칙). 160은 데이터·필터·빈상태까지.
