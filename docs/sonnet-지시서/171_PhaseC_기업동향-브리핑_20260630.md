## 1. Step 0 — 엔티티 연결 스키마 라이브 실측 (★차단 단계, 먼저 보고)

```sql
-- A. 엔티티 본체 테이블·컬럼
select table_name from information_schema.tables
where table_schema='public' and (table_name ilike '%entit%' or table_name ilike '%compan%');

select column_name, data_type, is_nullable
from information_schema.columns
where table_schema='public' and table_name='entities'   -- A 결과로 치환
order by ordinal_position;

-- B. 엔티티↔콘텐츠 / 엔티티↔이슈 연결 테이블 (이슈상세 "관련 엔티티"의 출처)
select table_name from information_schema.tables
where table_schema='public'
  and (table_name ilike '%entit%content%' or table_name ilike '%content%entit%'
       or table_name ilike '%entit%issue%' or table_name ilike '%issue%entit%'
       or table_name ilike '%mention%');

-- C. 그 연결 테이블 컬럼(예: content_entities)
select column_name, data_type from information_schema.columns
where table_schema='public' and table_name='content_entities'   -- B 결과로 치환
order by ordinal_position;

-- D. 엔티티 → 시그널 도달 경로 확인:
--    entity ─ (content_entities) ─ contents ─ (content_signals) 가 성립하는지 샘플 조인
select e.id, e.name, count(distinct cs.id) as signal_cnt
from entities e
join content_entities ce on ce.entity_id = e.id      -- 테이블/컬럼명 치환
join contents c          on c.id = ce.content_id
join content_signals cs  on cs.content_id = c.id
group by e.id, e.name
order by signal_cnt desc
limit 10;

-- E. 라이브 건수: entities, 연결테이블, 위 조인 결과
```

**보고할 분기 질문:**
1. 엔티티 본체 테이블명·주요 컬럼(name, type/category, 기타 메타)?
2. "관련 엔티티"의 연결 테이블은 무엇이고 **엔티티↔콘텐츠**인가 **엔티티↔이슈**인가(둘 다인가)?
3. 위 D 조인(엔티티→시그널)이 성립하나? 성립하면 #IA14 시그널 묶음을 **뷰로** 만들 수 있음.
4. 라이브 건수(엔티티 N, 시그널 보유 엔티티 N).

> Step 0 결과 보고 후 2장(뷰)·3~4장(UI) 진행.

## 2. 읽기 뷰 (Step 0에서 경로 확정 후)

엔티티별 시그널·이슈 집계를 매번 조인하지 않도록 읽기 뷰 1개를 권장한다. 컬럼/테이블명은 Step 0 결과로 치환.

파일: `supabase/2026-06-30-entity-signals-view.sql`

```sql
-- 엔티티별 시그널/콘텐츠 집계 (그레인: entity_id)
create or replace view public.entity_signal_summary as
select
  e.id                                        as entity_id,
  e.name,
  count(distinct c.id)                        as content_count,
  count(distinct cs.id)                       as signal_count,
  array_agg(distinct cs.signal_type::text)
    filter (where cs.signal_type is not null)  as signal_types,
  max(c.published_at)                          as last_seen
from public.entities e
join public.content_entities ce on ce.entity_id = e.id   -- Step0 치환
join public.contents c          on c.id = ce.content_id
left join public.content_signals cs on cs.content_id = c.id
group by e.id, e.name;

-- ★ GRANT 필수
grant select on public.entity_signal_summary to anon, authenticated;
```

> 엔티티↔이슈가 직접 연결이면(2번 분기) 이슈 묶음용 뷰(`entity_issues`)도 동일 패턴으로 추가. 둘 다면 두 뷰.
> 검증: `select * from entity_signal_summary order by signal_count desc limit 5;` 행 ≥ 1, PostgREST 노출 확인.

## 3. UI — #IA13 엔티티 한장 브리핑

위치: `/dashboard/entities` (기존 경쟁사 카드·관계지도 2차 탭은 유지·확장).

요구사항:
- 엔티티별 **요약 카드**: 이름, (있으면) 유형 배지, signal_count·content_count, `signal_types` 상위 배지(예: `경쟁사동향` `기술트렌드`), last_seen

## 4. UI — #IA14 기업별 이슈/시그널 묶음

위치: 엔티티 카드 클릭 시 펼침/상세 영역(신규 라우트 `/dashboard/entities/[id]`를 만들면 **빌드 매니페스트 등록 검증**).

요구사항:
- 선택 엔티티의 **시그널 묶음**: signal_type별 건수 바(이슈 상세의 "신호 구성" 위젯 스타일 재사용 가능) + 대표 콘텐츠 카드 리스트
- 엔티티↔이슈 연결이 있으면 **관련 이슈 리스트**(이슈 상세로 링크)
- 콘텐츠 카드는 Phase A `IssueEvidenceSection`의 카드 스타일 재사용(썸네일·출처·분류 배지·원문 링크)
- 0건 빈 상태 문구

> 논조 배지는 이번 차수 제외(sentiment 미채움). 백필 후 후속 차수에서 카드/요약에 추가.
