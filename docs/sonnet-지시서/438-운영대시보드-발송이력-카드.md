## 2. 구현

### 2.1 `src/app/admin/page.tsx` — 조회 추가
- `Promise.all` 배열에 추가(admin 클라이언트 있을 때만, failedJobsRes와 동일한 graceful):
```ts
admin
  ? admin.from('job_runs')
      .select('id, job_key, status, started_at, duration_ms, meta')
      .in('job_key', ['cron:ops-brief', 'cron:ops-weekly', 'cron:ops-alert'])
      .order('started_at', { ascending: false })
      .limit(30)
  : Promise.resolve({ data: [], error: null })
```
- 결과에서 **key별 최신 1건**을 뽑아 3개 요약(없으면 '실행 기록 없음'). `ready = !res.error`(42P01 → 카드 숨김).
- `AdminMailDispatchCard`에 `rows`(key별 최신) + `ready` 전달. 렌더 위치: `AdminFailedJobsCard` 다음 줄.

### 2.2 `src/components/admin/AdminMailDispatchCard.tsx` (신규, AdminFailedJobsCard 미러)
```ts
export interface MailRunRow {
  job_key: string
  status: string
  started_at: string
  duration_ms: number | null
  meta: Record<string, unknown> | null
}
interface Props { rows: MailRunRow[]; ready: boolean }
```
- `ready=false` → `return null`.
- 라벨 맵: `cron:ops-brief`='일일 운영 브리핑', `cron:ops-weekly`='주간 운영 리포트', `cron:ops-alert`='긴급 즉시 알림'. **세 크론 고정 순서로 3행**(해당 key 행 없으면 '아직 실행 기록 없음' 회색 표시 — ops-alert는 pg_cron 등록 전이라 비어있을 수 있음, ops-weekly는 월1회).
- 각 행: 라벨 · **상태 배지**(succeeded=positive '발송'/'정상', skipped=muted '건너뜀'+`meta.reason`, failed=negative '실패', running=진행) · 발송 시각(KST, AdminFailedJobsCard의 formatTime 복제) · **발송 수**(`meta.sent`가 숫자면 "N명 발송", `meta.alerted`(긴급)면 "N건 알림") · 제목(`meta.subject`, 있으면 clamp).
- `meta` null/비객체 방어. 하단 "작업 이력 전체 → `/admin/job-runs`" 링크.
- 스타일: AdminFailedJobsCard의 카드 컨테이너(rounded-xl border bg-card) 재사용, 실패 아닐 땐 중립 톤.
