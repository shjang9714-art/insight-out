## 3. 단계별 작업

### P0 — 대시보드 홈 RSC 전환 (지시서 37-A 로 분리 권장)
> 목표: 첫 화면 데이터를 **서버에서 병렬 조회**해 HTML 에 실어 보낸다. 인터랙션 필요한 부분만 작은 client 섬으로 남긴다.

1. **공용 서버 클라이언트** `src/lib/supabase/server.ts` 신설: `cookies()`(async, `await` 필수 — Next 16) 기반 `createServerClient` 래퍼. 상세 페이지의 인라인 보일러플레이트도 이걸로 교체.
2. `dashboard/page.tsx` 를 **서버 컴포넌트**로 전환. `Promise.all` 로 피드/카테고리 카운트/경쟁사 등 **초기 데이터 병렬 조회** 후 props 로 전달.
3. 표현 컴포넌트(`RecentFeed`·`CategoryGrid`)는 **초기 데이터를 props 로 받는 서버 렌더** + 서비스 전환 등 상호작용만 client. `activeService` 는 서버에서 `searchParams` 로 수신(현재 client `useSearchParams` → 서버 `searchParams` prop).
4. `DashboardHeader` 의 알림/오늘카운트는 상호작용(드롭다운·읽음)이 있으니 client 유지하되, 초기 데이터는 서버에서 주입하거나 그대로 두되 **단일 쿼리**로 축소.
5. `layout.tsx` 의 `'use client'` 는 모바일 드로어·서비스 라우팅 때문에 필요 → **셸만 client, 콘텐츠는 서버 children** 유지(현재 구조 보존 가능).

> 주의: Next.js 16 / React 19. `cookies()`·`headers()` **async await**. RSC 기본. `node_modules/next/dist/docs/` 확인.

### P1 — 이미지 최적화 (지시서 37-B)
1. `next.config.ts` 에 `images.remotePatterns` 추가(썸네일 출처 도메인 화이트리스트 — 실제 수집 도메인 조사해 등록, 와일드카드 최소화).
2. `ContentCard`·`YoutubeSection` 의 `<img unoptimized>` → `next/image <Image>` 로 전환, `sizes`·`fill` 또는 width/height 지정, `loading="lazy"` 유지, LCP 후보(상단 카드)만 `priority` 검토.
3. 등록 안 된 도메인 대비 폴백(현재 그라데이션 폴백) 유지.

### P1 — RecentFeed 워터폴 제거
- `services`→`content_services`→`contents` 3쿼리를 **조인/단일 쿼리**로: `contents` 에서 `content_services!inner(service_id)` 필터 또는 서버단 단일 라운드트립. 서버 전환(P0) 이후 자연히 합치기 쉬움.

### P2 — 캐싱 & 번들
1. 콘텐츠 목록류에 `export const revalidate = N`(예: 60~300s) 또는 `unstable_cache` 적용 검토(실시간성 낮은 피드). 어드민/개인화 페이지는 `force-dynamic` 유지.
2. `@next/bundle-analyzer` 로 1회 측정 → 큰 클라이언트 의존성(차트·아이콘 등) 동적 import 검토. 측정 결과만 보고에 첨부(최적화는 후속).
