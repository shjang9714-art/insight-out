## 0. 한 줄

이슈 목록에 **정렬 컨트롤**을 추가한다: 증가율 · 활동량 · 최신 · 내 관련도 · 주의 우선. 대부분 기존 `IssueCard` 필드로 클라이언트 정렬하고, "최신"용 `lastActivityAt` 만 집계에 소량 추가(SQL 아님).

## 1. 현행 진단 (검증된 코드 사실)

- `IssueBoardClient`(48-56): `activeLens` 로 필터 후, 렌즈=all 이면 `score` 순, 아니면 매칭 순 — **고정 정렬, 사용자 선택 없음.**
- `IssueCard`(activity.ts): `recentCount`(7일)·`prevCount`·`changePct`·`sentimentPos/Neg`·`changeFlag`(surge/worsening). **최신 시각(lastActivityAt) 없음** → "최신순"엔 추가 필요.
- 범위 필터(165)와 공존해야 함(정렬은 필터 결과 안에서).

## 2. DB / SQL

**없음.** `activity.ts` 에서 `contents.collected_at` 최대값을 이슈별로 집계해 `lastActivityAt` 산출(기존 조인 데이터).

## 3. 구현

### 3-1. `activity.ts` — lastActivityAt 추가
- `computeIssueActivity` 집계 시 이슈별 `contents.collected_at` **최대값**을 `lastActivityAt: string | null` 로 `IssueCard` 에 추가(이미 순회 중이라 비용 0).

### 3-2. `IssueBoardClient` — 정렬 컨트롤
- `sortBy` state: `'surge' | 'activity' | 'recent' | 'relevance' | 'attention'`. 기본 `'surge'`(증가율) 또는 현행 유지.
- 컨트롤 UI: 작은 pill/segmented(165 ScopeFilter 톤과 구분 — 정렬은 보조). 라벨: **증가율 · 활동량 · 최신 · 내 관련도 · 주의**.
- 정렬 규칙:
  - 증가율: `changePct`(null=신규는 상단 또는 큰 값 취급) 내림차순.
  - 활동량: `recentCount` 내림차순.
  - 최신: `lastActivityAt` 내림차순.
  - 내 관련도: `score` 내림차순(범위 매칭 강도). 범위=전체면 비활성 또는 score.
  - 주의: `changeFlag`(worsening > surge > null) 우선 → 그 안에서 recentCount.
- 정렬은 **필터(activeLens) 적용 후** 리스트에 대해. 렌즈≠all 매칭 우선 로직과 충돌 없게(정렬 선택이 우선, 매칭 여부는 배지로 유지).
- 선택 상태 localStorage 저장(선택) — 과설계 말고 세션 유지 정도면 충분.

### 3-3. 빈/경계
- 카드 0개면 컨트롤 숨김 또는 비활성. `lastActivityAt` null 카드는 최신 정렬 시 맨 뒤.
