## 3. 구현

### 3-1. ⭐ 피드 실검증 API (신규)

`src/app/api/admin/sources/validate-feed/route.ts`
```
POST { url }  →  {
  ok: boolean
  httpStatus: number | null
  itemCount: number
  latestPublishedAt: string | null
  sampleTitles: string[]        // 최대 3개
  error: string | null          // 'http_404' | 'timeout' | 'not_xml' | 'no_items' | …
}
```
- **`fetchFeedText`를 재사용할 것.** 새 fetch 로직을 만들지 말 것(User-Agent·타임아웃이 이미 맞춰져 있다).
- 파싱도 **크롤러가 쓰는 파서를 그대로** 쓴다. 검증이 크롤과 다르게 판단하면 검증의 의미가 없다.
- 관리자 권한 확인(다른 `/api/admin/*` 라우트 패턴 따를 것).
- **타임아웃 짧게**(8~12초). 화면에서 기다리는 호출이다.

### 3-2. `/admin/sources`에 **[피드 검증]** 버튼

`SourceManager.tsx`의 소스 편집 폼(`rss_url` 입력 옆):
```
RSS 주소 [https://…                    ] [피드 검증]

✅ 정상 · 20건 · 최신 2026-07-12
   "개인정보위, 제13회 전체회의 개최"
   "…"

🔴 HTTP 404 — 주소가 유효하지 않습니다
```
- **저장을 막지는 말 것.** 경고만 띄운다(일시적 장애일 수 있다).
- 단, **`ok: false`인데 저장하면 확인 다이얼로그**를 띄운다.

### 3-3. 목록에서도 바로 검증

`/admin/source-quality`의 **🔴 연속실패** 소스 행에서 바로 **[피드 검증]**을 누를 수 있게 한다(선택 — 여유 있으면).

### 3-4. ⭐ 죽은 소스 4개 — **새 주소를 찾아 검증하고 보고할 것**

**Sonnet이 네트워크로 직접 확인한다**(플래너 샌드박스는 해당 도메인이 차단돼 있어 못 한다).

대상:
| 소스 | 사이트 |
|---|---|
| 개인정보보호위원회 | pipc.go.kr |
| 국토교통부 | molit.go.kr |
| 산업통상자원부 | motie.go.kr |
| 정책브리핑 보도자료 | korea.kr |

**요건:**
- 후보 RSS 주소를 찾아 **§3-1의 검증 API(또는 동일 로직)로 실제 파싱까지 확인**할 것. *"이 주소일 것 같다"는 보고는 받지 않는다.*
- **`itemCount > 0` 이고 `latestPublishedAt`이 최근**이어야 유효하다.
- **정책브리핑(korea.kr)은 부처별 피드를 제공할 수 있다** — 그렇다면 4개를 각각 그쪽으로 통일하는 것도 대안이다. **찾아본 뒤 판단해서 보고할 것.**
- RSS가 아예 폐지됐다면 **그 사실을 보고**할 것(그 경우 대안은 별도 판단 — 스크래핑은 범위 밖).

**보고 형식:**
```
| 소스 | 새 RSS 주소 | HTTP | items | 최신 발행일 |
|---|---|---|---|---|
| 개인정보보호위원회 | https://… | 200 | 20 | 2026-07-12 |
```
→ **DB는 건드리지 말 것.** David가 `/admin/sources`에서 직접 교체한다.

## 4. 회귀 가드

- **`fetchFeedText`·기존 파서를 재사용할 것.** 검증이 크롤과 다른 코드를 쓰면 *"검증은 통과했는데 크롤은 실패"* 가 난다. **의미가 없어진다.**
- **검증 실패가 저장을 막지 말 것.** 경고 + 확인 다이얼로그. 일시적 장애를 영구 차단으로 만들면 안 된다.
- **DB의 소스를 코드로 수정하지 말 것**(§3-4). 조사·검증·보고만. 교체는 David가 화면에서.
- 크롤러(`orchestrator.ts`)를 건드리지 말 것.
- 기존 소스 등록·CSV 임포트 동작 불변.
- 검증 API에 **관리자 권한 확인**을 빠뜨리지 말 것(임의 URL fetch = SSRF 표면).

## 5. 검증 (Sonnet)

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build`.
- **살아 있는 피드**(예: 디지털데일리)로 검증 → `ok: true`, `itemCount > 0`, 샘플 제목이 뜨는지.
- **죽은 피드**(현재 정부 소스 4개의 기존 주소)로 검증 → **`http_404`가 정확히 뜨는지.**
- 아무 문자열(`https://example.com`) → `not_xml`·`no_items`로 **구분되어** 뜨는지.
- 비관리자 호출 → **403**.
- ⭐ **§3-4 보고서** — 4개 소스의 새 주소를 **실제 파싱까지 확인**해서 표로 제출.
- 커밋: `feat: 피드 실검증 + 죽은 소스 진단 (지시서 311)`
