## 0. 목표 (한 줄)
크롤링 적재 직전에 **품질 필터**를 적용: 광고성·과도하게 짧은 글은 **제외(미적재)**, 등록 키워드와 관련 없는 글은 **보류(`status='pending'`, 어드민 승인 큐)** 로 적재한다.

## 1. 배경·경계 — 현행 반영 (중요)
- **본문은 RSS 스니펫**이다(#4에서 풀페이지 본문추출 제거). 보통 100~250자. → **PRD "본문 300자 미만 제외"를 그대로 쓰면 대부분 탈락**하므로 v1 에서는 길이 기준을 낮춘다(아래 §2). **300자 풀본문 품질 필터는 풀본문 enrichment 도입 후로 보류(백로그)**.
- `contents.status` enum(`pending`/`published`/`rejected`)은 **이미 스키마/타입에 존재**. 보류 = `pending`.
- 현행 `crawlOne` 루프 순서: `findByUrl → findByBodyHash → findByTitleHash`(전부 miss) → **publishedAt 정규화 → near-dup 그룹핑(#12) → `row` 구성 → `insert`**. #13은 이 흐름에 **두 지점**을 추가(아래 §3.2).
- 키워드 관련도는 `keywords` 테이블 기반인데 **현재 시드가 비어 있음** → **키워드가 0건이면 관련도 게이팅 OFF**(전부 published). 키워드가 생기면 자동 활성.

## 3. `src/lib/crawler/orchestrator.ts` (수정)

### 3.1 키워드 1회 로드 (runCrawl)
- `runCrawl` 에서 소스 조회 후 **키워드를 한 번만 조회**: `admin.from('keywords').select('name')` → `const keywords = (data ?? []).map(k => k.name)`.
- `crawlOne(admin, source, since)` 시그니처에 `keywords: string[]` 추가 → 호출부에 전달.

### 3.2 루프에 품질 단계 2곳 삽입
현재 코드 기준 위치:
1. **제외 필터** — `findByTitleHash` 통과 직후(= 완전중복 아님), `publishedAt` 정규화 전:
```ts
const qText = `${item.title} ${item.body ?? ''}`
if (isAdLike(qText) || effectiveLength(item.title, item.body) < MIN_EFFECTIVE_LENGTH) {
  counts.rejected++
  continue   // 미적재(제외)
}
```
2. **보류 판정** — near-dup 그룹핑으로 `clusterId` 구한 직후, `row` 구성 전:
```ts
const score = relatednessScore(qText, keywords)
const status: 'pending' | 'published' =
  (score !== null && score < RELATEDNESS_THRESHOLD) ? 'pending' : 'published'
```
3. **row 에 `status` 포함**(기존 `cluster_id` 와 함께):
```ts
const row = { /* …기존… */ cluster_id: clusterId, status, /* … */ }
```
4. **insert 성공 카운트 분기**: 기존 `counts.inserted++` 를 →
```ts
if (status === 'pending') counts.held++
else counts.inserted++
```

### 3.3 카운트·응답 계약 확장 (additive)
- `CrawlCounts` 에 `rejected: number` 추가(초기 0). (`held` 는 이미 존재 — 이제 실제 사용)
- `CrawlSourceDetail` 과 `CrawlSummary` 에 `rejected` 추가, 집계.
- 응답 형태: `{ ok, sources_total, success, failed, fetched, inserted, duplicates, rejected, held, details }` (필드 추가만, 기존 필드 유지).
