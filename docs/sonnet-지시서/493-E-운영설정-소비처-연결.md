## 0. 현재 상태

493에서 `ops_settings` 테이블과 `src/lib/ops/settings.ts`(`getOpsSettings()`, env 폴백 내장)를 만들었다.
**연결된 소비처는 `ops/recipients.ts`와 설정 저장 API 두 곳뿐**이다. 나머지는 여전히 `process.env`를 직접 읽는다.

즉 관리자가 화면에서 한도를 바꿔도 **실제 판정에는 반영되지 않는다.** `G-11`의 목적이 절반만 달성된 상태다.

---

## A. 교체 대상 6곳

| 파일:줄 | 읽는 값 | 비고 |
|---|---|---|
| `src/lib/ops/daily-brief.ts:612-613` | 번역·TTS 월간 한도 | 운영 리포트의 한도 대비 소진율 |
| `src/lib/ops/detect-issues.ts:42` 부근 | 번역·TTS 한도 | **80/95% 경보 판정** — 가장 중요 |
| `src/lib/tts/synthesize-briefing.ts:324` | TTS 한도 | 실제 합성 차단 지점 |
| `src/lib/briefing/generate-briefing.ts:12-16` | `BRIEFING_*` 4종 | ⚠️ **모듈 최상위 상수** — 아래 A-2 |
| `src/app/admin/page.tsx:329` | TTS 한도 | 대시보드 표시 |
| `src/app/api/admin/briefings/route.ts:72` | TTS 한도 | |

전부 `await getOpsSettings()`로 교체한다. **`process.env` 폴백을 각 파일에 남기지 마라** — 폴백은 `settings.ts` 안에 이미 있고, 두 곳에 두면 값이 갈린다.

### A-2. ⚠️ `generate-briefing.ts`는 구조가 다르다
```ts
const WINDOW_HOURS = Number(process.env.BRIEFING_WINDOW_HOURS ?? …)   // 모듈 최상위
```
**모듈 로드 시점에 한 번 계산되는 상수**다. 여기에 `await`를 넣을 수 없다.
→ 상수를 지우고 **함수 안에서 `getOpsSettings()`를 호출**해 지역 변수로 받는다. 호출 시점마다 최신값을 본다.
→ 이 파일의 다른 로직·시그니처는 건드리지 마라.

## B. 캐시 수명
`getOpsSettings()`가 값을 캐시한다면 **TTL을 60초 이하**로 두거나, 최소한 설정 저장 API가 캐시를 무효화하게 한다.
관리자가 한도를 바꾸고 화면을 새로고침했는데 옛 값이 보이면 "저장이 안 됐다"고 판단한다.
캐시가 없으면 그대로 둔다 — **이번에 캐시를 새로 만들지는 마라.**

## C. 조회 실패 처리
`getOpsSettings()`는 이미 env 폴백을 갖고 있다. **소비처에서 try/catch로 다시 감싸지 마라.**
단 `detect-issues.ts`는 예외다 — 한도를 못 읽으면 **경보를 내지 말 것**(0으로 두면 즉시 95% 초과로 오탐한다). 폴백값이 오는지 확인하고, 값이 비정상(0·NaN)이면 그 신호를 건너뛴다.
