# 지시서 241 — 위기/기회 LLM 분류 (백엔드)

목표: 경쟁사 관련 뉴스를 **LG U+ 전략 관점**에서 **위기(threat)/기회(opportunity)/관망(neutral)**으로 LLM 분류한다. 기존 `sentiment`(뉴스 자체 논조 긍정/부정)와 **별개 차원**의 새 필드 `lgu_impact`. 파이프라인은 **기존 sentiment 온디맨드 백필과 동일 패턴**(classify → backfill → admin route → 트리거).

David 결정: v2(정확) — 감성 반전이 아니라 LLM이 직접 LG U+ 관점 판정.

범위: `lib/insight/lgu-impact.ts`·`lgu-impact-backfill.ts`(신규) + admin route + 어드민 트리거 버튼. SQL은 `241-lgu-impact-위기기회.sql`(수희). 렌더(경쟁사 뉴스)는 **242**.

전제: LLM 라우팅 확장(238) 배포 후면 무료 용량 여유. `contents.lgu_impact` 컬럼(241 SQL) 필요 — 미적용 시 백필이 42703로 graceful 실패(무해).

## 1. 현행 진단 (검증된 코드 사실 — 미러 대상)
- `lib/insight/sentiment.ts`: `classifySentiment(title, snippet)` → `llmComplete('classify', SYSTEM_PROMPT, user)` → `looseJsonParse` → 긍정/중립/부정. 키워드 폴백 + try/catch null.
- `lib/insight/sentiment-backfill.ts`: 추적 엔티티(is_competitor OR mention≥3) 이름 → `contents`(published·sentiment null·recent·`overlaps(matched_keywords, names)`) 후보 → 순차 classify → `update({sentiment})`. deadline 인지.
- `app/api/admin/sentiment/route.ts`: admin 검증 + POST(days/max) → `backfillSentiment`.
- 어드민 트리거 UI: `components/admin/AdminContentHealth.tsx`(sentiment 백필 호출 지점) — 여기에 위기/기회 트리거 병설.
- `contents.sentiment` 유지(변경 없음). 위기/기회는 신규 `lgu_impact`.

## 2. 구현

### 2-1. `lib/insight/lgu-impact.ts` (신규 — sentiment.ts 미러)
```ts
import 'server-only'
import { llmComplete } from '@/lib/llm'
import { looseJsonParse } from '@/lib/llm/parse'

const SYSTEM_PROMPT =
  '당신은 LG U+(엘지유플러스) 전략 분석가다. 주어진 경쟁사/시장 관련 기사가 ' +
  '**LG U+ 관점에서** 위기인지 기회인지 관망인지 판정하라. ' +
  '위기=경쟁사의 약진·우위 확대·신사업 선점·LG U+ 시장·고객 잠식 위협. ' +
  '기회=경쟁사의 부진·실패·리스크·규제 압박 등 LG U+에 유리한 틈. ' +
  '관망=중립·단순 사실·산업 전반·영향 불명확. ' +
  '**JSON만 출력**: {"impact":"위기|기회|관망"}. 설명·머리말 금지.'

export type LguImpact = '위기' | '기회' | '관망'

function keywordFallback(text: string): LguImpact | null {
  if (/위기|threat|위협/i.test(text)) return '위기'
  if (/기회|opportunity/i.test(text)) return '기회'
  if (/관망|neutral|중립/i.test(text)) return '관망'
  return null
}

export async function classifyLguImpact(
  title: string,
  snippet: string,
  competitors?: string[],
): Promise<LguImpact | null> {
  try {
    const hint = competitors?.length ? `관련 경쟁사: ${competitors.slice(0, 4).join(', ')}\n` : ''
    const user = `${hint}제목: ${title}\n발췌: ${snippet.slice(0, 300)}`
    const out = await llmComplete('classify', SYSTEM_PROMPT, user)
    if (!out) return null
    const parsed = looseJsonParse(out) as Record<string, unknown> | null
    const val = parsed?.impact
    if (val === '위기' || val === '기회' || val === '관망') return val
    return keywordFallback(out)
  } catch {
    return null
  }
}
```

### 2-2. `lib/insight/lgu-impact-backfill.ts` (신규 — sentiment-backfill.ts 미러)
- **경쟁사 한정**: 엔티티 `is_competitor=true`(또는 `competitor_group is not null`) 이름 목록. (mention≥3 확대는 제외 — 위기/기회는 경쟁사 대상이 핵심.)
- 후보: `contents`(status='published' · `lgu_impact is null` · recent(days) · `overlaps(matched_keywords, names)`) order collected_at desc limit max.
- 각 후보: snippet = summary_ko ?? body_original.slice(0,300) ?? title. 매칭된 경쟁사 이름을 `competitors` 힌트로 전달. `classifyLguImpact` → `update({ lgu_impact })`. deadline 인지.
- **graceful**: `lgu_impact` 컬럼 미존재(42703, 241 SQL 미적용) 시 update 에러 코드 확인 후 `reason:'lgu_impact 컬럼 미적용'`로 0 반환(크래시 금지).
- 반환 `{ analyzed, candidates, nullCount, reason? }`.

### 2-3. `app/api/admin/lgu-impact/route.ts` (신규 — sentiment route 미러)
- 동일 admin 검증. POST body `{ days?=14, max?=40(≤100) }` → `backfillLguImpact`. 결과 JSON.

### 2-4. 어드민 트리거 (`AdminContentHealth.tsx`)
- sentiment 백필 버튼 옆/아래에 **"위기·기회 분석 백필"** 버튼 추가 → `POST /api/admin/lgu-impact`. 결과(analyzed/candidates/null) 토스트·인라인 표시. sentiment UI 패턴 그대로 복제.

## 3. 회귀 가드
- `sentiment` 로직·필드 **불변**(위기/기회는 독립 신규 필드·모듈).
- `lgu_impact` 컬럼 미적용 시 백필 graceful(42703 → 0 반환). 렌더(242)도 없는 값은 미표시.
- LLM 부하: classify task 사용 → 238 라우팅(cerebras→sambanova→groq→gemini…)로 분산. 온디맨드 백필이라 크롤 실시간 부하 없음.
- 분류 실패(null)는 저장 안 함(다음 백필에서 재시도).
