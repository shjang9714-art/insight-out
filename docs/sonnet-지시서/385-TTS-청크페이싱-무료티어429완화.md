## 1. 현행 진단 (확인된 코드 사실)

`src/lib/tts/synthesize-briefing.ts`:
- 청크는 **순차 합성**(루프 내 `await synthesizeChunk`), 청크 간 간격 **`await sleep(300)`**(357행) — 300ms뿐.
- `synthesizeChunk` 429 처리(185–195행): PerDay(일일 쿼터)면 즉시 중단, 그 외 429는 백오프 `sleep(1500 * (attempt+1))`(1.5s·3s) 후 **최대 2회** 재시도. 503도 동일 백오프(200행).
- 예산 가드(305–310행): `estimatedSeconds = script.length * SECONDS_PER_CHAR`(0.055초/자)만으로 계산 → **청크 간격을 반영하지 않음.** `> TOTAL_BUDGET_SECONDS(280)`이면 사전 중단.
- 상수: `MAX_CHUNK_CHARS = 750`, `SECONDS_PER_CHAR = 0.055`, `TOTAL_BUDGET_SECONDS = 280`, route `maxDuration = 300`.

**증상(2026-07-18, David)**: 모델 교체 후 청크 1·2 성공, **청크 3/3에서 429**("요청 한도 초과, 잠시 후 다시") → 500. 무료 티어 TTS는 분당 요청 한도가 매우 낮아, 순차 합성으로 ~40초 간격이어도 3연속에서 한도에 걸림. 백오프 1.5~3초는 **분(minute) 단위 리셋**엔 너무 짧아 회복 못 함.

## 3. 구현 (`src/lib/tts/synthesize-briefing.ts` 단일 파일)

### 3.1 청크 간격 상수 추가(환경변수 조절 가능)
`TOTAL_BUDGET_SECONDS = 280` 정의 **아래**에 추가:
```ts
/** 청크 간 간격(ms). 무료 티어 분당 요청 한도(RPM) 완화용. env로 조절 가능(재배포만).
 *  기본 15초 — 순차 합성(~40초/청크)과 합쳐 요청 간격 ~55초로 벌린다. */
const CHUNK_GAP_MS = Number(process.env.TTS_CHUNK_GAP_MS ?? 15_000)
```

### 3.2 청크 간격 적용 (357행)
```ts
// 변경 전
if (i > 0) await sleep(300) // 청크 간 소폭 간격 — 무료 티어 rate limit 완화
// 변경 후
if (i > 0) await sleep(CHUNK_GAP_MS) // 청크 간 간격 — 무료 티어 RPM 완화(385)
```

### 3.3 예산 가드에 간격 오버헤드 반영 (305–310행)
```ts
// 변경 전
const estimatedSeconds = Math.round(script.length * SECONDS_PER_CHAR)
if (estimatedSeconds > TOTAL_BUDGET_SECONDS) {
// 변경 후
const estimatedChunks = Math.max(1, Math.ceil(script.length / MAX_CHUNK_CHARS))
const estimatedSeconds = Math.round(
  script.length * SECONDS_PER_CHAR + (estimatedChunks - 1) * (CHUNK_GAP_MS / 1000),
)
if (estimatedSeconds > TOTAL_BUDGET_SECONDS) {
```
> 이렇게 하면 긴 스크립트는 간격까지 포함한 실제 소요로 **사전 중단**되어, 300초 함수 타임아웃(504) 대신 명확한 안내가 나간다. (기본값 기준 대략 **5청크·~3,700자**까지 소화, 그 이상은 사전 안내.)

### 3.4 429/503 백오프 상향 (187행·200행)
분당 한도는 몇 초 대기로 안 풀리므로 백오프를 늘린다.
```ts
// 187행(429), 200행(503) 공통: 변경 전
await sleep(1500 * (attempt + 1))
// 변경 후
await sleep(8_000 * (attempt + 1)) // 8s·16s — 분당 리셋 대비(385)
```
> 프로액티브 간격(3.2)으로 429가 애초에 잘 안 뜨게 하고, 이 백오프는 안전망. (238–240행 일반 catch의 `sleep(1000)`은 네트워크/timeout 재시도라 **그대로 둔다**.)

## 4. 회귀 가드
1. **청크 크기(750)·per-chunk timeout(120s)·모델·voice·캡·`increment_tts_usage`·`audio_url` 갱신·verifyAdmin·PerDay 즉시중단·WAV 이어붙임·샘플레이트 일관성**은 **그대로**. 이번엔 페이싱 3곳 + 상수 1개만.
2. **짧은 브리핑(1청크)**은 간격 로직을 안 타므로(첫 청크 `i>0` 아님) 지연 없이 즉시 합성 — 회귀 없음.
3. `TTS_CHUNK_GAP_MS` 미설정 시 기본 15,000. 0이나 비정상 값이면 `Number(...)` 결과가 그대로 쓰이니, ops는 정수 ms만 넣을 것(문서 주석에 명시).
4. 예산 가드 강화로 **기존보다 살짝 짧은 스크립트에서도 사전 중단**될 수 있음(간격 포함). 이는 504 방지를 위한 의도된 동작.
5. `maxDuration=300`(route)·`TOTAL_BUDGET_SECONDS=280`은 유지. `Math.ceil` 청크 추정은 대략치(문장 경계 그리디라 실제와 다를 수 있으나 보수적).
