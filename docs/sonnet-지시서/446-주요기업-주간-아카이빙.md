# 지시서 446 — 주요기업 주간 아카이빙·조회

> Opus · 2026-07-26 · 개선검토 [9a]. **SQL 0**(insight_cards.period_start/end + 유니크 인덱스 기존). 브랜치 `agent/446-company-weekly`.
> 재사용: competitor_weekly 패턴(`getLastCompletedWeekKst`·CompetitorWeeklyTimeline·[week] 라우트).

## 현행 문제
- `generateCompanyInsightCards`(generate.ts)가 `period_start=kstDateString(days-1)`(90일 롤링) → **매일 period 밀림**, 주 경계와 무관, 회사당 새 행 누적. `major-companies.ts`는 period_start desc "최신 1건"만 → 주 선택·아카이브 없음.
- 목표(David): 주요기업 카드를 **주 단위로 아카이빙 + 주 선택 조회**(핵심인사이트/경쟁사 주간처럼).

## 수정 (SQL 0 — 기존 컬럼·인덱스 재사용)
### 2.1 생성 주경계 정렬 (`src/lib/insight/generate.ts`)
- `generateCompanyInsightCards`에 옵션 `weekStart?: string` 추가. **period_start/period_end를 주 경계로**: `const { weekStart, weekEnd } = opts.weekStart ? {…} : getLastCompletedWeekKst()`(competitor-weekly에서 import) → `period_start=weekStart, period_end=weekEnd`.
- **기사 코퍼스 window(90일 `days`)는 그대로**(LLM이 읽는 범위). period 라벨만 주 경계. onConflict `(period_start,scope,topic)` 기존 → **주당 회사당 1건 멱등**(같은 주 재실행 시 덮어씀, 누적 없음).
### 2.2 트리거
- cron `ai-refresh`(일일)는 그대로 호출 → 이제 "지난 완료주" 카드를 매일 덮어써 안정 유지. 별도 게이트 불필요.
- 관리자 수동(`/api/admin/insights`): 요청 body에 `weekStart` 받아 특정 주 재생성(competitor-weekly admin 라우트 미러).
### 2.3 조회 + 주 선택 (`src/lib/entities/major-companies.ts`)
- "period_start desc 최신" → **선택 주(weekStart) 필터**: 인자 `weekStart?` 받아 `.eq('period_start', weekStart)`. 기본 = 최신 가용 주(distinct period_start max).
- 가용 주 목록: company 카드의 `distinct period_start`(내림차순) → 주 선택 UI 데이터.
### 2.4 UI 주 선택
- 주요기업 뷰(`entities` watchlist / `entities/major/[group]`)에 **주 선택기** 추가 — `CompetitorWeeklyTimeline` 패턴 재사용(주별 점·라벨). `?week=YYYY-MM-DD` 로 선택. 없으면 최신 주.
- (선택) 주별 라우트는 competitor-weekly `[week]` 구조 참고. 최소안은 `?week=` 쿼리로 충분.

## 회귀 가드
- **기존 롤링 카드 공존**: 과거 rolling period_start 카드와 신규 주경계 카드가 섞임 → 주 선택은 신규(주경계)만 정확 매칭. forward-only(과거 소급 재생성은 수동 weekStart로 개별). 주 목록에 잡카드가 뜨면 필터(예: 요일=월요일 시작만).
- SQL 0(컬럼·인덱스 기존), 의존성 0. tsc/lint/build 통과. **운영철학**: 생성 실패 시 기존 로그 유지(별도 실패 가시성은 오류센터 트랙).
