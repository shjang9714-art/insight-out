# 지시서 25 — 오피니언 채널 크롤링 (#43)

> 작성: Opus(Cowork) · 대상: 구현 에이전트(Codex) · 검증: Opus · 커밋: 구현 에이전트
> 방향: Substack/Medium/벤더 블로그는 **표준 RSS/Atom** → 기존 크롤러 재활용. 새 어댑터·스키마 변경 없음.
> ⚠️ 작업 전 `AGENTS.md` + `src/lib/crawler/adapters/index.ts`(getAdapter)·`src/lib/crawler/adapters/news-site.ts`·`src/lib/crawler/orchestrator.ts`(crawlOne category 하드코딩·runCrawl since)·`src/lib/types.ts`(`ContentCategory`,`SourceType`)·`src/components/dashboard/CategoryGrid.tsx`(오피니언 카테고리 존재) 를 읽을 것.

## 현 상태(재활용 지점)
- `opinion_channel` enum·UI 오피니언 카테고리(💼)·뱃지·`ContentCategory`에 `'오피니언'` **이미 존재**.
- 단 `getAdapter('opinion_channel')` → `null` 이라 crawlOne 이 **"어댑터 미구현, 건너뜀"**. crawlOne 은 `category: '뉴스'` 하드코딩. `since`는 전 소스 공통(당일).

## 1. 어댑터 매핑 (RSS 재활용)
- `adapters/index.ts` `getAdapter`: **`opinion_channel` → `newsSiteAdapter`** 반환(동일 RSS 파싱 재사용). 다른 타입(report_publisher·newsletter)은 그대로 null 유지.

## 2. 타입별 카테고리 (crawlOne)
- crawlOne 의 `category: '뉴스'` 하드코딩을 **source.type 기반 매핑**으로:
  - `news_site` → `'뉴스'`, `opinion_channel` → `'오피니언'`. (그 외는 현재 도달 안 함.)
  - `ContentCategory` 타입 안전하게(헬퍼 `categoryForSourceType(type)` 등).
- 나머지 행 구성·dedup·품질·태깅·번역·crawl_logs **그대로**(오피니언도 영문이면 #19 번역 적용됨).

## 3. 오피니언 주간 수집창 (날짜 정책)
- 오피니언은 **주 1회 수집**이라 "당일만"(지시서23) 적용 시 대부분 누락 → **더 넓은 조회창** 필요.
- `runCrawl` 에서 소스별 `since` 산정: **`opinion_channel` 且 비backfill 이면 `getDaysAgoStartKst(OPINION_LOOKBACK_DAYS=7)`**, 그 외는 기존(당일/backfill). 산정한 per-source since 를 `crawlOne(admin, s, srcSince, …)` 로 전달.
- 발행일 없는 항목 제외(`getPublishedAtSince`)는 그대로 — Substack/Medium 은 발행일 항상 있음. 중복은 original_url 기준이라 주간 창이 겹쳐도 23505로 스킵(누적 없음).

## 4. 데이터(운영) — 코드 아님, 보고에 안내만
- 오피니언 소스는 **`/admin/sources` 에서 개별 등록**(type=`opinion_channel`, `crawl_interval_minutes=10080`(7일), 활성). 주간 due-체크로 자동 수집됨(별도 크론 불필요).
- ⚠️ 대량등록(#P7)은 현재 news_site/youtube만 지원 → 오피니언은 개별 등록(또는 향후 import 확장은 별도 작업).

## 건드리지 말 것
- dedup·품질·태깅·번역·스키마·RLS·뉴스(news_site) 경로·youtube 경로 불변. service_role 서버 전용. 새 카테고리 값 추가 없음(기존 '오피니언' 사용).
