# 지시서 465 — 경쟁사 주간 브리핑 '패스② 분석 실행 상태' 가시화

**SQL·env·의존성 0.** 읽기전용(표시만). 브랜치 `agent/465-cwr-analysis-state`.

## 배경
`draft|published|archived` 3상태만 있어 **패스②(해석) 미실행 리포트가 완성품과 구분되지 않는다**. "발행됨"인데 요약이 비고 전 영역이 '관망'인 상태가 결함으로 오인된다(실제로는 패스① 정상 출력). 운영철학 — 미완 상태는 화면이 지목해야 한다.

## 판별 (신규 로직 금지 — 기존 함수 재사용)
`hasAnalysis(section)`(`src/lib/competitor-weekly/query.ts`)가 이미 렌더 분기 기준이다. 이걸 그대로 쓴다.
리포트 레벨 3상태를 `query.ts`에 추가:
```
export type AnalysisState = 'none' | 'partial' | 'done'
export function analysisState(sections: CompetitorWeeklySection[]): AnalysisState
// 0건 → 'none' / 일부 → 'partial' / 전부 → 'done'  (sections 빈 배열도 'none')
```

## 변경
1. **`src/components/admin/CompetitorWeeklyManager.tsx`** — 행의 `StatusBadge` 옆에 분석 상태 배지 추가.
   - `none` → tone `risk`, 라벨 **"분석 전(사실만)"**
   - `partial` → tone `risk`, 라벨 **"분석 일부"**
   - `done` → 배지 없음(완성품이 기본)
   - `CompetitorWeeklyRow`에 `sections`가 **이미 있다** → 조회·API 변경 0.
2. **`src/components/entities/CompetitorWeeklyReport.tsx`** — 헤더에 동일 표시.
   - 현재 `summary &&` 조건부라 분석 전에는 제목이 아예 없다 → `none`/`partial`이면 제목 자리에 **"분석 전 — 사실 나열만 표시됩니다"** 안내 한 줄(muted, 배지 톤 `risk`).
   - `LegacySection` 헤더에도 영역 단위 "분석 전" 배지(`hasAnalysis` false인 섹션).
3. `StatusBadge{tone,label}` · `Tone`(`positive|risk|negative|neutral|info`) 기존 것 사용. 신규 톤·색 정의 금지.
