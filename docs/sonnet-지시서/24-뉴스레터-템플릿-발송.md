## 0. 목표
어드민 전역 설정(`newsletter_settings`)에 따라, 선정된 콘텐츠 카드 N장을 구독자에게 Resend로 자동 발송하고 회차·수신자 로그를 남긴다. 온보딩/마이페이지의 per-user 주기 선택을 제거한다.

## 1. 카드뉴스 HTML 템플릿 (#40)
`src/lib/email/newsletter-template.ts` 신규.

- `archive-template.ts`의 인라인 스타일·테이블 레이아웃 컨벤션 그대로 따를 것(메일 클라이언트 호환).
- 인터페이스(예):
  ```ts
  export interface NewsletterCard {
    title: string
    category: string
    sourceName: string | null
    summaryKo: string | null
    url: string | null          // 원문 또는 상세뷰 링크
  }
  export interface NewsletterEmailData {
    dateLabel: string           // 'YYYY-MM-DD' KST
    cards: NewsletterCard[]
    unsubscribeUrl: string      // 필수
  }
  export function buildNewsletterHtml(data: NewsletterEmailData): string
  ```
- 구성: 상단 브랜드 헤더(`#E6007E`) → 날짜 → 카드 N개(번호·카테고리·출처·제목·요약·`자세히 보기 →`) → 푸터.
- **푸터에 수신거부 링크 필수**: `수신을 원치 않으시면 <a href="${unsubscribeUrl}">구독 해지</a>`.
- 모바일 폭(최대 600px), 한국어 카피.

## 2. 발송 코어 (#41)
`src/lib/newsletter/dispatch.ts` 신규 — 라우트에서 호출하는 순수 함수 `runNewsletterDispatch({ triggeredBy }: { triggeredBy: 'cron'|'manual' })`.

순서(설계서 §4):
1. service_role 클라이언트 생성(`SUPABASE_SERVICE_ROLE_KEY`).
2. `newsletter_settings`(id=1) 로드. `is_enabled=false` → `{ skipped:'disabled' }`.
3. KST today/요일 계산. ISO 요일 ∉ `send_days` → `{ skipped:'not_a_send_day' }`.
4. `last_sent_on === todayKST` → `{ skipped:'already_sent' }` (멱등).
5. (manual은 3·4 건너뜀 — 어드민 수동발송은 강제 1회.)
6. 수신자: `newsletter_subscriptions` where `is_active=true and newsletter_email is not null`. 0명 → issue 생성 없이 `{ skipped:'no_recipients' }`.
7. 콘텐츠 선정: `contents` where `status='published'` order by `is_editor_pick desc, view_count desc, published_at desc` limit `card_count`. (직전 issue.sent_on 이후 published 우선, 부족하면 최신 보충 — 단순화 가능.)
8. `newsletter_issues` insert(status='pending', triggered_by, sent_on=todayKST, subject=`subject_tpl` 치환, content_ids).
9. 각 수신자: `resend.emails.send({ from, to, subject, html })` → 응답 id로 `newsletter_recipients` insert(status='sent', resend_message_id). 실패 시 status='failed', error 기록.
10. 집계 → issue status(sent/partial/failed)·recipient_cnt update. cron 성공 시 `settings.last_sent_on = todayKST`.
11. 반환 `{ ok, issueId, sent, failed, skipped }`.

주의:
- `from`은 기존 send-archive와 동일 발신주소 재사용.
- 절대경로 base URL은 **`process.env.NEXT_PUBLIC_APP_URL ?? 'https://insight-out-app.vercel.app'`** 사용(현재 이 env 없음 → 폴백으로 안전, `.env.example`에 `NEXT_PUBLIC_APP_URL` 키 추가). 이걸로 unsubscribe/상세 링크 구성.
- 에러는 throw하지 말고 집계에 반영(부분 실패 허용).

## 3. Cron 라우트 (#41)
`src/app/api/cron/newsletter/route.ts` 신규.
- `crawl` 라우트와 동일하게 `Authorization: Bearer ${CRON_SECRET}` 검증.
- `runNewsletterDispatch({ triggeredBy:'cron' })` 호출 → JSON 반환.
- `export const dynamic='force-dynamic'`, `runtime='nodejs'`.

`vercel.json` crons에 추가(설계서 §4-제약 참고, Hobby=일1회):
```json
{ "path": "/api/cron/newsletter", "schedule": "0 23 * * *" }
```
(= 08:00 KST. Pro 전환 시 `0 * * * *`로 변경하면 `send_hour_kst` 반영.)
→ `middleware.ts`의 `publicPaths`에 `/api/cron`이 이미 포함돼 있으니 추가 불필요.
