## 배경 (David 결정)
"지금 수집"이 항상 **당일분**만 수집(crawl-now 가 backfillDays 미전달). **최근 N일 소급 수동 수집**을 추가한다 — 81 깨진 기사 비운 뒤 7일치 재수집 등 복구·운영에 필요. **임의 시작~종료 구간은 범위 밖**(RSS가 옛 기사를 안 줘 비현실적) → "최근 N일" 소급만.

## 작업

### 1. crawl-now API — `backfillDays` 수용
- `src/app/api/admin/crawl-now/route.ts` POST: body 파싱에 `backfillDays` 추가.
  ```ts
  let sourceId: string | undefined
  let backfillDays: number | undefined
  try { const b = await request.json(); sourceId = b?.sourceId; backfillDays = b?.backfillDays } catch {}
  ```
- `runCrawl` 호출에 전달:
  ```ts
  await runCrawl({ force: true, sourceIds: sourceId ? [sourceId] : undefined, backfillDays })
  ```
- 범위 가드는 `runCrawl` 이 이미 수행(`Math.min(floor, 30)`, 0/미지정=당일). 별도 검증 불필요하나, 음수 방지 위해 `backfillDays` 가 숫자 아니면 undefined 처리.

### 2. SourceManager — 기간 선택 UI
- 상태 추가: `const [crawlDays, setCrawlDays] = useState(0)` (0=오늘).
- "지금 수집"(전체, 730줄) 옆에 **기간 Select**: `오늘(0) / 최근 3일(3) / 최근 7일(7) / 최근 14일(14) / 최근 30일(30)`.
- `handleCrawlNow`(412): POST body 에 `backfillDays: crawlDays` 추가.
  ```ts
  const res = await fetch('/api/admin/crawl-now', {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ backfillDays: crawlDays }),
  })
  ```
- 확인 문구를 기간 반영: `crawlDays === 0 ? '오늘 발행분을' : '최근 ' + crawlDays + '일치를'` + " 지금 수집하시겠습니까?".
- `handleCrawlSource`(433, 개별): body 에 `backfillDays: crawlDays` 동일 추가(개별 수집도 같은 기간 적용).

### 3. 안내(경고) 문구
- 기간 Select 아래/옆에 작은 회색 힌트: "RSS 특성상 피드에 남아있는 기사까지만 수집됩니다." (당일 외 선택 시 노출, 선택)

## 회귀 / 주의
- 기본값 `crawlDays=0` → 기존 당일 동작 동일(비파괴).
- **타임아웃 주의**: crawl-now `maxDuration=60`, `after()` 백그라운드. 소스 많은데 30일 소급이면 60초 초과로 일부 미완 가능 → 힌트에 "기간이 길면 시간이 걸립니다" 추가(선택). 7~14일 권장.
- web_insight 는 sinceForSource 가 별도 lookback 적용(기존) — backfillDays>0 이면 defaultSince 사용(orchestrator 로직 그대로, 변경 없음).
- 관리자 인증·`after` 백그라운드·진행 표시(crawlJob) 기존 그대로.
- UI 한국어(#1)·토큰 색(#9)·`'use client'` 유지.
