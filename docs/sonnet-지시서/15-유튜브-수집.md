# Sonnet 지시서 15 — 유튜브 채널 수집 (RSS) (#유튜브 Data, Phase 3-A)

> 작성: Opus(Cowork) · 대상: Claude Code(Sonnet) · Phase 3-A 용주 트랙 (유튜브 수집)
> 방식 결정(Opus): **YouTube 채널 RSS(Atom)** — API 키·쿼터 없이 기존 RSS 인프라 재사용. 차단 시 `/admin/crawl-logs` 로 관측 후 Data API 승급(후속).
> ⚠️ 작업 전 `AGENTS.md` + 현재 `src/lib/crawler/orchestrator.ts`(runCrawl/crawlOne 구조)·`src/lib/crawler/adapters/news-site.ts`(rss-parser 사용법)·`src/lib/types.ts`(`YoutubeVideoRow`) 를 읽을 것.

## 0. 목표 (한 줄)
`sources.type='youtube_channel'` 인 소스의 채널 RSS 를 파싱해 영상 메타를 **`youtube_videos`** 에 멱등 적재한다. (뉴스는 `contents`, 유튜브는 `youtube_videos` — 분기)

## 1. 설계
- **채널 = 소스**: 어드민이 `/admin/sources` 에서 `type=youtube_channel`, `rss_url=https://www.youtube.com/feeds/videos.xml?channel_id=<CHANNEL_ID>` 로 등록(별도 채널관리 페이지 불필요).
- **크롤러 분기**: `runCrawl` 의 소스 루프에서 `source.type==='youtube_channel'` → `crawlYoutube(admin, source)`, 그 외(`news_site`) → 기존 `crawlOne`. 둘 다 `crawl_logs` 기록.
- **적재 대상**: `youtube_videos`(컬럼: `video_id, source_id, title, channel_name, channel_id, description, thumbnail_url, duration_seconds, view_count, published_at, collected_at`). RSS엔 duration/view_count 없음 → null.
- **썸네일**: 파싱 대신 `https://i.ytimg.com/vi/${videoId}/hqdefault.jpg` 로 유도(견고).
- **채널명**: 채널 RSS 의 `feed.title` = 채널명.
- **멱등**: `youtube_videos_video_id_key`(video_id 유니크) → **insert + 23505 스킵**(contents 패턴과 동일).

## 2. 할 일

### 2.1 `src/lib/crawler/adapters/youtube.ts` (신규)
- `rss-parser` 로 `source.rss_url` 파싱(YouTube 는 Atom). customFields(item): `['yt:videoId','videoId']`, `['yt:channelId','channelId']`.
- 반환 타입(예) `YoutubeRawItem`: `{ videoId, title, channelId?, published_at? }`. 채널명은 `feed.title` 로 별도 전달(또는 fetch 결과에서 함께 반환).
- `videoId` 없거나 `title` 없으면 스킵. (since 필터 불필요 — video_id 유니크로 멱등)

### 2.2 `src/lib/crawler/orchestrator.ts` (수정 — 유튜브 분기)
- `crawlYoutube(admin, source, keywords?)`:
  - 어댑터로 영상 목록 + 채널명(feed.title) 획득(withRetry 재사용).
  - 각 영상 → `youtube_videos` insert:
    ```ts
    const row = {
      source_id: source.id,
      video_id: videoId,
      title,
      channel_name: feedTitle,
      channel_id: channelId ?? null,
      description: null,
      thumbnail_url: `https://i.ytimg.com/vi/${videoId}/hqdefault.jpg`,
      duration_seconds: null,
      view_count: null,
      published_at: <ISO 정규화>,
      collected_at: new Date().toISOString(),
    }
    const { error } = await admin.from('youtube_videos').insert(row)
    if (error) { if (error.code === '23505') duplicate++; else { partial; 로그 } } else inserted++
    ```
  - `crawl_logs` 기록(fetched/inserted/duplicate/held=0), `sources.last_crawled_at` 갱신. 반환은 기존 `SourceCrawlResult` 형태(집계 호환).
- `runCrawl` 소스 루프: `source.type==='youtube_channel' ? crawlYoutube(...) : crawlOne(...)`. (due 판정·요약 집계는 기존 그대로 양쪽 공통)

### 2.3 건드리지 말 것
- 뉴스(`crawlOne`)·dedup·태깅·품질·응답계약 로직 변경 금지(유튜브 분기만 추가).
- `youtube_videos` 는 **태깅(content_services) 대상 아님**(contents 전용) — 유튜브는 그대로 적재만.
- 스키마/타입 변경 불필요(`youtube_videos` 이미 존재).

## 3. 주의
- `published_at` ISO 정규화(비ISO 방어). thumbnail 유도 URL 그대로.
- 유튜브 차단 가능성: 서버 fetch 가 막히면 `crawl_logs` 에 `failed` 로 남음(정상 관측). 코드가 죽지 않게 try/catch.
- service_role(admin client)로 적재(크롤러는 이미 admin). 라우트/크론 변경 없음(`/api/cron/crawl` 그대로 — 소스 타입으로 분기).
