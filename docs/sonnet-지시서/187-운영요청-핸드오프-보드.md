## 0. 한 줄

**요청사항 + 공지사항을 어드민에서 다루는 얇은 게시판**(`/admin/requests`)을 만든다. `post_type`으로 **요청(request)**(SQL·인프라·공유 — 상태 대기/진행/완료/블록·담당·참조)과 **공지(announcement)**(고정·게시)를 함께 담는다. 사이드바에 미완료 요청 개수 배지(in-admin 알림). (작업(work) 타입·작업계획서 자동 export는 189.)

## 1. 현행 진단

- 팀 간 핸드오프(SQL 적용·버킷 생성·공유)를 노션/대화로 수동 추적 → 매 슬라이스 마찰(우리도 178 SQL·report-covers·186 RPC를 손으로 챙김).
- 어드민에 이런 요청 추적 화면 없음. `ADMIN_NAV_GROUPS`(nav.ts) 시스템 그룹에 추가 여지.

## 2. DB / SQL (수희 핸드오프)

`docs/sql-handoff/187-ops_requests.sql` — `ops_requests`(id·title·body·kind·status·owner·ref·created_by·created_at·updated_at·resolved_at) + updated_at 트리거 + 인덱스 + RLS(서버 service_role 경유). **먼저 커밋·푸시해 수희 적용**(테이블 없으면 보드는 빈 상태·graceful).

## 3. 구현

### 3-1. 어드민 라우트 — `app/admin/requests/page.tsx`(신규)
- admin 가드(미들웨어) 재사용. `createAdminClient()`로 `ops_requests` 조회.
- 사이드바 nav(`lib/admin/nav.ts`)에 **시스템 그룹**에 항목 추가: `{ href:'/admin/requests', label:'운영 요청', description:'SQL·인프라 요청과 핸드오프 추적', icon: (예: ClipboardList) }`.
- `AdminPageHeader`(174) 자동.

### 3-2. 보드 UI (`RequestsBoard` 클라 + API) — 요청 / 공지 탭 (같은 페이지, 필터)
> 주의: 페이지 안에서 [요청]/[공지] 전환은 **데이터 필터**(post_type)이지 L3 내비 아님 — 세그먼트 필터로 OK.

- **요청(request)**: 상태별(대기/진행/완료/블록) 목록/보드. 행 = 제목·종류 배지·담당·참조(링크/지시서)·업데이트. 완료 접기/흐리게. 인라인 상태 변경(done 시 resolved_at 자동 트리거). 필터(상태·담당·종류).
- **공지(announcement)**: 게시글 목록(최신순, `pinned` 상단 고정). 행 = 제목·작성자·게시일·본문(펼침). status=active/archived(보관).
- **생성**: post_type 선택 → 요청이면(종류·담당·참조), 공지면(고정 여부). 제목·본문 공통.
- API: `/api/admin/requests`(GET 목록 `?post_type=`·POST 생성·PATCH 상태/필드). service_role. 42P01(테이블 없음) graceful.
- 상태·종류 색 = 175 status-style 톤(그린 없음: 완료=positive(블루)/진행=info/블록=risk/대기=neutral). 어드민 v2 타이포.

### 3-3. 사이드바 미완료 배지 (in-admin 알림)
- nav "운영 요청" 옆에 **미완료(pending+in_progress) 개수 배지**(있을 때만). AdminSidebar에서 카운트 조회(가벼운 count 쿼리, service_role 경유 API).

### 3-4. (범위 밖) 멘션·이메일 알림

- 테이블 미적용(42P01) → 보드 빈 상태·배지 0 graceful(어드민 정상).
- 어드민 한정·service_role 서버 경유(클라 직접 접근 금지).
