## 배경 (근본 원인)

"오늘 업데이트/수집 건수"가 화면마다 **기준 컬럼과 KST 헬퍼가 제각각**이라 값이 어긋나고, 일부는 의도(수집분)와 다르게 집계됨:

| 위치 | 기준 컬럼 | KST 헬퍼 | 문제 |
|---|---|---|---|
| `DashboardHeader.tsx` (오늘 업데이트 N건) | **`created_at`** | 인라인 계산 | 의도(`collected_at`=수집분)와 **다름**. 헤더만 다른 수를 보임 |
| `CategoryGrid.tsx` (카테고리별 오늘 N건) | `collected_at` ✓ | 로컬 `todayStartKstIso()` | 헬퍼 중복 |
| `admin/page.tsx` (오늘 수집) | `collected_at` ✓ | 로컬 `getTodayStartInKst()` | 헬퍼 중복 |
| `crawler/orchestrator.ts` | — | `getTodayStartKst()` | 동일 로직 3중 복제 |

→ #74 의 "매일 갱신 안 됨/숫자 이상"은 **`created_at` vs `collected_at` 혼용 + 헬퍼 중복**이 핵심. `collected_at`(수집 시각, insert 시 `now()` 기본값) 으로 통일하면 "당일 수집분" 기준으로 매일 정상 갱신된다.

## 작업

### 1. 공용 KST 헬퍼 신설 — `src/lib/date.ts` (신규)
```ts
/** KST 기준 오늘 0시를 UTC ISO 문자열로 반환 */
export function getKstTodayStartIso(): string {
  const now = Date.now()
  const kst = new Date(now + 9 * 60 * 60 * 1000)
  const midnightUtc = Date.UTC(kst.getUTCFullYear(), kst.getUTCMonth(), kst.getUTCDate()) - 9 * 60 * 60 * 1000
  return new Date(midnightUtc).toISOString()
}
```
(= 현재 `CategoryGrid.todayStartKstIso` 와 동일 로직. 클라이언트/서버 양쪽 import 가능한 순수 함수.)

### 2. DashboardHeader — `collected_at` 으로 교정 + 헬퍼 사용
- 인라인 `kstOffset`/`kstDateStr`/`kstMidnightUtc` 계산 제거 → `getKstTodayStartIso()` import.
- 오늘 카운트 쿼리: `.gte('created_at', kstMidnightUtc)` → **`.gte('collected_at', getKstTodayStartIso())`**.
- 알림 목록(최근 8건)은 기존대로 `created_at` 정렬 유지(이건 "최근 수집 순"이라 무방). **카운트만** `collected_at` 로 통일.

### 3. CategoryGrid — 로컬 헬퍼 제거, 공용 사용
- `todayStartKstIso()` 정의 삭제 → `getKstTodayStartIso()` import 후 `.gte('collected_at', getKstTodayStartIso())` 로 교체(동작 동일, 중복 제거).

### 4. admin/page.tsx — 로컬 헬퍼 제거, 공용 사용
- `getTodayStartInKst()` 정의 삭제 → `getKstTodayStartIso()` import. `오늘 수집` 쿼리 그대로 `collected_at` 기준 유지.

### 5. (선택) crawler/orchestrator.ts
- `getTodayStartKst()` 도 `getKstTodayStartIso()` 로 대체 가능하나, 크롤러 동작에 영향 가니 **별도 검토**. 이번 범위에서는 손대지 않아도 됨(주석으로 TODO 표기만).
