핵심 결정(확정): 회사 이메일 `@lguplus.co.kr` OTP(구글·비번 제거) · 도메인 검증 시 **자동 승인** · 관리자만 Google(allowlist) · **Brevo 무료 1계정 SMTP** 발송.

## 4. OTP 카드 (`LoginCard.tsx`) — 인증 로직
- **1단계(이메일)**: `supabase.auth.signInWithOtp({ email, options:{ shouldCreateUser:true } })` → 성공 시 step='otp'. (신규는 생성 시 도메인 Hook이 게이팅)
- **2단계(코드)**: `verifyOtp({ email, token:code, type:'email' })` → 성공 `router.push('/dashboard')`+`refresh()`.
- 코드 입력: 6자리 숫자(`inputMode="numeric"` maxLength6, 붙여넣기, 6자리 채워지면 자동 제출). **재전송 30s 쿨다운**, **이메일 변경**(step 복귀).
- **도메인은 소프트 힌트만**(placeholder `name@lguplus.co.kr` + 캡션) — 클라이언트 하드검증 금지(allowlist/기존계정 폴백 위해). 서버 Hook이 판정.
- 에러 매핑(한국어): 403 도메인 거부(`사내 이메일(@lguplus.co.kr) 계정만 로그인할 수 있습니다.`) / 코드 불일치·만료 / 429 레이트리밋 / 네트워크. 배너 `--destructive` 토큰.
- 타이틀 `Insight Out` 중앙 + 골드 언더바(30×3px, radius999), 전구 로고 없음.
- **관리자 Google 보조 진입**(240): 카드 하단 저강조 링크 `관리자는 Google로 로그인` → `signInWithOAuth({provider:'google', options:{redirectTo:`${location.origin}/auth/callback`}})`. 일반 직원 gmail은 Hook이 거부(안전).

## 5. DB (수희 — 코드 아님)
- **239 SQL**: `signup_email_allowlist`(yjhead@gmail 등 admin 예외) + `hook_restrict_signup_by_email_domain`(@lguplus.co.kr+allowlist) + `handle_new_user` 자동승인.
- **240 SQL**: allowlist `is_admin` + `handle_new_user` 최종판(자동승인 + admin 역할). **239 뒤 적용.**

## 6. 회귀 가드
- 라우팅·미들웨어·`/auth/callback` 변경 없음(OTP는 콜백 미사용, Google만 사용).
- 애니메이션 레이어 `pointer-events:none` — 폼 클릭·입력·탭 방해 없음.
- 씬 153% 확대돼도 `overflow-hidden`으로 가로 스크롤 없음. asset feather로 사각 경계·세로 띠 없게(있으면 재생성).
- `.io-login` 항상 라이트(다크 토글 무관).
- 기존 비번/구글 계정도 동일 이메일 OTP 로그인 가능(신원 동일). 도메인/자동승인 SQL 미적용 시에도 로그인 자체는 동작(승인 게이트만 기존대로).
- OTP 응답 스키마 표준(`signInWithOtp`/`verifyOtp`).
