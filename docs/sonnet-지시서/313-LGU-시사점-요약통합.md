## 0. 한 줄

**"뉴스 요약"은 어디에나 있다. "이게 LG U+에 무슨 의미인가"가 Insight Out이 있는 이유다.**
요약 LLM 호출에 시사점을 **얹어서**, 토큰을 늘리지 않고(오히려 줄이고) 제품의 존재 이유를 화면에 올린다.

## 1. 현행 진단 (검증된 코드 사실)

### 1.1 절반이 이미 있다
| | 현황 |
|---|---|
| `contents.lgu_impact` (`'위기'\|'기회'\|'관망'`) | ✅ **241 SQL 적용됨** |
| `classifyLguImpact()` (`src/lib/insight/lgu-impact.ts`) | ✅ LLM 판정 + `looseJsonParse` + 키워드 폴백 |
| `backfillLguImpact()` (`src/lib/insight/lgu-impact-backfill.ts`) | ✅ 어드민 잡. **단 경쟁사 관련 기사만**(`is_competitor` 엔티티와 `matched_keywords` overlap) |
| **서술문(시사점)** | ❌ **없다.** 라벨 3개뿐 |
| **사용자 화면 노출** | ❌ **0회.** `components/`·`dashboard/`에 `lgu_impact` 참조 없음 |

→ **경쟁사 주간 생성 프롬프트의 입력으로만 쓰이고, 사용자는 본 적이 없다.**

### 1.2 ⭐ 통합하면 LLM 호출이 **줄어든다** (David의 "무료로 감당"에 직접 부합)

```
지금:  summarizeKo()      → llmComplete('summarize')   1회
       classifyLguImpact() → llmComplete('classify')    1회 (경쟁사 기사에 한해)
       ─────────────────────────────────────────────────────
       최대 2회 · 본문/발췌를 두 번 넣는다

313:   summarizeKo() 한 번에 JSON 으로 { summary, impact, implication }
       ─────────────────────────────────────────────────────
       1회 · 입력(본문 2,000자 ≈ 1,300토큰)을 공유. 출력만 ~100토큰 증가
```

> **시사점을 별도 호출로 만들면 토큰이 2배가 된다. 요약 호출에 얹으면 +10%다.**
> 그리고 `classifyLguImpact`의 별도 호출을 대체하므로 **총량은 오히려 감소한다.**

### 1.3 재사용할 것
- `src/lib/llm/parse.ts`의 **`looseJsonParse`** — 이미 있다. **새로 만들지 말 것.**
- `stripLlmArtifacts` (293) — 시사점도 LLM 서술문이다. **반드시 거쳐야 한다.**
- `summarizeKo`는 **310 후속에서 이미 객체를 반환**한다(`{ text, rateLimited }`). 필드를 늘리면 된다.

## 3. 구현

### 3-1. `summarizeKo` — JSON 산출로 확장

`src/lib/crawler/summarize.ts`

```ts
export interface SummarizeResult {
  text: string | null            // 요약 (기존)
  impact: '위기' | '기회' | '관망' | null
  implication: string | null     // 시사점 서술문. 관련 없으면 null
  rateLimited: boolean           // 310 후속
}
```

**프롬프트** (기존 `SYSTEM_PROMPT`를 확장. `classifyLguImpact`의 정의를 **그대로 가져올 것** — 두 개가 달라지면 안 된다):
```
당신은 LG U+(엘지유플러스) B2B 텔레콤/엔터프라이즈 시장 정보 분석가다.
입력 기사에 대해 JSON만 출력하라.

{
  "summary":     "한국어 2~3문장. 핵심만. 사실만, 추측·과장 금지.",
  "impact":      "위기" | "기회" | "관망",
  "implication": "LG U+ 관점의 시사점 1~2문장. 관련이 없으면 null."
}

impact 정의:
  위기 = 경쟁사의 약진·우위 확대·신사업 선점·LG U+ 시장/고객 잠식 위협
  기회 = 경쟁사의 부진·실패·리스크·규제 압박 등 LG U+에 유리한 틈
  관망 = 중립·단순 사실·산업 전반·영향 불명확

⛔ implication 규칙:
  - LG U+와 직접 관련이 없으면 반드시 null. **억지로 만들지 마라.**
  - "AI 시장이 성장하므로 LG U+도 AI 사업에 시사점이 있다" 같은
    아무 기사에나 붙는 뻔한 말은 null 보다 나쁘다.
  - 구체적으로 말할 수 없으면 null.
  - 서술문에 태그(<quote> 등)나 대괄호 id를 넣지 마라.
```

### 3-2. ⭐⭐ 최우선 회귀 가드 — **요약이 시사점 때문에 죽으면 안 된다**

JSON 산출로 바꾸면 **파싱 실패 시 요약까지 날아갈 수 있다.** 무료 티어 모델은 JSON을 자주 어긴다.
**요약은 필수, 시사점은 부가다.**

```ts
const parsed = looseJsonParse(out)
if (parsed && typeof parsed.summary === 'string') {
  → 정상 경로
} else {
  → 🛟 폴백: 응답 전체(out)를 요약으로 쓰고 impact/implication 은 null
}
```
- **`looseJsonParse` 실패 = 요약 실패가 아니다.** 반드시 폴백할 것.
- `impact`가 3값이 아니면 → `null`(폴백하지 말고 그냥 null. `classifyLguImpact`의 `keywordFallback`은 **쓰지 말 것** — 요약문에 "위기"라는 단어가 있다고 위기가 아니다).

### 3-3. 저장 — `summarize-backfill.ts`

`summarizeOne`이 `summary_ko`와 함께 `lgu_impact`·`lgu_implication`을 저장한다.
- **`stripLlmArtifacts(implication)`** 를 반드시 거칠 것 (293).
- **컬럼 미적용(42703) graceful**: `lgu_implication`이 없으면 그 필드만 빼고 재시도. **요약 저장이 실패하면 안 된다.** (`body_markdown` 42703 폴백과 같은 패턴)
- `summary_attempted_at` 마킹 정책(310 + 후속)은 **그대로**. 시사점 유무와 무관하다.

### 3-4. `classifyLguImpact` 별도 호출 — **정리**
- `backfillLguImpact`(어드민 잡)는 **남긴다** — 기존 데이터(요약이 이미 있는 콘텐츠)의 `lgu_impact`를 채우는 용도.
- 다만 **신규 수집분은 313 경로로 한 번에 처리**되므로, 백필 잡은 **후보가 점점 줄어드는 게 정상**이다.
- **`classifyLguImpact`를 지우지 말 것.** 백필이 쓴다.

### 3-5. 화면 — **있는 것만 보여준다**

**콘텐츠 상세** (`dashboard/contents/[id]/page.tsx`)
```
[뉴스] [보안/클라우드]                      🔴 위기
제목
────────────────────────────────────
요약 2~3문장

┌─ LG U+ 관점 ───────────────────────┐
│ 시사점 1~2문장                      │
└────────────────────────────────────┘
```
- **`lgu_implication`이 null이면 블록 자체를 렌더하지 말 것.** *"시사점 없음"* 같은 빈 껍데기 금지.
- `lgu_impact` 배지: 위기=경고색 · 기회=긍정색 · 관망=중립색. **`관망`은 배지를 아예 안 띄우는 것도 검토**(노이즈).

**콘텐츠 카드** — 이번 범위는 **배지만**(시사점 서술문은 상세에서). 카드가 이미 빽빽하다.

> **있는 것만 보여주는 게 전부 보여주는 것보다 강하다.** 대부분의 기사는 LG U+와 무관하고, 그게 정상이다.

## 4. 회귀 가드

- ⛔⛔ **JSON 파싱 실패로 요약이 사라지면 안 된다**(§3-2). 폴백 필수. **이게 이 슬라이스 최대 위험이다.**
- ⛔ **억지 시사점 금지.** LLM이 null을 낼 수 있어야 하고, null이면 **화면에 아무것도 안 띄운다.** 뻔한 시사점은 없느니만 못하다 — **신뢰를 깎는다.**
- ⛔ **`stripLlmArtifacts`를 거칠 것**(293). 시사점도 LLM 서술문이다. `<quote>`·`[uuid]`가 다시 샌다.
- **`lgu_implication` 컬럼 미적용(42703)에도 요약 저장이 성공해야 한다.**
- **`impact` 키워드 폴백을 쓰지 말 것** — 요약문에 "위기"가 들어 있다고 위기가 아니다.
- **`classifyLguImpact`·`backfillLguImpact`를 지우지 말 것.** 기존 데이터 백필에 쓴다.
- **310 후속의 `rate_limited` / `not_ready` / `failed` 마킹 정책 불변.**
- **`looseJsonParse`를 재사용할 것.** 새 파서 금지.
- 요약 프롬프트의 *"사실만, 추측·과장 금지"* 를 유지할 것.

## 5. 검증 (Sonnet)

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build`.
- ⭐ **JSON 폴백**: 모델이 JSON이 아닌 평문을 뱉는 상황을 강제로 만들어 → **요약이 살아남는지**(impact/implication만 null). **이게 통과 못 하면 배포 금지.**
- ⭐ **억지 시사점**: LG U+와 무관한 기사(예: 일반 국제 뉴스)를 넣어 → `implication`이 **null**로 나오는지. 뻔한 말이 붙으면 프롬프트를 더 강하게 할 것.
- **`lgu_implication` 컬럼 없는 상태**(SQL 전)에서 → 요약이 **정상 저장**되는지(42703 graceful).
- 시사점에 `<quote>`·`[uuid]`가 **안 새는지**(`stripLlmArtifacts`).
- **LLM 호출 횟수**: 신규 수집 1건당 요약 호출이 **1회**인지(2회가 아닌지). `/admin/llm` 사용량으로 대조.
- 화면: `implication`이 null인 콘텐츠에 **블록이 안 뜨는지**.
- 커밋: `feat: LG U+ 관점 시사점 — 요약 호출에 통합 (지시서 313)`
