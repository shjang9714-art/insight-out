## 1. 착수 전 확인 결과 (현황대조 §5 규율)

**대상 화면을 직접 열어 구성을 확인했다.**

| 화면 | 컴포넌트 | 실제 구성 |
|---|---|---|
| 지식보고서 | `KnowledgeReportManager` (29줄) | `KnowledgeReportUploadForm` + `KnowledgeReportList` |
| AI 리포트 | `ReportsManager` (93줄) | `ReportCreateForm` + 필터칩(전체·발행·미발행) + `ReportRow` 목록 |

**둘 다 (가) "있는 걸 묶기" 범위에 정확히 맞는다.** 신규 기능 0.

### 1.1 ⚠️ 흡수는 이번에 하지 않는다 — 확인으로 판단이 바뀜

현황대조 §3 에 *"리포트 그룹의 `프롬프트 콘솔`·`AI 콘텐츠 보강`을 흡수"* 라고 적었으나, **확인 결과 대상이 다르다.**

`/admin/ai-jobs` 가 다루는 `enrich-jobs` 레지스트리 내용:
```
논조 분석 · 위기·기회 분석 · 유튜브 요약 생성 · 뉴스 요약 백필 ·
신호 분류 · 누락 기사 본문 수집 · 원문 URL 정규화 · 누락 썸네일 다시 수집 · 유튜브 자막
```
**전부 콘텐츠(뉴스·유튜브) 보강 작업이며 AI 리포트와 무관하다.** 최종안 §15 도 *"각 콘텐츠 관리 화면의 AI 작업"* 으로 지정한다.

→ **`AI 콘텐츠 보강` 흡수는 `AdminContentManager`(2,198줄) 슬라이스로 이관.**
→ **`프롬프트 콘솔` 은 범위 미확인.** 전역 프롬프트 콘솔인지 리포트 전용인지 확인되지 않아 이번에 손대지 않는다.

> 현황대조 §5 가 경고한 그대로다 — **import 여부로 판정한 계획은 실물을 열어보면 바뀐다.**

## 2. 구현

### 2.1 지식보고서 — `KnowledgeReportHub.tsx` (신규)

`'use client'`. 396 의 `CompetitorWeeklyHub` 와 같은 모양.

| 탭 value | 라벨 | 내용 |
|---|---|---|
| `list` | **발행 콘텐츠** | `KnowledgeReportList` (기본 탭) |
| `upload` | **보고서 등록** | `KnowledgeReportUploadForm` |

⚠️ **상태 공유 주의.** 현재 `KnowledgeReportManager` 가 `reports` 상태를 들고, 업로드 폼의 `onCreated` 가 목록에 즉시 추가한다. **탭을 나눠도 이 연동이 끊기면 안 된다.**
→ `reports` 상태를 **Hub 에서 들고** 두 탭에 내려준다. 등록 후 `list` 탭으로 가면 새 항목이 보여야 한다.

`page.tsx`: `initialReports`·`schemaReady` 는 **서버 조회 유지**, Hub 에 prop 으로 전달(396 §3.2 와 동일 — 함수는 넘기지 않는다).

### 2.2 AI 리포트 — `ReportsHub.tsx` (신규)

| 탭 value | 라벨 | 내용 |
|---|---|---|
| `list` | **발행 콘텐츠** | 필터칩 + `ReportRow` 목록 (기본 탭) |
| `create` | **리포트 생성** | `ReportCreateForm` |

⚠️ **`onCreated` → `load()` 연동 유지.** 생성 후 목록이 갱신되어야 한다. `ReportsManager` 가 클라이언트에서 `/api/admin/reports` 를 직접 조회하므로, **조회·필터 로직을 Hub 로 올리고** 두 탭이 같은 `load()` 를 공유한다.

`page.tsx`: 현재 `AdminPageHeader` + `ReportsManager` 구조 → `Suspense` + `ReportsHub` 로. **`AdminPageHeader` 는 제거**(`AdminTabShell` 이 렌더).

### 2.3 하지 말 것
- 하위 컴포넌트(`KnowledgeReportList`·`UploadForm`·`ReportCreateForm`·`ReportRow`) **내부 로직·UI 수정 금지.** 배치만 바꾼다.
- 최종안의 미구현 탭(지식보고서 §9.3 의 `자료·출처`·`편집·검수`·`발행 설정`, AI 리포트 §9.1 의 `리포트 유형`·`프롬프트`·`모델 설정`·`실행 이력`·`사용량·비용`)을 **만들지 않는다.** (나) 범위다.
- `nav.ts` 무변경. 두 화면 모두 이미 활성이다.
- `/admin/prompts`·`/admin/ai-jobs` 를 **건드리지 않는다**(§1.1).

## 3. 회귀 가드
1. **지식보고서 업로드 → 목록에 즉시 반영**된다(탭 전환해도 유지).
2. 지식보고서 **수정·삭제**가 동작한다(`onUpdated`·`onDeleted`).
3. `schemaReady === false` 일 때 업로드 폼이 비활성 상태로 뜬다.
4. **AI 리포트 생성 → 목록 갱신**된다.
5. AI 리포트 **필터칩 3종**(전체·발행·미발행)과 카운트가 정확하다.
6. AI 리포트 목록의 행 액션(`onChanged`·`onDeleted`)이 동작한다.
7. 로딩·빈 상태·에러 박스가 각각 정상 표시된다.
8. URL `?tab=upload` / `?tab=create` 직접 진입이 동작한다.
9. 브레드크럼이 `리포트 / 지식보고서`, `리포트 / AI 리포트` 로 뜬다.
10. 헤더가 두 번 나오지 않는다.
