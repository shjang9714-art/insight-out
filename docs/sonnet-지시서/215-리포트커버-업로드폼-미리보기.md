# 지시서 215 — 업로드 폼 커버 이미지 미리보기·설정

목표: 콘텐츠 업로드 시점에 커버 이미지를 확인·지정할 수 있게 한다. 커버 미리보기(실제 노출 비율), 직접 업로드, 자동 커버 선택, "커버 없음" 안내, 권장 사이즈 힌트, 교체/제거, 모바일·웹 카드 미리보기를 제공한다.

범위 결정(David): **세 탭(파일 업로드·붙여넣기·URL) 모두** 커버 UI 추가. 미리보기·권장 사이즈 비율은 **16:9(1200×675)**.

전제(중요): 이 작업은 **지시서 211을 확장**하는 것이며 중복 구현을 피한다. 211이 이미 만든 것은 재사용한다.

## 1. 현행 진단 (검증된 코드 사실)

### 211이 이미 구현한 것 (재사용 대상)
- **기본 표지(BrandedCover)**: `src/components/dashboard/ContentCard.tsx` 72–102. 썸네일 없으면 그라디언트+제목+카테고리 칩+발행처를 표시. 카드 컨테이너는 `aspect-[16/9]`(151). `Thumbnail`(104–129)이 url 있으면 `<img>`, 없으면 BrandedCover.
- **편집 모달 커버 업로드/교체/제거**: `src/components/admin/AdminContentManager.tsx`
  - `EditState.thumbnailUrl`(64–74), `openEdit` select에 `thumbnail_url`(337–365), 저장 시 `thumbnail_url` update(384).
  - `handleThumbnailUpload`(414–453): `image/*`·2MB 검증 → `POST /api/admin/upload {filename:'cover.<ext>', kind:'cover', contentId}` → `supabase.storage.from('report-covers').uploadToSignedUrl(...)` → `getPublicUrl` + `?v=<ts>` 캐시버스터.
  - `handleThumbnailRemove`(455–458): `thumbnailUrl: null`(→ 기본 표지 복귀).
- **업로드 API**: `src/app/api/admin/upload/route.ts` — `kind:'cover'`면 `report-covers`(공개) 버킷, 경로 `{contentId}.{ext}`, `upsert:true`. **커버는 contentId 필수.**
- **PDF 자동 표지**: `ReportUploadForm.tsx` handleSubmit 296–333 — PDF는 `renderPdfCover`(`src/lib/contents/pdf-cover.ts`)로 1페이지 webp 생성 후 동일 경로 업로드 + `contents.thumbnail_url` update. **content row insert 이후(=contentId 확보 후) 실행.**
- **데이터 모델**: `contents.thumbnail_url TEXT`(nullable) 이미 존재. `report-covers` 버킷 이미 존재. → **SQL·마이그레이션 불필요.**

### 업로드 폼 3종 현황
`src/app/admin/upload/page.tsx` → `ContentAddTabs`(`src/components/admin/ContentAddTabs.tsx`): 탭1 `ReportUploadForm`, 탭2 `TextPasteForm`, 탭3 `UrlImportForm`(→ TextPasteForm 사용).
- **ReportUploadForm**: 파일·기본정보(제목/카테고리/발행일/저자/출처/요약)·서비스태그·키워드. **커버 UI 없음**(PDF만 자동). insert는 handleSubmit 230–247.
- **TextPasteForm / UrlImportForm**: 커버 선택 로직 **없음**.

### 핵심 제약
커버 업로드 경로가 `{contentId}.{ext}`라 **contentId가 있어야 업로드 가능** → 폼에서는 파일을 로컬 state에 들고 있다가 **content row insert 이후 업로드**해야 한다(PDF 표지와 동일 타이밍).

## 2. 구현

### 2-1. BrandedCover 공유화 (미리보기 재사용)
`ContentCard.tsx`의 `BrandedCover`(+ `CATEGORY_FALLBACK_BG`/`CATEGORY_COLOR` 맵)를 `src/components/dashboard/BrandedCover.tsx`로 분리·export하고, `ContentCard`는 이를 import해 사용(렌더 결과 동일). → 업로드 폼 미리보기가 실제 카드와 **동일한 기본 표지**를 보여준다.
> 가드: ContentCard 시각적 변화 0.

### 2-2. 공유 업로드 헬퍼
편집 모달·PDF 표지·신규 폼이 같은 로직을 쓰도록 `src/lib/contents/upload-cover.ts` 신설:
```ts
// contentId 필요. File 또는 Blob 업로드 후 contents.thumbnail_url 갱신, 캐시버스트 URL 반환
export async function uploadCover(supabase, contentId: string, file: File | Blob, ext = 'jpg'): Promise<string>
```
- `AdminContentManager.handleThumbnailUpload`(414–453), `ReportUploadForm` PDF 표지 블록(296–333)을 이 헬퍼로 리팩터(동작 동일, 중복 제거).

### 2-3. CoverImageField 컴포넌트 (신규, 세 폼 공용)
`src/components/admin/CoverImageField.tsx`:
- Props: `category`, `title`, `sourceName`, `value: File | null`, `onChange(File | null)`.
- **미리보기**: `aspect-[16/9]` 박스. `value` 있으면 로컬 `URL.createObjectURL` 미리보기, 없으면 `<BrandedCover .../>` 렌더. (언마운트 시 objectURL revoke — 누수 가드.)
- **버튼**: 업로드 / 교체 / 제거. `accept="image/*"`, ≤2MB(211과 동일 검증·에러 문구 재사용).
- **권장 사이즈 힌트**: "권장 1200×675 (16:9). 이미지 파일, 2MB 이하."
- **커버 없음 안내**: `value == null`일 때 인라인 안내 "커버를 지정하지 않으면 기본 표지가 표시됩니다." (외부 노출/발행 콘텐츠 권장).
- **모바일·웹 카드 미리보기**: 웹 카드(16:9 상단 이미지 + 제목/요약)와 모바일 카드 폭 두 가지를 나란히 렌더(ContentCard 축약 프리뷰 또는 간이 목업). 실제 노출 형태 확인용.

### 2-4. 세 폼에 통합 + 업로드 타이밍
- **ReportUploadForm**: [기본 정보] 아래 `[커버 이미지]` 섹션에 `CoverImageField` 추가. `coverFile` state 보관. handleSubmit에서 **content insert 이후**:
  - `coverFile` 있으면 `uploadCover(...)` 실행(사용자 커버 우선).
  - `coverFile` 없고 PDF면 기존 자동 표지 로직(자동은 사용자 커버 없을 때만). → **우선순위: 사용자 지정 > PDF 자동 > (없음→렌더 시 기본 표지)**.
- **TextPasteForm / UrlImportForm**: 동일하게 `CoverImageField` 추가 + insert 이후 `uploadCover`. (URL 임포트는 크롤 og:image가 이미 있으면 미리보기 초기값으로 채우되, 사용자가 교체 가능.)
- 전부 **graceful**: 커버 업로드 실패해도 본문 저장은 성공 처리(콘솔 경고), 렌더 시 기본 표지로 폴백.
