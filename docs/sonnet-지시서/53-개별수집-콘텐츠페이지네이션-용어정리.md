## Part 1. 개별 소스 수동 수집 ("이 소스만 수집")

현재 `crawl-now` POST 는 활성 소스 전체를 `runCrawl({force:true})` 로 돌린다. 소스 1개만 즉시 수집하는 경로를 추가.

### 1-1. `src/lib/crawler/orchestrator.ts`
- `RunCrawlOptions` 에 `sourceIds?: string[]` 추가(타입이 `CrawlScheduleOptions` 재export면 거기 확장 or 인터페이스 교차).
- `runCrawl` 내부, rawSources 로드 후 due 선정 전에 스코프 제한:
  ```ts
  const scoped = options.sourceIds?.length
    ? rawSources.filter(s => options.sourceIds!.includes(s.id))
    : rawSources
  const dueSources = selectCrawlSources(scoped, { backfillDays, force: options.force })
  ```
  (개별 수집은 호출부에서 `force:true` 로 보내 주기 무관 즉시 실행.)

### 1-2. `src/app/api/admin/crawl-now/route.ts`
- `POST()` → `POST(request: NextRequest)` 로 변경, **옵션 body** `{ sourceId?: string }` 파싱(body 없을 수 있으니 try/catch):
  ```ts
  let sourceId: string | undefined
  try { sourceId = (await request.json())?.sourceId } catch { /* 전체 수집 */ }
  ```
- `sourcesTotal`: sourceId 있으면 1, 없으면 기존 활성 소스 count.
- 백그라운드 실행: `runCrawl({ force: true, sourceIds: sourceId ? [sourceId] : undefined })`.
- GET(진행 조회)은 그대로(started_at 기준 crawl_logs 집계). 단일 소스도 sourcesTotal=1 로 동일하게 동작.

### 1-3. `src/components/admin/SourceManager.tsx`
- 행 "작업" 칸에 **"이 소스만 수집"** 버튼(아이콘, 예: `RefreshCw`/`DownloadCloud`) 추가.
- `handleCrawlSource(sourceId)`: 기존 `handleCrawlNow` 와 동일하되 `fetch('/api/admin/crawl-now', { method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({ sourceId }) })`, 응답 job 으로 기존 진행 패널(우하단) 재사용(sourcesTotal=1).
- 전역 "지금 수집"(전체) 버튼은 그대로 두되, 크롤 진행 중이면 개별 버튼도 disabled(중복 실행 방지 — 기존 `crawlProgress?.status==='running'` 가드 재사용).

## Part 2. 콘텐츠 관리 페이지네이션 (서버 페이징)
대상: `src/components/admin/AdminContentManager.tsx`

현재 최근 100건만 로드 후 클라이언트 필터 → 100건 밖 누락. **서버 페이징 + 페이지 크기 선택**으로 교체.

### 2-1. 필터·검색을 서버 쿼리로 일원화
- 상태: `page`(1-base, 기본 1), `pageSize`(기본 50, 옵션 20/50/100), `totalCount`.
- 로드 쿼리(모든 필터 서버 적용):
  ```ts
  let q = supabase.from('contents')
    .select('id, title, category, status, collected_at, sources(name)', { count: 'exact' })
    .order('collected_at', { ascending: false })
  if (status !== 'all')   q = q.eq('status', status)
  if (category !== 'all') q = q.eq('category', category)
  if (term.trim())        q = q.ilike('title', `%${term.trim()}%`)
  q = q.range((page-1)*pageSize, page*pageSize - 1)
  const { data, count } = await q
  ```
- 검색어는 **디바운스**(약 300ms) 후 재조회(키 입력마다 쿼리 금지).
- 필터/검색/pageSize 변경 시 `page` 를 1 로 리셋.
- 재조회 의존성: `[status, category, debouncedTerm, page, pageSize]`.
- 기존 클라이언트 `filteredContents`/pending 상단정렬 제거(서버 정렬·필터로 대체). collected_at desc 단일 정렬. (검토 대기는 "검토 대기" 칩으로 status=pending 필터해서 봄.)

### 2-2. 페이지네이션 UI
- 하단에: `이전`/`다음` + "page / totalPages" + 총 건수. totalPages = `Math.ceil(totalCount/pageSize)`.
- 상단 필터 바에 페이지 크기 Select(20/50/100).
- 일괄 선택은 **현재 페이지 기준**(전체선택=현재 페이지 행). pending 카운트 칩(head count)은 유지.

## Part 3. 상태 용어 정리 (라벨만, enum 무변경)

현재 라벨 `게시/보류/반려` + 버튼 `승인/반려` 가 "결재" 느낌이라 혼란. **표시 라벨·버튼 문구만** 바꾼다. `content_status` enum 값(published/pending/rejected)·DB 무변경.

| enum 값 | 기존 라벨 | **신규 라벨** | 의미 |
|---|---|---|---|
| published | 게시 | **노출** | 사용자에게 보임 |
| pending | 보류 | **검토 대기** | 게이트가 자동으로 잡아둔 것(보일지 결정 전) |
| rejected | 반려 | **숨김** | 관리자가 숨김 처리 |

- 행 액션 버튼(문구·동작):
  - 검토 대기·숨김 행 → **[보이기]** (status='published')
  - 노출 행 → **[숨기기]** (status='rejected')
  - 모든 행 → **[삭제]** (기존 delete 유지)
- 일괄 바: **[일괄 보이기]**(published) / **[일괄 숨기기]**(rejected) / [선택 해제].
- 상태 필터 Select·pending 칩 문구도 신규 라벨로("검토 대기 N건").
- `STATUS_STYLE` 의 label 만 교체(색은 유지: 노출=green, 검토대기=yellow, 숨김=red).
- ⚠️ "승인/반려" 단어가 이 컴포넌트 외(예: 다른 어드민 화면·주석)에도 쓰이면 같이 정리(grep `승인`·`반려` 확인). schema.sql enum 주석은 무변경(값 의미는 그대로).
