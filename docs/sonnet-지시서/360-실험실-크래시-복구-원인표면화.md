# 지시서 360 — 실험실(/dashboard/lab) 크래시 복구 + 원인 표면화

> 대상: 구현 에이전트 · **신규 SQL 없음** · 관리자 전용 페이지
> ⚠️ 읽을 것: `src/lib/lab/data.ts`(getLabData) · `src/app/dashboard/lab/page.tsx` · `src/components/analysis/LabBoard.tsx` · `src/components/analysis/InsightCardsSectionClient.tsx`·`IssueBoardClient` · `src/lib/issues/activity.ts` · `AGENTS.md`

## 증상 (David, 재현됨)
관리자로 `/dashboard/lab` 진입 시 세그먼트 error 바운더리("콘텐츠 준비중… 일시적인 문제로 화면을 불러오지 못했습니다"). 상단 레이아웃·다른 대시보드 페이지는 정상 → **lab 세그먼트 한정**.

## 작업

1. `getLabData` 전체를 try/catch로 보호하고 서버 로그에 스택을 기록한 뒤 안전한 빈 `LabData`를 반환한다. 반환 타입의 `error?: string`을 관리자 화면 상단에 노출한다.
2. 병렬·2차 쿼리를 개별 격리하고 어느 쿼리가 실패했는지 `[lab]` 로그 태그와 화면 오류 문자열로 구분한다.
3. 모든 배열 순회와 `LabBoard` 하위 렌더 props를 방어해 부분 데이터나 누락 데이터로 전체 세그먼트가 실패하지 않게 한다.

## 회귀 / 주의

- 신규 SQL 없음. `getLabData`는 실험실 전용이며 다른 대시보드에 영향을 주지 않는다.
- 토큰 색상과 한국어 문구를 사용하고 링크는 `prefetch={false}`를 유지한다.
- 검증: `tsc`·ESLint·`check-prefetch`·`build`, 관리자 화면의 오류 메시지 표면화 확인.
