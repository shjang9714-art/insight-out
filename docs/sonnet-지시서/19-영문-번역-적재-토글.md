## 1. 번역 레이어 — 무료 멀티프로바이더 + 한도 라우팅 (핵심)
`src/lib/translate/` 신규:
- `providers/deepl.ts` · `providers/papago.ts` · `providers/google-unofficial.ts` — 각자 동일 인터페이스:
  ```ts
  interface TranslateProvider {
    name: string                 // 'deepl' | 'papago' | 'google'
    monthlyCharLimit: number     // 무료 한도(문자). deepl 500000, papago 보수적(예: 100000), google 무제한이지만 throttle
    isConfigured(): boolean      // 필요한 env 키 존재 여부
    translate(text: string): Promise<{ text: string; chars: number } | null>
  }
  ```
  - **DeepL Free**: `DEEPL_API_KEY`, endpoint `api-free.deepl.com/v2/translate`, target=KO. 1순위.
  - **Papago**: `PAPAGO_CLIENT_ID`/`PAPAGO_CLIENT_SECRET`(네이버클라우드), source=en target=ko. 2순위.
  - **Google 비공식**: 키 불필요. **요청 간 딜레이(예 1~2s)** + 짧은 타임아웃, ToS·차단 위험이 있으니 **최후 overflow 전용**. 3순위.
- `index.ts`: `translateToKorean(text): Promise<string | null>`:
  1. `period = 'YYYY-MM'(KST)`, `chars = text.length`.
  2. `translation_usage` 에서 이번 달 프로바이더별 사용량 조회(admin).
  3. **configured && (사용량+chars ≤ limit)** 인 프로바이더를 우선순위대로 선택.
  4. 호출 성공 → `increment_translation_usage(provider, period, chars)` 로 사용량 누적 → 번역문 반환.
  5. 실패 시 다음 프로바이더로 폴백. 전부 실패/한도초과 → `null`(미번역 적재).
  - 모든 외부호출 `AbortSignal.timeout`(예 15s). `console.log('[번역] provider=… chars=… month_used=…')` 로깅.
- **제목+본문은 한 번에**(구분자) 번역해 호출/문자수 절약.

## 2. 사용량 스키마 (Codex 가 SQL 작성 → 수희 실행)
`supabase/2026-06-06-번역사용량.sql`(멱등):
- `create table if not exists public.translation_usage ( provider text not null, period text not null, chars bigint not null default 0, updated_at timestamptz not null default now(), primary key (provider, period) );`
- 원자적 증가 RPC:
  ```sql
  create or replace function public.increment_translation_usage(p_provider text, p_period text, p_chars bigint)
  returns void language sql security definer as $$
    insert into public.translation_usage(provider, period, chars, updated_at)
    values (p_provider, p_period, p_chars, now())
    on conflict (provider, period) do update set chars = public.translation_usage.chars + excluded.chars, updated_at = now();
  $$;
  ```
- RLS: 테이블 enable, **service_role(서버)만** read/write(클라이언트 정책 없음). RPC 는 서버에서만 호출.
- 보고에 매체별 아니라 **테이블·RPC 생성 SQL 경로** 명시. **SQL 핸드오프**(수희 실행)라 먼저 커밋 가능.

## 3. 수집 시 번역 (crawler)
`crawlOne` 에서 영문 기사를 **insert 전** 번역:
- 조건: 어댑터 language 판정이 `en`.
- `translateToKorean(제목+본문)` 성공 시 row: `title_original`=영어 원제, `title`=한국어 번역제목, `body_original`=영어 원문, `body_translated_ko`=한국어 번역본, `original_language='en'`.
- 실패/한도초과/키없음: 영어 그대로 적재(`body_translated_ko=null`). **번역 실패가 적재를 막지 않음**(try/catch).
- **한 크롤 실행당 번역 상한**(예 20건) — 초과분은 미번역 적재(다음 틱/백필에서 보충 가능). 한국어 기사는 번역 호출 없음(불변).
- dedup·태깅·품질 순서·로직 불변, 번역 단계만 삽입.

## 4. 상세 페이지 토글
- `original_language==='en'` && `body_translated_ko` 있으면: 기본 **한국어**(`title`/`body_translated_ko`) + **"영어 원문" 배지** + **원문/번역 토글**(클라이언트 island) → 토글 시 `title_original`/`body_original`. (이미 번역 적재 → Suspense 불필요)
- 미번역 영문: 영어 원문 + "원문 보기" 링크. 한국어 기사: 기존대로.
