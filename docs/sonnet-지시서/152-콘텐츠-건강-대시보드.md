## 0. 한 줄

수집 품질이 *어디가 비었는지*를 관리자가 한눈에 못 본다 — 본문 미추출·논조 미분류·태깅 누락·구글뉴스 미해소 링크가 흩어져 있다. 어드민 현황판에 **"콘텐츠 건강" 카드**를 추가해 이 비율들을 점등하고, 각 항목을 **기존 보강 액션(본문 보강·논조 분석·신호 분류·콘텐츠 관리)으로 원클릭 연결**한다. 새 데이터·새 액션 없음 — 기존 신호를 한 화면에 모으고 행동으로 잇는 것.

## 1. 현행 진단 (검증된 코드 사실)

- 건강 신호 컬럼 전부 존재: `body_fetched_at`·`body_len`(130)·`sentiment`(149 자동화)·`matched_groups`(태깅)·`original_url`·`status`.
- 본문 상태 판정(`AdminContentManager.tsx:90~92`): `body_fetched_at IS NULL`=미시도 / `body_len>=400`=풀본문 / `<400`=스니펫. **이 임계(400)를 그대로 미러.**
- 보강 액션 이미 존재: `/admin/contents` 본문 보강·신호 분류 버튼(128·137), `/admin/insights` 논조 분석(149). → 건강 카드는 **이리로 보내기만** 하면 됨.
- 현황판(`src/app/admin/page.tsx`)은 대량 head-count(`count:'exact', head:true`) 병렬 → AdminTodoBlock·AdminOpsSignals·KPI·차트. **여기에 집계·카드 추가.**
- 점등(AdminOpsSignals)은 이슈/엔티티/인사이트/시그널/보고서 *존재 수*만 — 콘텐츠 *품질 비율*은 없음(이 슬라이스가 채움).

## 3. 구현

### 3-1. `src/app/admin/page.tsx` — 건강 집계 추가

기존 `Promise.all`에 head-count 7개 추가(전부 `count:'exact', head:true`):

```ts
// 본문 상태 (전체 기준)
supabase.from('contents').select('*', { count:'exact', head:true }).not('body_fetched_at','is',null).gte('body_len', 400),   // 풀본문
supabase.from('contents').select('*', { count:'exact', head:true }).not('body_fetched_at','is',null).lt('body_len', 400),    // 스니펫
supabase.from('contents').select('*', { count:'exact', head:true }).is('body_fetched_at', null),                              // 미시도
// 논조 (published 기준)
supabase.from('contents').select('*', { count:'exact', head:true }).eq('status','published').is('sentiment', null),           // 논조 미분류
// 태깅 (전체 기준)
supabase.from('contents').select('*', { count:'exact', head:true }).is('matched_groups', null),                              // 태깅 누락
// 원문 링크 위험 (published 기준, 151 자가치유 잔존)
supabase.from('contents').select('*', { count:'exact', head:true }).eq('status','published').ilike('original_url','%news.google.com%'),
```

- `publishedRes.count`(기존 L70)·`totalRes.count`(L67)를 분모로 재사용.
- **graceful**: `body_len` 컬럼 미적용 시 풀본문/스니펫 쿼리가 42703 → `.count`가 null. 컴포넌트에서 null이면 "본문 상태" 블록 숨기고 "처리/미시도"만(또는 안내). page.tsx에서 결과 객체에 `bodyLenAvailable = bodyFullRes.error?.code !== '42703'` 류로 판정해 전달. (130 적용 완료 환경이면 정상.)

집계 객체 구성:
```ts
const contentHealth = {
  total:         totalRes.count ?? 0,
  published:     publishedRes.count ?? 0,
  bodyFull:      bodyFullRes.count ?? 0,
  bodySnippet:   bodySnippetRes.count ?? 0,
  bodyNone:      bodyNoneRes.count ?? 0,
  bodyLenAvailable: !bodyFullRes.error,
  sentimentMissing: sentMissingRes.count ?? 0,   // published 중
  untagged:      untaggedRes.count ?? 0,
  brokenLinks:   brokenLinkRes.count ?? 0,        // published 중
}
```

### 3-2. `src/components/admin/AdminContentHealth.tsx` (신규)

AdminOpsSignals 스타일 미러(AdminSectionHeader + rounded 카드 + 바). 각 행 = 지표 + 보강 링크. **읽기 전용, 새 액션 없음** — `next/link`로 기존 화면 이동.

```tsx
import Link from 'next/link'
import { HeartPulse } from 'lucide-react'
import AdminSectionHeader from '@/components/admin/ui/AdminSectionHeader'
import { cn } from '@/lib/utils'

export interface ContentHealth {
  total: number; published: number
  bodyFull: number; bodySnippet: number; bodyNone: number; bodyLenAvailable: boolean
  sentimentMissing: number; untagged: number; brokenLinks: number
}

function pct(n: number, d: number) { return d > 0 ? Math.round((n / d) * 100) : 0 }
```

표시 항목(각 행: 라벨 · 수/비율 · "보강하기" 링크):
- **본문 풀텍스트** — 풀본문 `bodyFull`/`total` (%). 스니펫·미시도 합이 보강 대상. → Link `/admin/contents`("본문 보강"). `bodyLenAvailable=false`면 미시도만 표시.
- **논조 분류(발행분)** — 미분류 `sentimentMissing`/`published`. → Link `/admin/insights`("논조 분석"). 야간 cron(149)이 줄여줌 안내.
- **태깅** — 미태깅 `untagged`/`total`. → Link `/admin/contents`("신호 분류"/키워드그룹 점검).
- **원문 링크 위험** — `brokenLinks`건(구글뉴스 미해소, 151 클릭 시 자가치유). 0이면 ✅. → Link `/admin/contents`.

비율 바 색은 **위험도 역방향**(나쁠수록 amber/destructive): 미보강 비율 ≥30% amber, ≥60% destructive. 색은 기존 토큰(`bg-amber-500`·`bg-destructive`·`bg-brand-600`)만 — **하드코딩 hex 금지**.

빈/완전 상태: 모든 지표 양호하면 "콘텐츠 건강 양호" 안내([[insight-out-일반사용자-우선]]).
