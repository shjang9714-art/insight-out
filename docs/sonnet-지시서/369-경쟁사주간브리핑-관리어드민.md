# 지시서 369 — 경쟁사 주간 브리핑 관리 어드민 (편집·상태전환·삭제)

> 대상: 구현 에이전트 · 관리자 전용 · **SQL 소량**(status에 'archived' 추가 — sql-handoff 분리)
> ⚠️ 읽을 것: `src/app/admin/competitor-weekly/page.tsx`(하단 "최근 브리핑" 읽기전용 목록) · `src/components/admin/BriefingManager.tsx`(모닝브리핑 관리 패턴 — changeStatus·삭제·낙관적 갱신) · `src/app/api/admin/briefings/[id]/route.ts`(PATCH/DELETE 패턴) · `docs/sql-handoff/261-competitor-weekly.sql`(competitor_weekly_reports 스키마·컬럼·RLS) · `src/lib/admin/verify-admin-request.ts` · `AGENTS.md`

## 배경 (David, 스샷)
`/admin/competitor-weekly`에 생성①·분석②·스케줄③은 있으나 하단 **"최근 브리핑" 목록이 읽기 전용** — 개별 브리핑을 편집·발행·삭제할 방법이 없다. 모닝브리핑(`/admin/briefings` BriefingManager)엔 이미 상태전환·삭제가 있으니 그 패턴을 경쟁사 주간에 이식한다. (David 결정: **본문·제목 편집 + 상태전환(초안↔발행↔보관) + 삭제**. 재생성은 이번 범위 아님 — 기존 생성① 사용.)

## 작업

### 1. SQL 핸드오프 — status에 'archived' 추가 (`docs/sql-handoff/369-cwr-archived-status.sql`)
- `competitor_weekly_reports.status` check가 `('draft','published')`뿐 → **'archived'(보관) 추가**. `alter table ... drop constraint`(기존 이름 확인) 후 `check (status in ('draft','published','archived'))` 재생성. 멱등. **RLS 확인**(published만 사용자 조회 정책 유지 — archived는 사용자 비노출).
- ⚠️ 코드는 이 SQL 미적용(보관 전환 시 23514 check_violation)이어도 **그레이스풀**: 보관 액션은 에러 안내로 처리하고 초안/발행 전환·편집·삭제는 정상 동작.

### 2. 관리 API 신규 — `src/app/api/admin/competitor-weekly/[id]/route.ts`
- `verifyAdminRequest()` 게이트. `briefings/[id]/route.ts` 패턴 재사용.
- **PATCH**: body에 따라 (a)상태전환 `{ status: 'draft'|'published'|'archived' }` (b)내용편집 `{ title?, summary?, sections? }`(261 스키마의 실제 편집 대상 컬럼 확인 — 본문/요약/제목 해당 필드). admin 클라이언트로 `competitor_weekly_reports` update. 발행 시 `published_at`·상태 갱신.
- **DELETE**: 해당 id 삭제. (하드삭제 — 신규 SQL 없이. 실수 방지 confirm은 프런트에서.)
- 42P01(테이블 미적용)·23514(archived 미적용) 등은 의미 있는 에러 메시지로 반환(크래시 금지).

### 3. 관리 UI — "최근 브리핑" 목록을 인터랙티브 클라이언트로
- `page.tsx`의 인라인 읽기전용 목록을 **클라이언트 컴포넌트**(예: `CompetitorWeeklyManager.tsx`)로 교체(BriefingManager 구조 참고). 서버는 초기 목록만 넘기고 이후는 낙관적 갱신.
- 행별 액션: **[편집]**(제목·요약·본문 인라인/모달 수정 → PATCH), **상태전환 버튼**(초안↔발행↔보관, 현재 상태에 따라 노출), **[삭제]**(confirm 후 DELETE). 상태 배지(초안/발행됨/보관)·`overall_impact`(위기 등) 배지는 기존 톤 유지.
- 보관 전환이 23514로 실패하면 "SQL 369 미적용" 안내(그레이스풀).

## 회귀 / 주의
- `verifyAdminRequest` 게이트·admin 클라이언트만(쓰기 RLS 없음). 색 토큰·한글 문구·`prefetch={false}`.
- 사용자 노출은 published만(archived·draft 비노출) — RLS·조회 정책 유지.
- 생성①·분석②·스케줄③ 컴포넌트는 건드리지 말 것(목록 영역만 교체).
- 검증: `tsc`·ESLint·`check-prefetch`·`build` + (dev)브리핑 1건 편집·발행·보관·삭제 왕복. 완료보고에 커밋 해시.
