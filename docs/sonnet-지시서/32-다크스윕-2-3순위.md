## 1. 토큰 치환 매핑 (공통 규칙)

하드코딩 → 시맨틱 토큰. 그대로 일괄 적용:

| 기존(하드코딩) | 교체(토큰) |
|---|---|
| `bg-white` (카드/패널 표면) | `bg-card` |
| `bg-white` (페이지 배경에 쓰인 경우) | `bg-background` |
| `bg-gray-50` / `bg-slate-50` | `bg-muted` |
| `bg-gray-100` (호버/구분 배경) | `bg-muted` 또는 `hover:bg-accent` |
| `text-gray-900` / `text-black` | `text-foreground` |
| `text-gray-600/700/800` (본문) | `text-foreground` 또는 `text-muted-foreground`(보조) |
| `text-gray-400/500` (캡션·placeholder) | `text-muted-foreground` |
| `border-gray-100/200/300` | `border-border` |
| `divide-gray-*` | `divide-border` |

> 판단 기준: **주(主) 텍스트 = `text-foreground`, 보조/캡션 = `text-muted-foreground`**. 표면 카드 = `bg-card`, 한 단계 들어간 배경 = `bg-muted`. 브랜드 색(`brand-*`)·상태색(red/green 의미색)은 **유지**. 단 의미 없는 장식 파스텔은 §3 참조.

## 3. 2순위 — ContentCard 파스텔 fallback (다크 보강)

`src/components/dashboard/ContentCard.tsx` L19~26 `CATEGORY_FALLBACK_BG` 의 카테고리별 `from-*-50 to-*-50` 그라데이션은 썸네일 없을 때 카드 배경이다. 라이트에선 OK지만 **다크에서 파스텔이 그대로 떠서 눈부심**. 두 방식 중 택1:

- **(권장)** 각 항목에 다크 변형을 더한다. 예: `'뉴스': 'from-brand-50 to-pink-50 dark:from-brand-950/40 dark:to-pink-950/30'` 형태로 8개 카테고리 모두 `dark:` 페어 추가. 채도 낮춘 950/40 톤.
- (대안) 다크에선 카테고리 무시하고 일괄 `dark:from-muted dark:to-muted` 로 눌러도 됨(단조롭지만 안전).

L70 기본값 `'from-muted to-muted'` 는 이미 토큰 — 유지.
