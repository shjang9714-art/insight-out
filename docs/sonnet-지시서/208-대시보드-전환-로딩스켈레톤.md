## 0. 한 줄

`/admin`(대시보드)이 `force-dynamic` + Supabase 집계 ~21쿼리를 매 진입마다 돌리는데 **로딩 경계가 없어** 준비 완료까지 이전 화면에 멈춰 있다 → **`src/app/admin/loading.tsx`(스켈레톤)** 추가로 클릭 즉시 전환되게 한다.

## 1. 현행 진단 (검증된 코드 사실)

- `src/app/admin/page.tsx`: `export const dynamic = 'force-dynamic'`(:16). `cookies()`로 인증(→ 캐시 원천 불가, revalidate 무효). KPI·차트용 집계 쿼리 다수를 `await Promise.all([...])`(:55~69)로 병렬 실행 후 렌더. `AdminPageHeader` + KPI 6카드 + `DashboardCharts` + `AdminTodoBlock`/`AdminOpsSignals`/`AdminContentHealth`.
- `src/app/admin/` 및 하위에 **`loading.tsx` 없음**(확인). → Next.js는 로딩 경계가 없으면 새 세그먼트가 완전히 준비될 때까지 **이전 페이지에 머무름** → 클릭 후 수 초 멈춘 것처럼 체감. (쿼리는 병렬이라 순차 문제는 아님; 21개 왕복 총시간 + 무경계가 원인.)

## 2. 구현

### 2-1. `src/app/admin/loading.tsx`(신규)
- 어드민 레이아웃(사이드바+AdminThemeScope) 안 main 영역에 렌더되는 **중립 스켈레톤**:
  - 상단: 페이지 헤더 자리(제목 블록 + 설명 블록).
  - 본문: KPI 카드 그리드 자리(6개 `rounded-2xl` 블록) + 넓은 차트 블록 2~3개.
  - 전부 `bg-muted`/`bg-card` + `animate-pulse`, admin-scope 토큰 사용(신규 hex 0). 실제 대시보드 레이아웃과 대략 비슷한 골격이면 충분.
- `/admin/loading.tsx`는 `/admin` 세그먼트(대시보드)와 그 하위 라우트 로딩의 fallback → **어드민 전체 네비가 즉시 전환**되는 부수효과(허용·바람직). 특정 하위 페이지가 자체 스켈레톤을 원하면 후속으로 각 세그먼트에 loading.tsx 추가.

### 2-2. (선택·권장) 무거운 섹션 스트리밍
- 여력이 되면 대시보드 page.tsx에서 **가벼운 셸(AdminPageHeader) 먼저** 렌더하고, 집계가 필요한 블록(차트·헬스·시그널)을 **async 하위 컴포넌트로 분리해 `<Suspense fallback={스켈레톤}>`** 으로 감싼다 → 헤더 즉시, 데이터 스트리밍. (범위가 크면 2-1만으로도 체감 개선 충분 — 이 항목은 선택.)
