## 배경 (David)
"과거 기사와 연관된 기사 추천" 가능 — 임베딩 없이 **`matched_keywords`/`matched_groups` 배열 겹침**(GIN 인덱스 `overlaps`)으로 v1. 상세 페이지 하단에 **"관련 기사"** 섹션을 추가한다. (의미기반 pgvector 는 후속.)

## 작업

### 1. 상세 select 보강 — `[id]/page.tsx`
- content select 에 **`matched_keywords, matched_groups, cluster_id`** 추가(현재 누락). `ContentDetail` 타입에도 필드 추가(`string[]`·`string|null`).

### 2. 추천 헬퍼 — `src/lib/contents/related.ts` (신규, server-only)
```ts
import 'server-only'
// SupabaseClient 타입은 호출부에서 주입(any 금지 → 적절한 제네릭/타입)
export interface RelatedItem {
  id: string; title: string; summary_ko: string | null
  category: string; published_at: string | null; collected_at: string
  original_url: string | null; sources: { name: string } | null
}
export async function getRelatedContents(
  supabase: /* 서버 클라이언트 타입 */,
  current: { id: string; matched_keywords: string[]; matched_groups: string[]; cluster_id: string | null },
  limit = 6,
): Promise<RelatedItem[]>
```
로직:
- `kws = current.matched_keywords ?? []`, `grps = current.matched_groups ?? []`. 둘 다 비면 `[]` 반환(섹션 숨김).
- 후보 조회(병렬, 각 limit 30): 
  - `kws.length` 면 `supabase.from('contents').select(FIELDS).eq('status','published').neq('id', current.id).overlaps('matched_keywords', kws).limit(30)`
  - `grps.length` 면 동일하게 `overlaps('matched_groups', grps)`.
  - FIELDS = `'id, title, summary_ko, category, published_at, collected_at, original_url, matched_keywords, matched_groups, cluster_id, sources(name)'`.
- 병합·dedup(id). **같은 클러스터 제외**: `current.cluster_id` 있으면 `row.cluster_id === current.cluster_id` 제외 + `row.id === current.cluster_id` 제외(근접중복 숨김).
- 점수: `score = 2 * |kws ∩ row.matched_keywords| + 1 * |grps ∩ row.matched_groups|`. `score > 0` 만.
- 정렬: score desc, 동점은 `collected_at`(또는 published_at) 최신순. 상위 `limit` 반환(matched_* 필드는 응답에서 제외해도 됨).

### 3. 상세 페이지 렌더 — "관련 기사" 섹션
- `getRelatedContents(supabase, content)` 를 서버에서 await(이미 supabase·content 있음).
- `</article>` 뒤(컨테이너 div 안)에 섹션 추가, `related.length > 0` 일 때만:
  - 제목 `<h2 class="text-base font-semibold text-foreground mb-3">관련 기사</h2>`.
  - 목록: 각 항목 `Link href={/dashboard/contents/${r.id}}` — 제목(line-clamp-2) + 메타(카테고리 배지·출처·날짜). `ContentRow` 재사용이 과하면 **콤팩트 카드/행**으로(제목+메타만). 토큰 색(#9)·hover:brand.
  - 모바일 1열·데스크톱 2열 그리드 권장.

## 회귀 / 주의
- DB·인덱스 무변경(matched_* GIN 이미 존재 → overlaps 빠름).
- `overlaps` 인자 배열은 supabase-js 가 인코딩. **키워드에 콤마 포함 시** PostgREST 배열 리터럴 깨질 수 있음(드묾) — 그런 키워드는 무시되거나 빈 결과, 에러는 try/catch 로 흡수해 섹션만 숨김(추천 실패가 상세 렌더를 막지 않게).
- matched_* 비어있는(미태깅) 기사는 관련 섹션 없음(폴백 동일카테고리 최신은 범위 밖, 후속 선택).
- 생성물(AI보고서 등)이 우연히 매칭돼 섞일 수 있음 — 허용(대개 matched_* 없음).
- 서버 컴포넌트 유지. UI 한국어(#1).
