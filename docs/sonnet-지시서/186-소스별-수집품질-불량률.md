## 0. 한 줄

**소스별로 최근 N일 수집 품질**(발행률·검토 대기율=불량률·본문 확보율·dead-link율·불량 사유 분포·북마크 기여)을 집계해 **소스 관리 화면에 노출**하고, 저품질 소스를 식별할 수 있게 한다. 집계는 GROUP BY RPC(수희 핸드오프).

## 1. 현행 진단 (검증된 코드 사실)

- 소스: `sources`(id·name·type·is_active·trust_tier·last_crawled_at). `SourceManager`는 목록 + `/api/admin/source-status`(crawl_logs 7일 집계: 성공/실패 등) 표시 — **콘텐츠 품질 지표는 없음**.
- 재료(contents): `source_id·status(published/pending/rejected)·review_reason(178)·body_len(130)·link_ok(155)·bookmark_count·collected_at`. → 소스별 집계 가능.
- 소스가 수십 개 × 콘텐츠 수천 → 클라이언트 집계 비효율 → **DB RPC로 GROUP BY**.

## 2. DB / SQL (수희 핸드오프)

`docs/sql-handoff/186-source-quality.sql` — RPC `source_quality_stats(p_days int default 30)`:
소스별 total·published·pending·rejected·body_full(≥400)·link_checked·dead_links·bookmarks + 사유 6종(body_missing/short/truncated/extract_failed/low_relevance/llm_irrelevant) 카운트.
→ **먼저 커밋·푸시해 수희 적용**(RPC 없으면 UI는 crawl-status만 표시 graceful).

## 3. 구현

### 3-1. API — `/api/admin/source-quality`(신규) 또는 source-status 확장
- `supabase.rpc('source_quality_stats', { p_days })` 호출(admin service-role) → source_id 별 stat 반환.
- RPC 미존재(42883 등)·오류 → 빈 결과 graceful(UI는 기존 crawl-status만).
- 기간 파라미터(기본 30, 7/14/30 선택 지원).

### 3-2. 파생 지표(API 또는 UI)
- 발행률 = published/total · **검토 대기율(불량률) = pending/total** · 반려율 = rejected/total
- 본문 확보율 = body_full/total · dead-link율 = dead_links/link_checked
- 대표 불량 사유 = 사유 6종 중 최대(라벨은 178 REVIEW_REASON_LABEL 재사용)

### 3-3. UI — `SourceManager`(소스 관리)에 품질 지표
소스 행(또는 확장 패널)에 최근 30일 요약:
- 수집수 · **불량률(검토 대기율) 배지**(높으면 risk 톤) · 본문 확보율 · dead-link율 · 대표 불량 사유 · 북마크 기여.
- **저품질 소스 강조**: 불량률 높음/본문 확보율 낮음/dead-link 많음 → risk 배지·경고 아이콘(175 status-style 톤, 그린 없음).
- 정렬/필터(선택): 불량률순·본문확보율순(후속 가능).
- 기간 셀렉트(7/14/30). 컬럼 과밀하면 핵심(수집수·불량률·본문확보율)만 행에, 나머지는 상세 툴팁/확장.
- `.admin-scope` v2 스타일 자동. 숫자·라벨 admin-* 타이포.

### 3-4. (선택) 소스 상태 라벨
- 정상/주의/저품질 판정(예: 불량률<20% 정상 · 20~40% 주의 · >40% 저품질) 배지. 임계값 가이드(튜닝 허용).

## 4. 회귀 가드 / 비기능 요건

- **RPC 미적용 시 graceful**(품질 지표 숨김, 기존 소스 관리·crawl-status 정상). 178 사유는 적용 완료 가정.
- 집계는 RPC 1콜(소스 전체) — N+1 금지.
- 어드민 한정. 상태색 = 175/180 토큰(그린 없음). 신규 hex 0.
- 기존 소스 CRUD·크롤 실행 무변경.

## 5. 검증 (Sonnet 자체)

3. 저품질 소스가 risk 톤/경고로 강조됨
