## 배경

`keyword_groups`(16그룹, 지시서 51)는 뉴스 수집의 **관련도 게이트 + 해시태그 + 검색 시드**를 한 메커니즘으로 담당하는데, **관리 UI가 전혀 없어 현재 SQL로만 수정** 가능하다. 키워드 기반 수집을 정교화하려면(커버리지↑·오탐↓) 운영자가 직접:
- `search_seeds`(검색 질의어) 를 늘리고 — Google News 키워드 검색(56) + 유튜브 API 검색(60) 공용 커버리지
- `include_patterns`/`exclude_patterns`/`weight` 를 조정해 — 관련도 점수·EXCLUDE 하드reject·게이트 결과 튜닝

해야 한다. 이를 위한 **키워드 그룹 CRUD 화면**을 만든다. SourceManager 와 동일 패턴.

### 설계 결정(Opus)
1. **기존 SourceManager CRUD 패턴 미러**(목록 테이블 + 추가/수정 폼 + 활성 토글 + 삭제). 새 발명 없음.
2. **text[] 필드(include/exclude/search_seeds)는 칩 입력**(ReportUploadForm 키워드 태그 UX: Enter 추가·Backspace 삭제·× 제거).
3. **kind 는 text(슬러그) 자유 입력**, **tag_type 은 enum 셀렉트**(industry/company/tech/market/policy/content_type). 둘 다 기존 값 → SQL 불필요.
4. **클라이언트에서 직접 supabase CRUD**(keyword_groups RLS=admin 전체 `is_admin()` 이미 존재, status 변경과 동일 경로). 서버 라우트 불필요.
5. 게이트 threshold(코드 상수 `RELATEDNESS_THRESHOLD`)는 이 UI 범위 밖 — per-group `weight` 로 세밀 조정. (threshold 설정화는 후속.)

## 작업

### 1. 컴포넌트 `src/components/admin/KeywordGroupManager.tsx`
- SourceManager 구조 미러. `'use client'`.
- 로드: `supabase.from('keyword_groups').select('id, name, kind, tag_type, description, include_patterns, exclude_patterns, weight, search_seeds, is_active').order('kind').order('name')`.
- **목록 테이블**: 이름 / kind / tag_type / weight / include·exclude·seeds 개수(또는 미리보기 칩 몇 개) / 활성 토글 / 작업(수정·삭제). 행 많지 않음(16개+) — 페이지네이션 불필요.
- **추가/수정 폼**(SourceManager 의 showForm 패턴):
  - name(필수), kind(필수, 슬러그), tag_type(셀렉트), description(선택)
  - include_patterns / exclude_patterns / search_seeds → **칩 입력 3개**(각각 text[])
  - weight(number, 기본 1.0), is_active(체크박스)
  - 저장: editingId 있으면 `.update(payload).eq('id', editingId)`, 없으면 `.insert(payload)`. 성공 시 목록 갱신.
- **활성 토글**(낙관적 갱신, 실패 롤백) · **삭제**(window.confirm; "삭제 시 이 그룹의 관련도·태그·검색 시드가 사라집니다. 중단만 원하면 비활성화 권장").
- 검증: name·kind 빈 값 방지. weight 숫자 파싱(빈 값 → 1.0). text[] 는 빈 배열 허용.
- 에러 메시지·UI 텍스트 한국어(#1). 색상은 의미 토큰/brand-* 만(#9, hex 금지). `cn()` 사용.

## 회귀 / 주의
- DB/RLS/enum 무변경. keyword_groups 는 크롤러 게이트·태깅·검색이 읽음 → **값 변경이 다음 수집부터 즉시 반영**(코드 변경 없음). 운영자 실수로 include 비우면 그 그룹 관련도 0 → "지금 수집"으로 검토대기 비율 보며 조정.
- exclude_patterns 는 **하드 reject**(도메인무관 제외)라 과하게 넣으면 정상 기사도 탈락 — 폼에 안내 문구.
- search_seeds 변경은 뉴스(56)·유튜브(60, 구현 시) 검색에 공용 반영.
- admin 외 접근은 미들웨어(`/admin/*`)가 차단(중복 체크 금지). RLS 가 2차 방어.
