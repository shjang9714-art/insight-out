## 0. 한 줄

다크모드를 "완전 검정 단일 톤"에서 **짙은 차콜 3레이어 + 의미 분리된 상태색**으로 바꾼다. ⓐ 배경 레이어/텍스트 티어/보더 토큰을 globals.css에 정의하고, ⓑ 상태색(긍정·리스크·부정·중립) 시맨틱 토큰을 추가해, ⓒ 인텔 화면(159~162로 정리된 AI 인사이트·기업동향·이슈)의 하드코딩 색(emerald/red/orange…)·브랜드 남용을 토큰으로 교체한다.

## 1. 현행 진단 (검증된 코드 사실)

- `src/app/globals.css`: Tailwind v4 `@theme inline` 에서 `--color-*` → `--background`/`--card`/`--border`/`--muted-foreground` 등 CSS 변수 매핑. 실제 값은 `:root`(라이트)·`.dark` 에서 **무채색 oklch 단일 톤**.
  - 다크: `--background: oklch(0.145 0 0)`, `--card: oklch(0.205 0 0)`, `--border: oklch(1 0 0 / 10%)`, `--foreground: oklch(0.985 0 0)`, `--muted-foreground: oklch(0.708 0 0)`. **"섹션 배경" 중간 레이어 없음.**
- 브랜드: `@theme` 에 `--color-brand-50/100/200/600/700`(hex, `#E6007E` 마젠타). brand-600 사용이 전 앱 14개 파일(파일당 9~14회)에 광범위 → 풀 sweep은 본 슬라이스 범위 밖.
- 상태색은 **시맨틱 토큰 없이 Tailwind 하드코딩**으로 흩어짐. 인텔 화면 사용 파일: `analysis/AiInsightsView.tsx`(6), `analysis/InsightCardNewsList.tsx`(1), `issues/IssueSentimentTrend.tsx`(4), `issues/IssueBoardClient.tsx`(4), `issues/IssueEvidenceExplorer.tsx`(2), `entities/EntityBrowse.tsx`(3), `entities/EntityEventTimeline.tsx`(7), `entities/KnowledgeGraph.tsx`(4), `entities/[id]/page.tsx`(7), `entities/page.tsx`(2) — `emerald-*`/`red-*`/`orange-*`/`rose-*`/`amber-*`.

## 3. 구현

### 3-1. globals.css — 다크 배경 레이어/텍스트 티어 (전역)
`.dark` 블록의 무채색을 **차콜 계열 hex**로 교체 + 신규 레이어 토큰 추가. 설계안 §6-1 값 사용(hex 직접 가능):

| 토큰 | 값 | 역할 |
|---|---|---|
| `--background` | `#08090C` | 전체 배경 |
| `--surface`(신규) | `#0D0F14` | 섹션 배경 |
| `--card` | `#151820` | 카드 배경 |
| `--accent`(hover) | `#1B1F28` | 카드 hover |
| `--border` | `#2A2F3A` | 보더 |
| `--foreground` | `#F2F3F5` | 주요 텍스트 |
| `--muted-foreground` | `#8A909A` | 보조 텍스트 |
| `--text-body`(신규) | `#B8BBC2` | 본문 텍스트 |
| `--text-disabled`(신규) | `#5F6670` | 비활성 텍스트 |

- `@theme inline` 에 신규 매핑 추가: `--color-surface: var(--surface)`, `--color-text-body: var(--text-body)`, `--color-text-disabled: var(--text-disabled)`.
- 라이트(`:root`)는 본 슬라이스에서 **신규 토큰만 합당한 라이트 값으로 정의**(surface=섹션 옅은 회색, text-body/disabled 대응). 기존 라이트 무채색은 유지(라이트 풀튜닝은 후속).
- `--muted`(섹션/배지 배경)·`--popover` 등은 새 레이어와 톤 충돌 없게 다크 값 보정.

### 3-2. globals.css — 상태색 시맨틱 토큰 (신규, 라이트+다크)
의미별 토큰을 `@theme` + `:root`/`.dark` 에 추가. 각 색은 **텍스트/아이콘용(진한 값)** 과 **배경용(soft)** 2종:

| 의미 | 토큰 | 다크 예 | 라이트 예 |
|---|---|---|---|
| 긍정/증가 | `--color-positive` / `--color-positive-soft` | 민트 `#34D399` / `#34D39922` | `#059669` / `#ECFDF5` |
| 주의/리스크 | `--color-risk` / `--color-risk-soft` | 오렌지 `#FB923C` / `#FB923C22` | `#EA580C` / `#FFF7ED` |
| 부정/위험 | `--color-negative` / `--color-negative-soft` | 레드 `#F87171` / `#F8717122` | `#DC2626` / `#FEF2F2` |
| 중립/정보 | `--color-neutral` / `--color-neutral-soft` | 그레이 = muted-foreground / muted | 동일 |

- 값은 가이드(접근성 대비 확보 선에서 Sonnet 미세조정 허용). 핵심은 **의미별 분리**.

### 3-3. 인텔 화면 — 하드코딩 색 → 토큰 교체
대상 파일(§1 목록)에서 의미에 맞춰 치환:
- 긍정/증가율 ▲·"긍" 배지: `emerald-*` → `text-positive` / `bg-positive-soft`.
- 부정/하락·"부" 배지: `red-*`/`rose-*` → `text-negative` / `bg-negative-soft`.
- 리스크/주의(브리핑 리스크·경고): 오렌지 → `text-risk` / `bg-risk-soft`.
- 중립/"중" 배지: `muted` 유지(=neutral).
- **증가율(+100%)은 핑크 금지**(설계안 §6-3) — 증가=긍정 맥락이면 positive, 리스크 맥락이면 risk. 기본은 positive, 리스크 어휘 토픽이면 risk(162 `RISK_VOCAB` 참고 가능, 과설계 말고 단순 규칙).
- `InsightBriefCard`(162)의 리스크 섹션 = `text-risk`, 키워드 칩 = 중립/저채도.

### 3-4. 인텔 화면 — 핑크(브랜드) 절제 (한정)
**이 슬라이스 범위 = 인텔 화면(analysis·issues·entities·이 세션 산출 탭)만.** 전 앱 sweep 아님.
- 유지(핑크 OK): 활성 2차 탭, 선택된 필터, 핵심 링크/포커스, "관심 표시" 배지.
- 완화: 토픽/카테고리 칩의 `bg-brand-600/10 text-brand-600` 고정 → 중립(`bg-muted text-muted-foreground`) 또는 저채도. 일반 본문 링크의 brand 남용 → foreground/hover 로.
- 레이어 구조 살리기: 페이지 배경=`background`, 섹션 래퍼=`surface`, 카드=`card`, hover=`accent`.

## 4. 회귀 가드 / 비기능 요건

- **라이트모드 회귀 0**: 신규 토큰이 라이트에서도 정의돼 깨지지 않게(미정의 변수로 인한 투명/검정 금지).
- 대비(WCAG) 확보: 본문 텍스트/배경 대비 4.5:1 지향(주요), 보조/비활성은 톤 위계만.
- 의미 일관: 같은 의미=같은 토큰(긍정이 어디선 emerald, 어디선 민트 = 금지).
- **범위 밖 파일(인텔 외)은 건드리지 않음** — diff 최소화.
- 하드코딩 hex는 globals.css 토큰 정의부에만 허용. **컴포넌트 내 신규 하드코딩 hex 0.**
