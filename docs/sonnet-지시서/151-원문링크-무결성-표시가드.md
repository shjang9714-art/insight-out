## 0. 한 줄

사용자 "원문 보기"가 `content.original_url`을 **그대로** 건다. 그런데 구글뉴스 리다이렉트 해소(`resolveArticleUrl`)는 *수집 시점*에만 돌아서, 해소 실패분은 클릭 시 google 리다이렉트/깨진 페이지로 떨어진다. → **클릭을 서버 리다이렉트 라우트로 통과**시켜 항상 해소된 원문으로 보내고, **성공 시 original_url을 해소값으로 덮어써(자가치유)** 다음부턴 즉시. 기존·신규 콘텐츠 모두 백필 없이 치유.

## 1. 현행 진단 (검증된 코드 사실)

- `src/app/dashboard/contents/[id]/page.tsx` — "원문 보기" `href={content.original_url}` target=_blank (다수 위치: 약 251·306·422행). raw 링크.
- `src/lib/crawler/resolve-url.ts` `resolveArticleUrl(url)` — news.google.com만 redirect-follow 해소(5초 타임아웃, 실패=원본 반환, throw 없음). **수집 파이프라인에서만 호출.**
- 즉 수집 때 해소 실패/미적용 기사는 `original_url`이 google 리다이렉트로 남아 사용자 클릭 시 깨짐.
- 카드/피드 등 다른 곳에서도 original_url 직접 링크 가능(grep 필요).

## 2. DB / SQL

**스키마 변경 없음.** `original_url` 기존 컬럼에 해소값을 덮어써 캐시(자가치유). SQL 핸드오프 없음.

## 3. 구현

### 3-1. `src/app/api/contents/[id]/source/route.ts` (신규, GET 리다이렉트)

```ts
import { NextRequest, NextResponse } from 'next/server'
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'
import { createAdminClient } from '@/lib/supabase/admin'
import { resolveArticleUrl } from '@/lib/crawler/resolve-url'

export const runtime = 'nodejs'
export const dynamic = 'force-dynamic'

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> },
) {
  const { id } = await params
  const detailUrl = new URL(`/dashboard/contents/${id}`, request.url)

  // 로그인 사용자 세션(RLS) — 콘텐츠 가시성 검증
  const cookieStore = await cookies()
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    { cookies: { getAll() { return cookieStore.getAll() }, setAll() {} } },
  )

  const { data } = await supabase
    .from('contents')
    .select('id, original_url')
    .eq('id', id)
    .single()

  const originalUrl = (data as { original_url: string | null } | null)?.original_url
  if (!originalUrl) {
    // 원문 없음(업로드 리포트 등) → 상세로
    return NextResponse.redirect(detailUrl, 302)
  }

  // 해소 (google 리다이렉트만 실제 fetch, 그 외 즉시 반환)
  const resolved = await resolveArticleUrl(originalUrl)

  // 자가치유: 해소돼 바뀌었으면 DB에 덮어써 다음 클릭은 fetch 없이 즉시
  if (resolved !== originalUrl) {
    try {
      await createAdminClient()
        .from('contents')
        .update({ original_url: resolved })
        .eq('id', id)
    } catch { /* 캐시 실패 무시 — 리다이렉트는 진행 */ }
  }

  // 여전히 google이면(해소 실패) 그래도 best-effort 이동
  return NextResponse.redirect(resolved, 302)
}
```

- 외부 URL 리다이렉트는 절대 URL(resolved)이라 그대로. 상세 폴백만 `new URL(..., request.url)`.
- 업데이트는 service-role(admin) — RLS로 일반 사용자 write 불가하므로. 읽기는 사용자 세션(가시성).

### 3-2. "원문 보기" 링크 라우트 경유로 교체

`src/app/dashboard/contents/[id]/page.tsx` 의 모든 사용자용 원문 링크:
```tsx
href={`/api/contents/${content.id}/source`}
```
(target=_blank·rel 유지.) **리포트(file_path) 분기는 무관** — 원문 링크는 뉴스(original_url)에만.

추가: **카드/피드 등 다른 사용자 화면에서 `original_url`을 직접 href로 거는 곳**을 grep(`original_url`)으로 찾아 동일하게 `/api/contents/[id]/source` 경유로 교체. (어드민 화면·내부 디버그 링크는 제외 — 사용자 노출만.)

### 3-3. 본문/링크 빈 상태 가드 (가벼움)

- 원문 링크: 이미 `content.original_url &&` 조건부라 없는 경우 미표시 — 유지(회귀 0).
- 본문 표시: 상세에서 본문이 비거나 스니펫뿐이면 요약/안내가 보이는지 확인(기존 ensureFullBody·summary 경로). 깨진 빈 블록 노출 금지. **신규 로직 최소** — 본질은 링크 무결성.

## 4. 회귀 가드 / 비기능 요건

- 해소 실패/타임아웃 → best-effort로 원래 URL 이동(throw 없음, 기존과 동일 또는 더 나음).
- 정상 원문(비-google) → resolveArticleUrl 즉시 반환, fetch 없음, 지연 0.
- 첫 클릭만 ≤5초(google 해소), 이후 자가치유로 즉시.
- 업로드 리포트(original_url null) → 상세로 안전 폴백.
- SQL·신규 의존성 0. 하드코딩 hex 0.

## 6. 후속 (수집 품질 ②~③, 별 슬라이스 — David "시스템적 양질 유지")

- **링크 헬스 cron + 격리**: 주기적으로 published 콘텐츠 original_url HEAD 체크 → 404/죽은 링크는 `status` 격리(사용자 비노출) + 어드민 리포트. (이번 슬라이스의 자가치유는 google 해소만 — 진짜 dead-link는 여기서.)
- **콘텐츠 건강 대시보드**: 본문 없음/스니펫뿐/저관련도/논조 미분류 비율을 어드민 한 화면에 점등 → "한 클릭 보강". 130 body_len·128 body-backfill·149 sentiment 재사용.
- **저품질 자동 격리**: 수집 후 effectiveLength·isAdLike·관련도 하한 미달분 자동 숨김(현재는 pending까지만) + 주기 정리.
