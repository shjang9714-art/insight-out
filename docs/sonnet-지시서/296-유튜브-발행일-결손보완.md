> 협업 루프: 로컬(커밋X). 위임 → 구현 → 재현검증 → "커밋해" → 커밋·병합·푸시.

---

## 0. 한 줄

**정렬은 이미 발행순이다.** 문제는 **`published_at`이 없는 유튜브가 `collected_at`으로 조용히 폴백**되어, **수집일이 발행일인 척** 표시되는 것이다.

---

## 1. ⚠️ 스펙의 전제 정정

> David 스펙: *"`publishedAt` 기준 정렬(수집일 아님)"*

**이미 그렇게 돼 있다.**
```ts
// src/app/dashboard/contents/page.tsx:227
const sort = (searchParams.get('sort') ?? 'published') as 'published' | 'collected'
//                                        ↑ 기본값이 발행순이다
```
서버 쿼리도 `.order('published_at', { ascending: false, nullsFirst: false })` — **null은 뒤로 밀린다.**

### 진짜 문제 — **조용한 폴백**
```ts
// :114-119  displayDate()
return item.published_at ?? item.collected_at   // ← 발행일이 없으면 수집일을 그대로 보여준다

// :121-124  basisTime()
const d = sortByCollected ? item.collected_at : (item.published_at ?? item.collected_at)
```
→ **사용자는 "발행 2026년 7월 12일"을 보지만 그게 수집일일 수 있다.** 구분이 없다.

`youtube.ts` 어댑터는 `isoDate ?? pubDate`로 `published_at`을 채운다 — **RSS에 날짜가 없으면 null**이다.

---

## 2. ⭐ SQL 먼저 — **진단 없이 구현하지 말 것**

`docs/sql-handoff/296-유튜브-발행일-진단.sql` (수희):
```sql
select
  count(*)                                          as 유튜브_전체,
  count(*) filter (where published_at is null)      as 발행일_없음,
  round(100.0 * count(*) filter (where published_at is null)
        / nullif(count(*),0), 1)                    as 결손률
from public.contents where category = '유튜브';
```

**판단 기준:**
| 결손률 | 조치 |
|---|---|
| **0%** | ⛔ **이 슬라이스 취소.** 할 일이 없다 |
| **~5%** | §3-1(표시 구분)만. 백필은 과하다 |
| **10% 이상** | §3-1 + §3-2(백필) |

> **오늘 이 프로젝트에서 반복된 실수다 — 없는 문제를 고치려 하지 말 것.**

## 3. 구현 (결손률에 따라)

### 3-1. 조용한 폴백을 깬다 (결손이 있으면 무조건)

**`published_at`이 없으면 "발행 …"이라고 쓰지 않는다.**
```
있음:  발행 2026년 7월 12일
없음:  수집 2026년 7월 12일        ← 사실대로
```
- `displayDate()`가 **날짜와 함께 라벨("발행"/"수집")도 반환**하게 한다.
- 지금은 `ContentCard` 등이 `발행 {date}`를 하드코딩하고 있을 가능성이 크다 → **라벨을 props로 받게** 할 것.
- **거짓말을 하지 않는 게 이 슬라이스의 본질이다.** 사용자가 발행일이라고 믿는 게 수집일이면 안 된다.

### 3-2. 백필 — video id로 재조회 (결손률 10% 이상일 때만)

- 대상: `category = '유튜브' AND published_at IS NULL`
- `original_url`에서 **video id를 추출**(`extractVideoId` — 이미 있다. `dashboard/contents/[id]/page.tsx`가 쓴다)
- **YouTube oEmbed 또는 Data API**로 발행일 조회
  - ⚠️ **API 키가 필요하면 David에게 확인할 것.** 없으면 oEmbed(키 불필요)로 가능한지 검토.
  - ⚠️ **레이트 리밋** — 265(자막)에서 겪었다. **배치 상한 + 시도 마커 필수.**
- ⭐ **`published_at_attempted_at` 같은 시도 마커를 둘 것** — 265·310에서 배운 것. **실패한 것을 무한 재시도하면 API 한도가 소진된다.**
  - 단, **"조회 못 함"(영구)과 "레이트 리밋"(일시)을 구분**할 것. 310의 `rate_limited` 패턴을 따를 것.
- 어드민 `/admin/ai-jobs`에 **수동 실행 버튼** + `runJob` 계측. (cc59a1d가 이걸 빠뜨려 사고가 났다.)

## 4. 회귀 가드

- ⛔ **정렬 로직을 바꾸지 말 것.** 이미 발행순이 기본이다. 건드리면 회귀다.
- ⛔ **`published_at`이 없는데 "발행"이라고 표시하지 말 것.** 이게 이 슬라이스의 전부다.
- **`collected_at` 폴백 자체는 유지**한다(정렬이 깨지면 안 된다). **표시 라벨만** 사실대로 바꾼다.
- 리포트(`category = '리포트'`)는 **항상 수집일 기준**이다(`:115`). 그 동작 불변.
- 백필: **시도 마커 없이 돌리지 말 것.** 레이트 리밋 지옥(265).
- 백필: **일시 실패(429)를 영구 실패로 마킹하지 말 것**(310에서 겪은 것).
