### 1.3 조직 3단 매핑 (`src/lib/org.ts` — 확정)

### 1.4 관리자용 update 액션 — 없음. 신규 필요

- → 신규 `updateUserProfileByAdmin` 을 `admin/users/actions.ts` 에 만든다: `requireAdmin()` + `serviceClient().from('users').update({...}).eq('id', targetUserId)` + `revalidatePath('/admin/users')`.

### 1.5 재사용할 편집 UI 패턴
- `src/components/mypage/ServiceSettingsModal.tsx`: `@/components/ui/dialog` + `open`/draft state + 저장 성공 시 닫기. **모달 골격 이식.**

## 2. 구현

### 2.1 조회·타입에 `team_name` 추가 (§1.2 선행)
- `src/app/admin/users/page.tsx` select 에 `team_name` 추가.
- `UserManager.tsx` `UserRow` 타입에 `team_name: string | null` 추가.

### 2.2 신규 서버액션 `updateUserProfileByAdmin` — `src/app/admin/users/actions.ts`
```ts
export async function updateUserProfileByAdmin(
  userId: string,
  patch: { name: string; team: string; team_name: string },
) {
  await requireAdmin()                          // 기존 게이트 재사용
  const name = patch.name.trim()
  const team_name = patch.team_name.trim()
  if (!name) return { ok: false, error: '이름은 비울 수 없습니다.' }
  if (!isOrgGroup(patch.team)) return { ok: false, error: '그룹 값이 올바르지 않습니다.' }
  const { error } = await serviceClient()
    .from('users')
    .update({ name, team: patch.team, team_name, department: FIXED_DEPARTMENT }) // 부문 서버 강제
    .eq('id', userId)
  if (error) return { ok: false, error: error.message }
  revalidatePath('/admin/users')
  return { ok: true }
}
```
- ⚠️ **`role`·`approval_status`·`email` 은 patch 에 절대 넣지 않는다**(프로필 필드만). 이 액션으로 권한/승인이 바뀌면 안 됨.
- `department` 는 클라이언트 입력을 **무시하고 서버에서 `FIXED_DEPARTMENT` 강제**(mypage `saveProfile` 패턴).
- `isOrgGroup`·`FIXED_DEPARTMENT` 는 `@/lib/org` 에서 import.

### 2.3 편집 모달 — `UserManager.tsx`
- 각 사용자 행 **작업 열에 "정보 수정" 버튼** 추가(기존 권한/승인 버튼 옆).
- 클릭 → radix `Dialog`(ServiceSettingsModal 골격) 열림, draft state 초기화(그 사용자의 현재 `name`·`team`·`team_name`).
- 폼 필드:
  - **이름**: text input(필수).
  - **부문**: read-only 표기 `DEPARTMENT_DISPLAY_LABEL`('Ent 부문') — 편집 불가(고정). SettingsTab 처럼 `<input readOnly>`.
  - **그룹**: `ORG_GROUPS` 4종 `<select>`.
  - **팀**: 자유입력 text(placeholder '예: 클라우드사업팀').
- 저장 → `updateUserProfileByAdmin(userId, { name, team, team_name })`.
  - 성공: 모달 닫고 목록 반영(`revalidatePath` + `router.refresh()` 또는 로컬 상태 갱신 — 기존 UserManager 방식에 맞춰).
  - 실패: 에러 문구 표기(기존 톤).
- 로딩/중복 제출 가드(저장 중 버튼 비활성).

### 2.4 팀명 표시(선택, 저비용)
- 이왕 조회에 `team_name` 을 넣었으니, **부서 컬럼을 조직 2줄(그룹·팀)로** 보강하면 좋다 — 408 이 (나) 가입자 현황(대시보드)에 한 것과 동일 취지. 단 어드민 테이블이 좁으면 무리하지 말고 **툴팁/부제 수준**으로. 과하면 생략하고 §7 에 기록.

## 3. 하지 말 것
- **역할(`role`)·승인(`approval_status`)·이메일 편집을 이 모달에 넣지 않는다.** 기존 액션(`updateUserRole`·`approveUser`·`rejectUser`) 그대로 유지.
- `updateOwnProfile`(본인 전용) **무수정·미사용**(어드민용은 신규 액션).
- `department` 를 클라이언트가 바꾸게 하지 않는다(서버 `FIXED_DEPARTMENT` 강제).
- `requireAdmin()` 게이트 **우회 금지** — 신규 액션도 반드시 통과.
- 온보딩/마이페이지 프로필 저장 경로 **무관·무수정**.
- DB 스키마 변경 없음(SQL 0) — `users` 테이블에 컬럼 이미 존재.

## 4. 회귀 가드
1. 사용자 행에 **"정보 수정"** 버튼, 클릭 시 모달에 현재 이름·그룹·팀이 채워짐.
2. 그룹은 `ORG_GROUPS` 4종 dropdown, 팀은 자유입력, 부문은 'Ent 부문' read-only.
3. 저장 → `users.name`/`team`/`team_name` 갱신, 목록에 즉시 반영.
4. **역할·승인 상태는 이 저장으로 안 바뀐다**(별도 확인).
5. 이름 공백·잘못된 그룹 값이면 저장 거부(에러 문구).
6. 비관리자/미인증은 액션 거부(`requireAdmin`).
7. 기존 권한 토글·승인/거절·admin 승격이 **그대로 동작**(회귀 없음).
8. `team_name` 이 조회·타입에 추가돼도 다른 화면(대시보드) 영향 없음.
