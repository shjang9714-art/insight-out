## 0. 한 줄

라이트 배경(`#F7F8FA`, 흰색 대비 ~2%)이 흰 카드와 거의 같아 카드가 묻히는 문제를, **배경을 한 단계 회색으로(`#EEF1F5`) + 카드에 옅은 그림자**를 더해 분리한다(어드민 라이트만, 다크 무변경).

## 1. 현행 진단 (검증된 코드 사실)

- `globals.css` `.admin-scope`(180) 라이트: `--background:#F7F8FA` · `--card:#FFFFFF` · `--border:#E5E7EB`. 배경-카드 대비가 약해 경계 흐림.
- 다크(`.admin-scope[data-admin-theme="dark"]`)는 `#0B0F14` vs `#121821`로 분리 양호 — **무변경**.

## 2. DB / SQL

**없음.**

## 3. 구현 (`globals.css` `.admin-scope` 라이트)

1. `--background: #F7F8FA` → **`#EEF1F5`**(회색 한 단계 ↓ — 흰 카드가 "캔버스 위에 뜬" 느낌). (`--muted`/`--accent`도 배경과 톤 균형 확인, 필요 시 미세조정.)
2. **카드 옅은 그림자**: 어드민 카드에 subtle elevation. 방식:
   - `.admin-scope`(라이트에서만) 카드 계열에 `box-shadow: 0 1px 2px rgba(16,24,40,.06)` 적용. 예: `.admin-scope:not([data-admin-theme="dark"]) .bg-card, ...` 는 취약 → **권장: 카드 공용 클래스가 있으면 거기, 없으면 `.admin-scope [class*="bg-card"]` 대신** 명시적 유틸(`shadow-sm`)을 카드 컴포넌트/래퍼에 추가하거나, `.admin-scope` 라이트에 카드 elevation용 CSS 규칙 정의.
   - 다크에서는 그림자 제거/약화(`data-admin-theme="dark"`에서 shadow none) — 다크는 보더로 충분.
3. 보더 `#E5E7EB` 유지(그림자 + 보더 + 배경 대비 3중으로 카드 분리).

> 구현 자유도: ①(배경 회색화)만으로도 상당히 개선됨. ②(그림자)는 보강. 과한 그림자 금지(subtle).

## 4. 회귀 가드 / 비기능 요건

- **어드민 라이트만** 변경 — 다크·사용자 화면 무영향.
- 배경만 낮추고 카드는 흰색 유지(대비 확보). 그림자는 은은하게(엘리베이션 과다 금지).
- 토큰 정의부 외 신규 hex 0(배경/그림자 값은 스코프 정의부 허용).

## 5. 검증 (Sonnet 자체)

3. 다크 어드민·사용자 화면 무변경
4. 그림자 과하지 않음, 신규 hex 0(스코프 정의부 제외)
