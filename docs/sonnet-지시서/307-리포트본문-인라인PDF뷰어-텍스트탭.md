## 1. 현행 진단 (검증된 코드 사실)

### 1.1 리포트 상세는 **이미 콘텐츠형이다** — 본문 자리만 다르다
`src/app/dashboard/contents/[id]/page.tsx`는 리포트에도 제목·카테고리 칩·발행기관·발행일·**요약(`summary_ko`)**·**키워드 칩**·관련 기업·관련 콘텐츠·북마크·아카이브를 뉴스와 **동일하게** 렌더한다.
→ **문제는 "콘텐츠처럼 안 보인다"가 아니다. 본문 자리에 브라우저 PDF 뷰어를 통째로 박아 넣은 것뿐이다.**

### 1.2 현재 분기 (`:442`, `:484`)
```
isReport (file_path 있음) ?
    signedUrl && isPdf   → <iframe src={signedUrl} style={{height:'80vh'}} />   ← 이것
  : signedUrl && !isPdf  → 다운로드 안내
  : (실패)               → "파일을 불러올 수 없습니다."
: bodyMarkdown ? <ReportMarkdown> : <ArticleBodyLoader>
```
문제:
- **iOS Safari는 iframe 내 PDF를 렌더하지 않는다** → 모바일에서 빈 화면일 가능성이 크다. **가장 먼저 실기기로 확인할 것.**
- 80vh 박스 안에 브라우저 뷰어가 들어가 **이중 스크롤**·UI 이질감.
- **`bodyMarkdown`은 리포트에서 도달 불가**다(`:484`는 `isReport === false`일 때만). 212에서 만든 어드민 본문 편집기가 **사용자에게 도달하지 않는다.** 죽은 경로.

### 1.3 재료는 이미 다 있다
| 필요 | 현황 |
|---|---|
| 클라이언트 PDF 렌더 | ✅ **`pdfjs-dist ^6.1.200` 이미 dependencies** (설치 불필요) |
| 추출된 원문 텍스트 | ✅ `contents.body_original` — `extract/route.ts:243`이 업로드 시 자동 저장 |
| 마크다운 본문·렌더러 | ✅ `body_markdown`(212) + `src/components/reports/ReportMarkdown.tsx`(remark-gfm) |
| 서명 URL | ✅ `getReportSignedUrl` — `src/lib/contents/report-url.ts` |

### 1.4 ⚠️ 함정 — 서명 URL이 **30분 만료**다
```ts
// src/lib/contents/report-url.ts:13
.createSignedUrl(filePath, 60 * 30)   // 30분
```
pdf.js는 PDF를 **range 요청으로 조각조각** 가져온다. 42페이지 리포트를 30분 넘게 열어두면 **뒤쪽 페이지 로드가 조용히 실패**한다.
→ **§3-4에서 반드시 처리할 것.** 이걸 놓치면 "가끔 뒷장이 안 나온다"는 재현 어려운 버그가 된다.

## 3. 구현

대상: `src/app/dashboard/contents/[id]/page.tsx`의 `isReport` 분기 + 신규 클라이언트 컴포넌트.

### 3-1. 본문 자리 = 탭 구조

```
[원문 보기]  [텍스트로 보기]              [원문 PDF 다운로드]
```
- 기본 탭: **원문 보기**(PDF 뷰어).
- `body_original`이 없으면(스캔·추출 실패) **[텍스트로 보기] 탭 자체를 숨긴다.** 빈 탭을 만들지 말 것.
- **`body_markdown`이 있으면** 탭 구성이 바뀐다 → §3-5.

### 3-2. ⭐ 원문 보기 — pdf.js 인라인 뷰어 (신규 클라이언트 컴포넌트)

`src/components/contents/PdfViewer.tsx` (`'use client'`)

- `pdfjs-dist`로 **페이지를 canvas에 연속 렌더**(세로 스크롤, 페이지 사이 간격).
- **폭은 컨테이너에 맞춘다**(`scale = containerWidth / viewport.width`). 고정 배율 금지 — 모바일에서 깨진다.
- **텍스트 레이어를 반드시 얹는다.** 이게 없으면 선택·복사·Ctrl+F가 안 되고, 그러면 iframe보다 나을 게 없다.
  - pdfjs-dist **v6는 `TextLayer` 클래스**다(구버전 `renderTextLayer` 아님). API 확인하고 쓸 것.
  - 텍스트 레이어 정렬 CSS 필요(투명 span 오버레이). `pdfjs-dist/web/pdf_viewer.css`를 쓰거나 필요한 규칙만 옮길 것.
- **⭐ 가상 스크롤 — 이 슬라이스의 유일한 난점.**
  - 42페이지를 전부 canvas로 그리면 메모리·렌더가 터진다.
  - **IntersectionObserver로 보이는 페이지(+앞뒤 1~2장)만 렌더**하고, 벗어나면 canvas를 비운다.
  - 렌더 안 된 페이지는 **정확한 높이의 placeholder**로 자리를 잡아야 스크롤이 튀지 않는다(`getViewport`로 미리 계산).
  - 동시 렌더는 1~2장으로 제한.
- **워커 설정**: `GlobalWorkerOptions.workerSrc`. Next 16(Turbopack)에서 동작하는 방식으로 잡을 것 — `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)` 또는 `public/`에 복사. **어느 쪽이든 프로덕션 빌드에서 워커가 실제로 로드되는지 확인할 것**(dev만 되고 prod에서 깨지는 게 흔하다).
- 상단에 페이지 표시(`3 / 42`) 정도면 충분. **줌·회전·인쇄 버튼은 만들지 말 것**(범위 밖 — 필요하면 다운로드).
- 로딩·실패 상태를 표시할 것. 실패 시 **[원문 PDF 다운로드]로 안내**(§3-6).

### 3-3. 텍스트로 보기 탭 — **변환 없음**

- `content.body_original`을 그대로 렌더한다. **LLM·구조화·가공 금지.**
- **이건 원문 문자 그대로라 틀릴 수가 없다.** 그게 이 탭의 존재 이유다.
- 다만 최소 정리만: 기존 `cleanBodyText(htmlToPlainText(...))`를 재사용하고, 문단 구분(`\n\n`)만 살려 `<p>`로 렌더. 읽기 좋은 폭(`max-w-prose`)·행간.
- **모바일에서 리포트를 읽는 실질적 수단은 이 탭이다.** 뷰어는 A4를 폭에 맞추면 글자가 작다.

### 3-4. ⭐ 서명 URL 30분 만료 대응 (§1.4)

둘 다 한다:
1. **만료 시간을 늘린다** — `report-url.ts`의 `60 * 30` → **`60 * 60 * 2`(2시간)**. 비공개 버킷 서명 URL이고 로그인 뒤라 위험이 낮다.
2. **그래도 실패할 수 있으므로 재발급 경로를 둔다** — 뷰어가 로드/렌더 실패를 잡으면 서명 URL을 **다시 받아 1회 재시도**한다.
   - 서버 액션 또는 작은 라우트로 `getReportSignedUrl(file_path)` 재호출.
   - **재시도는 1회만.** 무한 루프 금지.
3. **실패를 삼키지 말 것** — 재시도까지 실패하면 사용자에게 보이는 메시지 + `console.error`. (289·291·293과 같은 이유: 조용한 실패 금지.)

### 3-5. `body_markdown` 우선 (죽은 경로 살리기, §1.2)

`isReport`이면서 **`body_markdown`이 있으면**:
- 기본 탭을 **[본문]**(`<ReportMarkdown>`)으로 하고, 탭 구성을 `[본문] [원문 보기]` 로 한다. (텍스트 탭은 숨김 — 본문이 더 낫다.)
- **자동 변환은 하지 않는다.** 이건 *"중요한 리포트는 사람이 어드민에서 다듬어 넣는다"* 는 **수동 큐레이션 경로**를 여는 것뿐이다.
- `body_markdown` 조회는 **이미 `:124`에 42703 graceful 가드 쿼리로 존재**한다. 그대로 쓸 것.

### 3-6. 다운로드

- **[원문 PDF 다운로드]** — 보조 버튼(강조하지 말 것. 우선 읽을 것은 화면 본문이다).
- **파일명을 알아보게** 만든다: `{제목}_{발행기관}.pdf` 형태. 공백·경로 문자 정리, 한글 유지.
  - Supabase `createSignedUrl`의 `download` 옵션으로 파일명을 지정할 수 있다. 확인하고 쓸 것.
- PDF가 아닌 파일(`!isPdf`)은 **기존 다운로드 안내 UI를 그대로 유지**한다. 건드리지 말 것.

## 4. 회귀 가드

- **PDF를 HTML로 변환하지 말 것.** LLM·OCR·표 복원·블록 JSON 전부 **범위 밖이고, 하지 않기로 결정됐다.** 이 슬라이스는 **변환 0**이다.
- **텍스트 레이어 없는 canvas-only 뷰어는 실패다.** 선택·복사·Ctrl+F가 안 되면 iframe보다 나을 게 없다. 이게 이 슬라이스의 핵심 가치다.
- **가상 스크롤 없이 전 페이지를 렌더하지 말 것.** 42페이지에서 브라우저가 죽는다.
- **placeholder 높이를 실제 뷰포트 비율로 잡을 것.** 대충 잡으면 스크롤이 튀어 못 쓴다.
- **서명 URL 만료(§3-4)를 처리하지 않으면 "가끔 뒷장이 안 나온다"는 재현 어려운 버그가 남는다.** 반드시 처리.
- **실패를 조용히 넘기지 말 것** — 뷰어 로드 실패는 화면에 보이고 로그에 남아야 한다.
- `body_original`이 없으면 **텍스트 탭을 숨긴다.** 빈 탭 금지.
- 리포트 상세의 **나머지(요약·키워드·관련 콘텐츠·북마크·아카이브)는 불변.** 본문 자리만 바꾼다.
- **PDF 외 파일 분기·서명 URL 실패 분기는 기존 UI 유지.**
- 291의 PDF **커버** 경로(`pdf-cover`)와 무관하다. 건드리지 말 것.

## 6. 후속(범위 밖) — 결정 근거를 함께 남긴다

- **PDF → HTML 자동 변환(LLM 구조화·차트 추출·OCR·블록 JSON) — 폐기.**
