## 배경 (David)

이슈 레이어 마무리 두 가지: (1) **유사 이슈** — 한 이슈를 보다가 엔티티를 많이 공유하는 관련 이슈로 자연 이동. (2) **변화 감지** — 활동 급상승뿐 아니라 **논조가 나빠진** 이슈를 눈에 띄게(담당자가 놓치면 안 되는 변화).

## 설계 결정 (Opus)

1. **유사 이슈 = 엔티티 공유도**(co-occurrence 기반). 두 이슈가 공유하는 엔티티 수로 유사도. 콘텐츠 직접 공유보다 의미가 풍부.
2. **변화 감지 = 활동 급상승 ∪ 논조 악화**. 104 활동 집계(이번주/직전주)에 **직전 주 대비 부정 논조 비율 상승**을 더해 `changeFlag` 산출.
3. **신규 SQL 없음**(바운디드 집계). 이슈 수가 매우 커지면 유사도 RPC는 후속.
4. 배지/표현은 91/101/104 톤과 일관.

## 작업

### A. 활동 lib 확장 — `src/lib/issues/activity.ts`
- `IssueCard`(또는 활동 결과)에 추가: 직전 주 부정 수 → `prevNeg`, 최근 부정 비율 vs 직전 부정 비율 비교로 **`sentimentWorsening: boolean`**(예: 최근 부정비율 ≥ 직전 + 15%p 이고 최근 표본 ≥ 3). 그리고 **`changeFlag: 'surge' | 'worsening' | null`**(surge=기존 급상승 기준, worsening=논조 악화; 둘 다면 worsening 우선 또는 둘 표시).

### B. 변화 감지 배지 — 보드 + 홈
- `src/app/dashboard/issues/page.tsx`(보드 카드): 기존 급상승 배지 옆/대신 **`changeFlag`** 표시 — `surge`=▲급상승(기존), `worsening`=⚠ "논조 악화"(red/amber 톤). (선택) 상단에 "변화 감지" 필터/정렬 토글.

### C. 유사 이슈 — 이슈 상세 — `src/app/dashboard/issues/[id]/page.tsx`
- 이 이슈의 엔티티 집합 산출: 이슈 content_ids → `content_entities` → entity_id 집합(상위 N, 빈도순).
- 다른 이슈들과의 공유도: 
  - 후보 콘텐츠: 그 엔티티들을 가진 `content_entities`(`entity_id in 집합`) → content_id 집합.
  - 그 content_id 들이 속한 `issue_contents`(`issue_id != 현재`) → issue_id별 카운트 = 공유 점수.
  - 상위 3~5 이슈 → `issues`(published, title) join → "유사 이슈" 섹션(링크 `/dashboard/issues/{id}` + 공유 점수/공유 엔티티 수 표시).
  - 바운디드(엔티티 상위 N·content cap). 0이면 섹션 생략.
- 위치: 관련 엔티티 섹션 근처(이슈 상세 하단).
