> 작성: Opus(Cowork) · 대상: 구현 에이전트(Claude Code) · 검증: Opus · 커밋: 구현 에이전트
> ⚠️ 작업 전: `src/app/api/admin/translate-backfill/route.ts`(미러 템플릿) · `src/lib/crawler/orchestrator.ts`(`enrichRecentContents` L832~·상수 `MAX_ENRICH_PER_CRAWL`/`ENRICH_MIN_BODY_LEN`) · `src/lib/crawler/resolve-url.ts`(`resolveArticleUrl`) · `src/lib/contents/clean-body.ts`(`cleanBodyText`/`htmlToPlainText`) · `src/components/admin/AdminContentManager.tsx`(툴바 버튼 위치). `npm install` 먼저.

## 배경 (David)

본문을 우리 DB에 제대로 **축적**해야 요약·분류·엔티티·검색의 토대가 선다. 현재 `enrichRecentContents`는 **이번 크롤분만**(`collected_at >= runStartedAt`) + 1회 `MAX_ENRICH_PER_CRAWL=15` 한도라:
- 과거 코퍼스(~1931건)는 대부분 스니펫만(보강 도입 전 수집분 미대상).
- 한 크롤에서 15건 초과 신규분도 다음 런이 안 줌(collected_at이 다음 runStartedAt보다 과거 → 쿼리 제외) → 스니펫 고착.

→ **run 시점과 무관하게 `body_fetched_at IS NULL` 전체를 배치로 훑는 백필**이 필요. 키 없이 지금 가능. (요약 재생성은 키 살면 크롤 enrich가 자동 처리.)

## 설계 결정 (Opus)

1. `translate-backfill` 패턴 그대로 **`POST /api/admin/body-backfill?limit=N`** 신설(어드민 게이트·`maxDuration=300`). `runStartedAt` 의존 제거 → `body_fetched_at IS NULL` + `original_url NOT NULL` 전체 대상.
2. 멱등·반복 실행: 처리분은 `body_fetched_at` 마킹 → 다음 호출은 남은 것만. 반환 `{ processed, improved, skipped, remaining }`.
3. **LLM 미사용**(본문만 채움). 요약 재생성은 본 백필에서 안 함(크롤 enrich/후속 키 복구가 담당).
4. 추출 로직은 `enrichRecentContents`와 **동일 규칙 재사용**(드리프트 방지 위해 공유 헬퍼 권장).

## 작업

### A. (권장) 공유 헬퍼 — `src/lib/contents/enrich-body.ts` (신규)
- `enrichOneBody(admin, row): Promise<'improved' | 'marked' | 'error'>`:
  - `resolveArticleUrl(row.original_url)` → `extract(resolved, {}, { signal: AbortSignal.timeout(6000) })`.
  - `extracted = cleanBodyText(htmlToPlainText(result.content))`. 기존 `existingBody`와 비교해 `extracted.length > existingBody.length && >= ENRICH_MIN_BODY_LEN(400)` 면 `body_original`+`body_fetched_at` 업데이트 후 `'improved'`. 아니면 `body_fetched_at`만 마킹 후 `'marked'`. 실패는 try/catch로 `'marked'`(재시도 방지) 또는 `'error'`.
- `orchestrator.enrichRecentContents` 의 per-item 본문 부분도 이 헬퍼를 쓰도록 리팩터(요약 재생성은 orchestrator에 남김 — 헬퍼는 본문만). **동작 동치 유지.**
  - (리스크 줄이려면) orchestrator 리팩터는 생략하고 라우트에서 동일 로직을 복제해도 됨. 단 상수/규칙 일치.

### B. 백필 라우트 — `src/app/api/admin/body-backfill/route.ts` (신규, POST)
- `translate-backfill` 미러: 어드민 게이트·`runtime='nodejs'`·`maxDuration=300`.
- `limit` = clamp(parseInt(?limit) || 15, 1, **30**). (추출 6초/건이라 번역보다 작게.)
- 대상 쿼리: `contents.select('id, original_url, body_original').is('body_fetched_at', null).not('original_url','is',null).order('collected_at', desc).limit(limit)`.
- 루프: 각 행 `enrichOneBody` 호출, `improved`/`marked` 집계.
- 남은 수: `count(body_fetched_at is null AND original_url not null)`.
- 반환 `{ processed, improved, skipped, remaining }`.

### C. UI 버튼 — `src/components/admin/AdminContentManager.tsx` 툴바
- 기존 "수집 기사 비우기" 류 버튼 옆에 **"본문 보강"** 추가: 클릭 → `POST /api/admin/body-backfill?limit=15` → 결과(`improved/processed·remaining`) 토스트/문구 표시 → **남은 게 있으면 "다시 실행" 안내**(반복 클릭으로 소진). 로딩·에러 한국어. (논조/번역 백필 버튼 UX 미러.)
- 디자인: 하드코딩 hex 금지, 기존 토큰. (125 프리미티브 있으면 재사용.)
