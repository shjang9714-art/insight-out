## 1. 현행 진단 (검증된 코드 사실)

### 1.1 근본 원인 — 모달 폭이 512px다
```tsx
// src/components/admin/AdminContentManager.tsx:1056
<DialogContent className="max-w-lg">   // max-w-lg = 512px
```
→ 모든 필드가 **세로로 쌓이고**, 본문 편집기가 맨 아래로 밀려 짓눌린다. 커버는 파일 입력 한 줄이 된다.
**이건 레이아웃 문제다.** (아래 §1.2 참조)

### 1.2 ⚠️ David 스펙의 전제 정정
스펙 §1은 *"새 창 방식은 팝업 차단·창이 여러 개 쌓임·모바일 대응 어려움"* 을 근거로 **전체 페이지 전환**을 주장한다.
**그러나 현재는 `window.open`이 아니라 shadcn `Dialog`(모달)다.** 그 논거 대부분이 존재하지 않는 문제다.

→ **전체 페이지(`/admin/contents/[id]/edit`)로 전환하지 않는다.** 스펙 §5(*"팝업을 유지한다면"*)가 사실상 정답이다. 모달 규격만 고치면 진짜 불편이 해결되고, 라우팅 전환의 비용·리스크를 안 진다.
> (참고: 어드민 콘텐츠 상세 페이지 `/admin/contents/[id]`는 **이미 존재**한다. 나중에 전체 페이지가 필요해지면 여기 얹으면 된다.)

### 1.3 ⭐ 진짜 병목 — 2,326건
화면에 `검토 대기 2,326 / 총 4,538건`이 찍혀 있다.
**이 규모에서는 "한 건을 얼마나 예쁘게 편집하느냐"보다 "2,326건을 어떻게 빨리 훑느냐"가 압도적으로 중요하다.**
목록 ↔ 모달 왕복으로 처리하면 클릭만 수천 번이다. **연속 검수가 본체다.**

### 1.4 연속 검수 재료가 이미 다 있다
- 목록 데이터가 메모리에 있다: `const [contents, setContents] = useState<AdminContentRow[]>([])` (`:157`), `page`/`pageSize`(`:184-185`), `.range(...)`(`:285`).
  → **현재 페이지 안에서의 이전/다음 이동은 배열 인덱스만 옮기면 된다.**
- 편집 상태: `const [edit, setEdit] = useState<EditState | null>(null)` (`:193`).
- 저장은 `.update(updatePayload)`가 **2곳**이다: `:418`(본 경로) + `:426`(**`body_markdown` 컬럼 미적용 42703 graceful 재시도**).
  → **필드를 추가하면 `updatePayload` 한 곳만 고치면 되지만, 이 2단 구조를 깨지 말 것.**

### 1.5 ⚠️ 키워드 — 편집 모달에 **아예 없다** (지시서 초안의 전제 오류를 정정한다)
`AdminContentManager.tsx`에 `keyword` 문자열이 **0회** 등장한다. `EditState`(`:65-77`)는
`id · title · summary · category · sourceId · author · publishedAt · bodyOriginal · bodyMarkdown · thumbnailUrl · filePath` 뿐이다.

→ **검수자가 키워드를 볼 수도, 고칠 수도 없다.** 그런데 서비스 카드는 키워드를 렌더한다
(`dashboard/contents/page.tsx:641` → `keywords={item.matched_keywords ?? []}`).
**검수 화면에서 안 보이는 값이 사용자 화면에는 보인다.** 이게 2,326건 검수의 실제 구멍이다.

**저장 위치**: `contents.matched_keywords` (`text[]` 컬럼). 별도 테이블 아님 → **SQL 불필요.**

**덮어쓰기 안전 여부 — 검증했다(중요):**
- 재크롤은 `upsert`가 아니라 **`insert` + URL 중복(23505) 멱등 스킵**이다 (`crawler/orchestrator.ts:503`).
- `matched_keywords`를 쓰는 `tagContent`(`:150`)·`tagYoutubeContent`(`:546`)는 **신규 적재 경로에서만** 호출된다.
- → **수동 편집한 키워드가 재크롤로 덮어써지지 않는다.** 편집 기능을 넣어도 안전하다.

### 1.6 카드 미리보기 — 서비스 컴포넌트를 그대로 쓸 수 있다

## 3. 구현

### 3-1. 모달 규격 — 넓은 2패널
```
폭   : min(1440px, calc(100vw - 64px))
높이 : calc(100vh - 48px), 최대 960px
```
- `max-w-lg` **제거**.
- **헤더 고정 · 푸터(저장 영역) 고정 · 좌우 패널 각각 독립 스크롤.**
- **좌 36~40% / 우 60~64%** (또는 좌 400~460px 고정 + 우 유동).
- **Esc 닫기 시 변경사항 있으면 확인**. **외부 클릭으로 닫히지 않게** 할 것(작업 중 실수로 날아가면 안 된다).
- **1024px 미만**: 2패널 유지하지 말고 **탭 전환**(`[카드·설정] [본문 편집]`).

**왼쪽 패널** — 카드 미리보기 · 커버 · 요약 · 키워드
**오른쪽 패널** — 제목 · **본문 편집기(최소 높이 560px 이상, 패널 대부분 차지)** · 출처/발행 정보(접이식)

### 3-2. ⭐ 연속 검수 (이 지시서의 본체)

- **이전/다음 콘텐츠 이동**: 모달 헤더에 `← 이전` / `다음 →`. 현재 페이지의 `contents` 배열에서 인덱스 이동.
  - 페이지 경계에서는 비활성(간단히). 페이지 넘김까지 하려면 복잡해지니 **이번 범위 밖**.
- **진행률 표시**: `12 / 50` (현재 페이지 기준) + 전체 검토 대기 건수.
- **저장 드롭다운**: `[저장]` + `▾`
  - 저장
  - **저장 후 다음 콘텐츠** ← 검수 루프의 핵심. 기본값으로 둘 만하다.
  - 저장 후 노출 / 저장 후 숨김
  - 저장 후 목록으로
- **미저장 변경 경고**: 이동·닫기 시 변경사항이 있으면 확인.
- **키보드**: 가능하면 `←`/`→`로 이전·다음(입력 필드에 포커스가 없을 때만).

### 3-3. ⭐ 키워드 편집 — **신규 필드** (§1.5)

지금은 검수자가 키워드를 **볼 수도 고칠 수도 없는데** 사용자 화면에는 나온다. 이걸 닫는다.

- `EditState`에 `keywords: string[]` 추가. 모달 진입 시 행의 `matched_keywords ?? []`로 초기화.
- `updatePayload`에 `matched_keywords: edit.keywords` 추가 (**`:418` 본 경로의 payload 한 곳만.** `:426` 42703 재시도 구조는 그대로 둘 것 — 그건 `body_markdown` 전용 폴백이다).
- **목록 조회(`.select`)에 `matched_keywords`를 포함**시켜야 모달이 초기값을 받는다. `AdminContentRow` 타입에도 추가.
- UI: **칩 입력**(Enter/쉼표로 추가, ×로 제거). 새 컴포넌트를 만들기보다 기존 어드민 패턴이 있으면 재사용.
- **자동완성은 범위 밖.** 자유 입력으로 충분하다.

> **덮어쓰기 안전은 §1.5에서 검증했다** — 재크롤이 `insert`+멱등스킵이라 수동 편집이 보존된다.
> 이걸로 **298(유튜브 키워드 최소 1개)의 "저장 전 검증"이 실행 가능**해진다. 순서상 294가 먼저다.

### 3-4. ⭐ 검수 완료 자동 검증
저장/검수 완료 시 아래를 **자동 체크해 경고를 표시**한다(막지는 말고, 무엇이 빠졌는지 보여준다):
- 제목 존재
- **키워드 1개 이상** ← §3-3으로 비로소 검증 가능해진다. 유튜브가 특히 비어 있다
- 요약 존재
- 커버 존재(`thumbnail_url` 또는 생성 폴백)
- 발행일 존재
- 본문 존재

> 저장 자체를 막으면 2,326건 처리가 느려진다. **경고만 띄우고 통과시킨다.**

### 3-5. 카드 실시간 미리보기
- 왼쪽 상단에 **`ContentCard`를 그대로 재사용**(§1.6). CSS 새로 만들지 말 것.
- draft 값(제목·요약·썸네일·**키워드**·출처·발행일)이 바뀌면 **즉시 반영**.
- `ContentCard`는 클릭 시 이동하는 링크다 → 미리보기에서는 **이동을 막을 것**(`pointer-events-none` 래퍼 등). 검수 중 실수로 페이지를 벗어나면 안 된다.

### 3-6. 커버 이미지 관리 (291 통합)
파일 입력 한 줄 → **이미지 중심 UI**:
- 현재 이미지 크게 표시
- **[이미지 변경]** (기존 `uploadCoverFile`)
- **[1페이지 다시 가져오기]** (PDF만 — 291의 `/api/admin/contents/[id]/pdf-cover`, 확인 다이얼로그 유지)
- **[기본 이미지로 되돌리기]** ← 단순 삭제보다 안전. `thumbnail_url = null`로 두면 생성 커버 폴백이 뜬다.
- 드래그앤드롭 지원(있으면 좋음)
- 용량·형식 안내(2MB, JPG/PNG/WebP)

> **크롭·이미지 URL 입력·유튜브 원본 복원은 이번 범위 밖**(백로그).

## 4. 회귀 가드

- **전체 페이지로 전환하지 말 것**(§1.2). 모달을 고친다.
- **저장 경로의 2단 구조를 깨지 말 것** — `:418` 본 경로 + `:426` **42703 graceful 재시도**(`body_markdown` 컬럼 미적용 대비). 키워드는 `updatePayload`에 **한 번만** 추가하면 양쪽에 반영된다. **42703 폴백을 지우지 말 것.**
- **`matched_keywords`를 `.select`에 추가**하지 않으면 모달이 빈 배열로 초기화되어 **저장 시 기존 키워드를 날린다.** ← 이번 슬라이스에서 가장 위험한 회귀다.
- **외부 클릭으로 모달이 닫히면 안 된다** — 작업 중 실수로 날아간다.
- **미저장 변경 경고 없이 이동·닫기 금지.**
- **검수 완료 검증이 저장을 막지 않게 할 것** — 경고만. 막으면 2,326건 처리가 느려진다.
- **`ContentCard`를 재사용**할 것. 비슷한 CSS를 새로 만들면 서비스 화면과 어긋난다(스펙 §6의 핵심 지적). 단 **미리보기에서 링크 이동은 막을 것**.
- **291의 커버 경로(`pdf-cover` 라우트·확인 다이얼로그·"표지 없음" 필터)를 건드리지 말 것.** 통합만 한다.
- 목록의 기존 필터·페이지네이션·일괄 작업 동작 불변.
- 1024px 미만에서 2패널을 억지로 유지하지 말 것(탭 전환).

## 6. 후속(범위 밖) — 백로그

- **전체 페이지 편집기**(`/admin/contents/[id]/edit`) — 지금은 불필요. 필요해지면 기존 `/admin/contents/[id]`에 얹는다.
- **자동 저장**(20~30초) — 있으면 좋지만 급하지 않다.
- **AI 기능**: 재요약 · 제목 번역 · 문장 다듬기 · AI 본문 보강 → **새 백엔드 필요.** 별도 슬라이스.
- **원문 제목 / 표시 제목 분리** → 스키마 변경. 별도 검토.
- **변경 이력** → 새 테이블. 관리자가 소수라 급하지 않다.
- 커버 **크롭** · 이미지 URL 입력 · 유튜브 원본 썸네일 복원.
- 페이지 경계를 넘는 연속 이동(다음 페이지 자동 로드).
