## 3. 파일별 구현

### 3.1 `src/lib/supabase/admin.ts` (신규) — service_role 클라이언트 (서버 전용)
- `SUPABASE_SERVICE_ROLE_KEY` + `NEXT_PUBLIC_SUPABASE_URL`로 `@supabase/supabase-js`의 `createClient` 생성. 세션/쿠키 없음(`auth: { persistSession: false }`).
- **반드시 서버 전용.** 파일 최상단 주석으로 "클라이언트 import 금지" 명시. `NEXT_PUBLIC_` 접두사 절대 금지(AGENTS #8).
- export: `createAdminClient()` (호출 시마다 생성, 모듈 최상단 전역 보관 금지).

### 3.2 `src/lib/crawler/types.ts` (신규)
```ts
import type { SourceType } from '@/lib/types'

export interface RawItem {
  original_url: string
  title: string
  body?: string
  author?: string
  published_at?: string   // ISO
  thumbnail_url?: string
  language?: string
}

export interface SourceAdapter {
  type: SourceType
  fetch(source: import('@/lib/types').Source, since: string): Promise<RawItem[]>
}

export interface CrawlCounts {
  fetched: number
  inserted: number
  duplicate: number
  held: number   // 이번엔 항상 0 (#13에서 사용)
}
```

### 3.3 `src/lib/crawler/normalize.ts` (신규)
- `normalizeUrl(url)`: 소문자 호스트, `utm_*`·`fbclid`·fragment(`#...`) 제거, 끝 슬래시 정리, 쿼리 정렬(불필요 추적 파라미터 제거). 실패 시 원본 반환.
- `normalizeText(s)`: 소문자화, 양끝/연속 공백 정리, 문장부호 제거(제목·본문 해시 입력 표준화).
- `sha256(s)`: Node `crypto.createHash('sha256')` hex.
- `titleHash(title)` = `sha256(normalizeText(title))`, `bodyHash(body)` = `body` 있을 때만 `sha256(normalizeText(body))` 아니면 `null`.

### 3.4 `src/lib/crawler/adapters/news-site.ts` (신규)
- `rss-parser`로 `source.rss_url` 파싱. `rss_url` 없으면 빈 배열 + 경고 로그(throw 금지).
- 각 item → `RawItem`: `link`→`original_url`, `title`, `contentSnippet`/`content`→`body`, `creator`/`author`→`author`, `isoDate`/`pubDate`→`published_at`, `enclosure.url` 또는 본문 og:image→`thumbnail_url`.
- **본문 폴백**: `body`가 비었거나 200자 미만이면 `@extractus/article-extractor`의 `extract(original_url)`로 본문 추출 시도. 실패하면 RSS 값 유지(throw 금지, best-effort).
- `since`(ISO) **이전 발행분은 제외**(PRD 4.2 당일 발행분). `published_at` 없으면 보수적으로 **포함**.
- `language`: 제목/본문에 한글 있으면 `'ko'`, 아니면 `'en'`(단순 추론).

### 3.5 `src/lib/crawler/adapters/index.ts` (신규)
- `getAdapter(type: SourceType): SourceAdapter | null`. 이번엔 `news_site`만 매핑, 그 외 `null`(orchestrator가 skip).

### 3.6 `src/lib/crawler/dedup.ts` (신규)
- `findByTitleHash(admin, titleHash)` / `findByBodyHash(admin, bodyHash)`: `contents`에서 해당 해시 존재 여부 `select id ... limit 1`. 해시 `null`이면 false.
- URL 1단계는 별도 함수 불필요(upsert `on conflict`로 처리).

### 3.7 `src/lib/crawler/orchestrator.ts` (신규) — 핵심
의사코드(설계 §5.1 준수):
```
runCrawl(): CrawlSummary
  admin = createAdminClient()
  todayStartKst = KST 오늘 00:00의 ISO (UTC 변환 주의)
  sources = admin.from('sources').select('*')
            .eq('is_active', true)
            // 주기 도래: crawl_interval_minutes null 제외 +
            //   last_crawled_at null 이거나 now - last_crawled_at >= interval
  results = await Promise.allSettled(sources.map(s => crawlOne(admin, s, todayStartKst)))
  // 집계 후 요약 반환
```
`crawlOne(admin, source, since)`:
```
log start time
adapter = getAdapter(source.type); if null → skip(이유 로그), return
raw = await withRetry(() => adapter.fetch(source, since), 3, [500,1000,2000]ms)
counts = {fetched: raw.length, inserted:0, duplicate:0, held:0}
for item in raw:
  url = normalizeUrl(item.original_url)
  tHash = titleHash(item.title); bHash = bodyHash(item.body)
  if (bHash && await findByBodyHash) { duplicate++; continue }
  if (tHash && await findByTitleHash) { duplicate++; continue }   // 완전일치만
  row = buildContentRow(item, source, url, tHash, bHash)  // category='뉴스', status 미지정(기본 published)
  upsert contents on conflict(original_url) → inserted++ (충돌 시 갱신은 duplicate로 카운트)
write crawl_logs(status, counts, started/finished, error?)
update sources.last_crawled_at = now()  (성공/부분성공 시)
return counts + status(success|partial|failed)
```
- **status 판정**: 전부 성공 `success` / 일부 item 처리 실패하지만 진행 `partial` / fetch 자체 실패 `failed`.
- **멱등 upsert**: `on conflict (original_url)` 시 `title`·`body_original`·`summary_ko`·`title_hash`·`body_hash`·`thumbnail_url`·`updated_at`만 갱신. `view_count`·`bookmark_count`·`is_editor_pick`·`status`·`cluster_id`는 **갱신 제외**(보존). Supabase `upsert(..., { onConflict: 'original_url', ignoreDuplicates: false })` 사용하되, 보존 컬럼은 payload에 넣지 말 것.
- `buildContentRow`: `category:'뉴스'`, `source_id`, `title`, `body_original`, `original_url`(정규화본), `original_language`, `author`, `thumbnail_url`, `title_hash`, `body_hash`, `published_at`, `collected_at: now`. (요약·번역·summary_ko는 비움 — 후속.)

### 3.8 `src/app/api/cron/crawl/route.ts` (신규)
- **Vercel Cron은 GET으로 호출**하며 `CRON_SECRET` 설정 시 `Authorization: Bearer <CRON_SECRET>` 헤더를 자동 첨부. → **GET 핸들러**로 구현.
- 인증: `request.headers.get('authorization') !== \`Bearer ${process.env.CRON_SECRET}\`` 면 `401`. (설계 문서는 POST로 적혀 있으나 Vercel 실제 동작이 GET이라 GET 채택 — Opus 검증 시 의도된 변경.)
- 본문: `const summary = await runCrawl()` → `Response.json(summary)`.
- 라우트 세그먼트 설정: `export const runtime = 'nodejs'`, `export const dynamic = 'force-dynamic'`, `export const maxDuration = 60`.
- 에러는 try/catch로 잡아 `{ ok:false, error }` + 500. 비밀키·스택은 응답에 노출 금지(콘솔만).
- 응답 형태(설계 §5):
```json
{ "ok": true, "sources_total": 0, "success": 0, "failed": 0, "inserted": 0, "duplicates": 0, "held": 0 }
```

## 4. 주의·함정
- `SUPABASE_SERVICE_ROLE_KEY`는 **서버 라우트/orchestrator에서만**. 클라이언트 번들 유입 금지(AGENTS #8).
- `contents.status` enum 적용 후이므로 `is_published` 컬럼은 **없음**. 절대 참조 금지.
- 소스 1개 실패가 전체를 멈추면 안 됨(`Promise.allSettled`).
- KST↔UTC 변환 정확히(`since`는 KST 0시를 UTC ISO로). 서버는 UTC 가정.
- 타입은 `src/lib/types.ts`의 `Source`·`Content`·`CrawlLog`·`CrawlStatus` 재사용(신규 DB 타입 만들지 말 것).
- `any` 금지(AGENTS §2), UI/로그 한국어, 주석 한국어.
- 테스트용 소스가 DB에 없으면 결과가 0건일 수 있음 — 그건 정상(빈 요약 반환). seed INSERT는 이 작업 범위 아님(P7, David·수희).
