## 0. 왜 3단계 없이 머지하면 안 되는가

2단계만 배포하면 **어드민 목록에서 삭제분이 사라지는데 볼 화면이 없다.** 복원 경로가 SQL뿐이 된다.
그리고 SQL B 전에는 **사용자에게 삭제분이 계속 보인다.** "관리자는 못 보고 사용자는 보는" 반대 상태다.

---

## A. 휴지통 화면

`/admin/contents`에 **휴지통** 진입을 추가한다. 탭이든 `?deleted=1` 필터든 기존 UI 구조에 맞는 쪽으로 하되, **새 페이지를 만들지 말고** 기존 화면을 재사용한다.

- `AdminTable` v2 그대로 사용. 페이지네이션·선택은 이미 붙어 있다.
- 컬럼: 제목 · 카테고리 · 삭제 시각 · 삭제자 · 원본 수집일
- 조회는 `deleted_at is not null`, 정렬 `deleted_at desc`
- **삭제자 표시**: `deleted_by` → `users.name`/`email` 조인. 조인 실패 시 "확인 실패"(0·빈칸 위장 금지)
- 빈 상태: "휴지통이 비어 있습니다."

### A-2. 복원
- `update … set deleted_at = null, deleted_by = null`
- 단건 + 일괄(선택바). `AdminConfirm` 사용, `destructive` 아님
- 성공 토스트, 실패 인라인
- 감사 로그 `content.restore`

### A-3. 영구 삭제
- 실제 `delete`. **여기서만 CASCADE가 발화한다.**
- `AdminConfirm`에 **대상 제목 목록 + 연쇄 삭제 건수**(`bookmarks`·`archive_items`)를 표시. 491의 방식 그대로.
  ⚠️ `archive_items`에는 `id` 컬럼이 없다 — `.select('content_id', { count:'exact', head:true })`
  ⚠️ count 조회 실패는 `null`("확인 실패")로. 0으로 위장 금지
- 감사 로그 `content.purge`

## B. `purge` 라우트 재정의

`api/admin/contents/purge` · `api/admin/youtube/purge`를 **"휴지통 비우기"**로 바꾼다.

- 대상: `deleted_at is not null` 인 행만
- 491의 `expectedCount` 대조와 `runJob(rejectIfRunning)`은 **그대로 유지**
- `AdminDataReset`의 문구를 "휴지통 비우기"로 수정. 대상 건수 선조회도 삭제분 기준으로
- ⚠️ **살아있는 콘텐츠를 전량 삭제하는 경로를 남기지 마라.** 전량 삭제가 필요하면 목록에서 선택 → 소프트 삭제 → 휴지통 비우기 순서를 거친다

## C. 30일 자동 정리

**새 cron을 만들지 마라.** 기존 `ops-brief`(하루 1회) 안에서 처리한다.

```
delete from contents where deleted_at < now() - interval '30 days'
```
- 한 번에 지우는 상한을 둔다(예 500건). **상한에 걸리면 그 사실을 결과에 남긴다**(조용히 자르지 말 것)
- 정리 건수를 `job_runs` 결과와 운영 리포트에 남긴다
- 실패해도 `ops-brief` 본체는 계속 돈다(감사·계측과 같은 원칙)

## D. 사용자 화면 — 북마크·아카이브

삭제된 콘텐츠를 담아둔 사용자에게는 **목록에서 감춘다.** "삭제된 콘텐츠" 표시를 만들지 않는다 — 눌러도 갈 곳이 없어 오히려 나쁘다.

- 북마크·아카이브 목록 조회에 `deleted_at is null` 조건 추가(조인 대상 `contents` 기준)
- 카운트도 함께 줄어야 한다(목록과 숫자가 어긋나면 안 된다)
- ⚠️ 사용자 경로는 SQL B(RLS)로 대부분 덮이지만, **service_role로 도는 북마크·아카이브 조회가 있으면 명시 필터가 필요하다.** 2단계 인벤토리에서 놓친 게 있는지 확인하고 보고할 것

## 범위 밖 / 금지

- ❌ 다른 테이블 소프트 삭제 확산 · CASCADE 변경.
- ❌ 새 cron · 새 페이지 · 새 테이블.
- ❌ RLS 정책 수정(SQL B는 David가 적용).
- ❌ 휴지통 보존 기간을 설정화(30일 상수로 고정. 필요해지면 `ops_settings`에 나중에).
- ❌ 2단계 단독 머지.

## 검증

1. 콘텐츠 1건 삭제 → 일반 목록에서 사라지고 **휴지통에 나타난다**. 삭제자·삭제 시각이 보인다.
2. 복원하면 일반 목록으로 돌아오고 **북마크·아카이브 연결이 살아 있다**.
3. 영구 삭제 확인창에 대상 목록 + 연쇄 건수가 보이고, 실행 후 관계 행도 사라진다.
4. `purge`가 **삭제분만** 지우고 살아있는 콘텐츠는 건드리지 않는다.
5. 30일 초과분 정리가 `ops-brief`에서 돌고 건수가 `job_runs`에 남는다. 상한 도달 시 그 사실이 결과에 있다.
6. 사용자 북마크 목록에서 삭제된 콘텐츠가 사라지고 **개수도 함께 줄어든다**.
7. 삭제·복원·영구삭제가 `admin_audit_log`에 각각 다른 `action`으로 남는다.
8. `npm run lint` · `npx tsc --noEmit` · `npm run check:admin-auth` 통과.
