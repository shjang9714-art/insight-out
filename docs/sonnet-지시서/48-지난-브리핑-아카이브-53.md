## 배경·목표
- #51 플레이어는 홈 우측 레일에서 **최신 1건**만 보여준다. 사용자가 지난 브리핑을 다시 듣거나 스크립트를 보려면 별도 화면이 필요.
- 목표: `/dashboard/briefings` 에서 공개·보관된 브리핑을 **날짜 역순 목록**으로 보고, 하나 선택하면 **기존 플레이어(아이팟 나노)로 재생/스크립트 열람**. 대시보드 셸(헤더·사이드바·레일)은 레이아웃이 자동 제공.

## 파트 A — 서버 페이지 `src/app/dashboard/briefings/page.tsx` (서버 컴포넌트)
- `'use client'` **금지**(기본 서버). `metadata` 명시: title `'지난 브리핑 | Insight Out'`, description 한국어.
- 서버 Supabase(`createServerClient` + `await cookies()`, §6.2 패턴)로 조회:
  ```ts
  supabase.from('briefings')
    .select('id, briefing_date, title, script, audio_url, audio_duration_seconds, voice, status')
    .in('status', ['published', 'archived'])
    .order('briefing_date', { ascending: false })
    .limit(90)
  ```
  RLS 가 이미 published/archived 만 허용하므로 anon/auth 클라로 안전(service_role 불필요).
- 결과를 클라이언트 컴포넌트에 prop 으로 전달: `<BriefingArchive briefings={data ?? []} />`.
- 페이지 상단: "대시보드로 돌아가기" 백버튼(mypage 패턴) + 제목 "지난 브리핑" + 부제("공개된 모닝브리핑을 다시 듣고 스크립트를 확인하세요.").
- 컨테이너 폭: `mx-auto max-w-5xl px-4 py-8 sm:px-6 lg:px-8`(목록+플레이어 2단 들어갈 정도).

## 파트 B — 클라이언트 컴포넌트 `src/components/dashboard/BriefingArchive.tsx` (`'use client'`)
fetch 는 서버가 끝냈으므로 여기선 **선택 상태만** 관리(브라우저 인터랙션 leaf).
- props: `{ briefings: Briefing[] }`(타입은 플레이어의 `Briefing` 과 동일 — 공용 타입으로 추출하거나 로컬 정의 일치).
- 상태: `selectedId`(기본 = `briefings[0]?.id`, 최신).
- **레이아웃(반응형 2단)**: `grid gap-6 md:grid-cols-[minmax(0,1fr)_300px]`
  - 좌(목록): 카드 리스트. 각 항목 = 클릭 버튼, 선택 시 강조(`border-brand-600`/`bg-brand-50` 등 **브랜드 토큰**). 표시: 날짜(ko-KR), 제목, **상태 뱃지**(공개=brand, 보관=muted), 오디오 유무 아이콘(`Volume2`/없으면 "스크립트"), 스크립트 1줄 미리보기(`line-clamp-1`).
  - 우(플레이어): `<MorningBriefingPlayer briefing={selected} />` — 선택된 브리핑 주입. 모바일에선 목록 위/아래 스택(`md:` 미만 1단). 플레이어를 `md:sticky md:top-20` 로 두면 스크롤 시 따라옴(과하면 생략).
- **빈 상태**: briefings 0건 → 점선 카드 "아직 공개된 브리핑이 없습니다." (mypage 빈상태 톤).
- 모든 텍스트 한국어. 아이콘 lucide-react 기존 설치분.
- ⚠️ 플레이어는 `briefing` prop 이 **바뀔 때** 내부 오디오 인스턴스를 교체해야 함 — 기존 코드가 `useEffect([briefing?.audio_url, ...])` 의존이라 prop 변경 시 재생성됨(확인만, 수정 불필요). 선택 전환 시 이전 오디오가 `pause()`/정리되는지 육안 확인.
