## 배경 (David)

플랫폼을 "출처 중심 → 이슈/인사이트 중심"으로 진화시키는 **토대**. 지금은 뉴스/리포트/… (출처)와 AI분석/보고서(결과물) 사이의 **중간 지식계층(엔티티·이슈·관계)** 이 없다. 이 슬라이스는 그 토대의 첫 돌 = **엔티티(기업/기술/제품/인물/정책/산업) + 콘텐츠↔엔티티 링크**. 이슈 1급화·지식그래프·GraphRAG 검색은 모두 이 위에 올라간다.

## 설계 결정 (Opus, 확정 — 임의 변경 금지)

1. **엔티티 정규화가 핵심**: `entities`(정규 표기·타입) + `entity_aliases`(동의어→엔티티, 1:1) + `content_entities`(콘텐츠 링크). "MS=Microsoft=마이크로소프트" 병합은 alias 로 해결(병합 자체는 큐레이션=100).
2. **v1 = 룰 기반(키 불필요)**: 기존 큐레이션 데이터(keyword_groups.include_patterns + tag_type, user_watchlist)로 엔티티 사전을 **시드**하고, `matched_keywords` ↔ alias 매칭으로 콘텐츠를 링크. **LLM/NER 추출(인물 포함)은 후속 슬라이스**(별도). 키 부족과 무관하게 즉시 동작.
3. **적재는 post-insert·try/catch 격리**(content_signals 와 동일 위치·패턴). SQL 미적용 시 크롤 무중단.
4. **이번 노출은 최소**(콘텐츠 상세 "관련 엔티티" 칩) — 검증·체감용. 엔티티 사전 어드민·엔티티 상세/타임라인·관계망·이슈 1급화는 후속(메모).

## 작업

### A. (선행) SQL 핸드오프 — `docs/sql-handoff/99-entities.sql` (수희 선적용·먼저 푸시)
- 내용(이미 작성됨): entity_type enum(6) + entities + entity_aliases + content_entities + 인덱스 + RLS(인증 조회·admin 전체) + **시드**(keyword_groups.include_patterns→타입별 엔티티, watchlist→company, canonical→alias) + **백필**(matched_keywords↔alias→content_entities) + mention_count.
- `supabase/schema.sql` SSOT 반영(#6) — enum·3테이블·인덱스·RLS·트리거. (시드/백필은 일회성이라 SSOT엔 스키마만.)

### B. 타입 — `src/lib/types.ts`
- `EntityType = 'company'|'tech'|'product'|'person'|'policy'|'industry'`.
- `Entity { id; canonical_name; entity_type: EntityType; description: string|null; is_competitor: boolean; service_id: string|null; mention_count: number; created_at; updated_at }`.
- `ContentEntity { id; content_id; entity_id; source: string; score: number; created_at }`.
- `ENTITY_TYPE_LABEL: Record<EntityType, string>` = 기업/기술/제품/인물/정책/산업. (UI 한국어 라벨, 색은 컴포넌트.)

### C. 크롤러 룰 링킹 — `src/lib/crawler/orchestrator.ts`
- **엔티티 alias 맵 로드(크롤 1회)**: 크롤 시작부(groups 로드하는 곳 인근)에서 `entity_aliases` join `entities` 로 `Map<lower(alias), entity_id>` 구성(또는 `{alias_lower, entity_id}[]`). 실패/빈 맵이면 링킹 skip(격리).
- **processCrawlItem post-insert**(matched_keywords update·content_signals upsert 직후, 같은 `if (newId)` 블록):
  - `matchedTags.keywords`(=matched_keywords) 각 항목 lower → alias 맵에서 entity_id 조회 → 고유 entity_id 집합.
  - 행 구성 `{ content_id: newId, entity_id, source: 'rule', score: 1.0 }` 배열 → `admin.from('content_entities').upsert(rows, { onConflict: 'content_id,entity_id', ignoreDuplicates: true })`.
  - **try/catch 격리**(테이블 미적용/오류 시 크롤·태그·요약·시그널 정상). 빈 집합 skip.
- (선택) mention_count 증가는 v1 생략(백필 SQL·후속 트리거로 충분).

### D. 최소 노출 — 콘텐츠 상세 "관련 엔티티" 칩 — `src/app/dashboard/contents/[id]/page.tsx`
- 상세 데이터 조회에 **관련 엔티티** 추가: `content_entities` where content_id=이 글 → join `entities`(canonical_name·entity_type). (또는 별도 쿼리.)
- 본문/요약 근처에 **"관련 엔티티" 섹션**: 타입별 색 칩(`ENTITY_TYPE_LABEL`). 칩 클릭 → 우선 `/dashboard/topics/${encodeURIComponent(canonical_name)}`(98 타임라인 재사용; 전용 엔티티 페이지는 후속). 없으면 섹션 생략(graceful).
- 타입 색: 기업=brand/red(경쟁사), 기술=blue, 정책=amber, 산업=muted, 제품=violet, 인물=emerald (토큰/팔레트 일관, #9). 과하지 않게.

## 회귀 / 주의
- **SQL 99 선적용 필수(수희).** 미적용 시: 크롤 링킹 upsert 실패→격리(크롤 정상), 상세 칩 미표시(graceful). 적용 후 백필로 기존 콘텐츠 즉시 링크 + 다음 수집부터 자동.
- **시드는 패턴=엔티티**라 "MS"와 "Microsoft"가 별개 엔티티로 들어올 수 있음 — **정규화(병합)는 100(엔티티 사전 어드민)**. v1 모델은 alias 로 병합을 *지원*만.
- 인물(person) 엔티티는 시드에 없음(키워드그룹에 인물 타입 없음) → **LLM/NER 추출 후속**. person enum 값은 미리 둠(후속 대비).
- alias 매칭은 `matched_keywords` 정확 일치(98 패턴과 동일 소스) — 부분문자열 아님. 노이즈 적음.
- crawl 1회 alias 맵 로드 = 엔티티 수 바운디드(큐레이션)라 부담 적음. 매우 커지면 후속 RPC.
- RLS(#7)·service_role 적재(크롤러)·UI 한국어(#1)·색 토큰(#9)·`any` 금지·서버 컴포넌트(상세 페이지) 유지.

### 메모(후속 — 이슈/지식그래프 로드맵)
- **100 — 엔티티 사전 어드민**(관리 메뉴): entities/aliases CRUD, 동의어 병합(MS=Microsoft), 타입 수정, is_competitor. 정규화의 실질 도구.
- **LLM/NER 추출**: 크롤 시 LLM 로 엔티티(특히 **인물**·제품) 추출 → content_entities(source='llm'). 64/96 classify 패턴 확장. 키 여유 시.
- **이슈 1급화**: 이슈 = 엔티티집합+콘텐츠집합+타임라인. 98 토픽 타임라인·96 논조·97 회사카드·content_signals 를 "이슈 상세"로 수렴.
- **관계망(co-occurrence)**: content_entities 공기출현 → 엔티티-엔티티 엣지. 지식그래프 뷰(P2)·GraphRAG 검색(서브그래프 → LLM)의 입력.
