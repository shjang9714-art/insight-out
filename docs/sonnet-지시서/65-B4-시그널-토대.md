## 배경

태그(matched_keywords)·관련도(게이트)는 있으나 **시그널(이 기사가 어떤 시장 신호인가 — 경쟁사동향/규제/기술트렌드…)** 집계 토대가 없다. 설계 §6 의 `content_signals` 를 만들어 signal-insight·AI분석(후속 화면)의 바닥을 깐다.

이번 슬라이스(B4)는 **rule 기반**만: `keyword_groups.signal_hint`(그룹→시그널 매핑)를 이용해, 크롤 시 매칭된 그룹의 signal_hint 를 `content_signals` 로 적재한다. **키 불필요·결정적·즉시 동작**. 이벤트형 시그널(신제품/투자·M&A 등)은 그룹 멤버십으로 못 잡으므로 **LLM 시그널(후속 66)** 로 보강.

### 설계 결정(Opus)
1. **rule 기반 먼저**(signal_hint), LLM 시그널은 66 으로 분리(64 classify 확장). 키 없어도 동작.
2. **content_signals 적재는 post-insert**(matched 태그 블록과 동일 위치·try/catch 격리). SQL 미적용 시 테이블 없어 insert 실패 → 격리되어 크롤 무중단(matched 태그와 동일 graceful).
3. **signal_hint 편집을 KeywordGroupManager(63)에 추가** — 운영자가 그룹→시그널 매핑을 조정. (63 에서 빠졌던 필드.)
4. **소비 화면(signal-insight/AI분석)·집계 뷰는 66 범위** — 65 는 토대(스키마+적재+편집)까지. 데이터가 쌓여야 화면이 의미.

## 작업

### 1. (선행) SQL 핸드오프 — 수희 적용
- `docs/sql-handoff/65-content-signals.sql`: signal_type enum(8종) + content_signals(content_id·signal_type·score·source·unique) + 인덱스 + RLS(인증 조회·admin 전체) + signal_hint 시드(competitor→경쟁사동향, gov_reg/gov_business→규제·정부, ai_tech/aicc/aidc/physical_ai/manufacturing_dx→기술트렌드).
- ⚠️ **signal_type enum 목록은 David 확정 후** 수희 실행(enum 값 삭제 어려움).

### 2. 타입 + groups 로드에 signal_hint 포함
- `ScoringGroup`(quality.ts) 또는 groups 로드 타입에 **`signal_hint: string | null`** 추가.
- orchestrator 의 keyword_groups 로드 select 에 `signal_hint` 컬럼 추가(이미 include/exclude/weight/name 로드하는 곳).
- `matchKeywordGroups` 가 매칭된 그룹을 식별하므로, **매칭 그룹 → signal_hint(비null)** 매핑을 얻을 수 있게 한다(매칭 그룹 객체나 이름→signal_hint 룩업).

### 3. processCrawlItem — content_signals 적재
- matched 태그 post-insert update 직후(같은 `if (newId)` 블록):
  - 매칭된 그룹들 중 `signal_hint` 가 있는 것들의 **고유 signal_type 집합** 산출.
  - 각 signal_type 에 대해 `content_signals` 행 구성: `{ content_id: newId, signal_type, score: 1.0, source: 'rule' }`.
  - `admin.from('content_signals').upsert(rows, { onConflict: 'content_id,signal_type', ignoreDuplicates: true })` (또는 insert 후 23505 무시). **try/catch 격리**(테이블 미적용/오류 시 크롤 무중단, matched 태그와 동일 패턴).
  - 빈 집합이면 skip.
- counts 에는 영향 없음(시그널은 부가 메타).

### 4. KeywordGroupManager(63)에 signal_hint 편집 추가
- 폼에 **signal_hint 셀렉트**(nullable): 옵션 = signal_type 8종 + "없음". 저장 payload 에 `signal_hint: form.signalHint || null` 추가.
- 목록 테이블에 signal_hint 열(또는 태그유형 옆 작은 배지) 추가(선택, 가독성).
- signal_type 라벨 상수는 컴포넌트에 정의(한국어 그대로). enum 값과 문자열 일치 필수.

## 회귀 / 주의
- **SQL 선적용 필수** — 미적용 시 content_signals insert 실패하나 try/catch 로 격리(크롤·태그·요약 정상). 적용 후 다음 수집부터 시그널 적재.
- DB: 신규 테이블·enum 만 추가(기존 무변경). RLS 동반(#7). content_signals 는 content 삭제 시 cascade.
- rule 시그널은 그룹 매핑 기반이라 coarse — 이벤트형은 66(LLM)에서. 과적재 방지 위해 그룹당 signal_hint 1개.
- signal_hint 문자열은 **signal_type enum 값과 정확히 일치**해야 적재 성공(오타 시 enum 캐스트 실패 → 격리됨). KeywordGroupManager 셀렉트로 입력하므로 사람 오타 방지.
- UI/주석/프롬프트 한국어(#1). 색상 토큰만(#9).
