## 0. 한 줄

주간 리포트 자동 생성의 **요일·시각(KST)·자동발행 여부·on/off**를 어드민에서 설정하고, 크론이 그 설정을 읽어 해당 시점에만 생성하게 한다.

## 1. 현행 진단 (검증된 코드 사실)

- **크론 라우트 존재**: `src/app/api/cron/competitor-weekly/route.ts` — `CRON_SECRET` 확인 후 `generateCompetitorWeeklyReport(admin, { deadline })` 호출.
- **스케줄이 하드코딩**: `vercel.json` → `{ "path": "/api/cron/competitor-weekly", "schedule": "0 21 * * 0" }`
  - UTC 기준이므로 실제로는 **월요일 06:00 KST**에 돈다(일요일 21시 UTC).
- **핵심 제약**: **Vercel 크론 스케줄은 `vercel.json`에 배포시점으로 고정**되어 런타임에 바꿀 수 없다. → 어드민이 요일·시각을 고르게 하려면 **크론을 자주 돌리고 라우트가 게이트**하는 방식이어야 한다.
- **리포트 상태 모델**: `competitor_weekly_reports.status` = `'draft' | 'published'`(기본 `draft`), `unique (week_start)`.
- **기존 싱글턴 설정 패턴**: `crawl_settings`(`id boolean primary key check(id)` 단일행 + `set_updated_at` 트리거) — 이번 설정 테이블도 동일 패턴(SQL 284).
- 어드민 화면: `src/app/admin/competitor-weekly/page.tsx` + `src/components/admin/AdminCompetitorWeeklyGenerate.tsx`(수동 생성 버튼 + 최근 리포트 목록).

## 2. DB / SQL — **있음**

`docs/sql-handoff/284-경쟁사주간-발행스케줄-설정.sql` (수희 적용):

```
competitor_weekly_settings (단일행)
  enabled       boolean  default true    -- 자동 생성 on/off
  generate_dow  smallint default 1       -- 요일(KST) 0=일 … 6=토  (기본 1=월)
  generate_hour smallint default 6       -- 시각(KST) 0~23        (기본 6시)
  auto_publish  boolean  default false   -- true=생성 즉시 published, false=draft
  updated_at    timestamptz
```

- 기본값은 **기존 동작과 동일**(월 06시 KST = 구 `0 21 * * 0` UTC, 초안 생성).
- **값은 KST 기준으로 저장**한다(관리자가 생각하는 그대로). 라우트가 `Asia/Seoul`로 환산해 비교.
- RLS 켜고 정책 없음 → **service_role(서버)만** 접근.

## 3. 구현

### 3-1. 크론 스케줄 변경 (`vercel.json`)
- `"/api/cron/competitor-weekly"`의 `schedule`을 **`"0 * * * *"`(매시 정각)** 으로 변경.
- 매시 실행되지만, 설정과 안 맞으면 라우트가 **즉시 스킵**하므로 비용은 무시할 수준(아래 3-2).

### 3-2. 크론 라우트 게이트 (`src/app/api/cron/competitor-weekly/route.ts`)
`CRON_SECRET` 확인 이후, 생성 전에 다음 순서로 게이트:

1. 설정 조회(`competitor_weekly_settings` 단일행).
   - **테이블 미적용(42P01) 시 graceful**: 기본값(`enabled=true, dow=1, hour=6, auto_publish=false`)으로 동작 — 즉 기존과 동일하게 월 06시 KST에만 생성.
2. `enabled=false` → `{ skipped: 'disabled' }` 반환하고 종료.
3. **현재 KST 요일·시각**을 계산해 설정과 비교:
   ```ts
   const nowKst = new Date(Date.now() + 9 * 60 * 60 * 1000) // UTC+9
   const dow  = nowKst.getUTCDay()    // 0=일 … 6=토 (KST 기준)
   const hour = nowKst.getUTCHours()  // KST 시
   if (dow !== s.generate_dow || hour !== s.generate_hour) {
     return NextResponse.json({ skipped: 'not_scheduled', dow, hour })
   }
   ```
   (`Asia/Seoul` 오프셋은 DST 없이 고정 +9라 위 계산으로 충분.)
4. **멱등 가드**: 대상 주(`week_start`)의 리포트가 **이미 있으면 재생성하지 않는다** → `{ skipped: 'already_exists' }`.
   `unique (week_start)` 때문에 중복 생성은 어차피 실패하므로, 매시 크론이 같은 주를 계속 때리지 않도록 먼저 확인.
5. 생성: `generateCompetitorWeeklyReport(admin, { deadline })`.
6. **자동발행**: `auto_publish=true`면 생성된 리포트의 `status='published'`로 갱신. `false`면 `draft` 유지(어드민이 수동 발행).
   - 생성 함수가 이미 `draft`로 넣으므로, 발행은 생성 직후 update로 처리(생성 함수 시그니처는 건드리지 말 것).

> **주의**: 수동 생성(`/api/admin/competitor-weekly`, 어드민 버튼)은 **이 게이트와 무관**하게 항상 즉시 생성돼야 한다. 게이트는 크론 경로에만 적용.

### 3-3. 설정 API (`src/app/api/admin/competitor-weekly/settings/route.ts` 신규)
- `GET` — 현재 설정 반환. 테이블 미적용 시 기본값 + `{ ready: false }`.
- `PATCH` — `{ enabled?, generate_dow?, generate_hour?, auto_publish? }` 갱신.
  - 검증: `generate_dow` 0~6, `generate_hour` 0~23. 벗어나면 400.
- **어드민 role 재확인 필수**(`users.role === 'admin'`) — 미들웨어 의존 금지, 기존 어드민 라우트 패턴 따를 것.

### 3-4. 어드민 UI (`/admin/competitor-weekly`)
`AdminCompetitorWeeklyGenerate`(수동 생성) **위 또는 아래**에 "발행 스케줄" 설정 카드 추가(신규 컴포넌트 `AdminCompetitorWeeklySchedule.tsx`):
- **자동 생성** on/off 토글(`enabled`).
- **요일** select(일~토) — `generate_dow`.
- **시각** select(0~23시, KST 명시) — `generate_hour`.
- **자동 발행** 토글(`auto_publish`) — 설명: "켜면 생성 즉시 서비스에 노출됩니다. 끄면 초안으로 두고 검토 후 직접 발행합니다."
- 저장 버튼 → `PATCH`. 저장 후 현재 설정 요약 문구 표시(예: "매주 **월요일 06시(KST)** 생성 · 초안으로 보관").
- 테이블 미적용 시: 안내 문구 + 컨트롤 비활성("SQL 284 적용 필요").
- 기존 어드민 UI 컴포넌트(`AdminSectionHeader` 등)와 톤 일치. 도움말 아이콘(263 패턴) 있으면 활용.

## 4. 회귀 가드

- **SQL 284 미적용(42P01)에서도 크론·어드민이 깨지지 않아야 함** — 기본값으로 기존 동작(월 06시 KST, 초안) 유지.
- **수동 생성 버튼은 스케줄 게이트의 영향을 받지 않는다**(언제든 즉시 생성).
- 매시 크론이 **같은 주 리포트를 중복 생성하지 않을 것**(멱등 가드 3-2.4). `unique(week_start)` 위반 로그가 반복되면 실패.
- `auto_publish=false`가 기본 — 켜지 않는 한 **서비스에 자동 노출되지 않는다**.
- `CRON_SECRET` 검증 로직 제거·완화 금지.
- 설정 API는 **service_role/admin만** — RLS 정책이 없으므로 클라이언트 직접 조회는 빈 결과가 정상.
- 시각 비교는 **KST 기준**(UTC로 착각하면 9시간 어긋남). 기존 `0 21 * * 0`이 월 06시 KST였다는 점으로 검산할 것.
