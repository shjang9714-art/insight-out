> 작성: Opus(Cowork) · 대상: Claude Code(Sonnet) · Phase 2-B 용주 트랙 (뉴스 상세 뷰) + 크롤러 본문 보강
> 선행: `supabase/2026-06-04-본문추출-컬럼.sql`(`contents.body_fetched_at`) 수희 적용 후 캐시 동작(미적용이어도 추출은 되나 캐시는 안 됨 → 적용 권장).
> ⚠️ 작업 전 `AGENTS.md`(특히 Next.js 16 — `params`/`cookies()` async, 미들웨어 `proxy.ts`, 서버컴포넌트 기본)와 현재 `src/app/dashboard/contents/page.tsx`·`src/lib/supabase/*`·`src/lib/crawler/adapters/news-site.ts`(extractor 사용법) 를 읽을 것.

## 0. 목표 (한 줄)
콘텐츠 상세 페이지 `/dashboard/contents/[id]` 를 만들고, 본문이 스니펫만 있으면 **조회 시 원문에서 풀본문을 1회 추출·캐시**해 전문으로 보여준다. (배치 아님 → 읽는 것만 추출, 타임아웃 회피)

## 1. 동작 흐름
```
사용자가 목록/피드에서 기사 클릭
  → /dashboard/contents/[id] (서버 컴포넌트, dynamic)
     1) 콘텐츠 조회 (인증 사용자 client, RLS: status='published')
     2) ensureFullBody(content):
        - body_fetched_at 있으면 → body_original 그대로 반환
        - 없고 original_url 있으면 → 원문 fetch+추출(타임아웃) →
            성공: body_original=전문, body_fetched_at=now (admin 저장) → 전문 반환
            실패/타임아웃: body_fetched_at=now (스니펫 유지) → 스니펫 반환  ※ 1회만 시도
     3) 전문 + 메타(출처·작성자·발행일) + 서비스/키워드 태그 + "원문 보기" 링크 렌더
```

## 2. 할 일

### 2.1 `src/lib/types.ts`
- `Content` 에 `body_fetched_at?: string | null` 추가(`body_original` 인근).

### 2.2 `src/lib/contents/full-body.ts` (신규, 서버 전용)
- 파일 상단 주석 "서버 전용 — service_role 사용, 클라이언트 import 금지".
- `ensureFullBody(content: Content): Promise<string>`:
  - 이미 `content.body_fetched_at` 이 있으면 `content.body_original ?? ''` 반환(추출 안 함).
  - `original_url` 없으면 `content.body_original ?? ''` 반환.
  - 추출 시도: `@extractus/article-extractor` 의 `extract(original_url, { ... }, { signal })` 를 **타임아웃 6초**(`AbortSignal.timeout(6000)` 또는 `Promise.race`)로 감싼다.
    - 성공 + 추출 본문이 기존보다 의미있게 길면(예: > 기존 길이 그리고 > 200자):
      `createAdminClient()` 로 `update contents set body_original=<전문>, body_fetched_at=now() where id=<id>` → 전문 반환.
    - 실패/타임아웃/짧음: `update contents set body_fetched_at=now() where id=<id>`(스니펫 유지, 재시도 방지) → 기존 `body_original` 반환.
  - 모든 추출/DB 오류는 try/catch — 실패해도 **기존 본문을 반환**(페이지가 깨지지 않게). admin 클라이언트는 `@/lib/supabase/admin` 의 `createAdminClient()`.

### 2.3 `src/app/dashboard/contents/[id]/page.tsx` (신규, 서버 컴포넌트)
- `export const dynamic = 'force-dynamic'`(추출·DB 갱신 side-effect 있으므로 캐시 제외).
- Next.js 16: `params` 는 Promise → `const { id } = await params`.
- 콘텐츠 조회: 서버 supabase client(쿠키 기반, `src/app/dashboard/contents/page.tsx` 패턴 참고)로 `contents` 단건 + 매핑 조회. 없으면 `notFound()`.
  - 함께: `content_services(services(name))`, `content_keywords(keywords(name))` 조인으로 서비스·키워드 태그.
- `const body = await ensureFullBody(content)`.
- 렌더(한국어 UI, AGENTS 디자인 토큰):
  - 제목(h1), 메타 라인(출처 source.name · 작성자 author · 발행일 published_at),
  - 서비스/키워드 태그(있으면; CONTENT_CATEGORY_LABEL 등 기존 톤),
  - 본문 전문(줄바꿈 보존 — `whitespace-pre-wrap` 등. HTML 직접 주입 금지/이스케이프),
  - 하단 **"원문 보기"** 외부 링크(`original_url`, `target=_blank rel=noopener`),
  - 페이지 컨테이너·간격은 AGENTS §9 토큰.
- metadata: `export const metadata`(또는 generateMetadata)로 제목 반영(AGENTS #10).

### 2.4 목록/피드 → 상세 링크
- `/dashboard/contents` 목록 항목과 `RecentFeed`·`EditorPick` 의 콘텐츠 항목을 `/dashboard/contents/${id}` 로 링크(`next/link`). 유튜브 항목은 기존 동작 유지.

### 2.5 건드리지 말 것
- 크롤러(`src/lib/crawler/*`)·dedup·태깅 로직 변경 금지(상세뷰는 읽기/추출만).
- `body_fetched_at` 외 스키마/타입 변경 불필요.

## 3. 주의·함정
- **service_role 는 서버 전용**(`full-body.ts`). 클라이언트 번들 유입 금지(AGENTS #8).
- 추출 실패가 페이지를 막으면 안 됨 → 항상 기존 본문으로 폴백.
- 풀본문은 내부 표시용 + **"원문 보기" 링크 병기**(리더뷰 패턴).
- Next 16 async `params`/`cookies()` 준수.
- `@extractus/article-extractor` 는 이미 의존성에 있음(#4). 없으면 `npm i` 후 사유 기록.
