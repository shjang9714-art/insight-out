## 4. 구현

### 4-1. 의존성
- `npm i mcp-handler`(+ `zod` 없으면 추가 — 툴 스키마용).

### 4-2. MCP 엔드포인트 — `app/api/mcp/route.ts`(신규)
- `mcp-handler`의 `createMcpHandler`로 MCP 서버 정의(streamable HTTP, **무상태 stateless — Redis 불필요**). `runtime='nodejs'`, `maxDuration` 적정.
- **Bearer 인증**: 요청 `Authorization: Bearer <MCP_TOKEN>` 검증(불일치 401). `mcp-handler`의 `withMcpAuth` 또는 핸들러 앞 수동 검증. `MCP_TOKEN` 미설정 시 비활성(401).
- 툴 내부 DB = `createAdminClient()`.
- 값 검증은 `lib/admin/ops-requests.ts` 상수 재사용(post_type/status/kind 화이트리스트).

### 4-3. 툴 정의(zod 스키마)
- **`ops_request_list`**`({ post_type?, status?, owner?, limit? })` → 목록(제목·상태·종류·담당·ref·updated_at). 기본 미완료(pending+in_progress) 우선/최신순.
- **`ops_request_create`**`({ title, body?, kind?, owner?, ref?, post_type?='request', created_by? })` → 생성, 생성된 id 반환.
- **`ops_request_update`**`({ id, status?, owner?, ref?, pinned?, note? })` → 갱신(note는 body에 append 또는 별도). done 전환 시 resolved_at은 DB 트리거 자동.
- (선택) `ops_request_get({ id })`.
- 결과는 간결한 텍스트(+구조화). 실패 시 명확한 오류 메시지. 테이블 미적용(42P01) graceful 안내.

### 4-4. 미들웨어 — `/api/mcp` 공개(자체 인증)
- `publicPaths`에 `'/api/mcp'` 추가(세션 미들웨어 우회, MCP는 Bearer로 자체 인증).

### 4-5. 연결 문서 — `docs/mcp-연결.md`(신규, 짧게)
- Claude Code/Cowork MCP 설정 예(streamable HTTP):
  - URL: `https://insight-out-app.vercel.app/api/mcp`
  - 헤더: `Authorization: Bearer <MCP_TOKEN>`
- 툴 목록·용도 요약. (실제 토큰 값은 문서에 넣지 않음 — 환경변수/시크릿.)
