> 협업 루프: 로컬(커밋X). 위임 → 구현 → 재현검증 → "커밋해" → 커밋·병합·푸시.
> **SQL 있음**: `docs/sql-handoff/306-죽은컬럼-제거.sql`
> ⛔ **선행: 308(마이페이지)** — UI에서 `position`을 빼기 전에 컬럼을 지우면 깨진다.
> ⚠️ **오픈 후에 해도 된다.** 급하지 않다. 데이터가 사라지는 작업이니 서두르지 말 것.

## 0. 한 줄

**아무도 안 쓰는 컬럼 2개를 지운다.** 코드에서 먼저 끊고, 그 다음 DB에서 지운다. **순서를 바꾸면 앱이 깨진다.**

---

## 1. 현행 진단 (검증된 코드 사실)

### 1.1 `users.position` (직책) — **죽었다**
```
src/lib/types.ts:25                position?: string          (User)
src/lib/types.ts:56                position: string           (다른 타입)
src/app/admin/users/actions.ts:62  .select('… position …')    ← 지우면 여기가 깨진다
src/app/admin/users/page.tsx:21    .select('… position …')    ← 여기도
src/app/dashboard/mypage/page.tsx:43,62,142,165               ← 308이 제거
```
- **추천·권한·개인화 어디에도 안 쓰인다.** 어드민 사용자 목록에 표시만 된다.
- **David 결정: 제거.**

### 1.2 `users.content_filter_mode` — **`default_lens`로 대체됨(309)**
```
src/lib/types.ts:27   content_filter_mode: ContentFilterMode   ← 타입 정의만 남았다
```
- **309가 `default_lens`로 승격**했다. 온보딩·마이페이지 저장 경로는 이미 `default_lens`로 옮겨졌다.
- **컬럼은 롤백 여지로 남겨뒀다**(309 SQL 주석 참조). 이제 지운다.

### 1.3 ⚠️ 순서를 지키지 않으면 깨진다
```
❌ SQL 먼저 → admin/users의 .select('… position …')가 42703으로 실패 → 사용자 목록이 안 뜬다
✅ 코드 먼저(§3) → 배포 확인 → SQL(§2)
```

## 2. DB / SQL — **코드 배포 후에 실행**

`docs/sql-handoff/306-죽은컬럼-제거.sql` (수희):

- ⛔ **되돌릴 수 없다.** 코드가 배포되고 화면이 정상인 것을 확인한 뒤에 실행한다.
- 실행 전 **값 분포를 한 번 찍어보고** 버려도 되는지 눈으로 확인한다(SQL 파일에 쿼리 포함).

## 3. 구현 — **코드에서 먼저 끊는다**

### 3-1. `position` 제거
| 파일 | 할 일 |
|---|---|
| `src/lib/types.ts:25, :56` | `position` 필드 제거 |
| `src/app/admin/users/actions.ts:62` | `.select()`에서 `position` **제거** |
| `src/app/admin/users/page.tsx:21` | `.select()`에서 `position` **제거** + 표시 열 제거 |
| `src/app/dashboard/mypage/page.tsx` | **308에서 이미 제거됨.** 남아 있으면 함께 정리 |

### 3-2. `content_filter_mode` 제거
| 파일 | 할 일 |
|---|---|
| `src/lib/types.ts:27` | `content_filter_mode` · `ContentFilterMode` 타입 **제거** |
| 그 외 | **309에서 이미 `default_lens`로 옮겨졌다.** `grep -rn "content_filter_mode" src/` 로 **0건**을 확인할 것 |

### 3-3. ⭐ 전수 확인
```bash
grep -rn "position" src/ | grep -v "position:" | grep -viE "absolute|relative|fixed|sticky"
grep -rn "content_filter_mode\|ContentFilterMode" src/
```
→ **둘 다 0건**이어야 SQL을 보낼 수 있다. **CSS의 `position`과 헷갈리지 말 것.**

## 4. 회귀 가드

- ⛔ **SQL을 코드보다 먼저 실행하지 말 것**(§1.3). 어드민 사용자 목록이 42703으로 죽는다.
- ⛔ **CSS `position`을 지우지 말 것.** `grep`이 섞인다.
- **어드민 사용자 목록(`/admin/users`)이 정상 동작해야 한다** — 이 슬라이스의 유일한 실질 위험이다.
- **308이 먼저 배포돼야 한다** — 마이페이지가 아직 `position`을 저장하고 있으면 안 된다.
- `default_lens`(309) 동작 불변.
- **오픈 후에 하는 게 안전하다.** 되돌릴 수 없는 작업을 오픈 직전에 하지 말 것.
