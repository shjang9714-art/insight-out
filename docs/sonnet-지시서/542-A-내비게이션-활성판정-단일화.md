## 3. 작업

### 3-1. `src/lib/nav/active.ts` 신설

```ts
export interface ActiveNav {
  /** NAV_TABS 의 href 문자열과 정확히 일치하는 값. 어떤 L1 도 아니면 null */
  l1Href: string | null
  /** 해당 L1 섹션의 활성 L2 탭 id. L2 가 없는 섹션이면 null */
  l2Id: string | null
}

export function resolveActiveNav(
  pathname: string,
  searchParams: URLSearchParams,
  categoryHint?: string | null
): ActiveNav
```

기존 로직을 **의미를 바꾸지 않고** 이 함수 안으로 모은다. 옮겨올 것:

- `DashboardHeader.tsx` 의 `resolveIssuesActiveHref` · `issuesL1HrefForView` ·
  `isEntityDetailFromIssues` · `isDocumentsViewFromEntities` · `activeL1Href` 4단 폴백
- `taxonomy.tsx` 의 `getL2ForSection` 호출 결과(`activeId`)

**판정 순서는 현재 `activeL1Href` 의 폴백 순서를 그대로 지킨다:**

1. `resolveIssuesActiveHref(pathname, searchParams)`
2. `isEntityDetailFromIssues` → `issuesL1HrefForView(searchParams.get('view'), 'keyword')`
3. `isDocumentsViewFromEntities` → `/dashboard/contents`
4. `NAV_TABS.find(tab => isTabActive(...))?.href ?? null`

`isTabActive` · `NAV_ALIAS_PREFIXES` · `ISSUES_L1_HREFS` 는 이 파일로 옮기고
`DashboardHeader.tsx` 는 재export 하거나 import 해서 쓴다 —
**외부 import 경로가 깨지지 않게 할 것.**

### 3-2. 호출부 5곳을 전부 이 함수로 바꾼다

| 파일 | 바꿀 것 |
|---|---|
| `DashboardHeader.tsx` | `activeL1Href` 계산을 `resolveActiveNav().l1Href` 로 대체. `isGraphActive`·`isContentsActive` 도 같은 결과에서 파생 |
| `MobileBottomNav.tsx` | 자체 분기 제거, `resolveActiveNav().l1Href === tab.href` 비교로 통일 |
| `DashboardShell.tsx` | 드로어 판정을 `resolveActiveNav().l1Href === tab.href` 로 (§4-3 버그 수정) |
| `ContentsL2Tabs.tsx` | `getL2ForSection` 직접 호출 대신 `resolveActiveNav()` 사용. **단 §1-4 의 본문 렌더 위치는 그대로** |
| `taxonomy.tsx` | `NAV_SECTIONS`·`FORCED_L2`·`buildL2Href` 는 **데이터로 남긴다.** `getL2ForSection` 은 `active.ts` 내부에서만 쓰이게 하고 외부 호출을 없앤다 |

### 3-3. 드로어 버그 수정

3-2 를 하면 자동으로 해소된다. **별도 특례 코드를 추가하지 말 것.**
`핵심 인사이트`와 `키워드 분석` 중 **하나만** 활성이어야 한다.

### 5-1. 드로어 — 여기만 달라진다

모바일 폭에서 햄버거를 열고 `/dashboard/issues?view=keyword` 상태를 확인한다.

- **수정 전:** `핵심 인사이트`·`키워드 분석` **둘 다** 활성

`/dashboard/issues` 에서는 `핵심 인사이트` 하나만 활성이어야 한다.
