## 배경 (David)

가트너·KRG 등 **PDF 리포트를 대량 업로드**할 예정. 현재 업로드는 파일을 Storage 에만 저장하고 **본문 텍스트를 추출하지 않는다** → 검색·요약·엔티티·이슈 어디에도 안 잡히는 죽은 자료. 추출해서 `body_original` 에 넣으면, 그 위에서 검색·번역·요약·엔티티·이슈 매칭이 전부 동작한다.

## 설계 결정 (Opus)

1. **추출 = 업로드 후 별도 서버 단계**. 업로드(서명 URL, 기존)는 그대로. 콘텐츠 row 생성 후 **추출 엔드포인트** 호출 → Storage 에서 PDF 다운로드(service_role) → 텍스트 추출 → `body_original` 적재.
2. **번역 재사용**: 추출 텍스트 언어 감지 → 영문이면 기존 `translateToKorean`(lib/translate) 으로 `body_translated_ko` 적재, `original_language='en'`. (크롤러 영문 처리와 동일. 예산=translation_settings.)
3. **인입(enrichment) 재사용**(추출 본문 위에서, 각 best-effort try/catch):
   - **요약**: `summarizeKo(title, koBody)` → `summary_ko`.
   - **엔티티**: entity_aliases ↔ 본문/제목 매칭 → `content_entities`(99 룰 재사용).
   - **이슈**: `matchIssues(title, body, issues)` → `issue_contents`(101 재사용).
4. **스캔(이미지) PDF는 텍스트가 거의 안 나옴** → 추출 결과 길이 < 임계면 "추출 실패/스캔 추정" 표시, OCR 은 **후속**(별도, 무거움).
5. 신규 SQL 없음(컬럼·테이블 기존).

## 작업

### A. PDF 추출 유틸 — `src/lib/extract/pdf.ts` (신규)
- 의존성 추가: `unpdf`(권장) 또는 `pdf-parse`. `extractPdfText(buffer: Uint8Array): Promise<string>` — 페이지 텍스트 결합, 공백 정리. 실패 시 throw/'' 반환.
- 상한: 너무 큰 본문은 캡(예 100k자) — DB·LLM 부담 방지.
- (선택) 간단 언어 감지 `detectLang(text): 'ko'|'en'|'other'` — 한글 음절 비율 기반(81 언어감지 유틸 있으면 재사용). 한글 비율 낮고 라틴 위주면 'en'.

### B. 추출 엔드포인트 — `src/app/api/admin/contents/[id]/extract/route.ts` (신규)
- `POST`. verifyAdmin(기존 패턴) + service_role 클라이언트.
- 절차:
  1. content 조회(id) → `file_path`. PDF 아니거나 없으면 무시(204/메시지).
  2. Storage `reports` 버킷에서 다운로드(service_role) → `extractPdfText`.
  3. 텍스트 길이 < 임계(예 200자) → `{ ok:false, reason:'scanned' }`(스캔 추정, OCR 후속). row 변경 없음 또는 상태 표기.
  4. 언어 감지. 기본 `body_original = 추출텍스트`, `original_language = lang`.
  5. **영문이면** `translateToKorean(제목+본문)` → 성공 시 `body_translated_ko` 적재(예산 체크). 한글이면 생략.
  6. **요약**: koBody(= body_translated_ko ?? body_original) 충분하면 `summarizeKo(title, koBody)` → `summary_ko`(try/catch·예산).
  7. **엔티티**: `entity_aliases`(+entities) 로드 → alias 가 (제목+koBody) 에 포함되면 그 entity_id → `content_entities` upsert(source='rule', onConflict). (orchestrator 룰 미러, try/catch.)
  8. **이슈**: `issues`(published) match_keywords 로 `matchIssues(title, koBody, ...)` → `issue_contents` upsert(source='rule', try/catch).
  9. content update(body_original·body_translated_ko·original_language·summary_ko·body_fetched_at) → `{ ok:true, chars, lang, translated, summarized, entities:n, issues:n }`.
- 각 enrichment 는 **독립 try/catch**(하나 실패해도 본문 적재는 유지).

### C. 업로드 흐름에 추출 트리거 — `src/components/admin/ReportUploadForm.tsx`
- 업로드 + contents insert(기존, ~L218) **성공 직후**, 새 content id 로 `fetch('/api/admin/contents/{id}/extract', { method:'POST' })` 호출.
- 결과 표시: "본문 추출 N자 · 번역 O · 요약 O · 이슈 N건" 또는 "스캔 PDF 추정 — 텍스트 추출 실패(OCR 필요)". 실패해도 업로드 자체는 성공 처리(추출은 보조).
- PDF 외(.pptx/.docx/.xlsx)는 이번 범위 아님(추출 호출 skip 또는 PDF 만 대상). docx/pptx 추출은 후속(메모).

## 회귀 / 주의
- **신규 의존성**(unpdf 등) — 서버리스 호환 확인(Vercel Node 런타임, `export const runtime='nodejs'`). PR 사유 명시(#18).
- 추출 엔드포인트는 **service_role**(Storage 다운로드·RLS 우회) — 서버 전용(#8). verifyAdmin 필수.
- 대용량 PDF: 본문 캡·요약/번역 입력 길이 캡. 타임아웃 주의(필요시 본문만 먼저 적재, enrichment 분리 호출).
- 번역·요약은 **예산 의존**(translation_settings·llm_settings) — 한도 시 본문만 적재(graceful). 키 부족과 무관하게 **본문 추출·검색은 동작**(핵심 가치).
- 스캔 PDF = OCR 후속(이번 X). docx/pptx/xlsx 추출도 후속.
- 엔티티/이슈 룰 매칭은 크롤러와 동일 로직 — 가능하면 공용 헬퍼로 추출해 중복 줄이기(orchestrator 의 alias 매칭). 시간 없으면 복제+주석.
- UI 한국어(#1)·`any` 금지·색 토큰(#9).

### 메모(후속)
- **OCR**(스캔 PDF): tesseract/클라우드 OCR — 별도 슬라이스(무거움·비용).
- **docx/pptx/xlsx 추출**: mammoth(docx) 등으로 확장(ACCEPT_ATTR 이미 허용).
- 추출 룰매칭(엔티티/이슈)을 크롤러와 **공용 헬퍼**로(중복 제거).
- 전략보고서 워크벤치(캡스톤)는 이 추출 위에서 PDF 근거까지 인용 가능.
