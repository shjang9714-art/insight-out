## 배경 (David, 마스터플랜 §3)

어드민 진입을 "현황 나열"에서 **"오늘 할 일"**로 바꾼다. 운영자가 매일 처음 보는 화면이 *검토 대기·오늘 수집·실패/오류*와 *사용량 한도·데이터 점등 상태*여야 한다. 특히 **시드/데이터 점등 상태**(지금은 SQL로만 확인 가능 → 수희 적용 여부를 숫자로 가시화)를 이 화면에서 본다.

## 설계 결정 (Opus)

1. `/admin/page.tsx` 상단에 **두 섹션을 추가**(기존 KPI·차트 위). 순서: ① **오늘 할 일** → ② **운영 신호등** → (기존) 운영 현황 KPI → 수집 분석 차트.
2. usage/점등 집계는 **`createAdminClient()`**(service role, server-only)로 — `llm_usage`·`llm_settings`·`translation_usage`·`tts_usage`는 RLS 제약 가능. 기존 콘텐츠/소스 집계는 현행 쿠키 클라이언트 유지.
3. **graceful**: 모든 신규 쿼리는 `?? 0` / try 가드. `content_signals` 등 테이블 미존재/RLS 차단 시에도 0으로 표시(크래시 금지).
4. **§4 디자인 가이드 준수**(아래 "디자인 준수" 절). 신규 위젯은 **공통 섹션 헤더 패턴**(아이콘+제목+목적 한 줄)으로.

## 작업

### A. 데이터 집계 — `src/app/admin/page.tsx` (server, 기존 Promise.all 확장 또는 admin 클라 별도 묶음)

`createAdminClient()` 인스턴스(`admin`) 추가 후, 다음을 **병렬**로:

- **오늘 할 일**
  - 검토 대기: 이미 있음(`pendingRes.count`) 재사용.
  - 오늘 수집: 이미 있음(`todayRes.count`) 재사용 + 오늘 실패 건수: `crawl_logs` `status in ('failed','partial')` `started_at >= todayStart` count.
  - 점검 필요 소스: 최근 24h `crawl_logs`에서 `status in ('failed','partial')`인 **distinct source_id** 수(간단히 `select source_id, status` 바운디드 후 코드 집계). 0이면 "정상".
- **운영 신호등 — 사용량/한도** (period = `getKstPeriod()`)
  - LLM: `llm_usage(provider,tokens)` + `llm_settings(provider,enabled,monthly_token_limit)` 현재 period → provider별 `tokens/limit` %. `PROVIDER_MAP[p].isConfigured()`로 **키 설정 여부**. (api/admin/llm/route.ts 패턴 그대로.)
  - 번역: `translation_usage(provider,chars)` 현재 period 합. (한도는 env라 표시 생략 가능 — chars 사용량만.)
  - TTS: `tts_usage(chars)` 현재 period 합 + `process.env.TTS_MONTHLY_CHAR_CAP`(있으면 %).
- **운영 신호등 — 데이터 점등** (head count, `?? 0`)
  - `issues`(전체), `entities`(전체), `insight_cards`(status='published' 또는 전체), `ai_reports`(전체), (graceful) `content_signals`(전체). 각 0이면 "미점등".

### B. 오늘 할 일 위젯 — `src/components/admin/AdminTodoBlock.tsx` (신규, server 또는 순수 presentational)
- props: `{ pending: number; todayCollected: number; todayFailed: number; sourcesToCheck: number }`.
- **3개 액션 카드**(가로 그리드, `rounded-xl border p-4`, 그림자 없음):
  1. 콘텐츠 검토 — `검토 대기 {pending}건` + CTA Link `/admin/contents?status=pending` "검토하기 →". pending>0이면 숫자 강조(`text-foreground`), 0이면 muted + "검토할 항목 없음 ✓".
  2. 오늘 수집 — `{todayCollected}건` + (todayFailed>0면) `실패 {todayFailed}` amber 배지. Link `/admin/contents?from=today`.
  3. 소스 점검 — `점검 필요 {sourcesToCheck}곳`(>0 amber, 0 "정상 ✓" muted) Link `/admin/sources`.
- 섹션 헤더: `아이콘(ClipboardCheck) + "오늘 할 일" + "검토·수집·점검을 한눈에"`.
- 모두 0/정상이면 카드는 유지하되 차분한 muted 상태(휑하지 않게 "오늘은 급한 작업이 없습니다" 한 줄 보조).

### C. 운영 신호등 위젯 — `src/components/admin/AdminOpsSignals.tsx` (신규, presentational)
- props: usage 배열 + 점등 카운트.
- **사용량 바**: 항목별 가로 막대(`provider · 사용/한도 · %`). %≥100 red, ≥80 amber, else brand-600/muted. 키 미설정 LLM provider는 "미설정" 회색칩(막대 없음). tabular-nums.
- **데이터 점등**: 칩 그리드(이슈 N·엔티티 N·인사이트 N·시그널 N·보고서 N). 값>0 = `text-foreground`, 0 = muted + "미점등". 점등 0 항목이 있으면 보조문구 "0인 항목은 SQL 적용/수집 후 점등됩니다."
- 섹션 헤더: `아이콘(Activity) + "운영 신호등" + "사용량 한도와 데이터 점등 상태"`.

### D. 페이지 조립 — `src/app/admin/page.tsx`
- 반환 JSX 최상단(제목 아래)에 `<AdminTodoBlock …/>` → `<AdminOpsSignals …/>` → 기존 KPI 섹션 → 차트. `space-y-10` 유지(섹션 간 32~40px).

## 디자인 준수 (마스터플랜 §4)
- 색: 의미색 최소 — 한도 경고 amber(≥80%)/red(≥100%), 그 외 muted·brand-600은 CTA만. 한 카드 색 배지 ≤2.
- 타이포: 숫자 `tabular-nums`, 본문 ≥12px, 위계 weight 400/500/600.
- 여백/경계: `rounded-xl`, 0.5px `border-border`, **그림자 없음**. 카드 패딩 16~20px(`p-4`~`p-5`).
- 빈 상태: 항상 "무엇을 하면 채워지는지" 한 줄(점등 0·검토 0 등).
- 섹션 헤더 패턴 통일(아이콘+제목+목적 한 줄) — TodoBlock·OpsSignals·기존 KPI 헤더와 톤 맞춤.
- 다크모드: 의미 토큰만(하드코딩 hex 금지, AGENTS §9).
