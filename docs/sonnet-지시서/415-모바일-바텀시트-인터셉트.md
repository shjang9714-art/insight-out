## 1. 착수 전 확인 (직접 확인 2026-07-23)

### 1.1 현재 진입 동선 — 전부 `<Link>` 전체 페이지 이동
| 출처 | 파일 | 이동 대상 |
|---|---|---|
| 신호(급상승) | `src/components/dashboard/IssueRankTicker.tsx` (51·97행) | `contentId` 있으면 `/dashboard/contents/[id]`, 없으면 `/dashboard/issues/[id]` |
| 기업 | `src/components/entities/EntityBrowse.tsx` (104행) | `/dashboard/entities/[id]` |

→ 인터셉트 대상 상세 라우트 **3종**: `contents/[id]` · `issues/[id]` · `entities/[id]`. 셋 다 `src/app/dashboard/<type>/[id]/page.tsx` 로 실재(확인함).

### 1.2 🔑 인터셉팅 라우트는 `<Link>` 를 안 건드린다
- `@modal` 병렬 슬롯 + `(.)<type>/[id]` 인터셉트를 깔면 **기존 `<Link>` 의 소프트 내비게이션이 자동으로 슬롯에서 가로채진다.** IssueRankTicker·EntityBrowse **무수정.**
- 새로고침·직접 URL·하드 내비게이션 → 인터셉트 안 됨 → **기존 `[id]/page.tsx` 전체 페이지 그대로 렌더**(회귀 없음). 이게 이 패턴의 핵심 안전장치다.

### 1.3 ⚠️ 데스크톱도 인터셉트된다 — 설계상 수용
- 인터셉트는 **뷰포트와 무관**하다. 데스크톱에서도 앱 내 클릭 시 전체 페이지 이동 대신 **오버레이**가 뜬다(직접 URL·새로고침은 여전히 전체 페이지).
- → **시트를 반응형으로**: 모바일 = 하단 바텀시트, 데스크톱 = 중앙 모달. David 육안 확인 항목(§4-9).
- 이건 M-4 가 요구하는 "라우트 유지 오버레이"(설계문서 §136)의 정석 구현이다. 데스크톱 전체-페이지 이동을 굳이 보존하려 인터셉트를 뷰포트로 끄는 꼼수는 **쓰지 않는다**(복잡·깜빡임).

### 1.4 재사용할 오버레이 — 없음, 단 radix 프리미티브는 있음
- `src/components/ui/dialog.tsx` = radix-ui `Dialog` 기반 **중앙 모달**(하단 시트 아님). 그대로는 못 쓴다.
- 하지만 radix `Dialog` 프리미티브(Portal·Overlay·focus trap·ESC 닫기)는 **시트의 하부로 재활용**한다. 위치·애니메이션 클래스만 시트용으로 새로.
- `vaul`·`framer-motion`·자체 `createPortal` **없음**(grep 0건) — 새 의존성 추가 금지, radix + tailwind 로 만든다.

### 1.5 z-index 스택
- 드로어 오버레이 `z-30` / 드로어 본체 `z-40` / 하단 탭바(411) `z-40` / `FloatingBriefingMini`·기존 Dialog `z-50`.
- → **시트 오버레이·본체는 `z-50` 이상**(탭바·미니플레이어 위). 미니플레이어와 겹치면 시트가 위(모달 컨텍스트가 최상단).

## 2. 구현

### 2.1 `@modal` 병렬 슬롯 추가 — `src/app/dashboard/layout.tsx`
- 시그니처에 `modal` 슬롯 추가: `{ children, modal }: { children: React.ReactNode; modal: React.ReactNode }`.
- `DashboardShell` 안, `{children}` **뒤에** `{modal}` 렌더.
- ⚠️ 기존 `ActiveCategoryProvider`·`resolveInitialCategory`·`Suspense` **무수정.** 슬롯 prop 만 추가.
```tsx
export default async function DashboardLayout({
  children, modal,
}: { children: React.ReactNode; modal: React.ReactNode }) {
  // ... 기존 그대로 ...
  return (
    <ActiveCategoryProvider initialCategory={initialCategory}>
      <Suspense fallback={<div className="min-h-screen bg-background" />}>
        <DashboardShell>{children}</DashboardShell>
      </Suspense>
      {modal}
    </ActiveCategoryProvider>
  )
}
```

### 2.2 슬롯 기본값 — `src/app/dashboard/@modal/default.tsx`
```tsx
export default function Default() { return null }
```
- ⚠️ **필수.** 병렬 슬롯은 하드 내비게이션/새로고침 시 매칭 안 되면 `default.tsx` 가 없으면 404 가 난다. `null` 반환으로 "슬롯 없음".

### 2.3 인터셉팅 라우트 3종
`(.)` = `@modal` 슬롯 기준 같은 레벨(`dashboard/`)의 자식을 인터셉트.

```
src/app/dashboard/@modal/(.)contents/[id]/page.tsx
src/app/dashboard/@modal/(.)issues/[id]/page.tsx
src/app/dashboard/@modal/(.)entities/[id]/page.tsx
```

각 파일(서버 컴포넌트):
- **기존 상세 페이지가 쓰는 데이터·본문 컴포넌트를 그대로 재사용**해 `<DetailSheet>` 로 감싼다. **상세 본문을 새로 쓰지 않는다.**
- 방법: 기존 `src/app/dashboard/<type>/[id]/page.tsx` 를 열어, 데이터 조회 + 본문 렌더 부분을 확인하고 **동일하게** 조회해 같은 본문 컴포넌트를 `<DetailSheet>{본문}</DetailSheet>` 로 렌더.
  - 본문이 페이지 파일 안에 인라인이면, **공용 컴포넌트로 추출**(예: `src/components/<type>/<Type>DetailBody.tsx`)해 **기존 페이지와 인터셉트 슬롯이 함께 import** 하게 한다. 이러면 상세 로직이 한 곳(중복 0).
  - 추출 시 **기존 페이지 렌더 결과가 픽셀 단위로 동일**해야 한다(회귀 금지). 추출은 "잘라 옮기기"지 재작성 아님.
```tsx
// 예: @modal/(.)entities/[id]/page.tsx
import DetailSheet from '@/components/mobile/DetailSheet'
import EntityDetailBody from '@/components/entities/EntityDetailBody' // 기존 본문 추출분
export default async function InterceptedEntity({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  return (
    <DetailSheet titleFallback="기업 상세">
      {/* 기존 페이지와 동일한 데이터 흐름 */}
      <EntityDetailBody id={id} />
    </DetailSheet>
  )
}
```
- ⚠️ **본문 추출이 위험하면**(로직이 페이지에 강하게 얽힘) 그 타입은 **본문 재조회 없이 기존 페이지 컴포넌트를 직접 재사용**하는 최소 방식으로. 셋 중 하나라도 추출이 과하면 §7 기록란에 남기고 그 타입만 방식 달리해도 된다(단 결과 화면은 동일해야 함).

### 2.4 신규 `src/components/mobile/DetailSheet.tsx` (클라이언트)
반응형 오버레이. radix `Dialog` 프리미티브 기반.
- **열림 상태 = 라우트가 이 슬롯을 채운 것 자체.** 별도 `open` state 없이, 마운트되면 열린 것으로 본다.
- **닫기 = `router.back()`**(뒤로가기로 URL 원복 → 슬롯 비고 `default.tsx` 로). 오버레이 클릭·ESC·닫기(×)·시트 핸들 아래로 스와이프(선택) 모두 `router.back()`.
- 레이아웃:
  - 오버레이: `fixed inset-0 z-50 bg-black/50`.
  - **모바일**(기본): 하단 시트 — `fixed inset-x-0 bottom-0 z-50 rounded-t-2xl max-h-[85vh] overflow-y-auto`, 상단에 그랩 핸들 바, 아래에서 위로 슬라이드업 애니메이션. **하단 탭바 높이 고려**해 콘텐츠 하단 패딩(`pb-[calc(...safe-area)]`).
  - **데스크톱**(`md:` 이상): 중앙 모달 — `md:inset-auto md:left-1/2 md:top-1/2 md:-translate-x-1/2 md:-translate-y-1/2 md:max-w-2xl md:rounded-2xl md:max-h-[85vh]`.
- 헤더: 제목(라우트가 주거나 `titleFallback`) + 닫기(×). 접근성: `Dialog.Title`(radix 요구), `aria-label`.
- **`preload='none'` 등 미니플레이어 로직과 무관.** 시트는 별개 레이어.

### 2.5 액션 바(시트 하단) — 설계문서 §42 골격
시트 하단에 **액션**: `추적 토글` · `보고서로` · `공유`.
- ⚠️ **이번 슬라이스는 자리(플레이스홀더)만 정확히 잡는다.** 각 액션의 실제 동작(watchlist 연동·리포트 생성·공유 시트)은 **기존 기능이 있으면 연결, 없으면 다음 슬라이스.** 없는 걸 새로 만들지 않는다.
  - `추적 토글`: `WatchlistManager`/`WatchlistSettingsModal` 기존 로직이 있으면 재사용, 아니면 버튼만(비활성 툴팁 "준비 중").
  - `보고서로`·`공유`: 기존 진입점 있으면 연결, 없으면 자리만.
- §7 기록란에 3개 각각 "연결함/자리만" 기록.

- 액션의 실제 기능을 **새로 구현하지 않는다**(§2.5 — 연결 or 자리).
- `daily-insights/[id]`·`insights/[id]`·`reports/[id]` 등 **다른 상세는 이번 대상 아님**(신호·기업만).

## 4. 회귀 가드
1. **모바일**: 신호 탭 → 하단 바텀시트로 상세(페이지 이동 없음). 기업 탭 → 동일.
2. 시트에 **시사점·논조 차트·근거 콘텐츠**(=기존 상세 본문)와 하단 액션 바.
3. 시트 닫기(×·오버레이·ESC·뒤로가기) → 원래 목록으로, URL 원복.
4. **뒤로가기 버튼**으로 시트가 닫힌다(라우트 유지의 이점).
5. **직접 URL·새로고침** `/dashboard/entities/[id]` → **기존 전체 페이지** 렌더(인터셉트 안 됨, 회귀 없음).
6. 신호가 `contentId` 없을 때 `issues/[id]` 시트, 있을 때 `contents/[id]` 시트 — 둘 다 뜬다.
7. 시트가 **하단 탭바·미니플레이어 위**(z-50+)에 뜨고 본문과 안 겹친다.
8. **하드 내비게이션/다른 슬롯 미매칭**에도 404 안 남(`@modal/default.tsx`).
9. **데스크톱**: 앱 내 클릭 시 중앙 모달로 상세(오버레이). 직접 URL·새로고침은 전체 페이지. 다른 데스크톱 네비 무변경. ← David 확인
10. 시트 안 근거 콘텐츠/링크가 정상 동작(추가 이동 시 시트 위에서).
