## 배경 (David)

346까지 UI는 정리됐지만 **내용이 비어 있다.** 현재 리포트 문장: *"경쟁사들의 공격적인 AI 인프라 투자와 사업 재편 움직임이 두드러졌습니다."* — "공격적", "두드러졌다"는 관찰이 아니라 형용사다. 읽고 나서 할 수 있는 행동이 없다. 단일 패스 LLM의 전형적 실패다.

골드 샘플(같은 데이터, 프레임 적용)과 비교하면 격차가 명확하다: KT 1GW·5조 vs SK 15GW로 **자릿수가 벌어졌고**, KT가 같은 주에 '토큰 팩토리'를 발표한 것은 스케일 경쟁을 포기하고 **정의를 바꾸려는** 수다 — 이런 문장이 나와야 한다.

## 설계 결정 (Opus·David)

1. **해석을 LLM 자유서술에 맡기지 않는다.** 프레임 슬롯을 코드로 고정하고 채우게 한다: 사실 → 의도 → 충돌면 → 비대칭 → 시사점 → **지켜볼 지표**.
2. **`watch_metrics`(지켜볼 지표)가 핵심 장치다.** 반증 가능한 문장을 강제하면 "~할 것으로 전망된다"로 도망갈 수 없다.
3. **3패스 체인 + 수동 경로.** 유료 LLM API는 보류(David). 패스 ①③은 앱이 자동, **패스 ②(분석)만 Claude MCP 수동**. ②의 입출력을 JSON 스키마로 고정해두면, 나중에 `llmComplete` 호출로 갈아끼우는 것만으로 완전 자동이 된다. **수동 경로는 임시방편이 아니라 정식 경로로 설계한다.**
4. **HTML을 LLM에게 생성시키지 않는다.** 구조화 JSON → 앱 템플릿 렌더. HTML을 뱉게 하면 근거 검증이 불가능해지고(문장↔기사 연결이 사라짐) 톤·다크모드·반응형이 매번 깨진다. (현 전략보고서의 실패 지점 — 349에서 같이 고친다.)
5. **스키마 변경 0.** 전부 `sections` JSONB 내부.

## 작업

### A. 데이터 계약 — `src/lib/competitor-weekly/query.ts`

`CompetitorWeeklySection` 확장(기존 필드 유지, 신규 필드는 **전부 optional** — 과거 리포트 하위호환).

```ts
export interface WeeklyEvent {
  id: string            // 'evt_001' — 패스① 산출, 근거 참조 키
  date: string          // 'YYYY-MM-DD'
  actor: string         // 'KT' | 'SKT' | '정부' …
  event: string         // 사실 서술(해석 금지)
  numbers?: Record<string, string>   // { capex_krw: '5조', capacity: '1GW' }
  content_id: string    // 원 기사
  source_name?: string
}

export interface StatusPoint {          // 현황 — 꼭지 문장 + 근거
  thesis: string        // "규모의 자릿수가 벌어졌다" (한 줄, 명제형)
  detail: string        // 2~3문장 설명
  evidence: string[]    // ['evt_001','evt_003']
}

export interface IntentRead {
  actor: string
  seeking: string       // '자원(전력·GPU·부지)' | '수익모델·표준' | '고객 접점' | '규제 대응' | '신뢰 회복'
  reading: string       // 왜 지금 이 수를 두는가
  evidence: string[]
}

export interface Option {
  action: string
  rationale: string
  cost?: '상' | '중' | '하'
}

export interface WatchMetric {
  metric: string        // '7/22 부총리 2차 회동 인센티브 배분'
  if_then: string       // '특정사 쏠림 시 … 판단이 맞다'
  due?: string          // 'YYYY-MM-DD'
}

export interface CompetitorWeeklySection {
  area_key: string
  area_label: string
  companies: string[]
  impact: '위기' | '기회' | '관망'
  moves: string                     // (레거시) 유지 — 과거 리포트 렌더용
  implication: string               // (레거시) 유지
  citations: CompetitorWeeklyCitation[]

  // 348 신규 (optional)
  events?: WeeklyEvent[]            // 패스①
  overview?: string                 // 개요 1문단
  status_points?: StatusPoint[]     // 현황 — 꼭지 3~5개
  intents?: IntentRead[]            // 의도 분석
  conflict_areas?: string[]         // LG U+ 관점 — 충돌면
  asymmetry?: { theirs: string; ours: string; evidence: string[] }  // 비대칭
  options?: Option[]                // 시사점 — 대응 옵션 2~4
  watch_metrics?: WatchMetric[]     // 지켜볼 지표 2~4
}
```

### B. 패스 ① 사실 추출 (자동) — `generate.ts`

- 기존 "영역별 기사 묶음 → LLM 1회(moves/impact/implication)" 를 **사실 추출 전용 호출**로 바꾼다.
- 출력: `events[]`(위 `WeeklyEvent`). **해석 금지** — "~로 보인다/전망된다/공격적" 등이 섞이면 패스① 실패다. 프롬프트에 명시.
- 모델: 현재 무료 라우팅(`llmComplete`) 그대로. 이 작업은 저가 모델로 충분하다.
- `impact`(위기/기회/관망) 판정은 패스①에서 하지 않는다 → 패스②로 옮긴다(해석이므로).
- 프롬프트는 `llm_prompts` 테이블 우선 + 코드 상수 폴백(기존 패턴 유지). key: `competitor_weekly_facts`.

### C. 패스 ② 분석 (Claude MCP 수동) — 어드민 export/import

`AdminCompetitorWeeklyGenerate.tsx` + `api/admin/competitor-weekly/`에 추가.

**① 컨텍스트 내보내기** (`GET .../export?week=YYYY-MM-DD`)
- 응답: `{ week_start, week_end, areas: [{ area_key, area_label, events: WeeklyEvent[] }], frame_spec }`
- `frame_spec`은 패스② 산출 JSON 스키마 + 작성 규칙(아래)을 그대로 담은 문자열. **어드민 화면에 "복사" 버튼** — David가 Claude에 붙여넣는다.

**② 결과 가져오기** (`POST .../import`)
- 본문: 영역별 `{ area_key, overview, status_points, intents, conflict_areas, asymmetry, options, watch_metrics, impact }` + 상단 종합(`summary`, `overall_impact`, `emerging_topics`)
- **스키마 검증**(zod 등 불필요, 수동 검증 함수로 충분): 필수 필드 누락·타입 불일치·`evidence`가 존재하지 않는 `evt_id` 참조 → 400 + 어느 필드가 왜 틀렸는지 반환.
- 검증 통과 → 패스③ → 저장(`status='draft'`). 발행은 기존 발행 버튼.

**frame_spec 작성 규칙 (프롬프트에 포함)**
- `status_points[].thesis`는 **명제형 한 줄**("규모의 자릿수가 벌어졌다"). 형용사 나열 금지.
- `intents[].reading`은 **왜 지금 이 수를 두는가**. "확보하려는 것"을 seeking에 명시.
- `asymmetry`는 **그쪽이 가진 것 / 우리가 가진 것**을 각각 한 문단. 없는 자산을 지어내지 말 것.
- `watch_metrics`는 **반증 가능해야 한다**. "지켜봐야 한다" 금지. "8월 내 확정 공시가 없으면 선언에 가깝다" 형태.
- 모든 서술 필드는 `evidence`의 `evt_id`로 뒷받침. 근거 없는 해석은 쓰지 말 것.

### D. 패스 ③ 근거 검증 (자동, 저장 직전)

`lib/competitor-weekly/verify.ts`(신규)
- 규칙: `status_points`·`intents`·`asymmetry`의 모든 항목은 **`evidence` 배열이 비어 있으면 저장하지 않는다**(드롭 + 경고 로그).
- `evidence`의 `evt_id`가 해당 영역 `events[]`에 없으면 드롭.
- `numbers`에 등장하는 수치가 서술문에 나오는데 어떤 event의 `numbers`에도 없으면 **경고**(드롭까지는 하지 않되 어드민에 표시) — 환각 수치 차단.
- 드롭된 항목은 import 응답에 리스트로 반환 → 어드민에 "검증에서 제외된 문장" 표시.

### E. 상세 페이지 5파트 — `CompetitorWeeklyReport.tsx` 재작성

**지면(paper)형 레이아웃.** 좌측 마진에 섹션 넘버, 본문은 우측 컬럼.

```
┌────────────────────────────────────────────────────────┐
│ COMPETITOR WEEKLY · 2026 W28      2026.07.06–07.13 · 근거 18건
│ AIDC 규모 경쟁이 자본·정책·수익모델 3개 전선으로 번졌다   ← summary(22px)
│ [종합 위기]  AIDC · 통신 B2B · 보안
├════════════════════════════════════════════════════════╡ (2px 룰선)
│ 01 · 개요      │ overview 한 문단
│ 02 · 현황      │ ▸ 규모의 자릿수가 벌어졌다  [1][2]      ← thesis(15px/600)
│                │   KT 1GW·5조 vs SK 15GW…               ← detail(14px)
│                │ ▸ SK는 구조까지 손대고 있다 [3]
│ 03 · 의도 분석 │ [SK — 자원 선점]  reading…             ← 카드(bg-muted)
│                │ [KT — 수익모델 선점] reading…
│ 04 · LG U+ 관점│ 충돌면: AIDC · 통신 B2B · 보안         ← 칩
│                │ 비대칭: 그쪽 / 우리 (2열)
│ 05 · 시사점    │ 대응 옵션 1~4 (번호 목록)
│                │ ┃ 지켜볼 지표 (좌측 액센트 바 블록)
│ 근거           │ [1] 디일렉·07.07  [2] 디지털데일리·07.12 …
└────────────────────────────────────────────────────────┘
```

- **각주 방식**: 서술문 끝에 `[1][2]` 위첨자 → 하단 근거 목록 → 클릭 시 `/dashboard/contents/{content_id}`(우리 DB 상세). 외부 원문 직링크 아님.
- 섹션 넘버·라벨: `text-[12px] text-muted-foreground`, 좌측 128px 컬럼(`md:grid-cols-[128px_1fr]`, 모바일은 1열 스택).
- `지켜볼 지표`는 좌측 3px 액센트 바 블록(`border-l-[3px] border-brand-600`, **rounded 금지** — 단면 보더에 라운드 주지 않는다).
- 신규 필드가 없는 **과거 리포트는 레거시 렌더**(`moves`/`implication`)로 폴백. 필드 유무로 분기.
- `@media print` 규칙 추가(임원 보고용 PDF 저장) — 헤더/네비 숨김, 페이지 여백.

## 회귀 / 주의

- **`sections` JSONB 하위호환**: 신규 필드는 전부 optional. 과거 리포트가 깨지면 안 된다. `(sections ?? [])`, `section.status_points ?? []` 방어.
- **패스①에 해석이 섞이면 전체가 무너진다.** `events[].event`에 "~로 보인다/전망/공격적/두드러진" 류가 들어가지 않는지 프롬프트 + 후처리로 확인.
- 크론(`api/cron/competitor-weekly`)은 **패스①까지만** 자동 수행하고 `draft`로 남긴다. 패스② 없이 발행되지 않게 할 것.
- `impact` 판정 위치가 패스①→②로 이동한다. 기존 코드에서 패스① 결과로 `impact`를 쓰던 곳 확인.
- 어드민 import는 **admin 권한 검증**(기존 `verifyAdmin` 재사용) 필수.
- 검증: `npx tsc --noEmit` · ESLint · `check-prefetch` · `npm run build` · 육안(과거 리포트 = 레거시 렌더 정상 / 신규 = 5파트).

## 부록 — 전략보고서 수동 등록 경로 (349-A 선행분)

주간 리포트와 같은 철학을 전략보고서에도 최소한으로 적용했다. **LLM에게 HTML을 생성시키는 기존 경로**(`/api/reports/generate-strategy`)와 별개로, **사람이 Claude로 작성·검토한 본문을 그대로 등록하는 경로**를 추가한다.

- `POST /api/admin/reports/import` (신규, 어드민 전용)
  - body: `{ type, topic, title, summary, bodyHtml, sourceTitles?: string[], publish?: boolean }`
  - `bodyHtml`은 `sanitizeReportHtml`로 살균 후 저장(script/style/on* 차단).
  - `sourceTitles`는 **우리 DB 기사 제목 부분일치**로 `contents`를 찾아 `ai_report_sources`에 연결한다 → 보고서 각주가 외부 죽은 링크가 아니라 **우리 DB 콘텐츠 상세**를 가리킨다. 매칭 실패분은 `unmatchedTitles`로 반환.
  - `publish: true`면 `published_at`을 찍어 즉시 발행.
- 349에서 구조화 JSON + 앱 템플릿 렌더로 확장할 때, 이 엔드포인트가 그대로 import 경로가 된다.

**⚠️ 로컬에서 동작하지 않는다** — `createAdminClient()`가 `SUPABASE_SERVICE_ROLE_KEY`를 요구하는데 `.env.local`에는 anon 키만 있다. 로컬 검증하려면 서비스 롤 키를 `.env.local`에 추가하거나, 배포 후 프로덕션에서 실행할 것. (패스① 생성도 같은 이유로 로컬 실행 불가 — LLM 키도 `.env.local`에 없다.)
