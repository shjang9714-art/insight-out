## 0. 한 줄
394 §3.2 "전환 시 이전 목록 유지"를 **카테고리 전환에까지 적용한 것이 과했다.** 유튜브 탭에서 뉴스 탭으로 갈 때 **유튜브 썸네일이 잔상으로 남아** 더 정신없어졌다.

---

## 1. 무엇이 잘못됐나 (플래너 판단 오류)

394 §3.2 는 `isLoading && page === 1` 을 `items.length === 0 && isLoading` 으로 바꿔, 목록이 있으면 무조건 유지하게 했다. 그 결과:

```
유튜브 탭 (강렬한 썸네일들)
  → "뉴스" 클릭
  → 유튜브 카드가 화면에 그대로 남아 있음  ← 잔상
  → 뉴스 카드로 교체
```

**"이전 목록 유지"는 같은 성격의 데이터가 갱신될 때 유효하다.** 검색어 변경·키워드 칩·페이지네이션이 그렇다. 그러나 **카테고리가 바뀌면 내용물이 완전히 다른 것**이라, 이전 것을 남기면 "안 바뀐 화면" 또는 "잘못된 화면"으로 읽힌다. 유튜브 썸네일은 빨강·노랑 텍스트가 박힌 고채도 이미지라 특히 두드러진다.

> 외부 검토의 "탭 재방문 시 스켈레톤 금지"는 **캐시된 같은 데이터를 복원할 때** 얘기였다. 플래너가 카테고리 전환까지 싸잡아 적용했다.

**진행선도 실패다.** 브랜드 마젠타 2px가 콘텐츠 상단을 가로지르니 **경고 배너처럼 읽힌다**(디렉터 확인). 정확한 신호인 것과 안심되는 신호인 것은 다르다.

## 2. 구현

### 2.1 카테고리가 바뀌면 목록을 비운다

`category` 값이 직전 값과 달라지면 **즉시 `setItems([])`** 하여 스켈레톤 경로를 타게 한다.

- `useRef` 로 직전 `category` 를 들고, 콘텐츠 조회 `useEffect` 안에서 **쿼리를 쏘기 전에** 비교·초기화한다.
- `total` 도 함께 `null` 로 초기화한다(카테고리별 건수가 다르므로).
- **`fixedCategory` 로 고정된 사용처**(`/dashboard/reports` 의 `ContentsBoard fixedCategory="리서치"` 등)는 `category` 가 바뀌지 않으므로 영향 없다.

### 2.2 이전 목록을 유지할 대상은 그대로 둔다

**아래는 394 동작을 유지한다** — 여기서 스켈레톤으로 돌아가면 안 된다.
- 검색어 변경(`q`)
- 키워드 칩 선택/해제(`kw`)
- 정렬 변경(`sort`)
- `더 보기`(페이지네이션 — 원래도 append)

즉 **`category` 만 예외**다.

### 2.3 진행선 제거

콘텐츠 영역 상단 2px 진행선을 **삭제**한다.

`opacity-[0.85]` 는 **유지**한다 — 검색·칩 전환 때 "바뀌는 중"을 알리는 최소 신호이고, 경고로 읽히지 않는다.
※ 단, `더 보기`(page > 1)에서는 **기존 목록 전체가 흐려지지 않도록** 적용에서 제외한다(394 육안 나짓).

### 2.4 손대지 말 것
- `ContentCardSkeleton` 의 **모양·썸네일 자리는 그대로 둔다.** 디렉터 확인 결과 레이아웃 점프는 해결됐다.
- 로딩 사다리(200ms 지연 · 350ms 최소 유지 · 1.5s 문구 · 5s 재시도) 그대로.
- 칩 영역 `min-h-[34px]` 그대로.
- `strip-llm-artifacts` 그대로(정상 동작 확인됨).

## 3. 회귀 가드
1. **카테고리 전환(뉴스↔유튜브↔웹인사이트) 시 이전 카테고리 카드가 한 프레임도 보이지 않는다.**
2. 검색어 입력·키워드 칩 선택 시에는 **기존 목록이 유지**된다(스켈레톤으로 돌아가지 않는다).
3. `더 보기` 시 기존 목록이 흐려지지 않고, 새 항목이 아래에 붙는다.
4. 카드↔목록 뷰 전환 시 재조회 없음(현재 정상).
5. `?category=` 4개 진입 정상.
6. 결과 0건일 때 빈 상태 UI 정상.
