## 0. 한 줄

인사이트 카드와 이슈 카드에 **관련 키워드 칩**을 추가한다. 근거 콘텐츠의 `matched_keywords` 를 집계해 상위 3~5개를 칩으로 보여준다(토픽 칩과 별도). 새 컬럼 없이 기존 데이터 집계.

## 1. 현행 진단 (검증된 코드 사실)

- 인사이트 카드: `ContentMetaRecord`(`InsightCardsSectionClient` 30-33) = `{title, category, sourceName}` — **matched_keywords 없음**. 카드는 `topic` 칩만(164/169). 근거 콘텐츠 id 는 `source_content_ids`·`citations[].content_id` 로 보유.
- 이슈 카드: `IssueCard`(activity.ts) 에 키워드 없음. `fetchIssueActivity` 는 `issue_contents` 조인으로 `contents{collected_at, sentiment}` 만 집계(키워드 미수집).
- `contents.matched_keywords`(text[]) 는 존재(전 파이프라인에서 사용 중).

## 2. DB / SQL

**없음.** `contents.matched_keywords` 기존 컬럼 집계.

## 3. 구현

### 3-1. 인사이트 카드 관련 키워드
- `AiInsightsView`·`entities/page`(관심기업)의 contents 조회에 **`matched_keywords` 추가**(현재 `id, title, category, sources(name)` 조회에 병합).
- `ContentMetaRecord` 에 `matchedKeywords?: string[]` 추가.
- `InsightCardsSectionClient`(+`InsightCardNewsList`): 카드의 근거 content 들(`source_content_ids` + citations)의 matched_keywords 를 **합집합·빈도순 상위 5개**로 집계(topic 과 중복 제거) → "관련 키워드" 칩(작은 중립/저채도, `/dashboard/topics/{kw}` 링크). 169 카드의 근거 위 또는 푸터 근처.
- 키워드 0개면 섹션 생략.

### 3-2. 이슈 카드 관련 키워드
- `fetchIssueActivity`: `issue_contents` 조인 select 에 `contents(collected_at, sentiment, matched_keywords)` 로 확장. 이슈별 matched_keywords **빈도 상위 4개** 집계 → `IssueCard.topKeywords: string[]` 추가.
- `IssueBoardClient`: 카드에 관련 키워드 칩(작은 중립 칩) — "왜 중요한가"(166) 아래 또는 푸터. 0개면 생략.

### 3-3. 공통
- 칩 스타일: 저채도 중립(`bg-muted text-muted-foreground`) — 버킷색(167) 카테고리 칩과 구분(관련 키워드는 보조 정보). 과밀 방지(최대 5·4개, 한 줄 wrap).
- 링크: 토픽 페이지(`/dashboard/topics/{encodeURIComponent(kw)}`) 존재 활용.
