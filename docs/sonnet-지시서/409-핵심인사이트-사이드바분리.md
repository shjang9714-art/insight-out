## 0. 한 줄
핵심인사이트 3탭(카드·이슈·일일)을 **사이드바 3개 메뉴로 분리**한다. **이슈·일일은 독립 라우트가 이미 있다** — nav 에 꺼내고 insights 를 카드 전용으로 줄이면 끝.

---

## 1. 착수 전 확인 (직접 확인 2026-07-22) — 분리 대상이 이미 라우트로 존재

| 탭 | 컴포넌트 | 독립 라우트 | 상태 |
|---|---|---|---|
| 인사이트 카드 | `InsightCardsManager`(422줄) | `/admin/insights`(현재 Hub) | Hub 안에만 |
| 이슈 관리 | `IssueManager`(852줄) | **`/admin/issues` 이미 존재** | `AdminPageHeader + IssueManager` 완성 |
| 일일 핵심 | `DailyInsightsManager`(225줄) | **`/admin/daily-insights` 이미 존재** | `AdminPageHeader + DailyInsightsManager` 완성 |

- `InsightHub`(383/384)가 **이미 있는 두 라우트를 탭으로 다시 묶은 것**이다. nav 에는 `/admin/insights` 하나만 노출돼 두 라우트가 매몰돼 있었다.
- → **새 라우트를 거의 만들지 않는다.** nav 노출 + insights 축소 + Hub 삭제.

---

## 2. 구현

### 2.1 `nav.ts` — `인사이트` 그룹을 3개 메뉴로
현재(73행 근처):
```ts
{ href: '/admin/insights', label: '핵심인사이트', description: '…한 화면 탭으로…', icon: Sparkles },
```
→ **3개로 교체:**
```ts
{ href: '/admin/insights',       label: '인사이트 카드', description: 'AI 인사이트 카드 생성·검수·발행.', icon: Sparkles },
{ href: '/admin/issues',         label: '이슈 관리',     description: '이슈 생성·발행·키워드 매칭·콘텐츠 배정.', icon: <적절한 아이콘> },
{ href: '/admin/daily-insights', label: '일일 핵심',     description: '자동 게시된 일일 핵심 검토·편집·반려.', icon: <적절한 아이콘> },
```
- 아이콘은 기존 import 에서 적절한 것(예: 이슈 `Flame`/`TrendingUp`, 일일 `CalendarDays`/`Sun` 중 미사용). **새 import 추가는 최소로.**
- `키워드분석`·`관계지도`(준비중) 항목은 **그대로 둔다.**

### 2.2 `/admin/insights` → 인사이트 카드 전용
`src/app/admin/insights/page.tsx`:
```tsx
// InsightHub 제거 → InsightCardsManager 직접
import InsightCardsManager from '@/components/admin/InsightCardsManager'
import AdminPageHeader from '@/components/admin/ui/AdminPageHeader'
export default function AdminInsightsPage() {
  return (
    <div className="space-y-6">
      <AdminPageHeader />
      <InsightCardsManager />
    </div>
  )
}
```
- `metadata` 제목을 `인사이트 카드` 로.
- **`issues`·`daily-insights` page.tsx 는 무수정**(이미 완성). nav 에 노출되면서 바로 쓰인다.

### 2.3 `InsightHub.tsx` 삭제
- 더 이상 참조되지 않는다(전수 확인: `grep -rn InsightHub src/`). insights/page 만 쓰던 컴포넌트.
- `AdminTabShell` 은 다른 화면(탭 유지 5개)이 계속 쓰므로 **삭제하지 않는다.**

### 2.4 브레드크럼 확인
- `AdminPageHeader`/브레드크럼이 `findAdminNavLocation` 으로 nav 를 읽어 `인사이트 / 이슈 관리` 식으로 뜬다. nav 에 3개가 등록되면 자동. **별도 작업 없음**, 육안 확인만.

## 3. 하지 말 것
- `IssueManager`·`DailyInsightsManager`·`InsightCardsManager` **내부 무수정.** 배치만.
- `issues`·`daily-insights` **기존 page.tsx 무수정.**
- `AdminTabShell` **삭제·수정 금지**(5개 화면 공용).
- 다른 nav 그룹·라우트 무관.
- 경쟁사 주간(다음 지시서 410)은 이번에 안 건드린다.

## 4. 회귀 가드
1. 사이드바 `인사이트` 그룹에 **인사이트 카드 · 이슈 관리 · 일일 핵심** 3메뉴가 뜬다.
2. `/admin/insights` → **인사이트 카드**(탭 없음), `/admin/issues` → 이슈 관리, `/admin/daily-insights` → 일일 핵심.
3. 세 화면의 **기능이 각각 정상**(카드 생성·검수 / 이슈 생성·배정 / 일일 검토·반려).
4. 브레드크럼이 각 화면에서 `인사이트 / <메뉴>` 로 뜬다.
5. **L2 탭이 사라졌다**(핵심인사이트에 탭 바 없음).
6. `키워드분석`·`관계지도`(준비중)가 그대로 있다.
7. `AdminTabShell` 쓰는 5개 화면(뉴스레터·지식보고서·AI리포트·콘텐츠·콘텐츠추가)이 **영향 없다.**
