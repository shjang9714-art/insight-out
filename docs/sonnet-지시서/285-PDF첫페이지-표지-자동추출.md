# 지시서 285 — PDF 첫 페이지 표지 자동추출 (PDF 커버 슬라이스 A)

> 작성: Opus(플래너) · 2026-07-11 · 설계: `docs/설계-PDF표지-자동추출-커버소스-우선순위.md`
> 근거: David 요청 — "리서치 PDF 첫 페이지는 대개 보고서 표지이니, 업로드 시 1페이지를 커버로 쓰자."
> 협업 루프: 로컬(커밋X). 위임 → 구현 → 재현검증 → "커밋".
> **SQL 없음.** 독립 슬라이스(다른 레인과 충돌 없음).
> 후속: B(기존 PDF 재처리 백필) · C(수동 override UX) — 이번 범위 밖.

---

## 0. 한 줄

업로드된 PDF의 **1페이지를 이미지로 렌더해 콘텐츠 카드 커버(`contents.thumbnail_url`)로 자동 설정**한다. 수동 커버가 있으면 절대 덮지 않는다.

---

## 1. 현행 진단 (검증된 코드 사실)

### 1.1 업로드 → extract 흐름 (훅 지점)
- `POST /api/admin/upload`는 **서명 URL만 발급**하고 파일은 클라이언트가 스토리지에 직접 올린다 → **업로드 라우트에서는 PDF를 만질 수 없다.**
- `src/components/admin/ReportUploadForm.tsx`:
  - `:236` contents 행 insert → `:251` `contentId` 확보
  - `:292` (커버 파일을 골랐으면) `uploadCover()` → **`thumbnail_url` 선설정**
  - `:303` `POST /api/admin/contents/${contentId}/extract` **자동 호출**
- ⇒ **extract 라우트가 유일하고 올바른 훅 지점**이다. 그리고 수동 커버는 extract보다 **먼저** 설정되므로, `thumbnail_url IS NULL` 가드만 지키면 수동 커버를 자동으로 존중하게 된다.

### 1.2 extract 라우트 (`src/app/api/admin/contents/[id]/extract/route.ts`)
- `runtime='nodejs'`, `maxDuration=60`.
- `reports` 버킷에서 PDF 다운로드(service_role) → **`const buffer = new Uint8Array(await fileData.arrayBuffer())`** (이미 메모리에 있음 → 재다운로드 불필요).
- `extractPdfText(buffer)`(unpdf) → 텍스트 추출.
- ⚠️ **`isScannedPdf(bodyText)`이면 `{ ok:false, reason:'scanned' }`로 조기 return** 한다(텍스트가 200자 미만).
- 조회 컬럼: `id, title, file_path, original_language` (현재 `thumbnail_url`은 안 가져옴 → 추가 필요).

### 1.3 커버 체인·저장 규약
- 카드 커버 = **`contents.thumbnail_url`**. `src/lib/contents/topic-cover.ts`의
  `coverUrlFor(row) = row.thumbnail_url ?? pickTopicCover(...) ?? null` — **thumbnail_url 최우선**.
- 자동 커버 저장 규약(282, `src/lib/contents/cover-from-image.ts`): `report-covers/{contentId}.{ext}` 업로드(upsert) → `thumbnail_url` 갱신. **`thumbnail_url`이 null일 때만** 호출.
- 수동 커버(`src/lib/contents/upload-cover.ts`)도 같은 버킷·경로. 동일 경로 upsert라 **`?v=` 캐시버스터 필수**.

### 1.4 렌더 도구
- `unpdf`(설치됨, 텍스트 추출에 이미 사용). **`renderPageAsImage`를 제공한다** — 확인된 시그니처:
  ```ts
  renderPageAsImage(
    data: Uint8Array | ArrayBuffer,
    pageNumber: number,
    options?: {
      canvasImport?: () => Promise<typeof import('@napi-rs/canvas')>
      scale?: number      // 기본 1.0
      width?: number
      height?: number
      toDataURL?: false   // 생략/false → PNG ArrayBuffer 반환
    }
  ): Promise<ArrayBuffer>
  ```
- **`@napi-rs/canvas`는 미설치** → 추가 필요(unpdf가 canvasImport로 요구).
- **Next 16.2.6**, `next.config.ts`는 **비어 있음**.

## 3. 구현

### 3-1. 의존성 + Next 설정 (**빠뜨리면 배포에서 터짐**)
- `npm i @napi-rs/canvas` (prebuilt 네이티브 — Vercel Node 런타임 호환).
- `next.config.ts`에 **반드시** 추가:
  ```ts
  const nextConfig: NextConfig = {
    serverExternalPackages: ['@napi-rs/canvas'],
  }
  ```
  네이티브 `.node` 바이너리는 번들링하면 안 된다. 이 설정이 없으면 빌드는 통과해도 **런타임에 모듈 로드가 실패**할 수 있다.

### 3-2. 신규 `src/lib/contents/cover-from-pdf.ts`
```ts
coverFromPdfFirstPage(admin: SupabaseClient, contentId: string, pdf: Uint8Array): Promise<string | null>
```
- `renderPageAsImage(pdf, 1, { canvasImport: () => import('@napi-rs/canvas'), width: COVER_WIDTH })` → PNG `ArrayBuffer`.
  - `COVER_WIDTH = 1000` 권장(카드·상세에 충분하고 용량 과하지 않음). 종횡비는 unpdf가 유지.
- **JPEG로 재인코딩**해 용량을 줄인다(카드 그리드에 PNG 원본은 과함). `@napi-rs/canvas`의 `loadImage` + `createCanvas` + `toBuffer('image/jpeg', <quality>)` 사용. 품질 80 내외.
  - 재인코딩이 여의치 않으면 PNG 그대로 올려도 되지만, **파일 크기를 로그로 남길 것**.
- `report-covers/{contentId}.jpg`에 업로드(**upsert**, contentType 정확히) → public URL 획득 → `contents.thumbnail_url`을 **`?v=<타임스탬프>` 캐시버스터 붙여** 갱신.
- **graceful**: 렌더·인코딩·업로드·갱신 어느 단계든 실패하면 **throw 하지 말고 `null` 반환 + 로그**. (커버가 없으면 생성 풀·BrandedCover로 자연 폴백된다.)
- `import 'server-only'`.

### 3-3. extract 라우트 훅 (`src/app/api/admin/contents/[id]/extract/route.ts`)
1. content 조회 컬럼에 **`thumbnail_url` 추가**.
2. PDF 다운로드 후 **이미 메모리에 있는 `buffer`를 재사용**해 커버를 시도한다(재다운로드 금지).
3. ⚠️ **커버 시도는 `isScannedPdf` 조기 return보다 반드시 앞에 둘 것.**
   현재 스캔 PDF는 `reason:'scanned'`로 조기 return하는데, **스캔 PDF야말로 1페이지 이미지 커버가 가장 유효한 대상**이다(텍스트는 못 뽑아도 표지 그림은 멀쩡하다. 지금은 본문도 커버도 없는 상태). 커버 로직이 그 return 뒤에 있으면 이 이득을 통째로 잃는다.
4. 가드: **`thumbnail_url`이 이미 있으면 스킵**(수동 커버·기존 커버 보존).
5. **독립 try/catch**: 커버 실패가 본문 추출·번역·요약 흐름을 절대 깨뜨리지 않게 한다.
6. 응답에 `coverSet: boolean`(또는 `coverUrl`)을 포함해 어드민이 결과를 알 수 있게 한다.

> 텍스트 추출 성공/실패와 **무관하게** 커버는 시도된다 — 두 관심사는 독립이다.

## 4. 회귀 가드

- **수동 커버를 절대 덮지 않는다** — `thumbnail_url IS NULL`일 때만 설정. (`ReportUploadForm:292`가 extract보다 먼저 도므로 순서상으로도 안전하지만, 코드 가드도 반드시 둘 것.)
- **스캔 PDF에서도 커버가 설정되어야 한다**(조기 return 앞에 배치 — §3-3.3).
- 커버 실패는 **graceful** — 본문 처리·업로드 플로우 무중단. 예외 전파 금지.
- 비PDF(`file_path`가 .pdf 아님)·`file_path` 없음 → 조기 스킵(기존 분기 유지).
- 동일 경로 upsert이므로 **`?v=` 캐시버스터** 없이 갱신하면 브라우저가 옛 이미지를 계속 보여준다.
- `serverExternalPackages` 누락 시 런타임 모듈 로드 실패 — **빌드 통과했다고 안심하지 말 것**.
- 대용량/다페이지 PDF: **1페이지만** 렌더(전체 래스터화 금지). `maxDuration=60` 내에 끝나야 한다.
- 기존 `extractPdfText`·`isScannedPdf`·번역·요약·엔티티·이슈 로직은 **건드리지 말 것**.

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build`.
- **`npm run build` 후 실제로 `@napi-rs/canvas`가 로드되는지 확인**(빌드만으로는 부족 — 가능하면 로컬에서 PDF 하나로 렌더 1회 실행).

- **스캔 PDF 업로드 → 본문 추출은 실패(`reason:'scanned'`)해도 커버는 설정된다.** (이 케이스를 반드시 확인할 것 — 핵심 이득이다.)

- 생성된 커버 파일 크기 확인(과도하면 `COVER_WIDTH`·품질 조정).
