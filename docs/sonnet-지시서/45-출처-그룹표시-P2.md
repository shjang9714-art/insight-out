## 배경
출처 RSS가 잘게 쪼개져(`Google News - A/B…`, `AWS News Blog`, `AWS Architecture Blog`…) 필터에 ~50개가 깔림. SQL이 `group_name`(예: `Google News`, `AWS`, `Cloudflare`)을 채워놨으니, **필터를 그룹으로 접는다**. URL 쿼리는 **기존 `src`(소스 UUID 콤마 다중) 그대로** 유지 → `.in('source_id', srcIds)` 쿼리 무변경. UI만 그룹화.

## 파트 A — 소스 로드에 group_name 추가
- `contents/page.tsx`·`search/page.tsx` 의 소스 조회: `from('sources').select('id, name')` → **`select('id, name, group_name')`**.
- `SourceOption` 타입에 `group_name: string | null` 추가.
- #43 카테고리 스코프(`visibleSources`)는 그대로(id 기준 필터, group_name 만 함께 실림).

## 파트 B — SourcePopover 그룹화
- props 타입: `sources: { id: string; name: string; group_name?: string | null }[]`.
- **그룹 구성**: `label = group_name ?? name` 기준으로 묶어 `{ label, ids: string[], count }[]` 생성(라벨 정렬). 같은 라벨의 소스 id 들을 멤버로.
- **검색 input**: 라벨 대상 필터(기존 name 필터 → label 필터).
- **각 행 = 그룹**: 체크 상태 = 그룹 멤버 ids 가 **모두 `value` 에 포함**되면 checked(전체 토글 방식이라 all-or-nothing). 라벨 옆 멤버 수 표기(예: `Google News (12)`).
- **토글**: 체크 시 → 멤버 ids 전부 `value` 에서 제거 / 해제 시 → 멤버 ids 전부 추가(dedupe, `[...new Set(...)]`).
- 버튼 배지 수 = **선택된 그룹 수**(원시 id 수 아님). "전체 해제" = `onChange([])` 유지.
- `onChange` 는 여전히 **소스 id 배열** 방출 → `src` 규약 불변.

## 파트 C — 활성 칩 그룹화 (contents·search)
- 현재 활성칩은 srcId 별 개별 출처명. → **선택된 그룹 단위 칩**으로 변경.
- `value(srcIds)` + 그룹맵에서 "멤버가 모두 선택된 그룹"을 도출해 **그룹 라벨 칩** 렌더. X = 해당 그룹 멤버 ids 전부 해제.
- 그룹화 헬퍼는 중복 방지를 위해 **공용 함수로 추출 권장**(예: `SourcePopover` 에서 `export function groupSources(sources)` / `selectedGroups(value, sources)`), contents·search·팝오버가 공유. 과하면 각 페이지 inline(보고에 택일 명시).
- 부분선택(멤버 일부만 value) 상황은 전체 토글만 쓰면 발생 안 함 — 단, 카테고리 스코프 변경으로 멤버 일부가 사라질 수 있으니 칩 도출은 "현재 visibleSources 기준 그룹의 멤버 ⊆ value" 로 안전하게.

## 회귀
- `src` `.in('source_id', …)` 쿼리·#43 카테고리 스코프·#42 팝오버 검색/ESC/바깥클릭·다크모드 정합. group_name 없는 소스(미백필/신규)는 자기 이름이 그룹(단일 멤버)로 정상 표시.
