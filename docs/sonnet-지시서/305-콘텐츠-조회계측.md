## 1. 현행 진단 (검증된 코드 사실)

### 1.1 API는 이미 완성돼 있다 — `src/app/api/content_views/route.ts`
```
POST  { content_id, dwell_seconds? }  → content_views insert → { id } 반환
PATCH { id, dwell_seconds }           → 해당 행의 dwell_seconds 갱신 (user_id 일치 확인)
```
- 인증 확인·유효성 검사·에러 로깅 전부 있다.
- **`content_views`를 참조하는 코드는 이 라우트 파일 하나뿐이다.** (`grep -rn "content_views" src/` → 4건 모두 이 파일)
- → **호출자가 0이다. 데이터가 0건인 이유는 버그가 아니라 호출부 부재다.**

### 1.2 계측 대상
`src/app/dashboard/contents/[id]/page.tsx` — **서버 컴포넌트**다(`'use client'` 없음).
→ 계측은 **작은 클라이언트 컴포넌트**를 하나 만들어 이 페이지에 끼운다.

여기에 뉴스·리서치(PDF)·유튜브가 **전부 들어온다.** 이 한 페이지면 콘텐츠 조회의 대부분을 덮는다.

### 1.3 ⚠️ 범위에서 **제외**할 것 — FK 때문이다
- `/dashboard/reports/[id]` (전략보고서) → **다른 테이블**(`ai_report_sources` 계열)이다.
- `/dashboard/entities/competitor-weekly/[week]` (경쟁사 주간) → 역시 별개다.
- `content_views.content_id`는 **`contents`를 가리킨다.** 여기에 report id를 넣으면 **FK 위반**이다.
- → **이번 범위는 `/dashboard/contents/[id]` 하나.** 리포트·주간 조회수는 별도(백로그). **억지로 끼워 넣지 말 것.**

## 3. 구현

### 3-1. `src/components/contents/ViewTracker.tsx` (신규, `'use client'`)

```tsx
export default function ViewTracker({ contentId }: { contentId: string }) 
```
렌더 결과 **없음**(`return null`). 부수효과만 있는 컴포넌트다.

**동작**
1. **마운트 시 1회** `POST /api/content_views` → 응답의 `id`를 ref에 보관.
2. 체류 시간 측정 — **탭이 숨겨진 동안은 세지 말 것**(`visibilitychange`). 실제로 본 시간이어야 의미가 있다.
3. **이탈 시** `PATCH /api/content_views` 로 `dwell_seconds` 전송.

### 3-2. ⭐ 반드시 지킬 3가지 (여기서 사고가 난다)

**① 중복 POST 금지 — `useRef` 가드**
React StrictMode(dev)는 effect를 **두 번** 실행한다. 가드가 없으면 조회 1회에 행이 2개 생긴다.
- `const startedRef = useRef(false)` 로 **첫 실행만** 통과시킨다.
- `contentId`가 바뀌면 리셋(라우터가 컴포넌트를 재사용할 수 있다).

**② 이탈 전송은 `fetch(..., { keepalive: true })`**
- `beforeunload`에서 그냥 `fetch`하면 **요청이 취소된다.**
- **`navigator.sendBeacon`을 쓰지 말 것** — sendBeacon은 **POST만** 보낸다. 우리 갱신은 **PATCH**다.
- → **`fetch(url, { method: 'PATCH', keepalive: true, ... })`** 를 쓴다. 언로드에도 살아남고 PATCH도 된다.
- 전송 시점: **`pagehide`** + **`visibilitychange`(hidden)** 둘 다. (모바일 Safari는 `beforeunload`가 안 온다.)
- 언마운트(SPA 내 이동) 시에도 전송.
- **중복 전송 가드**: 이미 보냈으면 다시 보내지 않는다(`sentRef`).

**③ 계측이 페이지를 깨뜨리면 안 된다**
- 모든 호출을 `try/catch` + `.catch()`로 감싼다. **절대 throw하지 않는다.**
- 다만 **조용히 삼키지도 말 것** — 실패 시 `console.error('[content_views] …', err)`. (289·291·293과 같은 이유다. 이 코드베이스의 반복된 실패 원인은 "조용한 실패"다.)

### 3-3. 페이지에 끼우기
`src/app/dashboard/contents/[id]/page.tsx` 렌더 트리 안에 `<ViewTracker contentId={content.id} />` 한 줄.
- **다른 것은 아무것도 바꾸지 말 것.** 이 슬라이스는 호출부 추가가 전부다.

### 3-4. 즉시 POST 한다 (지연 없음)
"3초 이상 머문 경우만 기록" 같은 지연을 **넣지 말 것.**
- *몇 명이 열었나* 를 알려면 진입 즉시 기록해야 한다.
- 스쳐 지나간 조회는 나중에 **`dwell_seconds`로 걸러내면 된다.** 기록을 안 하면 걸러낼 것도 없다.

## 4. 회귀 가드

- **`/dashboard/reports/[id]`·경쟁사 주간에 붙이지 말 것** — FK 위반이다(§1.3).
- **`sendBeacon` 금지** — POST만 되고 PATCH가 안 된다.
- **StrictMode 이중 마운트로 행이 2개 생기면 안 된다** — `useRef` 가드 필수.
- **계측 실패가 페이지 렌더를 깨면 안 된다.** 동시에 **조용히 삼키지도 말 것**(console.error).
- API 라우트(`route.ts`)를 **수정하지 말 것.** 이미 완성돼 있다.
- 상세 페이지의 기존 동작(요약·본문·북마크·관련 콘텐츠) **불변**.

## 5. 검증 (Sonnet)

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build`.
- 콘텐츠 상세 1건을 열고 **DevTools Network에서 `POST /api/content_views`가 정확히 1회**(2회 아님) 나가는지.
- 뒤로 가기·탭 닫기·다른 콘텐츠로 이동 시 **`PATCH`가 나가는지**. `dwell_seconds`가 **0이 아닌 실제 값**인지.
- 탭을 다른 창으로 가린 동안의 시간이 **dwell에 포함되지 않는지**.
- 로그인 안 된 상태에서 401이 나도 **페이지가 정상 렌더되는지**.
- 커밋: `feat: 콘텐츠 조회 계측 — content_views 호출부 추가 (지시서 305)`
