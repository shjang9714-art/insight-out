## 0. 한 줄

공개 홈(`/dashboard`)의 **6개 섹션 노출 여부·순서**를 어드민이 `/admin/settings` 하단 "공개 홈 구성"에서 토글/재정렬하고, `homepage_sections` 테이블에 저장한다. 홈 페이지는 이 설정을 서버에서 읽어 렌더(미적용 시 현행 하드코딩 순서로 graceful).

## 1. 현행 진단 (검증된 코드 사실)

- **공개 홈 = `src/app/dashboard/page.tsx`**(서버 컴포넌트, 동적 렌더 — `dynamic`/`revalidate` 선언 없음 = 요청마다 재조회). 하드코딩 JSX 순서:
  1. `PersonalizationNudge` (`src/components/dashboard/PersonalizationNudge.tsx`) — 온보딩 미완 배너
  2. `VisitDelta` (`.../VisitDelta.tsx`) — 지난 방문 이후 신규 수 배지
  3. `SuggestedQuestions` (`src/components/search/SuggestedQuestions.tsx`) — 추천 질문 칩(client)
  4. `IssueSignals` (`.../IssueSignals.tsx`) — 트렌딩 이슈 티커
  5. `TodayBriefingHighlights` (`.../TodayBriefingHighlights.tsx`) — 오늘의 핵심 인사이트 3
  6. `FeedSlot` (`src/components/feed/FeedSlot.tsx`) — 맞춤 피드 캐러셀
- **각 섹션은 자체 데이터 페칭**(Suspense 래핑, 페이지가 props 안 내림). → 순서/노출만 바꾸면 되고 데이터 흐름은 안 건드림.
- **홈 구성 설정 메커니즘 전무**(home_layout/site_settings 등 없음). 전부 JSX 하드코딩.
- **설정 저장 패턴 참고**: `llm_settings`(provider PK + RLS `is_admin()`), API `src/app/api/admin/llm/route.ts`(GET+PATCH, `verifyAdmin` → `createAdminClient` → upsert onConflict). 202도 동형.

## 2. SQL 핸드오프 (수희, 먼저 푸시)

- 파일: `docs/sql-handoff/202-homepage-sections.sql`(작성됨). `homepage_sections(section_key PK, enabled, sort_order, updated_at)` + `set_updated_at` 트리거 + RLS(읽기 전체 허용·쓰기 어드민) + anon/authenticated select grant + **현행 6섹션 시드**.
- 읽기 전체 허용 이유: 공개 홈이 방문자 세션으로 레이아웃을 읽어야 함(비민감 데이터). 쓰기만 어드민.
- 코드는 SQL 선적용 불필요(42P01 → 기본 레이아웃). **적용되면 어드민 토글이 실제 홈에 반영 시작.**

## 3. 구현

### 3-1. 섹션 레지스트리 — 코드 상수(신규 `src/lib/home/sections.ts`)

- `HOME_SECTION_REGISTRY`: 배열 of `{ key, label, description }` — 위 6개를 사람이 읽을 라벨과 함께 **코드가 진실의 원천**(DB 는 enabled·order 만). 예:
  - `personalization_nudge` — "맞춤 설정 유도 배너", "온보딩 미완 사용자 안내"
  - `visit_delta` — "새 소식 배지", "지난 방문 이후 신규 콘텐츠·이슈 수"
  - `suggested_questions` — "추천 질문", "트렌딩 기반 검색 진입점"
  - `issue_signals` — "트렌딩 이슈 티커"
  - `briefing_highlights` — "오늘의 핵심 인사이트"
  - `feed_slot` — "맞춤 피드"
- 이유: DB에 없는/이름 바뀐 섹션 graceful, 어드민 UI 라벨 소스, 홈 렌더 매핑 소스(단일 관리).

### 3-2. 설정 읽기 헬퍼 — `src/lib/home/layout.ts`(신규, 서버)

- `getHomeSectionLayout(): Promise<{ key: string; enabled: boolean }[]>`:
  - `createServerClient`(또는 공개 읽기이므로 익명 서버 클라이언트)로 `homepage_sections` select(order by sort_order).
  - **graceful**: 에러(42P01 포함)·빈 결과 → `HOME_SECTION_REGISTRY` 기본 순서 전부 enabled 반환.
  - DB에 있는 key 중 **레지스트리에 있는 것만** 사용(모르는 key 무시), **레지스트리에 있는데 DB에 없는 신규 섹션은 맨 뒤 enabled** 로 append(신규 섹션 추가 시 자동 노출 — 누락 방지).
  - 캐시: 페이지가 동적이라 매 요청 조회 OK. (원하면 `unstable_cache`/React cache 로 요청 내 1회.)

### 3-3. 홈 페이지 리팩터 — `dashboard/page.tsx`

- 상단에서 `const layout = await getHomeSectionLayout()`.
- **key → 컴포넌트 렌더러 맵**: `{ personalization_nudge: () => <PersonalizationNudge/>, … }` (각 섹션의 기존 Suspense·props 그대로 이 맵 안에 캡슐화).
- `layout.filter(s => s.enabled).map(s => renderer[s.key]?.())` 로 순서대로 렌더. 매퍼 없는 key skip.
- **회귀 0 조건**: SQL 미적용/기본 시드면 6섹션 전부·현행 순서 → 지금과 동일 출력. 각 컴포넌트 내부·데이터 페칭 무변경.

### 3-4. API — `src/app/api/admin/homepage/route.ts`(신규)

- `GET`: `verifyAdmin` → `createAdminClient` → `homepage_sections` 전체 select. **레지스트리와 병합**해 반환(`{ key, label, description, enabled, sort_order }[]`, DB에 없는 레지스트리 항목은 기본값으로 채움). graceful(테이블 없으면 레지스트리 기본).
- `PUT`(또는 POST): `verifyAdmin` → body `{ sections: { key, enabled, sort_order }[] }` 검증(레지스트리 key 만 허용) → `upsert(onConflict: section_key)` 일괄. 반환 `{ ok: true }`. 에러 graceful 500(한국어 메시지).

### 3-5. 어드민 UI — `/admin/settings` 하단 "공개 홈 구성" 섹션

- 201이 만든 `settings/page.tsx` 에 섹션 추가(`AdminSectionHeader` "공개 홈 구성" + 설명 "방문자에게 보이는 홈 화면의 항목과 순서를 정합니다. 모든 방문자에게 적용됩니다.").
- `HomeSectionsSettings.tsx`(`'use client'`):
  - 마운트 시 `GET /api/admin/homepage` → 목록 state.
  - 각 행: 라벨·설명 + **노출 토글**(스위치/체크) + **위/아래 이동 버튼**(드래그 불필요 — 의존성 0, 접근성·단순). 순서는 배열 인덱스 → 저장 시 sort_order 재부여(10·20…).
  - "저장" 버튼 → `PUT` 일괄. 저장 중 로딩·성공/실패 메시지(한국어). (자동저장 대신 명시 저장 — 실수 방지.)
  - **미리보기 링크**: "공개 홈 보기"(`/dashboard` 새 탭)로 결과 확인 유도.
  - 안내: "최소 1개 이상 노출 권장" — 전부 끄면 홈이 비므로 **최소 1개 강제**(전부 off 저장 차단, 경고).
- 비전문 사용자 배려(memory): 전문용어 지양, 각 섹션 설명을 사람 말로.

## 4. 회귀 가드 / 비기능 요건

- **SQL 선적용 불필요**: 42P01·빈 결과 → 현행 6섹션·순서 그대로(graceful). 배포해도 홈 안 바뀜, 수희 적용+어드민 저장 후에만 반영.
- **데이터 흐름 무변경**: 각 섹션 컴포넌트·쿼리·Suspense 그대로. 순서/노출만 제어.
- 신규 섹션을 코드에 추가하면 레지스트리에 넣는 한 자동으로 맨 뒤 노출(누락 방지). DB에만 있고 코드에 없는 key 는 무시(안전).
- 서비스롤 키는 API(서버)에서만(Rule 8). 홈 읽기는 공개 select 정책(비민감).
- 어드민 UI 는 `.admin-scope` 유지(197 토큰, 신규 hex 0). 사용자 홈은 기존 스타일 그대로.
- SQL 스키마 변경은 `supabase/schema.sql` **와** 필요 시 `src/lib/types.ts` **양쪽 반영**(AGENTS §8). 신규 npm 의존 0.
