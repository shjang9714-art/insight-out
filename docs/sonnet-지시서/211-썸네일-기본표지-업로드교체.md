## 0. 한 줄

썸네일 없는 카드를 **제목·카테고리·발행처가 들어간 브랜드 커버**로 렌더(저장 0, 전 코퍼스 즉시)하고, 어드민 **편집 모달에서 썸네일 이미지를 올려/교체·제거**할 수 있게 한다.

## 1. 현행 진단 (검증된 코드 사실)

- `contents.thumbnail_url` 컬럼 존재. 크롤 뉴스=`extractThumbnail`(og:image), 유튜브=ytimg, PDF 보고서=`pdf-cover.ts`가 채움. **없는 것**=붙여넣기/URL 임포트·비PDF 보고서·og 추출 실패분.
- `ContentCard.tsx`: 썸네일 있으면 이미지 카드, **없으면 컴팩트 텍스트 행**(:114~149, 이미지 영역 없음). 이미지 슬롯 폴백은 `Thumbnail`(:66~96)의 카테고리 그라디언트+라벨뿐. 카테고리별 그라디언트 맵 `CATEGORY_FALLBACK_BG`(:20~31)·색맵 `CATEGORY_COLOR`(:6~17) 존재.
- 커버 업로드 흐름(재사용): `POST /api/admin/upload { filename, kind:'cover', contentId }` → `{ storagePath, token }` → `supabase.storage.from('report-covers').uploadToSignedUrl(storagePath, token, blob)` → `getPublicUrl` → `thumbnail_url` 갱신. (`ReportUploadForm.tsx` :298~317가 PDF 커버로 사용 중. `report-covers`=공개 버킷, `{contentId}.{ext}`, upsert:true.)
- 편집 모달: `AdminContentManager.tsx` `EditState`(:170, title·summary·category·sourceId·author·publishedAt·bodyOriginal·id), `openEdit`(:~332 select), `handleEditSave`(:358 supabase update), Dialog(:927 `max-w-lg`).

## 2. 구현

### 2-A. 기본 표지 — 표시 시점 브랜드 커버(`ContentCard.tsx`, 저장 없음)
- **썸네일 없는 카드도 커버 카드 레이아웃**으로 통일(컴팩트 텍스트 행 → 커버+본문). 이미지 슬롯에 `<img>` 대신 **BrandedCover** 렌더:
  - 배경: `CATEGORY_FALLBACK_BG[category]` 그라디언트(기존 재사용).
  - 내용: **제목**(2~3줄 line-clamp, 굵게, 그라디언트 위 대비 확보한 색=foreground/브랜드 톤) + 카테고리 라벨 칩 + 발행처(sourceName) 작게. 브랜드 느낌의 커버(사진 아님이 자연스럽게 구분).
  - 접근성: `role="img"` + aria-label(제목). 다크에서도 대비 OK(그라디언트 다크 변형 이미 있음).
- `Thumbnail`(:66~96)을 확장: `url` 있으면 기존 `<img>`, 없으면 `BrandedCover`(제목·카테고리·발행처 전달). 카드 상단 이미지 영역(고정 비율)에 채움.
- 컴팩트 전용 분기(:114~149)는 커버 카드로 대체(또는 커버를 얹어 유지) — **모든 카드가 표지를 갖게**. `resolvedHref`·hover·keywords 등 기존 동작 보존.
- **주의(공개 피드 변화)**: 썸네일 없던 항목이 컴팩트 행 → 커버 카드로 바뀜(의도된 개선). ContentCard 단일 변경이라 사용처(FeedSlot·RecommendedFeed 등) 자동 반영.

### 2-B. 편집 모달 썸네일 업로드/교체·제거(`AdminContentManager.tsx`)
- `EditState`에 `thumbnailUrl: string | null` 추가. `openEdit`의 select에 `thumbnail_url` 포함 → 세팅.
- 편집 모달(Dialog :927) 필드에 "썸네일" 섹션 추가:
  - 현재 썸네일 미리보기(있으면 `<img>` 썸네일, 없으면 "기본 표지 사용 중" 안내).
  - **이미지 선택** input(`accept="image/*"`, ~2MB·형식 클라 검증) → 업로드:
    1. `POST /api/admin/upload { filename: \`cover.${ext}\`, kind:'cover', contentId: edit.id }` → `{ storagePath, token }`.
    2. `supabase.storage.from('report-covers').uploadToSignedUrl(storagePath, token, file)`.
    3. `getPublicUrl(storagePath)` → `setEdit(e=>({...e, thumbnailUrl: publicUrl}))`. 업로드 중 스피너·오류 한국어.
  - **제거** 버튼 → `setEdit(e=>({...e, thumbnailUrl: null}))`(기본 표지로 복귀). (버킷 파일 삭제는 선택; 미삭제 무해.)
- `handleEditSave`(:358) update에 `thumbnail_url: edit.thumbnailUrl` 포함. 성공 시 로컬 `contents` 행의 `thumbnail_url`도 갱신(카드 즉시 반영 — 현재 setContents 병합에 thumbnail 추가).
- **캐시 무효화**: 같은 경로 upsert라 URL 동일 → 교체 후 브라우저 캐시로 옛 이미지 보일 수 있음. `getPublicUrl` 결과에 `?v=${Date.now()}` 쿼리 덧붙여 강제 새로고침.

## 3. 회귀 가드 / 비기능 요건
- **SQL·신규 npm 없음**. thumbnail_url 기존 컬럼, 업로드 라우트·버킷·서명URL 재사용.
- 2-A는 ContentCard 표시 로직만(데이터 불변). 썸네일 있는 카드는 기존과 동일. 다크·라이트 대비 확보.
- 2-B 업로드 실패·큰 파일·비이미지 graceful(검증+오류 메시지). 제거는 thumbnail_url=null(기본 표지).
- 203/204 토큰·209 탭 유지, 생 red-* 지양. 어드민 게이트(upload 라우트 기존). 공개 화면은 2-A 커버만 변화(의도).
