---

## 배경 / 목표
게이트·태그·키워드검색이 곧 켜지므로, **게이트 이전에 쌓인 저품질·무태그 기사를 한 번 비워** 깨끗한 기준점을 만든다. David 결정: **크롤링 기사만 삭제, 업로드 리포트는 보존.**

- 크롤링 기사 = `contents.original_url IS NOT NULL` (RSS/검색 수집물). 업로드 리포트는 `file_path` 있고 `original_url` 없음 → **보존**.
- AI보고서(`ai_reports`)·유튜브(`youtube_videos`)는 별도 테이블 → 영향 없음.
- `contents` 의 모든 FK 가 `on delete cascade`(content_keywords·content_services·bookmarks·archive_items·ai_report_sources) → 삭제 시 연관행 자동 정리. cluster_id 자기참조는 `on delete set null`.

## 작업

### 1. 어드민 라우트 `src/app/api/admin/contents/purge/route.ts`
- `verifyAdmin()`(crawl-now 패턴 복제 또는 공통 헬퍼) + `createAdminClient()`(service_role, RLS 우회·cascade).
- `runtime='nodejs'`, `dynamic='force-dynamic'`.
- **GET** (미리보기 건수): 크롤링 기사 수 반환.
  ```ts
  const { count } = await admin.from('contents')
    .select('id', { count: 'exact', head: true })
    .not('original_url', 'is', null)
  return NextResponse.json({ count: count ?? 0 })
  ```
- **POST** (삭제 실행):
  ```ts
  const { error, count } = await admin.from('contents')
    .delete({ count: 'exact' })
    .not('original_url', 'is', null)
  if (error) throw error
  return NextResponse.json({ deleted: count ?? 0 })
  ```
  - 연관행은 FK cascade 로 자동 삭제.
  - ⚠️ **bookmark_count 트리거 주의**: bookmarks 가 cascade 삭제될 때 `contents.bookmark_count` 갱신 트리거가 있으면, 같은 삭제 대상 content 를 업데이트하려다 churn/에러 가능. 구현 후 **로컬/실데이터로 실제 대량 삭제가 에러 없이 되는지 확인**. 에러 나면: 대상 content_id 의 bookmarks·archive_items 를 먼저 명시 삭제 후 contents 삭제(2단계)로 폴백.
  - 대량일 경우 타임아웃 대비(`maxDuration` 상향 or 배치). 우선 단일 delete 로 구현하고 느리면 배치.

### 2. 어드민 UI — "수집 기사 비우기" 버튼
- 위치: `AdminContentManager` 상단(또는 소스 관리). **위험 액션이므로 눈에 띄되 분리**(예: 우측 끝, outline+빨강 텍스트).
- 클릭 흐름(2단계 확인):
  1. GET 으로 건수 조회 → 확인 다이얼로그: **"크롤링 기사 N건을 삭제합니다. 업로드한 리포트·AI보고서·유튜브는 보존됩니다. 되돌릴 수 없습니다."**
  2. 확인 시 POST → 성공 시 토스트/배너 "N건 삭제 완료" + 목록·pending 카운트 새로고침.
- 처리 중 로딩·중복 클릭 방지.

## 회귀 / 주의
- **업로드 리포트 보존 확인**: `original_url IS NULL`(file_path 보유) 행은 삭제 안 됨. 삭제 후 리포트 카테고리 콘텐츠가 그대로인지 육안.
- 스키마/RLS/enum 무변경.
- service_role 라우트이므로 **반드시 admin 인증 가드**(비admin 403). 키 노출 없음(서버 전용).
- 삭제는 되돌릴 수 없음 — 2단계 확인 필수.
- crawl_logs 는 삭제 대상 아님(수집 이력 보존). cluster_id 잔존 참조는 set null 로 안전.
