## 배경

경쟁사 논조의 긍정/부정 배지가 직관적이지 않은 근본 이유 = **사건이 의미를 만드는데 감정 점수만 보여줘서.** 해법 = **기업별 굵직한 사건 내러티브 타임라인**(예: AI 조직 신설 → MS 협업 → 해킹사고 → CEO 사퇴). 자사·경쟁사 모두 = 그냥 각각의 엔티티이므로 **모든 엔티티 상세에 동일 적용.**

**데이터 토대 이미 존재**: `content_entities`(엔티티↔콘텐츠) + `content_signals.signal_type`(8종=사실상 이벤트 분류: 경쟁사동향/규제·정부/신제품·출시/투자·M&A/기술트렌드/시장지표/파트너십/인사·조직) + `contents`(published_at·sentiment·title·summary_ko). **새로 만들 것 = "여러 신호·기사 → 사건 한 줄"로 묶는 LLM 집계 레이어 + 저장 + 타임라인 UI.**

**재무 트랙(매출·영업이익·재무제표)은 데이터가 전무 → v2(신규 소싱).** 본 지시서 범위 밖.

## A. SQL 핸드오프 — `docs/sql-handoff/134-entity-events.sql` (신규)
```sql
-- 134: 기업 사건 타임라인 캐시. 멱등(재생성 시 entity 단위 delete→insert).
create table if not exists public.entity_events (
  id                 uuid primary key default gen_random_uuid(),
  entity_id          uuid not null references public.entities(id) on delete cascade,
  event_date         date not null,
  signal_type        text,                         -- content_signals enum 중 하나(없으면 null)
  headline           text not null,                -- "사건 한 줄"
  detail             text,                          -- 1~2문장(선택)
  sentiment          text check (sentiment in ('긍정','중립','부정')),
  source_content_ids uuid[] not null default '{}',
  citations          jsonb not null default '[]',
  model              text,
  generated_at       timestamptz not null default now(),
  created_at         timestamptz not null default now()
);
create index if not exists entity_events_entity_date_idx
  on public.entity_events (entity_id, event_date desc);

alter table public.entity_events enable row level security;
drop policy if exists "entity_events: 인증 조회" on public.entity_events;
create policy "entity_events: 인증 조회" on public.entity_events
  for select to authenticated using (true);
drop policy if exists "entity_events: admin 관리" on public.entity_events;
create policy "entity_events: admin 관리" on public.entity_events
  for all to authenticated
  using (exists (select 1 from public.users u where u.id = auth.uid() and u.role = 'admin'))
  with check (exists (select 1 from public.users u where u.id = auth.uid() and u.role = 'admin'));
```
- (구현 시 `users.role` 컬럼·기존 admin RLS 패턴에 맞춰 조정.)

## B. LLM 생성 — `src/lib/entities/generate-events.ts` (신규)
`issues/brief.ts` 패턴 미러.
```ts
export interface EntityEvent {
  event_date: string      // YYYY-MM-DD
  signal_type: string | null
  headline: string        // 사건 한 줄
  detail: string | null
  sentiment: '긍정'|'중립'|'부정' | null
  citations: string[]     // content_id (검증 통과분)
}
export async function generateEntityEvents(admin, entityId, opts?: { days?: number }): Promise<EntityEvent[]>
```
- 입력 수집: entity → `content_entities` → `contents`(status=published, 최근 `days`=기본 120, 상위 ~80건 published_at desc) + `content_signals`(signal_type). 각 항목 `{content_id, title, summary_ko, published_at, signal_type, sentiment}`만(본문 미전송).
- 프롬프트: "이 기업의 **굵직한 사건만** 시간순으로 추려라(잡다한 일상 기사 제외). 각 사건 = {날짜, 신호유형, 한 줄 제목, 1문장 설명, 논조, 근거 content_id}. 제공된 사실만, 추측 금지. JSON으로만." 스키마·신호유형 enum 명시. 최대 ~15개.
- 호출: `llmComplete('report', prompt)` → `looseJsonParse`.
- **환각 가드**: citations의 content_id가 입력 집합에 존재해야 함(미존재 제거). signal_type이 enum 밖이면 null. headline 빈 사건 제거. event_date 파싱 실패 제거.
- 키 없음/실패 → `[]`(throw 금지).

## C. API — `POST /api/admin/entities/[id]/events` (신규)
- 어드민 게이트(기존 verifyAdmin), `runtime nodejs`, `maxDuration 60`.
- `generateEntityEvents(admin, id)` → **재생성 멱등**: `delete from entity_events where entity_id=id` → 결과 batch insert. → `{ count }` 반환. 키 없음/실패 503 + 사유.

## D. UI — `src/components/entities/EntityEventTimeline.tsx` (신규) + 상세 통합
- props: `events: EntityEvent[]`(서버가 entity_events 조회해 주입).
- **세로 내러티브 타임라인**(최신 → 과거, 연결선): 각 노드 = `event_date` · **signal_type 배지**(유형별 색, 기존 신호 톤 재사용·하드코딩 hex 금지) · **headline(굵게)** · detail · **논조 점/라벨** · 근거 링크(citations → `/dashboard/contents/{id}`).
- **엔티티 상세 페이지**(`entities/[id]/page.tsx`): `entity_events` 조회(없으면 42703 graceful → 섹션 숨김). 기존 "콘텐츠 타임라인" 위/대신 **"사건 타임라인"** 섹션 배치. 비었으면 "사건 타임라인 미생성"(관리자 안내) 폴백.
- **관리자 트리거 버튼**: 상세 페이지에서 **뷰어가 admin일 때만** "사건 타임라인 생성/갱신" 버튼(→ C API, 스피너·완료 후 새로고침). (별도 어드민 페이지 신설 회피.)

## E. (보너스·저비용) 논조 추세 차트 재사용
- 엔티티 상세에 `IssueSentimentTrend` 재사용: 엔티티 콘텐츠의 일자별 긍/중/부 집계(이미 sentiment 가짐) → 추세 차트 + 개선/악화 라벨. 사건 타임라인과 함께 논조 직관성 보강.

## F. v2 (짓지 않음)
- **재무 트랙**(매출·영업이익·재무제표) = 신규 소싱(DART 공시 등) 후 병렬 트랙.
