# 지시서 291 — PDF 표지: 백지 감지 + 실패 가시화 + 수동 보정 경로

> 작성: Opus(플래너) · 2026-07-11 · 근거: David —
> *"스캔 PDF에서 첫 페이지를 못 가져오는 것 같다. 못 가져오면 사용자가 넣어야 할 것 같은데 방법을 찾자. PDF는 가능하면 리포트의 표지를 써야 하고, 생성된 커버는 정말 표지가 없을 때만 써야 한다."*
> 협업 루프: 로컬(커밋X). 위임 → 구현 → 재현검증 → "커밋".
> 전제: 285(신규 업로드 자동)·286(백필) 배포됨. **SQL 없음.**

---

## 0. 한 줄

PDF 표지 추출이 **실패했는지·왜 실패했는지 관리자가 알 수 있게** 하고, **실패하면 사람이 직접 표지를 넣을 수 있는 경로**를 만든다. 그리고 **백지로 렌더된 커버를 커버로 착각하지 않게** 막는다.

---

## 1. 현행 진단 (검증된 코드 사실)

### 1.1 커버 우선순위 자체는 이미 옳다
`coverUrlFor(row) = row.thumbnail_url ?? pickTopicCover(...) ?? null`
→ **수동 커버 > PDF 1페이지 > og:image > 생성 풀 > BrandedCover**.
자동 경로는 전부 `thumbnail_url IS NULL`일 때만 동작하므로 수동 커버를 덮지 않는다.
**구조는 David 요구사항과 일치한다. 문제는 "실패했을 때 사람이 개입할 길이 없는 것"이다.**

### 1.2 실패가 관리자에게 안 보인다 (핵심)
- `extract` 라우트는 응답에 **`coverSet`을 넣고 있다**(`:107`, `:129`, `:264`).
- 그런데 **`ReportUploadForm`은 `coverSet`을 화면에 쓰지 않는다**(grep 0건). 본문 추출 결과(글자 수·번역·요약·엔티티·이슈)만 보여준다.
- 실패 **사유**는 `console.error`로 **Vercel 로그에만** 남는다(`cover-from-pdf.ts:40,53,59`).
→ 관리자는 표지가 붙었는지, 왜 안 붙었는지 **알 방법이 없다.**

### 1.3 백지 렌더 위험 (실패보다 나쁜 케이스)
- 스캔 PDF의 본문은 **JBIG2·CCITT 등 팩스 압축 이미지**인 경우가 많다. `unpdf`가 쓰는 서버리스 pdf.js 빌드는 이 디코더가 없을 수 있다.
- 그러면 `renderPageAsImage`가 **예외를 던지지 않고 백지(흰 화면)를 반환**할 수 있다.
- 현재 코드는 `coverUrl !== null`만 보므로 **성공으로 판정**하고 **흰색 이미지를 `thumbnail_url`에 저장**한다.
- 게다가 286 백필은 **성공·실패 무관하게 마커를 찍으므로**, 이 백지 커버는 재시도 대상에서도 빠진다.
→ **"성공했다고 믿고 백지를 붙인" 상태**가 될 수 있다. 반드시 막아야 한다.

### 1.4 수동 보정 경로가 사실상 없다
- 커버 교체 UI는 **콘텐츠 검수의 편집 모달 안**에만 있다(`AdminContentManager.tsx:451`, `uploadCoverFile`). 발견하기 어렵다.
- **"1페이지 다시 가져오기" 버튼이 없다.**
- **커버 없는 PDF만 모아 보는 방법이 없다** — 어떤 리포트에 표지가 빠졌는지 알 수 없다.

### 1.5 현재 렌더 설정
- `cover-from-pdf.ts`: `COVER_WIDTH = 1000`, `JPEG_QUALITY = 80`, 반환 `Promise<string | null>`(전 경로 graceful null).
- `extract` 라우트: `maxDuration = 60`.

## 3. 구현

### 3-1. 백지 감지 (`cover-from-pdf.ts`) — **가장 중요**

렌더 직후, 업로드 **전에** 이미지가 사실상 백지인지 검사한다.

```ts
/** 픽셀을 격자로 샘플링해 거의 균일한 색이면 백지로 본다(스캔 PDF 디코더 미지원 시 흰 화면이 나온다). */
function isBlankImage(canvas: Canvas): boolean {
  const ctx = canvas.getContext('2d')
  const { width, height } = canvas
  const STEP = 20                       // 격자 간격(px)
  let total = 0, near = 0
  // 기준색 = 좌상단 샘플
  const base = ctx.getImageData(0, 0, 1, 1).data
  for (let y = 0; y < height; y += STEP) {
    for (let x = 0; x < width; x += STEP) {
      const d = ctx.getImageData(x, y, 1, 1).data
      total++
      const diff = Math.abs(d[0]-base[0]) + Math.abs(d[1]-base[1]) + Math.abs(d[2]-base[2])
      if (diff < 24) near++            // 기준색과 거의 같음
    }
  }
  return total > 0 && near / total >= 0.985   // 98.5% 이상이 같은 색 → 백지
}
```
- **성능 주의**: `getImageData`를 픽셀마다 부르면 느리다. **한 번에 전체를 읽어(`getImageData(0,0,w,h)`) 배열을 격자로 순회**하는 방식으로 구현할 것.
- **임계값 주의**: 단색 배경에 제목만 있는 진짜 표지도 있다. 98.5%는 **거의 완전한 단색**만 걸러내는 값이다. 너무 낮추면 정상 표지를 버린다.
- 백지면 **업로드하지 않고** 실패로 처리한다.

### 3-2. 실패 사유를 반환하도록 (`cover-from-pdf.ts`)

반환 타입을 바꾼다:
```ts
export type CoverResult =
  | { ok: true;  url: string }
  | { ok: false; reason: 'render_failed' | 'blank_page' | 'upload_failed' | 'update_failed' }

export async function coverFromPdfFirstPage(
  admin: SupabaseClient, contentId: string, pdf: Uint8Array,
): Promise<CoverResult>
```
- **여전히 throw 하지 않는다**(graceful 유지). 실패는 `{ ok:false, reason }`으로 반환.
- 각 실패 지점에서 적절한 `reason`을 붙인다.

### 3-3. 렌더 견고화 (선택적 재시도)
- `renderPageAsImage`가 실패하면 **더 작은 폭(예: 600)으로 1회 재시도**한다(메모리·시간 초과 완화).
- 두 번 다 실패하면 `render_failed`.

### 3-4. 호출부 갱신

**`extract` 라우트** (`src/app/api/admin/contents/[id]/extract/route.ts`):
- 응답에 `coverSet: boolean` **유지** + **`coverReason?: string`** 추가(실패 시).
- 모든 응답 경로(에러·스캔·성공)에 동일하게 포함(현재도 그렇게 돼 있다).
- **커버 시도가 `isScannedPdf` 조기 return보다 앞에 있는 현재 순서를 유지할 것**(285의 핵심).

**`pdf-cover-backfill.ts`** (286):
- `CoverResult`에 맞춰 `filled` 판정을 `result.ok`로.
- **마커(`thumbnail_fetched_at`)는 성공·실패 무관하게 계속 무조건 찍는다**(무한 재렌더 방지 — 286의 핵심 가드). **바꾸지 말 것.**
- 백지(`blank_page`)·실패 건은 `thumbnail_url`이 null로 남으므로 **"표지 없음" 필터(§3-7)에 잡힌다** → 사람이 채운다.

### 3-5. 업로드 폼에 표지 결과 표시 (`ReportUploadForm.tsx`)

기존 "본문 추출 완료" 박스에 **표지 결과 한 줄 추가**:
- 성공: `· 표지 자동 추출 완료`
- 실패: `· 표지 자동 추출 실패({사유}) — 콘텐츠 검수에서 표지를 직접 올려주세요`
- 사유 한글화: `render_failed`→"1페이지 렌더 실패", `blank_page`→"1페이지가 비어 있음(스캔 PDF일 수 있음)", `upload_failed`/`update_failed`→"저장 실패"
- **수동 커버를 미리 지정해 업로드한 경우**(자동 시도 자체를 안 함)는 "표지 직접 지정됨"으로 표시.

### 3-6. "1페이지 다시 가져오기" + 수동 커버 (콘텐츠 검수)

`AdminContentManager`의 편집 모달(또는 행 액션)에서, **PDF 콘텐츠(`file_path`가 `.pdf`)에 한해**:
- **[1페이지 다시 가져오기]** 버튼 — 신규 라우트 `POST /api/admin/contents/[id]/pdf-cover`
  - `reports` 버킷에서 다운로드 → `coverFromPdfFirstPage` 호출 → 결과 반환.
  - ⚠️ **이 버튼은 `thumbnail_url`이 있어도 강제로 덮어쓴다**(사용자가 명시적으로 누른 것이므로). 단 **확인 다이얼로그** 필수 — 수동으로 올린 커버가 날아갈 수 있다.
  - 어드민 role 직접 재확인.
- **[커버 직접 올리기]** — 기존 `uploadCoverFile`(`:451`) 경로를 **눈에 띄게** 노출. 지금은 편집 모달 깊숙이 있다.
- 실패 시 사유를 그대로 보여준다.

### 3-7. "표지 없음" 필터 (어드민 콘텐츠 목록)

`/admin/contents`에 필터 추가: **표지 없음**
- 조건: `thumbnail_url IS NULL` (선택적으로 `file_path ILIKE '%.pdf'`로 PDF만)
- 목적: **표지가 빠진 리포트를 한눈에 모아 보고 채운다.** 이게 "사람이 개입할 길"의 핵심이다.
- 기존 필터(상태·카테고리·소스)와 동일한 패턴으로 붙일 것.

## 4. 회귀 가드

- **커버 시도는 `isScannedPdf` 조기 return보다 앞**에 유지(285). 스캔 PDF가 표지를 받을 수 있는 유일한 경로다.
- **286 백필의 마커는 성공·실패 무관 무조건** 유지. 이걸 조건부로 바꾸면 무한 재렌더(CPU 폭증).
- **자동 경로(업로드 시 extract, 백필)는 `thumbnail_url IS NULL`일 때만** — 수동 커버를 절대 덮지 않는다.
  - **예외는 §3-6의 "다시 가져오기" 버튼뿐**(사용자가 명시적으로 누름 + 확인 다이얼로그).
- **`coverFromPdfFirstPage`는 여전히 throw 하지 않는다.** 실패는 반환값으로.
- **백지 임계값(98.5%)을 낮추지 말 것** — 단색 배경 + 제목만 있는 진짜 표지를 버리게 된다.
- `getImageData`를 픽셀마다 호출하지 말 것(성능). 한 번에 읽어 순회한다.
- 커버 우선순위 체인(`coverUrlFor`)·생성 풀(`pickTopicCover`)은 **건드리지 말 것**.

## 5. 검증 (Sonnet)

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build`.
- **백지 감지**: 흰 페이지만 있는 PDF를 만들어 렌더 → `blank_page`로 판정되고 **업로드되지 않는지**. (실제 백지 PDF를 생성해 로컬에서 함수 직접 실행할 것.)
- **정상 표지 오탐 없음**: 단색 배경 + 제목 있는 표지가 `blank_page`로 잘못 걸리지 않는지.
- 업로드 폼에 **표지 성공/실패(사유)가 표시**되는지.
- **"1페이지 다시 가져오기"** 가 동작하고, 확인 다이얼로그가 뜨는지.
- **"표지 없음" 필터**로 커버 빠진 PDF가 모아지는지.
- 286 백필 두 번 실행 → **여전히 재렌더되지 않는지**(마커 가드 불변).
- 수동 커버가 있는 PDF는 자동 경로에 **안 덮이는지**.
- 커밋: `feat: PDF 표지 백지 감지 + 실패 가시화 + 수동 보정 경로 (지시서 291)`
