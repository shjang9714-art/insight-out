## 배경
어드민 콘텐츠 관리(`/admin/contents`)의 한계:
1. 카테고리 필터가 **옛 카테고리**(가트너 리포트·KRG 리포트·오피니언 채널·뉴스레터)를 그대로 노출 — 지시서 50에서 정리한 현재 규칙과 불일치.
2. **소스별로 콘텐츠를 모아보는** 수단이 없음.
3. 콘텐츠/업로드 리포트의 **제목 등 메타 수정 기능이 아예 없음**(보이기/숨기기/삭제만).

## 작업

### 1. 카테고리 탭/필터 현행화 (현재 규칙에 맞춤)
- 카테고리 옵션을 `CONTENT_CATEGORY_LABEL`(deprecated 포함) 대신 **`categories.ts`의 `CATEGORY_DEFS`**(이미 50에서 정리됨: 뉴스/리포트/웹인사이트/유튜브/AI보고서)에서 생성.
- 상단을 **탭 형태**로(전체 / 뉴스 / 리포트 / 웹인사이트 / 유튜브 / AI보고서) — 기존 Select 를 탭 버튼 행으로 교체(또는 탭+Select 병행, 취향). 선택 시 서버필터 `.eq('category', …)`(기존 53 서버필터 재사용).
- deprecated 카테고리(가트너/KRG/오피니언/뉴스레터)는 옵션에서 **제외**. (50 마이그레이션으로 해당 데이터는 거의 없음 — 잔존분은 "전체"에서만 보임.)

### 2. 소스 필터 (소스별 콘텐츠 모아보기)
- 탭(카테고리) 옆에 **소스 드롭다운** 추가: 선택 시 `.eq('source_id', sourceId)` 서버필터.
- 소스 목록 로드: `sources` 에서 id·name·type (가능하면 선택된 카테고리에 맞는 타입만 — news_site↔뉴스, report_publisher↔리포트, web_insight↔웹인사이트, youtube_channel↔유튜브). 단순화하려면 전체 소스 + 이름 정렬도 허용(보고에 명시).
- **null 출처(Google News 키워드 검색 수집물)** 대응: 옵션에 "Google News 검색" → `source_id is null` 필터(`.is('source_id', null)`).
- 카테고리/소스/검색/페이지는 함께 동작(기존 서버 페이지네이션·디바운스 유지, 필터 변경 시 page=1 리셋).

### 3. 콘텐츠/리포트 편집
- 각 행에 **"수정" 버튼** → 모달(또는 인라인 폼)로 편집:
  - **title**(필수), **summary_ko**, **category**(현행 카테고리 셀렉트), **source_id**(발행처 — sources 드롭다운, 없음 허용), **author**, **published_at**(date).
  - (파일 자체 교체는 범위 밖 — 메타데이터만.)
- 저장: `supabase.from('contents').update({ … }).eq('id', id)` (admin RLS 로 update 허용 — 기존 status 변경과 동일 경로). 성공 시 목록 갱신.
- 업로드 리포트(파일 콘텐츠)도 동일 폼으로 제목·발행처·요약·발행일 수정 가능해야 함(David 명시 요구).
- 검증: title 빈 값 방지, published_at 빈 값 허용(null).

## 회귀 / 주의
- DB/RLS/enum 무변경. 기존 보이기/숨기기/삭제·pending 카운트·일괄·페이지네이션 정상.
- 카테고리 탭에서 deprecated 제외해도, 그 카테고리의 잔존 데이터가 "전체"에선 보여야 함(숨겨 사라지지 않게).
- 편집 update 는 admin 만(RLS). 클라이언트 update 가 RLS 로 막히면 status 변경과 동일하게 동작하는지 확인(이미 됨).
- source_id 변경 시 카테고리와 불일치 가능(자유 허용) — 막지 않되, category 도 같이 수정 가능하니 운영자 판단.
