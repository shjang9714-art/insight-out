# 지시서 545-fix — "오늘의 주요 변화" 카드도 같은 분류 기준으로

> 기준 `origin/main = ea4a98d` (545 머지 완료) · 플래너 작성 2026-08-22
> **선행 SQL 없음. 화면 레이아웃 변경 없음. 판정식 3줄만 바꾼다.**

## 1. 실측 사실 — 재조사 금지

### 1-1. 이건 플래너의 지시서 누락이다

545 지시서 §3-2 에 `AiInsightBoard.tsx:269-276 의 카운터` 라고 **줄 번호를 콕 집어** 쓰는
바람에 `buildKeywordChangeCards()` 가 범위 밖으로 빠졌다.
**Sonnet 은 스펙대로 구현했다. 빠뜨린 쪽은 지시서다.**

### 1-2. 그래서 지금 한 화면에 기준이 두 개다

545 로 타일 4개와 랭킹 3탭은 `classifyKeyword()`(±20% 완충)를 쓴다.
그런데 바로 아래 **"오늘의 주요 변화"** 카드는 **옛 0% 기준**을 그대로 쓴다.

`src/components/analysis/AiInsightBoard.tsx` — `buildKeywordChangeCards()` 안 3곳:

| 줄 | 현재 판정식 | 무엇에 쓰이나 |
|---|---|---|
| **149** | `!keyword.isNew && (keyword.changePct ?? 0) > 0` | `fastestRising` — "○○ 관심 급증" 카드 |
| **161** | `keyword.isNew` | `newKeywords` — "△△ 신규 흐름 유입" 카드 |
| **182** | `keyword.bucket === bucket && (keyword.changePct ?? 0) > 0` | 버킷별 `rising` — "상승 키워드 N개" 문구 |

**실측 (2026-08-22, RPC 153행)**

```
타일 "급상승" (±20% 기준) = 59
카드가 쓰는 0% 기준        = 63     ← 4개 차이
```

**545 이전에는 타일도 0% 였으므로 최소한 일관됐다. 545 가 불일치를 새로 만들었다.**

### 1-3. `newKeywords`(161행)는 지금도 결과가 같다

`isNew === (prev === 0 && cur > 0)` 이고 `classifyKeyword` 의 `'new'` 도 같은 조건이다.
**그래도 바꾼다** — 기준을 한 곳으로 모으는 것이 이 지시서의 목적이고,
`isNew` 는 표시용 필드지 분류 기준이 아니다.

## 2. 작업

`src/components/analysis/AiInsightBoard.tsx` 의 `buildKeywordChangeCards()` 안에서
**판정만** `classifyKeyword()` 로 바꾼다. 정렬·문구·카드 구성은 그대로.

```ts
// 149행
.filter(keyword => classifyKeyword(keyword) === 'rising')

// 161행
const newKeywords = keywords.filter(keyword => classifyKeyword(keyword) === 'new')

// 182행
const rising = keywords.filter(
  keyword => keyword.bucket === bucket && classifyKeyword(keyword) === 'rising'
)
```

`classifyKeyword` 는 **이미 import 돼 있다**(545 에서 추가됨). 새 import 불필요.

## 3. 하지 않을 것

- ❌ **정렬 기준을 바꾸지 않는다.** `changePct` 내림차순 → `cur` 내림차순 그대로 둔다.
  (분류에는 안 쓰지만 **정렬에는 계속 쓴다** — 이건 정상이다.)
- ❌ 카드 문구·제목·개수(`slice(0, 3)`)·아이콘을 바꾸지 않는다.
- ❌ **배지 표시용 `isNew`·`changePct` 사용처를 건드리지 않는다**
  (`:504`, `:522`, `:528`, `:617`, `:621-627`). 그건 표시지 분류가 아니다.
- ❌ `SUSTAINED_BAND_PCT` 값을 바꾸지 않는다. 20 이다.
- ❌ `classifyKeyword` 자체를 수정하지 않는다.
- ❌ 다른 파일을 건드리지 않는다. **이 파일 하나, 3줄이다.**
- ❌ **DDL·SQL 작성 금지.**

## 4. 검증 — 브라우저 없이 한다

### 4-1. 🔴 분류 판정이 한 곳뿐인지

```
grep -n "isNew\|changePct" src/components/analysis/AiInsightBoard.tsx
```

결과에서 **분류에 쓰인 곳이 0곳**이어야 한다.
남아 있어도 되는 것은 **표시·정렬**뿐이다 — 각 잔류 줄이 표시인지 정렬인지 한 줄로 적는다.

`buildKeywordChangeCards` 안에 `classifyKeyword` 호출이 **3곳** 있어야 한다.

### 4-2. 카드 숫자와 타일 숫자가 맞물리는지

RPC 결과에 `classifyKeyword` 를 적용하는 스크립트로 확인한다(545 에서 쓴 방식 그대로).

- 버킷별 `rising` 합계 ≤ 타일 `급상승` 값
- `fastestRising` 으로 뽑히는 키워드가 `classifyKeyword === 'rising'` 인지

**스크립트는 커밋하지 않는다.**

참고 — 2026-08-22 플래너 실측: RPC 153행 = 급상승 59 + 신규 6 + 관심 지속 22 + 하락 66.

(`npm run build` 는 샌드박스에서 Google Fonts 페치로 실패한다 — 돌리지 않아도 된다.)
