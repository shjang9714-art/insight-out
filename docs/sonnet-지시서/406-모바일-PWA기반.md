## 2. 구현

### 2.1 `src/app/manifest.ts` (신규 — Next Metadata)
```ts
import type { MetadataRoute } from 'next'
export default function manifest(): MetadataRoute.Manifest {
  return {
    name: 'Insight Out',
    short_name: 'Insight Out',
    description: 'B2B 서비스 인텔리전스 플랫폼',
    start_url: '/dashboard',
    display: 'standalone',
    background_color: '#ffffff',
    theme_color: '#E6007E',
    lang: 'ko',
    icons: [
      { src: '/favicon-192.png', sizes: '192x192', type: 'image/png', purpose: 'any' },
      { src: '/favicon-512.png', sizes: '512x512', type: 'image/png', purpose: 'any' },
      { src: '/favicon-512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
    ],
  }
}
```
- `start_url: '/dashboard'` — 설치 후 앱은 대시보드로 연다(로그인 세션은 기존 미들웨어가 처리).
- ⚠️ `maskable` 아이콘이 실제로 여백을 가진 이미지가 아니면 안드로이드에서 잘릴 수 있다. **일단 512를 재사용하되, 잘림이 문제되면 후속 슬라이스에서 전용 maskable 제작**(이번 범위 밖, §7 기록).

### 2.2 🔴 `public/sw.js` (신규 — 안전 최우선)
**서비스워커는 잘못하면 stale 캐시로 배포가 사용자에게 반영되지 않는다.** 이번은 **설치 조건 충족용 최소 SW** 만 둔다.
```js
// 설치 가능 조건(fetch 핸들러 존재)만 충족하는 pass-through SW.
// ⚠️ 캐싱하지 않는다 — stale 배포 방지가 오프라인 캐시보다 우선.
// 오프라인 캐시 전략은 별도 슬라이스에서 network-first 로 신중히 도입한다.
self.addEventListener('install', () => self.skipWaiting())
self.addEventListener('activate', (e) => e.waitUntil(self.clients.claim()))
self.addEventListener('fetch', () => { /* 네트워크로 그대로 통과 */ })
```
- **캐시 저장 금지.** Chrome PWA 설치 조건(fetch 핸들러)만 만족시키고, 요청은 네트워크로 통과. 배포 반영이 즉시 유지된다.
- `skipWaiting`+`clients.claim` 으로 새 SW 가 즉시 활성 — 구 SW가 남지 않는다.

### 2.3 `src/components/pwa/ServiceWorkerRegister.tsx` (신규 — 클라이언트)
```tsx
'use client'
import { useEffect } from 'react'
export default function ServiceWorkerRegister() {
  useEffect(() => {
    if ('serviceWorker' in navigator) {
      navigator.serviceWorker.register('/sw.js').catch(() => {})
    }
  }, [])
  return null
}
```
- 조용히 등록. 실패해도 앱 동작에 영향 없음(`.catch` 무시).

### 2.4 `src/app/layout.tsx` — 메타데이터 + SW 등록 마운트
- `metadata` 에 추가:
  ```ts
  appleWebApp: { capable: true, title: 'Insight Out', statusBarStyle: 'default' },
  ```
  (`manifest` 는 `app/manifest.ts` 가 자동 링크하므로 metadata 에 수동 추가 불필요.)
- `viewport` export 로 `themeColor` 지정(Next 16 은 `themeColor` 를 `metadata` 가 아닌 `viewport` 로):
  ```ts
  export const viewport: Viewport = { themeColor: '#E6007E' }
  ```
- `<body>` 안(Toaster 근처)에 `<ServiceWorkerRegister />` 마운트.
- ⚠️ **기존 `metadata`·폰트·ThemeProvider·Toaster 무수정.** 추가만.

### 2.6 🔴 미들웨어 공개 경로 예외 — **PWA 설치의 필수 조건** (지시서 보강 2026-07-22)

> ⚠️ **플래너 착수 전 누락 — 구현자가 실측으로 잡았다.** 미들웨어가 비로그인 `/manifest.webmanifest`·`/sw.js` 요청을 `/login` 으로 **307 리다이렉트**한다. 그러면 SW 등록이 로그인 HTML 을 받아 실패하고 manifest 도 못 읽어 **설치 조건이 무너진다.** §2.1~2.4 코드가 맞아도 이 예외가 없으면 M-1 목적이 달성되지 않는다.

`src/middleware.ts` 의 `publicPaths` 배열에 **두 경로를 추가한다:**
```ts
const publicPaths = [
  '/login', '/auth/callback', '/api/cron', '/api/version',
  '/api/newsletter/unsubscribe', '/api/webhooks/brevo', '/api/mcp', '/api/council',
  '/manifest.webmanifest', '/sw.js',   // ← 추가: PWA 설치 조건(공개 접근 필요)
]
```
- `startsWith` 매칭이라 두 경로가 정확히 통과된다. 로그인/비로그인 **양쪽 모두** 리다이렉트 대상에서 빠진다.
- **그 외 미들웨어 로직·`matcher`·세션 캐시·게이팅은 무수정.** 배열에 2개만 추가.
- ⚠️ 이 두 경로는 **비밀 정보가 없다**(manifest = 앱 메타, sw = pass-through 스크립트) → 공개 안전.

### 2.5 하지 말 것
- **모바일 앱 셸(탭바·미니플레이어·바텀시트)을 만들지 않는다.** M-2 이후.
- SW 에 **캐시 로직을 넣지 않는다**(§2.2). 오프라인 캐시는 별도 슬라이스.
- `dashboard/*` 화면·`globals.css`·인증 로직 무수정. **미들웨어는 §2.6 의 `publicPaths` 2줄만** 손댄다(그 외 무수정).
- 405 가 건드리는 `reports/*` 를 건드리지 않는다(병렬 격리).

## 3. 회귀 가드
1. **기존 앱이 그대로 동작**한다(데스크톱·모바일 웹 모두). SW 는 요청을 통과만 시킨다.
2. 배포 후 **새로고침 시 최신 코드가 즉시 반영**된다(stale 캐시 없음).
3. 크롬 모바일에서 **"홈 화면에 추가/설치"가 뜬다**(manifest + SW + HTTPS 충족).
4. 설치한 앱을 열면 `/dashboard` 로 시작하고 **standalone(주소창 없음)** 으로 뜬다.
5. 상태바/테마 컬러가 브랜드 마젠타.
6. `manifest.webmanifest` 가 200 으로 서빙된다(`/manifest.webmanifest`).
7. Lighthouse PWA "Installable" 통과.
