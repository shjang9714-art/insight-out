# 지시서 351-C — 키워드 상승 요인(3패스 LLM, 경쟁사 브리핑 재사용)

> 대상: 구현 에이전트 · 상위설계 `docs/키워드분석-재설계-사전분석.md` · 선행: 351-A·351-B(둘 다 origin/main 반영 완료)
> ⚠️ 읽을 것: `src/lib/keywords/detail.ts`(getKeywordSnapshot/Related·이벤트 조회) · `src/app/dashboard/keywords/[name]/page.tsx`(L293~294 "상승 요인" placeholder·추이차트) · `src/lib/competitor-weekly/{generate.ts,frame-spec.ts,verify.ts,query.ts}`(3패스 원형) · `src/app/api/admin/competitor-weekly/analysis/route.ts`(GET 컨텍스트/POST 검증저장) · `src/components/admin/AdminCompetitorWeeklyAnalyze.tsx` · `src/lib/prompts/catalog.ts`(프롬프트 등록) · `src/lib/prompts/loadPrompt`(DB 우선 로드) · `AGENTS.md`
> ⚠️ **이 지시서는 신규 SQL 있음** — 결과 저장 테이블 1개(수희 핸드오프). 아래 §0 참조.

## 배경
351-B가 상세에 "상승 요인" 자리(placeholder)만 뒀다(`분석 준비 중입니다…`). 급상승 키워드가 **왜** 뜨는지를 근거 사건으로 묶어 3~5개 요인으로 제시한다. 경쟁사 브리핑의 3패스(사실추출→분석→근거검증)와 프롬프트 콘솔을 **그대로 재사용**한다. 자동 전량이 아니라 **급상승 키워드 대상 어드민 수동 실행**(패스② Claude MCP).

## 설계 결정
1. **대상 한정** — 351-A 급상승/신규 상위 키워드만(전 키워드 아님). 상세 진입 시 저장된 요인이 있으면 렌더, 없으면 기존 placeholder 유지.
2. **3패스 = 경쟁사 브리핑 미러링**
   - **패스① 사실추출(자동)**: 키워드의 최근 30일 근거 사건 목록을 만든다. `detail.ts`의 이벤트/기사 조회 재사용 → `{ evt_id, event, date, source, content_id, numbers }[]`. 해석 금지, 사건만.
   - **패스② 분석(Claude MCP 수동)**: 어드민이 컨텍스트(키워드+사실목록+프레임) 복사 → Claude 붙여넣기 → 요인 JSON 붙여넣기. `AdminCompetitorWeeklyAnalyze` UI 패턴 복제.
   - **패스③ 근거검증(자동, 저장 직전)**: evidence(evt_id)가 없거나 존재하지 않는 사건을 가리키는 요인은 **버린다**. `verify.ts`의 `resolveEvidence`/`checkNumbers` 패턴 복제.
3. **저장** — 키워드별 최신 요인 1세트 유지(재실행 시 upsert). §0 테이블.

## §0. 신규 SQL (수희 핸드오프)
`docs/sql-handoff/351C-keyword-rise-factors.sql` 작성:
- 테이블 `keyword_rise_factors`: `keyword text primary key`(정규화 소문자), `display_name text`, `overview text`, `factors jsonb`(배열 `[{thesis, detail, evidence:[content_id...]}]`), `generated_at timestamptz`, `status text default 'draft'`. RLS: 읽기 public(또는 인증), 쓰기 service_role.
- 인덱스 불필요(PK 조회). 적용 전에는 상세가 placeholder로 안전 폴백(테이블 미존재 42P01 → graceful).

## 작업

### A. 사실추출 + 검증 — `src/lib/keywords/rise.ts`(신규, server-only)
- `buildRiseFacts(name)` → 패스① 사실 목록(위 스키마). `detail.ts` 조회 재사용, evt_id 부여.
- `verifyRiseFactors(facts, input)` → 패스③. 유효 evt_id 집합으로 근거 없는 요인 드롭, 드롭 리포트 반환(어드민 노출용).
- `getRiseFactors(name)` / `saveRiseFactors(name, verified)` → 테이블 read/upsert. 테이블 없으면 read는 `null`, save는 명확한 에러(42P01 안내).

### B. 프레임 스펙 + 프롬프트 등록
- `src/lib/keywords/rise-frame.ts`: 요인 출력 스키마·작성 규칙(명제형 thesis + detail + evidence[evt_id], 3~5개, LG U+ 시각 불요 — 이건 시장 관심 상승 "이유"). `RISE_FRAME_FALLBACK` export.
- `PROMPT_CATALOG`에 `keyword_rise_frame` 등록(그룹 `키워드 분석`) + `loadPrompt(admin,'keyword_rise_frame',RISE_FRAME_FALLBACK)`로 DB 우선. (catalog.ts 주석의 3곳 동시 갱신 규칙 준수.)

### C. 어드민 라우트 + UI (패스②)
- `src/app/api/admin/keywords/rise/route.ts`: `GET ?name=` → 컨텍스트(키워드+사실목록+프레임) 텍스트. `POST {name, analysis}` → JSON 파싱 → `verifyRiseFactors` → `saveRiseFactors`(draft) → 드롭/경고 리포트. verifyAdmin 재사용.
- `src/components/admin/AdminKeywordRiseAnalyze.tsx`: 경쟁사 컴포넌트 복제, 주 입력이 `name`(키워드). 어드민 키워드 관리 화면 또는 `/admin/keywords`에 배치.

### D. 상세 렌더 — 351-B placeholder 대체
- `keywords/[name]/page.tsx` L293~294 "상승 요인" 섹션: `getRiseFactors(name)` 있으면 요인 카드(명제 + detail + 근거 각주 → `contents/{content_id}` 링크, `CompetitorWeeklyReport`의 `Footnotes` 표기 재사용). 없으면 기존 "분석 준비 중" 유지.
- **추이차트 사건 마커**(351-B가 라인만 둠): 요인 근거 사건 날짜에 recharts `ReferenceDot`/마커 추가(있을 때만).

## 회귀 / 주의
- **근거 없는 요인 = 저장 안 함**(패스③ 필수). "왜 떴는지"는 반드시 우리 DB 사건에 링크.
- 테이블 미적용(42P01) 시 상세·어드민 모두 graceful(크래시 금지).
- 프롬프트는 콘솔에서 편집 가능해야 함(하드코딩 금지, `loadPrompt` 경유).
- 급상승 아닌 키워드에 억지로 요인 만들지 말 것(대상 한정).
- `prefetch={false}`, 한글 키워드 URL 인코딩, 색상 토큰(하드룰 9).
- 검증: `tsc` · ESLint · `check-prefetch` · `npm run build` · 육안(어드민 3패스 왕복 → 상세에 요인·각주·마커).
