## 배경 (인지부조화 원인)
- **네비에 현재 위치 표시 없음** → 어디 있는지 모름.
- **소스 타입 필터가 멀티 토글(Set)** → "정신없음".
- **타입별 입력 안내 부재 + 잘못된 경고**:
  - 수집 분기는 `type` 기반이고 `collection_method`(rss/html/api/manual)는 **분기에 안 쓰임**(라벨일 뿐). html(스크래핑)·api **어댑터 미구현** → 그 옵션은 동작 안 함.
  - `web_insight` 는 실제로 **RSS 어댑터로 수집됨**(getAdapter web_insight→newsSite)인데 폼이 "어댑터 준비 중" 경고를 띄움 = 버그성.
  - 유튜브는 채널 RSS(`youtube.com/feeds/videos.xml?channel_id=…`)를 입력해야 하나 찾는 법 안내 없음.
- **⚠️ 점검 필요(활성·7일 수집 0) 소스의 원인(에러)을 어드민에서 볼 수 없음** → 진단·제거 판단 불가.

### 설계 결정(David 확정 — Opus 추천 채택)
- 유튜브: **채널 RSS 도움말만** 추가(입력 자체 제거는 60 도입 시). "추후 키워드 검색으로 대체 예정" 명시.
- collection_method: **미구현 옵션(html·api) 숨김** — 동작하는 rss/manual/youtube 만 노출. (기존 행에 html/api 있으면 표시 라벨은 유지.)

## 작업

### 1. 어드민 네비 활성 표시
- `layout.tsx` 의 네비를 클라이언트 하위 컴포넌트로 분리: `src/components/admin/AdminNav.tsx`('use client') — `usePathname()` 으로 현재 경로 판정.
  - active 판정: `pathname === item.href` (단, `/admin` 홈은 정확히 일치, 그 외는 `pathname === href || pathname.startsWith(href + '/')`).
  - active 스타일: `text-brand-600 font-semibold` + 하단 밑줄(예 `border-b-2 border-brand-600`) 또는 `bg-accent` — 기존 톤(#9 토큰)으로. 비active 는 현행 muted.
- `layout.tsx` 는 서버 유지, `<AdminNav items={NAV_ITEMS} />` 렌더. NAV_ITEMS 는 layout 또는 AdminNav 에 정의(직렬화 가능 데이터).

### 2. 소스 타입 단일 탭 (멀티 → 단일)
- `SourceManager`: `selectedTypes: Set<SourceType>` → `selectedType: SourceType | 'all'` 단일 상태로 교체.
- 상단 탭 행: `전체 / 뉴스 / 웹인사이트 / 리포트 / 유튜브`(SOURCE_TYPE_LABELS 순서). 한 번에 하나 active(브랜드색). 클릭 시 해당 타입만 필터.
- `filteredSources` = `selectedType === 'all' ? sources : sources.filter(s => s.type === selectedType)`. 개수 배지는 탭 라벨 옆 유지.

### 3. 타입별 입력 가이드 + 경고 정리 (추가/수정 폼)
- **선택된 type 에 따라 안내·필드 동적**:
  - `news_site` · `web_insight`: **rss_url 필수** 강조 + 도움말: "사이트 RSS 주소를 입력하세요. 보통 `/rss`, `/feed`, `/rss.xml`. Substack=`/feed`, Medium=`https://medium.com/feed/@핸들`. 못 찾으면 사이트에서 'RSS' 링크 확인." web_insight 의 **"어댑터 준비 중" 경고 제거**(실제 수집됨).
  - `report_publisher`: "자동 수집하지 않습니다 — **발행처 등록 전용**. 콘텐츠는 [리포트 업로드]에서 추가." rss_url/주기 입력 **숨김 또는 비활성**(혼란 제거), 이름만 필수.
  - `youtube_channel`: 도움말 "채널 RSS: `https://www.youtube.com/feeds/videos.xml?channel_id=UC...`. channel_id 는 채널 페이지 '소스 보기'에서 `channelId` 검색(또는 URL 이 `/channel/UC…` 면 그 값). ※ 추후 키워드 검색 수집으로 대체 예정(지시서 60)."
- **collection_method 셀렉트**: 옵션을 `rss / manual / youtube` 로 축소(html·api 숨김). 기본값은 기존 `defaultCollectionMethod(type)` 유지. (타입 고정형이면 셀렉트 대신 자동 설정도 가능하나, 최소 변경 위해 옵션만 축소.)
- `needsRssUrl`(news_site·youtube_channel)에 **web_insight 도 포함**(RSS 필수 안내 일관) — 또는 안내 문구로 처리. report_publisher 는 RSS 불필요.

### 4. ⚠️ 소스 진단 — 마지막 에러 노출
- `source-status` API 확장: `SourceStatusInfo` 에 `lastError: string | null` 추가. 쿼리 select 에 `error_message` 포함하고, **각 소스 최신 로그(finished_at desc 첫 행)의 error_message** 를 lastError 로 채움.
- `SourceManager` 수집 상태 열: `⚠️ 점검 필요`(활성·inserted7d 0) 또는 `🔴 연속실패` 행에 **lastError 를 title 툴팁 또는 작은 회색 텍스트로 노출**(예: "RSS 404", 파싱 오류 메시지). → David 가 원인 보고 수정/비활성/삭제 판단.
- (표시만; 자동 삭제 없음.)

## 회귀 / 주의
- DB/수집 로직 무변경. 수집은 여전히 type 기반(web_insight·news_site=RSS 어댑터). UI 안내만 현실에 맞춤.
- collection_method 옵션 축소는 **표시 한정** — 기존 저장값(html/api)은 라벨로 계속 보임(데이터 보존). 신규 선택만 제한.
- report_publisher 폼에서 rss/주기 숨겨도 기존 행 편집 시 값 손실 없게(미표시 필드는 기존 payload 유지 또는 null 유지).
- 네비 active 는 클라이언트 컴포넌트 분리로만(레이아웃 서버 유지, 최소 'use client').
- UI 텍스트 한국어(#1), 색상 토큰/brand-*(#9), `cn()` 사용.
