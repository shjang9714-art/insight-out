## 1. 현행 진단 (2026-07-13, `origin/main` 확인)

### 1.1 🔴 지금은 **브라우저 `while(true)` 루프**다 — 화면을 떠나면 진행현황이 사라진다

`AdminContentProcessing.tsx:110` (본문 수집 예시)
```ts
while (true) {
  const res = await fetch(`${endpoint}?limit=30`, { method: 'POST' })
  const { processed, improved, skipped, remaining } = await res.json()
  acc.processed += processed; …
  if (stopRef.current) { setEnrichResult(`중단됨 · 남은 ${remaining}`); break }
  if (remaining === 0)  { setEnrichResult(`완료 · …`); break }
  if (processed === 0)  break                    // ⭐ 무한루프 가드
  setEnrichResult(`채우는 중… 남은 ${remaining}`)
  await new Promise(r => setTimeout(r, 300))     // ⭐ 300ms 간격
}
```
**상태가 컴포넌트 로컬 `useState`다.** 라우트를 옮기면 언마운트되고 **진행현황이 통째로 사라진다.**

### 1.2 잡의 성격이 **두 가지**다 (전수 확인)

| 종류 | 개수 | 어디 | 목록 |
|---|---|---|---|
| **루프 잡** (`remaining === 0` 까지 반복) | **8** | `AdminContentProcessing` 6 + `ai-jobs` 2 | body-backfill · canonical-backfill · thumbnail-backfill · youtube-transcript · pdf-cover-backfill · cluster-backfill · **summary-backfill** · **signals-backfill** |
| **단발 잡** (1회 호출) | **4** | `ai-jobs` 3 + `enrich` 1 | sentiment · lgu-impact · youtube-summary · **youtube-tagging** |

### 1.3 🔴 **응답 스키마가 잡마다 다르다** — 이게 이 슬라이스의 핵심 난점

```
{ processed, improved,   skipped,    remaining }          body-backfill
{ processed, filled,     skipped,    remaining, ready }   summary-backfill
{ processed, fetched,    skipped,    remaining, ready }   youtube-transcript
{ processed, resolved,   deduped,    remaining, ready }   canonical-backfill
{ processed, merged,     repChanged, remaining, ready }   cluster-backfill
```
- **공통**: `processed` · `remaining`
- **성공 건수의 이름이 제각각**: `improved` / `filled` / `fetched` / `resolved` / `merged`
- **`ready`**: SQL 미적용 시 `false` → **graceful 중단**(컬럼이 없으면 조용히 안 돌게 하는 장치)

→ **정규화 없이는 전역 Provider를 못 만든다.**

### 1.4 `stopRef`가 **6개 따로** 있다
`stopRef` · `canonicalStopRef` · `thumbRetryStopRef` · `transcriptStopRef` · `pdfCoverStopRef` · `clusterStopRef`
→ 잡별 중단은 되지만, **전역에서 관리되지 않는다.**

### 1.5 ⭐ 레퍼런스가 이미 있다 — **새로 발명하지 말 것**
`SourceQualityManager.tsx:31` — `CRAWL_JOB_STORAGE_KEY = 'insight-out:admin-crawl-job'`
- localStorage에 잡 저장(`:399`) → 마운트 시 복원(`:257`) → `setInterval` 폴링(`:328`) → 끝나면 제거(`:298`)
- 크롤은 **진짜 서버 백그라운드**다(`crawl-now/route.ts:92` Next `after()`). 우리 12개 잡은 그게 아니다 — **혼동하지 말 것.**

### 1.6 `admin/layout.tsx`는 **서버 컴포넌트**다 (`metadata` export)
`AdminThemeScope` → `AdminSidebar` → `<main>{children}</main>` 구조.
→ Provider는 **클라이언트 컴포넌트**로 만들어 이 안에 끼운다.

### 1.7 `job_runs` 계측은 이미 살아 있다
12개 API 전부 `runJob(admin, { key: 'admin:…' })` 로 감싸져 있고, **화면에서 기록이 남는 것을 확인했다**(2026-07-13). **`job_key`를 바꾸면 작업 이력이 끊긴다.**

## 3. 구현

### 3-1. ⭐ `ENRICH_JOBS` 메타 확장 — **실행 규격을 단일 진실로**

`src/lib/admin/enrich-jobs.ts` (330에서 만든 것을 **확장**)

```ts
export type EnrichJobKind = 'loop' | 'once'

export interface EnrichJobMeta {
  key: EnrichJobKey
  label: string
  endpoint: string
  usesLlm: boolean
  surface: EnrichJobSurface
  // ── 337 추가 ────────────────────────────────
  kind: EnrichJobKind
  method: 'POST' | 'GET'          // canonical-backfill 만 GET (확인함)
  limit?: number                  // 30 / 20 / 15 / 10 / 5 — 현재 값을 그대로 옮길 것
  modes?: readonly ['fresh', 'retry']   // thumbnail · transcript · pdf-cover
  dateRange?: true                // body-backfill 만 (from/to)
  confirm?: string                // LLM 잡 확인 문구 (현재 confirm() 문구 그대로)
}
```

> ⛔ **`limit`·`method`·`endpoint`를 추측하지 말 것.** `AdminContentProcessing.tsx` / `ai-jobs/page.tsx` 의 **현재 값을 그대로 옮긴다.** 하나라도 바뀌면 동작이 달라진다.
> 330의 **`usesLlm ↔ surface` throw 가드를 그대로 유지**하고, **`kind === 'once'` 인데 `limit`이 있으면 throw** 같은 가드를 추가할 것(루틴 §5.2).

### 3-2. ⭐ 응답 정규화 — **모르는 스키마면 throw**

```ts
export interface EnrichJobResult {
  processed: number
  succeeded: number                 // improved | filled | fetched | resolved | merged | (once: 잡별)
  skipped: number
  remaining: number | null          // once 잡은 null
  ready: boolean                    // 기본 true. false면 SQL 미적용 → 루프 중단 + 안내
  extra?: Record<string, number>    // deduped · repChanged 등 부가 지표
}

export function normalizeEnrichResult(key: EnrichJobKey, json: unknown): EnrichJobResult
```
- 잡별 성공 필드 매핑을 **표로 명시**한다(§1.3).
- **알 수 없는 형태면 `throw`.** 조용히 `succeeded: 0`으로 넘기지 말 것 — **인수인계 §4-1의 graceful-silent를 만들지 않는다.**
- `ready === false` → **루프를 멈추고** "SQL 미적용 — 수희 핸드오프 필요"를 독에 표시.

### 3-3. 전역 Provider

`src/components/admin/EnrichJobsProvider.tsx` (신설, `'use client'`)

- 상태: `Map<EnrichJobKey, RunState>`
  ```ts
  interface RunState {
    key: EnrichJobKey
    status: 'running' | 'done' | 'stopped' | 'error' | 'interrupted'
    acc: { processed: number; succeeded: number; skipped: number }
    remaining: number | null
    startedAt: string
    message: string
    error?: string

  ```
- API: `startJob(key, params?)` · `stopJob(key)` · `resumeJob(key)` · `dismiss(key)`
- **루프는 여기서 돈다.** `AdminContentProcessing`·`ai-jobs`의 로컬 루프·`stopRef` 6개는 **전부 삭제**하고 `startJob`을 부른다.
- **`processed === 0` 무한루프 가드 · 300ms 간격 · `remaining === 0` 종료** — **현재 로직을 그대로 옮길 것.**
- **동시 실행 허용.** 잡마다 독립적으로 돈다(지금도 `stopRef`가 6개 따로다).
- `admin/layout.tsx` 의 `AdminThemeScope` 안에 끼운다(§1.6).

**localStorage 영속** — `insight-out:enrich-jobs`
- 매 tick마다 running 잡 상태를 저장한다.
- ⭐ **마운트 시 `status === 'running'` 인 잡이 있으면 → `'interrupted'`(중단됨)로 바꾼다.**
  탭을 닫았거나 새로고침한 것이다. **루프는 죽었다.**

> 🔴 **여기가 A안의 정직성이다.** 탭을 닫으면 루프는 끊긴다. **그걸 숨기지 않는다.**

## 4. 회귀 가드

- ⛔ **`job_key`·`endpoint`·쿼리 파라미터(`limit`·`mode`·`from`·`to`)를 하나도 바꾸지 말 것.** 바뀌면 **`/admin/job-runs` 작업 이력이 끊긴다.** 오늘 화면에서 기록이 남는 걸 확인했다 — **그걸 깨면 안 된다.**
- ⛔ **API 라우트를 수정하지 말 것.** 이 슬라이스는 **클라이언트만** 바꾼다.
- ⛔ **`nav.ts`를 건드리지 말 것**(330 소유).
- **⭐ `processed === 0` 무한루프 가드를 반드시 유지.** 없으면 `remaining`이 안 줄어드는 상황에서 **API를 영원히 때린다.**
- **⭐ 300ms 간격 유지.** 없애면 서버를 두들긴다.
- **`ready === false`(SQL 미적용) graceful 유지.** 지금도 그렇게 동작한다. **에러로 처리하지 말 것.**
- **330의 `usesLlm ↔ surface` throw 가드를 깨지 말 것.** `ENRICH_JOBS`를 확장하되 기존 가드는 살린다.
- **`SourceQualityManager`의 크롤 잡(`insight-out:admin-crawl-job`)을 건드리지 말 것.** 그건 **진짜 서버 백그라운드**(`after()`)라 성격이 다르다. 독에 합치지 말 것 — **후속.**
- **`AdminThemeScope`를 깨지 말 것** — 어드민 테마가 여기 걸려 있다.
- **어드민 밖(`/dashboard`)에서는 독이 뜨지 않아야 한다.** Provider는 `admin/layout.tsx` 안에만.

## 6. 후속(범위 밖)

- **진짜 durable 백그라운드**(탭 닫아도 계속) — `after()` + 소프트 데드라인 + 자기 재기동. **재기동 실패가 조용히 멈추는 지점**이라 별도 설계 필요
- 크롤 잡(`SourceQualityManager`)을 같은 독으로 흡수
- 잡 진행률을 `job_runs` 에서 **서버 기준으로** 복원 (지금은 localStorage 기준)
- TTS 라우트 `runJob` 래핑 (현재 `job_runs`에 안 남는 유일한 잡)
