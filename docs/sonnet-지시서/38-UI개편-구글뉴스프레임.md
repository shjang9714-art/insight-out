## 목표 (한 줄)
Google News 같은 프레임: **헤더 중앙 검색** + **얇은 카테고리 스트립(sticky)** + **3단 본문**(좌: 아카이빙/최근, 중: 피드, 우: 브리핑/경쟁사/트렌딩), 반응형. 동시에 **서비스(조직/사업) 필터 중복 제거**.

## 배경 (현재 문제)
1. **sticky 과다**: 지시서 34에서 상단 전체(8칸 카테고리 그리드+서비스탭+검색)를 통째로 `sticky` 처리 → 고정 높이 ~280px라 본문 가시영역이 좁음.
2. **검색 위치**: 검색이 상단 네비 안에 묻혀 있음.
3. **서비스 필터 중복**: 상단 `ServiceTabs`(mock `SERVICES` from `taxonomy.ts`, `?service=mockId`) **와** 콘텐츠 페이지 "서비스" 드롭다운(실 `services` 테이블, `?svc=uuid`)이 **같은 선택을 두 번**, 게다가 데이터 소스가 다름(작업루프 BL-1). `RecentFeed`는 `MOCK_ID_TO_SERVICE_NAME` 으로 mockId→name→UUID 우회 중.
4. **우측 여백**: 본문이 단일 컬럼이라 와이드에서 우측이 빔.

## 파트 A — 헤더에 중앙 검색 배치 (`DashboardHeader.tsx`)
- 현재 헤더(`sticky top-0 z-20`, h-14): 좌 로고 → `ml-auto` 우측(날짜·오늘건수·ThemeToggle·알림). 여기에 **검색을 가운데**로.
- 레이아웃: `[로고(좌, shrink-0)] [검색(flex-1, 중앙, max-w-md mx-auto)] [액션(우, shrink-0)]`.
- `SearchBar` 를 헤더 안으로 가져온다(컴포넌트 재사용; placeholder·라우팅 그대로). 데스크톱은 항상 노출, **모바일(`< md`)은 검색 아이콘 버튼 → 탭 시 펼침**(간단히: 모바일에서 검색을 헤더 아래 한 줄로 토글 노출하거나 아이콘 토글). 과하면 모바일은 아이콘만 두고 클릭 시 `/dashboard/search` 로 이동해도 됨(판단 위임).
- 날짜/오늘건수(`md:flex`)는 우측 유지. 공간 부족 시 날짜 텍스트는 `lg:` 부터 노출.

## 파트 B — 카테고리: 얇은 pill 스트립 (sticky 높이 축소) (`CategoryGrid.tsx` + `layout.tsx`)
- **8칸 카드 그리드 → 한 줄 가로 pill 스트립**으로 축소(아이콘+라벨, 오늘건수는 작은 배지 또는 생략). `flex items-center gap-2 overflow-x-auto scrollbar-hide`. 각 pill = `rounded-full px-3 py-1.5 text-sm`, 활성 `bg-brand-600 text-white`, 비활성 `border border-border text-muted-foreground`. (= 카테고리 "가로배치 좁히기")
  - 컴포넌트는 `CategoryGrid` 를 스트립으로 리팩터(이름 유지 또는 `CategoryStrip` 신설 후 교체). 링크 href 로직(파트 C의 `svc` 파라미터 반영)은 유지.
- `layout.tsx` 상단 네비 박스를 **이 스트립 한 줄 + 서비스 셀렉터(파트 C)** 만 남겨 **얇게**(목표 ~44~52px) 하고 `sticky top-14 z-10 bg-card`(불투명) 유지. 검색 줄은 제거(파트 A로 이동).
  - 결과 고정 높이 = 헤더(~56px) + 스트립(~48px) ≈ **~104px** (기존 ~280px 대비 대폭 감소 → 본문 가시영역 확대).
- (선택, 권장) **스크롤 다운 시 카테고리 스트립 숨김 / 업 시 표시**: 간단한 스크롤 방향 감지(`useEffect` + `lastScrollY`)로 스트립에 `-translate-y-full`/`translate-y-0` 트랜지션. 헤더는 항상 고정. 과하면 생략 가능.

## 파트 C — 서비스(조직/사업) 필터 IA 통일 ⭐ (중복 제거)
> 핵심: **서비스 선택을 전역 1곳**으로, **실 `services` 테이블 단일 소스**, **파라미터 `svc`(UUID) 통일**, **콘텐츠 페이지 중복 드롭다운 제거**.

1. **`ServiceTabs` → 실데이터 + 전역 셀렉터화**:
   - mock `SERVICES`(taxonomy.ts) 사용 중단. `services` 테이블에서 `id, name, icon` 조회(`order('order')`). 콘텐츠 페이지가 쓰는 쿼리와 동일 소스.
   - UI: 얇은 스트립에 공간이 빠듯하므로 **우측 정렬 드롭다운("서비스 ▾", 기본 "전체")** 권장(pill 줄 오른쪽). pill 줄로 두고 싶으면 스트립이 길어지지 않게 주의.
   - 선택 시 전역 파라미터 **`?svc=<uuid>`** 갱신(기존 `?service=` 폐기).
2. **`layout.tsx`**: `handleServiceChange`/`activeService` 를 `service`→**`svc`** 로 변경. `?svc` 없으면 전체.
3. **`CategoryGrid`(스트립)**: 링크 href 의 `&service=` → `&svc=` 로 변경(현재 `activeService !== 'all'` 분기).
4. **`RecentFeed`**:
   - `MOCK_ID_TO_SERVICE_NAME` 및 name 우회 **제거**. `activeService`(=`svc` UUID)로 `content_services.eq('service_id', svc)` 직접 조회 → content_ids → contents. ('all' 이면 필터 없음.)
   - props 명칭은 유지하되 의미가 UUID 임을 주석.
5. **콘텐츠 페이지 `contents/page.tsx`**: "서비스" 드롭다운(약 L417~432) **제거**. 전역 `svc`(URL)에서 상속해 필터링(`content_services` 조인 로직 유지). "출처(`src`)"·"키워드"·"날짜" 필터는 **그대로 유지**(이건 목록 페이지 전용 정제 필터). 활성 필터 칩에서 서비스 칩은 전역 값 기준으로 표시(제거 버튼은 `svc` 비우기).
6. **mock 정리**: `taxonomy.ts` 의 `SERVICES` 가 다른 곳에서 미사용임을 grep 확인 후 제거(또는 deprecated). `CATEGORIES`/`SAVED_KEYWORDS` 는 파트 D에서 사용처 확인 후 처리.

> ⚠️ 전제: `services` 테이블에 'Connectivity/보안·클라우드/M2M/AICC/AIDC/모빌리티/기업솔루션' 행이 시드돼 있어야 함(현재 RecentFeed 가 name 으로 조회 성공 중이므로 존재 추정). 만약 비어 있으면 셀렉터가 빈 채로 나오므로 **보고에 services 행 존재 여부 명시**.

## 파트 D — 3단 본문 + 우측 레일 (`dashboard/page.tsx`)
> 좌측 레일(아카이빙+최근)은 이미 `layout.tsx` 의 `Sidebar`(전역). **우측 레일은 홈 전용**이라 `dashboard/page.tsx` 에서 구성.
- `page.tsx` 를 **2열 그리드**로: `grid gap-6 xl:grid-cols-[minmax(0,1fr)_300px]`.
  - **중앙(1fr)**: `RecentFeed`(메인 피드). `EmailArchiveWidget` 은 중앙 상단 유지 또는 우측 이동(판단 위임, 기본: 중앙 상단 유지).
  - **우측(300px, `xl:` 에서만)**: 위→아래
    1. **오늘의 브리핑** 카드 — Phase 3-B 미구현이므로 **placeholder**(아이콘+“오늘의 브리핑” + "곧 제공" 또는 기존 `MorningBriefingPlayer` 연계). 중복 방지: 하단 플로팅 `MorningBriefingPlayer` 와 역할 겹치면 플로팅을 제거하거나 우측 카드만 두기(판단 위임, 보고에 결정 명시).
    2. **경쟁사 동향** — 기존 `CompetitorTrends` 를 본문에서 **우측으로 이동**(컴포넌트 재사용, 폭 맞게 컴팩트화).
    3. **트렌딩 키워드**(선택, 가벼움) — `keywords` 테이블 또는 mock `SAVED_KEYWORDS` 로 pill 목록. 데이터 부담되면 1차는 정적/간단 버전.
- 우측 레일 각 카드는 `Sidebar` 와 같은 톤(작은 제목·시맨틱 토큰·`rounded-2xl border bg-card`).

## 파트 E — 반응형
- **xl(≥1280)**: 3단(좌 Sidebar `w-56` + 중 피드 + 우 레일 300). 
- **lg(1024~1279)**: 좌 Sidebar + 중 피드(2단). **우측 레일은 숨기거나 피드 아래로** 스택.
- **< lg(모바일/태블릿)**: 1단. 좌 Sidebar = 기존 드로어 유지. 우측 레일 모듈(브리핑·경쟁사·트렌딩)은 **피드 아래로** 스택 노출.
- 카테고리 스트립: 모바일 가로 스크롤(`scrollbar-hide`). 헤더 검색: 파트 A 모바일 처리.
- 기존 가독 폭(#70 `max-w-screen-xl`)·다크모드(#68)·카드뷰(#69)·정렬(#75) 회귀 없을 것.
