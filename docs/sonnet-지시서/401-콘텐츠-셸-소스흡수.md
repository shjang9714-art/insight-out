## 0. 한 줄
**2,198줄을 쪼개는 슬라이스가 아니다.** `AdminContentManager` 는 통째로 탭 하나의 내용이 되고, 이번 작업은 **그 위에 셸을 씌우고 `소스 관리` 를 흡수하는 것**이다.

## 1. 착수 전 확인 결과 (현황대조 §5 규율)

### 1.1 ⚠️ 2,198줄은 겁줄 뿐이다 — 계획의 전제가 틀렸다

현황대조는 이 화면을 **"가장 크다"** 고 적었다. 열어보니 크기의 성격이 다르다.

`AdminContentManager` 는 **섹션이 여럿인 화면이 아니라, 목록 관리 화면 하나**다. 2,198줄의 내역:
```
카테고리 탭(1530) · 필터(1540) · 활성 필터 칩(1606) · 리스트 헤더(1654) ·
선택 작업 바(1670) · 데스크톱 테이블(1735) · 모바일 카드(1882) ·
페이지네이션(1981) · 편집 모달(2011~)
```
**전부 "목록 하나를 다루는 도구"다.** 탭으로 가를 경계가 내부에 없다.

→ **이 컴포넌트를 쪼개지 않는다.** 통째로 `발행 콘텐츠` 탭의 내용이 된다. 396~400 과 달리 **분해 작업이 0** 이다.
→ 따라서 이 슬라이스의 실제 일감은 **셸 씌우기 + 흡수**뿐이다. 줄 수가 시사하는 것보다 훨씬 작다.

### 1.2 ⚠️ 흡수 4건 중 이번에 되는 건 1건이다

현황대조 §3 은 `소스 관리`·`수집 설정`·`데이터 보강 재처리`·`AI 콘텐츠 보강` 4개를 흡수 대상으로 적었다. **네 화면을 다 열어보니 셋은 지금 흡수할 수 없다.**

| 흡수 대상 | 컴포넌트 | 카테고리 개념 | 판정 |
|---|---|---|---|
| **소스 관리** | `SourceManager` | ✅ **있다** — `type: news_site \| youtube_channel \| web_insight \| report_publisher`, `selectedType` 필터가 이미 구현돼 있다(357·365행) | **이번에 흡수** |
| 수집 설정 | `CrawlSettings` | ❌ 없다 — **전역 최소 본문 길이 하나**다 | 보류 |
| 데이터 보강 재처리 | `AdminContentProcessing` + `getEnrichJobs('data')` | ❌ 없다 — 전역 잡 러너 | 보류 |
| AI 콘텐츠 보강 | `getEnrichJobs('ai')` | ❌ 없다 — 전역 잡 러너 | 보류 |

**보류 사유가 핵심이다.** 최종안 §2.3 은 `뉴스 > 수집 설정`, `유튜브 > 수집 설정` 처럼 **카테고리별 진입점**을 전제한다. 그런데 실제 컴포넌트는 전역값 하나를 다룬다.

→ 이걸 그대로 `?category=뉴스` 아래 넣으면 **"뉴스의 수집 설정"처럼 보이는 전역 설정**이 된다. 운영자가 뉴스 탭에서 값을 바꾸면 유튜브까지 바뀐다. **잘못 흡수하는 편이 안 흡수하는 것보다 나쁘다.**
→ 카테고리별로 만들려면 **DB 스키마·API 변경이 필요하다 — 그건 (나)다.**

> **399 §1.1 · 400 §1.1 에 이어 세 번째로 실물 확인이 계획을 바꿨다.** 세 번 다 같은 원인이다 — 현황대조를 `import` 와 줄 수로 썼기 때문이다. **§7 에 이 패턴을 기록한다.**

## 2. 구현

### 2.1 신규 `src/components/admin/ContentHub.tsx`

`'use client'`. 396 패턴.

| 탭 value | 라벨 | 내용 |
|---|---|---|
| `list` | **발행 콘텐츠** | `AdminContentManager` **통째로** (기본 탭) |
| `sources` | **소스** | `SourceManager` — **현재 카테고리에 해당하는 type 으로 스코프** |

- `defaultTab = 'list'`
- `aria-label="콘텐츠 관리"`
- ⚠️ **탭을 2개보다 늘리지 않는다.** `수집 설정`·`보강` 탭을 빈 껍데기로 만들지 말 것(396 §1).

### 2.2 🔴 `key={sp.category}` 와 `?tab=` 의 충돌 — 이 슬라이스의 최대 위험

현재 page 는 **`key` 로 카테고리 전환 시 강제 리마운트**를 건다(1.3의 27행). `?tab=` 이 같은 URL 에 붙으면:

- `?category=뉴스&tab=list` → `?category=뉴스&tab=sources` 로 바뀔 때 **`sp.category` 는 그대로**이므로 `key` 는 안 바뀐다 → 리마운트 없음. **정상.**
- 그러나 `AdminTabShell` 이 `useTabParam` 으로 URL 을 갱신할 때 **`category` 파라미터를 보존하는지 반드시 확인할 것.** 날려버리면 카테고리가 초기화되어 **뉴스 탭에서 소스를 보고 돌아왔더니 전체 콘텐츠**가 된다.

→ **`useTabParam` 이 기존 searchParams 를 유지하며 `tab` 만 갱신하는지 코드로 확인하고, 아니면 이 슬라이스에서 `useTabParam` 을 고치지 말고 `ContentHub` 에서 우회할 것.** Shell·`useTabParam` 은 396·399·400 의 5개 화면이 이미 쓰고 있다 — **여기서 손대면 그 5개가 같이 깨진다.**

→ 확인 결과를 **§7 에 기록**한다.

### 2.3 소스 탭의 카테고리 스코프

`SourceManager` 는 `selectedType` 상태로 이미 타입 필터를 구현하고 있다(365행 `sources.filter(s => s.type === selectedType)`).

| `?category=` | 스코프할 `SourceType` |
|---|---|
| `뉴스` | `news_site` |
| `웹인사이트` | `web_insight` |
| `유튜브` | `youtube_channel` |

- **`selectedType` 초기값을 prop 으로 받도록만** 바꾼다. 필터 UI·등록 폼·CRUD 로직은 **무수정**.
- ⚠️ **필터를 잠그지 않는다.** 초기 선택만 해주고, 운영자가 `전체` 로 바꿀 수 있게 남긴다. 잠그면 `report_publisher`(외부리포트 발행처) 소스에 **접근 경로가 사라진다** — 현재 콘텐츠 카테고리 탭에 외부리포트가 없기 때문이다.
- 카테고리가 위 셋 중 어느 것도 아니면(무파라미터 등) **`전체`** 로 둔다.

### 2.4 `page.tsx`
- `AdminPageHeader` **제거**(Shell 이 렌더).
- `Suspense` + `key={sp.category ?? 'all'}` 는 **유지**. `ContentHub` 에 `category` 를 prop 으로 넘긴다.
- **`renderContent` 를 page 에서 만들지 않는다**(396 §3.2).

### 2.5 nav.ts
- `소스 관리`(`/admin/sources`) 항목을 **아직 지우지 않는다.** 라우트도 **살려 둔다.**
- 이유: `report_publisher` 소스는 콘텐츠 3탭 어디에도 대응 카테고리가 없다(§2.3). 지금 지우면 **접근 불가**가 된다.
- `description` 만 갱신: `"각 콘텐츠 소스 탭으로 이동 예정(S4)"` → `"콘텐츠 소스 등록·관리. 각 콘텐츠 화면의 소스 탭에서도 관리합니다."`
- **제거는 외부리포트 어드민이 정리된 뒤** 별도 슬라이스에서.

## 3. 하지 말 것
- 🔴 **`AdminContentManager` 를 쪼개거나 내부를 수정하지 않는다.** 2,198줄 전부 그대로 `list` 탭에 넣는다. 편집 모달·일괄 처리·필터 어느 것도 손대지 않는다.
- **`AdminTabShell`·`useTabParam` 무수정**(§2.2).
- `SourceManager` 는 **`selectedType` 초기값 prop 하나만** 추가. 그 외 무수정.
- `수집 설정`·`데이터 보강`·`AI 보강` **흡수하지 않는다**(§1.2). 라우트도 그대로 둔다.
- 최종안의 미구현 탭을 만들지 않는다.

## 4. 회귀 가드

**콘텐츠 목록 — 이 화면은 매일 쓰는 운영 도구다. 하나라도 깨지면 롤백.**
1. `?category=뉴스`·`웹인사이트`·`유튜브` 3개 진입이 각각 해당 카테고리를 연다.
2. 검색(300ms 디바운스)·소스·상태·본문 상태·페이지 크기 **필터 5종**이 동작한다.
3. 활성 필터 칩 표시·해제가 동작한다.
4. **일괄 선택 → 일괄 처리**(발행·보류·삭제 등)가 동작한다.
5. **편집 모달**이 열리고 저장된다. 썸네일 업로드·PDF 표지 재취득·원문 열람 포함.
6. 페이지네이션(서버 페이징)이 동작한다.
7. 검토 대기 카운트가 뜬다.
8. 모바일 폭에서 카드 리스트로 전환된다.
9. `EnrichJobsProvider` 진행 표시가 유지된다.

**탭·소스**

10. `?tab=sources` 직접 진입이 동작한다.
11. 🔴 **탭 전환 시 `?category=` 가 보존된다**(§2.2).
12. 소스 탭이 **해당 카테고리 타입으로 선택된 상태**로 열리고, `전체` 로 바꿀 수 있다.
13. 소스 **등록·수정·삭제·활성 토글·순서 변경**이 동작한다.
14. `/admin/sources` 직접 진입이 **여전히 동작한다**(§2.5).
15. 브레드크럼이 `콘텐츠 / 뉴스` 로 뜬다.
16. 헤더가 두 번 나오지 않는다.

## 6. 다음 — 402 는 아직 쓰지 않는다

`수집 설정`·`데이터 보강`·`AI 보강` 흡수는 **디렉터 결정이 필요하다**(§1.2). 셋 다 전역 기능인데 최종안은 카테고리별을 전제한다. 선택지:

| 안 | 내용 | 성격 |
|---|---|---|
| **A** | 전역인 채로 `시스템` 그룹에 남긴다. 최종안 §2.3 을 이 부분만 수정. | (가) — 문서만 고침 |
| **B** | 카테고리별로 만든다. `crawl_settings` 에 category 컬럼 추가, 잡 러너에 카테고리 인자. | **(나)** — 스키마·API 변경, 수희 SQL 필요 |
| **C** | 전역인 채로 각 콘텐츠 화면에 **읽기 전용 표시**만 하고 수정은 시스템 화면에서. | 절충 |

**401 완료 후 디렉터에게 물을 것.** 지금 402 를 쓰면 또 실물과 어긋난다.
