## 0. 한 줄

붙여넣기/URL 임포트 폼의 본문을 **마크다운 에디터(서식 툴바 + 미리보기)** 로 바꾸고, 마크다운 원본을 `body_markdown`에 저장, 상세 페이지는 `body_markdown` 있으면 **`ReportMarkdown`(react-markdown, raw HTML 미렌더=안전)** 으로 렌더. 검색·스니펫은 기존 평문(`body_original`) 유지.

## 1. 현행 진단 (검증된 코드 사실)

- 마크다운 렌더 자산: `react-markdown@10`+`remark-gfm` 설치. `src/components/reports/ReportMarkdown.tsx` = 스타일 완비 렌더러(제목·목록·인용·표·코드, **raw HTML 미렌더로 안전**). → 상세 렌더 재사용.
- 붙여넣기: `TextPasteForm.tsx` `FormState.bodyText`(평문 textarea) → `POST /api/admin/paste`(:87 `cleanHtml(bodyText)` → `body_original`). URL 임포트(210)는 TextPasteForm를 프리필 재사용 → 에디터 자동 적용.
- 상세: `src/app/dashboard/contents/[id]/page.tsx` :393 `<ArticleBodyLoader ... snippet=... />`(본문 lazy 평문 렌더, `whitespace-pre-wrap`). content select :125.
- `contents`엔 `body_markdown` 없음 → 신규 컬럼(212 SQL).

## 2. 구현

### 2-A. SQL 핸드오프(수희, 먼저 푸시)
- `docs/sql-handoff/212-body-markdown.sql`(작성됨): `contents.body_markdown text` nullable 추가. `src/lib/types.ts` `Content`에 `body_markdown?: string | null` 추가.

### 2-B. 마크다운 에디터 — `src/components/admin/MarkdownEditor.tsx`(신규, `'use client'`, 신규 dep 없음)
- Props: `value: string`, `onChange: (v: string) => void`, `placeholder?`.
- 구성: **서식 툴바**(버튼) + **textarea**(마크다운 원본) + **미리보기 토글**(ReportMarkdown로 렌더).
- 툴바 최소 세트(선택 영역 wrap/삽입):
  - 제목(H2 `## `, H3 `### ` 줄머리), 굵게(`**…**`), 기울임(`*…*`), 목록(`- ` / `1. ` 줄머리), 링크(`[선택](url)`), 인용(`> ` 줄머리).
  - textarea `selectionStart/End`로 선택 텍스트 감싸기/줄머리 삽입, 갱신 후 커서 유지(가능 범위).
- "미리보기" 토글 시 `<ReportMarkdown>{value}</ReportMarkdown>`로 결과 표시(편집↔미리보기 전환). 어드민 전용이라 마크다운 원본 노출 무방.
- admin-scope 스타일(203/204 토큰), 툴바 버튼은 세그먼트/아이콘 버튼(생 red-* 금지).

### 2-C. TextPasteForm 연결
- 본문 `bodyText` textarea(현행) → `<MarkdownEditor value={form.bodyText} onChange={(v)=>setForm(f=>({...f, bodyText: v}))} />`.
- 제출 시 payload에 `bodyMarkdown: form.bodyText` 추가(기존 `bodyText`는 그대로 두거나 동일값). **프리필(210)로 들어온 평문도 유효한 마크다운**이라 그대로 편집 가능.

### 2-D. paste 라우트 — `src/app/api/admin/paste/route.ts`
- body에 `bodyMarkdown?: string` 수용.
- 저장:
  - `body_original` = 기존대로 **평문**(검색·스니펫·요약용). bodyMarkdown 있으면 `stripMarkdown(bodyMarkdown)`, 없으면 기존 `cleanHtml(bodyText)`.
  - `body_markdown` = bodyMarkdown(있을 때). **컬럼 미적용(42703) 대비 graceful**: insert에 바로 넣되, 에러 시(컬럼 없음) `body_markdown` 없이 재시도하거나 post-insert update(try/catch)로 분리 — **SQL 전에도 paste 저장이 깨지지 않게**.
- `stripMarkdown(md)` 소유틸(신규, `lib/contents` 등): `#`·`*`·`_`·`>`·`` ` ``·`- `/`1. ` 제거, `[텍스트](url)`→`텍스트`, 여분 공백 정리(검색/스니펫 품질용, 완벽할 필요 없음).

### 2-E. 상세 렌더 — `dashboard/contents/[id]/page.tsx`
- content select에 `body_markdown` 추가하되 **컬럼 미적용 대비 graceful**: 별도 guarded 조회(try/catch → 없으면 null) 또는 select 실패 시 폴백. (전 콘텐츠 상세가 안 깨지게 최우선.)
- 렌더 분기: `content.body_markdown`(비어있지 않음) 있으면 `<ReportMarkdown>{content.body_markdown}</ReportMarkdown>`(서버 렌더), 없으면 **기존 `ArticleBodyLoader`** 그대로(크롤 콘텐츠 lazy 평문). 스니펫/요약 로직 불변.

## 3. 회귀 가드 / 비기능 요건
- **신규 npm 0**(react-markdown/remark-gfm 재사용). SQL 1컬럼(nullable). 42703 graceful → SQL 적용 전에도 paste·상세 안 깨짐(기능은 적용 후 점등).
- 크롤 콘텐츠(대다수)는 `body_markdown` null → 기존 평문 렌더 100% 동일(회귀 0). 검색·스니펫·카드는 `body_original`/`summary_ko`(평문) 유지.
- **보안**: react-markdown 기본이 raw HTML 미렌더 → XSS 표면 없음(DOMPurify 불필요). remark-gfm 표/링크만.
- 203/204/209 토큰·스타일 유지. 공개 상세만 마크다운 렌더 추가(수기 콘텐츠 한정). 비어드민 무영향.
- 편집 모달 서식 편집은 범위 밖(후속): 기존 콘텐츠 body_markdown 편집은 다음 슬라이스.

## 4. 검증 (Sonnet 자체)
1. `npx tsc --noEmit` 0 / `npx eslint` 0 / build.
2. (로컬 212 SQL 적용 후) 붙여넣기 탭에서 마크다운 에디터로 제목·굵게·목록·링크·인용 작성 → 미리보기 정확 → 저장 → 상세에서 서식대로 렌더.
3. URL 임포트로 프리필된 본문을 에디터에서 서식 편집·저장 → 상세 렌더.
4. **SQL 미적용 상태**에서도 붙여넣기 저장·상세(기존 평문) 안 깨짐(graceful). 크롤 콘텐츠 상세 기존과 동일.
5. 검색/카드 스니펫이 마크다운 기호 없이 평문으로 보임(stripMarkdown). 라이트·다크 스크린샷.
