# [03] 온보딩 UI + 추천 피드 컴포넌트 지시서

> 원본 워크스페이스 경로: 추천피드_설계/03_온보딩UI_지시서.md, Opus 작성

## 작업 목적

홈 대시보드의 기존 "최근 피드" 슬롯을 다음 3가지 상태로 분기 렌더링한다:
① 신규 사용자 → 인라인 키워드 선택 UI (슬롯 전체)
② 키워드 선택 진행 중 → 선택 + 미리보기
③ 기존 사용자 → 추천 피드 + [관심사 편집] 진입점

## 산출물

### 신규/수정 파일

- `components/feed/OnboardingKeywordPicker.tsx` — 인라인 키워드 선택 UI
- `components/feed/RecommendedFeed.tsx` — 추천 피드 (슬롯 60/20/10/10)
- `components/feed/FeedSlot.tsx` — 상태 분기 라우터 컴포넌트
- `components/feed/EditPreferencesButton.tsx` — 관심사 편집 진입점
- `app/(home)/page.tsx` (또는 기존 홈) — `FeedSlot` 삽입
- `lib/preferences.ts` — 선호 조회/저장 헬퍼 (Supabase 클라이언트 래퍼)

### API 사용

- 04번 지시서에서 만들 `/api/feed/recommended?slot=personalized|trending|editor|explore` 호출
- 키워드 마스터 목록은 `/api/keywords/top?service_id=<uuid>&limit=30` (없으면 본 작업에서 신설)

## 컴포넌트 명세

### `FeedSlot` (서버 컴포넌트)

```ts
// pseudo
const { data: { user } } = await supabase.auth.getUser()
const prefs = await getUserPreferences(user.id)  // user_preferences 카운트

if (prefs.count === 0 && !prefs.skipped) {
  return <OnboardingKeywordPicker />
}
return <RecommendedFeed showEditButton />
```

> 스킵 상태는 `user_preferences`에 source='onboarding', keyword_id=NULL이면 의미가 모호 →
> 별도 컬럼 대신 클라이언트 `localStorage.feed_onboarding_skipped` 또는
> `user_service_prefs` sentinel row 중 후자가 서버 단일 진실원에 가까움.
> **결정**: `user_service_prefs`에 source='onboarding_skip', weight=0인 row(service_id=NULL 허용 컬럼 필요) 존재 시 스킵으로 간주.
> ⚠️ `service_id`가 NOT NULL이면 sentinel row 저장 불가 → 02 마이그레이션에 `onboarded_at` / `is_skipped` 컬럼을 `user_preferences` 또는 별도 `user_onboarding_state` 테이블로 도입하는 안이 더 깔끔. **02 검수 시 재논의.**
>
> **갱신 (84번 작업 시점)**: 위 논의는 `users.feed_onboarding_skipped` 컬럼 도입(커밋 `0e89461`)으로 해소됨. sentinel row 방식은 사용하지 않고 해당 컬럼을 단일 진실원으로 사용한다.

### `OnboardingKeywordPicker` (클라이언트)

상태:
- `selectedServiceId: string | null` (services.id, uuid)
- `selectedKeywordIds: string[]` (keywords.id, uuid, 3개 이상 권장, 최대 10개)
- `previewItems: ContentCard[]` — 칩 클릭 시 1~2건 미리보기

UI 구조:
```
┌─ 슬롯 전체 ──────────────────────────────┐
│ 🎯 관심 키워드를 골라 맞춤 피드를 만들어요  │
│                                          │
│ [Connectivity] [AICC] [클라우드] ...     │ ← 서비스 토글 (services 테이블)
│                                          │
│ #5G  #IDC  #UCaaS  #생성형AI  ...        │ ← 키워드 칩 (가변)
│                                          │
│ ┌ 미리보기 ────────────────────────────┐ │
│ │ [최근 콘텐츠 카드 1~2건]             │ │
│ └────────────────────────────────────┘ │
│                                          │
│ 선택: 4 / 최대 10                        │
│ [건너뛰기]            [추천 피드 시작 →] │
└──────────────────────────────────────────┘
```

동작:
- 서비스 클릭 → `/api/keywords/top?service_id=<uuid>` 호출 → 칩 갱신
- 키워드 칩 클릭 → 토글 추가/제거 + 디바운스 후 미리보기 갱신
- [추천 피드 시작] → `POST /api/preferences/bootstrap` (service_id + keyword_ids[] 전송) → 부모에 완료 콜백
- [건너뛰기] → `POST /api/preferences/skip` → 스킵 마커 저장 → fallback 피드 렌더링

> 참고: 기존 `user_services` 테이블은 사용자가 마이페이지에서 명시 핀한 담당 서비스로, **본 온보딩에서 자동 INSERT하지 않음**. 추천용 가중치는 `user_service_prefs`에만 기록.

### `RecommendedFeed`

슬롯 비율:
- `personalized`: 6건
- `trending`: 2건
- `editor`: 1건
- `explore`: 1건

각 슬롯은 병렬 fetch. 결과를 한 줄(또는 그리드)에 슬롯 라벨과 함께 배치.
빈 슬롯(예: explore 0건)이면 personalized로 fallback.

`showEditButton` prop이 true면 상단 우측에 `EditPreferencesButton`을 렌더.

### `EditPreferencesButton`

클릭 시 `OnboardingKeywordPicker`를 모달이 아닌 **같은 슬롯 자리에 다시 렌더링**(상태 ① 복귀).
저장 완료 시 `RecommendedFeed`로 복귀.

## 데이터 흐름

```
신규 로그인
   ↓
FeedSlot SSR — user_preferences count=0
   ↓
<OnboardingKeywordPicker /> 렌더
   ↓ 키워드 선택
POST /api/preferences/bootstrap
  → user_preferences (source='onboarding') bulk insert
  → user_service_prefs upsert
   ↓
router.refresh() → FeedSlot 재평가 → <RecommendedFeed />
   ↓ 콘텐츠 카드 클릭
POST /api/content_views (content_id, dwell_seconds=0)
   ↓ 페이지 이탈 시 dwell 업데이트 (visibilitychange 이벤트)
PATCH /api/content_views/:id
```

## API 신설 (이 작업에서 포함)

- `POST /api/preferences/bootstrap` body: `{ service_id: string (uuid), keyword_ids: string[] (uuid[]) }`
- `POST /api/preferences/skip`
- `GET /api/keywords/top?service_id=<uuid>&limit=30` — content_keywords/content_services 조인해 콘텐츠 수 기준 상위 키워드
- `POST /api/content_views` body: `{ content_id: string (uuid), dwell_seconds?: number }`

> `/api/feed/recommended`는 04번 지시서에서 구현.

## 주의사항

- shadcn/ui 컴포넌트 우선 사용 (Button, Card, Badge, Toggle, Toast)
- 클라이언트 컴포넌트는 `'use client'` 최소화 — 가능한 한 서버 컴포넌트로 유지
- Supabase 호출은 RLS 위배 안 되게 user_id 항상 `auth.uid()` 기반
- 위임 시점 커밋 금지. Opus 검수 통과 후 한 번에 커밋.
