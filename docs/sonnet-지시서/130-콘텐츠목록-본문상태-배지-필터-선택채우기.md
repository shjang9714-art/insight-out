## 배경

129로 "기사 풀본문 채우기"(일괄·기간·cron)는 됐으나, 어드민 목록에서 **어떤 행이 풀본문인지/스니펫인지/미시도인지 안 보이고**, 풀본문 여부로 **필터**도 못 하고, **선택한 행만 골라 채우기**도 없음. enrich 결과는 `body_fetched_at`(시도 시각, improved·marked 둘 다 채워짐)뿐이라 **성공/실패 구분에 본문 길이가 필요**. → 길이 생성컬럼을 토대로 3-state 배지·서버사이드 필터·선택 채우기 제공.

**상태 정의(임계 400 = `ENRICH_MIN_BODY_LEN`):**
- **풀본문**: `body_fetched_at IS NOT NULL` && `body_len >= 400`
- **스니펫**(추출 실패/짧음): `body_fetched_at IS NOT NULL` && `body_len < 400`
- **미시도**: `body_fetched_at IS NULL`

`body_len` 미존재(SQL 미적용) 환경에선 **2-state로 degrade**: 처리됨(`body_fetched_at` not null) / 미시도.

## A. SQL 핸드오프 (수희) — `docs/sql-handoff/130-body_len-컬럼.sql` (신규)
```sql
-- 130: contents.body_len 생성컬럼(풀본문/스니펫 구분용). 멱등.
-- char_length 는 immutable → STORED 생성컬럼 가능. body_original 갱신 시 자동 재계산.
alter table public.contents
  add column if not exists body_len integer
  generated always as (char_length(body_original)) stored;

-- 필터 성능(선택): 부분 인덱스
create index if not exists idx_contents_body_len on public.contents (body_len);

-- 확인
select
  count(*) filter (where body_fetched_at is not null and body_len >= 400) as 풀본문,
  count(*) filter (where body_fetched_at is not null and body_len < 400)  as 스니펫,
  count(*) filter (where body_fetched_at is null)                          as 미시도
from public.contents;
```

## B. 목록 쿼리 + 타입 — `AdminContentManager.tsx`

1. `AdminContentRow` 인터페이스에 추가: `body_fetched_at: string | null`, `body_len: number | null`.
2. 목록 select(현재 `'id, title, category, status, collected_at, bookmark_count, sources(name)'`)에 **`body_fetched_at, body_len`** 추가.
3. **graceful fallback**: select 실행이 `42703`(undefined column `body_len`)로 실패하면 `body_len` 제외 select로 1회 재시도하고, 각 행 `body_len = null` 처리. (SQL 미적용 시에도 목록 안 깨짐.) — fetch 헬퍼에 try/catch + 에러코드 분기.

## C. 본문 상태 배지 — 테이블에 "본문" 컬럼 추가

- thead: `상태`와 `수집일` 사이에 `<th>본문</th>` 추가.
- tbody 각 행: 상태 셀 옆에 작은 chip. 파생 함수:
  ```ts
  function bodyState(r: AdminContentRow): 'full' | 'snippet' | 'none' {
    if (!r.body_fetched_at) return 'none'
    if (r.body_len == null) return 'full'   // degrade: 처리됨을 풀본문으로 간주(=처리됨 라벨)
    return r.body_len >= 400 ? 'full' : 'snippet'
  }
  ```
- 라벨/스타일(하드코딩 hex 금지, 기존 의미색 유틸 사용):
  - full → `풀본문` (emerald 계열, 예 `text-emerald-700`)
  - snippet → `스니펫` (amber 계열, 예 `text-amber-600`)
  - none → `미시도` (`text-muted-foreground`)
  - degrade(body_len==null)일 땐 full 라벨을 **`처리됨`**으로 표기(길이 모름 → 성공 단정 회피). `bodyLenAvailable` 플래그(아무 행이라도 body_len!=null) 기준.
- chip 마크업은 기존 status 배지 스타일(line~822) 톤과 통일.

## D. 본문 상태 필터

- 기존 필터 영역(카테고리 탭/소스/상태 셀렉트 근처)에 **"본문 상태"** Select 추가: `전체 / 풀본문 / 스니펫 / 미시도`. 상태 `const [bodyFilter, setBodyFilter] = useState<'all'|'full'|'snippet'|'none'>('all')`.
- fetchContents의 목록 쿼리 **및 count 쿼리** 둘 다에 서버사이드 조건 적용(헬퍼로 중복 제거):
  - none: `.is('body_fetched_at', null)`
  - full: `.not('body_fetched_at','is',null).gte('body_len',400)`
  - snippet: `.not('body_fetched_at','is',null).lt('body_len',400)`
- bodyFilter 변경 시 page를 1로 리셋(기존 필터들과 동일 패턴).
- **degrade**: body_len 미적용 환경에선 풀본문/스니펫 선택 시 빈 결과가 되므로, `bodyLenAvailable===false`면 해당 두 옵션을 비활성(disabled) 처리하거나 드롭다운에서 숨김. (미시도/전체는 항상 동작.)

## E. 다중선택 → "선택 풀본문 채우기"

### E-1. 엔드포인트 — `src/app/api/admin/body-backfill/by-ids/route.ts` (신규)
- `POST` 어드민 게이트(기존 `verifyAdmin` 패턴 복사 또는 공유). `runtime nodejs`, `maxDuration 300`.
- body: `{ ids: string[] }`. 빈 배열 → 400. **clamp ids 최대 50건**(초과는 앞 50만; 응답에 `truncated` 표시).
- 조회: `.from('contents').select('id, original_url, body_original').in('id', ids).not('original_url','is',null)` — **`body_fetched_at` 조건 없음**(실패/처리됨도 강제 재시도 허용 = 선택의 의미).
- 각 행 `enrichOneBody(admin, row)` 순회, **270초 time-box**(데드라인 초과 시 중단, 남은 건 미처리로 반환).
- 응답 `{ processed, improved, skipped, remaining? , truncated }`.
- (권장) E의 루프/타임박스를 `enrich-body.ts` 헬퍼(`enrichByIds(admin, ids, { deadline })`)로 추출해 라우트는 얇게.

### E-2. UI — 일괄 작업바(line~720)
- "일괄 보이기/숨기기" 옆에 버튼 **"선택 풀본문 채우기"** 추가(`disabled={isBulkWorking || isEnrichingSel}`).
- 핸들러: `[...selectedIds]` → `POST /api/admin/body-backfill/by-ids` → 결과 문구(`선택 ${processed}건 처리 · 개선 ${improved} · 실패 ${skipped}${truncated?' · 50건 초과분 제외':''}`) → **목록 새로고침**(fetchContents 재호출)로 배지 갱신 → 선택 해제.
- 50건 초과 선택 시 안내(문구 또는 비활성). 진행 중 스피너.
