## 배경 (David)
소스별 "지금 수집"이 **하나 돌면 다른 건 기다려야** 함 — 모든 수집 버튼이 단일 `crawlProgress.status==='running'` 에 묶여 비활성. **서버 `runCrawl`·crawl-now 는 이미 동시 호출 가능**(전체 수집은 `Promise.allSettled` 병렬). 병목은 **클라이언트가 작업 1개만 추적**하는 것. → 소스별 독립 추적으로 **동시 여러 소스 수집** 허용.

핵심: 진행 엔드포인트(GET crawl-now)는 시간창 기반(소스 격리 X)이라 동시 작업엔 부적합 → **소스별 완료는 `/api/admin/source-status` 의 `lastFinishedAt`(소스별 최신 완료시각)로 감지**한다.

## 작업 — `SourceManager.tsx` (클라이언트만)

### 1. 소스별 진행 상태
- 신규 상태: `const [crawlingIds, setCrawlingIds] = useState<Set<string>>(new Set())` + `const crawlStartedRef = useRef<Record<string, number>>({})` (sourceId → 시작 ms).
- 전체 수집(`crawlJob`/`crawlProgress`)은 **그대로 유지**(전체용). 개별만 분리.

### 2. `handleCrawlSource(sourceId)` — 비차단 동시 실행
- 글로벌 `crawlJob`/localStorage 건드리지 않음. 대신:
  ```ts
  crawlStartedRef.current[sourceId] = Date.now()
  setCrawlingIds(prev => new Set(prev).add(sourceId))
  try {
    const res = await fetch('/api/admin/crawl-now', {
      method: 'POST', headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ sourceId, backfillDays: crawlDays }),
    })
    if (!res.ok) throw new Error((await res.json())?.error ?? '수집 시작 실패')
  } catch (e) {
    setCrawlingIds(prev => { const n = new Set(prev); n.delete(sourceId); return n })
    setError(e instanceof Error ? e.message : '수집 시작에 실패했습니다.')
  }
  ```
- 여러 소스 버튼을 연달아 눌러도 각자 set 에 추가 → 병렬.

### 3. 완료 감지 폴링 (source-status)
- effect: `crawlingIds.size > 0` 일 때만 인터벌(~4초) 가동. 매 틱에 `/api/admin/source-status` fetch:
  - 각 `sid ∈ crawlingIds` 에 대해 `info = statusMap[sid]`:
    - `info?.lastFinishedAt` 있고 `new Date(info.lastFinishedAt).getTime() > crawlStartedRef.current[sid]` → **완료** → crawlingIds 에서 제거.
    - 안전장치: `Date.now() - crawlStartedRef.current[sid] > 120_000`(120초) → 타임아웃 제거(멈춘 작업 방지).
  - 완료/타임아웃으로 set 변경 시 `setSources` 상태 배지도 갱신(기존 source-status 반영 로직 재사용 — 이미 loadStatus 가 있으면 그걸 호출).
- `crawlingIds.size === 0` 이면 인터벌 정리.

### 4. 개별 버튼 — 자기 작업만 비활성
- 개별 "지금 수집" 버튼(909): `disabled={crawlingIds.has(src.id)}` (글로벌 `isStartingCrawl || crawlProgress?.status==='running'` 의존 **제거**).
- 수집 중인 소스는 스피너/“수집 중” 표시(`crawlingIds.has(src.id)`). 아이콘 버튼이면 `Loader2 animate-spin`.

### 5. 전체 수집 버튼 — 기존 유지
- `handleCrawlNow`/전체 progress 바·버튼 비활성(`crawlProgress?.status==='running'`)은 그대로. 개별 수집과 독립.

## 회귀 / 주의
- DB·API 무변경. 동시 호출은 서버가 `after()` 백그라운드로 각각 처리(Vercel 동시성 한도 내). 과도한 동시 클릭은 사용자 재량(필요 시 후속에 동시 N개 제한).
- source-status 는 7일 집계라 `lastFinishedAt` 이 직전 실행값일 수 있음 → **시작 ms 비교**로 이번 실행만 완료 처리(직전 값은 `< startedAt` 라 무시). 첫 수집(로그 0)도 완료 후 timestamp 생겨 감지.
- 전체 수집이 동시에 돌면 개별 소스 `lastFinishedAt` 이 전체 로그로 갱신될 수 있음 → 그 소스도 수집된 것이라 완료 처리 무방.
- 120초 타임아웃은 UI 잠금 해제용(실제 수집은 백그라운드 계속).
- `'use client'` 유지·UI 한국어(#1)·토큰 색(#9).
