## 배경 (마스터플랜 §3④)

어드민 메뉴 14개(개요1·콘텐츠3·수집2·분류엔진3·AI·처리4·발행1 + 시스템1). 활성표시·그룹은 76에서 됨. 빠진 것 = **메뉴 검색**(많은 메뉴에서 빠른 점프) + 그룹 의미 정리("AI·처리"가 큐레이션+인프라 혼재).

## 설계 결정 (Opus)

1. **메뉴 검색이 핵심 산출물**: 사이드바 상단(로고 아래)에 검색 입력. 입력 시 전 메뉴(그룹+하단 포함)를 label·description 기준 필터해 **평면 결과**로 표시. 빈 입력이면 기존 그룹 네비 그대로.
2. **그룹 정리는 보수적**: "AI·처리"(4개)를 의미별 2그룹으로 — **이슈·인사이트**(이슈 관리·AI 인사이트) / **연동·사용량**(번역·LLM 관리). 나머지 그룹·라우트·라벨 **무변경**(되돌리기 쉬움). href 변경 없음.
3. 활성표시·disabled·badge 렌더 로직은 현행 유지(검색 결과 항목도 동일 스타일 재사용).

## 작업

### A. nav 그룹 정리 — `src/lib/admin/nav.ts`
- 기존 `'AI·처리'` 그룹(이슈 관리·AI 인사이트·번역·LLM 관리) → **2그룹으로 분리**:
  ```
  { group: '이슈·인사이트', items: [ 이슈 관리, AI 인사이트 ] },
  { group: '연동·사용량',   items: [ 번역, LLM 관리 ] },
  ```
- 순서: 개요 · 콘텐츠 · 수집 · 분류 엔진 · **이슈·인사이트** · **연동·사용량** · 발행. (하단 시스템 그대로.)
- 아이콘·href·description 변경 금지. AdminNavItem/Group 타입 무변경.

### B. 메뉴 검색 — `src/components/admin/AdminSidebar.tsx` (client)
- `useState('')` 검색어 `query`. 로고 아래에 검색 input(돋보기 아이콘 `Search`, placeholder "메뉴 검색…", `aria-label`). `print:hidden` 불필요(어드민은 인쇄 대상 아님).
- **평면 항목 목록** 구성: `[...ADMIN_NAV_GROUPS, ADMIN_NAV_BOTTOM].flatMap(g => g.items.map(it => ({ ...it, group: g.group })))`.
- `query.trim()` 있으면:
  - 필터: `label` 또는 `description`에 query(소문자 비교) 포함. disabled 항목은 제외(또는 흐리게 — 택1, 일관).
  - 렌더: 그룹 헤더 없이 평면 리스트. 각 행 = 아이콘 + label + 우측에 `group` 작은 muted 칩(어느 그룹인지). 기존 Link 스타일·활성표시 재사용.
  - 결과 0건: "일치하는 메뉴가 없습니다." muted 안내(휑하지 않게).
- `query` 비어 있으면: **기존 그룹 네비 그대로** 렌더(현 코드 경로 유지).
- (선택, 가산점) 키보드: input에서 `Enter` → 첫 결과로 `router.push`. `/` 키로 input 포커스(전역, 입력 중이 아닐 때). 과하면 생략 가능.

## 디자인 준수 (§4)
- 검색 input: `rounded-md border border-border bg-background`, focus ring brand-600/30, text ≥12px. 하드코딩 hex 금지(토큰만, AGENTS §9).
- 결과 행: 기존 사이드바 항목과 동일 밀도·색(제목+그룹칩 2요소). 색 배지 남발 금지.
- 빈 상태 안내 문구 필수. 다크모드 토큰 양립.
