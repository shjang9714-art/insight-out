### 1.1 "오늘 할 일"은 **이미 있고, 클릭 이동도 된다** (`AdminTodoBlock.tsx`)
타일 4종 전부 `<Link href>`로 감싸져 있다(`:79-83`):
- 검토 대기 → `/admin/contents?status=pending`
- 수집 실패 → `/admin/crawl-logs`
- 소스 오류 → `/admin/sources`
- 승인 대기 → `/admin/users` (`pendingUsers !== null`일 때만 조건부 렌더)

→ **스펙의 "카드를 클릭하면 상세로 이동"은 이미 충족돼 있다.** 새로 만들 것 없음.
→ 스펙이 추가하라는 **"작업 이력"·"운영 게시판"은 넣지 않는다.** 숫자도 조치도 없는 **그냥 메뉴**다(사이드바에 이미 있다). "오늘 할 일"에는 **건수가 있고 조치가 필요한 것**만 둔다.

> ✅ **§1 재검증 (2026-07-13, 330 배포 후 `9c5b405` 기준)** — 330은 `nav.ts`·`ai-jobs`만 건드렸고 **이 지시서의 대상 파일은 하나도 안 건드렸다.** 아래 라인 참조 전부 유효함을 재확인했다.

### 1.2 🔴 "데이터 점등"은 정보량이 사실상 0이다 (`AdminOpsSignals.tsx:125`)
- 칩 5개(이슈·엔티티·인사이트·시그널·보고서) + **2색 도트**: `value > 0` → 초록, `0` → 회색 (`:137`)
- **3색 신호등이 아니라 켜짐/꺼짐이다.** "0인 항목은 SQL 적용/수집 후 점등됩니다" 안내가 붙어 있다 → **초기 셋업 확인용이었지 일상 운영 지표가 아니다.**
- **Link import 0회** — 클릭해도 아무 데도 못 간다.

### 1.3 "운영 현황" KPI (`:296-374`) — 유형별 분해가 **이미 있다, 캡션으로**
- 총 콘텐츠(`:302`) → `/admin/contents` · **아래에 `CATEGORIES.map`으로 `뉴스 N 리포트 N 웹인사이트 N 유튜브 N AI보고서 N` 캡션 한 줄**(`:309-313`)
- 오늘 수집(`:317`) → 동일하게 캡션 병기(`:324-328`)
- 북마크된 콘텐츠(`:332`) → `/admin/contents?bookmarked=1` (집계는 `contents.bookmark_count > 0` head count — `:83`)
- 전체 사용자(`:342`) · 활성 소스(`:352`)
- **리서치 반영**(`:365`) — `<div>`, **링크 아님**, `cursor-default opacity-60`, **"준비중"**

> ⛔ **카테고리는 뉴스·리포트·웹인사이트·유튜브·AI보고서 5종이다**(`page.tsx:24`). **"PDF"는 카테고리가 아니다** — 리포트의 파일 형식이다. 스펙 예시의 PDF는 무시할 것.

### 1.4 "수집 분석"은 대시보드 본문에 인라인이다 (`:377-382`)
`DashboardCharts.tsx` — recharts 차트 4개(카테고리 분포 · 상태 분포 · 최근 14일 수집 추이 · 소스 기여 Top10). 전부 클릭 시 `/admin/contents?...` 필터로 이동.
`chartData`에 `todayCategoryDist`가 직렬화돼 넘어가지만(`page.tsx:253`) **`DashboardCharts` 내부에서 미사용**(`:45` 구조분해에 없음) — **죽은 prop.**

## 3. 구현

### 3-1. "데이터 점등" 카드 **제거** — 카드만 지우면 절반만 한 것이다

**(a) UI** — `AdminOpsSignals.tsx`
- 우측 "데이터 점등" 카드(`:123-140` 부근)를 삭제. 2열 그리드 → **1열**.
- 섹션 제목: `:82` `title="운영 신호등"` **→ `"사용량 및 수집 관리"`** (스펙 §1-1 B)
- `:82` `hint="사용량 한도와 데이터 점등 상태"` → **점등 언급 제거**
- 점등용 props(이슈/엔티티/인사이트/시그널/보고서 카운트)를 **인터페이스에서 제거**

**(b) ⭐ 집계 쿼리까지 제거** — `src/app/admin/page.tsx` **3곳** (재검증에서 확인)
```
:68   // 신규 — 데이터 점등
:116  // 데이터 점등
:222  // ── 데이터 점등 집계 ──────────────────────────
:283  {/* ④ 운영 신호등 */}   ← 주석도 고칠 것
```
**카드만 지우고 쿼리를 남기면, 아무도 안 보는 값을 매 로드마다 DB에서 긁어온다.** 대시보드는 이미 무겁다(속도개선 316 레인이 도는 중이다). **반드시 같이 걷어낼 것.**

### 3-2. "수집 분석" → **팝업(Dialog)** 으로 내린다
- `page.tsx:377-382` 의 인라인 섹션을 **제거**한다.
- 대신 **"수집 분석 보기" 버튼** 하나를 둔다. 위치: "콘텐츠 수집현황" 섹션 헤더 우측.
- 클릭 → `Dialog`(`@/components/ui/dialog`, 308에서 쓴 것과 동일)로 `<DashboardCharts />` 를 띄운다.
- **`DashboardCharts` 내부는 건드리지 말 것.** 차트 4개와 클릭 이동을 그대로 유지한다.
- **죽은 prop `todayCategoryDist` 제거** (§1.4) — 넘기지도, 계산하지도 않는다.

> Dialog는 `max-w-5xl` 이상 + 내부 스크롤이 필요하다. 차트 4개가 2열 그리드다.

### 3-3. "운영 현황" → **"콘텐츠 수집현황"** + 유형별 시인성 강화
- 섹션 제목 변경.
- **총 콘텐츠 / 오늘 수집**: 지금의 캡션 한 줄(`:309-313`, `:324-328`)을 **유형별 카드/막대로 승격**한다.
  ```
  총 콘텐츠  12,480건
  ┌──────┬──────┬──────────┬───────┬─────────┐
  │ 뉴스  │ 리포트│ 웹인사이트 │ 유튜브 │ AI보고서 │
  │ 8,920│  620 │   1,210  │ 1,240 │    490  │
  └──────┴──────┴──────────┴───────┴─────────┘
  ```
  각 유형은 **`/admin/contents?category=…` 로 이동**해야 한다(현재 캡션은 링크가 아니다).
- **"리서치 반영"(`:365`)** — "준비중" 비활성 카드다. **이번엔 그대로 둔다**(범위 밖). 단 `opacity-60 cursor-default`가 의도된 것인지 보고할 것.
- **"북마크된 콘텐츠"** — 클릭 시 지금은 콘텐츠 목록 필터로만 간다. **"누가 북마크했는지"는 후속 슬라이스다**(bookmarks × users join이 어드민에 0곳). 이번엔 **건드리지 않는다.**

### 3-4. 섹션 순서 정리
스펙의 관제 화면 순서로 맞춘다:
```
1. 최근 실패한 작업        (AdminFailedJobsCard — 유지)
2. 오늘 할 일             (AdminTodoBlock — 유지)
3. 사용량 및 수집 관리      (AdminOpsSignals[점등 제거] + AdminContentHealth)
4. 콘텐츠 수집현황         (KPI + [수집 분석 보기] 버튼)
5. 사용자 현황            (전체 사용자 — DAU/MAU는 후속)
```
`AiRefreshButton`(`:281`)은 현재 오늘할일과 신호등 **사이에 끼어 있다.** 관제 흐름을 끊으므로 **"사용량 및 수집 관리" 섹션 안이나 페이지 우상단으로** 옮길 것.

> **주의**: 소스 주석의 번호(①②③④⑤)와 실제 렌더 순서가 이미 어긋나 있다. **주석도 같이 고칠 것.**

## 4. 회귀 가드

- ⛔ **`nav.ts`를 건드리지 말 것.** 330이 단독 소유한다. 대시보드 제목은 `nav.ts:54`가 공급한다 — **`page.tsx`에 제목을 하드코딩하지 말 것.**
- ⛔ **`DashboardCharts.tsx` 내부 로직·차트·클릭 이동을 바꾸지 말 것.** 위치만 Dialog 안으로 옮긴다.
- **`AdminTodoBlock`을 건드리지 말 것.** 이미 요구사항을 충족한다(§1.1).
- **`AdminContentHealth`의 지표 4종을 이번에 바꾸지 말 것.** 스펙의 6지표(정상비율·썸네일누락·요약누락·중복의심)로 재정의하는 건 **별도 슬라이스**다 — 지표 정의와 SQL이 따라온다.
- **`AdminOpsSignals`의 "사용량 / 한도" 카드는 유지.** LLM·번역·**TTS** 사용량이 여기 있다. 임계값 로직(100%/80%)도 그대로.
- **KPI 집계 쿼리의 결과값을 바꾸지 말 것.** 표현만 바꾼다. (`bookmark_count > 0` head count 등)
- 카테고리는 **5종**이다. PDF를 만들어내지 말 것(§1.3).

## 5. 검증

- `npx tsc --noEmit` 0 / `npx eslint` 0 / `npm run build` **통과 (반드시 네가 돌릴 것)**
- `/admin`에 **"데이터 점등"이 사라졌는지** — `grep -rn "데이터 점등" src/` → **0건**
- **"수집 분석" 섹션이 본문에서 사라지고**, "수집 분석 보기" 버튼 → Dialog에서 **차트 4개가 다 뜨는지**
- Dialog 안 차트 클릭 → `/admin/contents?category=…` 이동이 **여전히 되는지**
- "운영 현황" → **"콘텐츠 수집현황"** 으로 바뀌고, 유형별 카드 **5개**가 각각 **클릭 이동**되는지
- 안 쓰는 집계 쿼리·죽은 prop(`todayCategoryDist`)이 **남아 있지 않은지** — grep으로 0 확인
- 대시보드 **초기 로드 시간이 나빠지지 않았는지** (쿼리를 뺐으니 빨라져야 정상)
