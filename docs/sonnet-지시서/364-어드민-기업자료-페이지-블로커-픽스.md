# 지시서 364 — /admin/company-documents 조회 오류 픽스 (블로커)

> 대상: 구현 에이전트 · **신규 SQL 없음** · 관리자 전용 · 360 방식(graceful + 원인 표면화) 재사용
> ⚠️ 읽을 것: `src/app/admin/company-documents/page.tsx`(L52~74 entity_dart_map·company_documents 조회) · `src/lib/supabase/{server,admin}.ts` · `docs/sql-handoff/355A-company-documents.sql`(RLS·grant) · `AGENTS.md`

## 증상 (355-F 구현자 보고)
`/admin/company-documents` 진입 시 **기존 데이터 조회 오류로 페이지가 안 뜸.** 이 때문에 **DART 수집·355-F 후보찾기·355-C 검토함이 전부 막힘**(모두 이 페이지에 있음). 355-F와 무관한 355-A 페이지 자체 버그(구현자가 main diff로 무관 확인).

## 진단 방향
- 페이지가 `createClient()`(세션) 로 `entity_dart_map`(embed `entities(canonical_name)`)·`company_documents`(`contents!inner`+`entities`) 조회. FK는 존재(entity_id→entities 확인). 유력 원인 후보: **RLS/grant**(세션 클라이언트로 company_documents/document_sources 읽기 불가 — 355-F도 llm_usage에서 같은 grant 문제를 겪음) 또는 PostgREST embed 힌트/모호성 또는 status enum('기업자료') 관련.
- **정확한 원인은 실제 에러 메시지로 확정** → 360처럼 표면화한다.

## 작업
1. **쿼리 격리 + 에러 표면화**: `entity_dart_map`·`company_documents`·(있으면)소스 조회를 **각각 try/catch**로 감싸고, 실패 시 `console.error('[company-docs] <쿼리> 실패:', err)` + 페이지 상단에 **실제 err.message를 관리자용 알림 박스로 노출**(관리자 전용이라 안전). 한 쿼리 실패가 **페이지 전체를 죽이지 않게** — 나머지 UI(수집 트리거·업로드·후보찾기)는 뜨게.
2. **원인 정타 수정**(표면화된 메시지 기반):
   - RLS/권한이면 → 관리자 조회는 **`createAdminClient()`** 로 전환(355-F가 llm_usage에서 한 것과 동일 패턴, 관리자 페이지이므로 verifyAdmin 후 admin 클라이언트 사용 정당). 또는 355A SQL에 누락된 select policy 보강(수희 핸드오프 — SQL이면 별도 파일).
   - embed 모호성이면 → 명시 FK 힌트(`entities!company_documents_entity_id_fkey(...)`).
3. **데이터 0건 graceful**: 매핑·문서가 없어도 "아직 없음" 안내로 정상 렌더(빈 상태), 42P01/enum 미적용도 graceful(기존 schemaReady 로직 유지·보강).

## 회귀 / 주의
- 다른 어드민 페이지·라우트에 영향 없게(이 페이지 한정).
- `createAdminClient()` 사용 시 반드시 `verifyAdmin` 통과 후에만(권한 상승 노출 금지).
- 색 토큰·한글 문구.
- 검증: `tsc`·ESLint·`check-prefetch`·`build` + **관리자로 `/admin/company-documents` 진입 시 크래시 없이 렌더**(에러 있으면 박스에 메시지). 완료보고에 **표면화된 실제 에러 메시지 + 정타 수정 내용** 첨부.
