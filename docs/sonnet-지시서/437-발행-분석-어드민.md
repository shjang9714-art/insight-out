## 2. 구현

### 2.1 `src/lib/admin/analytics.ts` 에 추가 (436 파일 확장, 신규 파일 아님)
```ts
export interface PublishAnalytics {
  months: string[]                                    // 최근 N개월 'YYYY-MM'
  byMonth: { period: string; strategyReports: number; briefings: number; newsletters: number; competitorWeekly: number }[]  // 발행량 추이
  successRate: {
    strategy: { completed: number; failed: number }   // ai_reports status
    briefings: { ok: number; failed: number }         // briefings status
  }
  leadTime: { strategyAvgHours: number | null; briefingAvgHours: number | null } // 생성→발행 평균(시간)
  newsletter: { period: string; issues: number; recipients: number }[]
}
export async function gatherPublishAnalytics(admin: SupabaseClient, months: number): Promise<PublishAnalytics>
```
구현 지침:
- `months` = `recentMonths(months)`(436 헬퍼 재사용, 기본 6). 각 소스 병렬 조회(`Promise.all`), 창은 첫 달 1일 이후.
- **발행량 byMonth**(발행/발송 시점 기준으로 월 버킷):
  - 전략보고서: `ai_reports.select('published_at').not('published_at','is',null).gte('published_at', windowStart)` → published_at 월별. (published_at 컬럼 에러 시 graceful 0.)
  - 브리핑: `briefings.select('published_at, generated_at').gte(...)` → published_at(없으면 generated_at) 월별.
  - 뉴스레터: `newsletter_issues.select('sent_on, recipient_cnt, status').gte('sent_on', windowStart)` → status='sent' 월별.
  - 경쟁사 주간: `competitor_weekly_reports.select('week_start, status, generated_at').gte('week_start', windowStart)` → generated_at(또는 week_start) 월별.
- **successRate**:
  - strategy: 창 내 `ai_reports` status별 count(completed vs failed). `count:'exact', head:true` 병렬 2건 or 한 번 select 후 JS.
  - briefings: status 정상(‘published’/생성완료) vs error_reason not null/‘failed’. 실제 status 값은 조회로 확인해 매핑.
- **leadTime**: 전략 = published_at not null 행의 `published_at - created_at` 평균(시간). 브리핑 = `published_at - generated_at` 평균. 표본 `.limit(2000)`, 값 없으면 null.
- **newsletter**: 월별 발송 건수 + `recipient_cnt` 합.
- graceful: 어떤 소스 쿼리가 에러(컬럼 부재 등)나면 그 소스만 0/빈값, 페이지는 유지.
