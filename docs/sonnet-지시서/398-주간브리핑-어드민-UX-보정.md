## 1. 🔴 A. 성공을 "생성된 리포트 없음"으로 표시한다 (버그)

`src/components/admin/AdminCompetitorWeeklyGenerate.tsx:73~76`
```tsx
{result.status === 'published'
  ? `${result.weekStart} ~ ${result.weekEnd} 발행됨 (사업영역 ${result.sections}개)`
  : result.reason ?? '생성된 리포트 없음'}
```

**`generate.ts` 에서 `reason` 없이 반환하는 경우는 성공 하나뿐이다.**
```ts
return { weekStart, weekEnd, status: 'draft', sections: sections.length }   // 성공
```
조기 반환 5개는 전부 `reason` 을 담는다(경쟁사 목록 없음 / 기사 조회 실패 / 경쟁사 기사 0건 / 영역 매칭 0건 / LLM 결과 0건 / upsert 실패).

그리고 **348 설계상 패스① 은 항상 `draft`** 다 — *"분석(패스②) 없이는 발행하지 않는다"*. 따라서 `status === 'published'` 는 **영원히 거짓**이고, 성공 시 `reason` 이 `undefined` 라 **`'생성된 리포트 없음'` 으로 떨어진다.**

> 348 에서 "항상 draft" 정책으로 바꾸면서 이 문구를 갱신하지 않은 것이다. **디렉터는 성공한 실행을 실패로 알고 있었다.**

### 조치
```tsx
{result.reason
  ? result.reason                                     // 실패 — 사유 그대로
  : `${result.weekStart} ~ ${result.weekEnd} 사실추출 완료 (사업영역 ${result.sections}개) — 분석(패스②) 대기`}
```
- **`reason` 유무로 성패를 가른다.** `status` 로 가르지 않는다(항상 draft 이므로 무의미).
- 실패 문구는 `AdminErrorBox` 등 **경고 톤**으로, 성공 문구는 중립 톤으로 구분한다.
- `sections` 가 0 인데 `reason` 도 없는 경우는 없어야 하나, 방어적으로 0이면 실패 톤으로 처리한다.

## 2. B. 생성 결과에 **어떤 영역이 만들어졌는지** 보여준다

패스① 은 **사건이 뽑힌 영역만** 섹션을 만든다(`사건 0건 — 건너뜀`). 그래서 주마다 존재하는 `area_key` 가 다른데 화면에 안 보인다.

디렉터가 실제로 겪은 결과: 패스② import 에서 **`존재하지 않는 area_key: telecom_b2b`** 로 실패. 그 주에 해당 섹션이 없다는 걸 알 방법이 없었다.

### 조치
- 생성 성공 문구에 **영역 라벨 목록**을 함께 표시한다. 예: `사업영역 3개 — AIDC · 보안 · 클라우드`
- API 응답에 `areas: { key, label }[]` 를 추가한다(`generate.ts` 의 `GenerateCompetitorWeeklyResult` 확장). **`sections` 숫자는 유지**한다(기존 호출부 호환).

## 3. C. 주 선택을 **실제 존재하는 초안 목록**에서 고르게 한다

`AdminCompetitorWeeklyAnalyze` 의 주 시작일이 **자유 입력 date** 라, 존재하지 않는 주를 지정할 수 있다. 디렉터는 기본값 `2026-07-20`(이번 주, 아직 미완결) 상태로 시도해 **`해당 주 리포트가 없습니다`** 를 받았다.

### 조치
- 주 시작일 입력을 **`select` 드롭다운**으로 바꾸고, `competitor_weekly_reports` 에 **실제 존재하는 주**만 옵션으로 노출한다(최신순, 상태 배지 포함: `2026-07-06 ~ 07-12 (초안)`).
- 목록은 **이미 페이지가 조회하는 `initialReports`(최신 10건)를 재사용**한다. 새 API 를 만들지 않는다 — `CompetitorWeeklyHub` 가 이미 prop 으로 들고 있다.
- 선택된 주의 **영역 목록**(§2)도 드롭다운 아래에 표시한다.
- 초안이 0건이면 드롭다운 대신 `먼저 사실 추출(생성)을 실행하세요` 안내.

## 4. D. JSON 입력칸 두 개의 **스키마 차이**를 라벨로 구분한다

같은 화면에 JSON 입력칸이 둘인데 기대 형태가 다르다. 디렉터가 반대쪽에 붙여넣어 **`본문(JSON)은 배열이어야 합니다`** 를 받았다.

| 위치 | 기대 형태 | 현재 라벨 |
|---|---|---|
| `분석(패스②)` 탭 | **객체** `{summary, overall_impact, areas:[...]}` | `② Claude 분석 결과 (JSON)` |
| `발행 브리핑` 탭의 리포트 편집 | **배열** `[{area_key, ...}, ...]` | `사업영역별 본문 (JSON)` |

### 조치
- 두 라벨에 **기대 형태를 명시**한다.
  - `② Claude 분석 결과 — 객체 { summary, overall_impact, areas: [...] }`
  - `사업영역별 본문 — 배열 [ { area_key, ... } ] (직접 편집용)`
- `placeholder` 도 각각의 형태를 그대로 보여준다(이미 일부 되어 있음 — 배열 쪽도 맞출 것).
- 396 으로 탭이 갈렸으므로 두 칸이 **동시에 화면에 보이지는 않는다.** 라벨 보강만으로 충분하다.

5. 패스② import 가 기존과 동일하게 동작한다(스키마 무변경).
6. `발행 브리핑` 탭의 직접 편집(배열)도 그대로 동작한다.
7. 396 의 탭 4개·`?tab=` 유지가 깨지지 않는다.

## 8. 별건 — 이번에 함께 드러난 것 (고치지 말고 기록만)

**8.1 패스① 이 연도를 잘못 추출한다**
디렉터가 받은 사건 목록에서 `security`·`mobility` 영역의 날짜가 **2024년**으로 나왔다(`evt_020` 2024-01-18, `evt_021`·`evt_022` 2024-01-01, `evt_023`·`evt_024` 2024-06-22). 전부 2026년 기사다.
→ `FACTS_SYSTEM_FALLBACK` 에 **"연도를 추론하지 말고 기사 발행일을 그대로 쓸 것"** 제약이 필요하다. 별도 슬라이스.

**8.2 영역 오분류**
`mobility` 영역에 과기정통부 AIDC 회동·NIPA '모두의 AI' 설명회가 들어갔다. 모빌리티가 아니라 정책 사안이다.
→ `AREA_DEFS` 의 `matchNames` 와 키워드 그룹 태깅을 함께 봐야 한다. 별도 슬라이스.

**8.3 영역 간 사건 중복**
같은 `content_id` 의 같은 사건이 두 영역에 들어간다(`evt_015`/`evt_021`, `evt_016`/`evt_022`, KT 1GW 가 `aidc`·`telecom_b2b` 양쪽). 의도된 것인지 결함인지 판단 필요.
