## 작업

### 1. `related.ts` — 유형별 버킷 반환
- 신규 `getRelatedGrouped(supabase, current, perCat = 8)`:
  - 기존 겹침 로직(matched_keywords×2 + matched_groups×1, 같은 클러스터 제외, score>0) 재사용하되 **후보 limit 상향(각 overlaps 60)**.
  - 점수순 정렬 후 **표시 카테고리별 버킷**: `getCategoryDbValues` 역매핑 또는 직접 — `뉴스→뉴스`, `리포트/가트너/KRG→리서치`, `웹인사이트/오피니언→웹인사이트`(생성물 제외). 각 버킷 상위 `perCat`.
  - 반환 `{ 뉴스: RelatedItem[], 리서치: RelatedItem[], 웹인사이트: RelatedItem[] }`(빈 버킷 제외).
- 신규 `getRelatedYoutube(supabase, current, limit = 8)`:
  - **youtube_videos 는 matched_* 없음** → 느슨한 매칭: `current.matched_keywords` 상위 몇 개로 `youtube_videos` `title.ilike.%kw%`(OR, **LIKE 특수문자·PostgREST `,()` 정제**), `order published_at desc`, limit. 결과 `{ id, title, channel_name, thumbnail_url, published_at }`. 키워드 없으면 `[]`.
  - 유튜브 링크 대상: 기존 유튜브 상세/외부(`/dashboard/youtube` 또는 video_id) — 프로젝트 컨벤션 따름.
- 88의 `getRelatedContents`는 유지(다른 곳에서 쓰면) 또는 페이지만 신규 함수로 교체.

### 2. 상세 페이지 — 유형별 가로 캐러셀
- 88의 "관련 기사" 단일 그리드 → **유형별 섹션 반복**(있는 유형만): 제목 "관련 뉴스 / 관련 리서치 / 관련 웹인사이트 / 관련 유튜브".
- 각 섹션: **가로 스크롤 행** — `flex gap-3 overflow-x-auto snap-x pb-2`(스크롤바 숨김 유틸 있으면 사용). 카드 `min-w-[260px] max-w-[260px] snap-start shrink-0`.
- 카드(컴팩트): 썸네일(있으면)·제목(line-clamp-2)·출처/채널·날짜·카테고리 배지. 클릭 → 뉴스/리서치/웹인사이트는 `/dashboard/contents/{id}`, 유튜브는 컨벤션 대상.
- 출처 제목 매핑 불필요(관련 함수가 row 반환). 모든 섹션 비면 영역 자체 숨김.
- **서버 컴포넌트 유지** — 가로 스크롤은 CSS만(네이티브 스와이프/트랙패드). (화살표 버튼은 client 필요 → 후속 선택.)

## 회귀 / 주의
- DB·SQL 무변경. 겹침 엔진 재사용(점수·클러스터 제외 동일).
- 유튜브 추천은 **태깅 없어 제목 ILIKE 근사** — 정확도 낮을 수 있음(빈 결과면 섹션 숨김). 정밀화는 youtube_videos 태깅 도입 후속.
- ILIKE/`.or` 필터의 LIKE 특수문자(`%_\`) + PostgREST 구분자(`,()`) 정제(93 메모와 동일).
- 카드 폰트 11px↑·토큰 색(#9)·한국어(#1). 가로 스크롤 영역 nested scroll 주의(본문 세로 스크롤과 독립).
