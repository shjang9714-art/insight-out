## 0. 한 줄

매일 06:00 KST cron이 브리핑을 생성하지만 `draft`로 저장돼 관리자가 발행해야 사용자(`/dashboard/briefings`는 published만)에게 닿는다. **cron 경로의 생성 결과를 텍스트 자동발행**(충분한 브리핑=선정 ≥ MIN_ARTICLES만)으로 바꿔 습관 루프를 닫는다. **어드민 수동 생성은 draft 유지**(검토 보존), **TTS·음성은 수동 그대로**(player가 음성 유무 분기).

## 1. 현행 진단 (검증된 코드 사실)

- `src/lib/briefing/generate-briefing.ts` `generateBriefing({force,date})` — 후보 선정·LLM 스크립트·**`status:'draft'` upsert**(L419). 실패 시 `status:'failed'`. 멱등 가드(published/archived면 재생성 차단).
- `src/app/api/cron/briefing/route.ts` — 매일 호출(vercel.json `0 21 * * *`=06:00 KST), `generateBriefing({force,date})`.
- `src/app/api/admin/briefings/generate/route.ts` — 어드민 "생성" 버튼, `generateBriefing({force})`.
- 사용자뷰 `/dashboard/briefings` — `status in (published, archived)`만. player는 음성 유무 분기(텍스트만도 OK).
- 수동 발행 PATCH(`/api/admin/briefings/[id]`) — `status='published'` + `published_at=now`(없을 때). **자동발행도 이 필드 미러.**
- TTS는 별도(`synthesize-briefing.ts`·admin `[id]/tts`), **cron 없음**(수동). → 자동발행은 텍스트만, 음성은 이후 수동.

## 3. 구현

### 3-1. `src/lib/briefing/generate-briefing.ts` — autoPublish 옵션

옵션 타입 확장:
```ts
export async function generateBriefing(
  opts?: { force?: boolean; date?: string; autoPublish?: boolean }
): Promise<GenerateResult> {
```

성공 upsert(L411~423) 직전, 발행 여부 판정:
```ts
// 자동발행: cron 경로 + 충분한 브리핑(선정 >= MIN_ARTICLES)만. 얇으면 draft(검토).
const publish = (opts?.autoPublish ?? false) && selected.length >= MIN_ARTICLES
```

upsert payload 분기:
```ts
.upsert({
  briefing_date: briefingDate,
  title,
  script,
  source_content_ids: sourceContentIds,
  status: publish ? 'published' : 'draft',
  ...(publish ? { published_at: new Date().toISOString() } : {}),
  generated_at: new Date().toISOString(),
}, { onConflict: 'briefing_date' })
```

- 실패 경로(`status:'failed'`)·멱등 가드 무변경.
- MIN_ARTICLES(기본 3)는 기존 상수 재사용 → 충분분 기준 단일 출처.

### 3-2. `src/app/api/cron/briefing/route.ts` — autoPublish 전달

```ts
const result = await generateBriefing({ force, date, autoPublish: true })
```
(어드민 generate 라우트는 **무변경** → 수동 생성은 draft 유지, 검토 후 수동 발행.)

## 4. 회귀 가드 / 비기능 요건

- 어드민 수동 생성 = draft 그대로(검토 흐름 보존).
- cron 자동발행은 **충분한 브리핑(선정≥MIN_ARTICLES)** 만 → 얇은 날은 draft로 남아 사람 검토(신뢰 보수).
- 음성(TTS)은 수동 유지 — 자동발행 브리핑은 텍스트만(player 음성 유무 분기로 정상 표시).
- published_at은 수동 발행 PATCH와 동일 세팅(정합).
- 멱등 가드 유지 → 이미 published면 재생성/덮어쓰기 없음.
- SQL·신규 의존성 0. UI 변경 0(기존 player/아카이브가 published 자동 노출).
