## 1. 현행 진단 (확인된 코드 사실)

**(a) 카테고리는 DB 테이블이 아니라 코드 상수다.** `categories`·`taxonomy` 테이블 없음(스키마 68테이블 확인). 세 곳에 나뉘어 있다:

| 계층 | 위치 | 값 |
|---|---|---|
| **DB enum** | `content_category`(schema) = `DB_CONTENT_CATEGORIES`(`src/lib/categories.ts`) | 뉴스·리포트·기업자료·웹인사이트·가트너·KRG·오피니언·뉴스레터·AI보고서·유튜브·지식보고서 (**11**) |
| **사용자 화면** | `CATEGORY_DEFS`(`src/lib/categories.ts`) | 뉴스·리서치·웹인사이트·유튜브·AI분석·AI 리포트 (**6**), 각 `dbCategories[]` 로 DB값 매핑 |
| **어드민 탭** | `ADMIN_CATEGORY_TABS`(`AdminContentManager.tsx` 137행, **비공개 const**) | 뉴스·유튜브·웹인사이트·외부리포트·지식보고서 (**5**) |

**(b) 확인된 불일치 — 이 화면이 드러내야 할 것:**
- **`기업자료`·`뉴스레터`** 는 DB enum에 있으나 `CATEGORY_DEFS`·`ADMIN_CATEGORY_TABS` **어디에도 매핑이 없다** → 어느 화면에서도 카테고리로 보이지 않는 **고아**.
- **`지식보고서`** 는 어드민 탭엔 있으나 `CATEGORY_DEFS`엔 없다(사용자는 별도 경로).
- **`가트너`·`KRG`·`오피니언`** 은 `ContentCategory` 타입 주석상 **deprecated(수집 미사용)** 인데, 기존 데이터 표시를 위해 리서치·웹인사이트 탭의 `dbCategories`에 여전히 묶여 조회된다(의도된 동작).
- ⚠️ **`AI분석`·`전략보고서`는 불일치가 아니다.** `generated: true` 인 UI 전용 생성물이고 `toDbCategories()`(`categories.ts` 122행)가 DB에 없는 값을 이미 걸러낸다. **오진하지 말 것.**

**(c) 공통 태그는 실체가 없다.** `tags`·`content_tags` 테이블 없음. 이 시스템의 "태그"는 이미 존재한다 — `contents.matched_keywords`(text[], GIN 인덱스, 코드 121회 참조, 원장=`keywords` 테이블)와 `keyword_groups.tag_type`(enum: industry/company/tech/market/policy/content_type). 즉 **별도 태그 원장을 만들면 쓰는 화면이 0개인 원장**이 된다.

**(d) nav 현황(382)**: 기준정보 그룹에 `분류·카테고리`(`/admin/taxonomy`, disabled '준비중')·`공통 태그`(`/admin/tags`, disabled '준비중')가 자리만 잡혀 있다.

### 8.2 수정 요구

#### A. 집계 실패가 `—` 아닌 `0` 으로 표시된다 — **가드 5 위반 · 거짓 숫자**
supabase-js 는 쿼리 에러 시 reject 하지 않고 `{ error, count: null }` 로 **fulfilled** 된다. 따라서 모든 조회 실패가 `?? 0` 을 타고 **"0건"** 으로 표시된다. 고아 카테고리에 데이터가 실제로 쌓였는지 보는 것이 이 화면의 존재 이유인데, 실패를 0 으로 덮으면 *"기업자료 0건이니 enum 에서 정리해도 된다"* 는 오판을 부른다.

```diff
- counts[category] = r.status === 'fulfilled' ? (r.value.count ?? 0) : null
+ counts[category] =
+   r.status === 'fulfilled' && !r.value.error ? (r.value.count ?? 0) : null
```

#### B. `createAdminClient()` 예외가 페이지 전체를 죽인다 — **가드 5 위반**
`getContentCounts()` 안에서 호출되는데 try/catch 가 없다. env 누락 시 throw 되어 **표 자체가 렌더되지 않는다.** 가드 5는 "집계가 실패해도 표는 렌더".

```diff
  async function getContentCounts(): Promise<Record<string, number | null>> {
-   const admin = createAdminClient()
-   const results = await Promise.allSettled(...)
-   ...
-   return counts
+   const counts: Record<string, number | null> = {}
+   try {
+     const admin = createAdminClient()
+     const results = await Promise.allSettled(
+       DB_CONTENT_CATEGORIES.map((category) =>
+         admin.from('contents').select('id', { count: 'exact', head: true }).eq('category', category)
+       )
+     )
+     DB_CONTENT_CATEGORIES.forEach((category, i) => {
+       const r = results[i]
+       counts[category] =
+         r.status === 'fulfilled' && !r.value.error ? (r.value.count ?? 0) : null
+     })
+   } catch {
+     DB_CONTENT_CATEGORIES.forEach((category) => { counts[category] = null })
+   }
+   return counts
  }
```

#### C. 하단 섹션 서술이 사실과 다르다 — **가드 4 정신 위반**
`AI분석` def 의 `dbCategories` 는 `['AI보고서', 'AI분석']` 이고 **`AI보고서` 는 DB enum 11개에 실재한다.** 그 결과 하단 "UI 전용 생성물 카테고리 **(콘텐츠 테이블에 없음)**" 표에 `AI보고서` 가 찍히는데 이는 거짓이고, 위 표의 `AI보고서` 행과 값이 중복된다.

→ 하단 표의 `매핑된 dbCategories` 컬럼은 **`DB_CONTENT_CATEGORIES` 에 없는 값만** 표기한다(= `AI분석`·`전략보고서`). 즉 `def.dbCategories.filter((c) => !(DB_CONTENT_CATEGORIES as readonly string[]).includes(c))`. DB 에 실재하는 값은 위 표에서 이미 매핑으로 보이므로 여기서 반복하지 않는다.

#### D. 한쪽만 미매핑인 셀까지 경고색 — **오진 유발**
§3.2 는 "**양쪽 모두** `—` 인 행"만 경고 톤이다. 현재 구현은 `!row.userLabel && 'text-amber-600'` 로 **셀 단위** 착색해, `지식보고서`(사용자는 별도 경로)·`AI보고서`(어드민 탭 없음)가 경고색으로 뜬다. 둘 다 §1(b) 에서 "불일치 아님"으로 못박은 항목이다.

→ 셀 단위 amber 를 제거하고 **행 단위 강조(`isOrphan`)만** 남긴다. 값이 없는 셀은 중립색 `—`.
