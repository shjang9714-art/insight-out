## 1. 현행 진단 (검증된 코드 사실)

> ⚠️ **David 가설 정정**: 스펙은 *"hover 상태가 팝업 표시를 직접 제어하고 있을 가능성"*을 원인으로 봤지만, **틀렸다.** 상태는 이미 분리돼 있다:
> - `edgeTooltip`(:187) — 호버. `hoveredLinkRef`로 제어, 마우스 떼면 해제.
> - `lockedEdge`(:201) — **클릭 고정 선택**. `handleLinkClick`(:573)이 세우며, 비동기 `.then()`에 **호버 가드가 없다**(:597). 패널도 `activeLockedEdge`로 별도 렌더(:1086).
>
> **진짜 원인은 "선 클릭이 잘 안 잡히는 것"이다.**

### 1.1 선 클릭이 안 잡히는 이유
- react-force-graph의 **`linkHoverPrecision` prop이 설정돼 있지 않다**(기본값 4px). 선이 얇아 클릭 판정이 매우 좁다.
- 클릭이 빗나가면 **배경 클릭**으로 떨어지고, `handleBackgroundClick`(:516~519)이 **`edgeTooltip`·`lockedEdge`·`selectedNodeId`를 전부 지운다.**
- 결과: 사용자는 **호버 툴팁만 보다가** 마우스를 떼면 사라지는 걸 겪는다. 고정 패널은 존재하지만 **도달하지 못한다.**

### 1.2 선택 패널의 현재 위치
- `activeLockedEdge` 패널은 **팝업이 아니라 그래프 아래에 붙는 카드**(`:1087` `className="mt-3 rounded-xl border bg-card p-4"`). 우측 인스펙터가 아니다.

### 1.3 Esc 없음
- `Escape`/`keydown` 핸들러가 **전혀 없다**(grep 0건).

### 1.4 구슬 크기·선 굵기 — 의미는 있는데 **아무도 모른다**
```ts
// entityToNode(:107)
val = isCenter ? clamp(√(mention_count) × 2,   4, 16)
               : clamp(√(mention_count) × 1.2, 2, 10)
// linkWidthFromWeight(:121)
width = clamp(log2(weight + 1) × 0.9, 1.0, 5)
```
- 크기 = **언급 횟수**, 굵기 = **함께 등장한 기사 수**. 둘 다 의미가 있다.
- 그런데 범례 문구(:783)는 *"점=기업·기술·인물, 선=함께 뉴스에 등장한 관계. 점을 누르면 관련 기사가 보여요."* 뿐 — **크기·굵기가 무슨 뜻인지 한 마디도 없다.**

### 1.5 구슬 간 거리 — **의미가 없는데 있는 것처럼 보인다**
```ts
charge.strength(-280)   // :339 — 모든 노드 동일
link.distance(80)       // :342 — 상수!
```
- **모든 선의 목표 길이가 80으로 고정**이다. 관계 강도와 무관하다.
- 화면상 거리는 물리 시뮬레이션의 부산물일 뿐인데, 사용자는 **"가까우니 관련이 깊나 보다"**라고 읽는다. **의미 없는 것이 의미 있는 것처럼 보이는 상태** — 없는 것보다 나쁘다.

### 1.6 라벨칩이 "눌러도 반응 없는" 이유 (4가지, 전부 확인)
칩은 **타입 필터**다: `visibleNodes = nodes.filter(n => !hiddenTypes.has(n.type) || n.isCenter)` (:638)
1. **그 타입 노드가 애초에 없다.** 칩 7종이 `TYPE_ENTRIES`(:94)로 **항상 전부 렌더**되는데, 현재 ego 그래프에 '인물' 노드가 0개면 눌러도 화면이 그대로다. ← **주범**
2. **중심 노드는 절대 안 숨겨진다**(`|| n.isCenter`). 중심이 '기술'인데 '기술' 칩을 누르면 중심만 남아 이상해 보인다.
3. **시각 피드백이 `opacity-30`뿐**(:792). 눌린 건지 아닌지 잘 안 보인다.
4. **이게 필터라는 걸 아무도 말해주지 않는다.** 색 동그라미 + 라벨이라 **범례로 읽는 게 자연스럽다.**

## 3. 구현 — `src/components/entities/KnowledgeGraph.tsx`

### 3-A. 선을 확실히 클릭할 수 있게 (가장 중요)

1. **`linkHoverPrecision` 상향** — `<ForceGraph2D>`에 `linkHoverPrecision={10}` 정도(기본 4). 히트영역이 넓어져 클릭이 잡힌다. 이 한 줄이 체감의 대부분이다.
2. **선택 중일 때 선을 굵게** — `linkWidth`(:935)에서 선택된 선은 `base × 2.5`(최소 4px) 정도로.
3. **배경 클릭 오폭 완화** — `handleBackgroundClick`은 그대로 두되(스펙상 배경 클릭은 해제가 맞다), 히트영역 확대로 오폭 자체를 줄인다.

### 3-B. 우측 고정 인스펙터 패널

- 데스크톱(`lg` 이상): 그래프 우측에 **고정 인스펙터**(`lg:grid lg:grid-cols-[1fr_320px]` 형태). 모바일/태블릿: **기존처럼 그래프 아래**에 카드로.
- 내용은 **지금 있는 데이터로만**: 두 엔티티명 · "기사 N건에서 함께 등장" · 콘텐츠 목록 · `×` 버튼.
  > ⚠️ David 스펙의 **관계 유형·관계 강도 라벨·관계 요약·근거 문장·기사/리서치/유튜브 탭은 데이터가 없다.** `entity_pair_contents` RPC는 `(content_id, title, collected_at)` 3개만 반환한다(`schema.sql:1334`). **이번 범위에서 만들지 말 것** — 빈 패널이 된다. 후속 B·C에서 다룬다.
- **관계 강도만 예외적으로 파생 가능**: `weight`로 `강함/보통/약함` 뱃지를 붙여도 좋다(예: log2 기준). 선택 구현.

### 3-C. 선택 시 나머지 약화(디밍)

- 선택된 선의 **양 끝 노드는 선명하게**, 그 외 노드·선은 **투명도 30~40%**로.
- `nodeCanvasObject`(:858)와 `linkColor`(:930)에서 `activeLockedEdge`의 `pairKey`를 참조해 알파를 조절한다.
- **호버는 툴팁만** — 호버로는 디밍하지 않는다(탐색 보조에 그친다).

### 3-D. Esc + 해제 규칙 명문화

`useEffect`로 `keydown` 리스너 추가 → `Escape`면 `setLockedEdge(null)` + `setSelectedNodeId(null)`.

**해제되는 경우(이것만)**: `×` 버튼 · 배경 클릭 · `Esc` · 다른 선 클릭 · 노드 클릭
**해제되면 안 되는 경우**: 선에서 마우스 벗어남 · 패널에 마우스 올림 · 패널 스크롤 · 창 리사이즈
> 현재 코드도 대부분 이 규칙을 지키고 있다. **깨뜨리지 말 것.**

### 3-E. 거리에 의미 부여 (한 줄)

`:342`의 `link.distance(80)` 상수를 **weight 역함수**로:
```ts
if (link?.distance) link.distance((l: any) => 140 - Math.min(80, Math.log2((l.weight ?? 1) + 1) * 20))
```
→ **강한 관계일수록 가깝게**. 그래야 "가까움 = 관련 깊음"이 실제 의미를 갖는다.
- 값은 조정 가능. 핵심은 **상수가 아니게** 하는 것.

### 3-F. 범례 직관화

`:783`의 안내 문구를 확장해 **크기·굵기·거리의 의미**를 명시:
```
점 = 기업·기술·인물 등 엔티티 · 크기 = 언급 횟수
선 = 함께 뉴스에 등장한 관계 · 굵기·가까움 = 관계 강도
점을 누르면 관련 기사, 선을 누르면 두 엔티티의 관계가 보여요.
```

### 3-G. 칩 직관화 — "눌러도 반응 없음" 제거

1. **개수 표시**: 각 칩에 현재 그래프의 해당 타입 노드 수를 붙인다 → `기업 12`
2. **0개면 비활성**(`disabled` + `opacity-40` + `cursor-not-allowed`) → **애초에 누를 수 없으니 "반응 없음"이 사라진다.** ← 핵심
3. **필터임을 명시**: 칩 그룹 위에 라벨 한 줄 — `유형 필터 (누르면 숨김)`
4. **선택 상태를 명확히**: 숨겨진 칩은 `opacity-30`만 말고 **취소선 + 배경 반전**으로 확실히 구분.
5. **중심 노드 예외 안내**: 중심 노드 타입 칩을 누르면 *"중심 노드는 숨겨지지 않습니다"* 를 툴팁/캡션으로. (동작은 유지 — 중심을 숨기면 그래프가 무너진다.)

## 4. 회귀 가드

- **`lockedEdge` / `edgeTooltip` 분리 구조를 깨지 말 것.** 이미 올바르다. 새로 만들지 말고 **그대로 쓴다.**
- **`handleLinkClick`의 비동기 `.then()`에 호버 가드를 넣지 말 것**(:597). 지금 없는 게 정답이다. 넣으면 클릭 결과가 마우스 이동에 사라진다.
- `forLoadedKey` 무효화(:209) 유지 — 중심이 바뀌면 선택이 자동 해제되어야 한다.
- **중심 노드는 계속 숨겨지지 않아야 한다**(`|| n.isCenter`). 숨기면 그래프가 무너진다.
- `entity_pair_contents` RPC·호출 방식 **변경 금지**(SQL 없음).
- **없는 데이터를 UI에 만들지 말 것** — 관계 유형·요약·근거 문장·기사/리서치/유튜브 탭은 이번 범위 밖(§3-B 경고).
- 모바일에서 우측 인스펙터가 화면을 잡아먹지 않을 것(그래프 아래 카드 유지).
- 노드 클릭(관련 기사) 기존 동작 불변.
