
- 작은 fix 는 main 직접 push 도 가능(AGENTS §20.5). 기능·스키마·환경변수는 브랜치+PR 권장.

## 2. 배포됐는지 확인 (Vercel 대시보드 없이) ⭐

프로덕션에 **지금 떠 있는 커밋**을 반환하는 공개 엔드포인트:

```bash
curl -s https://insight-out-app.vercel.app/api/version
# → {"shortCommit":"7a9af75","branch":"main","env":"production", ...}
```

내가 머지한 커밋과 비교:

```bash
# 한 줄 비교 (배포본 vs 원격 main 최신)
echo "deployed: $(curl -s https://insight-out-app.vercel.app/api/version | grep -o '"shortCommit":"[^"]*"')"
echo "main HEAD: $(git rev-parse --short origin/main)"
```

- 두 값이 **같으면 배포 완료** ✅ → 기능 테스트 진행.
- **다르면 아직 빌드 중** → 1~2분 뒤 다시 `/api/version` 호출. (보통 머지 후 1~2분)

## 3. 크롤러 수동 검증

```bash
# 당일분
curl -s "https://insight-out-app.vercel.app/api/cron/crawl" -H "Authorization: Bearer $CRON_SECRET"
# 소급 N일(최초 구축·검증, 최대 30) — due-체크 우회하고 활성 소스 전부 강제 수집
curl -s "https://insight-out-app.vercel.app/api/cron/crawl?days=7" -H "Authorization: Bearer $CRON_SECRET"
```

응답: `{ ok, sources_total, success, failed, inserted, duplicates, held }`.
- 멱등 확인: 같은 호출 2회차는 `inserted:0` + `duplicates` 증가가 정상.

## 4. Preview 배포로 테스트하려면 (선택)

브랜치 push 시 Vercel 이 PR 전용 Preview 배포를 생성하지만 **Deployment Protection(SSO)** 이 걸려 있어 curl 이 막힘. 쓰려면 수희가 1회 설정:
- Vercel → Settings → Deployment Protection → Vercel Authentication 을 "Only Production" 으로, 또는
- Protection Bypass for Automation 토큰 발급 → URL 에 `&x-vercel-protection-bypass=<토큰>&x-vercel-set-bypass-cookie=true`.

## 5. 환경변수 주의

- Vercel 환경변수는 스코프(Production / Preview / Development)가 분리. 새 변수는 필요한 스코프에 모두 체크.
- 크롤러 필수: `CRON_SECRET`, `SUPABASE_SERVICE_ROLE_KEY` (서버 전용, NEXT_PUBLIC_ 금지).
- 값에 한글·따옴표·공백 섞이면 헤더 빌드 에러(ByteString) 발생 → JWT(`eyJ…`)만 깔끔히.
