## 276 — 전략보고서 근거(출처) 블록 ⭐ 최우선

> **왜 최우선인가**: 이건 **그동안 조용히 실패하고 있던 것**이다. `ai_report_sources`의 이슈 행이 CHECK 제약(content/youtube 중 정확히 하나)을 위반해 **에러 없이 저장이 안 되고 있었다.** 276 SQL로 `issue_id` 컬럼 + 3항 CHECK를 넣어 고쳤다. **실제로 고쳐졌는지 확인해야 한다.**

### 절차
1. 어드민 → **전략보고서 관리**(`/admin/reports`) → 새 보고서
2. `type` + `topic` 입력하고, **소스로 이슈와 콘텐츠를 둘 다 선택**한다 ← 핵심. 이슈를 반드시 포함할 것.
3. 생성 실행
4. 표지 업로드 → 발행자·발행일 확인 → **발행**
5. 서비스(`/dashboard/reports`)에서 카드 확인 → 클릭 → 상세 진입

### 합격 기준
- [ ] 생성 응답의 **`sourcesSaved`가 0이 아니다** (선택한 이슈+콘텐츠 수만큼)
- [ ] 서비스 상세 하단 **"근거" 블록에 이슈와 콘텐츠가 실제로 표시**된다
- [ ] 발행 해제하면 서비스에서 사라진다
- [ ] **표지 업로드 후 `contents` 테이블이 안 건드려졌다** ← `uploadCover()` 오용 방지가 실제로 작동하는지. 무관한 콘텐츠의 썸네일이 바뀌면 안 된다.

### 불합격 시 의미
- `sourcesSaved = 0` → **CHECK 제약이나 FK가 여전히 막고 있다.** 276 SQL이 실제로 적용됐는지, 아래 쿼리로 확인:
  ```sql
  select conname, pg_get_constraintdef(oid) from pg_constraint
   where conrelid = 'public.ai_report_sources'::regclass and contype = 'c';
  -- content/youtube/issue 중 정확히 하나(= 3항)여야 정상
  ```
- 콘텐츠만 저장되고 **이슈만 0** → `issue_id` 컬럼이나 FK 문제
- 근거 블록이 비어 있는데 `sourcesSaved > 0` → 상세 페이지 조회 쿼리 문제(적재는 됐는데 못 읽음)

## 284 — 경쟁사 주간 리포트 발행 스케줄

> 크론이 **매시(`0 * * * *`)** 로 바뀌었고, 라우트가 KST 요일·시각을 설정과 대조해 안 맞으면 즉시 스킵한다.

### 절차
1. 어드민 → **경쟁사 주간 리포트**(`/admin/competitor-weekly`)
2. **"발행 스케줄" 카드** 확인

### 합격 기준
- [ ] 카드가 **활성화**돼 있다 (SQL 미적용 안내가 안 보인다)
- [ ] 기본값이 **월요일 · 06시(KST) · 자동발행 OFF · 자동생성 ON**
- [ ] 요일·시각·자동발행을 바꿔 저장 → **새로고침해도 유지**된다
- [ ] **수동 생성 버튼은 스케줄과 무관하게 즉시 동작**한다 (게이트의 영향을 받으면 안 됨)

### 시간이 지나야 확인되는 것
- [ ] **다음 월요일 06시(KST)** 에 리포트가 **초안(draft)** 으로 생성된다 (자동발행 OFF이므로 서비스에 안 뜬다)
- [ ] 그 전까지 매시 호출은 Vercel 로그에 **`skipped: 'not_scheduled'`** 로 찍힌다

### 불합격 시 의미
- 카드가 비활성 → 284 SQL 미적용
- **엉뚱한 시각에 생성** → KST 환산 오류(UTC로 착각하면 9시간 어긋난다). 참고: 구 크론 `0 21 * * 0`(UTC)이 실제로는 **월 06시 KST**였다.
- **같은 주 리포트가 매시 중복 생성** → 멱등 가드(`already_exists`) 실패. `unique(week_start)` 위반 로그가 반복될 것.
- 자동발행 OFF인데 **서비스에 바로 노출** → `publish` 옵션이 안 먹은 것(재현검증에서 고친 부분)

## 265 — 유튜브 자막 수집·번역

> **핵심 리스크는 rate limit**이다. 비공식 엔드포인트라 자막 없는 영상을 반복해서 긁으면 차단될 수 있다. 그래서 `transcript_fetched_at` 마커가 전부다.

### 절차
1. 어드민 → **일괄 작업 관리** → 데이터 보강·재처리 → **"유튜브 자막 수집"**
2. **"아직 시도 안 함"** 실행 → 끝날 때까지 대기 (`remaining` 확인)
3. 유튜브 콘텐츠 상세 진입 → 분석 패널

### 합격 기준
- [ ] 자막 있는 영상 상세에 **"스크립트" 접힘 섹션**이 뜬다 (한글 번역)
- [ ] 원문이 한국어가 아니면 **"원문 보기" 토글**이 있다
- [ ] 자막 없는 영상은 **스크립트 섹션이 아예 안 뜬다** (에러 아님)
- [ ] ⭐ **"아직 시도 안 함"을 한 번 더 눌렀을 때, 방금 처리한 영상이 다시 안 잡힌다** ← **가장 중요.** `remaining`이 줄어들고, 자막 없던 영상을 재수집하지 않아야 한다.
- [ ] 번역 예산이 소진돼 `transcript_ko`가 빈 영상이 있다면, **"실패행 재시도"** 로 잡히고 **유튜브를 다시 긁지 않고 번역만** 수행한다

### 불합격 시 의미
- **두 번째 실행에서 같은 영상이 또 잡힌다** → **마커가 안 찍히고 있다.** 그대로 두면 백필 돌릴 때마다 자막 없는 영상 전체를 재수집해 **rate limit·ToS 위험**. 즉시 보고 요망.
- 스크립트가 안 뜬다 → 265 SQL 미적용(컬럼 없음) 또는 자막 자체가 없음
- 백필이 안 끝나고 계속 돈다 → `remaining` 계산 오류

## 286 — PDF 첫 페이지 표지 백필

> **핵심 리스크는 무한 재렌더**다. PDF 렌더는 CPU·메모리를 크게 먹어서, 커버를 못 만드는 PDF(손상·암호화)를 매번 재시도하면 비용이 크다.

### 절차
1. 어드민 → **일괄 작업 관리** → 데이터 보강·재처리 → **"PDF 표지 수집"**
2. **"아직 시도 안 함"** 실행
3. 콘텐츠 목록(리서치/리포트 탭)에서 카드 확인

### 합격 기준
- [ ] 기존 PDF 카드에 **1페이지 표지**가 뜬다
- [ ] ⭐ **"아직 시도 안 함"을 한 번 더 눌렀을 때 `remaining=0`이고 방금 처리한 게 다시 안 잡힌다** ← **가장 중요**
- [ ] 렌더 실패한 PDF(있다면)는 **"실패행 재시도"** 에만 잡힌다
- [ ] **이미 커버가 있는 PDF는 안 건드려진다** (수동으로 올린 커버가 덮이면 안 됨)
- [ ] 282 썸네일 백필(뉴스·웹인사이트)이 **영향받지 않는다** — 대상 집합이 분리돼 있다

### 285(신규 업로드)도 함께
- [ ] **새 PDF를 업로드**하면 자동으로 1페이지 표지가 붙는다
- [ ] ⭐ **스캔 PDF**(텍스트 추출이 안 되는 이미지 PDF)를 업로드해도 **표지는 붙는다** ← 이 기능의 최대 이득. 본문 추출은 `reason:'scanned'`로 실패해도 표지는 나와야 한다.
- [ ] 업로드할 때 **커버 파일을 직접 지정**하면, PDF 1페이지가 그걸 **덮지 않는다**

### 불합격 시 의미
- **두 번째 실행에서 또 렌더한다** → 마커 실패. CPU 폭증 위험.
- 수동 커버가 덮인다 → `thumbnail_url IS NULL` 가드 실패. **데이터 손실**이므로 즉시 보고.
- 스캔 PDF에 표지가 안 붙는다 → 커버 시도가 `isScannedPdf` 조기 return **뒤에** 있는 것(순서 오류)
- Vercel 런타임에서 `Cannot find native binding` → `@napi-rs/canvas` 바이너리 문제(lock에 linux-x64-gnu는 확인했으므로 발생 가능성 낮음)
