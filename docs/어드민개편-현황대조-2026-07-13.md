### 2-3. TTS → **이미 구현돼 있다** (Google Cloud TTS)

- 코어: `src/lib/tts/synthesize-briefing.ts` — 공급자 **Google Cloud TTS**, 보이스 `ko-KR-Wavenet-C`(env `GCP_TTS_VOICE`), 월 캡 900,000자(`TTS_MONTHLY_CHAR_CAP`), 초과 시 합성 전 차단

- 사용량: `/admin` 대시보드 `AdminOpsSignals`에도 "TTS(문자)" 노출

**즉 "TTS 관리 신설"의 실체는 "모닝브리핑에서 TTS를 떼어내 독립 메뉴로 만들기"다.**

**진짜 빈 곳은 딱 하나: 실패 로그.** TTS 라우트만 `runJob` 래핑이 안 돼 있어 **`job_runs`에 안 남는다**(`console.error`로만). 인수인계 §4-1의 "graceful인데 silent" 패턴이다.

### 2-5. 원문 URL 정규화 → 이미 있다. **위치만 틀렸다**

- 라이브러리: `src/lib/crawler/normalize.ts:12` `normalizeUrl()` — utm/fbclid/gclid 제거, 호스트 소문자화, 쿼리 정렬
- 수집 시 자동 적용(`orchestrator.ts:382`), `canonical_url` 저장(`:1165`), 교차중복 병합(`mergeByCanonical :1086`)
- 어드민 버튼: **`/admin/ai-jobs`의 "원문 URL 정규화"**(`AdminContentProcessing.tsx:517`)

→ 스펙의 "소스관리 탭으로 반영"은 **이 버튼을 옮기라는 뜻**이다. 새로 만들 게 아니다.
→ 스펙이 나열한 "모바일 URL → PC URL 변환", "언론사별 URL 패턴 정리"는 **없다.** 이건 신규다.

### 2-6. 총 콘텐츠 유형별 분해 → 이미 있다 (형태만 다름)

`/admin/page.tsx:309-313` — 총 콘텐츠 카드 아래 `뉴스 N 리포트 N 웹인사이트 N 유튜브 N AI보고서 N` **캡션 한 줄**로 이미 병기돼 있다.

## 4. ⚠️ 스펙이 **되돌리려는** 결정 — 소스관리 ↔ 소스품질 분리

`SourceManager.tsx:3-4` 주석:
> *"280 — 카탈로그(CRUD+import)만 슬림 유지. 수집 상태·품질·크롤 실행 트리거는 /admin/source-quality로 이동."*

**즉 이 둘은 지시서 280에서 *의도적으로* 분리한 것이다.** 스펙은 이걸 다시 합치자고 한다.

**합칠 때의 실제 비용**(코드 사실):
- 데이터 출처가 다르다 — SourceManager는 Supabase 직접 / SourceQualityManager는 **REST 2개 + RPC 1개**(`source_quality_stats`)
- SourceQualityManager는 **localStorage 크롤 잡 폴링 + interval 2개**를 돌린다. 합치면 CRUD 폼과 폴링이 한 컴포넌트에 섞인다 (797 + 824 = **1,621줄**)
- `qualityUnavailable`(186 SQL 미적용 시 RPC 부재 graceful) 배너 상태를 통합 컴포넌트가 이어받아야 한다
- 필터가 다르다 — 유형 탭(sources) vs 건강도 필터+정렬(quality)

→ **합치는 게 맞다고 보지만**(운영자는 "이 소스 살아있나 + 계속 쓸까"를 같이 판단하므로 스펙의 논리가 옳다), **1,621줄 단일 컴포넌트는 안 된다.** 탭 분리(카탈로그/품질) 또는 하위 컴포넌트 분해가 전제다.

## 5. 🔴 스펙의 진단이 코드와 다른 것 3건 — **확인 필요**

### 5-1. 틀고정 — **왼쪽이 아니라 오른쪽이다**

스펙: *"관리 기준 틀고정이 되어있음 → 틀고정 해제"*

코드 사실(`AdminContentManager.tsx`):
- sticky는 **오른쪽 "관리" 컬럼**: `th :1389 sticky right-0` / `td :1463 sticky right-0`
- **`left-0` grep → 0회.** 제목·체크박스는 고정돼 있지 **않다**
- 관리 컬럼 폭 **340px 고정**(`MANAGE_COL_WIDTH=340`), 나머지 6개 컬럼은 **드래그 리사이즈 가능**(`RESIZABLE_COLUMNS`)
- 테이블은 `table-fixed` + `overflow-x-auto`

→ **관리 컬럼 sticky를 풀면, 가로 스크롤 시 관리 버튼이 화면 밖으로 나간다.** 지금 sticky인 이유가 그것이다.
→ **진짜 문제는 sticky가 아니라 340px를 차지하는 버튼 5개**로 보인다. 스펙 스스로 제안한 **2줄형 리스트**가 더 나은 해법이다(제목/본문을 넓게, 메타는 칩, 관리는 아이콘/드롭다운).

### 5-2. 크롤 로그 "실패 사유 필터" — **분류 체계가 존재하지 않는다**

스펙이 제시한 7종(URL 접근 실패 / 파싱 실패 / 본문 없음 / 썸네일 없음 / 중복 콘텐츠 / API 한도 초과 / 권한 오류)은 **코드에 없다.**

실제 코드:
- `crawl_logs.status` = `'success' | 'partial' | 'failed'` **3종뿐**
- **실패 사유 = `error_message` 자유 텍스트.** enum도 코드 컬럼도 없다 → **필터를 만들 근거 데이터가 없다**
- 다만 **제외 사유**는 분류가 있다 — `RejectedBy` 5종(`lib/crawler/types.ts:23-30`): `ad`(광고성) · `excludedGroup`(그룹제외) · `tooShort`(길이미달) · `bodyTooShort`(본문짧음) · `excludeRule`(제외규칙). **현재는 툴팁으로만 노출, 필터 아님.**

→ 두 갈래다. **(A)** 기존 `RejectedBy` 5종으로 필터를 만든다(코드 무관·즉시 가능) / **(B)** `error_message`를 파싱해 새 실패코드 enum을 도입한다(**수집 파이프라인 변경 + SQL 필요**).

### 5-3. 제외 키워드 — **이미 두 군데로 갈라져 있고, 그게 버그다**

스펙은 "제외 규칙"과 "제외 키워드"를 **별도 항목**으로 두라고 한다. 그런데 지금 **이미 두 군데**다:

| | `keyword_groups.exclude_patterns` | `exclusion_rules` |
|---|---|---|
| 화면 | `/admin/keyword-groups` | `/admin/exclusion-rules` |
| 매칭 | **제목만** | 제목 + URL + 도메인 |
| 액션 | reject 고정 | reject / **hold** 선택 |
| 집계 | 없음 | `hit_count`·`last_hit_at` |

> ### ⛔ 정정 (2026-07-13) — **"hit_count가 0으로 남는 silent 버그"는 없다. 플래너가 틀렸다.**
>
> 초안에서 *"판정 순서상 `excludedGroup`이 먼저 잡으므로 `exclusion_rules.hit_count`가 0으로 남는다"* 고 썼다. **사실이 아니다.**
>
> `orchestrator.ts:410-413` — `matchExclusion()` 결과는 **reject 체인(418~442)보다 먼저** 계산되고, 매칭되면 `exclusionHits.set()`이 **무조건** 실행된다. `:1530-1535`에서 `increment_exclusion_hits` RPC로 플러시된다.
> → **어느 사유가 먼저 잡든 `hit_count`는 정상 기록된다.**
>
> **틀린 이유**: 서브에이전트가 판정 순서만 보고 단정했고, 플래너가 **코드를 열어보지 않고 그대로 옮겼다.** 루틴 §5-1("부분 grep으로 단정하기")의 전형.

**남는 진짜 문제 2개** (버그 아님):

1. **관리가 두 군데로 갈라져 있다.** 같은 "제외 키워드"를 어디에 넣어야 하는지 운영자가 매번 판단해야 한다. → §6 "키워드 규칙" 통합으로 해소.
2. **문구가 부정확하다.** `ExclusionRulesManager.tsx:247`은 `hit_count` 합을 **"지금까지 N건 차단"** 이라 표시하는데, 실제로는 **"매칭"** 이다. `isAdLike`·`excludedGroup`·`tooShort`가 먼저 잡은 건도 hit에 포함되므로, **그 규칙이 실제로 차단에 기여했다는 뜻이 아니다.** → 문구를 "매칭"으로 바꾸는 경미 수정.

→ **스펙대로 "제외 규칙"과 "제외 키워드"를 나란히 두는 건 지금 구조를 그대로 두는 것**이다. 통합이 목적이라면 §6과 함께 가야 한다.

## 6. "키워드 규칙" 재편의 실제 범위

스펙: *"제외규칙 → 키워드 규칙으로 변경. 안에 수집 키워드 / 제외 규칙 / 제외 키워드 / 키워드 분류 기준"*

현재 이 4가지는 **4개 화면에 흩어져 있다**:

| 스펙 항목 | 현재 위치 | 실체 |
|---|---|---|
| 수집 키워드 | `/admin/keyword-groups` | `keyword_groups.search_seeds` (Google News·유튜브 검색어) |
| 제외 규칙 | `/admin/exclusion-rules` | `rule_type`: `domain`·`url_pattern`·`title_pattern` **3종** (※ nav 설명엔 "키워드"라 써 있으나 코드엔 없다) |
| 제외 키워드 | `/admin/keyword-groups` + `/admin/exclusion-rules` | **중복** (§5-3) |
| 키워드 분류 기준 | `/admin/keywords` + `/admin/keyword-groups` | `keywords` 테이블(태깅) + `signal_hint`(시그널) |
| (스펙 누락) | `/admin/crawl-settings` | `min_body_length` **설정 1개뿐** → 스펙대로 제외 규칙에 흡수 타당 |

→ **"키워드 규칙" 메뉴 = 4개 화면(keywords · keyword-groups · exclusion-rules · crawl-settings)을 탭으로 통합.** 스펙이 말한 것보다 범위가 크다.
→ **그리고 `/admin/entities`(엔티티 사전, 1,227줄)는 어디로 가나?** 스펙에 언급이 없다.

## 7. 라벨 분류 체계 — **기존과 다르다**

스펙의 "기사 라벨 분류" 8종:
`정책/규제 · 시장동향 · 경쟁사동향 · 기술변화 · 고객사동향 · 위기 · 기회 · 투자/제휴`

현재 코드의 분류 체계는 **셋으로 쪼개져 있다**:
1. `keyword_groups.signal_hint` — 경쟁사동향/규제/정부/신제품/출시/투자/M&A/기술트렌드
2. `contents.sentiment` — 긍정/중립/부정 (논조, LLM)
3. `contents.lgu_impact` — **위기/기회** (313, LLM)

→ 스펙의 8종은 **1번(시그널)에 2·3번(위기·기회)을 섞은 것**이다.
→ **이름만 "신호 분류 → 기사 라벨 분류"로 바꾸는 건가, 분류 체계 자체를 8종으로 재정의하는 건가?** 후자면 LLM 프롬프트·백필·DB가 다 바뀐다. **범위가 완전히 다르다.**

## 9. 재정리한 우선순위 (플래너 제안)

스펙의 3·4순위가 이미 구현돼 있으므로 순위를 다시 짠다.

### 1순위 — 즉시 체감, 결정 불필요
1. **`/admin/ai-jobs` 이름·섹션 정리** — "일괄 작업 관리" → **"AI 콘텐츠 보강"**, LLM 사용 여부에 맞게 섹션 재배치(유튜브 태그는 룰 기반 → 데이터 보강으로)
2. **"데이터 점등" 카드 제거** (`AdminOpsSignals`)
3. **수집 분석 → 팝업/사이드패널화** (`DashboardCharts`를 대시보드 본문에서 제거)
4. **"운영 현황" → "콘텐츠 수집현황"** 이름 변경 + 유형별 캡션을 카드로 승격
5. **콘텐츠 검수 행 액션에 "본문 보강" 추가** — **API가 이미 있다**(`body-backfill/by-ids`). UI만 붙이면 끝. *가장 싸고 효과 큰 건.*

### 2순위 — 구조 정리 (결정 필요)
6. **소스관리 + 소스품질 통합** (§4 — 탭 분리 전제)
7. **키워드 규칙 통합** (§6 — 4개 화면 → 탭)
8. **크롤 로그 상단 일별 차트** (N3)
9. **콘텐츠 검수 테이블 2줄형 전환** (§5-1)

### 3순위 — 신규 개발
10. **북마크한 사람 조회** (N2) — 조직별 관심사 분석의 토대
11. **DAU / MAU** (N1) — `last_seen_at` 원재료는 있음
12. **TTS 실패 로그** — `runJob` 래핑만 하면 `/admin/job-runs`에 잡힘 (§2-3)

### 보류 — 결정 없이는 착수 불가
- 기사 라벨 8종 재정의 (§7)
- 크롤 실패사유 enum 도입 (§5-2 B안)
- TTS 독립 메뉴 분리 (§2-3)
- 모바일→PC URL 변환·언론사별 URL 패턴 (§2-5)
