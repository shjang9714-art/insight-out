## 3. 수희와의 병렬·의존성 매트릭스

```
Phase 1-A (1주)    수희: 안정화 3건         │ 용주: 🟢 브랜치 전략 (완료)
─────────────────────────────────────────────────────────────────────────
Phase 1-B (2주)    수희: 인증·온보딩 3건    │ 용주: DB 설계 4건 [Opus×2 + Sonnet×2]
                   ↓                          ↓
                   수희가 Supabase SQL 실행 ← 용주 SQL 작성  ⚠️ lag 발생 지점
─────────────────────────────────────────────────────────────────────────
Phase 2-A (3~4주)  수희: 수동업로드+검색 4건 │ 용주: 크롤링 5건 [Opus×2 + Sonnet×3]
                                                ↑ #1 DB 스키마 완료 전제
─────────────────────────────────────────────────────────────────────────
Phase 2-B (5~6주)  수희: 아카이빙·메일 4건  │ 용주: 콘텐츠 열람 UI 5건 [Sonnet×5]
Phase 2-C (5~6주)  수희: Admin 권한 2건     │ 용주: Admin 페이지 4건 [Sonnet×4]
                                                ↑ 권한 모델 (수희) 의존
─────────────────────────────────────────────────────────────────────────
Phase 3-A (7~8주)  수희: 뉴스레터 3건       │ 용주: 오피니언·유튜브 4건 [Sonnet×4]
Phase 3-B (9~10주) 수희: 브리핑 LLM 3건    │ 용주: TTS·플레이어 4건 [Opus×1 + Sonnet×3]
                                                ↑ #5 는 수희 LLM 스크립트 설계 완료 의존
Phase 3-C (9~10주) 수희: 번역 1건           │ 용주: 경쟁사 크롤링 1건 [Opus×1]
─────────────────────────────────────────────────────────────────────────
Phase 4 (11주~)    공동                      │ 용주: 5건 [Opus×3 + Sonnet×2]
```

## 6. 위험·의존성 메모

> [!WARNING]
> **Supabase 실행 lag** — 매 단계 수희에게 SQL 실행 부탁. 미리 batch 로 묶거나 매주 정기 시간 약속 필요. Phase 1-B 첫 회 lag 가 가장 길 위험.

> [!WARNING]
> **Vercel 로그 접근 불가** — Phase 2-A 크롤링 Cron 등록 후 실패 시 본인이 진단 불가. 수희가 로그 봐줘야 함. 매번 부탁할 흐름 합의 필요.

> [!WARNING]
> **수희 LLM 스크립트 의존** — Phase 3-B #5 TTS 는 수희가 LLM 스크립트 파이프라인을 먼저 설계·구현해야 의미 있음. 9-10주차 동시 진행이지만 수희가 한 주 정도 먼저 가야 함.

> [!NOTE]
> **PRD/시나리오 변경 위험** — 수희님이 PRD v2.1 → v2.2 갱신할 가능성. 시나리오 미팅 결과에 따라 본 계획도 갱신 필요. 마스터 [작업계획서.md](./작업계획서.md) 가 1차 sync 대상, 본 문서는 2차 sync.

## 7. 갱신 규칙

1. **마스터 작업계획서 갱신 후** 본 문서를 같은 PR 또는 후속 docs PR 로 sync
2. 각 항목의 신호등은 **노션 (마스터)** 먼저 → git [`docs/작업계획서.md`](./작업계획서.md) → 본 문서 순으로 동기화
3. 작업 시작 시: 본 문서에서 해당 항목 위치 + 의존성 확인 → `🟡` 갱신
4. PR 머지 후: `🟢` 갱신 + [`AGENTS.md`](../AGENTS.md) §20.8 따라 노션 일지·작업 DB·작업계획서 모두 갱신
