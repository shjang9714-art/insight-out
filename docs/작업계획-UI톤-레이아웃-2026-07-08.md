## 0. 디자인 톤 원칙 (모든 UI 작업의 공통 기준)

- **마젠타는 주얼리, 페인트 아님**: `#DB0078`를 소량·저대비로만. 활성 상태를 마젠타로 "채우지" 말고, **굵기 변화 + 얇은 하어라인/작은 포인트**로 표현. 필요 시 마젠타를 한 톤 낮춰(딥/무트) 사용.
- **위계는 색이 아니라 여백·elevation**: 리드/중요 요소는 은은한 그림자와 주변 여백으로 띄운다. 색 블록·2px 컬러 보더·글로우·그라디언트·좌측 색 스트라이프 금지.
- **하어라인·소프트**: 테두리 0.5px, 반경 10~12px(Balanced), 큰 둥근 pill 지양.
- **활성 언어 통일**: L1·L2가 같은 계열(얇은 언더라인/세그먼트), L2는 L1보다 가볍게.
- **타이포**: 위계는 크기·굵기로, 가중치는 2단(400/500). 한국어 본문 줄길이 ~40자(WCAG CJK) → 리딩 폭 좁게.
- **밀도는 폭이 아니라 구조**: 목록 다열·컴팩트 행, "히어로(리드)+그리드" 패턴.
- **어드민(AdminTabs·토큰)과 사용자단을 한 시스템으로**(제품 일관성).
